# task-queue 任务队列-说明文档

task-queue skill（`.agents/skills/task-queue/SKILL.md`）的配套说明与提示词手册。模式为**会话挂起**：在 ZCode 会话里挂起一个后台守望进程扫 `.tasks/pending/`，发现新任务即唤醒该会话认领、实施、归档，然后重挂守望继续循环——会话保持挂着，来任务自动干活。

协议细节以 SKILL.md 为准，本文只管「拿来就用」。

## 生命周期边界

- 守望进程依附当前会话：会话开着，监视就在；会话关了，监视即停。
- 同一时刻只有一个守望进程；每轮处理完由代理重挂，循环接力。
- 建议把监视挂在专用的、不干别的活的会话里，避免与正常开发会话互相打扰。

## 目录协议速览

```
.tasks/
├── pending/    新任务入口，.md 文件，文件名即任务名，内容即任务指令
├── doing/      实施中
├── done/       完成归档
├── failed/     失败归档
├── queue.state 手动开关，一行文本：on / paused / off
└── journal.log 心跳与动作流水
```

`.tasks/` 已加入 `.gitignore`，全部是本机运行产物。

## queue.state 开关

一行纯文本，直接用编辑器改，守望进程每轮轮询读取：

- `on` — 正常发现并报告任务（启动时自动写入，即复位）。
- `paused` — 跳过检测但守望继续轮询，任务在 pending 堆积，改回 `on` 自动恢复。
- `off` — 守望进程立即退出，代理结束监视循环并在 journal 记录。

任务实施到一半改 `off`，本轮照常做完，下一轮收尾。文件缺失按 `on` 处理并自动补写。

## 新建队列任务（pending 文件模板）

文件名格式 `YYYYMMDD-HHMM-<slug>.md`（如 `20260916-0820-env-selfcheck.md`），内容纯文本。目标、验收、约束写清楚，实施质量才稳：

```text
任务目标：<一句话说清要达成什么>

细节：
- <涉及文件/模块、具体要求逐条列>

验收标准：
- <怎么算完成：测试绿 / 文件存在 / 命令通过……>

约束：
- <不要动什么、注意什么>
```

已归档的实例参考 `.tasks/done/20260916-0820-env-selfcheck.md`（环境自检报告任务，全链路首跑验证通过）。

## 操作指令（在挂着监视的会话里对代理说）

```text
启动任务监视
```

```text
任务队列现在什么状态
```

```text
手动跑一轮任务队列
```

```text
停止任务监视
```

补充：启动默认轮询间隔 10 秒、守望超时 30 分钟（超时自动重挂），启动时可改；「手动跑一轮」不动后台守望，随时可用来验证链路或补跑。

## 通知行为

只在有动作的轮次弹 Windows toast（`TaskQueue/TYPE`）：认领 CLAIM、完成 DONE、失败 FAIL、开关关停 STOPPED。空轮与超时重挂完全静默。通知失败只记 journal，不影响流程。

## 排障速查

- 监视「死了」不再动：多半是会话重启过，重新说「启动任务监视」即可。
- `doing/` 有滞留文件：说明上一轮会话中途被杀，人工查看该任务文件，决定移回 `pending/` 重跑或移入 `failed/`。
- 想确认守望是否在跑：对代理说「任务队列现在什么状态」。
