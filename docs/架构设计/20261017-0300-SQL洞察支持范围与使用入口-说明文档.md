# SQL 洞察支持范围与使用入口

> 实施中的功能说明，最终支持与验收以 [非 UI 验收台账](../验收文档/20261016-2344-T-SqlInsight-实施与非UI验收台账-验收文档.md) 为准。本文不是已发布功能声明；本轮没有执行沙盒 UI 验收。

## 预览内分析

完整 SQL 预览的“更多”菜单提供分析入口。结构、来源与读写图只解析文本，不连接数据库、不执行 SQL。读箭头表示表被某语句读取，写箭头表示目标赋值，JOIN/筛选依赖与值来源分开。

- 当前精确语义围绕 MySQL/PostgreSQL 已验证子集：SELECT/JOIN、非递归 CTE、部分表达式/聚合/CASE、UNION、显式 INSERT…SELECT、单表 UPDATE/DELETE、MERGE 分支以及有序临时表脚本。
- 星号需要明确数据库身份与版本匹配的元数据。缺元数据、歧义裸列、未知表达式、递归或超预算均明确不完整，不猜边。
- 输入或结果超出预算时，原 SQL 仍可查看；分析取消/失败不会执行 SQL，也不会改写代码。
- 无可靠 token 源区间时只能定位全语句，不声称精确回到某个字符。外部库实体/运行反射不在静态文本能力保证内。

## 参数场景与渲染解释

场景页面读取当前语句的参数预设快照，在后台独立渲染，不切换激活预设、不改默认参数桶、不覆盖当前手工 SQL 草稿。

XML 条件使用存储的预览开关。普通参数参与 bind 与美元替换，foreach 使用实际提供的集合值；这仍是预览模拟，不证明应用运行时覆盖了某个分支。解释记录展开后节点路径、调用次数、条件依据和当时模板片段，不等于原 XML 字节偏移；include、trim 和参数回填后的定位精度需要按界面说明理解。

单批最多20场景，渲染节点应用与字符预算有界，嵌套集合超过总预算会停止。保存期望与验证只作用于本页内存；匿名回归包需先预览后复制，不包含原参数、源码路径、预设名或错误正文，也不能直接执行为 SQL。

## 运行 SQL 分析

运行分析需要用户在页面显式开启，且现有 SQL 捕获与增强捕获已经可用。它不自动启动应用、不绕过增强捕获同意、不改变参数脱敏开关。分析关闭后不新增事件；暂停/清空/重开与普通日志清空不是同一个操作。

- 独立事件在列表展示去重之前分流：相同 SQL 的真实多次执行仍分别计数。一次执行多次观测只有身份能证明相同才合并。
- 统计是保留范围内的客户端 JDBC 调用耗时，不是数据库 CPU 时间。累计耗时与同请求并行区间并集分别显示。
- 数据库身份只在可解析 JDBC 单主机子集上确定。未知连接或单次执行使用内部隔离桶，hash 不是数据库名；保守隔离可能降低聚合命中率。
- requestTag 是应用标签，不是请求 ID；没有生命周期证据时只做标签分组。
- 请求适配仅声明被织入 Servlet 线程观测，不保证 Filter、公有 service 覆写、线程池、响应式和异步工作完整。无法证明完整的请求预算为不可判定；已经观测到的下界超预算仍可判失败。
- 重复查询只作为候选，可能是重试、批量操作或合理业务。忽略候选只影响当前页告警展示，不删除事件、不改预算计数。
- 事务观测只覆盖代理连接包装生命周期，不等同已证明的物理连接/连接池借还；close不是commit，SQL成功不证明事务提交，XA/全局事务不承诺。

运行图只连已观测事实。缺消息、截断、驱动未覆盖、断连、旧协议或控制水位缺失都不能显示“完整”。

请求基线可由用户显式生成JSON并复制保存，后续粘贴加载；环境与上下文由用户声明，导入文件不是采集真实性认证。不完整基线只比较已观测子集差异，不把漏采的次数/耗时当完整阈值判退化；用户明确输入的绝对预算则可以由已观测下界超限判失败。

当前性能证据：真实本地固定负载的第三轮已做到每轮一万SQL与请求起止零丢失；但新增追踪5%成本目标尚未在稳定独占环境证明，不宣传“零开销”或“低于5%”。对应运行范围、版本和失败修复记录见验收台账。

## 实际 SQL 对照与结果比较

两类对比不同：

1. 预览—实际 SQL：候选按结构和上下文筛选；手动输入实际 SQL 样本需用户确认，不能由相同文本推断为同一次执行。文本差异只在本次页面内存展示。
2. 查询结果比较：会真正执行两个 SELECT。必须显式选择独立比较数据源、确认精确 SQL 对与副作用风险；不借用全局共享控制台目标。文本、参数、目标或配置变化使旧授权失效。

结果比较要求驱动报告的只读、自动提交连接；该标志不是服务端权限保证，因此仍要求函数副作用确认。锁读、写语句、多语句、未回填参数和安全上下文缺失均拒绝。两次顺序读取不保证同一数据库快照；无确定排序证据时只做多重集比较，保留重复行和 NULL/空字符串差别。截断、大字段无法限定、失败或取消都不能当作结果一致。

## 对象使用、Schema 与执行计划

对象使用查询限定用户显式选择的当前文件或模块，后台分片、可取消，不在编辑热路径自动扫全工程或依赖库。动态 XML、非常量拼接和未读取文件属于覆盖缺口，不能用“未找到”证明未使用。

Schema 比较只接受有数据库身份、方言和不同版本的本地快照。缺类型/未内省不等于列不存在。引用影响只覆盖已收集且上下文匹配的使用集合；源码改变后旧范围不应直接导航。

计划解释只读已有 EXPLAIN 结果，不自动执行 ANALYZE。估算成本是规划器单位，不是毫秒；实际行数/时间保留每循环语义，不把缺失值填零。原有计划历史与差异继续使用。

## 离线导入与外发边界

当前离线 Trace 格式为 OTLP JSON ExportTraceServiceRequest v1 的受限数据库 span 投影，用户点击后才读取输入。大小、深度、对象数、重复键和身份都受限制。SQL原文、参数、错误消息不保留，服务名做匿名标识。外部覆盖恒未知，导入不是重新采集。

配置的 Trace 链接必须显式点击才打开；不自动连接远程 OAP、Collector 或云端，不将导入 SQL 或参数发往外部。导入/导出字符串都按不可信数据展示，不能执行脚本或加载外部资源。

## 本轮验收边界

执行定向/反向、真实子 JVM、真实驱动、平台非 GUI 夹具、签名与最终统一门禁。GUI视觉、焦点、真实主题与窗口行为仍待后续验收。任何局部测试结果均不等于全部计划完成或可发布。
