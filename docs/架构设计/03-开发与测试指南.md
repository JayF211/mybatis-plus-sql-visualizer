# 03 · 开发与测试指南

> 系列文档（docs/架构设计/）：`01` 架构总览 → `02` 核心流程详解 → `03` 开发与测试指南（本文）。

## 1. 环境准备

| 项 | 要求 |
|---|---|
| JDK | 17（Kotlin jvmToolchain 17） |
| Gradle | 项目 wrapper（`./gradlew`） |
| IDE | 日常开发用 IntelliJ IDEA Ultimate 2026.2.1（构建基线 2024.3.7.1） |
| 网络 | 首次构建下载平台依赖；受限时可经本地代理（127.0.0.1:7890） |

## 2. 构建与运行命令

| 命令 | 用途 |
|---|---|
| `./gradlew runIde` | 启动沙盒 IDE（日常验证 UI；注意：日常 IDE 加载的是已发布旧 jar，新改动须在沙盒验证） |
| `./gradlew test` | 全量测试（2682 用例，权威串行兜底） |
| `./gradlew clean test --no-build-cache` | 无缓存全量（编译问题排查用，~2m） |
| `./gradlew clean test` | **带缓存全量（实测最优 ~1m03s，日常用这个）** |
| `./gradlew test --tests "cn.song.mybatisplus.visualizer.reverse.*"` | 定向测试（按包/类过滤） |
| `./gradlew testShards` / `testShard1` / `testShard2` | 并行分片测试（2 片，独立沙盒目录防 PersistentFS 互踩；新增测试类加入最小编号片） |
| `./gradlew verifyPlugin -PverifyIdes=243` | 插件验证（默认 243+253+262；`minimal`=243+262） |
| `./gradlew writeUpdateManifest` | 生成 `update/update.json`（Gitee 抢先体验检查源；`preview.update.json` 为草稿，发布时同步） |

> 构建脚本要点（build.gradle.kts）：`instrumentCode=false`、`buildSearchableOptions=false`（Windows 中文环境规避）；changeNotes 由 `patchPluginXml` 从 CHANGELOG.md 注入；`-PverifyIdes` 控制验证 IDE 集。

## 3. 测试体系

### 3.1 三类测试风格（无自定义测试基类）

| 风格 | 继承/形式 | 适用场景 | 数量 |
|---|---|---|---|
| Light fixture | `BasePlatformTestCase` + `myFixture.configureByText("Entity.java", …)` | PSI 解析/定位/gutter/补全/面板/历史导航（同文件或临时目录内联 fixture） | ~105 |
| Heavy | `HeavyPlatformTestCase` | 完整平台语义：跨文件索引、真实 HttpServer（更新链路）、参数类型解析 | ~7 |
| 纯 JUnit | `org.junit.Test` | 零 IDE fixture 的纯逻辑：模型、生成器、解析器、方言、OGNL、缓冲、分享格式化、真实场景回环 | ~120 |

**fixture 约定**：

- **无 testData 目录**——所有 fixture 用 Kotlin 三引号字符串内联（`configureByText("Entity.java", """…""")`）。
- 测试模型表统一用 `car_device_info`（对齐 README 示例）。
- 纯逻辑测试在 KDoc 注明「纯 JUnit / 无 PSI / 零 IDE fixture」。
- Light 测试不可测 DataContext/performTypingAction（headless 限制）；内嵌编辑器补全（非项目文件）需 `UiCompatibleDataProvider` 包装（2025.3+ 平台陷阱）。
- **UI 交互测试**（F-44 系列沉淀）：headless 下 `JCheckBox.setSelected` 不触发 ActionEvent，须 `doClick()`；`invokeAndWait{空任务}` 泵不动 `invokeLater` 队列，须 `UIUtil.dispatchAllInvocationEvents()`；`BasePlatformTestCase` 同类方法共享临时项目目录且残留不清，每个测试 setUp 自清理。
- 生产代码为可测性暴露 `internal` 接缝（sealed class + resolve* 函数，如 `LogJumpTarget` / `HistoryJumpTarget` / `resolveEntryJump`），是本仓认可的「生产可测化重构」模式。

### 3.3 测试编写约定

```kotlin
/**
 * 测试主题（任务ID）：一句话 + 覆盖点清单
 */
class XxxTest : BasePlatformTestCase() {
    fun `test 场景`() { … }
}
```

- KDoc 格式统一：`测试主题（任务ID）：一句话+覆盖点清单`；main 代码同理（中文 KDoc + 任务 ID）。
- **代码内不留 TODO/FIXME**——待办写进 docs/开发计划/ 文档（带任务 ID）。
- 测试断言数量变化（如 4→5）是并行会话互相踩踏的典型信号，见第 6 节。

### 3.4 EDT 与 PSI 读取红线（T-M44 真机实证，2026-08-16）

**UI 回调（elementChosen / treeSelection / ListCellRenderer / mouseClicked 等）里的任何 PSI 属性读取
（`name` / `qualifiedName` / `getIcon` / `containingFile`）必须包 `ReadAction.compute`**（EDT 上同步执行、
语义不变）——这些属性不是纯字段读取，暗含 stub 树访问（`getStubTreeOrFileElement` / `ensureParsed`），
IDEA 2026.2 在 EDT 上硬抛 `RuntimeExceptionWithAttachments`（用户真机双实证：`createEditor` 的
`createFileFromText`、`ClassPickerField.elementChosen` 的 `getQualifiedName`）。

**headless 测试测不到这类问题**：unit test 模式关闭线程断言（`isUnitTestMode`）+ 测试缝（pickForTest 等）
绕过真实回调 + 无真实 AWT EDT 派发——验证只能 runIde 沙盒或用户真机。审计 UI 链路时把 PSI 属性读取
一律视为 stub 访问，不要判「轻量」；改动此类路径后跑沙盒实测（计划里的「沙盒兜底」要真的做）。

## 4. 扩展指南（常见任务改动点）

### 4.1 新增 Wrapper 类型（converter SPI）

1. `model/WrapperChain.kt`：`WrapperType` 枚举加新值；
2. `converter/`：实现 `WrapperConverter`（`supportedTypes` + `convert`）；
3. `converter/WrapperConverter.kt`：`ConverterRegistry.converters` 列表追加；
4. `psi/WrapperLocator.factoryWrapperType` / `wrapperTypeOfChainHead`：新类型来源识别（工厂/构造）；
5. `ui/SqlPreviewService.preview`：检查消费语义分支是否需要排除守卫（参考 `UPDATE_DELETE_JOIN_TYPES`）；
6. 测试：converter 分发 + 定位 + 面板链路（参考现有新增类型的测试模式）。

### 4.2 新增数据库方言

1. `sql/Dialect.kt`：`DialectRegistry` 加方言实现（`renderLimit` 分页子句 + 标识符引号）；
2. `sql/SqlKeywords.kt`：方言保留字集合；
3. `config/PluginSettings`：方言默认值不变（用户在设置页选）；
4. `config/PluginSettingsPanel`：下拉选项源（如方言列表来自 `DialectRegistry` 则自动）；
5. **upsert 形态（T-M43）**：`renderUpsert` 覆写——有原生简洁 upsert 语法则实现（MySQL 系 `ON DUPLICATE KEY UPDATE`、PG 系 `ON CONFLICT`），否则保持默认 null（渲染降级纯 INSERT，SQL 保证可执行）；
6. 测试：`DialectTest` 加用例（分页/引用/保留字/upsert 四件套）。

### 4.3 新增设置项（⚠️ 必须检查全部调用点接线）

1. `config/PluginSettings.State` 加字段（默认值进 companion）；
2. `config/PluginSettingsPanel`（或对应子页 `*Configurable` + `SectionConfigurable`）：表单 UI + apply/reset/isModified 三方法联动（`isModified` 漏挂 = 改动被平台静默丢弃，实证 D1 缺陷）；
3. **消费点接线**：搜索该设置的读取点（历史教训：新增参数必须检查全部调用点——`renderSql`/`parserConfig`/缓存签名等）；
4. 若影响解析结果（如表相关），加入 `SqlPreviewService.tableConfigSignature()` 缓存签名，否则改设置不生效；
5. i18n：`src/main/resources/messages/MpSqlVisualizerBundle.properties`（en）+ `_zh` 双语；
6. 测试：`PluginSettingsPersistenceTest` 持久化 + 消费点行为测试（参考 `SqlLogManagerBehaviorTest` 设置生效性模式）。

### 4.4 新增 gutter / 触发入口

- 参考现有 9 个 `ui/gutter/*LineMarkerProvider`：`getLineMarkerInfo` 只做 O(1) 语法判定（性能红线），`navigate` 统一走 `SqlPreviewService.previewAsync` + `showResult`（JPA 族各自调 `SqlPreviewService.previewXxx` 方法）；
- `plugin.xml` 注册 `codeInsight.lineMarkerProvider`（带 language 属性；可选插件语言——如 Kotlin——的注册放 `kotlin-optional.xml`，避免主描述文件解析不了语言 ID）；
- 设置项 `showGutterIcon` 开关接线（`gutterEnabled`）。

### 4.5 新增 SQL 补全/高亮能力

- 预览编辑器已改用 **IDEA 原生 SQL 语言**（M34：自研 MP_SQL_Preview 语言的全语言注册 Contributor 不被调度，已弃用 parserDefinition/fileType 注册）；自研补全 `ui/highlight/SqlCompletionContributor` 显式注册 `language="SQL"`；
- 源码（XML/注解）补全：`XmlSqlCompletionContributor` / `AnnotationSqlCompletionContributor` 共享 `SourceSqlCompleter` + `SourceSqlSuggestionFactory`；Wrapper 链上下文补全：`ui/completion/WrapperCompletionContributor`（O(1) 文本判定，无 resolve）；
- 非项目文件的词法着色/格式化复用 `SqlLexer` / `SqlFormatter` / `SqlHighlightColors`（日志列表 HTML 渲染同源）；
- 陷阱：内嵌编辑器（非项目文件）补全需 `UiCompatibleDataProvider`；autopopup 需面板自建（DocumentListener + commitDocument + explicit=true），参考 `SqlInputEditor`。

### 4.6 新增 JPA/Hibernate 识别能力

1. `psi/jpa/`：新 Locator（O(1) 语法判定 + 查询文本/实体提取），仿 `HqlQueryLocator`；
2. `converter/jpa/`：转换器（查询文本 → SQL），实体解析统一走 `JpaEntityResolver`（注解）或 `HbmXmlEntityResolver`（.hbm.xml）；
3. `ui/SqlPreviewService`：加 `previewXxx` 方法（gutter 点击入口），展示复用 `showResult`；
4. `plugin.xml`：注册 gutter（language="JAVA"）；
5. 测试：converter 纯 JUnit + Locator Light fixture + 端到端（参考 `converter/jpa` / `psi/jpa` 现有测试分工）。

## 5. 开发约定

### 5.1 文档三处同步（每次功能交付必做）

| 位置 | 内容 | 粒度 |
|---|---|---|
| `docs/变更记录.md` | 全量变更记录总册（**唯一权威**，只追加） | 任务/里程碑 ID（T-Mxx.x） |

### 5.2 提交信息格式

```
type: T-Mxx.x 一句话（细节用顿号/分号补充，含实证结论）
```

## 6. 🔴 并行开发铁律（多智能体协作）

本仓库常有多智能体并行开发，**任何 `./gradlew` 命令执行前必须先查共享登记表**：

```bash
python C:\Users\USER\.zcode\cli\parallel_tasks.py check    # 查活跃任务
python C:\Users\USER\.zcode\cli\parallel_tasks.py register # 有活跃任务时登记独立沙盒（分片 testShard1/2）
python C:\Users\USER\.zcode\cli\parallel_tasks.py done     # 跑完注销
```

- 有活跃任务 → **禁止直接跑默认沙盒全量**（共享沙盒互踩损坏 PersistentFS，实证 191 失败+卡死）；
- 绝不 kill 对方的 Gradle daemon / 进程；共享文件只动自己的行；
- 以 git 提交节奏判断对方活跃度；`--tests` 过滤避开对方测试领地；
- 被踩的症状：PersistentEnumerator corrupted、用户映射区域错误、断言计数中间态（如 4→5）、NoSuchMethodError（Kotlin 增量残留 → `--rerun-tasks`）。

## 7. 发布流程速查

1. 全量测试绿（`./gradlew clean test`）+ 插件验证（`verifyPlugin -PverifyIdes=minimal`）；
2. `docs/变更记录.md` 追加任务记录 + `CHANGELOG.md` 新版本块（`patchPluginXml` 自动注入 changeNotes）；
3. `./gradlew writeUpdateManifest` 更新 `update/update.json`（Gitee 抢先体验检查源，Gitee raw 托管）；推送前可先用 `preview.update.json` 草稿 + `local-manifest-server.py` 本地清单沙盒验证通知效果；
4. 稳定版由 JetBrains Marketplace 推送；Gitee 通道为内测抢先体验（`autoCheckUpdate` 默认关，用户主动勾选开启；支持「忽略此版本」）；
5. 版本号 = `YYYY.M.D`（gradle.properties），一日一版；
6. 发布说明（docs/发行说明/）按规范编号；覆盖更新需重启（环境 performanceTesting 插件否决动态卸载，属已知环境限制，插件本身达标）。
