### 3.2 F69 关账：上轮定性证伪（本轮最重要回验产出）

上轮 F69 写「QuerydslConverter（object）静态 `tableCache = mutableMapOf<PsiClass, TableInfo>()`：强引用 PsiClass 键、无淘汰无失效」（出证 :569-571 亲测）。本轮 B 路子代理质疑该定性，主控双锚点亲验**证伪**：

### 4.3 t-statementweave 织入链专项（C 路：JDBC 热路径红线首评）

审计对象=对驱动 Statement/PreparedStatement 方法体的 ASM 入口+出口双插桩（StatementWeaver.java，45c9998），热路径频率=用户应用每条 SQL 一次。**这是插件全部代码中唯一运行在宿主应用热路径上的新增面。**

- **热路径逐指令**：入口 3 条指令+1 次 invokestatic（ALOAD 0/onStatementEnter/LSTORE）；每个返回点 12~16 条指令（结果存槽→压 6 参→onExecuteExit→恢复→原返回指令），每次调用只走一个出口点。两个 invokestatic 均单态调用点，C2 必然内联；nanoTime 为 JVM 内建。
- **停采短路**（结论：成立）：入口第一个判定即 `AgentState.isDisabled()` volatile 读（SqlHookCallbacks.java:73），短路则不碰 ThreadLocal 不取 nanoTime 直接返回 0；出口回调 `token==0L` 比较即返（:93-95）。停采稳态≈15~30ns/SQL（2 次 invokestatic+栈操作+1 次比较），相对任何真实 SQL 耗时 <0.1%。唯一残留=IRETURN/LRETURN 路径的装箱发生在织入字节码里、先于回调判定（StatementWeaver.java:256-265），停采时 executeUpdate 每次仍付一次 Integer.valueOf——Integer 缓存覆盖多数 updateCount，超缓存场景一个即刻弃置的 16 字节对象，可忽略（F75 伴记）。
- **开采稳态**（结论：与既有代理通道同级）：每 SQL ≈3~25µs，构成=2 次 nanoTime+事件组装（getStackTrace 主导，与代理通道 emitEvent 逐行同口径，属既定采集成本）；织入通道真正新增的重活只有归属链 `getMethod("getConnection")` 未按类缓存（SqlHookCallbacks.java:157，0.1~1µs/SQL，本轮 F75）。相对 1ms 级 SQL 约 0.3~2%，无数量级劣化。
- **WeaveGate ThreadLocal**（结论：正常）：enterProxy 在 try 外、exitProxy 在 finally（StatementHandler.java:101-108），异常路径不留脏态；exitProxy 是 set(FALSE) 而非 remove——每线程恒定一条 Boolean 缓存常量条目，无增长无泄漏，状态机语义成立。代理门窗口内织入双钩子空转成本 ≈30~60ns/SQL，与 WeaveGate.java:11-12 自述一致。
- **StatementRegistry**（结论：弱键清账正常，全局锁=F78）：值 Ctx 只含 sql/url/batch 字符串，不引用键，无 value→key 强引用链；`Collections.synchronizedMap(WeakHashMap)`（StatementRegistry.java:36-37）全局互斥、生产码无迭代操作；EXEC_CTX 每次执行与 addBatch 每次过同一把 monitor，无竞争 ~15-20ns，连接池高并发下是理论串行化点但量级远低于 SQL 耗时（本轮 F78）。unresolvedCount 为 AtomicLong 单变量。
- **反射缓存**（结论：正常）：UrlResolver 用 `ConcurrentHashMap<Class<?>, Method>`（:19-20），键是 Class 对象本身、天然规避跨 loader 错拿；强值钉 loader 仅在反复重部署驱动 jar 场景按 loader 数累积（个位数~几十，有界）。
- **一次性成本**（结论：正常）：插桩仅发生在类首次加载或 attach retransform 时，COMPUTE_FRAMES 单类毫秒级、登记面 12 类总停顿毫秒级；retransform 替换已 JIT 方法触发一次去优化+重编译，发生在 attach 瞬间非持续。
- **F74 批串无界**（本轮唯一低危发现，见 §5）：`ctx.batch` 只增不清——executeBatch 出口 `toString()` 读后不复位（SqlHookCallbacks.java:106）、addBatch 每次追加无上限（:133-136）、clearBatch 未登记未织入（git grep 生产码零命中，唯一命中=测试假驱动 FakeVendorFixtures.java:82）。语句存活期内内存与 toString 拷贝耗时双无界，且事件 SQL 混入历史批次陈旧语句（正确性偏差）。代理通道 batchSqls 有同型旧行为（本分支之前已存在），织入通道是新增的第二份独立累积。
