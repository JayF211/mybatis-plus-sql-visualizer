## 1. 调研范围与方法

三个口径先行钉死，其中第一个相对首轮做了修正：

1. **「所有功能」按分支归属计，可见性改用双轴**。首轮的可见性轴是「已上架 / 待合流 / 分支内」——那时一半资产滞留分支。四天后的现状是合流已闭环，几乎所有资产都在 master，这条轴失去了区分度；真正拉开差距的轴变成了 **master 轴（合并态有什么）与发行物轴（tag / Gitee / Marketplace 用户实际拿得到什么）**。本轮全部功能资产按双轴标注。
2. **计数以实测为准，历史声明作废**。本轮实测订正了两处既有口径：项目记忆中「v2026.9.18 正式版 Gitee 已发」经 releases API 全量核实**不存在**（21 个发行版最新为 beta.4，第九轮报告「指向从未创建的发行版」的口径与此吻合）；首轮报告「13 个分支引用」经四天收敛后为 8 条分支。
3. **首轮诊断逐项复核，不继承结论**。首轮 §6 的四个短板逐条到源码与线上核实（§4），两条候选新功能先做锚点核实再决定是否立项（§8，两条全部被既有形态覆盖，未立项）。

方法上，三路并行只读子智能体分工：master 注册面与源码规模盘点 / 七条非 master 分支拓扑与增量画像 / UX 首触旅程与市场素材核实；主智能体对承重结论复核（远端 tag、Gitee 发行版、21 tag MCP 断层、PreviewResult 锚点）。

## 6. 劣势与风险

1. **发行物断层（首位，已从「债」升级为「结构性风险」）**。21/21 发行 tag 无 MCP、正式版双渠道皆无、引导与安全件全部锁在 master、5383 绿门禁没有对应任何用户可得的产物。每多交付一天，剪刀差大一圈；任何一次工作树事故（370 提交未推放大了该敞口）损失的将是「从未存在的发行物」。N-31 三处整改两项未动，构成上传的直接前置。
2. **推送债继续冲峰**。master 370 + dev 52 + k2j 15（锚点文件自述「未 push」）= 437 提交仅存本地。三天前第九轮记录为 369+52——增速虽缓于上轮，但「k2j 无远端备份的 15 提交」是新出现的敞口（该分支是 19 万行级移植形态）。
3. **冷启动沉没成本继续累积**。295 下载持平、0 票 0 评论第六周、需求池 0 帖、增速 +1/日。首轮开出的首评与描述动作（N-24）至今零执行痕迹；获客素材（增强捕获、MCP 审计、安全纵深、9 GIF）已闲置一至两周。zMyBatis 接线冲刺 1~2 周量级的窗口压力在第九轮 §10 风险 3 已述，不赘。
4. **分支治理回潮**。O-22 闭环两天后：3 条新分支（其一无远端）、5 条旧 stash、1 个悬空引用。单人带宽的「引用管理成本」在回升，且 t-gif-rec-mcp 的 13 个提交是当前唯一未留底的活动资产。
5. **K2J 从「纯负债」转型为「滚动同步义务」**。首轮判其「只有成本没有进展」，本轮事实已变：src/main 557 文件 100% Java 化、门禁 5390 绿、MCP 全链覆盖——并行形态实际成形。但它落后 master 1003 提交，每轮同步（最近一次吸收 123 提交）的成本持续滚动发生，而「同步 vs 合并 vs 终止」的三选一决策（O-24）仍悬置。**决策每拖一周，沉没成本曲线就更陡一分**。
6. **挂起裁决悬置**。t-testdb-driver 的 4 个 DB 集成类 7 项断言失败按「不掩盖」策略挂起待裁，testDatabase 门禁的真实含义（10 绿是绕开了什么）需要一个显式决定。

## 7. 用户体验专项诊断（第二轮）：从「引导缺失」到「引导已建未达」

首轮的判语是「短板全在第一次接触」；四天后的现状是**第一次接触的所有补丁都写完了，只是用户拿不到**。三个具体后果：

- **新用户的插件画像比官网叙事小两圈**。官网首页宣传 v2026.9.18 画像与 MCP 十工具（IDEA 2025.2+），Marketplace 在售 2026.9.14 无 MCP——按官网叙事装在售版的用户，第一诉求直接落空。对外口径的统一纪律应当写进发行清单：**官网能力叙事的可见性前提与 Marketplace 同步**。
- **对外数字口径需检点**。官网宣称「加入超过 500 名开发者」，Marketplace 实测 295 下载（Gitee 侧下载量未并入统计）。冷启动期信任是最稀缺资源，宁可写「Gitee+Marketplace 合计」并给出处，不可留一个无法回查的总数。
- **素材链有断点**。screenshot-01~06 六张 PNG 在库零引用；MCP 演示 GIF 在 t-gif-rec-mcp 录制中（正是 §6 劣势 4 那批无远端备份的提交）——它是 MCP 面上市叙事的直接配套，收口节奏应与发行窗口绑定而不是独立漂着。

值得肯定的一面：引导三件套的形态质量高（一次性 + 可关 + 空态就近指引 + 零产出诊断行），「会不会坏」维度的防御（性能默认零开销、243 全宽、安全纵深）依旧充分。短板只剩一个字：**发**。

## 8. 新一轮建议（编号承接：N-31~N-34 / O-40~O-44 已占用，本轮自 O-45 起）

## 9. 长期演进路线（第二轮）

**近期（本周，唯一主线）**：出场清账专门窗口。这一轮的判断比首轮更硬：首轮说合流是主线，是因为分支资产还在涨；本轮发行是主线，是因为**所有其他资产的价值兑现都以它为闸门**——MCP 十工具、引导三件套、安全纵深、5383 门禁、9 张 GIF，全都在闸门内侧排队。

**中期（2~4 周）**：P1 三吸收件 + MCP 演示 GIF 收口（随发行窗口）+ O-45 治理 + K2J 决策评审收口。窗口末评估一个「能力大版本」叙事（增强捕获默认通道 + MCP 全链 + 安全纵深 + 引导三件套齐活），配描述重发——素材全部在库。

**远期（季度+）**：三件事不变但排序微调——其一，**口碑飞轮**升为第一优先（0 帖 0 票已进入第七周，它从「风险」变成了「越拖越贵的负债」，首评引导与需求池激活是飞轮的启动扭矩）；其二，agent 生态卡位固化（sqlv_* 十工具 + ACP 通道是全场最宽 agent 面，窗口期内成为中文 MyBatis 生态 agent 协作默认选择的先手只有一次）；其三，验证纵深（方言矩阵真机化、t-testdb-driver 裁决收口）。K2J 按决策结论终局化。

产品锚点全程不动摇：ORM SQL 调试闭环。判断新功能做不做的标尺沿用首轮定案——扩张「调试闭环内的深度」就做，跨出闭环做数据库产品形态就不做；本轮补一条时序修正：**闭环内的深度也要排在发行物追平之后**。

## 10. 落地优先级建议

如果只做三件事：**出场清账专门窗口**（N-31 整改 → 含 MCP 正式版 → 双通道上传 → N-24 随行 → push 留底；这是唯一一件「其他事都给它让路」的事）、**第九轮 P1 三吸收件**（两天量级，可信度叙事落）、**t-gif-rec-mcp 收口 + 留底**（MCP GIF 是发行窗口素材链的一环，顺手消掉最大的无备份敞口）。

一句话总结本轮：四天前说「不缺功能、不缺质量、不缺流程，缺的是最后一公里」；四天后最后一公里修完了三分之二——合流闭环、引导落地、素材在库——剩下的那一段（发行）被证明是唯一还能让五千三百个绿测试、十工具 MCP、引导三件套全部「白做」的环节。它已经不再是众多债务中的一条，而是其他一切资产产生回报的总闸门。
