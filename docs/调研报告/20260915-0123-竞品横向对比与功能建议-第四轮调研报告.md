## 2. 当前插件功能与定位（v2026.9.14 正式版 + 集成链）

**插件**：SQL Visualizer（id `cn.song.mybatisplus.visualizer.mybatis-plus-sql-visualizer`，Marketplace 页 33633），master 已发行 v2026.9.14（提交 `3c3a815`，CHANGELOG 40 条：Added 7 / Changed 5 / Fixed 20 / Test 8），集成链另有 Unreleased 三条 Added（回滚 SQL 按钮、预览四件套、MCP 三工具）与两条 Changed。免费开源，IDEA 2024.3+（sinceBuild 243，无 untilBuild），运行时仅依赖 JSqlParser。

## 4. 专项调研与格局修正

### 4.1 CodeHelperPro MCP 线——上轮「竞品 MCP 全空」结论失效

Marketplace updates 的 changeNotes 实测（直装版与付费版）：3.5.7（07-02）「新增 MCP 服务器操作支持」起步；3.5.8/3.5.9（07-24/08-03）生成 CRUD 代码的 MCP 工具；3.6.2（08-24）数据库表右键「调用 MyBatis MCP Prompt」一键复制 + 生成器配置读写工具；3.6.5 内容（09-09，随付费版上架）**MCP 工具 `validate_mybatis_mapper`——对 Mapper XML 与 Java 接口做深度静态契约校验，自动识别动态 SQL 标签并给置信度分级（纯静态 SQL 置信度 1.0 免跑单测，动态标签给针对性测试指引）**。

三点判断：

1. 这是全场唯一一块投向「静态 Mapper SQL 分析」的新功能，与写前预览同源。但形态错位：它做的是校验器（告诉你 SQL 可信度），本插件 MCP 三工具做的是渲染器（直接给出可执行 SQL 与 schema 上下文）——agent 消费 SQL 时，校验是辅助、渲染是主链。位差叙事要主动讲清（§8.3 N-16）。
2. 它验证了这个方向的市场投入产出，窗口从「无人」进入「有人抢跑边缘」。本插件的平台体系注册位（一次注册覆盖 AI Assistant/Junie/ACP/外部 Claude Code 全部 client 面）仍领先自建 MCP 的触达面，但执行要快。
3. MyBatisX 待审版内容未知。若它也带 MCP/预览类功能，凭 540 万用户盘可以瞬间抹平先手——这把 §9 风险 2 的权重顶了上去。

### 4.2 其余竞品动向

Ultra（113 天未发版，仓库半死）、Analyzer（克隆点零新提交，兼容墙 251.* 维持）、Log Free（纯兼容维护）、Flex-Helper（沉寂）、JPA Buddy（EAP 跟随，不碰 MyBatis）——上轮评级全部维持，无一上调。Analyzer 若复活（换兼容区间/恢复提交）应升回月检，当前降为季检即可。

一天 60 提交、353 文件（+12,800/-8,065）、+126 star（现值 19,451）、约 +64 commits（现值约 6,587）——日更机器节奏维持。本周期主题是插件生态发布（v0.6.12：Go SDK 插件模板、plugin-cli、条件表单字段、SSH 密钥选择器、framed binary 传输）加一批稳定性修复；**上轮吸收清单的 13 条核心机制（dml_preview、无界写判定、降级横幅、EXPLAIN 多视图、多结果页快照、keyless 守卫、临时写解锁、AI 提案矩阵、schema 预算化注入）所在文件全部零 diff，无一失效**。增量中值得吸收的 5 点见 §7；插件生态平台化（插件向 MCP 面贡献自己的工具的工具桥、插件市场 R2 catalog）是独立产品的扩张路线，与本插件无关，记录不吸收。

## 9. 风险

1. **双轨债升级（首位）**。上轮是「分支睡觉」，本轮是「集成链与 master 双向漂移」：集成链 75 提交领先的同时 master 又走了 29 提交，两边的 CHANGELOG/测试计数/文案各自演化，t-market-internal 还悬在第三轨（4081 基线与 4204+ 基线交叉）。每拖一天，合流冲突面都在变大——这与第三轮的教训是同一个，只是体量翻倍。
2. **MCP 生态位窗口收窄**。CodeHelperPro 三连发验证了方向并逼近能力圈（校验器与渲染器同源），MyBatisX 待审版是 540 万用户盘的盲区武器。先手仍在本插件（平台体系注册位 + 确定性渲染），但窗口从「无人竞争」变为「有人抢跑边缘」，N-16 的执行窗口以周计。
3. **冷启动失速**。+14/日 → +2/日，最强版本（40 条 CHANGELOG）缺席最大渠道，0 评论破局动作继续空转。势头窗口不等人：赛道大盘死寂意味着现在占住的搜索位（"sql visualizer" 第 1）和过审记录是仅剩的复利资产。
4. **AI 替代（延续，注脚更新）**。锚定 IDE 深度集成、执行期确定性、方言正确性背书的立场不变；MCP 化仍是对冲，但 CodeHelperPro 的进场提醒了对冲本身也在变成竞争——最终比的是谁的 agent 工具面先被生态默认接入。

## 10. 落地优先级建议

如果只做三件事：**集成落 master**（t-fourplans 合回 + t-market-internal 归属决断 + 工作树遗留清理，让 4207 绿的成果见用户）、**市场端闭合**（v2026.9.14/9.15 上市场 + N-15 冷启动动作，修势头拐点）、**N-16 MCP 合规核查**（structuredContent 半天量级 + 位差叙事，守住刚拿到的生态位）。

一句话总结本轮：上轮的问题是「成果在分支上睡觉」；这轮分支醒了、集成做完了，却发现最后一公里断了两处——代码没到 master，版本没到市场；与此同时第一个 MCP 对手进场，好在它做校验、我们守渲染，位置仍是我们的，但这次要跑着守。
