## 1. 总结论

**结论维持并加固：发行基线（master 040d127，在售用户实际运行的代码）对 IDEA 无体感影响。本轮不再是「零 diff 承袭」，而是把启动链、常驻线程、轮询、编辑器交互、内存、MCP 六个轴从第一性重扫一遍，未发现任何「会拖慢 IDEA」的新形态；新增发现 F69~F73 共五条全部为低/微危有界项，无一改变总结论。本轮对后续轮更有价值的产出是三处台账口径勘正入册（§2）——历轮「构造 13」「具名线程 0」「battery 锚点行号」的 grep 模式失真被逐一纠正。**

支撑结论的六个事实（本轮全部一手重扫）：

1. **启动路径零重活**：全描述符零 FileBasedIndex/stub 索引扩展、零静态 `<listeners>` 注册、零 applicationService/projectService XML 声明（11 个服务全为 light service 按需实例化）；五个 postStartupActivity 的 execute 本体全是 O(1) 级（读设置＋布尔门＋挂订阅），重活全部后移到后台线程或首次事件。默认安装面的启动确定成本≈3 个 O(1) 回调＋PluginSettings 一张小配置反序列化＋Onboarding 一条 messageBus 订阅（弹过即拆）。
2. **严格常驻定时源 = 0**：5 条 daemon 池线程中仅 2 条恒活且闲时零任务零唤醒；周期环全部带门（armed 稳态唤醒 ≤1 次/秒、空闲未武装 = 0 次/秒），EDT 上零 Thread.sleep。
3. **按键链近乎零税**：插件不向用户源文件的高亮链注入任何成本（零 parserDefinition/syntaxHighlighterFactory/语言注入 EP——历轮 battery 里的 XmlSynHiGate/SqlMapperParserDefinition 是 dev 预览链专有，master 在售面根本不存在）；全局每击键成本唯一点是 ExecDocAutosaveHost 应用级 DocumentListener，有身份快判＋防抖短路（F72 微）。
4. **daemon 行标快速路径以 O(1) 为主**：13 类 gutter provider 逐族定性，两处例外（CriteriaQuery 全块扫描 F70、Kotlin 逐叶行扫 F71）有界且条件触发。
5. **内存面绝大多数缓存有显式上限**（50/512/1024/4096/200/500/64 族），无上限点仅 3 处且规模受事实约束（methodCache=F57 在册、QuerydslConverter.tableCache=F69 本轮新登记、resolver 字符串键缓存带 clearCache）。
6. **MCP/ACP/agent 零闲转成本**：MCP 不自建 server 不开端口，filter 是被动 EP（无客户端连接时零回调）；ACP 探测式注册；agent jar 懒提取、注入的是用户应用 JVM，IDE 侧零启动面。
