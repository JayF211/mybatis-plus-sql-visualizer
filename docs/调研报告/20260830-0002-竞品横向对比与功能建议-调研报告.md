**创建时间**：2026-08-30
**文档定位**：基于子智能体并行调研（代码库功能梳理 + Marketplace 实时数据抓取），横向对比同类产品，输出新一轮功能与优化建议。本文是 `20260822-1500-竞品分析与优化建议.md` 的迭代版：上次的 F-1~F-9 多数已落地（JOIN 关系图、性能分析规则引擎、复杂度评分、Kotlin 支持、拦截器模拟、历史记录、设置页重构），本文不再重复，只给基于最新竞品数据的增量建议。

**数据来源**：JetBrains Marketplace API 实时抓取（2026-08-29），下载量/评分为 API 原样数值；付费插件价格档位 API 不返回，标"评论推断"或"未获取"，未获取项不编造。

## 1. 当前插件功能与定位

**插件**：SQL Visualizer（id `cn.song.mybatisplus.visualizer.mybatis-plus-sql-visualizer`，Marketplace 页 33633），v2026.8.21，免费开源，IDEA 2024.3+（sinceBuild 243，无 untilBuild 上限）。运行时仅依赖 JSqlParser，MyBatis-Plus 零运行时依赖。

**一句话定位**：IDEA 内 MyBatis-Plus / MPJ / JPA / Hibernate 的 SQL 调试闭环——写前静态预览、跑后日志还原、原地执行验证。

### 1.1 已有能力（按用户旅程）

| 阶段 | 能力 |
|------|------|
| 写代码时 | 9 类 gutter 锚点（Wrapper 链 Java/Kotlin、注解 SQL、XML 语句、JPA 派生方法、JPQL @Query、CriteriaQuery、HQL 等）；Wrapper 方法链补全；XML/注解 SQL 补全（表/列/#{} 参数/OGNL） |
| 预览 | Alt+Shift+Q 转 SQL；动态条件复选框、参数回填、静态常量内联、批量按列展开、逻辑删除/乐观锁注入、无 WHERE 警示、9 方言渲染（含达梦/人大金仓，真实引擎验证） |
| 跑起来后 | 控制台日志自动捕获（MyBatis Preparing/Parameters、Hibernate binding、JdbcTemplate 三族解析器），去重/过滤/耗时/慢查询/分组，批量还原 |
| 验证 | 预览面板内嵌 IDEA 原生 Database 控制台，Ctrl+Enter 直接执行（Ultimate，Community 优雅降级） |
| 反向 | SQL→MP Java 代码（四形态，增删改查+JOIN+子查询，生成可编译） |
| 分析 | JOIN 关系图（自绘 Swing）、SQL 性能规则引擎+复杂度评分、多租户/数据权限/动态表名拦截器模拟、SQL-Java Diff |
| 周边 | 四 Tab 工具窗口、历史记录、左侧树设置页（中英双语/导入导出/自更新）、内嵌浏览器帮助文档 |

规模：源码 210 个 .kt，测试 194 个 .kt（约 2500 用例，4 分片并行+DB 集成沙盒）。

### 1.2 主轴与周边

主轴是**预览—还原—执行**三合一闭环，这是产品立足点。周边（JOIN 图、性能分析、拦截器模拟、反向转换）是差异化加深器，单独拆开都不构成购买理由，合起来构成"别人没有的完整体验"。

### 2.4 内置 Database Tools 的能力边界

IDEA Ultimate/DataGrip 内置 SQL Console、数据编辑器、查询历史、EXPLAIN 计划、格式化，覆盖了"写、存、跑、看数据"。**内置做不到的四件事**：从 Java 代码静态推导 SQL（Wrapper/Criteria）、捕获运行日志自动填参、XML 动态 SQL 按参数分支预览、日志到控制台的零拷贝流转。这四件事就是本产品的立身点。约束：内嵌执行依赖 Ultimate 授权。

## 3. 竞品用户抱怨清单（即机会点）

来自竞品评论区的高频抱怨，按出现频率排序：

1. **IDE 新版本适配慢/断档**——MyBatisX 2025.1/2025.2 大量催更，用户被迫手改 plugin.xml 版本号；MyBatis Log 新旧版本不兼容。这是所有竞品的第一抱怨。
2. **日志参数拼接边界错误**——逗号、空格、LocalDate、IN 引号漏加，几乎每个日志插件都被吐槽。
3. **工具窗体验差**——不能固定、每次重启手动从 Tools 打开（MyBatis Log Free）。
4. **付费激活/退款体验差**——MyBatis Log 付费后激活失败评论几十条，是付费转化的反面教材。
5. **同质化插件全部止步于"复制到剪贴板"**——有还原无执行，有执行无预览。

本产品对应现状：①无 untilBuild 上限，已占优但需持续保证；②有真实引擎验证通道（H2/SQLite/Testcontainers/DBX 七家族），是竞品没有的正确性背书；③工具窗常驻已有，自动开启体验可再打磨；④暂不收费；⑤闭环已成立。

## 4. 功能与优化建议

> 相对 20260822 文档的增量。已落地项（JOIN 图 F-1、性能分析 F-2、复杂度评分 F-3、Kotlin F-4、补全 F-5、拦截器模拟 F-6、历史收藏 F-7）不再列。

### 4.1 新功能建议

| # | 项名 | 描述 | 依据 | 优先级 |
|---|------|------|------|--------|
| N-1 | 真实 EXPLAIN 联动 | 预览/还原出的 SQL 一键跑 EXPLAIN，把真实执行计划与静态性能规则引擎的结果并排展示（静态标注风险+真实计划验证） | MySQL Explain（3.5 万下载）验证了"还原+explain"组合需求；本产品已有原生执行通道和规则引擎，是两者唯一能合体的人 | P0 |
| N-2 | 日志↔源码双向跳转 | 日志条目定位到产生它的 Wrapper 链/XML 语句源码位置，反向亦可 | JTracker 的"调用链定位"和 Mybatis Log Ultra 的"点击跳到代码行"都在做这个方向，是日志赛道下一个差异化点；20260822 的 O-1 提过未落地 | P0 |
| N-3 | Run/Debug 会话感知捕获 | 检测到 Run/Debug 会话启动时自动进入捕获状态、首条 SQL 出现时自动展开工具窗（可配置） | MyBatis Log Free 最大抱怨是"每次手动开"；MyBatis SQL Capture 已验证思路但只有 64 下载，做细做好即可收割 | P1 |
| N-4 | Wrapper→测试资产生成 | 从 Wrapper 链/接口方法一键生成可执行 SQL 回归脚本（.sql 文件）或带真实断言的 JUnit 用例 | MybatisCodeHelperPro 的"接口方法生成 testcase"是其付费卖点之一；本产品有静态预览+方言渲染基础，生成正确性更有保障 | P1 |
| N-5 | MyBatis-Flex 支持评估 | 评估给 MyBatis-Flex QueryWrapper 做同款静态预览的成本与用户基数 | Mybatis-Flex-Helper（1.8 万）证明 Flex 生态有同款需求；本产品解析框架若抽象得当，边际成本可控。先调研后立项，不盲目扩线 | P2 |

### 4.2 优化建议（存量增强）

| # | 项名 | 描述 | 依据 |
|---|------|------|------|
| O-1 | IDE 新版本适配保障体系 | 建立 EAP/正式版发布后的快速验证流程（verifyPlugin + 关键路径 runIde 冒烟），并把"新版 IDEA 发布即适配"写进 Marketplace 描述 | 竞品第一抱怨；本产品无 untilBuild 是先天优势，要把优势变成可感知的承诺 |
| O-2 | 参数拼接正确性回归+背书 | 把逗号/空格/LocalDate/IN 引号等竞品翻车场景沉淀为显式回归用例集，并在文档中宣传"参数还原经真实引擎执行验证" | 竞品第二抱怨；本产品已有七家族真机验证通道，缺的只是把正确性"说出来" |
| O-3 | Marketplace 描述与 README 差异化改版 | 核心锚点："别的插件给你文本，我们给你可执行的 SQL"；突出三点——Wrapper 静态预览全市场独家、预览即执行闭环、国产数据库方言（信创场景） | 日志赛道 118 个同质化插件里，描述页是用户做选择的第一现场，当前描述未把闭环差异讲透 |
| O-4 | 捕获面板体验细节 | 面板固定/自动开启/焦点行为打磨；捕获开关状态在工具窗标题栏可见 | 对应竞品抱怨 3；低成本高感知 |

### 4.3 不建议做

延续 20260822 结论：不做代码生成（MyBatisX 地盘）、不做数据库连接管理（Ultimate 已有）、不做 Spring 导航。新增两条：

- **不做付费订阅（现阶段）**——MyBatis Log 的激活/退款抱怨说明个人付费插件的信任成本极高；本产品免费开源+Gitee 抢先版通道已是获客优势。
- **不做纯格式化/美化工具**——红海且有 SaaS 免费替代，会稀释产品定位。

## 5. 风险

1. **框架官方内置预览**——MyBatis-Flex 官方/社区已有 SQL 预览，若 MyBatis-Plus 官方跟进同款能力，第三方空间被直接侵蚀。对策是趁窗口期把用户基数和品牌做起来，让"SQL 可视化"与本产品绑定。
2. **AI 助手的零成本替代**——"把日志贴给 AI 拼 SQL"正在成为部分用户的习惯，它免费且不需要零学习成本。对策是不与"文本处理"竞争，锚定 AI 做不到的部分：IDE 深度集成、实时捕获、原地执行、静态解析的确定性。
3. **同质化竞品向捕获赛道涌入**——MyBatis SQL Capture 等已开始做 Run/Debug 自动捕获，虽下载量极低，但说明思路不再独家。N-3 宜早不宜迟。

## 6. 落地优先级建议

如果只做三件事：**N-1 真实 EXPLAIN 联动**（把"预览—执行"闭环延伸为"预览—执行—诊断"，独家性最强）、**N-2 日志↔源码跳转**（日志赛道下一个共识方向）、**O-3 描述改版**（零开发成本，直接提升转化）。
