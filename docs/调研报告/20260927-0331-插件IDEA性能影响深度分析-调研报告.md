## 1. 总结论

**结论维持并扩展：默认配置下插件对 IDEA 的资源型性能影响仍可忽略；本批解冻的两条新代码线均未引入实质性性能敞口。** MCP 全动态化是一笔「资源换资源」的交易：以冷路径一次性 10 个 ASM 微壳类 + 1 个单例子 ClassLoader + 1 个有界 CHM 的常驻代价，换来启动面 EP 声明 −10 与启动期零平台 MCP 类型加载，每次工具调用热路径净增仅 ns~µs 级（1 次 AtomicLong + 2 次 CHM 操作 + 1 次缓存反射）；注册挂在 mcp-optional 唯一 postStartupActivity 的项目启动后台协程，不在 EDT、不在 IDE 启动主链。agent 侧 B′/机制 A 在 SQL 事件热路径的健康形态（at==0 直取）零新增分配，新增成本集中在「缓存身份=祖先浅帧且更深段全 JAR 帧」的特定形态（每事件重复付 at 次 Class.forName，无负缓存，被栈深钳制——F30）。红线十三族重跑零漂移（其中两族为本轮口径补全而非漂移，见 §3.1）；F18~F28 逐条回验全部维持（F27 前半口径收窄），T-PerfSweep8/9 目标文件区间零 diff 仍在册。本轮新开发现点 F29~F34：**1 低·建议修（F29 动态壳注册幂等性缺口）+ 1 微~低（F30 B′ 深帧探测重复反射）+ 4 登记/信息级**，无中高级。

支撑结论的四个事实：

1. **增量面全量过筛**：src/main 24 文件 + agent 3 文件 + mcpStub 3 文件逐文件深读（三路只读子代理），主控对全部承重结论逐行二遍实证（§7）；新文件内资源红线（Timer/sleep/Executors/具名线程/监听注册/现场正则）逐点 grep 全零命中或确认为存量。

## 4. 新增子系统审计（按链路）

### 4.1 MCP 工具线全动态化（T-McpDynamicToolset 三笔）

**壳类生成与生命周期**：注册入口 = mcp-optional.xml 唯一 postStartupActivity（`mcp-optional.xml:27` McpGateFilterRegistrar : ProjectActivity），每项目打开触发、跑在平台项目启动后台协程（非 EDT）；`registerOnce` 以应用级 AtomicBoolean 做全应用一次闸（`McpToolsetDynamicRegistrar.kt:44`/`:62`），前置 `Class.forName("com.intellij.mcpserver.McpToolset")` 探测（:63），243/251 无新形态环境零成本静默跳过。壳类字节码 = 类头 + 无参构造器（COMPUTE_MAXS，V17），10 个壳类经单例 `ShellClassLoader`（插件 classloader 直系子加载器，defineClass 全仓唯一调用点 :116-117）define 后 registerExtension（:79-82）；无任何注销/重注册路径，断开重连与设置开关切换均不触碰注册器，类与 ClassLoader 不累积。单次成本亚毫秒到低毫秒、一次性。**trade-off**：工具可用时点从「IDE 启动即有」后移到「首个项目打开完成」——功能时点变化，非性能损耗；build.gradle.kts 新增 org.ow2.asm:asm 运行期依赖，仅壳生成一处使用。

**每次工具调用热路径**（`McpToolsetSupport.kt:124-143`）：净增 = `AUDIT_SEQ.incrementAndGet()` + `AUDIT_CTX[token] = AuditContext(...)`（CHM put，:129-130）+ `suspendCoroutineUninterceptedOrReturn` 包装 continuation（:131-142，intrinsics 透传不建 Job 不过 dispatcher）+ 记账时 CHM remove（:167/:228）+ `requireProject` 一次缓存反射 invoke（`McpExpectedBridge.kt:76-84`，Method 对象双检锁单次解析 :86-102，成功失败都缓存）。审计串构造、日志条数与改造前逐语义等价；同步完成路径不走 resume。`SqlvExpectedToolException` 仅错误路径抛出，转译走 `McpExpectedBridge.wrapExpected`（:42-51，ctor 单次解析缓存 :53-68）——异常控制流与改造前同型，成功路径零异常。`AUDIT_CTX` put/remove 严格配对（:130/:167/:228），规模上界 = 并发在途调用数；fatal Error 直穿路径不摘除（:136 先于 onFailure rethrow）——留一条微 entry 至会话结束，量级可忽略（F34 登记）。

**EP 与启动面对比**：删除 10 条 `<mcpServer.mcpToolset>` 静态声明与桩注释，保留 1 条 postStartupActivity（§1 事实 2）。mcpStub 源集 3 文件删除为纯编译期消解——桩从不进运行时与打包产物（build.gradle.kts 源集接线注释明示），运行时零影响；动态化后平台 MCP 类型首次触达推迟到「首次项目打开的探测」或「首次工具调用的桥解析/壳类链接」，插件自身代码路径启动期零平台 MCP 类型加载。注：10 个工具类仍静态 import `com.intellij.mcpserver.annotations.*`（243 旧版即有的注解包，仅平台反射工具方法时加载）——「jar 字节码零平台 MCP 引用」的准确口径是「零 mcpserver 核心 API 引用」。

### 4.2 T-ToolSiteBizFrame（agent 帧定位 + 协议扩段）

**StackLocator（agent 侧每 SQL 事件热路径）**：四阶段结构保留（携栈出口 → 廉价前缀扫描建 entryKey → 非框架帧 pool → 判定缓存命中校验 → 全量判定）。机制 B′ 只加在缓存命中且 at>0 分支：`firstBusinessFrameBefore(pool, loader, at)` 在更深段 [0..at-1] 找首个业务帧（:231/:305-312），at==0 直取零新增（:231 三元首支）；找到即改用并刷新判定（:237-245），找不到走原身份直取且**不刷新**（:232-236）。机制 A：`isBusinessOrigin` = EXTRA_BIZ_PREFIXES 逐项 startsWith（大小写敏感，无正则）+ 非目录来源判据（:320-327）；名单本体 volatile 整组替换（:110/:452-464），多线程注入环境下读侧遍历不可变快照，安全。判定缓存不变：DECISIONS CHM 有界 512 溢出整体清空（:116/:128）、只存判定不存结果帧、ENTRY_MISMATCH_REPORTED 有界 128（:136-138）。**新增成本集中点**：命中路径深帧探测对每帧先扫前缀再落 `loadedFromJar` → `Class.forName(className, false, loader)` + CodeSource 解析（:509-515），无负缓存无 per-class 记忆化；「deeper<0 不刷新判定」使「缓存身份=祖先浅帧 + 更深段全为名单外 JAR 帧」形态下同一 entryKey 每条事件重付 at 次来源解析（F30）——与全量路径 L1 环（:255-261，改动前即同款逐帧成本）同量级、被栈深钳制，判级微~低。健康路径（at==0 或存在名单/目录帧命中）零新增分配。

**SenderLoop / EventBus（agent 传输）**：bizJarPrefixes 提取挂在 CONFIG 帧处理分支（`SenderLoop.java:392-398`，contains 守卫 + `extractStringArray` 单次 O(payload) 扫描，与 skipPrefixes 同款泛化），CONFIG 仅在 IDE 侧低频下发，SQL 事件出环路径零新增；ACK 扩段为固定 4 键字符串拼接、仅 CONFIG 后回一次（:423-428）。EventBus +5 行全为 CMD_CONFIG_ACK 契约注释，队列（2048 有界 ArrayBlockingQueue）与 sender 线程零改动（:30-31/:44）。

**IDE 侧协议与下发链**：严格四键 ACK 校验用 object 级 `CONFIG_ACK_REGEX`（类初始化编译一次，`AgentProtocol.kt:143-144`），每 ACK 帧一次 `matchEntire`（:158），畸形回执返回 null + 计数（:158-165），会话读线程 WARN 不中断（`AgentManager.kt:1812-1818`）；解析跑在既有每会话守护读线程（:1727-1753，存量）。bizJarPrefixes 在每次 sendConfig 时从设置现拼（`AgentManager.kt:1860-1862`，lineSequence 过滤，无缓存但 sendConfig 低频：连接建立 :602/:957、设置变更 :263-284→:1251、采停切换 :1273）；**5s 巡检路径零增量**（:300-304 本区间未触碰）。一致性刷新 = 事件驱动即时推送 + 连接建立兜底重下发 + 既有 5s 一次性 ACK 超时巡检兜底，无新增轮询/重试循环。

### 4.3 T-PrefixValidate（设置面前缀校验）

校验器为纯函数对象：PREFIX_REGEX 单次编译（`SourceFramePrefixesValidator.kt:17`），invalidLines/duplicates O(n)、跨栏冲突集合求交 O(n+m) 非 O(n²)（:41-50），autoFix 幂等（:56-60，冲突 skip 优先从 BIZ 侧剔除）。面板侧两栏各挂 DocumentAdapter **每键击**实时触发 refreshPrefixValidationRow（`PluginSettingsPanel.kt:368-372`/`:398-402`，均在本批新增 hunk 内），EDT 同步跑两栏全文校验 + 至多几条 bundle 消息拼接——n 为手填名单行数（通常个位~几十）、算法线性，单次微秒~毫秒级，且仅设置面板存活期发生；粘贴超大文本时单次成本随行数线性涨、无防抖（F32 登记）。apply 时不重复校验只做规范化写回（:1695-1700）。PluginSettings 新字段为普通 String 持久化（`PluginSettings.kt:520-525`），热路径零解析（唯一 split 在 sendConfig 低频路径）。

## 5. 发现点与建议（编号 F29 起承接上轮系列；沿用户定例本轮仅交付报告，待立项指令后并入 T-PerfSweep10 或随触达批次顺带）

1. **【低·建议修】动态壳注册幂等性缺口两点**（`McpToolsetDynamicRegistrar.kt:62-71`/`:79-82`）：①`registered` 仅全循环成功后置位（:66），若循环中途失败（动态 EP 未就绪等），前若干壳类已 define 进单例 ShellClassLoader 并已 registerExtension，下个项目打开重试时 `ShellClassLoader.define` 对同 FQN 重复 define 必抛 LinkageError → 整循环再度失败 → **每次项目打开 warn 一条的永久重试**，未注册完的工具永不补齐（无类累积——define 先抛；无 EP 重复项——register 在 define 之后）；②:62 check-then-act 非原子，多项目并发打开可双线程同时越闸，后到者 define 撞 LinkageError 被 runCatching 吞掉（:64）多一条 warn，现状良性。建议：按工具粒度记账（已注册 FQN 集合跳过）或 define 前 `findLoadedClass` 预检，兼修两点。
2. **【微~低】B′ 命中路径深帧探测无负缓存，特定形态每事件重复反射**（`StackLocator.java:231-236`/`:305-312`/`:509`）：「缓存身份=祖先浅帧且 [0..at-1] 全为名单外 JAR 帧」时 deeper<0 不刷新判定，同一 entryKey 每条 SQL 事件重付 at 次 `Class.forName+CodeSource` 解析；深栈（非框架帧几十个）+ 高频 SQL 下为稳定新增 CPU 面，被栈深与全量路径同款成本钳制。建议：loadedFromJar 结果做 per-class 有界缓存（或 deeper<0 时对「更深段无业务帧」写否定判定），可随 T-PerfSweep10 与 F29 同批。
3. **【低·登记】bizJarPrefixes 名单长度无上限钳制**（`StackLocator.java:452-464`；IDE 侧校验只限格式不限数量 `SourceFramePrefixesValidator.kt`）：名单每增一项，isBusinessOrigin 的 startsWith 进入每帧×每事件热路径（:320-327）；skip 前缀同款存量边界。建议与 IDE 侧上限（如 100 条）+ 去重一起收口。
4. **【微·登记】设置面板前缀校验每键击无防抖**（`PluginSettingsPanel.kt:368-372`/`:398-402`）：EDT 每键全量重校验两栏，n 小线性、面板存活期限定，实际风险很低；若后续名单规模放开可与 3 同批加防抖。
5. **【信息·注释漂移】mcp-optional.xml 头注壳类命名描述与实现不符**（`mcp-optional.xml:16-17`「壳类名 = 业务类名 + "Gen"（如 SqlVisualizerCheckSqlToolGen）」vs 实现 = 同名 simpleName + `mcp.gen` 子包，`McpToolsetDynamicRegistrar.kt:79` 与其 KDoc :32-35 一致）：误导后续排障/审计，随触达顺带改注释即可。
6. **【信息·登记】微项两条**：①`AUDIT_CTX` fatal 直穿不摘除窗（`McpToolsetSupport.kt:136` rethrow 先于 onFailure 的 remove，:167）——留一条微 entry 至会话结束，上界=在途调用数，可忽略，登记防误判为泄漏；②`McpGateFilterEpBridge.applyFilters` 每次现场新建 Function1 谓词代理 + 反射 `getMethod("updateState")` 无缓存（:75-101）——平台外部清单刷新级频率，微；与第十一轮发现 2 同文件，实施 T-PerfSweep8 时一并核。
