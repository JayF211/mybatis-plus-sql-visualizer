### R42 DML 影响面预演（首推）

- 痛点：UPDATE/DELETE 执行前不知道会碰多少行——线上误删是开发者最贵的恐惧之一。现有链路里 sqlv_check_sql 给「写风险规则判定」、回滚链给「事后预案」，但「事前量化影响面」整条链无人做。
- 形态：CRUD/EXPLAIN 面板加「预估影响行数」动作——提取 WHERE 谓词转 COUNT(*) 只读试算（复用 EXPLAIN 的真机执行通道与 11 方言分发），行数分级提示（阈值可配，超限红色警示），大表防护=超时+EXPLAIN 行数估算降级路径。与只读护栏同源；MCP 侧可顺势评估第 12 工具（sqlv_dml_estimate），另行立项不随本候选默认绑定。
- 规模 M；前提 V60（改写语义边界：JOIN/子查询/多表 UPDATE 的 COUNT 等价性、方言 COUNT 语义差、大表成本防护与超时策略、与 McpSelectGuard 只读口径的联动）。
- 为何本轮成立：EXPLAIN 真机通道（R33 修复后已验收）+11 方言分发+回滚链三件基建全在，只差 COUNT 改写一层；竞品零对位（DBX 数据管理面不做，内置 DB Tools 手动）。红线对照：只读、非订阅、非 DB 管理工具化（属调试安全辅助，与 check_sql/rollback_plan 同域）。

### R43 渲染溯源（SQL 片段↔源节点双向定位）

- 痛点：动态 SQL 排查的高频问题是「这段 WHERE 是哪个 if 生成的/这条为什么没拼进来」——条件求值探镜（R30）回答「条件的真值」，不回答「片段的归属」，用户仍在肉眼比对 SQL 与 XML。
- 形态：预览产物片段悬停/点击→高亮来源 XML 节点或 Wrapper 链调用点；反向从 XML 节点跳到产物片段。引擎侧渲染时记录「节点→片段」映射，UI 侧双向定位。
- 规模视 V61 结果 S~M（求值探镜数据结构已携带映射则纯 UI 件，否则引擎埋点 M~L）；前提 V61（读 SqlPreviewService/求值探镜实现核实映射现状，先证伪再动手）。
- 为何本轮成立：R30 落地后引擎渲染链已有条件级观测点，溯源是同链路下一层；动态 SQL 预览是本插件核心赛道，溯源深度直接拉开与 zMyBatis（物化面收缩中）/MyBatisSQLPreviewer（停滞）的差距，且竞品零对位。

### R44 首日价值路径（功能发现与示例引导）

- 痛点：95+12 项设置、9 个设置页、18 种行标记的复杂度税（12 轮 §3.2.3 在册）；N-24 破零后新用户的第二步转化需要「5 分钟内看到第一次 SQL 预览」的路径保障；现有 onboarding 仅一条 Alt+Shift+Q 指路通知。
- 形态：克制形态——工具窗空态引导已在（批次 9 走查通过项），补「功能发现清单」常驻入口（设置页顶部或工具窗角落，checklist：打开一次预览/捕获一条日志/试一次 EXPLAIN/接一次 MCP），不加弹窗不抢焦点；可配一个「示例预览」按钮用内置样例直接渲染。
- 规模 S~M；前提 V62（现有首用指路 postStartup 通知的触发条件与频控核实，确保不与 N-24 零弹窗口径冲突）。
