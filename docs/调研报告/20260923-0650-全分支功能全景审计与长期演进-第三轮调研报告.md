## 1. 调研范围与方法

三个口径先行钉死，其中第一个相对第二轮做了修正：

1. **合并态基准从「本地 master」改为「origin/master」**。本轮实测本地 master 落后 origin/master 3 个提交——真机走查第八轮的 P20/P21 两真缺陷修复与两笔验收 docs 已推远端、本地未快进。这是项目史上首次出现「本地落后于远端」的主干形态（此前三轮审计记录的全是未推债），第二轮以本地 master 为基准的口径随之订正。
2. **「所有分支中的所有功能」按两层计**。分支层：逐分支独有内容画像（§2）；合并态层：八域功能资产全景（§3）。已完全合入的分支（diff 实测为空）不再展开功能，只进治理清单——功能在 master 里的，分支只是落后的指针。
3. **新功能建议全部先过锚点核实再立项**。三份计划的背景节均为实测锚点（file:line）；候选池里锚点未核的如实标注。沿用「用户点名才生成计划文件」的授权边界——本轮用户已点名。

方法：三路并行只读子智能体分工，主控对承重结论抽点复核（复核方式与结果见文末「专项索引」节）。

## 9. 长期演进路线（第三轮）

**近期（本周）**：两件事并行——①发行前置收敛（用户拍板转正三选一；口径落档进 O-62）；②O-62 治理波：50 个未推提交留底、三条死分支清掉、台账卫生一次补齐。走查车道继续跑到残留真机项收完或环境封顶。

**中期（2~4 周）**：发行窗口开启（N-24 随行 + N-28 T-ReleaseChecklist 执行）；O-63/O-64 与候选池小件穿插在交付间隙；真机依赖五条残留逐项销账或明确改判「环境受限」终态。

**远期（季度+）**：三件事排序不变——口碑飞轮（0 帖 0 票的负债继续计息）、agent 生态卡位（sqlv_* 十工具先手）、验证纵深（方言真机矩阵随 O-63 扩容）；K2J 三选一必须有一个显式结论，决策输入已齐（两轮同步实证 + 成本曲线 + 门禁读数）。

产品锚点不动摇：ORM SQL 调试闭环。排序标尺沿用第二轮 §8.3 并升格为本轮三份计划的立项依据：**收尾型资产（正确性/治理/真机收口）优先级高于宽度型资产，宽度型资产优先级高于一切「发行物追平之前」的新环**。

## 10. 落地优先级建议

如果只做三件事：**①发行窗口**（转正口径拍板是用户侧唯一闸门，其他一切让路）；**②O-62 治理波**（50 提交留底 + 死分支清理 + 台账补齐，一天量级，消灭当前最大的丢稿敞口）；**③走查车道收尾**（在途，无需新派活，残留真机项逐项销账）。O-63/O-64 与候选池在这三件的间隙里穿插。

一句话总结本轮：交付侧连续第三轮「六清账 + 走查抓缺陷」的高产状态，功能宽度连续三轮零扩张而质量基线三连涨；三轮前说「缺的是最后一公里」，本轮的答案是最后一公里还剩三段——发行（用户拍板）、治理（50 个未推提交和三条死分支）、边角（P18/P19）——三段都有计划或清单，只差执行。
