## 1. 总结论

**结论维持：默认配置下插件对 IDEA 的资源型性能影响仍可忽略。本轮的驱动事件是 Marketplace 审核退回后的「动态代理化」整改——所有被点名的 internal API 直调改成「反射 + 动态代理 + 探测式程序化 EP 注册」，这类形态天然带每次调用的反射开销，经逐点审计其频率全部落在启动期一次性（postStartupActivity，依赖插件在场才加载、原子闸防重）或会话/清单刷新级（微秒~低毫秒、低频），零新常驻线程、零新定时器、零新监听器；O-70 静默冲刷给逐行热路径新增的全部成本是每行 1 次时钟读 + 1 次 map put + 1 次 O(桶数≤64) 静默扫描 + 1 次无竞争锁，微秒以下。本轮无「中低」及以上新发现，4 条低危 + 2 条文档缺口全部为登记性质。** 全局红线十三族除 postStartupActivity 0→2（探测式启动活动，本轮有意引入的新族成员）外全部持平；plugin.xml 主线零新 EP/action/listener（+4 行为描述文案）；上轮 §5 的十七个发现点在 master 上零漂移（PS7 四任务承接实施已并 dev、按用户定的窗口待回流）。

支撑结论的六个增量事实：

1. **动态代理化的启动期成本是一次性的且条件加载**（§4.1）：ACP 传输 EP 的 XML 声明删除（acp-transport-optional.xml），改 `postStartupActivity` 探测式注册——`Class.forName` 1 次 + 代理创建 1 次 + EP 注册 1 次（`AcpTransportRegistrar.kt:65`/`:83`/`:85`），跑在启动后台协程线程，`AtomicBoolean` 保证多项目同开只注册一次（`:64`）；该 optional 文件仅在 ml-llm 插件在场时加载，无 AI Assistant 的平台整文件不加载、零成本。EP `dynamic=true` 晚注册触发的清单重算是注册时刻一次性，非持续成本。
2. **动态代理的运行时分派是会话级微秒开销**（§4.1）：平台调用的方法是 `getTransport(agentId)`，时机是 ACP 会话解析 MCP server 时（会话级，非每条消息）；每次 2 次反射查找无缓存（`AcpTransportRegistrar.kt:99`/`:80`），零每调分配，分发核与被删的直连实现逐语义一致，还顺带消除了原双重载形态的 AbstractMethodError 隐患（稳健性正收益）。
3. **O-70 静默冲刷零新常驻**（§4.4）：冲刷是「逐行判 + EDT 每拍兜底」双触发（`SqlLogConsoleBridge.kt:888`/`:233`），无新定时器无新线程；逐行新增 1 次 `synchronized(context)` 与轮询侧互斥（`:393`，无竞争约 20ns）；桥轮询 Timer 同位实证——`FAST_POLL_INTERVAL_MS=500`/`POLL_INTERVAL_MS=2000` 与 `isRepeats=true` 零变化（`:661-662`/`:125`/`:140`）。
4. **O-66 引导链纯用户动作驱动**（§4.5）：`showMissingSourceDialog` 只由「跳转到源码」点击触发（`SourceCaptureGuide.kt:70`，调用点 SqlLogPanel/HistorySqlLogPanel），无监听器无定时器；`requestReauthorization(onOutcome)` 回调经 `invokeLater` 落 EDT（`AgentManager.kt:460` 起），线程契约正确；AgentManager 本轮 +18 行全是这条回调链，零常驻变化。

## 4. 新增子系统审计

### 4.1 T-MarketCompatProxy 动态代理化族（ACP 传输 + earlyDisposable + 方言传参）

- **【启动期一次性】ACP 传输 EP 探测式注册**：XML EP 声明删除（acp-transport-optional.xml 当前 27~38 行，改为 postStartupActivity 指向 `AcpTransportRegistrar`）。启动期做 1 次 `Class.forName(PROVIDER_IFACE_FQN)`（`AcpTransportRegistrar.kt:65`）→ `Proxy.newProxyInstance`（`:83`）→ `registerExtension`（`:85`）→ 1 条 info 日志（`:70`）；失败路径 runCatching 一次 warn 带堆栈（`:72-74`），无重试循环。`AtomicBoolean registered`（`:54`/`:64`）保证多项目同开只注册一次，第二次起纯一次 volatile 读。跑在启动协程后台线程，非 EDT。**条件加载**：acp-transport-optional.xml 仅在 ml-llm 插件在场时加载，243/253 等无 AI Assistant 平台整文件不加载、零成本。EP `dynamic=true` 晚注册的清单重算是注册时刻一次性。
- **【会话级微秒】代理分派**：平台调用 `getTransport(agentId)` 的时机是 ACP 会话解析 MCP server（会话级）；每次 2 次反射查找（`getMethod("getFullId")` `:99`、命中时 `Class.forName(TRANSPORT_ENUM_FQN).getField("SSE")` `:80`），无缓存、零每调分配。分发核 `transportHandler`（`:94-108`）与被删直连实现逐语义一致（策略 a、精确 id 匹配 `:101`、非目标 null、Object 三方法 `:103-105`）；按方法名分发天然吸收上游两条发行线的形参包差异，消除 AbstractMethodError 隐患。
- **【中性】`getEarlyDisposable` 反射化**（`SqlPreviewPanel.kt:763-785`）：直调改 `proj.javaClass.getMethod("getEarlyDisposable").invoke(proj)`，`prewarmLifecycleGate` 非空早退保证每面板实例至多一次，微秒级冷路径；失败静默退回改动前行为。
- **【低·正收益】方言传参修复**（`DbTableSpecAdapter.kt:63`）：`currentDialect()` → `currentDialect(table.project)`，链路经 `DialectRegistry.effective`（`Dialect.kt:737-753`）——设置两层读 + `AgentUrlRegistry` synchronized WeakHashMap 一次查 + `DataSourceUrlProbe.firstUrl` 的**单槽 TTL 5s 缓存**（`DataSourceUrlProbe.kt:35`），未命中才反射探测数据源 URL（最坏 O(数据源个数)、命中即停）。每次右键生成 CRUD SQL 触发一次，冷路径低毫秒；换来的正确性收益实在（SQL Server/达梦表不再被按 MySQL 渲染）。

## 5. 发现点与建议（4 低 + 2 文档缺口，全部登记性质）

> 上轮 §5 十七项在 master 零漂移（§3.1），承接实施在 dev 在途，此处不重复开出。沿用户定例：本轮仅交付报告，发现点待立项指令后并入 T-PerfSweep 系列或随触达批次顺带。

1. **【低·文档缺口】AcpTransportRegistrar KDoc 声称「解析并缓存」但实现无缓存**（KDoc `AcpTransportRegistrar.kt:25` vs 实现 `:80`/`:99`）：`sseProvider` 每次 `getTransport` 命中都 `Class.forName+getField`，`getMethod("getFullId")` 每调用一次，无任何缓存字段。当前会话级频率下微秒级/次、可忽略；但注释与实现不符会误导后续维护。建议：随下一批 ACP 触达补一个 `@Volatile` 单槽缓存（枚举 Class 与 Method 各一）或改注释。
2. **【低】McpGateFilterEpBridge 每次清单刷新重建代理与反射查找**（`McpGateFilterEpBridge.kt:78-96`/`:104-111`）：每次 `applyFilters` 新建 Function1 代理 + 4 次反射查找，每工具 2 getMethod + 2 invoke，全无缓存；当前每次清单刷新亚毫秒~低毫秒、低频，可接受。建议：登记即可；若平台日后改为高频调用（如每消息过滤），优先给 Class/Method/代理三者加惰性缓存。
3. **【低·文档缺口】门控过滤注册的 XML 文件名残留**：`McpToolGate.kt` 头注与 `McpConfigurable.kt` KDoc 提「mcp-filter-optional.xml since-build=262 门控」，META-INF 下**无此文件**（主控 ls 实证），实际注册已走 mcp-optional.xml 的 postStartupActivity 探测（253 静默跳过替代 since-build 门控）。无运行时影响。建议：随下批 MCP 触达改两处注释。
4. **【低】O-70 逐行静默冲刷的全桶扫描**（`SqlLogConsoleBridge.kt:888` → `LogThreadRouter.kt:71-79`）：每行日志一次 O(桶数≤64)+fallback 的 IdentityHashMap 扫描 + 1 次时钟读 + 1 次 map put + 1 次无竞争锁（`:393`）。微秒以下/行。**建议：维持逐行 + 每拍双触发**（2026-09-24 立项核实订正：EP 主捕获通道 `SqlConsoleBridgeFilterProvider.EpLineFilter` 持有私有 BridgeLineContext、不在桥的 consoleContexts 注册表——其静默冲刷**只有逐行触发这一条路**，「逐行只 touch、冲刷只靠每拍」会让 M56 后的主通道在应用安静后退回「已扫描 N 行/产出 0 条」，等于 O-70 的用户可见收益在主通道归零；改单触发的隐藏前置是「EP 上下文纳入可轮询注册表」这一跨线程改造，成本远大于它省下的扫描）。
5. **【低】Thread.sleep 红线口径订正**：逐点清单见 §4.7（主仓 6 + agent 2 = 8 实点），上轮记 7 的分口径不再沿用；本轮零净增。建议：登记口径，无需动作。
6. **【低】方言推断的 TTL 首探**（`DbTableSpecAdapter.kt:63` → `DataSourceUrlProbe.kt:35`）：比旧形态多一次 WeakHashMap 查 + TTL 5s 窗口首探（反射读数据源 URL，最坏 O(数据源个数)）；冷路径低毫秒，正确性收益明确（P21 真机实证）。建议：无需动作。

**正向清单**（本轮净收益，供下轮对照）：O-70 静默冲刷根治「已扫描 N 行/产出 0 条」（§4.4，`ConsoleSettleFlushTest` 195 行守卫在库）；ACP 传输动态代理消除 AbstractMethodError 隐患且零直连注册面（§4.1）；门控过滤 EP 使外部会话清单与设置页单一真相源、`getUpdates=emptyFlow` 零常驻（§4.2）；filePath 统一减少一次 findFileByPath 上限（§4.3）；O-66 引导链零监听器零定时器（§4.5）；`render snippet` 读锁化使 262 平台线程 PSI 读合法（§4.3）；`SqlPreviewPanel` 卸载屏障反射化后 internal API 引用清零（§4.1）。
