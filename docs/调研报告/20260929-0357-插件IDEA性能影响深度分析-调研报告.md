## 1. 总结论

**结论维持：已发布基线（master）默认配置下对 IDEA 的资源型性能影响可忽略；T-Embedded 增量审计干净，为实体解析冷路径的常数因子。** dev 侧「dev 修复后」列的四个预期全部兑现：F20~F23 四快件（批次 2）逐件深审**修复干净**——F20 结构键 lazy 零触达、F21 批量单次 republish、F22 ThreadLocal 缓存化、F23 单趟取词，每条控制台日志与每次面板渲染的热路径成本实质下降。本轮最有价值的发现在风险侧：**系列首个高级别发现 F37**——dev 新增的 mapper XML 语法高亮注入子系统（T-XmlSynHi，批次 3~5+7）的注入器 EP 契约违背（`context as? XmlFile` 对平台喂入的元素类型 cast 恒败），注入全族当前**零成本也零功能**（功能失效）；且其潜伏形态（visitor 无 mapper/语句标签过滤、守卫函数零调用者）一旦按最小修复激活，会对全 IDE 任意 XML 文件每高亮 pass 加全树走查税。另有两条中级（F38 门控反射链无缓存、F39 每乘除号键击整文档 String 副本）与一条低-中（F36 R2 gutter 分组接线每到达元素三重服务查找）。

支撑结论的五个事实：

1. **master 侧增量全部有缓存或冷路径覆盖**：T-Embedded 的六个文件都挂在实体解析链上，而 `EntityResolver.resolve` 入口有 T-EntityCache 三维缓存（PsiFile+类名+configSignature，`EntityResolver.kt:77-84`），新增的类级 `attributeOverrides` 扫描与每字段嵌入判定只在缓存 miss 时付费；`columnByEmbeddedPath` 是纯函数线性查找（O(列数)，列数有界），挂在派生查询转换的兜底分支（`DerivedQueryConverter.kt:444-446`）。无新线程/Timer/正则/监听器/驻留状态。
2. **红线族独立重跑 16 族读数与上轮逐条吻合**（§3.1）：含一处口径自纠——Timer 构造点 17/10 文件中 `NativeJoinDiagramSupport.kt:90` 一处（`javax.swing.Timer(fits * 900)`）因初轮过滤器误剔含星号行，复核后归位，与上轮口径精确一致。
3. **F20~F23 修复全部判定干净**（§4.2）：F20 的 `hasStructureKeys` 门控位三处写点全配对无孤儿（`SqlLogManager.kt:70/:178/:618`）；F21 N 次发布压成 1 次；F22 照 LogTimestampParser 范式 ThreadLocal 化且输出逐字节一致；F23 与既有 `nextWordIs` 跳过规则逐位一致且调用点唯一低频。
4. **T-XmlSynHi 当前真实生效面只有两条小路径**：typedHandler（每键击 1 次 char 比较的 O(1) 全局税 + #/$ 键击守卫链）与 resultMap column 补全（守卫收窄后的用户触发面）；注入主链因 F37 死路，词法/高亮器/工厂零实例化——**子系统当前对 IDEA 的实际资源代价接近零，但代价为零的原因是功能不存在**。
5. **批次 2~7 无一新增红线族实例**：全 dev 增量 diff 的 +行红线族扫描仅 6 行命中（1 处用户正则检索编译、2 处 SDF、2 处补全链 Regex、1 条 KDoc），R4 导出写盘走平台共享池 `executeOnPooledThread`（`HistorySqlLogPanel.kt:594`、`SqlLogPanel.kt:1715`）非自建池。
