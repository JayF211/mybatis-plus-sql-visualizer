## 9. 风险

1. **获客缺位（维持第一风险）**：0 票 0 评论第 41 天，N-24 连续第二轮零动作；竞品全静默的窗口同时是「谁动谁吃」的窗口，静默不会永远持续（MyBatisX 待审批版过审、Hibernate Debugger 随 2026.3 铺开都是 Terminatoren）。
2. **交付/货架背离（升格第二）**：60 笔用户可见库存不在货架，其中 T-Embedded 是用户报障的闭环——报障者拿不到修复的体验损失是双重的；库存的合并冲突面与发版验证成本随时间复利。
3. **CHANGELOG 叙事断层**：发版若不补录，发行说明将缺 T-Embedded 与批次 2~7 主要条目——「已上架版与仓库叙述不一致」在 B5 重传时踩过一次（§11 上轮教训）。
4. **官方化长期挤压（维持）**：Hibernate Debugger 周更四版蓄水，2026.3（11 月）铺开倒计时约 6 周；「调试 ORM 查询」的平台默认答案临近，JPA 话术与搜索位养词（jpa sql）宜在铺开前落位。
5. **免费线内卷碎片化**：头部 fork（MybatisLogFree）+同位素密度（09 批次 3 个新同位素）在稀释「mybatis log」词场流量；承接内容（§8.2）是唯一低成本反制。
6. **MyBatiSuite 评分资产积累**：同窗 7.4 倍者拿到首个 5 星（1 票），评分飞轮的起点形态与我方 0 票对照刺眼；下轮继续观察其评论质量。
7. **push 债 60 笔+untracked 文档 3 份**：单点丢失风险持续累积；master 债 7 笔里包含 T-Embedded 修复本体。
8. **263 正式版 verifier 复跑尾巴**（V6 维持）与**平台审核节奏**（MyBatisX 待审批挂第四天旁证仍慢，跟版预期管理照旧）。
