## 1. 总结论

**在售基线（master 8d9a718，v2026.10.7）结论维持：对 IDEA 无体感影响，且本批方向是改善。** 32 笔增量中唯一的主体生产码 T-SqlLogPerf 本身就是性能优化交付——它修的正是用户真实报障的「并发灌入下监听与历史加载延迟」（idea.log 实测 65 条/秒、8708 条历史加载 15~16.6s）：isDuplicate 锁内 O(n) 全表扫描改 O(1) 索引、历史页浏览态免重复全量重读、实时列表重建链防抢占。红线族十四类两锚点计数全等，零新常驻任务、零新启动扩展点、零新线程；T-JpaParamOrder 全部为触发型一次性修正，gutter 热路径上的增量被既有三重门控限定在稀疏调用点。本批对 IDEA 的净效应为负（更快）。

**dev 库存面新增本系列第二例「高」级发现 F79**：mapper XML 着色修复（D68）把让位门从 O(1) 常量改为 per-host 活体探测后，「探针跑在 mapper 判定之前 × per-host 结论不缓存 × df6ca54 删白名单后全部三方注入器进探测圈」三者相乘，构成任意 XML 文件每文本/属性节点每高亮 pass 的常驻探针税（每问成本较旧形态放大约 10~100 倍，绝对量级未实测）。**F79 只存在于 dev（9b7f2dd 未回流 master），在售面不受影响**；两刀低风险修法（谓词前置重排+stamped memo）建议列为该面回流前置项。上轮「合并前必改」的 F74 已在 dev 修复并经本轮三点逐条回验闭合销账；F75/F76/F77/F78 维持。

## 4. 本轮增量审计（三链路）

### 4.1 T-SqlLogPerf 日志链（A 路：性能优化交付的性能面复核——重点审「优化本身不引入新常驻成本」）

- **常驻变化：零**。五文件本批改动不含任何 Timer/Thread/Executor 构造；LogPerfProbe 是无状态 object+internal inline（两次 nanoTime+阈值 100ms 比较，detail 惰性求值，达标才拼串打日志，LogPerfProbe.kt:28-37——常态成本约两次 nanoTime+一次比较，超阈路径才多付一次 size 锁读）；既有 searchDebounceTimer（一次性防抖）与 diagnosticsTimer（仅捕捉中且零条目时运行）为既有形态未触碰；SqlLogConsoleBridge 本批 diff 为空（catchUpTimer/pollTimer 双 Timer 轮询既有形态不变）。
- **监听器生命周期：干净**。滚动追加新增的两处 adjustment 监听器均挂在面板私有的 `JBScrollPane.verticalScrollBar` 上（HistorySqlLogPanel.kt:533 一带、SqlLogPanel.kt:1116-1119 一带），不挂平台共享对象；History 侧 historyPanel 是 by lazy 单例、tab 显隐重挂复用同一实例不累积；随面板组件树整体退役，无泄漏面。
- **EDT 姿态：全绿且有界**。缓冲通知经 SqlLogManager「置脏+单个幂等 flush」单 invokeLater 派发（:564-575），风暴期刷新被 EDT 吞吐自然合并；重建链防抢占补完（flushRebuildChainSync，SqlLogPanel.kt:1611-1620）单拍上界=snapshot−30≤maxEntries（默认 200→≤170 条/拍），ignoreRepaint 抑制布局；滚动续写每拍 ≤30 条（REFRESH_CHUNK_SIZE），追加约 30 行高即自然跳出 480px 触发窗，事件驱动无失控面。
- **锁与内存**：dedupeIndex 六个维护面（入队 upsert/头部淘汰回扫/重建/翻 true 补账/clear/removeEntry）**全部在 `synchronized(entries)` 锁内**（SqlLogEntryBuffer.kt:197-227 等），无锁外读写；键数 ≤ 队内不同 dedupeKey 数 ≤ maxEntries（默认 200）→ 有界，数 KB 级。isDuplicate 锁内工作 O(n)→O(1)，收益=三通道写线程持锁时间缩短、EDT snapshot 抢锁等待同步受益。
- **IO 面**：历史页惰性重读边界正确——refresh 在后台线程比对 (lastModified,length) 快照（私有字段 currentFileStamp，可见性为启发式判定，代码自述「最坏多读一次文件」，无害），相等则保留既有条目与滚动位置；countInFile 缓存为自建 CHM（双 stamp 校验，上限 256 超限整体清空）；refresh 仅由面板构造/手动刷新/切历史 tab 三个用户动作触发，非轮询。文件真变化时仍整文件重读（非尾部增量）——与旧版同价，留改善空间不立案。
- A 路另报两处静态审计无法闭环的真机观察项（多行显示模式下滚动连锁是否一步贴底；lateinit 安全调用写法），并入 §2 范围外真机登记，不影响结论。

- **正则：零新增现场编译，含一处净改善**。本批六文件新增 Regex 3 处全部类体级预编译（SqlPreviewService.kt:768/790/791），其中 NATIVE_NAMED_PARAM 由改前函数体内每次现场编译提升为常量=净改善；既有 18 处函数体内现场编译未动（其中 3 处在本批编辑过的函数体内，同域未修，见 F84）。

### 4.3 dev 侧回验专项（C 路：F74 闭合见 §3.2；此处为另两件+概览）

- **afb62e4 ZeroLoadClassWriter（P0 稳定性修复）性能面：一次性成本净降+热路径零变化**。原 `ClassWriter(COMPUTE_FRAMES|COMPUTE_MAXS)` 全量重算 StackMapTable（含 getCommonSuperClass 的 Class.forName 类型层级解析），改 COMPUTE_MAXS-only 后只算 max stack/locals、无类型解析（dev@ConnectWeaver.java:77、dev@StatementWeaver.java:163）；反向新增仅 StatementWeaver 读入固定 EXPAND_FRAMES（:144）与织入成功方法的每帧 O(k) 槽补齐（:345-364，k=帧 locals 项数小常量）——均类加载时一次，远小于被删的帧计算大头。逐 hunk 核对插桩序列（token 头插/出口压栈/装箱/回调签名）与修复前一致，织入产物指令流零变化。
- **XmlSynHiGate per-host 探针族（9b7f2dd 落、df6ca54/95bee1f 迭代，dev 现行形态）——本轮 dev 侧最重要发现，F79 定性**：
  - 调用面边界：平台对**任意 XML 族文件**的每个 XmlText/XmlAttributeValue 每 pass 各问一次 MultiHostInjector 链（喂入契约案底 dev@XmlSynHiGate.kt V38 计数缝 3002 喂入位；非每次编辑器打开一次）。
  - 短路序缺陷：dev@SqlMapperInjector.kt:14 `shouldYield` 跑在 :48 `allowStatementText`/:57 `inMapperFile` 两个廉价本地判定**之前**——pom.xml 等非 mapper XML 的每个文本节点付完全链探针才被拒绝。
