## 一、结论摘要

插件当前的原生化程度是「中间态」：编辑器内核、JBPopup、DiffManager、JCEF 帮助页、NotificationGroup、ChooseByNamePopup、StatusText、ActionToolbar、gutter lineMarker 等平台能力已经在用，且有若干教科书级实践（`SqlLogPanel` 的 `itemToText` 让 JBList 内置 Ctrl+C 复制生效、`CrudSqlPreviewFlow` 的 chooser builder、`PluginSettingsFolderConfigurable` 的 `DoubleClickListener`）。

但外壳层存在大量「自研替代品」：8 处直写系统剪贴板、3 个数据列表右键菜单是裸 `JPopupMenu`、20+ 处 `Messages.*` 模态弹窗当轻提示、预览主工具栏是小号裸 `JButton` 手摆、一个 `JSplitPane` 靠覆写 `paint()` 粉刷分隔条、搜索框实现两套分叉、三大列表都没有 SpeedSearch、设置页全 GridBag 手摆（全仓 0 处 Kotlin UI DSL）、十余处颜色写死十六进制。这些点用户不一定能说出哪里不对，但会形成「功能像、手感不像 IDEA」的累积割裂感。

按「用户可见度 × 实施风险」排出来的优先级：

| 批次 | 主题 | 一句话 |
|---|---|---|
| P0（一批小改可全清） | 剪贴板统一、模态轻提示换通知、Splitter 替换、搜索框归一、列表接 SpeedSearch | 全是局部替换，无结构改动 |
| P1（按面板拆分实施） | 右键菜单迁 ActionGroup+PopupHandler、列表渲染归一 SimpleColoredComponent、空态/加载态换原生件、写死颜色 namedColor 化、设置页迁 Kotlin UI DSL | 单面板内闭环，行为需回归 |
| P2（单独立项评估） | ER 图、快捷键录制、EditorTextField 迁移、设置落地页仿制 | 有平台 API 缺口或内部 API 风险，先评估再动 |

## 三、官方文档口径要点（262 Writerside 版）

以下要点取自 plugins.jetbrains.com/docs/intellij 对应页（URL 见 §8），是各建议的规范依据。

- 工具窗（tool-windows.html）：内容用 `ContentManager.getFactory().createContent` 装入；`SimpleToolWindowPanel` 是带工具栏的标准基类；工具窗标题栏可挂 action（`setTitleActions`）。工具窗专属通知用 `displayType="TOOL_WINDOW"` + `toolWindowId`，气泡出现在工具窗图标旁，点击自动消失。
- 对话框（dialog-wrapper.html）：DialogWrapper 提供按钮布局/尺寸记忆/Esc 键位/`Do not ask again`/非模态验证（`initValidation()`+`doValidate()` 返回 `ValidationInfo`）；明确要求不要在按 OK 时用模态对话框报校验错。
- 通知（notification-balloons.html / informing-users.html）：「设计原则之首是避免用模态消息框通知用户」；新式写法直接 `Notification(groupId, content, type).notify(project)`，文档明确 `NotificationGroupManager` 与 `Notifications.Bus` 已过时；`STICKY_BALLOON` + `setSuggestionType(true)` 是「建议类」通知（带按钮、不自动消失）；编辑器顶部横幅走 `EditorNotificationProvider` EP + `EditorNotificationPanel`；新功能引导用 `GotItTooltip`。
- 弹层（popups.html）：四种标准 popup（component/chooser/confirmation/actionGroupPopup）；动作型弹层键盘选择方式用 `JBPopupFactory.ActionSelectionAid` 编号或速度搜索。
- 列表与树（lists-and-trees.html）：`JBList` 替代 JList（空态文案 `getEmptyText()`、busy 图标 `setPaintBusy()`、超长 tooltip）；渲染器用 `ColoredListCellRenderer`/`SimpleColoredComponent`（自动处理选中色等平台细节）；`ListSpeedSearch`/`TreeSpeedSearch` 一行接入；「列表+增删改排序工具栏」的标准答案是 `ToolbarDecorator`（配 `CollectionListModel`/`EditableModel`）。
- 编辑器组件（editor-components.html）：`EditorTextField` 相比 JTextArea 有高亮/补全/折叠等全部优势，可嵌入对话框与工具窗；输入场景优先 `LanguageTextField`；补全用 `TextFieldWithCompletion`+`TextCompletionProvider`；定制走 `EditorCustomization`（SpellChecking/HorizontalScrollBar/ErrorStripe 三种现成实现）。
- 组件对照（misc-swing-components.html）：`Messages` 覆盖消息框/输入框/选择框（`showCheckboxMessageDialog` 实现"不再显示"）；`JBSplitter` 替代 JSplitPane（`setSplitterProportionKey` 记忆分割位置）；JBTabs 用于需要编辑器标签观感的场景。
- 设置（settings-guide.html）：EP 属性尽量声明在 plugin.xml（不加载类即可建树）；实现 `Configurable.NoScroll`/`NoMargin`/`Beta` 标记接口控制外框；`reset()` 在 `createComponent()` 后自动调，构造器里不必初始化控件值。
- Kotlin UI DSL（kotlin-ui-dsl-version-2.html）：适用于「有输入控件绑定状态对象」的表单（对话框/设置页），不适用于工具窗操作型 UI；`panel{}/row()/group()/collapsibleGroup()/buttonsGroup()`，`enabledIf/visibleIf` 声明式联动，`rowComment/cell.comment` 平台样式注释，`bind` 双向绑定 + `apply()/reset()/isModified()` 免手写；官方推荐用 IDE 内 `Tools | Internal Actions | UI | UI DSL Showcase` 对照学习。

## 五、逐项优化建议

优先级定义：P0=低风险局部替换，建议一批做完；P1=单面板闭环改造，需行为回归；P2=先评估再立项。每条注明「现状 → 改法（已核实的 API）→ 收益」。

### P0

1. **剪贴板统一收口**：8 处 `Toolkit.systemClipboard+StringSelection` 全部换 `CopyPasteManager.getInstance().setContents(...)`，在 util 层留一个收口函数。收益：进 IDE 复制历史（Ctrl+Shift+V 可粘贴回来）、与编辑器复制栈互通、删掉 Toolkit 直连的降级分支。同库已有 4 处 CopyPasteManager 先例，语义一致。
2. **模态轻提示换通知**：§2.2#2 清单中「成功/进行中/无害提示」类全部改 `Notification("mpv.preview", ..., INFORMATION).notify(project)`（组已在 plugin.xml 注册；错误类可考虑单独 ERROR 组或复用 feedback 组）。特别处理 `SqlPreviewPanel.kt:1514` 复制成功双按钮模态——换成通知+「关闭 SQL 面板」action 链接。收益：不打断流程、可进 Notifications 工具窗回看、样式天然跟主题。`Messages.*` 仅保留真正的决策场景（删除确认等）。
3. **分隔条替换**：`ThemedSplitPane`（SqlPreviewPanel.kt:537-551）换 `com.intellij.openapi.ui.Splitter(false, proportion)` 或 `OnePixelSplitter(false, "mpv.preview.split", proportion)`——后者构造即带位置持久化，顺手删掉 paint() 粉刷。同库 LogToSqlPanel/SqlToJavaPanel 已用 `Splitter`，属消除同库不一致。
4. **搜索框归一**：`SqlHistorySearchBar` 的 `JBTextField`+手写 ESC InputMap 换 `SearchTextField(false)`（与 SqlLogPanel/HistorySqlLogPanel 同款），ESC 收起、history、放大镜图标白得；三处搜索条行为完全对齐。
5. **三大列表接 SpeedSearch**：`ListSpeedSearch.installOn(list)`（262 静态方法；253 兼容性落地前复核，必要时退 `new ListSpeedSearch(list)` 实例构造或 `TreeUIHelper.installListSpeedSearch`——SqlSelectionDialog.kt:65 已有先例）。打字即搜是 IDEA 列表默认体验，与现有 Ctrl+F 搜索条并存不冲突。
6. **复制反馈去重**：合并 `CopyFeedback` 与 `SqlClickPreview` 两份 flashCopied 为一份 util（不追求平台件，平台无此标准件，属合理自研；重复实现才是问题）。

### P1

7. **右键菜单迁 ActionGroup 体系**：三个数据列表的 `JPopupMenu` 改 `DefaultActionGroup` + `PopupHandler.installPopupMenu(component, group, place)`（列表选中态用 `installSelectionListPopup`）；菜单项改为 AnAction 后可接 keymap（高级用户可设快捷键）、`update()` 灰置逻辑、与 plugin.xml action 复用（复制/删除等语义统一）。类型过滤弹层（SqlLogPanel.kt:686-690）改 `JBPopupFactory.createComponentPopupBuilder` 或 listPopup+多选 step。SqlHistoryPanel 为死代码，迁移前先确认去留（建议直接删，见独立说明）。
8. **列表渲染归一**：历史页两级列表的两个 HTML 渲染器（HistorySqlLogPanel.kt:563/606）换成与 SqlLogPanel 相同的 `SimpleColoredComponent` 双行范式（同文件 :606 注释已给出改造范式）；SqlHistoryPanel 的 HTML 渲染器随死代码一并处理。收益：删掉 HTML 通道的选中色/主题适配问题（`<span>` 写死色值是 §2.2#9 的组成部分）。
9. **选中视觉回归平台语义**：`SqlListSelectionOutline` 四边描边 + `SqlListTypeColor.ensureOutlineContrast` 提亮算法，改为用 `JBColor.namedColor("List.selectionBackground"/…)` 或直接依赖 `ColoredListCellRenderer` 的选中处理 + `JBUI.CurrentTheme.List.Selection/Hover` 键（262 已核实存在）。类型色条保留（信息密度设计），但描边与选中底色交给平台。
10. **写死颜色 namedColor 化**：DiagramRenderer 16 色板、耗时五色、元信息灰、慢查询红、闪烁高亮黄、`SqlHighlightColors` 默认值等，全部改 `JBColor.namedColor(name, lightColor, darkColor)` 形式（262 签名 `(String, int, int)` 已核实）。收益：主题/自定义主题覆盖生效路径打通（namedColor 读 UiTheme，用户配主题时插件跟着变），代码侧亮暗双值仍然保留兜底。HtmlReportFormatter 的导出 CSS 不属于 IDE 内 UI，可不动。
11. **空态/加载态换原生件**：DiagramPanel 的 JBLabel+JProgressBar 手工换页改 `JBLoadingPanel`（ctor 已核实）；SqlResultPanel「执行中」纯文字改 `StatusText.appendSecondaryText`+`AnimatedIcon` 或 JBList 的 `setPaintBusy(true)`；LogToSqlPanel 自管 hintLabel 改 emptyText。收益：加载动画样式与 IDE 一致（转圈风格、字体、颜色全免维护）。
12. **小号按钮行改 ActionToolbar**：SqlPreviewPanel 预览工具栏（:558-584）、DiagramPanel 缩放/导出行（:100-111）、HistorySqlLogPanel 返回/刷新行（:84-93）、SqlClickPreview 头部按钮（:239-257）、ParamImportDialog 图标按钮行（:123-140）改 `ActionToolbar` + AnAction（同库 LogToSqlPanel/SqlToJavaPanel 范式）。收益：图标主题化、无障碍 tooltip、`update()` 状态驱动、右键「添加到收藏工具栏」能力、删掉 smallButton/compactButton 字号 hack 与 IconScaler 12px 缩放需求。
13. **工具窗标题栏挂原生点**：主工具窗考虑把「捕捉开关」等全局动作用 `ToolWindow.setTitleActions(List<AnAction>)` 挂到标题栏（262 方法已核实）——这是 IDE 原生位置（如 Run 工具窗的停止按钮），能腾出面板工具栏空间；同时评估 `SimpleToolWindowPanel` 作为 SqlLogPanel 基类替换自建 WrapLayout 顶栏。
14. **设置页迁 Kotlin UI DSL v2**：`PluginSettingsPanel`（含 `addRow`/`sectionGroup` 手算布局）、`ProjectPluginSettingsConfigurable`、`ErrorReportDialog` 表单改 `panel{}` 体系：`enabledIf` 替代手写 ItemListener 联动、`comment()` 替代自管 hint、`collapsibleGroup` 替代 sectionGroup、`bind` 消灭 apply/reset 手写镜像。Configurable 实现可考虑 `Configurable.NoScroll` 标记接口控制外层滚动。分页实施：先项目级页（最小）再主面板。
15. **提示类通知进阶形态**：更新引导/新功能说明用 `GotItTooltip`（构造已核实）；错误反馈入口这类「重要且需用户行动」的提示可评估 `STICKY_BALLOON`+`setSuggestionType`（262 文档新形态，253 兼容需复核，降级方案是普通 BALLOON）。

### P2（先评估再立项）

16. **ER 图**：`com.intellij.diagram` 依赖 Diagrams 插件（Community/无 Diagrams 环境不可用），自绘引擎是为兜底存在——不建议强迁。改法：保留自绘，但按 #9/#10 把色板、描边 namedColor 化；工具栏按 #12 迁 ActionToolbar。若未来接受「Ultimate-only 原生 ER 图 + Community 降级文本」的产品分层，再立项。
17. **快捷键录制**：平台 `ShortcutTextField`/`KeymapPanel` 在 `com.intellij.openapi.keymap.impl.ui`（impl 包），跨版本破坏风险高，不建议直接 import。保留自研 JDialog，但界面按 Keymap 设置页观感微调（ExtendableTextField 外观 + 冲突提示行内化），并把「不支持鼠标键录制」记入已知边界。
18. **EditorTextField 迁移评估**：现 SQL 输入/预览编辑器走 `EditorFactory.createEditor`+PSI 文件支撑，功能已原生（高亮/补全/折叠全生效）。`EditorTextField` 的增益是 placeholder、单行模式、`setFontInheritedFromLAF`、`EditorCustomization`（关拼写检查等）与更省的生命周期管理；但 SqlInputEditor 现有 `CommonDataKeys.EDITOR` 补给与 autopopup workaround 是否在 EditorTextField 下仍成立需实验（autopopup 对非项目文件编辑器不生效的问题域相同）。建议先在「日志浮层 SqlClickPreview」这类单行/短文本场景试点 `EditorTextField`（其 ctor `(Document, Project, FileType, viewer, oneLine)` 已核实），主预览面板不动。
19. **设置落地页仿制**：`PluginSettingsFolderConfigurable` 的 master-detail 是仿原生实现，平台无公开的子页落地页 API，仿制本身合理。改进项：闪烁定位（:237-260）的颜色 namedColor 化 + 可选换成无动画的选中定位（对齐平台「搜索后高亮但不闪」的克制风格）；行渲染器迁 SimpleColoredComponent 删 GridBag 行内布局。

## 六、不建议动的点（避免过度原生化）

- `WrapLayout`（SqlLogPanel.kt:1344+）：折行工具栏是平台同类面板也存在的自写需求，保留。
- 单击延迟预览（300ms Timer + SqlClickPreview）：刻意设计的交互（平台无对应惯例），保留。
- `IconScaler`：IPGP 裁剪 IconUtil 的既定替代，保留直至裁剪名单变化。
- SQL 展示的 EditorFactory 直建路线（§5.18 主面板部分）：已充分原生化，迁移收益小于风险。
- 导出 HTML 报告的 One-Dark CSS：非 IDE 内 UI，主题无关。

## 七、风险与护栏

1. **253 兼容**：本报告 API 形状取证自 262。落地每个 API 前用既有路线（gradle caches 内 253 发行版 unzip + javap / sources jar）复核签名；重点存疑项：`ListSpeedSearch.installOn`（静态方法可能后于 253）、`Notification.setSuggestionType`、`STICKY_BALLOON`、`OnePixelSplitter(String,...)` 持久化 ctor、`GotItTooltip(String,String,Disposable)`。按「方法名超集版本策略」处理新旧差异。
2. **裁剪名单**：IPGP 发行版裁剪的平台类（JBIconButton/SmallIconButton/IconUtil）继续规避；新增依赖前先在沙盒跑一次。
3. **行为回归**：右键菜单迁 ActionGroup 后逐项核对（菜单顺序、灰置逻辑、快捷键冲突提示）；模态换通知后确认「用户未注意到通知」的场景（如复制成功）是否有替代确认（flashCopied 已有）；Splitter 替换后分割位置持久化 key 变更会让用户丢失一次旧位置。
4. **守卫测试三族同步**：bundle parity（若改名/新增键）、plugin.xml 结构守卫（若动 EP）、禁用 API 扫描（若引入新 import）；主题色 namedColor 的 name 字符串建议加常量表测试防拼写漂移。
5. **性能红线**：列表渲染改造（#8/#9）沿用固定行高与零分配渲染既有优化；StatusText/LoadingPanel 替换不得引入 EDT 长任务（沿用 Task.Backgroundable 路线）。
