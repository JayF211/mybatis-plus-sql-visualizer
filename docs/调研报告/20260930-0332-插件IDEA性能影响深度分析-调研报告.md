## 1. 总结论

**结论维持：已发布基线（master 5aff0c3）对 IDEA 的性能影响与上轮完全一致——本轮零生产码增量，在售用户零影响。** dev 侧 T-PerfSweep16 十一条修复全部落地且逐条判定干净（两路只读子代理分区审计 + 主控约 20 处承重锚点二遍实证全部命中），F36~F41/F43~F46 十条销账、F42 按 D3 定案维持。上轮 F37「若按最小修复激活而无过滤补齐，全 IDE 任意 XML 每高亮 pass 加全树走查税」的高级别警告**在激活轮被守卫设计化解**：喂入元素先过 shouldYield 三判（设置/平台注入器/三方插件），再过 mapper 祖先链守卫与 10 万字符熔断，注入位只可能落在 mapper 文件的语句文本与 11 个白名单属性上。真实的新增敞口收敛为一条**喂入税**（F47，低-中）：注入器 EP 全局注册且 dumb-aware，任意 XML 族文件（含 .idea/pom 等平台自有配置）每个 XmlText/XmlAttributeValue 每高亮 pass 喂入回调一次，IU 主航道在第二判即让位早停，每元素付一次 app 级服务查找 + runCatching 分配——单元素亚微秒级，但为**全插件历史最大扇出面**。另有一条内存屏障族新发现（F48）：SqlMapperParserDefinition 编程式 `addExplicitExtension` 无卸载摘除，动态禁用/更新时旧 classloader 被注册表钉住。

支撑结论的五个事实：

1. **master 侧零生产码**：`git diff bee2019..HEAD -- src/main sub-projects` 为空（主控亲证），上轮全部在役结论（T-Embedded 缓存覆盖、红线族 16 族读数、F18~F35 master 列状态）按构造承袭；主控 spot 核验四族口径逐项吻合（§3.1）。T-TestPerf9 的 buildSrc +24 行为 `-PtestGcThreads/testCiCount/testNoExplicitGc/testTieredStop` 四测试 JVM 旋钮，缺省全不动，零运行期影响。
2. **F37 激活链三线审计干净**（§4.2）：喂入线（每元素 shouldYield 早停，IU 两判即出）、注入线（守卫四层前置：`XmlSynHiGate.kt:37→38→78-81/:85-87/:96`，非 mapper 文件注入位为零）、键击线（#/$ 键击才触达，F38 缓存 + F39 charsSequence 修复在位）。**IU 主航道定性**：`platformInjectorPresent`（Ultimate Database 线恒真）→ 注入全族在 IU 上让位不发生，激活对 IU 用户的功能面为零，成本仅剩喂入税——与该产品的 since-build 243 IU 基线精确互补。
3. **F36~F46 修复判定全部干净**（§4.3~§4.5）：F36 十三家 gutter provider 每到达元素服务查找 3→1 且重活守卫 13/13 前置；F41/F43 双 memo 与 ThreadLocal 形态照仓内定例；F45 取词合并语义逐位等价（唯一差异 `.uppercase()` 移除，消费方本就 ignoreCase）；F46 lexer `regionMatches` 零分配、喂入表静态化、设置复选框零监听器。残留仅 XmlInline 一家未并入收敛（F51，低）。
4. **批次 8 新码基本干净**（§4.6）：R22 T-04 的参数方案存储单方案 50 条 LRU 封顶、主链路（预览保存）走既有 500ms 防抖 + pooled 线程、旧数据迁移构造期一次性；R3 日期族 ANSI 映射每占位符 O(1)、3 个 Regex 全 companion 单例、无 formatter 分配。两处低级（F49 EDT 同步全量序列化、F50 跨线程面扩大）均量级有界。

## 4. 本轮增量审计（按链）

### 4.1 T-PerfSweep16 批次 1 注入族——F37 激活（主控直审，本轮最大新增面）

**修法与计划前提的兑现**：T-PerfSweep16 计划（3d73e5d）D1 推荐「XmlFile 整文件收集」案并预登记「XmlFile 级 EP 注册契约为开工第一证伪点」——实施中被 243 平台源码 jar 证伪（`probeElementsUpInner` 沿 parent 上溯且 `current != hostPsiFile`，PsiFile 永不喂入），按预案回退 B 案：保持元素级喂入、修 cast 目标为 `PsiLanguageInjectionHost`（SqlMapperInjector :38）、守卫前置到首行（:37 shouldYield 先于 cast）。上轮 F37 的「潜伏敞口」（visitor 无过滤）与「守卫函数零调用者」两个孪生面**同步闭合**：`allowStatementText`（XmlSynHiGate :78-81）与 `allowAttributeValue`（:85-87）现各有真实调用点。

**激活后真实生效面三线**：

- **喂入线（新增全局税，F47 载体）**：`multiHostInjector` EP 无 language 限定（plugin.xml :339，本轮亲证未动）+ dumb-aware（:115）→ 平台对任意 XML 族文件（.mapper/pom/.idea 配置均含）高亮 pass 内每个 XmlText/XmlAttributeValue 喂入一次回调。单次成本＝`shouldYield`（:66-69）：`xmlSynHiEnabled()`（:73-76）＝**一次 app 级服务查找**（`ApplicationManager.getApplication().getService`，PluginSettings :688-690 主控亲证）+ runCatching 分配 → `platformInjectorPresent`（:30 lazy 进程内一次）→ `codeHelperActive`（:55/:58 缓存后零反射）。**IU 主航道在第二判早停**（Ultimate Database 线平台注入器恒在），Community 且未装 CodeHelperPro 时第三判后放行进入 mapper 判定。
- **注入线（仅让位环境真实发生）**：XmlText 分支须 `inMapperFile`（:96 祖先链找 `mapper` 标签或根标签名含 mapper，O(树深)，树深有界）+ `tag.textLength ≤ 100_000` 熔断（:24）；XmlAttributeValue 分支同 mapper 守卫 + 11 属性白名单（:90-93）+ 4096 上限（:85-86）。非 mapper 文件注入位恒为零——上轮警告的最坏形态（全树走查+海量注入位）不成立。注入本体走 `ensureParserDefinitionRegistered`（:60/:74-77，`@Synchronized` + registry 判空，进程内一次）后 `startInjecting/addPlace/doneInjecting`，注入 PSI 由平台按 host 缓存、变更才重解析。
- **键击线（低频用户触发）**：typedHandler 仅 #/$ 键击触达（:37 字符判别 O(1) 全局税，上轮已定性）；F39 修复后读单字符走 `charsSequence` 零拷贝；注入片段内击键先做宿主三件套还原（getInjectionHost + injectedToHost，各 1 次/键击）。

**ParserDefinition 伴随件（+65 新文件）**：lexer-only 语言单叶 PSI（`SqlMapperFile`），`findElementAt` 对 offset==textLength 边界返回末叶（O(1) 特判，越界仍 null 不放宽）；语言/文件类型不挂编辑器。注册面见 **F48**。

## 5. 发现点与建议（编号 F47 起承接上轮系列；本轮仅交付报告，待立项指令后归入对应批次/计划）

1. **【低-中】注入器喂入税——每元素每 pass 一次服务查找 + runCatching 分配，IU 让位早停后仍付**（SqlMapperInjector :37 + XmlSynHiGate :73-76 + PluginSettings :688-690，主控亲证）：`multiHostInjector` 全局 EP + dumb-aware（:115）使命中面＝IDE 内全部 XML 族文件（含 .idea/pom 平台自有配置）的每个 XmlText/XmlAttributeValue；单元素成本＝1 次 app 级服务查找 + runCatching 两次小分配 + 2 个缓存布尔读（IU 两判早停；Community 非 mapper 文件再加一次 O(树深) 祖先走查后才出局）。量级＝亚微秒/元素、万元素文件全 pass 毫秒级，占高亮 pass 本身的小头，**但为全插件历史最大扇出面**（gutter 只在 Java/XML 编辑器触达，此面覆盖一切 XML 打开态）。建议：`xmlSynHiEnabled` 读改为快照字段（设置页 apply 时刷新）或 `shouldYield` 结果 per-psi-vfs-epoch 记忆；随 F37 后续批次顺带。
2. **【低-中·内存屏障族】SqlMapperParserDefinition 编程式注册无卸载摘除**（SqlMapperInjector :74-77 `LanguageParserDefinitions.INSTANCE.addExplicitExtension`，主控亲证）：动态禁用/更新插件时平台只摘 EP 声明的扩展，编程式显式注册无人摘除——旧 classloader 被 LanguageExtension 注册表钉住，属本仓动态卸载屏障在役清单同族（归档档 `docs/memory-archive/` 键 project-dynamic-unload-barriers：结构性注册不可动态移除）；SqlMapperLanguage 本身亦属语言级结构性屏障（平台既知形态）。建议：按方案 A 口径登记 BarrierRegistry + 评估 Disposer 挂 plugin disposable 摘除，并纳入 PlatformSignatureCrossVersionTest 护栏面。
3. **【低】方案操作 EDT 同步全量序列化 + 写放大**（ParamHistoryCache :202-223/:286-298，B 路出证主控亲证）：switch/saveAs/rename/delete 每次全方案×条目重序列化，未变化的默认方案也重写 legacy 字段（:217-222）；方案个数无上限（:32）。建议：switch 只写 `paramActiveScheme` 指针字段；方案个数设上限（如 20）。
4. **【低】ParamHistoryCache 跨线程面扩大**（:186-187 pooled 结构写 vs :117/:151/:174 EDT 读，无同步）：既有 T-Perf-24 同族形态（pooled save vs EDT recall）的面扩大，后果为 EDT 渲染期潜在 CME/悬挂，非稳定性能税。建议：随触达批统一 `ConcurrentHashMap` 化或读写锁。
5. **【低】XmlInline 未并入 F36 收敛**（XmlInlineSqlGutterLineMarkerProvider :42，主控亲证）：仍走旧 `(Class, Boolean)` 重载，每元素 2 次服务查找（其余 13 家 1 次）；XML-only 触达、成本廉。建议随 gutter 触达批一行改传参。
6. **【微】方案下拉每 showResult pass 重建**（SqlPreviewPanel :3331/:3362）：布局路径非 paint 热路径，常数级组件构建；如需可改「方案集变更时重建」，登记不阻塞。
7. **【微】三处 O(1) 兜底项不建议动**：SqlExportService object 级 ThreadLocal 常驻（每线程 1 SDF）；XmlSqlCompletionContributor 无显式非注入快捷路径（getInjectionHost O(1) 兜底）；renderParam 每占位符 2~3 次锚定单例 regex（:68-:76，占位符频率、有界）。
