## 1. 总结论

**结论改写：默认配置下插件对 IDEA 的资源型性能影响仍可忽略，上轮立项的 T-PerfSweep5 十六项全部收口（十五项落地、一项诚信不实施），且本轮交付了两处系列级正向（心跳计时改造根治「30 秒必掉线」、设置页导航改 EP id 消除 EDT 慢操作）；但本轮引入了一个新的高频面——预览插入列 inlay 注册到 IDE 全部 SQL 编辑器，其规划器无缓存、一次性闸门非线程安全，是全新增的 daemon pass 成本与一处并发正确性面。** 另有两条中低发现值得排期：MCP `schema_context` 每次调用重建全量索引（无跨调用缓存），XML 预览对同一文本解析两遍。其余为中低/低危有界长尾，不动摇总结论。

支撑结论的五个增量事实：

1. **T-PerfSweep5 十六项全部收口**（§3.1）：执行链 DDL 判定解析复用（`UnboundedWriteDetector.kt:86`/`:104` 单槽 + `MetadataInvalidator.kt:78` parseSlot）、方言 URL 探测 TTL 缓存（`DataSourceUrlProbe.kt:54`）、AgentManager 常驻面解耦（`AgentUrlRegistry` 弱键 + monitor 懒启 `AgentManager.kt:264`）、XML 定位单槽缓存、schema 全扫限额、七项低危快件全落地；T-PS5-06 以「调用内索引」替代「扫描账本」、T-PS5-14 设置页懒建经实测（全量构造 ≈32.1ms）判定「诚实不实施」——两项均为计划允许的偏离路径。
2. **本轮最大正向：心跳计时改造根治「增强捕获 30 秒必掉线」**：agent 侧 `lastOutboundMs` 墙钟差取代「按假定每轮 200ms 累加」（`SenderLoop.java:101`/`:113`/`:121-124`），IDE 侧窗口由心跳间隔推导（`AgentProtocol.kt:40` `ONLINE_WINDOW_MS = HEARTBEAT_INTERVAL_MS * 3` = 30s，跨侧守卫锁定）；实测实际周期约 10.8s 对 30s 窗口有 2.8 倍余量。配套 `HeartbeatRhythmTest.java:41-101` 是真实读数测试（真跑发送循环 + 探针 ServerSocket 测节奏），非文本断言。
3. **inlay 新功能是全新增的 daemon 成本面**（§4.2）：`plugin.xml:257-258` 以 `language="SQL"` 注册，对 IDE 内所有 SQL 编辑器生效（含用户自己的 .sql 文件；provider 内靠文件名 + userData 双锚点过滤，非预览文件每次 pass 只付一次常量正则 + 两次 userData 读）；命中后每次 daemon pass 全文重新词法（`PreviewInsertColumnInlayProvider.kt:205-206` → `InsertColumnInlayPlanner.plan`，千行 VALUES 可达十万级 token 分配），且 `collected` 一次性闸门是普通 `var`（`:200`）——平台 `InlayHintsPass.doCollectInformation` 用 `JobLauncher.invokeConcurrentlyUnderProgress` 分片并行（平台源码实证），同一 collector 可能被两线程各跑一遍全文。
4. **MCP 与 XML 两条链各有一次可省的全量工作**：`schema_context` 每次调用遍历目标数据源整个 DasModel 并为**所有表的所有列**建 `ColumnLine`（每列 4 次反射 invoke + 3 次 runCatching），最终只输出请求的 ≤limit 表（`McpSchemaContextService.kt:157-193`/`:272-296`），无跨调用缓存；XML 一次预览对同一文本解析两遍（`XmlPreviewService.kt:43` 跨 ns 扫描一次 + `:44` 正式解析一次），SecureXml 预扫与 `DocumentBuilderFactory.newInstance()` 成本各付两遍（实测工厂 125µs/次 ≈ 解析的 8%）。
5. **常驻红线面持平、启动期净减**：Timer 构造点 17 处（git diff 核定本轮零增删）、repeating 5 处、Thread.sleep 实点 7 处、invokeAndWait/Executors/固定周期/SimpleDateFormat（6 处）/热路径现场正则（0）全持平；`plugin.xml` 本轮**删除**启动期 `SqlTemplateShortcutConflictCheck` action 并摘掉三个模板动作的平台冲突默认键位（T-TemplateKeyDrop）——启动期少一项后台动作与一次 keymap 全 actionId 扫描。

## 4. 新增子系统审计

### 4.1 增强捕获心跳与重连（agent 双侧，本轮最大变更）

- **【正向·系列级】心跳计时改造根治掉线**：agent 侧由「按假定每轮 200ms 累加」改为墙钟差（`SenderLoop.java:101`/`:113`/`:121-124`），事件突发期心跳自动被抑制（语义正确且省热流量开销）；IDE 侧窗口推导式 `ONLINE_WINDOW_MS = HEARTBEAT_INTERVAL_MS * 3`（`AgentProtocol.kt:40`）由跨侧源码扫描守卫锁定，任一侧漂移即红。实测实际周期 ≈10.8s（轮粒度 1.2s 离散化），对 30s 窗口余量 2.8 倍。
- **【正向】premain 通道改循环 accept**：会话摘除后 agent 可重连（原「只 accept 一次」使掉线即不可恢复）；线程数不增（本就是 1 条/通道），变化是寿命（≤120s → 整轮运行，兜底 TTL 12h），通道上限 4（`AgentManager.kt:114`），三条收口（未认领超时 `:720-732`、pid 消亡 `:756-768`、项目 Disposer 树 `:683-692`）。
- **【中低】attach 链未获重连能力**：`attachAndOffer` 仍是「`ServerSocket(0,1,loopback)` → `accept()` 一次即关」（`AgentManager.kt:581-610`），而 agent 侧 `SenderLoop` 是无限重连（`SenderLoop.java:86-155`）——现场根因形态在 attach 路径原样保留，attach 启动的运行一旦掉线仍是终局（功能面而非资源面，见 §5 发现 6 一并处置）。
- **【中低】退避在「连接成功」处复位**：`backoffMs = 1000` 写在 `new Socket(...)` 之后（`SenderLoop.java:90-94`），于是「每次都能连上、连上马上被对端关掉」的形态不指数退避而为稳定 1s 一发（§5 发现 6）。
- **【低】pid 未知时同 pid 去重失效**：`readHelloPid` 失败返回 0 就继续建会话（`:820-824` 判据含 `pid > 0`），每次回连新增一条会话 + 读线程 + socket，上界由 `MAX_PREMAIN_RECONNECTS = 32`（`:104`/`:780-786`）收住。
- **【低】monitor 懒启后无复位点**：`monitorStarted` 只写 true（`:217`/`:262-263`），`shutdownAll`（`:1073-1088`）不复位——用过一次增强捕获的项目保留 1 条 5s 空转线程至项目 dispose（每拍空表分配即返回）。
- **正向**：premain 闸门在提取 jar / 开端口之前（`:626-633`）；jar 缓存复用 + 内容定名 + 不登记 deleteOnExit（`:902-928`）；attach 排队去抖判定前移到请求线程（`:466-472`）；`ConnectWeaveEndToEndTest` 夹具鉴别力补强（子 loader 前提自检 `:148-151`，防空绿意识明确）；`SqlHookCallbacks` 包装失败返回原语句零额外成本（`ConnectionHandler.java:52-61`）。
- **agent 侧每次连接/每条 SQL 成本**：HELLO + 立即补一条 HEARTBEAT（约 20 字节 ×2，`SenderLoop.java:98-100`）；每条 SQL 仍是编码 + 写帧 + flush 不变；`chooseProxyLoader` 每次 connect/prepareStatement 跑接口可见性实测（不缓存是为避免强引用驱动类钉住旧 RestartClassLoader，`ProxySupport.java:78-81` 取舍合理，N ≈ 接口数 4~8 次类查找）——量级与 `Proxy.newProxyInstance` 自身开销同阶或更小。

### 4.2 预览插入列 inlay（全新高频面）

- **注册面**：`plugin.xml:257-258` `codeInsight.inlayProvider language="SQL"` — 对 IDE 内**所有** SQL 编辑器生效（含用户自己的 .sql 文件）；平台侧 EP 过滤用 bean 的 language 属性不实例化，只有语言匹配的 pass 才加载 provider 类（243/262 源码同形）。方言映射文件（面板预览映射到 MySQL 方言）因 `SqlLanguageDialect` 的 base language 就是 SQL 而同样命中（平台源码核实）。
- **【中低】规划器无缓存，每次 pass 全量重建**：`collect` 每次取 `editor.document.text`（`PreviewInsertColumnInlayProvider.kt:205`）后 `InsertColumnInlayPlanner.plan(text)`（`:206`）——`tokenize` 预分配 `sql.length / 4 + 8` 的 ArrayList（`InsertColumnInlayPlanner.kt:306`）逐 token 造对象，`wordUpper` 每次 `substring + uppercase` 两次分配（`:321-325`）且被 `isWord`/`isStatementBoundary` 高频调用。常态预览 SQL 微秒到毫秒级（后台线程，EDT 不付）；批量 INSERT（foreach 生成千行 VALUES、数百 KB）时每次 pass 十万级对象分配。缓存键现成（`document.modificationStamp`）。
- **【中低】一次性闸门非线程安全**：`private var collected = false`（`:200`）。平台 `InlayHintsPass.doCollectInformation` 用 `JobLauncher.invokeConcurrentlyUnderProgress(elementsInside + elementsOutside, ...)` 分片并行、`skippedCollectors` 虽为并发集但置位发生在 `collect` 返回之后（`ideaIU-2024.3.7.1-sources.jar` 内 `com/intellij/codeInsight/hints/InlayHintsPass.kt` 实证）——两个分片线程可能各自首元素都看到未被 skip，各跑一遍全文规划并把提示二次投进同一共享 sink（同 offset 的 presentation 会聚进同一 renderer）。修法极廉（`AtomicBoolean`/`synchronized`）。
