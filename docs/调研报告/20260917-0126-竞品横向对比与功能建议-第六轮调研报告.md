## 4. 专项调研与格局修正

### 4.1 zMyBatis 入场解剖——赛道内第一个活跃新面孔

**身份**：Marketplace id 30447，2026-04-01 上架，109 下载 0 票，GitHub `luceat-lux-vestra/zMyBatis`（Kotlin，0 star）。定位「将 MyBatis 动态 SQL（XML/注解）eval 成带参可执行 plain SQL」——正是本插件写前静态预览环的单点复刻。

**活跃证据**：GitHub 09-14~09-16 连续 5 提交，进入高频开发期；Marketplace 版本页未见随发（或未过审）。此前五轮四组搜索扫描从未捕获它（"mybatis" total 228 的前 20 无它、"sql preview" 前 20 无它），曝光面为零。

**威胁判断：低，但性质不同于前两个死者**。同赛道的 MyBatisSQLPreviewer（208 下载）与 MyBatis SQL Analyzer（1,131 下载）都是上架即停的死项目，而 zMyBatis 是上架五个月后进入活跃开发——虽然更可能是个人项目回坑而非有组织竞争。本插件对位的护城河不在单点 eval（这条赛道六轮验证只有死人和我们），在七环闭环+十工具 MCP 面+增强捕获的组合；单点功能复刻不改变格局。处置：列入跟踪名单，季度体检+哨兵关键词覆盖，不预设应对动作。它的 eval 实现形态是否有个别可吸收细节，留下一轮顺带看。

## 9. 风险

1. **滞留债四犯，且性质从「延误」升级为「资产安全」**。前三轮的滞留是「用户看不到」，本轮的滞留是「九个交付只有一份未推送的本地副本」——这不是叙事问题是容灾问题，push 留底必须在任何其他动作之前。
2. **并行交付与合流的撞车窗口**。报告落盘时有交付会话在途且盘点顺序②（T-MergeDev2Master）随时可能启动；若合流与发行动作不在同一会话闭环，第九个交付（T-StatementNaming）可能成为下一个滞留孤例。
3. **冷启动剪刀差拉大**。+37/日 的增长与 0 票 0 评论第三周的缺口同时在扩大——下载越涨，无口碑承接的脆弱性越显性；N-20 若继续空转，搜索位红利（"sql visualizer" 第 1）在泛词曝光为零的现状下没有第二来源。
4. **CodeHelperPro 校验型工具的落地倒计时**。validate_mybatis_mapper 挂 notes 16 天，脉冲式对手的下一波随时可能一次性落地校验型 MCP 工具；我方的对位叙事已落 dev 但同样未出场——这是六轮以来第一次「叙事先手」和「能力出场」同时悬在未合流状态上。
5. **AI 替代（延续，注脚更新）**。DBX 三线 AI 代理化（desktop/MCP/CLI/agents 同日发版）与 CodeHelperPro 校验型工具确认 agent 面竞争在加速；本插件的十工具面宽度领先仍在，但领先值只能由合流兑现。锚定 IDE 深度集成、执行期确定性、字节码级捕获独占性的立场不变。

## 10. 落地优先级建议

如果只做三件事：**留底+合流+发行一条龙**（先 push dev/master 留底，再 T-MergeDev2Master 合流，再 v2026.9.18 正式版上 Marketplace，文档回填与测试口径钉死随行——这是连续第三轮排第一的事，本轮加上了容灾属性）、**N-20 首评与画像重发**（增强捕获这个全场独有卖点目前只存在于 CHANGELOG 里，Marketplace 页面还在讲 9.11 时代的故事）、**N-21+O-26 小件插缝**（手工事务只读证明是七环叙事的自然收尾，方言复位自查是信创用户的暗坑排除）。

一句话总结本轮：交付侧创造了六轮以来的最快纪录——九个计划二十四小时九个落地，连报告都在追赶交付的尾巴；但出场清单（推送/合流/转正/首评）连续第三轮原封不动。纪录越长，欠账的利息越高——下一步唯一正确的动作是把已经造好的剑递出去。
