# （已移出公开仓）CodeHelperPro XML 高亮与补全能力再深挖调研（第二轮）

- 迁移日期：2026-10-12
- 处置：本文含对第三方**商业闭源插件**的逆向分析（类级实现细节、反编译路径），已移入内部资料库（`sql-visualizer-internal-docs` 的 `调研报告/` 目录），不随公开仓发布。
- 保留本占位文件的原因：维持引用路径可解析（配套开发计划与本仓其他文档指向本路径）。
- 公开结论与实施计划仍在公开仓：`docs/开发计划/20261012-1552-T-XmlGap-mapperXML高亮补全导航差距收敛-开发计划.md`。
- 公开可述的结论摘要（不含逆向手段与内部实现细节）：
  1. 竞品在 mapper XML 内的能力由三块组成——编辑器内语法着色、位置感知的代码补全、以及引用跳转/重命名；我方前两块已具备雏形但粒度与覆盖面偏窄，第三块整体缺失。
  2. 我方的 XML 着色在**用户本机（同时装有其他 MyBatis 插件）会整体让位**，实际观感接近「没有高亮」；这是让位粒度按「宿主元素」而非「着色区间」判定的结果。
  3. 我方 `#{}` 与 `${}` 同色不可区分、表达式内部无分色、颜色不可配置；补全缺口集中在「属性值」与「`#{}` 内部结构属性」两处。
  4. 竞品的若干能力建立在「引导注释」与自研索引之上，属其特有形态，我方不照搬；我方的方言感知能力是其免费档没有的差异化点。
- **勘误（2026-10-12 收口轮）**：第 2 条的归因**不完整**。实施期实测表明，「观感接近没有高亮」有两个叠加成因：①让位粒度按宿主元素判定（已由 W1 区间级互补修掉）；②**`plugin.xml` 的高亮器工厂 EP 名写成裸 `<syntaxHighlighterFactory>`（平台真名 `lang.syntaxHighlighterFactory`）→ 注册被平台静默忽略 → 注入语言的高亮器从未被实例化**（真根因，与竞品/让位无关；已修并加自动守卫）。详见配套开发计划 §十「着色真根因定位与修复」。
