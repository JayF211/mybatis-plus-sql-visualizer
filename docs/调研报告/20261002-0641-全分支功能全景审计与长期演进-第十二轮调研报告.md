## §3 优劣势分析

### 3.1 优势

1. 赛道无对位的功能宽度。静态预览赛道连续第五个月无竞品跟进（二十轮 §3.4）；dev 批次 9 后条件求值探镜、历史对比、EXPLAIN 结构化渲染、可移植导出、N+1 徽章、数据源角标、分页模拟、历史检索八件无任何竞品对位。
2. 信创方言矩阵是护城河。11 库含达梦/金仓/OceanBase/openGauss，头部竞品（MyBatisX、JPA Buddy、CHP）无一做国产库方言格式化与 EXPLAIN 分发，信创场景是结构化差异而非营销差异。
3. AI-native 先发。插件内 11 工具 MCP 面+ACP 会话下发+审计+只读护栏，竞品零对位；DBX 的 MCP 属外部产品形态，不在 IDE 插件货架竞争。
4. 兼容面结构性领先。since-build 243 无上限对竞品普遍 262/263 封顶（MyBatis Log Free 262+、官方两家 263 单线、Jtools 171-265 最宽也止于 265）；官方化挤压周期里，老版本用户只有我方能接。
5. 日志还原链深度。四解析器+字面量恢复+落盘+检索+对比+跳源码的闭环，对照 MyBatis Log 系停更 3.7 个月、MybatisLogFormat 262 崩溃报障，捕获质量是评论区可验证的口碑点。
6. 工程底盘复利。6370 例门禁、572 测试类、红线族与守卫测试族、九次墙钟压缩、二十轮竞品+十九轮性能调研纪律——这套底盘决定后续每个版本的质量下限与迭代速度。
7. 安全姿态可对企业交代。凭证不出 IDE、fail-closed 只读护栏、agent 注入双闸门+脱敏+24h 冷却，是企业采购叙事的现成素材。

### 3.2 劣势与风险

1. 市场冷启动未破零。343 下载、0 评 0 票第 44 天、真实增长 1~1.5%/日、sql explain 搜索位 11/31 且已易手。功能再强，无信任资产则转化环节全空，这是当前第一短板。
2. 交付货架剪刀差。172 笔滞留 dev，在售用户与产品前沿差一个批次 9；每拖一个发行窗口，剪刀差复利。
3. 上手复杂度税。93+12 项设置、9 个设置页、18 种行标记，首日价值路径长；onboarding 目前只有一条 Alt+Shift+Q 指路通知。功能多本身在冷启动期是负资产。
4. 获客机制空白。W1 文案备料三件至今未产出（发行日 10-06 倒计时内），且台账只有「搭发行车」没有「行车」——破零后的常态获客无条目。
5. 真机验证欠账集中。Memory leak 红线四类多轮挂 P3 无时点、方言真机验收 9/11（缺 MariaDB/SQL Server）、批次 9 十项走查挂起到「下次调整后」（无定义）。对外「EXPLAIN 11/11」与真机 9/11 之间的落差未被台账显式管理。
6. 发行链单点依赖用户手工。tag、上传、8 处同步、update.json 全在用户侧，窗口错过成本高。
7. AI 面有平台门槛。MCP 依赖平台内置 MCP Server（2025.2+），2024.3~2025.1 区间用户拿不到该面；agent 注入属安全敏感形态，信任成本天然偏高（双闸门已做，但获客文案须正面解释）。
8. i18n 仅双语。DBX 以多语言铺量，我方 zh/en 之外无存在感；按受众结构判断 ROI 低，属「有意不做」而非缺陷，但该口径未正式登记（见 §5.3）。

## §6 新功能推荐

在册候选 R25~R29、R34~R36 之外，本轮基于台账缺口分析（既有调研无对应条目、亦非红线明示不做）提出五件，编号自 R37 起。每件含痛点依据、形态、规模、前提；实施与否由配套计划 §五 决策点拍板。

### R37 SQL 与执行计划的安全 AI 上下文交递（首推）

- 痛点：开发者把 SQL/EXPLAIN 贴给 AI 助手时手工脱敏易漏敏感字面量；竞品新面孔 SnippetVeil（33770，「执行计划脱敏后贴 AI 上下文」）的出现证明该需求真实。我方有 11 个 MCP 工具服务接了 MCP 的 agent，但没接 MCP 的用户（多数人）没有任何「把 SQL 安全交给任意 AI」的插件内出口。
- 形态：预览面板与 EXPLAIN 面板加「复制为 AI 上下文」动作，复用 agent 侧 Desensitizer 脱敏核心，输出结构化文本块（方言+SQL+计划+表列摘要），敏感字面量参数化。
- 规模 M；前提 V51（脱敏边界与复用面核实）。红线对照：本地功能非订阅服务，不触「不做订阅制 AI」红线；安全姿态与 sqlv_schema_context 的「凭证不出 IDE」同源。
- 为何本轮成立：批次 9 落地后插件内结构化数据（EXPLAIN 树、参数方案、schema 上下文）已齐，只差出口；竞品信号首现且无第二家。

### R38 数据源角标强形态

- 痛点：多数据源项目日志里分不清 SQL 打到哪个库；已落弱形态只到 agent URL 推断。
- 形态：dynamic-datasource 族 url 到语义名映射、事务与连接池身份可达性（V40 采样已在册）。
- 规模 M；前提 V40（勿重复立项）。为何成立：弱形态 fa37403 已验证 UI 通道，属自然延伸；竞品零对位。

### R39 热重载场景兼容（JRebel/devtools）

- 痛点：热重载后 mapper 变更，gutter、预览、解析缓存是否失真从未实测；JRebel MyBatis-Plus 周 +151 且 mybatis 词跳升第 3，该人群在涨。
- 形态：先立 V50 证伪件（runIde 挂 JRebel 场景观察失效形态），实证有缺口再立实现件（缓存失效监听或 PSI 重载钩子）。
- 规模：V 为 S，实现视证伪结果 M~L。注意此条是「痛点假设」，存在性未验证，禁止跳过 V 直接派工。

### R40 团队配置档共享

- 痛点：93 项设置是个人资产，团队无共享形态；阶段二「企业护栏」叙事有定位无载体。
- 形态：SettingsIO 白名单 23 项扩为全量 profile 导出（敏感项甄别后），项目级 12 项深化为「可提交到 .idea 的团队档」。
- 规模 M；前提 V52（白名单扩容兼容性与敏感字段甄别清单：代理、注入确认态等机器态字段绝不入档）。

### R41 内测池运营与候选投票机制（机制件，非码件）

- 痛点：N-24 的根因是反馈盲飞——没有一手用户输入排序候选；Gitee 内测邀请只是 W1 的一次性文案。
- 形态：Gitee issue 模板+内测名单维护+批次候选投票贴+每轮调研报告候选来源挂用户票权；官网 /feedback 已是入口，补机制不补代码。
- 规模 S。为何成立：破零之后立刻需要「第二步」，现在立机制可在首批评论落位时启用。

### 明确不推荐（延续二十轮 §8.5 并加一条）

不跟 DBX #194 OCI thick、#189 zip 导入、#195 formatter；不做 SQLite 文件查看器抢位；不跟 Lens 系发版节奏；i18n 扩语言按 §5.3 登记有意不做。

## §7 结论

这个插件的功能面与工程底盘已经具备「碾压同类」的硬条件：静态预览赛道无跟进、八件功能无对位、信创方言与 AI 通道两道结构性护城河、兼容面领先全场、6370 例门禁的底盘在同类里没有对手。短板同样清晰且全部集中在「最后一公里」：货架落后一个批次 9、零评零票 44 天、获客机制空白、真机欠账无时点。当前阶段决定成败的不是再添功能，而是把交付与信任资产补上——10-06 发行窗口是近期唯一的转化杠杆，W1 弹药是唯一 P0 缺口。功能演进按「先收口（D31+O-93）、再纵深（R37 与 R25~R29 在册池）、后生态（R40/R41 与企业叙事）」的节奏走，与 1712 排期的阶段划分一致。
