## 4. 专项调研与格局修正

### 4.1 MyBatisX 1.7.7 解剖——「盲区武器」证伪

第四轮 §3.2 信号 2 称其为「全场最大盲区」，并设了过审 48 小时复查触发器（N-16 ③）。本轮触发器命中：1.7.7 于 2026-09-15 07:06 UTC 过审上线（updates id 1171092）。解剖过程与结论：

1. **notes 是死信息**：1.7.7 与历代版本的 changeNotes 逐字节相同（仍是 1.4.8 时代的陈旧模板），公开渠道无法判断内容——所以直接下载插件包本体做条目级 diff。
2. **包体 diff 无功能新增**：1.7.7（3,854,263 字节）对 1.7.6（3,294,483 字节），主 jar 条目数 559→538 反而变少。新增 8 个 class 全是包装/拼写修正/换皮级（NamespaceConverter、CodeGenerateUI$MyBaitsXModuleInfo、MapperNamespaceNameUtils 等）；移除 28 个（模板设置 UI MybatisXTemplateSettings/MybatisTemplateGeneratorConfigurable、TablePreviewUI、smartjpa extension 等）。**plugin.xml 全文扫描：mcp 0 命中、preview 0 命中、explain 0 命中**。
3. **本质是平台兼容收口**：since/until 从 232–262.* 收窄为 **251–263.***（2025.1~2026.3），连带依赖升级（commons-lang 2.6→commons-lang3、freemarker 升版）。
4. **开源仓库与发版完全脱钩**：GitHub pushed_at 仍是 2024-08-20（25 个月），发版节奏（1.7.5 03-25 → 1.7.6 05-17 → 1.7.7 09-15）只发生在闭源上传侧。
5. **残留疑点定案**：详情端点 hasUnapprovedUpdate 仍为 true，但 20 条 updates 全部 approve=true/listed=true、无隐藏实体——判定为标志残留噪声，「待审压 8 天」事件终结。

## 9. 风险

1. **双轨债第三犯（首位，体量创纪录）**。第四轮的教训是「集成链与 master 双向漂移 75/29」，本轮 dev 与 master 漂移到 94/26，外加 m56 三线（17 提交无远端）与 master/dev 各自未推送的 5/2 个提交。同一教训连续三轮出现，说明问题不在认知在执行——合流动作应该固定为「每个交付批次合完即回合」，而不是等调研报告来催。
2. **守位窗口在变宽，但出场才能守位**。对手侧风险全面下降：MyBatisX 证伪、CodeHelperPro 喘息、Analyzer 停摆补强。风险从「被抢跑」转移为「自我延误」——十工具 MCP 面一天不到用户手里，先手就一天不算数。CodeHelperPro 的脉冲式节奏意味着下一波加码随时可能来，哨兵在盯，但盯到信号后仍然需要已出场的能力去应对。
3. **冷启动未破局**。+13/日是好信号但只有 1 天样本；0 票 0 评论在 48 条 CHANGELOG 的版本上架后依旧。若 N-17 首评继续空转，下载增长缺口碑承接，搜索位（"sql visualizer" 第 1）的红利会随竞品任何一次复活而稀释。
