## 🎯 项目命名

项目名：**MyBatis-Plus SQL Visualizer** 

## 📋 痛点分析

| 痛点 | 描述 | 影响 |
|------|------|------|
| **调试困难** | 开发者无法直观看到MP构造器最终生成的SQL | 排查问题时需要开启MyBatis日志，查看繁琐的控制台输出 |
| **SQL优化不便** | 无法快速验证生成的SQL是否合理 | 影响性能调优效率 |
| **联表查询复杂** | `MPJLambdaWrapper`联表查询逻辑复杂，容易出错 | 需要频繁对比实际SQL验证逻辑正确性 |
| **参数不可见** | 日志中的SQL带着`?`占位符 | 无法直接看到实际参数值，调试效率低 |
| **CRUD全覆盖** | 现有方案只能看查询SQL，无法预览更新、删除语句 | 误操作风险高，特别是批量更新/删除 |
| **学习成本高** | 新成员学习MP时，无法直观理解API对应的SQL效果 | 团队培训成本增加 |

## 📌 预览 SQL 与运行时 SQL 的已知差异（设计特性）

> 预览目标是对齐 MP 运行时语义；以下差异为**静态求值特性**，语义等价、仅文本不同（M29 文档化）。

| 差异 | 说明 |
|------|------|
| **静态常量内联** | `in(col, DicConstants.A, DicConstants.B)` 等静态 final 常量引用被求值内联（预览 `IN (1, 2)`）；MP 运行时渲染 `IN (?, ?)` 绑定参数 |
| **集合单占位符** | `in(col, 集合变量)` 运行时大小不可静态展开 → 预览 `IN (?)`；面板输入框支持逗号分隔多值回填（输入 `1,2,3` → `(1, 2, 3)`） |
| **分页字面量计算** | `page(new Page<>(1, 10), wrapper)` 字面量直接计算 `LIMIT 0, 10`；运行时变量渲染 `LIMIT ?, ?`（offset 参数来源标注 `(pageNum - 1) * pageSize` 公式） |

## 🚀 核心功能

### 1. 支持的Wrapper类型
- ✅ **LambdaQueryWrapper** - 普通查询
- ✅ **LambdaUpdateWrapper** - 更新构造
- ✅ **LambdaDeleteWrapper** - 删除构造（MP 3.5+支持）
- ✅ **MPJLambdaWrapper** - 联表查询（MyBatis-Plus-Join）
- ✅ **MPJQueryWrapper** - 联表查询（字符串字段版）

### 2. 支持的SQL操作类型
```java
// 查询类
- select() / selectAs()  // SELECT 字段
- from()                 // FROM 表
- join()                 // JOIN 关联
- where() / eq() / like() // WHERE 条件
- groupBy()              // GROUP BY
- having()               // HAVING
- orderBy()              // ORDER BY
- limit() / page()       // 分页

// 更新类
- set()                  // SET 字段值
- setSql()              // 自定义SET

// 删除类
- delete()              // DELETE 条件
```

### 3. 功能特性
- 🔍 **实时预览**：光标悬停或快捷键触发，显示完整SQL
- 📋 **一键复制**：生成SQL后直接复制到剪贴板
- 🎯 **参数替换**：可将`?`替换为实际参数值（支持基本类型、对象、集合）
- 🎨 **语法高亮**：在工具窗口显示带语法高亮的SQL
- 📊 **格式化输出**：自动美化SQL格式，支持缩进和换行
- 🔄 **多数据库方言**：支持MySQL、PostgreSQL、Oracle等（通过数据库连接获取）
- ⚡ **批量操作预览**：批量插入/更新时生成批量SQL

## 📖 使用说明（初稿）

### 基础使用

**方式一：快捷键触发（推荐）**
1. 光标定位到 `MPJLambdaWrapper` 或 `LambdaQueryWrapper` 变量处
2. 按下快捷键 `Ctrl + Alt + S`（Windows/Linux）或 `Cmd + Option + S`（Mac）
3. 在弹出窗口或工具窗口查看生成的SQL

**方式二：右键菜单**
1. 选中包含Wrapper的代码行
2. 右键 → 选择 `"MP-SQL-Preview"` → `"Convert to SQL"`
3. 查看生成的SQL

**方式三：实时悬停**
1. 鼠标悬停在Wrapper变量上
2. 自动弹出提示框显示生成的SQL（类似文档提示）

### 高级功能

**参数值替换**
```java
// 代码中的条件
.eq(DeviceInfoEntity::getId, deviceId)  // deviceId = 1001L

// 生成的SQL（参数已替换）
WHERE device_info.id = 1001
```

**批量操作预览**
```java
// 批量更新
List<DeviceInfoEntity> list = ...;
boolean result = service.updateBatchById(list);

// 插件生成
UPDATE device_info 
SET station_id = ?, share_scheme_id = ? 
WHERE id = ?
-- 实际参数: [stationId=101, schemeId=5, id=1], [stationId=102, schemeId=6, id=2]
```

**联表查询预览**
```sql
-- 你给出的示例代码转换结果
SELECT 
    cd.id AS device_id,
    cd.station_id AS station_id,
    cd.share_scheme_id AS scheme_id,
    cssm.merchant_id AS merchant_id,
    cssm.electricity_share_rate AS electricity_share_rate,
    cssm.service_fee_share_rate AS service_fee_share_rate,
    cssm.parking_fee_share_rate AS parking_fee_share_rate
FROM device_info cd
INNER JOIN car_station_share_scheme_merchant_info cssm 
    ON cssm.scheme_id = cd.share_scheme_id
WHERE cd.id = 1001
    AND cd.share_scheme_id IS NOT NULL
ORDER BY cssm.sort ASC, cssm.id ASC
```

### 配置选项

插件提供配置页面（Settings → Tools → MP-SQL-Preview）：

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 数据库类型 | 选择目标数据库方言 | MySQL |
| 是否替换参数 | 是否将`?`替换为实际值 | 是 |
| SQL格式化 | 是否美化输出 | 是 |
| 显示方式 | 弹窗/工具窗口/两者 | 两者 |
| 快捷键 | 自定义触发快捷键 | Ctrl+Alt+S |
| 自动预览 | 光标悬停时自动显示 | 开启 |
| 表名策略 | 表名映射规则（下划线/驼峰） | 自动识别 |

## 🎨 技术选型建议
