# 🎉 SQL Visualizer v2026.10.6

> 发行说明留档：对应 Gitee 发行版 **v2026.10.6**（标签 `2026.10.6`），附件 `mybatis-plus-sql-visualizer-2026.10.6.zip`。
> 本说明于 2026-09-30 预先整理、2026-10-05 发行日补充（10-05 三项修复与实测门禁读数），版本号按「版本号即发行当日日期」规则定为发行日 2026-10-06。
> 范围＝自 v2026.9.23 发行包（2026-09-23 打包）之后的全部用户可见增量。

自 v2026.9.23 后的正式版。本版主题是 **嵌入实体识别补全 + SQL 日志屏蔽 + 信创方言扩容 + 通用 XML 内嵌 SQL 识别**：JPA、Spring Data、MyBatis-Plus 三族 `@Embedded` 嵌入值对象全形态识别；日志列表一键屏蔽保活心跳类 SQL 并配套管理对话框；方言注册表扩至 11 种（新增 OceanBase 与 openGauss）；自研框架自定义 XML 标签里的 SQL/HQL 可直接预览；另有一批 HQL 列名映射、foreach 渲染、T-SQL 切分与注入范围收口的修复。

## ✨ 新增

**`@Embedded` 嵌入值对象识别补全**
- 用户报障「插件不能识别 @Embedded」的全缺口闭合，三族形态一并支持：
- **JPA 嵌套点路径覆写**：嵌套嵌入的列名覆写按规范用 `name="zipcode.zip"` 点路径，此前按裸名查找、点路径覆写静默丢失——现按「实体根点路径 > 嵌入相对点路径 > 裸名兜底」三级查找
- **Spring Data 形态**：`@Embedded.Nullable` / `@Embedded.Empty` 捷径注解不再落成伪单列，`prefix` 按官方语义拼在嵌入对象每一列之前
- **MyBatis-Plus 混合注解实体**：`@TableName` 与 jakarta `@Embedded`/`@Embeddable`/`@EmbeddedId` 共存的实体，值对象字段展平为宿主表列，Wrapper 预览、批量模板与 CRUD 生成不再产出伪列
- **派生查询嵌入段伪列修复**：`findByUpdateInfoCreatedTimeAfter` 这类嵌入段驼峰路径此前在派生查询 WHERE / ORDER BY 被映射成伪列，现按展平列正确映射

**SQL 日志屏蔽**
- 日志列表右键【屏蔽此 SQL】一键屏蔽保活心跳类 SQL（如 `SELECT 1`），支持多选批量
- 管理对话框：规则列表（模式摘要 / 创建时间 / 已拦截计数）+ SQL 语法高亮只读预览，新增/删除/清空即时生效；支持拖拽缩放并记忆尺寸
- 匹配口径＝空白规范化精确匹配 + 尾分号剥离；可选**结构匹配**——开启后按语句形状匹配，参数值不同的同形状 SQL 一并屏蔽
- 规则应用级全局生效、上限 500 条；删除规则后仍在缓冲内的条目恢复显示

**信创方言：OceanBase 与 openGauss**
- 方言注册表 9 → 11 种，EXPLAIN 支持面与连接串自动推断同步登记 `jdbc:oceanbase://`、`jdbc:opengauss://`、`jdbc:gaussdb://`
- openGauss 形态经真库引擎级验证：upsert 按 `ON DUPLICATE KEY UPDATE` MySQL 形态产出（非 PG 的 `ON CONFLICT`），`LIMIT 1,2` 不再被 PG 语义静默错解
- OceanBase 为 MySQL 模式形态（backtick 引号、LIMIT、NONE 折叠）

**通用 XML 内嵌 SQL 识别**
- 自研框架 XML（根元素名不固定、SQL 写在自定义标签的 CDATA/文本里）此前无预览入口——现叶子标签文本以 SELECT / INSERT / UPDATE / DELETE / WITH / REPLACE 开头即认领，任意框架生效
- 载体标签声明 `type="hql"` / `"jpql"` 时走 HQL 实体映射管道（别名作用域列名映射自动生效），转换失败回退原文直显不报错
- 既有 mapper / pages / hbm 文件零双图标；设置页「界面与操作」提供总开关（默认开）

**预览渲染增强**
- XML 预览集合参数按签名拆分多值渲染：`List<String>` 输入 `PI,WP` 产出 `IN ('PI','WP')` 而非整串单值，数值集合裸渲染；mapper 排版换行的 `IN (` 探测不再漏判

## 🔧 改进

- **空参数填充策略三态化（默认行为变更）**：未填写的参数（含 foreach 集合元素）默认保留 `?` 占位提示，不再默认渲染 `NULL`——`NULL` 会静默过滤行（如 `amount >= NULL` 恒不匹配），不易察觉有参数未填。需要可直接执行的 SQL 时在 设置 → 空参数填充策略 切换 NULL / 空字符串档；已持久化过 NULL / 空字符串的用户保持原档
- **注入无法识别项目类型时改引导开启增强捕获**：自动注入无法识别工程类型（非 Spring Boot + MyBatis-Plus）时，弹窗从「确定 + 手动配置示例」改为引导开启增强捕获（agent 通道不改工程代码），一键走完开关与授权流程
- **MCP 工具线兼容性加固**：jar 字节码零平台 MCP 类型引用（运行期动态注册），兼容性验证 243/251/253/262/263 五目标全绿；十工具清单与门控行为零变化，MCP 能力仍需 IDEA 2025.2+

## 🛠 修复

**HQL / JPA**
- 无别名形态 HQL 的裸属性与嵌入段限定符位不再残留属性名：`WHERE stationCode = ?` 正确转 `STATION_CODE`，`updateInfo.BE_DELETE = 0` 剥限定符产出裸列名（带别名三段形态逐字不变）

**预览与渲染**
- foreach 数值集合元素不再误加引号成字符串（`IN ('1','2')` → `IN (1,2)`），且任意输入节奏下所填值完整回填、不再丢尾巴
- 同一 mapper 文件里其他语句带 `${ew.customSqlSegment}` 时，普通语句不再误报「方法无 Wrapper 参数（ew）」红色警示；跨语句占位污染与跨命名空间 include 占位漏检一并收敛
- hbm 命名查询 CDATA 缺口修复（`<query>` 正文写在 CDATA 里时提取不到）

**切分与执行**
- T-SQL 切分两处误合并：`BEGIN TRAN` 等非块形态不再误武装块计数（此前后续整段脚本并成一条）；`IF … BEGIN … END` 后省略分号的下一条语句不再被并成一条
- 回滚产物含 `SET IDENTITY_INSERT` 时静态检查不再误报「无法解析语句结构」；执行对话框此前默认只勾第一条（＝只切了开关、INSERT 不跑），identity 包装产物现默认整批直跑

**捕获与注入**
- premain 注入不再落入 Gradle/Maven 任务 fork 出的 JVM：IDE 工具窗跑 `test` / `runIde` 等任务不再被挂上 agent；`bootRun` / `run` 等真实应用运行任务照常注入，非 Gradle 的普通运行配置完全不变
- agent 通道慢拨号不再被误判为正常掉线（退避计时改按建连成功时刻起算，连上即被关闭的场景正确触发退避换端口）
- 控制台通道在「只开 JdbcTemplate DEBUG、无参数行」的工程零产出修复——语句行之后无同线程后续行时按静默 1 秒判定交出；顺带修掉 2026.2 上停止后重启捕捉的重复解析

**MCP 与只读闸门**
- SELECT 白名单不再误杀同名标量函数（如 MySQL 的 `INSERT(name,1,2,'x')` 串函数、`TRUNCATE(price,2)` 数学函数）；`INSERT INTO` / `UPDATE (t)` 等真实写形态照常拦截
- SQL Server 方括号 SQL 不再被 MCP 只读链路整类拒绝（解析入口改走共享解析器，单语句 / 非 INTO / 非锁读 / 关键字粗扫四道闸一条不少）
- 方括号语句在性能建议与批量合并链不再静默降级（AST 性能规则与合并预览正常生效）

**MCP 真机走查三项收口（T-McpWalkFindings，10-05 真机十工具端到端走查后修复）**
- `sqlv_render_sql` 的 line 参数指向语句标签行（gutter 标注行号）时报「找不到语句」——定位锚从行首改为行内首个非空白字符（标签行行首是缩进空白，语法树沿父级爬不到语句节点），纯空白行顺延最多 2 行，错误文案补操作提示
- `sqlv_mapper_check` 空参模拟对含动态分支的语句 6/10 误报 `DANGEROUS PARSE_FAILED`——真因链＝mapper 渲染产物保留源 XML 换行缩进、注释剥离后空行变「真空行」，JSqlParser 5.3 简单模式解析失败时静默返回 null 而非抛异常，落成无归因价值的空指针——共享解析槽入口空白规范化治本（确认流与回滚链同时获得真空行免疫）＋解析入口对 null 响亮防御（残余失败带输入摘录），输出补 `simulate risk note:` 归因线索行
- `sqlv_schema_context` 成功路径首行披露实际命中的数据源（`source: …`），未指名时标注 `auto-resolved` 并附 pin 提示（跨源静默解析两次真机实证：schema 可能来自非意图库）

**增强捕获确认去重窗初始化顺序陷阱（10-05 初始化顺序守卫抓出）**
- `AgentManager` 的 `consentAskGuardMs` / `lastConsentAskAtMs`（R2 去重窗）声明在 init 块之后，而 init 注册的 SETTINGS_CHANGE 监听上升沿回调链会同步读它们——若设置变更事件在构造期同步到达，去重窗宽度读到 JVM 默认值 0（去重失效、可能双弹）且弹窗时刻表为 null（NPE）。两属性声明上移到 init 块之前（测试缝区块内），初值与语义零变化；守卫回归绿

## 兼容性

- 支持 IntelliJ IDEA **2024.3+**（Ultimate / Community；EXPLAIN、执行 SQL、表右键入口与 Database 原生图需 Ultimate）；MCP 能力需 **2025.2+**
- **空参数填充默认值变化**：升级后未动过该设置的用户，预览未填参数从 `NULL` 变为 `?` 占位（可直接看出有参数未填，也更安全）；已手动选过 NULL / 空字符串的用户不受影响
- **premain 注入范围收窄**：Gradle/Maven 测试任务与 IDE 任务 fork 进程不再被注入增强捕获 agent；真实应用运行（含 `bootRun`）与非 Gradle 运行配置不变
- 新增 OceanBase / openGauss 方言不影响既有方言选择；方言智能推断的 URL 前缀表同步扩容
- 插件 ID 与升级链路不变，v2026.9.23 用户可直接覆盖升级；历史文件与回滚快照格式向后兼容
