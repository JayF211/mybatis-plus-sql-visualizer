## ✨ 新增

**增强捕获升级为默认捕获通道（M56）**
- 字节码增强（动态挂载 agent 采集应用进程内的真实执行）此前默认关闭且从未真正触发，本版起**默认开启**；脱敏默认关闭，默认采集真实参数值，设置页「增强捕获」分组仍可开启打码
- 注入确认时机改为**首次运行项目挂载时弹一次**：同意即注入并持久记忆，拒绝则本次不注入、下次运行再询问，控制台捕获照常回落零劣化；随后按真机反馈收窄打扰面——未确认时非主配置进程（HTTP 请求 / 测试 / profiler）静默跳过，拒绝记忆 24 小时冷却，弹窗新增第三个按钮**「关闭增强捕获并不再询问」**一键持久化关闭
- **条目信息与日志通道同口径**：目标库角标（由 JDBC URL 子协议推断，覆盖 9 种方言数据库及 openGauss / GBASE）、日志原始时间（agent 在线接管期间后台嗅探日志行时间并按同指纹回填）、毫秒级精确耗时、影响行数与报错信息
- **源码位置回退定位**：增强事件除主位置外多带至多 3 个栈序候选帧，主位置不在工程内时按序取首个可解析项；定位不再依赖硬编码框架前缀黑名单，改为按帧来源跳过 JAR 帧（与类名无关，根治 PageHelper 等数据层插件帧误选）
- **停止 SQL 监听时同步停掉应用内采集**：此前 agent 仍持续采集并传输、到 IDE 侧被丢弃（白采集白传输）；重新开启即恢复采集，应用启动挂载完成后按当前监听状态校正一次

**汇聚入口跳源码上溯（T-SourceJumpFunnel）**
- 自研框架汇聚入口（业务 Service 统一收口到 Wrapper 构造处）此前跳转到框架层：agent 侧 `StackLocator` 判定收敛（候选增厚至四列 8 条、缓存仅 L1 命中写入、上顶路径收敛、动态前缀热下发）+ IDE 侧统一跳转解析器 `EntryJumpResolver`（实时/历史两面板共用，历史面板补候选回退）
- 设置页新增**帧过滤前缀**配置项，栈快照详情可直接查看候选帧；cands / sd 双端协议列尾追加，新旧 agent 双向兼容

**SQL 历史全量化与保留上限（T-SqlHistoryFull / T-HistoryFileRetention）**
- 历史条目改为全量落盘（此前达上限后丢弃后续条目），并消除历史打开时的卡顿（后台扫描 + 增量读取）
- 新增**历史文件保留上限**配置项（默认开启），按命名模板文件族自动裁剪防磁盘膨胀，裁剪加 60 秒节流

**日志原始时间与检索增强（beta.2）**
- **时间来源单选组**：日志原始时间戳记录与显示切换——`LogTimestampParser` 预置 Logback / Log4j2 / Spring Boot / ISO 8601 / nginx 等常见格式严格解析，非法或残缺时间戳回退捕获时间；设置页「SQL 日志」可切换「日志时间」（默认，日志行解析值）与「捕获时间」（插件捕获时刻），时间戳格式对两种来源同样生效；历史文件随条目保存 `logTime`，旧版文件照常读取
- **搜索行号 / 时间 + 右键复制时间戳**：搜索框新增 `#行号`（精确等于第 N 条，非包含）与时间文本（所见即所搜）两类匹配；右键「复制时间戳」逐行复制纯时间文本，与批量复制 SQL 同构
- **排序方式选择器**：原「耗时排序」按钮升级为五种方式——时间升序（默认）/ 时间降序 / 耗时升序 / 耗时降序 / 行号；耗时与行号缺失条目恒沉底

**界面组件全面原生化首轮（T-UiNative）**
- 日志主列表与历史二级 SQL 列表接入原生 `SpeedSearch`（匹配高亮与平台一致）；19 处预览相关模态轻提示改平台通知；右键菜单迁 `ActionGroup` + `ActionPopupMenu`、类型过滤弹层换 `JBPopup`；JOIN 图与历史导航按钮行迁 `ActionToolbar`；加载态与占位符接原生件（`JBLoadingPanel` / `AnimatedIcon` / `EditorEx.setPlaceholder`）；33 项写死颜色集中为 `MpvsUiColors` namedColor、设置落地页行渲染器归一 `SimpleColoredComponent`；项目级设置页迁 Kotlin UI DSL v2 试点

**项目级设置页（T-SettingsTruth P4）**
- `plugin.xml` 注册 `projectConfigurable`（tools 顶层，防套娃），面板扩容为 10 个控件：增强捕获开关、方言、三项 tri-state 勾选、逻辑删除值、表前缀 / 后缀、推断策略下拉、忽略字段
- 项目级覆盖全链生效：预览服务的参数替换 / 逻辑删除注入 / 表配置读取、实体解析器与 JPA 解析器的表配置读取统一走 `effective*`，缓存签名改项目维；无项目上下文时降级回退全局设置

## 🔧 改进

- **预览链 2 秒阻塞消除（T-PreviewFast）**：点击预览后控制台 SQL 区固定要等约 2 秒才出现。根因是 exec 文件写入无差量快路径——内容与磁盘已一致时仍派发 EDT 并等满 2000ms 有界等待、再无条件落盘（连续预览同一 SQL 的主路径每次白付），且预热属投机写入却在后台线程白等。修复=内容一致即直接返回、预热派发改非阻塞、落盘前判「已修改未保存」、程序性写入不再触发防抖落盘、显示模式变换加单槽缓存；另加「请求 → 弹窗 → 控制台可见」三段耗时埋点便于后续回归对照
- **性能收敛十三项（T-PerfSweep4）**：捕捉开启时控制台日志不再双路解析（每行只走增强或轮询单通道，解析成本减半）；增强捕获每条 SQL 只做一次调用栈捕获，且 fat jar 部署下源码定位缓存正常生效；日志时间配对签名按 256 字符截断、数值判定与空白规范化正则常量化；历史文件保留上限裁剪加节流；设置变更触发的历史落盘排水限批，界面线程不再承担整批磁盘写；执行文件自动落盘监听随插件容器释放并带身份快判；agent jar 提取一次缓存、attach 待处理进程表去抖落地
- **设置真实性收敛（T-SettingsTruth）**：假开关 `autoInjectSqlSourceInterceptor` 改为纯动作（勾选即注入、无论成败终态复位未勾选、不持久化，tooltip 明示「本开关不保存状态」）；增强捕获状态行接线（`AgentManager` 新增三态状态摘要 + 应用级 Topic 广播，面板聚合多项目实时显示）；设置搜索索引清掉已不存在的 `filterBar` 分组并补录 13 项真实未索引设置；顺带清理两枚存量幽灵 bundle 键
- **增强捕获链路稳定性收口**：会话读循环退出补异常栈（掉线原因不再不可查）、超限帧丢弃继续不杀会话、单事件编码失败不断开连接
- **历史页与日志页元信息口径统一**：历史页元信息顺序改为与日志页一致的「时间 → 耗时 → 目标库 → 来源」；「捕获时间」含义明确为语句开始执行时刻；日志列表移除「[⚡增强]」来源角标（增强已是默认通道，逐行标注属噪音）

## 🛠 修复

**日志解析链**
- **并发下 SQL 日志条目严重不正确根治（T-LogParseConc）**：并发时日志不对——三条根因一次修复：① MyBatis 解析器单槽状态机不分线程，另一线程的语句行提前闭合本线程尚未收到参数的语句（参数全丢、`?` 未还原）；② 空 `Parameters:` 行触发的兼容态跨语句残留，把下一行整行吞成参数值；③ 多行 SQL 条目取不到日志时间回落捕获时刻。修复=线程分桶下沉为三解析器共享的 `LogThreadRouter` + 空参判别式不吞下一行 + 多行 SQL 时间取语句首行 + MyBatis 多行 SQL 续行支持（mapper 里格式化的 SQL 不再只留首行）
- **Hibernate / JPA 链路并发配对同步修复（T-HibConc）**：同为单槽状态机，并发下「A 的 SQL 配 B 的值」——改用 MRU 归属策略按线程分桶，Hibernate 独有的双副本合并正文与标志行按最近 token 桶归属，零参影子隔离槽按桶隔离
- **JdbcTemplate 并发日志交错参数错挂 / 丢失（beta.2）**：Tomcat 并发请求日志按到达序混排时，named 单行的强制闭合会清空其它线程的待收语句，该线程随后到达的参数行被静默丢弃（`?` 残留 + 参数空 → 预览误报「未捕获到参数绑定日志」）。改按日志行线程 token 分桶，每桶独立状态机，无线程 token 的多行续行路由到唯一收集桶、提取失败回退共享桶
- **增强捕获条目时间与控制台日志行对不上（T-AgentLogTime）**：关联键原先用「还原后 SQL」，两侧还原器口径分叉致静默失配——改用占位符版 SQL 指纹，采集时刻前移到语句开始执行，同键排队 + 30 秒陈旧窗

**预览与执行链**
- **预览参数区背景丢失 + JOIN 图默认自适应居中（T-PreviewBgFit）**：深色主题下左侧参数面板只有标题行是灰的、下方一片黑——界面原生化换分栏时漏掉了原分栏显式设置的面板背景；JOIN 图打开不居中要手点【调整内容】——平台「布局后自适应」是图设置项，手工构造编辑器嵌进预览面板时开关从未置位。修复=恢复分栏面板背景并让参数滚动区自身不透明，嵌入时置「布局后自适应」与「尺寸变化后保持自适应」并在首次显示且有尺寸后按同参补一次 `fitContent`（第二轮修正：开关须置于异步布局触发**之前**，否则同会话会出现「第一张图不居中、第二张正常」的竞态）
- **预览控制台显示回归格式化（T-PreviewConsoleFmt）**：预览后内嵌控制台的 SQL 区只显示裸单行——控制台挂载在 exec 文件本体上，而预览链的预热把预览原文写进该文件，面板渲染的格式化文本只落在自建编辑器里。修复=控制台嵌入完成即按当前渲染文本回填一次，预热在控制台已挂载时不再改写文件内容
- **预览会话库上下文对齐与诊断（T-ConsoleDbContext）**：同一条 SQL 在预览窗口执行报 `Unknown column`、在原生控制台正常——根因是库上下文错位（文件→数据源映射把执行文件钉在另一个库上）。修复=控制台就绪即把当前库对齐到数据源 URL 里的库（已一致则不动，不覆盖用户后来的手选），执行失败提示追加「当前库 / 数据源 / 数据源默认库」上下文
- **预览 / 控制台写入上下文 write-unsafe 报错根治（T-WriteSafeCtx）**：真机日志出现 `Write-unsafe context!` 断言。根因=写模型的合法性不取决于是否包了写命令，而取决于这次 EDT 活动有没有 write-safe 资格，而 `invokeLater(..., ModalityState.any())` 排出的活动恒 write-unsafe。修复=新增写入上下文闸门 `DocWriteContext`（入口自愈重投递 + 5 处写入类回调改 `nonModal` + 只读回调标注豁免），并加源码守卫与闸门行为测试防复发
- **执行文件「文件缓冲区冲突」连环根治（T-ExecDocSync / 2 / 3）**：第三轮=document 驱动写只改内存不落盘 + 写失败兜底无条件裸写盘 + 双写方不互斥，统一为「派 EDT + 同临界区 setText → commit → saveDocument」并拒绝有已加载文档时的裸写兜底；第四轮=补齐 Database 控制台侧四处文档同步（此前只 commit 不落盘，用户手改更是插件拦不到的未保存源）+ 执行文档防抖自动落盘 + 冲突探针；第五轮=裸写兜底退役（冷启动 EDT 忙时 document 写的有界派发超时，兜底守卫误判「无已加载文档」而放行裸写，随后排队任务才建出文档并标脏 → 弹冲突），改为 VFS 已有该文件时绝不裸写
- **JOIN 图连线丢失修复（T-EmbedFkOrder）**：同样两条 SQL 一条有连线一条没有——连线来自虚拟外键注册表（由 ON 条件登记），而预览面板是「先建新图、后清旧图」，旧图释放时把注册表整表清空、连新图刚登记的 ON 条件一并抹掉。修复=清理旧图前移到建新图之前，组件释放不再顺带清注册表（改由整图卸载显式回收）

**预览渲染与参数**
- **增删改语句源码位置捕获修复（T-AgentCudSource）**：INSERT / UPDATE / DELETE 捕获不到源码位置——调用方缓存把「无调试信息的 null 位置」也缓存，某调用方一旦解析出 null，该名下所有后续语句恒无位置且不再自愈。修复=仅缓存有效位置，候选全 null 则本次不产出不缓存
- **IN 字面量 SQL 预览参数未识别修复（T-InParamRec）**：上游把值直接内联进 SQL 时，源码跳转反查入口打开的预览不出现参数行——该入口是早期独立实现，漏接字面量恢复能力；现与日志页 / 历史页收编同一识别通道
- **IN 列表全量竖向排列（T-VStack·InAll）**：预览「竖向排列」对 IN 列表不再按元素数分级，含逗号即 ≥2 元素一律 `(` 自占一行逐元素竖排；单元素形态与子查询 IN、LIMIT 分页参数照旧不展开
- **JdbcTemplate 集合参数方括号误入 SQL（beta.1）**：`IN (:param)` 配集合值此前被还原成 `IN ('[a, b]')`，字符串里带着方括号致集合查询恒为空集。现位于 `IN (...)` 内的集合值剥括号后按元素渲染（单元素即 `IN ('a')`、多元素逗号分隔、数值裸渲染、空集合输出 `NULL`），`IN` 识别为字符串 / 注释感知 + 词边界判定；非 IN 位置的行为逐字节不变
- **HQL 继承 / 抽象类实体「列信息未解析」降级修复（T-HqlInhCols）**：实体解析返回「表信息在但列清单为空」时被直接当作成功短路，跳过 hbm 映射兜底与别名反查；且 HQL `FROM 别名` 里的 `@Entity(name=...)` 实体名全链无读取点。修复=空列不再短路（先试更优候选）、新增实体名反查（带 PSI 修改计数缓存）、SELECT 展开降级注释分两档（实体不可解析 / 实体可解析但列空，指向检查继承链父类映射）、`@Inheritance` 形态附边界说明注释

**其他**
- **捕捉开关回归日志面板工具栏（T-CaptureBack）**：SQL 日志面板的「捕捉」按钮在用户视角「消失」——界面原生化把捕捉开关从面板内工具栏迁到了工具窗标题栏，而新 UI 下标题栏动作需悬停/激活才渲染。修复=回迁面板工具栏首位，工厂侧移除标题栏挂载（单一入口），空态文案改走既有 bundle 键
- **帧过滤前缀输入框被压扁不可见（T-FramePrefixVisibility）**：真机截图定谳——被 GridBag 压扁，修复=高度保底 ≥60px + 长词换行，并补平台标准文本框边框与编辑区背景，深色主题下框体辨识度提升
- **历史裁剪不再误删用户文件（T-PS4-10）**：自定义保存目录下与插件历史命名无关的 .sql 文件曾被按「最旧组」一并静默删除——现只认本插件命名模板渲染出的文件族，其余文件永不计数、永不删除（宁漏删不误删）
- **批量错误报告合并为单个弹窗（T-FeedbackBatch2）**：平台「报告全部」逐错误簇循环提交，N 个错误 = N 个弹窗。修复=提交侧累积合并（队列 + 500ms 去抖 + 自首条 3 秒强制兜底），逐事件指纹去重，分节标题如实计数，消除两处开关不一致丢主堆栈的暗坑
- **定时回归任务不再弹出真机浏览器（T-BrowserLeak2）**：测试为验证「测试环境不弹浏览器」直调了两个真实 URL，而守卫写成「有 Application 且单测模式才短路」，纯 JUnit 无平台 Application 的测试进程反被放行，定时任务每天跑全量测试即周期性拉起默认浏览器。修复=守卫语义反转为 fail-safe 默认拦，测试断言改为直接验证判定函数
- **增强捕获杂项**：事件零到达（agent 事件写出器产出非法 JSON 被静默丢弃）、243 平台无法挂载（进程 pid 解析双败）、查询条目误显示影响行数「-1 rows」（`execute()` 返回语义写反）、设置页增强捕获项无法保存（读写判定分区不一致）、驱动私有类型参数渲染垃圾值（降级为类名标注）、历史文件「日志时间」读回恒丢失（头部正则嵌套捕获组错位）
