# 🎉 SQL Visualizer v2026.9.18-beta.1（内测版）

> 内测版留档：Gitee 抢先体验通道发行版，标签 `2026.9.18-beta.1`，附件 `mybatis-plus-sql-visualizer-2026.9.18-beta.1.zip`。
> 基线为正式版 v2026.9.14，本内测版承载其后的全部增量；对外更新清单只保留最新一个 beta 版。

自 v2026.9.14 正式版后的首个内测版。本版为**单项修复版**：修复用户真机反馈的 NamedParameterJdbcTemplate 日志还原把集合值的方括号带进 SQL 的问题——`IN (:param3)` 配 `{param3=[6b31d693…]}` 此前被还原成 `IN ('[6b31d693…]')`，字符串里带着方括号，集合查询恒为空集。

## 🐛 修复

- **JdbcTemplate 命名参数集合值方括号落进 SQL（T-ListParamCollect）**：日志还原链路此前只有「数值裸渲染 / 其余整体加引号」两个分支，Java 集合的 `toString()` 形态 `[a, b]` 被当成单个字符串整体加引号。现在位于 `IN (...)` 内的集合值剥括号后按元素渲染——单元素即 `IN ('6b31…')`，多元素逗号分隔、数值裸渲染、空集合输出 `NULL`；`IN` 识别为字符串/注释感知 + 词边界判定，`index_col` 一类标识符不误伤。**非 IN 位置的行为逐字节不变**（形如 `[a]` 的普通字符串值仍原样加引号）。边界如实声明：该日志行格式不存在「一个命名参数对多值」的形态（多元素集合运行时展开成 `IN (:p1, :p2, …)`），本版只修「方括号不落进 SQL」，不声称支持集合传参。

## 🧪 测试

- 新增 `ListParamRendererTest` 9 例（集合拆分、`IN` 识别的大小写/无空格/注释/字符串字面量/嵌套括号/标识符误判、渲染与回调逐元素）；`JdbcTemplateLogParserTest` +6 例（用户真机日志逐字复现并断言产物不含方括号、多元素逐元素引号、空集合 `NULL`、非 IN 位置原样、数值集合裸渲染）；`LogEntryPreviewRecognizerTest` +2 例
- 本版全量 **4123/0/0/6 绿**（基线 4103 + 本轮 20 例净增），与基线一致零回归；`verifyPlugin` 三目标（IU-243/253/262）Compatible

## 兼容性

- 支持 IntelliJ IDEA **2024.3+**（Ultimate / Community；EXPLAIN、执行 SQL、表右键入口与 Database 原生图需 Ultimate）
- 仅日志还原链路修复，无设置项、无文案键变更；非 IN 位置渲染与旧版逐字节一致
- 插件 ID 与升级链路不变，v2026.9.14 用户可直接覆盖升级

## 📦 安装（内测通道）

1. 下载附件 `mybatis-plus-sql-visualizer-2026.9.18-beta.1.zip`
2. IDEA：`Settings → Plugins → ⚙️ → Install Plugin from Disk…` → 选择 zip → 重启 IDE
3. 已装 v2026.9.11+ 用户：设置页「更新」分区检查更新即自动收到本内测版（Gitee 抢先体验通道），经该通道更新免重启即时生效
