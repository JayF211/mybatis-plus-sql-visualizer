# 🎉 SQL Visualizer v2026.9.18-beta.3（内测版）

> 内测版留档：Gitee 抢先体验通道发行版，标签 `2026.9.18-beta.3`，附件 `mybatis-plus-sql-visualizer-2026.9.18-beta.3.zip`。
> 基线为内测版 v2026.9.18-beta.2，本内测版承载其后的全部增量；对外更新清单只保留最新一个 beta 版。

自 v2026.9.18-beta.2 后的同日内测第三轮。本版以 **M56 字节码增强全链路合入 master** 为主线——增强捕获升级为默认捕获通道，条目显示目标库、日志原始时间与真实执行耗时/影响行数，源码位置定位不再误选第三方插件帧，并补齐 243 平台挂载与监听联动；同时**三条控制台解析链路（MyBatis / JdbcTemplate / Hibernate）全部完成并发分桶配对根治**，并发下 SQL 日志不再交错错配，日志时间与控制台对齐。

## ✨ 新增

- **增强捕获升级为默认捕获通道（2026-09-16 用户定案）**：此前增强捕获（字节码动态挂载，采集应用进程内的真实执行与耗时/影响行数）默认关闭，需在设置页手动勾选且从未真正触发。本版起默认开启、脱敏默认关闭（默认采集真实参数值）；注入确认时机改为**首次运行项目挂载时弹一次**，同意后方注入并持久记忆，拒绝则本次不注入、下次运行再询问（控制台捕获照常回落零劣化）
- **增强捕获条目显示目标库与日志原始时间（T-AgentDialectLoop）**：增强捕获事件流全链透传 JDBC 连接 URL，日志页/历史页元信息行新增**目标库角标**（如 `[MySQL]`、`[DM（达梦）]`，由库名推断，覆盖 9 种方言数据库及 openGauss/GBASE）；agent 在线接管期间不再整链短路控制台日志——后台嗅探日志行原始时间并按同指纹回填到增强条目，增强模式下「日志时间」照常显示（可关，关闭零成本）；执行耗时（毫秒级精确）与影响行数、报错信息在增强条目上齐备，与控制台通道同口径
- **日志列表「耗时排序」按钮升级为「排序方式」选择器（T-LogSortModes）**：支持**时间升序（默认=捕获顺序）/ 时间降序 / 耗时升序 / 耗时降序 / 行号**五种方式，常驻按钮点击弹单选菜单（与「SQL 类型」按钮同款式）；耗时与行号缺失的条目恒沉底，时间排序口径与列表时间列一致

## 🐛 修复

- **并发下 SQL 日志条目严重不正确根治（T-LogParseConc）**：用户实测「并发时日志不对」——三条根因一次修复：① `MyBatisLogParser` 是单槽状态机不分线程，另一线程的语句行提前闭合本线程尚未收到参数的语句，本线程随后到达的参数行被静默丢弃（参数全丢、`?` 未还原）；② 空 `Parameters:` 行（MP 的 COUNT 语句必打）触发的兼容态跨语句残留，把下一行整行吞成参数值（面板出现 `LIMIT 2026-09-16 14:35:00.413 DEBUG …` 这类文字）；③ 多行 SQL 条目取不到日志时间回落插件捕获时刻（实测差 209ms）。修复=**线程分桶下沉为三解析器共享的 `LogThreadRouter`**（token 提取+分桶+空闲桶淘汰，MyBatis 全状态按桶隔离）+ 空参判别式不吞下一行 + 多行 SQL 时间取语句首行 + **MyBatis 多行 SQL 续行支持**（mapper 里格式化 SQL 不再只留首行）
- **Hibernate/JPA 链路并发配对同步修复（T-HibConc）**：`HibernateLogParser` 同为单槽状态机，并发下另一线程的语句行提前闭合本线程 SQL 块、绑定行被追加进共享参数列表（**A 的 SQL 配 B 的值**）。改用 MRU 归属策略按线程分桶——Hibernate 独有的「双副本合并」（`Hibernate: ` stdout 副本 + `org.hibernate.SQL` logger 副本）正文与标志行都不带线程前缀，无 token 行跟随最近一次出现 token 的桶，零参影子隔离槽按桶隔离（同一 SQL 两线程执行各产独立条目）
- **增强捕获条目时间与控制台日志行对不上（T-AgentLogTime）**：增强条目的「日志时间」靠控制台日志行暂存再按指纹取回，而关联键原先用「还原后 SQL」——两侧还原器三处口径分叉静默失配，回落显示 agent 采集时刻经前移后仍比日志行晚。三处同修：采集时刻前移到 execute **开始**；关联键改用占位符版 SQL 指纹（不再依赖参数还原口径），同键排队+30s 陈旧窗；日志时间采集不再受渲染偏好控制
- **增强捕获源码位置误选第三方插件帧（T-AgentSourceJump）**：源码定位原靠硬编码框架前缀黑名单，漏收 PageHelper 等数据层插件导致跳转误选插件帧、报「源码文件未找到」。三层修复：developer 用户业务类来自目录、第三方依赖恒来自 JAR，**按帧来源跳过 JAR 帧**（与类名无关根治黑名单遗漏）+ 补齐数据层家族前缀 + 增强事件多带 ≤3 个候选帧、IDE 侧主位置解析失败按序回退（候选全部出自本次真实调用栈，不会误导）
- **增强捕获事件零到达根治（agent 事件 JSON 非法）**：agent 事件写出器给首字段也补了前导逗号，产出 `{,"sql":…}` 非法 JSON——SQL/参数/耗时其实已全部采集到位，却因解析全量失败被静默丢弃（表现「增强开着但列表空」）。重写为首字段分隔并补格式守卫测试
- **增强捕获在 243 平台无法挂载（进程 pid 解析双败）**：243 平台无 `getNativePid`、`getProcess().pid()` 经反射调 JDK 包私有类抛 IllegalAccessException——改接口直接调用虚分派 + `OSProcessUtil.getProcessID` 兜底三步回退
- **查询条目误显示影响行数「(-1 rows)」**：JDBC 语义为 `execute()` 返回 true=首结果是 ResultSet（此时 `getUpdateCount()` 恒 -1 无意义）、返回 false 才是更新计数；采集侧条件写反致每条 SELECT 上报 -1，按正确语义取计数并统一负值兜底
- **设置页增强捕获项无法保存（勾选后重开仍未勾选）**：勾选状态与读写判定分区不一致——界面项已归位日志页分组、读写判定却留预览页分支，日志页勾选被判「无改动」平台不落盘。读写判定随分组归位
- **驱动私有类型参数不再渲染垃圾值**：`setObject` 直传未覆写 `toString` 的驱动类型（Oracle `oracle.sql.Datum` 族）降级为 `<类名>` 形态标注
- **历史文件「日志时间」读回恒丢失**：头部正则毫秒分数为嵌套捕获组占位错位，`logTime` 读回断链修复，并支持 `| db:` 字段持久化读回

## ⚡ 优化

- **增强捕获链路稳定性收口**：会话读循环退出补异常栈（掉线原因不再不可查）、超限帧丢弃继续不杀会话、agent 单事件编码失败不断开连接；监听开关与应用内采集联动——停止监听即向应用 JVM 下发停采指令（此前仍白采集白传输），重新开启即恢复
- **SQL 历史页元信息顺序与日志页统一**：历史页原「行号→耗时→时间」改为与日志页一致的「时间→耗时→目标库→来源」，耗时复用日志页片段（按慢查询阈值着色、缺失占位「—」）
- **「捕获时间」含义明确为语句开始执行时刻**：该时间源下显示的一律是 SQL 开始执行那一刻，与控制台通道口径一致
- **日志列表移除「[⚡增强]」来源角标**：增强捕获已是默认捕获通道，逐行标注来源属噪音；目标库角标/耗时/影响行数等有效信息保留

## 兼容性

- 支持 IntelliJ IDEA **2024.3+**（Ultimate / Community；EXPLAIN、执行 SQL、表右键入口与 Database 原生图需 Ultimate）
- 增强捕获为默认通道：**首次运行项目会弹一次注入确认**，同意后生效并持久记忆；拒绝则本次不注入、下次运行再询问，控制台捕获照常回落零劣化
- 脱敏默认关闭（默认采集真实参数值），设置页「增强捕获」分组仍可开启打码
- 插件 ID 与升级链路不变，v2026.9.18-beta.2 用户可直接覆盖升级

## 📦 安装（内测通道）

1. 下载附件 `mybatis-plus-sql-visualizer-2026.9.18-beta.3.zip`
2. IDEA：`Settings → Plugins → ⚙️ → Install Plugin from Disk…` → 选择 zip → 重启 IDE
3. 已装 v2026.9.11+ 用户：设置页「更新」分区检查更新即自动收到本内测版（Gitee 抢先体验通道），经该通道更新免重启即时生效
