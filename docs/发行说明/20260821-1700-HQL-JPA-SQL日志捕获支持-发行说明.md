# 🎉 MyBatis-Plus SQL Visualizer v2026.8.21

> 发行说明留档：对应 Gitee 发行版 **v2026.8.21**（标签 `v2026.8.21`），附件 `mybatis-plus-sql-visualizer-2026.8.21.zip`。

自 v2026.8.20 后的第九个版本。本版核心主题是 **JPA/Hibernate SQL 预览支持**（三种查询风格全覆盖——Derived 派生查询 / CriteriaQuery 强类型 / HQL 自定义 DAO，gutter 图标点击直接弹窗看 SQL）与 **Hibernate/JPA SQL 日志捕获**（双解析器并列架构——MyBatis 与 Hibernate 日志同时解析互不干扰）——同时完成 JPA 嵌套对象 JOIN 查询支持、SQL→Java 反向子查询 JOIN 解析 + MConsumer 形态 + ext 条件 lambda 化增强、Pageable 分页 LIMIT 生成、@Query 路由优先修复、SQL 预览表名按短类名查找实体、复制时剥离注释、JPQL IN 子句三层修复、MPJ 工厂链双图标回归修复、ReadAction.compute 废弃 API 修复，以及 JPA 测试体系三层加固 + 端到端预览测试。

## ✨ 本版新增（相对 v2026.8.20）

**JPA/Hibernate SQL 预览支持（三种查询风格全覆盖）**
- **Derived 派生查询预览**：Spring Data JPA 的 `findByXxx` 方法 gutter 图标点击直接预览 SQL——支持嵌套对象属性路径（如 `findByDepartmentName`）自动展开为 JOIN 查询，解析属性路径中的关联实体生成对应 LEFT JOIN 子句；`Pageable` 参数自动生成分页 `LIMIT pageSize OFFSET pageOffset` 占位符；重复列自动去重（简单字段优先于 `@ManyToOne` 关联字段）
- **CriteriaQuery 强类型查询预览**：`CriteriaBuilder` 构建的 JPA 强类型查询正确解析为 SQL，gutter 图标过滤 `CriteriaBuilder` 内部方法避免误标
- **HQL 自定义 DAO 方法预览**：自定义 DAO 的 HQL 字符串（如 `commonDao.findByQueryUniqueResult("select ... from WmsZone ...", "locIdList", locIdList)`）正确识别并预览——参数名自动推断（从 HQL 字符串提取 `:paramName` 命名参数，不再显示 `?1` `?2`），参数类型自动推断（数值/布尔/String 类型感知引号），`JOIN FETCH` 语法正确解析为 JOIN 子句
- **@Query 路由优先**：`@Query` 方法即使方法名匹配派生查询模式（如 `findByMinAmount`），也走 JPQL 路径（`@Query` 优先于 PartTree 推导）；多行拼接 `@Query("..." + "...")` 正确提取完整 JPQL
- **端到端预览测试**：新增 `JpaDemoIntegrationTest` 端到端用例——从 gutter 图标点击到弹窗渲染全链路覆盖

**Hibernate/JPA SQL 日志捕获支持（双解析器并列架构）**
- **独立 HibernateLogParser**：与 MyBatisLogParser 并列运行——每行控制台输出同时喂入两个解析器，MyBatis 行由 MyBatisLogParser 处理，Hibernate 行由 HibernateLogParser 处理，互不干扰、各自产出 `LogSqlEntry` 汇入同一 buffer
- **三种 SQL 行前缀识别**：`Hibernate:` 显式前缀（`show-sql=true`）/ `/* load Entity */` 注释前缀 / 纯 SQL 行（行首即 SELECT/INSERT/UPDATE/DELETE，可配置开关）
- **参数绑定行解析**：`binding parameter [1] as [BIGINT] - [1]` 单参数单行格式，按索引追加到 pending 条目，下一条 SQL 行到来时自动闭合当前条目
- **JDBC 类型映射扩展**：`LogSqlRestorer.PLAIN_TYPES` 追加 JDBC 类型名（BIGINT/INTEGER/SMALLINT/TINYINT/FLOAT/DOUBLE/NUMERIC/DECIMAL/BIT/BOOLEAN 数值型原样直出，VARCHAR/CHAR/DATE/TIMESTAMP 保持引号），未知类型走启发式
- **条目来源标记**：`LogSqlEntry` 新增 `source: SqlSource` 枚举字段（MYBATIS / HIBERNATE / UNKNOWN），预览弹窗标题显示来源
- **设置页 Hibernate 配置分区**：新增「启用 Hibernate/JPA 日志捕获」开关 + 「Hibernate SQL 前缀」/「Hibernate 参数前缀」可配置输入框——适配不同 Hibernate 版本的日志格式差异
- **LogToSqlPanel 兼容**：手动粘贴日志批量还原同步支持 Hibernate 格式
- **新增测试**：`HibernateLogParserTest`（620 行，覆盖 Hibernate 前缀/注释前缀/纯 SQL/参数绑定/JDBC 类型还原/噪声行/超长截断/连续 SQL/来源标记等全路径）+ `DualParserIntegrationTest`（双解析器互不干扰/配置同步）+ `LogToSqlPanelTest`（Hibernate 格式面板还原）

**SQL 预览复制时剥离注释**
- 新增 `SqlCommentStripper` 工具类（`--` 行注释 + `/* */` 块注释），复制 SQL 时自动忽略注释——粘贴即用纯 SQL，与 Java 代码复制行为对齐

## 🔧 修复（相对 v2026.8.20）

**SQL→Java 反向转换增强**
- **子查询 JOIN 解析**：新增 `JoinSubQuery` 模型 + `parseSubqueryStructure` 解析简单单表子查询结构，`parseSubqueryTable` 返回文本+结构，`parseJoinTableExpression` 传递 `JoinSubQuery`
- **MConsumer 子查询形态**：`renderJoins` 优先 MConsumer 形态（`leftJoin(Class, t -> t.setAlias(...).selectAll().ge(...), left, right)`），其次 ext lambda，最后字符串
- **ext 条件 lambda 化增强**：`canLambdaJoin` 放宽为单等值列对 + N 个副表 Simple 条件，修复 ext 操作符映射（ext.eq → ext.ge/gt 等）
- **effectiveKind 纳入 MConsumer 判定**：子查询可 lambda 化时保持 MPJLambdaWrapper 类型
- 新增 11 个测试覆盖子查询 JOIN、ext lambda、MConsumer 端到端

**JPA 分页与查询修复**
- **Pageable 分页 LIMIT 生成**：`previewDerivedQuery` 检测方法含 `Pageable` 参数时，为 SELECT 语句添加 `LIMIT pageSize OFFSET pageOffset` 占位符，参数列表排除 Pageable 本身、添加 pageSize/pageOffset 可输入占位
- **重复列去重**：`JpaEntityResolver` 的 columns 按 columnName 去重，简单字段优先于 `@ManyToOne` 关联字段（`departmentId`(@Column) 和 `department`(@ManyToOne) 同映射 `department_id` 时 SELECT 只出现一次）
- **@Query 路由优先**：`@Query` 方法即使方法名匹配派生查询模式（如 `findByMinAmount`），也走 JPQL 路径（`@Query` 优先于 PartTree 推导）——`hasQueryAnnotation` 检查排在 `isDerivedQuery` 之前
- **@Query 拼接字符串提取**：`@Query("..." + "...")` 正确提取完整 JPQL——`JpqlQueryLocator.extractStringValue` 递归收集 `PsiLiteralExpression` 子节点

**SQL 预览表名解析修复**
- **按短类名查找实体**：`SqlPreviewService.resolveHqlTable` 新增从 HQL FROM 子句提取实体类名，按短类名查找 `@Entity` 类——解决 `createQuery(HQL)` 单参数场景表名显示 `unknown_table` 问题
- **表名解析兜底**：HQL 实体类名无 `@Table` 注解时按命名策略推断表名

**JPQL IN 子句三层修复**
- **括号补全**：`replaceNamedParameters` 把 `IN :param` 替换为 `IN (?)`（而非裸 `IN ?`）
- **数值参数不加引号**：`Collection<Integer>` 等数值集合参数标记 `quote=false`，渲染为 `IN (1, 2, 3)` 而非 `IN ('1', '2', '3')`
- **inList 标记 + 逗号分割多值**：JPQL/XML/MP/MPJ 全路径 `detectInClauseParams` 检测 `IN (?, ?, ...)` 模式参数索引，面板回填时标记 `inList=true`，逗号分割多值自动渲染为 `IN (1, 2, 3)`

**MPJ 工厂链 selectAll 双图标回归修复**
- 新增整体不变量锚点断言覆盖 MPJ 工厂链（补双图标回归测试盲区）

**ReadAction.compute 废弃 API 修复（T-M52 补充）**
- 262 平台报 `ReadAction.compute(ThrowableComputable)` deprecated，243 编译目标仅此重载可用——保留显式类型参数 + `@Suppress("DEPRECATION")`

## 🧪 测试加固

- **JPA 测试体系三层加固**：组件契约升级（断言参数名内容/数量而非仅非空）+ 端到端集成（gutter 点击到弹窗渲染全链路）+ 面板行为测试（实例化 `SqlPreviewPanel` 验证交互层）
- **HQL/JPA 预览全方位集成测试**：新增 `JpaDemoIntegrationTest` 端到端用例
- **MPJ 工厂链回归测试**：整体不变量锚点断言覆盖
- **测试覆盖缺口修复延续**：波次三（接缝测试）+ 波次四（沙盒验证清单）
