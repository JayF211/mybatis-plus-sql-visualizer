# 🎉 SQL Visualizer v2026.9.2

> 发行说明留档：对应 Gitee 发行版 **v2026.9.2**（标签 `v2026.9.2`），附件 `mybatis-plus-sql-visualizer-2026.9.2.zip`。

自 v2026.8.21 后的第十个版本。本版核心主题是 **实时日志跳转源码可靠方案**（F-44-6——在应用 JVM 用 MyBatis-Plus `InnerInterceptor` 捕获真实调用点，精确 `file:line` 跳转替代不可靠的"按表名猜实体"）与 **全插件 UI / 集成测试覆盖**（日志面板 / 历史面板 / 设置页 / 帮助 / 弹窗 / gutter 等 50+ 测试文件 200+ 用例，覆盖真实渲染、布局、交互、端到端场景）——同时完成 **插件显示名更名 SQL Visualizer**（已装用户正常升级）、**SQL 日志面板四项缺陷终局修复**（SQL 高亮恢复 / 耗时接入控制台链路 / 去重即时生效 / 徽章同步）、**SQL 历史面板两级导航 + 高亮 + 耗时**、**HQL SELECT 实体别名展开为列清单**（M36.7——修复 `SELECT u` 在 MySQL 报 Unknown column）、**帮助按钮本地 HTML 定稿**（零网络依赖）、**多行拼接 HQL gutter 漏检修复**、**弃用 API 清理**，以及全仓 2682 用例 0 失败。

## ✨ 本版新增（相对 v2026.8.21）

**插件显示名更名 SQL Visualizer**
- `plugin.xml` `<name>` 与全部用户可见文案（设置页 / 弹窗标题 / gutter tooltip / 通知 / 工具窗口标题，中英双语）同步更名——**插件 ID（`<id>`）、构建产物 zip 顶层短名、仓库与 Marketplace 页地址均不变**，已安装用户正常升级，配置与历史记录全保留。仍全面支持 MyBatis-Plus / MPJ / JPA / Hibernate
- 项目内数据目录随插件更名（F-44-4）：`.idea/` 下插件数据目录由旧名 `mybatis-plus-sql-visualizer` 改为新名 `sql-visualizer`（含 `sql-history/` 历史 SQL 与 `exec/` 执行临时文件）——**不考虑向前兼容**，旧目录数据不再读取；新增统一常量 `SqlLogAutoSaver.DATA_DIR_NAME` 供历史面板 / 历史 tab 显隐检测 / 数据源执行文件路径引用

**实时日志精确跳转源码可靠方案（F-44-6）**
- **根因**：旧 `extractSourceLocation` 在 IDE 控制台线程取栈恒失败（栈帧只有 JDK / IntelliJ / 插件帧，永远取不到应用调用点），退化为按表名猜实体的不可靠跳转
- **新方案**：运行期用 MyBatis-Plus `InnerInterceptor` 在 SQL 执行线程捕获真实调用点，向 stdout 打印标记行 `SQLVIS-SOURCE|<相对路径>|<行号>`；`SqlLogConsoleBridge.processConsoleLine` 解析写入 `LogSqlEntry.sourceFile/sourceLine`，实时日志复用与历史面板一致的精确 `OpenFileDescriptor` file:line 跳转——无标记时零影响、被动回退原表名搜索
- 新增 `SqlSourceMarker`（标记格式 / 解析）、`CallerSourceLocator`（调用栈 → 用户代码帧纯函数，VFS 路径统一正斜杠）
- 运行期拦截器自包含示例 `docs/instrumentation/SqlSourceInterceptor.kt`（Windows 反斜杠拼接坑已修复为正斜杠）
- `SqlLogPanel` 抽 `internal sealed class LogJumpTarget`（Precise / NoSource / NotFound / SearchByTable / NoTable）+ `resolveEntryJump` 统一解析层

**SQL 日志面板四项缺陷终局修复（F-44-2）**
- **列表 SQL 词法高亮恢复**：SQL 摘要走 `SqlListHtmlRenderer`（关键字 / 表名 / 字符串 / 数字 / 注释分色），时间戳与耗时走灰色 `#9E9E9E` 视觉分层不抢 SQL 颜色
- **耗时字段接入控制台链路（root fix）**：`ExecutionTimeParser` 已有完整 p6spy / MP TimeCount / 自定义前缀实现，但 bridge `FilterProxyHandler` 从未调用——本次接通，`SqlLogEntry.executionTimeMs` 写入真实值，耗时面板与历史面板均显示 `ms`，阈值色（<100ms 灰 / ≥100ms 橙 / ≥`slowQueryThresholdMs` 红）
- **「移除重复的sql」已存在条目同步去重**：勾选后面板新增 `SqlLogEntryBuffer.dedupeExisting()` 立即按窗口裁剪，丢弃数累加到 `dedupeCounts`，徽章与列表内容同生命周期
- **去重计数即时刷新**：去重分支也调用 `notifyChanged()`，`⨉N` 徽章与去重动作一帧同步

**SQL 历史面板两级导航（F-44-3）**
- **一级（默认视图）**：文件列表，每行 = 文件名（加粗）+ 文件大小（B/KB/MB）+ SQL 条数；空目录显示「暂无历史 SQL 文件」；搜索框按文件名过滤
- **二级（文件内容）**：双击文件进入，展示该文件逐条 SQL（SQL 高亮 + 耗时 + 时间戳 + 源码 renderer）；双击 SQL → 预览面板；右键 → 复制 SQL / 跳转源码；顶部「← 返回」回一级；搜索框按 SQL 内容/源文件过滤
- **刷新语义**：重新扫描目录生成文件摘要；正在浏览某文件且文件仍存在时保持二级视图（重载内容），否则回一级
- **性能**：新增 `SqlLogFileReader.countInFile(file)` 轻量条数统计（只数头部行不构建 `LogSqlEntry`，`useLines` 惰性 IO）
- **文案**：新增 `log.history.back / back.tip / files.empty / entries.empty / sqlCount / search.files` 六个中英文案

**HQL SELECT 实体别名展开为列清单（M36.7）**
- 修复 HQL 预览生成的 SQL 在 MySQL 执行报 `[1054] Unknown column 'u' in 'field list'`——HQL 语义 `SELECT u` 表示取整个实体，此前原样输出导致别名被当作列名
- 新增 SELECT 子句展开：裸别名且登记在 FROM / JOIN 才展开；无 SELECT 子句自动补列清单；JOIN 副表 / 元数据缺失降级 `alias.*`；DELETE / DISTINCT / 子查询 / 聚合 / 显式列不误伤
- 新增 `HqlConverterSelectExpandTest`（197 行）全路径覆盖

**帮助按钮本地 HTML 定稿（M36.5.80）**
- JCEF 在线文档在国内网络加载超时、`data: URL` 样式丢失——内嵌浏览器改为主路径（`marketplace-custom-page.html`，纯内联样式），JCEF 不可用 / 资源缺失时降级系统浏览器打开在线文档，删除网络探测逻辑

## 🔧 修复（相对 v2026.8.21）

**多行拼接 HQL gutter 漏检（M36.5.79）**
- 修复多行拼接 HQL 无预览图标——gutter 漏检 `PsiPolyadicExpression`（HQL 字符串被 `+` 拆分到多行），`findAssignedVariable` 沿引用链上溯以覆盖链式赋值场景

**弃用 API 清理（M36.5.78）**
- `HttpConfigurable` / `USE_HTTP_PROXY` → `ProxySettings.getProxyConfiguration()`（IDEA 2026.2 适配）
- `isUnderDarcula()` → `StartupUiUtil.isDarkTheme()`（平台弃用替代）

**历史文件注释格式回归（F-44-2）**
- F-43 旧版 3 个 `-` 注释（`--- source: ... ---`）回归为标准 SQL 单行注释（`-- source: ... --`）——更严格 SQL 方言对 3 个 `-` 整行注释兼容性差
- `SqlLogFileReader.NEW_HEADER_REGEX` 升级为 `^--+ source: ...`，可同时读 2/3 个 `-` 起结的文件（旧 3 `-` 文件仍可读，无需迁移）

**数据源选择器 NPE 修复**
- `DataSourceSelector.prepareConsole` 在平台 runner 列表为空时返回降级路径（`onError` 非空），避免选择 NPE；环境门控由新增的 `DataSourceSelectorIntegrationTest` 锁定
