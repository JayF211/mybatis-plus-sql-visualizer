# 🎉 SQL Visualizer v2026.9.10

> 发行说明留档：对应 Gitee 发行版 **v2026.9.10**（标签 `2026.9.10`），附件 `mybatis-plus-sql-visualizer-2026.9.10.zip`。

自 v2026.9.9 后的下一个版本（31 个提交，其中代码交付 15 项）。本版主题是**预览加载体验与 Hibernate 日志捕获的一日集中打磨**：双击日志预览弹窗加载卡顿根治、预览打开时 EDT 读权限断言刷屏全库排雷、Hibernate 双份日志参数分裂根治、竖向排列 VALUES 行尾列名标注配置项、IN 列表展开阈值、预览顶部元信息压按钮行修复、执行静默不执行修复、预览显示模式持久化，以及更新检查版本比较改用 IDEA 内置比较器（消除内测通道「同日先 beta 后转正」提示倒挂）。

## ✨ 新增

**竖向排列 VALUES 行尾列名标注做成配置项（T-VPairAnno）**
- 竖排展示下 INSERT 语句每个值行尾的 `-- 列名` 配对标注改为可配置——新增「竖向排列时显示列名标注」开关，默认**开启**，设置页可关闭；竖排按钮 tooltip 补充「可在设置中关闭」提示

**IN 列表竖向排列阈值（T-VStack·InThreshold）**
- `IN` 列表展开改为按元素数量分流：元素 **< 5** 保持同行、**≥ 5** 才逐行展开——避免短 IN 列表展开的负收益（此前只要选了竖向排列就全展开）

## 🔧 修复

**双击日志预览弹窗加载卡顿根治（T-PreviewSlow）**
- 双击 SQL 日志打开预览弹窗耗时偏长——根因一：`SqlPreviewPanel.awaitPrewarmedTempFile` 在 EDT 上 `Thread.sleep` 自旋轮询预热线程产物（同步 VFS refresh + PSI findFile 冷态常跑数百 ms~数 s，全烧进 UI 线程），预热等待上界 2000ms → 60ms——热态/二次打开预热已就绪立刻命中走 PSI 主路径，冷启动首拍直接降级纯内存编辑器不烧 EDT，预热完成后下次打开自愈回高亮/补全路径
- 伴随修复：`DataSourceSelector.prepareInConsole` 用 `ReadAction` 包裹 `attachConsole`，DBN 的 `attachConsole` 底层 new `EditorImpl` 构造里 `setHighlighter` 走 WriteIntentReadAction，平台锁层明文禁止「read-action 内再开 write-intent-read-action」，被 runCatching 吞成原生控制台从未挂载成功、每次静默回退自研编辑器——改为直接插桩去掉 ReadAction（第三方链入口自带读权限与切 EDT 语义）

**预览打开时 EDT 读权限断言刷屏（T-PreviewDocLock 系列）**
- 262 平台每次双击预览固定刷 4 条 `Read access is allowed from inside read-action only` SEVERE（`Plugin to blame: SQL Visualizer`）——根因=平台加固型契约违约：262 的 `FileDocumentManager.getDocument` 加了 `softAssertReadAccess`，而 EDT 鼠标事件无读权限，单次 `PsiDocumentManager.getDocument(psi)` 即踩 4 条。修复=该处按需包 `ReadAction`，并全库排雷 62 处 PSI/Document/VFS 访问点（业务帧全量零命中，不修未复现路径）
- 续修 F2/F3：项目类型检测 EDT 上 `JavaPsiFacade.findClass`（`assertReadAccess` **硬抛**，被设置页 `catch(Exception)` 吞成「注入静默失败」）移入 `ReadAction`；预览临时文件从「必得」改「尽力」——超时/拿不到时降级纯内存可编辑编辑器而不是整段打不开预览

**Hibernate 日志同语句双条目参数分裂根治（T-HibDualCapture）**
- `show-sql` 与 `org.hibernate.SQL: debug` 双路打印时同一条 SQL 被切成两条（logger 副本提前闭合产出零参 `?` 残留，参数全挂 stdout 副本，去重拦不住）——零参闭合条目入隔离槽、后继同 SQL 到达即取代；`?` 占位符按位替换改为 string-aware（单引号字面量/注释内的 `?` 不误回填错位）；预览警示分流：零参提示「未捕获到参数绑定日志」引导开 TRACE，有参不齐才报数量不匹配
- 参数框加宽 16 列 + 光标钉首 + tooltip 携带全值（8 列放不下 16 字符日期露尾部被当截断）

**预览顶部元信息压按钮行（T-PreviewTopOverlap）**
- 预览面板顶部元信息（JPA/Wrapper 等长行）在窄窗下压到按钮行重叠——低频按钮（导入/对比/分享）折叠进「更多」菜单，宽度预算截断，关键字换行按钮直显、复制错误永不折叠

**执行 SQL 首次静默不执行 + 误报凭据提示（T-ExecSilentNoop）**
- 预览首次「执行 SQL」可能静默不执行或误报凭据提示——执行模型回落强制走 `executeQueries` 兜底，提示分流去重

**预览显示模式持久化（T-PreviewDisplayMode 系列）**
- 输入参数后竖向排列/关键字换行形态消失——编辑器是模型派生视图，按钮里直改文档会被全量重建抹掉；显示模式收敛为唯一状态（压缩短路 / 工具栏 / 快捷键零改动），刷新复位普通模式、新预览保留、手改仍不保留（边界）

**更新检查版本比较改用 IDEA 内置比较器（T-VersionUtil）**
- Gitee 内测通道版本比较弃自研点分算法，委托平台 `com.intellij.util.text.VersionComparatorUtil`（243/253/262 三平台签名一致），与 IDE/Marketplace「发现新版」同口径——消除「同日先 beta 后转正」时内测通道提示倒挂；`-beta` 正确识别为预发布判小，`beta.10 > beta.9` 数值排不变

**SQL 日志列表行号两处修复（T-LogRowNumber 续）**
- 行号被非主进程启动重置（HTTP 请求脚本/profiler 等误触发清零）——仅主业务 Java 应用（ModuleBasedConfiguration 子类）启动才清行号
- 点击「移除重复的sql」漏裁跨窗口重复——手动一次性去重去时间窗口条件，纯按指纹判重（运行时窗口语义不变）

- **预览加载**：`SqlPreviewPanelTest` 增 237 行、`ExecSilentNoopHintTest`（99 行）、`SqlPreviewTopRowLayoutTest`（215 行）——布局断言 + 静默执行提示分流 + 顶部元信息折叠
- **Hibernate 双副本**：新增 `HibernateLogParserDualCopyTest`（168 行）、`SqlPreviewPanelParamFieldTest`（61 行）；`HibernateLogParserTest`/`LogEntryPreviewRecognizerTest`/`DualParserIntegrationTest` 改判合并语义与 string-aware 口径
- **竖向排列**：`SqlFormatterTest` 增 484 行（IN 阈值/列名标注开关/横向组展开）、`SettingsIOTest` + 配置项持久化断言
- **版本比较**：`VersionComparatorTest` 补 beta 预发布/同日序号用例
- 本版全量 **3254/0/0/6 绿**（263 套件），与基线一致零回归

## 兼容性

- 支持 IntelliJ IDEA **2024.3+**（Ultimate / Community；执行 SQL 与 Database 原生图需 Ultimate）
- 三版本（2024.3 / 2025.3 / 2026.2）verifyPlugin 全绿；本版未引入新的弃用/内部 API 使用
- 行为默认值变更：竖向排列 VALUES 行尾列名标注默认**开启**（可关闭）；IN 列表 < 5 元素保持同行

## 📦 安装

1. 下载附件 `mybatis-plus-sql-visualizer-2026.9.10.zip`
2. IDEA：`Settings → Plugins → ⚙️ → Install Plugin from Disk…` → 选择 zip → 重启 IDE
3. 已装旧版：设置页「更新」分区可直接检查更新下载安装（Gitee 渠道），或按上法手动安装覆盖
