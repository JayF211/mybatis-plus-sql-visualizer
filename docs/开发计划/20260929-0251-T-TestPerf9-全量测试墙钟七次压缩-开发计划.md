- 线程面旋钮只测过一代：T5 的 `-XX:ActiveProcessorCount` 帽的是**应用线程池本身**（测试代码里的并行度一起被压），证伪≠「JVM 自带线程争用」假说死。**二代旋钮只压 JVM 自带线程**（GC 工作线程、JIT 编译线程、显式 GC），应用并发度不动——机制面是空白区：5 并发平台测试 JVM 在 6C12T 上，G1 默认 ParallelGCThreads（Windows 12 逻辑核默认约 6~8）×5 + JIT 编译线程（tiered 默认约 4~5）×5 ≈ 50+ 条 JVM 自带线程与 5 套 EDT/测试线程争抢，头部 EDT 敏感类（每例秒级的那批）是首要嫌疑膨胀带。

## 二、改动方案

### S1 基线重建 + 全链段级拆账（测量件，先于一切改动）

- **借权重预热**：主树 `build/test-results/testShard1..5`（同 repo 同基线的真实实测数据）拷入本树同路径（本地构建数据不入 git，台账披露）——跳过新树冷启动两轮失准期（T8 V7：权重冷启动滞后一轮，cold 749.9s、前两轮不作数），首轮即得 warm 级分区。
- cold 1 轮 + warm 2 轮默认 5 片，记录四元组 + 逐片 execSum。
- `--profile` 一轮：拆 compileKotlin/compileTestKotlin/mcpStub/jar/prepareSandbox/各 testShard 任务墙钟——把 wall−exec 开销带（T8 推算 9.5~12s/片）钉死到段。
- 产出＝S2/S3 判据数据 + 段级账（后续轮次的地基，也是给用户的「时间花在哪」答卷）。

### S2 JVM 线程面二代旋钮筛查（主菜，全开关化、缺省不动）

buildSrc `mpv-testing.gradle.kts` 的 `withType<Test>` 块追加四个 `-P` 旋钮（一次提交；面＝根项目全部 Test 任务，agent 子项目不在面内且早收非瓶颈）：

| 旋钮 | JVM flag | 机制假说 |
|---|---|---|
| `-PtestGcThreads=N` | `-XX:ParallelGCThreads=N -XX:ConcGCThreads=max(1,N/2)` | 5×G1 工作线程风暴压帽，GC 停顿更短更稳 |
| `-PtestCiCount=N` | `-XX:CICompilerCount=N` | JIT 编译线程 ×5 压帽，头部类 JIT 争用回吐 |
| `-PtestNoExplicitGc=true` | `-XX:+DisableExplicitGC` | 平台显式 System.gc() 全暂停 ×5 JVM 根除 |
| `-PtestTieredStop=true` | `-XX:TieredStopAtLevel=1` | bootstrap JIT 预热提速（T8 S5 遗留，本轮一并销案/转正） |

- 筛查：每旋钮单独 1 轮 warm，同窗交错（与基线轮交替执行，同窗成对读数）；flag 合法性已用 JBR 17 -version 预验（测试 distro JBR 21 同 HotSpot 面，V2 复验）。
- 赢家判据＝中位差 >5% 且方向为正；赢家复证 2 轮同窗交错后定案（D1）。
- 风险预案：DisableExplicitGC 若引出 OOM/长尾（512m 堆失去显式回收点）即销案；TieredStop 若长 UI 类回劣即销案；全部销案也是合规交付（负结果入台账）。

### S3 片数保质期第五次复测 5 vs 6（实验件，S2 定型后的负载形态）

- 同法同窗交错 4/5/6 各 ≥2 轮 warm（4 片做下界哨兵），全程 PowerShell 3s 采 Commit（资源定例 R6）。
- 判据不变：中位差 >5% **且** Commit 峰值余量 >8GB、无换页；余量 <8GB 一票否决。
- T8 先验：6 片 −2.0%、余量 8.6GB 贴线——本轮若仍不过双判据即销案（第五次负结果防复立项）。

### S4 编译带画像（登记件，不翻多工作树定例）

- 增量态：touch 一个 main 源文件后 `./gradlew testShards` 拆 compile 段时长（真实开发态的全量=编译+测试，用户实际痛感大头之一）。
- `in-process`（现行，多工作树定例）vs `-Pkotlin.compiler.execution.strategy=daemon` 单路编译段 A/B 各 1 轮——只入台账，**不默认翻**（翻它影响多工作树并行开发定例，超出本任务权限）。

### S5 头部巨类方法级拆分扩展（算术销账，不实施）

立项画像已证：头部 8 座未拆山 7 座 <30 例（S3 机制门槛不可达），唯一达标的 SqlPreviewPanelTest 已拆。路线死，留档防复立项。若未来某巨类自然长到 ≥30 例，机制自动接管（`splitHeavyClassCandidates` 扩一行）。

### S6 mini-shard/工作窃取（算术销账，不实施）

10~16 个细粒度小片 + 并发帽（build service 信号量）的工作窃取方案：每片一个平台测试 JVM，bootstrap ≈12s/JVM 是**串行功**（K 片总税 K×12s÷并发），K=12/C=5 时税 ≈ +29s > 静态分片打包损失 ~17s（窃取收益上限）＝结构性负收益。留档。

### S7 jar 恒重建 + 沙盒链治理（算术销账，不实施）

Jar 恒重建（MPV-Build 时间戳，root 注入）实测对象仅 4.6MB（打包 ≈1~2s）、prepareSandbox ×5 sync ≈1~3s——合计 <5% 判据，且 up-to-date 化要动「构建时间每次刷新」的对外语义。不值，留档。

## 三、基线与验收

- **基线策略**：借权重预热 → cold 1 + warm 2；对照实验全部同窗交错（窗口漂移 ±5~8% 定例）；计时跑前 `parallel_tasks.py check` + 登记独立沙盒；全量单路收口、跑前 `timeout 10 docker info` 验 daemon、机器级只跑一路 test；buildSrc 改动集中一个提交且改动后先跑废轮（T8 教训：一次性编译税 ~2.5min 不许落进实验读数）。
- **红线**（沿用 T6/T7/T8）：零用例删减、零断言改动、测试效果不变；本轮**连测试执行面都不扩不缩**（全部旋钮只动 JVM 运行时参数，缺省全不动）；每步 -P 开关化可回退。
- **验收门禁**：①parity 全绿——计划类全集均有结果 XML，计数与基线轮一致（6082/0F/0E 口径随 dev 批次合流浮动，逐轮自比）；②S2 赢家（若有）同窗交错中位差 ≥5% 且复证 2 轮同向；③S3 双判据（≥5% + Commit 余量 >8GB）或销案；④测试源码零改动；⑤master 侧零触碰（写集＝buildSrc/gradle.properties 注释/文档，全在本任务树）。
- **预期（诚实口径）**：S2 一代旋钮已证伪过相邻假说，二代全销案概率不低；任一旋钮 ≥5% 即超 T8「持平带」交付；S3 先验 −2%；S1 段级拆账是**确定交付**（地基件）。

## 四、待验证前提（实施者先证伪再动手）

- **V1** 借权重预热收敛：拷 XML 后首轮分区预期 vs 实测落 ±7% 内（否则预热无效，退回 cold 校准两轮口径）。
- **V2** GC/JIT 线程帽在真实测试 JVM 上生效：已用 JBR 17 `-version` 预验合法；实施轮以一轮 shard JVM 实际 jvmArgs（Gradle debug 日志或 `-Xlog:gc+init` 抽查）证实透传到位。
- **V3** DisableExplicitGC 安全性：筛查轮零 OOM、零 timeout 型假失败（平台显式 GC 被禁后 512m 堆全靠 G1 自动回收；出现即销案）。
- **V4** CICompilerCount 下限：tiered 取 3 档（<下限 JVM 拒启，-version 预验已过；JBR emulated-client 特性不干扰）。
- **V5** 6 片 execSum 膨胀率不恶化：T8 读数 +17~29%；本轮 >35% 直接销案（膨胀主因是内存带宽/调度，帽不回来）。
- **V6** Commit 余量 8GB 硬判据不放松；采样轮峰值复核。
- **V7** 同窗交错纪律 + 废轮纪律（buildSrc 改动后第一轮读数一律作废）；S2 各旋钮筛查轮之间零 buildSrc 零零散改动。
