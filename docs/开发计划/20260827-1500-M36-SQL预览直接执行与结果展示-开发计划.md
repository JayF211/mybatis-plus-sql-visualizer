## 一、需求概述

### 1.1 当前问题

SQL 预览面板的「执行 SQL」按钮当前逻辑是创建临时 `.sql` 文件并打开原生编辑器，用户需要手动选择数据源 + 按 Ctrl+Enter 执行，执行结果不在预览面板内展示。链路过长，体验割裂。

### 1.2 目标

1. **直接执行**：点击按钮后直接执行 SQL，不再创建临时文件
2. **智能确认**：查询类语句（SELECT/SHOW/EXPLAIN 等）免确认直接执行；非查询类语句（INSERT/UPDATE/DELETE/CREATE 等）弹出二次确认
3. **数据源选择**：无默认数据源时，使用 IDEA 原生数据源选择弹窗
4. **结果内嵌展示**：查询结果直接在 SQL 预览面板下方展示（表格形式），非查询结果显示影响行数

### 1.3 边界条件

- Community 版（无 Database 插件）→ 保持现有降级提示
- 多条 SQL 语句 → 按最高风险级别处理
- 大数据量 → 限制最大返回行数（10000 行），超出截断
- 执行超时 → 显示超时提示，不阻塞 UI

## 二、技术调研

### 2.1 IDEA Database 插件关键 API

| 功能 | API | 所在 JAR |
|------|-----|----------|
| 原生数据源选择 | `DatabaseRunners.getAttachDataSourceRunners(PsiFile, String, Consumer<DatabaseSession>)` | intellij.database.impl.jar |
| 获取已配置数据源 | `DataSourceStorage.getStorage(Project).getDataSources()` | intellij.database.core.impl.jar |
| 执行 SQL | `JdbcConsole.executeQueries(Editor, ScriptModel, ExecOption)` | intellij.database.impl.jar |
| 创建查询请求 | `DataRequest.newRequest(OwnerEx, String)` | intellij.database.core.impl.jar |
| 查找/创建会话 | `JdbcConsoleProvider.findOrCreateSession(Project, VirtualFile)` | intellij.database.impl.jar |
| 数据源管理器 | `LocalDataSourceManager.getInstance(Project)` | intellij.database.impl.jar |

### 2.2 架构约束

- **反射隔离**：所有 `com.intellij.database.*` API 调用必须通过反射，保持 Community 版兼容
- **现有模式**：`ExecuteSqlSupport` → 反射 → `DatabaseConsoleLauncher` 的调用结构保持不变
- **临时文件**：执行时仍需创建临时 `.sql` 文件作为 PsiFile 上下文（供 `DatabaseRunners` 使用），但不再打开编辑器

### 2.3 执行流程对比

```
【当前】
SqlPreviewPanel.executeSql()
  → ExecuteSqlSupport.execute()
    → DatabaseConsoleLauncher.execute()
      → createTempFile() → FileEditorManager.openFile() → 用户手动操作

【目标】
SqlPreviewPanel.executeSql()
  → SqlTypeClassifier.classify(sql) → isQuery
  → 非查询 → 二次确认
  → DataSourceSettings.getDefaultDataSource()
    → 有 → 直接使用
    → 无 → DataSourceSelector.select() → 原生弹窗
  → SqlExecutor.execute(session, sql) → SqlExecuteResult
  → SqlResultPanel.showResult(result)
```

### Phase 7：执行流程编排

**目标**：串联完整执行流程

**修改文件**：
- `src/main/kotlin/cn/song/mybatisplus/visualizer/ui/SqlPreviewPanel.kt`（`executeSql()` 方法）

**新执行流程**：
```kotlin
// SqlPreviewPanel.executeSql()
internal fun executeSql() {
    val proj = project ?: return
    val sql = editor?.document?.text?.takeIf { it.isNotBlank() } ?: return

    // 1. SQL 类型分类
    val isQuery = SqlTypeClassifier.isQuery(sql)

    // 2. 非查询 → 二次确认
    if (!isQuery) {
        val keyword = SqlTypeClassifier.getFirstKeyword(sql) ?: "SQL"
        val confirm = Messages.showYesNoDialog(
            proj,
            MpSqlVisualizerBundle.message("execute.confirm.dml.message", keyword),
            MpSqlVisualizerBundle.message("execute.confirm.dml"),
            Messages.getWarningIcon()
        )
        if (confirm != Messages.YES) return
    }

    // 3. 获取数据源
    val defaultDs = DataSourceSettings.getDefaultDataSource(proj)
    if (defaultDs != null) {
        executeWithDataSource(proj, sql, defaultDs, isQuery)
    } else {
        DataSourceSelector.select(proj, sql) { ds ->
            if (ds != null) {
                executeWithDataSource(proj, sql, ds, isQuery)
            }
        }
    }
}

private fun executeWithDataSource(proj: Project, sql: String, ds: DbDataSource, isQuery: Boolean) {
    resultPanel.showLoading()
    // 后台执行 + EDT 更新结果
    ProgressManager.getInstance().run(object : Task.Backgroundable(proj, "Executing SQL", false) {
        override fun run(indicator: ProgressIndicator) {
            val result = SqlExecutor.execute(ds, sql, isQuery)
            ApplicationManager.getApplication().invokeLater {
                resultPanel.showResult(result)
            }
        }
    })
}
```

## 五、风险评估与缓解

| 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|----------|
| `DataRequest` 执行 API 复杂，结果捕获困难 | 高 | 无法获取执行结果 | 优先使用 `JdbcConsole.executeQueries()` + `getEmbeddedResults()` 提取 |
| 反射 API 版本兼容性 | 中 | 升级 IDEA 后失效 | 保持反射隔离，关键 API 多版本适配 |
| 临时 PsiFile 生命周期 | 中 | 内存泄漏/文件残留 | try-finally 确保清理，使用 `Disposable` 管理 |
| 大数据量内存溢出 | 中 | OOM | 限制最大行数 10000，分页加载 |
| 非查询语句误操作 | 低 | 数据被修改 | 强制二次确认 + SQL 类型检测 |
| EDT 阻塞 | 低 | UI 卡顿 | 使用 `Task.Backgroundable` 后台执行 |

### 最终根因（字节码级确认）

**`DatabaseRunners.runInDataSource` / `MyRunner.run()` 只创建 `DatabaseSession` 并回调
`Consumer`——并不执行 SQL**。反编译证实：

```java
// runInDataSource 完整实现（3 行）：
session = DatabaseSessionManager.getSession(project, localDataSource, sql);
consumer.consume(session);  // SQL 执行由 consumer 续接！
```

此前传入空 Consumer `{ }` → session 创建后被丢弃 → 选中数据源后无任何动作。

**执行链完整实现**（`cd1eb17`）：

```
getAttachDataSourceRunners(psiFile, sql, sessionConsumer)  // 原生数据源弹窗
  └─ 选中 runner → run() → 建session → sessionConsumer 回调
       └─ attachConsole(project, session, vf)   // 控制台挂到临时文件
       └─ openTextEditor(vf)                    // executeQueries 需要 editor
       └─ console.executeQueries(editor, scriptModel, execOption)  // 执行+原生结果展示
```

### 关键教训（记入全局踩坑）

1. **包私有类反射**：`DatabaseRunners$MyRunner` 跨包 invoke 须 `isAccessible = true`
2. **Database 执行 API 分层**：session 创建与 SQL 执行是两步，`Consumer` 回调是执行链入口
3. **Windows 沙盒文件锁**：runIde 的沙盒 IDEA 未完全退出时 jar 被内存映射锁定，
   `prepareSandbox` 静默失败（或覆盖失败），**沙盒跑的还是旧代码**——排查"改了没效果"先验 jar 时间戳/内容
4. **反编译核实**：反射调用前先 `javap -c` 看目标方法真实行为，勿凭方法名臆测语义

### 需求 1：默认打开查询结果 Tab

**现状**：`getUi()` 返回的 RunnerLayoutUi 默认激活 Output 视图（内容仅 "Console output"），
查询结果在旁边的结果 Tab，需要手动点击。

**方案**：内嵌前反射调用 `RunnerLayoutUi` 导航到结果视图：
- `getContents()` 获取全部视图内容（Result/Output 等）
- 选中**非 Output** 的第一个内容（即查询结果视图）
- 兜底：`selectAndFocus` 相关 API 反射调用

### 需求 2：控制台编辑器融合插件补全

**现状**：内嵌控制台的编辑器是 Database 原生编辑器（原生 SQL 补全、方言感知），
但**没有插件的补全能力**（表/列注释提示、实体字段感知——`SqlCompletionContributor`）。

**方案**：给内嵌控制台编辑器注册插件补全上下文：
- 取控制台编辑器 document + PSI
- 复用 [SqlCompletionContext]：把当前预览的表名/列名/注释注入该编辑器
- `editor.putUserData(SqlCompletionContext.KEY, ctx)` + `SqlCompletionContributor.registerContext(document, ctx)`
- 插件 contributor 的 `IS_PREVIEW_EDITOR` 守卫需放宽（当前只认预览面板编辑器）——
  新增注册表/标记位识别"内嵌控制台编辑器"
- 效果：Database 原生补全（方言/关键字/schema 对象）+ 插件补全（列注释 tooltip、实体字段）**叠加生效**

### 关键反编译结论（勿重复踩坑）

1. **原生 Database 控制台布局是拼合的，无单一完整组件**：
   - SQL 编辑器 = `EditorImpl.component`（由工具窗口 FileEditor 放上方）
   - 结果区/Output tabs = `logView.getUi().getComponent()`（RunnerLayoutUi）
   - `consoleView.getComponent()` = LanguageConsoleView 拼合体（编辑器+history viewer+
     **"Console output" 占位**）——用它必多出一块 Output（`c8740c2` 的教训）
2. **结果 Tab 由 executeQueries 异步创建**：执行前 contents 恒为 [Output]；
   阻塞等待不可行（密码挂起场景），必须 EDT Timer 非阻塞重试
3. **`ensureContentInitialized` 在 BaseLogView 上**（不在 RunnerLayoutUi），
   触发 buildConsoleUi() 构建内容
4. **MyRunner/ExecOption 等反射陷阱**（M36 已记录）：包私有类须 isAccessible；
   ExecOption 非 enum 须 newInstance

### 新方案架构

```
SqlPreviewPanel
├── 上半：参数面板 | SQL 预览编辑器（保持不变）
└── 下半：SqlResultPanel
    ├── 状态行（影响行数 / 错误 / 加载中）
    └── JBTable（查询结果：列名 + 行数据）

执行链路：
点击「执行 SQL」→ DataSourceSelector 选数据源 → JdbcExecutor 执行 → SqlResultPanel 渲染
                 ↓
        反射 LocalDataSource → DriverManager.getConnection → Statement.executeQuery
```

### JdbcExecutor 实现要点

- 反射 `LocalDataSource.getUrl/getUsername/getDriverClass/getConnectionProperties`
- 密码通过 `PasswordSafe` 获取（多策略兜底）
- 驱动加载优先从 `DatabaseDriver.getDriver()`，兜底 `Class.forName`
- 返回 `SqlExecuteResult（columns/rows/error）`
