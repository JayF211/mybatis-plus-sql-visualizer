# T-ErrReport：错误一键上报官网需求池 开发计划

> **创建日期**：2026-09-08
> **分支**：master（当前 HEAD `7aac2cb`）
> **优先级**：P1（用户遇到插件报错时没有任何顺手的报告通道，错误信息就此流失；官网需求池已上线却收不到 IDE 侧反馈）
> **预估工时**：4~6h（插件主体 3~4h + 官网配套 1~2h；runIde 真机人工验证另计）
> **来源**：用户截图 IDE Internal Errors 对话框——「插件出现报错信息后，无法报告错误，是否可以有办法快捷报告到官网的需求池」。截图案例本身（EDT 冻结 16 秒，`javax.swing.text.html.BasicHTML` 渲染栈，SQL Visualizer 2026.9.4）正是 T-LogListFreeze04 已在 master `9223f44` 根治的问题，用户安装版尚未拿到修复；但这恰好暴露了通用缺口：**这条线索目前只能靠用户手动复制粘贴到 Gitee Issues，错误对话框里那个 "report the problem to SongRenShuo" 链接只跳 Gitee 个人主页，连 Issues 都不是**。

## 一、需求分析

### 1.1 现场与痛点

IDE Internal Errors 对话框（`IdeErrorsDialog`）对第三方插件的默认行为：显示异常栈 + 一句「This plugin is not a production of JetBrains. Please report the problem to SongRenShuo」，链接取自 plugin.xml `<vendor url="https://gitee.com/SongRenShuo">`——用户点过去是 Gitee 主页，不是反馈入口。用户要报告必须：手动全选复制堆栈 → 打开 Gitee Issues 或官网需求池 → 手工粘贴 → 手工补 IDE 版本/插件版本/环境信息。门槛高，实际发生率为零。

### 1.2 目标：三条上报链路

1. **错误对话框直报**：注册平台 `errorHandler` 扩展点后，`IdeErrorsDialog` 对归属本插件的错误出现可用的报告按钮，点击弹出本插件自己的报告确认框——标题/描述按异常预填，堆栈自动打包为 txt 附件，连同 `source='ide'`、IDE 版本、插件版本一键提交到需求池，成功后给出 `FR-XXXX` 编号与详情页链接。
2. **手动反馈入口**：Help 菜单加「SQL Visualizer 反馈 / 需求池」项（原需求池计划 §八 的 Phase 2 设计），设置页「更新与诊断」分区加「报告问题…」按钮，复用同一个报告对话框（无异常预填形态）。
3. **浏览器兜底**：Help 菜单入口同时提供直接打开官网需求池表单的路径，URL 带 `source=ide&ideVersion=…&pluginVersion=…` 参数；官网表单读取参数自动填充（Phase 2 配套）。

### 1.3 边界

- 只覆盖**归属本插件 classloader 的错误**——平台按 PluginId 查 errorHandler EP，天然只把本插件异常派给本插件提交器，无需自行过滤；EDT 冻结（Freeze）在截图实证中已被归属到本插件，同样进入本通道。
- **不做静默自动上报**：无账号体系、服务端 5 次/小时/IP 限流、堆栈含本地路径的隐私顾虑，三点共同决定了报告必须是用户主动确认的动作（§3.8）。

## 二、现状盘点与数据契约

### 2.1 IDE 侧现状

- plugin.xml 无 `errorHandler` EP 注册；`<vendor url="https://gitee.com/SongRenShuo">SongRenShuo</vendor>`（plugin.xml:20）。
- 平台默认注册 `com.intellij.diagnostic.ITNReporter`（JetBrains 匿名统计通道），第三方插件错误不走它，于是对话框退化为 vendor 链接。

### 2.2 需求池 API 契约（已上线，后端零改动）

前端域名为 `https://sql-visualizer.jvtools.cn`（Pages Function `/api/v1/*` 代理 → `sql-visualizer-admin` Worker）。插件直连同域地址即可，无 CORS 问题（CORS 只约束浏览器）。

**POST /api/v1/feedback/posts**（提交反馈）

| 字段 | 约束 | 插件取值 |
|------|------|---------|
| `title` | 5~200 字符，必填 | 预填：异常简单名 + message 摘要（截断） |
| `description` | ≥10 字符，必填 | message + 用户补充说明 |
| `type` | 1功能需求 / 2Bug / 3体验优化 / 4疑问咨询 | 错误通道固定 2；手动入口默认 4 可改 |
| `category` | slug：wrapper/xml/annotation/sql-to-java/sql-log/batch/completion/other | 按异常栈包名映射，兜底 other |
| `submitterName` / `submitterEmail` | 选填（邮箱仅用于回执推送，不公开） | 记忆于设置，默认空 |
| `isAnonymous` | 缺省 true | 默认 true，与 web 表单一致 |
| `source` | 默认 'web'；建表 DDL 注释预留 **web / ide / import** | 固定 `'ide'` |
| `ideVersion` / `pluginVersion` | 选填 | `ApplicationInfo` / `PluginVersion.current()` |
| `attachments` | ≤3 个，先经 /upload 拿 key | 堆栈 txt（默认勾选） |

成功返回 `{code:0, data:{postNo:"FR-XXXX"}}`。服务端限流：提交 **5 次/小时/IP**、上传 10 次/分钟/IP；请求体含 U+FFFD（非 UTF-8）直接 400。

**POST /api/v1/feedback/upload**（multipart 字段名 `file`）：≤5MB，扩展名白名单 png/jpg/jpeg/gif/webp/pdf/**txt**/md，返回 `{data:{key,fileName,mimeType,fileSize}}`，key 随 posts 提交落 `fb_attachments`。

详情页深链（已上线）：`https://sql-visualizer.jvtools.cn/about/feedback?postNo=FR-xxxx`。

官网仓库 `docs/开发计划/20260903-1600-需求反馈池-开发计划.md` §八「In-IDE 集成（Phase 2）」已预留：HelpMenu action、`?source=ide&ideVersion=…&pluginVersion=…` URL 参数、表单自动附带环境。本计划是其 Phase 2 的完整落地，并新增了原案没有的错误对话框直报通道（errorHandler EP）。官网 FeedbackForm.vue 目前**不读** URL 参数，Phase 2 配套须补（§3.7）。

## 三、技术方案

### 3.1 总体结构

新增包 `cn.song.mybatisplus.visualizer.feedback`，五个类，渲染/日志管线零接触：

```
feedback/
├── IdeErrorReportSubmitter.kt   // errorHandler EP 实现（薄壳：事件 → 对话框 → 提交）
├── ErrorReportDialog.kt         // DialogWrapper 报告确认框（错误/手动两形态）
├── ErrorReportPayload.kt        // 标题/描述/分类映射/堆栈附件的组装纯函数
├── ErrorFingerprint.kt          // 栈指纹 + 24h 去重 LRU
└── FeedbackApi.kt               // posts/upload 客户端（sender 接口注入，测试可换 fake）
```

### 3.2 errorHandler EP 注册与 IdeErrorReportSubmitter

plugin.xml（`<extensions defaultExtensionNs="com.intellij">` 内）：

```xml
<errorHandler implementation="cn.song.mybatisplus.visualizer.feedback.IdeErrorReportSubmitter"/>
```

`IdeErrorReportSubmitter : ErrorReportSubmitter()`：

- `getReportActionText()`：bundle key `error.report.action`，中文「报告到 SQL Visualizer 需求池」/英文「Report to SQL Visualizer Feedback Pool」。注册后 `IdeErrorsDialog` 对本插件错误的报告按钮即用此文案。
- `submit(events, additionalInfo, parentComponent, consumer)`：events 空返回 false；否则在 EDT 弹 `ErrorReportDialog`（携带 events 预填），用户确认后交后台任务执行（§3.4），无论成败经 `consumer.consume(SubmittedReportInfo(...))` 回调——成功 `NEW_ISSUE`（携带详情页 URL + `FR-XXXX` 文案），本地判重命中 `DUPLICATE`，网络/服务端失败 `FAILED`；方法返回 true。
- `getPrivacyNoticeText()`：一句话说明将上传异常堆栈与 IDE/插件版本（平台会在对话框展示）。
- 自身 PluginDescriptor 经 `PluginAware.getPluginDescriptor()` 可得，但版本号仍走 `PluginVersion.current()`（该 API 在 2025.3~2026.2 有包迁移风险，PluginVersion.kt 注释已实证，不引平台 PluginManager API）。

### 3.3 ErrorReportDialog 报告确认框

DialogWrapper 单页表单（**普通 Swing 组件，不走 HTML 渲染**——截图里的 EDT 冻结正是 HTML 渲染栈，本对话框不得重蹈；DialogWrapper 的 cancelAction 本地化坑见项目记忆）：

- 错误形态预填：标题 = `异常类简单名: message 摘要`（超 200 截断、不足 5 补齐描述词）；描述 = message 全文；类型固定 2（Bug）；分类按栈帧包名映射（`log`/`console` → sql-log，`converter`/`wrapper` → wrapper，`xml` → xml，`completion` → completion，其余 other）。
- 「附带异常堆栈（.txt）」勾选框默认开，旁边小字注明堆栈可能含本地路径/类名，下方只读预览区展示堆栈前 ~60 行；不勾则仅提交标题描述与环境字段。
- 昵称/邮箱（选填，记忆于设置）+ 匿名勾选（默认开，与 web 表单行为一致）。
- 手动形态（无事件）：同布局，标题/描述空置，类型默认 4（疑问咨询）可改，无附件勾选（Phase 2 可扩截图粘贴）。
- 确定后禁用按钮直到回调完成，成功气泡/通知展示 `FR-XXXX` + 可点链接打开详情页（`BrowserUtil.browse`）。

### 3.4 FeedbackApi 客户端

- `createPost(payload: FeedbackPost): Result<String>`（返回 postNo）：`HttpRequests.post(URL, gsonBody)` ——字节码反编译确认 `post(String, String)` 即 `requestWithBody(url, "POST", body, null)`，二参是请求体；header `Content-Type: application/json; charset=UTF-8`（服务端显式校验 UTF-8）。超时 connect/read 各 10s。
- `uploadAttachment(fileName, bytes): Result<UploadedKey>`：multipart/form-data 手拼 boundary 字节（单文件字段 `file`），`HttpRequests.request(url).tuner { 设置 Content-Type: multipart/form-data; boundary=… } .connect { it.write(bodyBytes) }`——`Request.write(byte[])` 已 javap 核实。不引第三方 HTTP 库。
- 网络层抽象为 `FeedbackHttpSender` 函数接口，生产实现绑 HttpRequests，测试注入 fake（服务端契约测试不依赖外网）。
- 全程后台线程（`Task.Backgroundable` 或应用线程池），**禁止在 EDT 发起任何网络调用**——本插件刚为此付过 16 秒冻结的学费。
- 错误传播：429 时对用户提示「提交过于频繁（服务端每小时每 IP 限 5 次），请稍后再试」；其余非 0 code 透出服务端 message。

### 3.5 指纹去重与限流协同

- `ErrorFingerprint`：SHA-256(异常类名 + 前 5 个非平台栈帧的类名.方法名) 取前 16 位。同指纹 24 小时内不再重复提交（`SubmittedReportInfo.DUPLICATE`，对话框提示已收到过同类报告），内存 LRU（128 条）即可，不做持久化——重启后允许再报属可接受语义。
- 指纹短码写入 description 末尾一行（`fingerprint: xxxx`），管理员侧合并重复帖时有人工依据；不占用后端字段。
- 提交是用户逐次确认的动作，频率天然远低于 5/h，服务端限流仅作兜底文案（§3.4）。

### 3.6 手动入口

- Help 菜单：`<action id="cn.song.mybatisplus.visualizer.Feedback" class="...FeedbackAction">` `<add-to-group group-id="HelpMenu" anchor="last"/>`，文案「SQL Visualizer 反馈 / 需求池」。弹对话框（手动形态）+ 对话框底部「转浏览器填写」链接（带 source/ideVersion/pluginVersion 参数，Phase 2 官网读参后生效，当前跳转也不损失信息）。
- 设置页「更新与诊断」分区（UpdateSection 内）加「报告问题…」按钮，同对话框。

### 3.7 官网配套（Phase 2，跨仓库 `mybatis-plus-sql-visualizer-docs`）

- `FeedbackForm.vue` 读 URL query：`source`/`ideVersion`/`pluginVersion` → 提交时携带三字段；表单顶部展示「来自 IDE 插件 v{pluginVersion}」只读徽标。
- `about/feedback.md`（中英）补一段「IDE 内报错请直接用错误对话框的报告按钮，无需来网页」引导。
- 管理后台详情/列表展示 `source`（Worker 详情接口已返回 source 字段，仅前端展示缺失）——可选，与 admin 仓库排期对齐。

### 3.8 不采纳项与理由

- **静默自动上报（崩溃遥测）**：服务端 5 次/小时/IP、无账号去重、堆栈隐私三者叠加下不可控；用户主动确认模式与需求池「人工审阅入库」的产品定位一致。
- **后端新增专用错误上报接口**：posts 的 source/ideVersion/pluginVersion/attachments 已全覆盖，新接口只会造成两套审阅流。
- **vendor 链接改为直跳需求池作为唯一方案**：一行改动收益太小（仍无预填、无附件），作为 §3.6 的兜底链接保留。
- **上报 JetBrains ITN**：第三方插件错误本就不归 ITN；需求池是唯一权威池。

## 四、平台 API 核实记录（javap 权威，构建基线 ideaIU 2024.3.7.1）

> 按全局铁律：生成代码以本地 jar 反编译为唯一权威。以下全部于 `lib/app-client.jar` / `lib/util-8.jar` javap 核实（2026-09-08）。

- **EP 声明**（app-client.jar `META-INF/PlatformExtensionPoints.xml`）：`<extensionPoint name="errorHandler" interface="com.intellij.openapi.diagnostic.ErrorReportSubmitter" dynamic="true"/>`；平台默认实现 `PlatformExtensions.xml` 注册 `com.intellij.diagnostic.ITNReporter`。
- `com.intellij.openapi.diagnostic.ErrorReportSubmitter`：`abstract getReportActionText(): String`；`submit(IdeaLoggingEvent[], String, Component, Consumer<? super SubmittedReportInfo>): boolean`；`getPrivacyNoticeText(): String`；`getReporterAccount()` / `changeReporterAccount(Component)` 可不覆写；`PluginAware.getPluginDescriptor()`。
- `com.intellij.openapi.diagnostic.SubmittedReportInfo`：构造 `(String url, String linkText, SubmissionStatus)`；`SubmissionStatus` 枚举仅 `NEW_ISSUE / DUPLICATE / FAILED`。
- `com.intellij.openapi.diagnostic.IdeaLoggingEvent`：`getMessage() / getThrowable() / getThrowableText() / getData()`。Freeze 事件的堆栈取 `getThrowableText()`；平台内建附件对象（threadDump 等）无公开稳定取用 API，不依赖。
- `IdeErrorsDialog.Companion`：`ERROR_HANDLER_EP`（字符串字面量 `com.intellij.errorHandler`）+ `getSubmitter(Throwable, PluginId)`——平台按错误归属插件解析 EP；vendor 链接构造用 `IdeaPluginDescriptor.getVendor()/getVendorUrl()/getVendorEmail()`（email 加 `mailto:` 前缀）。
- `com.intellij.util.io.HttpRequests`：`post(String url, String body)`（反编译确认委托 `requestWithBody(url, "POST", body, null)`）；`RequestBuilder.tuner(ConnectionTuner)` 设自定义 header；`HttpRequests.Request.write(String)` / `write(byte[])`。
- `com.intellij.openapi.application.ApplicationInfo`（util-8.jar）：`getInstance() / getBuild(): BuildNumber / getFullApplicationName()`。
- `HelpMenu` group 与 `BrowserUtil.browse(String)` 为平台长稳 API（后者本插件 UpdateSection 已在用）。

## 六、测试计划

- **契约单测**：payload JSON 字段名/边界（title 5 与 200 截断、description ≥10、type=2、source='ide'、isAnonymous 默认 true、ideVersion/pluginVersion 非空回退）；multipart 字节结构（boundary 分隔、字段名 file、Content-Type 白名单 txt）；响应解析（code:0 取 postNo；400/415/429 message 透传）。UTF-8 编码显式断言（服务端 U+FFFD 400 拒绝）。
- **指纹单测**：同异常同指纹；首帧不同异指纹；平台帧过滤；24h 过期；LRU 容量。
- **Submitter 单测**：events 空 → false；预填标题截断与补齐；分类映射表逐例；去重命中 → DUPLICATE 回调且不发网络（fake sender 计数）；sender 抛异常 → FAILED 回调。
- **对话框单测**（组件内嵌模式，仿 UpdateSection 测试手法）：两形态默认值；附件勾选联动；匿名默认。
- **全量回归**：基线 3112 全绿 + 本轮新增（预估 +20 左右）零失败；跑前按铁律查并行任务表。
- **runIde 真机**：沙盒内触发插件异常（临时注入）→ IDE 错误对话框出现「报告到 SQL Visualizer 需求池」按钮 → 提交 → 通知给出 FR 编号 → 浏览器详情页可见附件与环境字段。真机步骤留人工跟进（同 T-LogListFreeze04 惯例）。

## 七、风险与边界

- **调用线程**：`submit` 由平台在 EDT 调用，对话框可同步弹；网络一律后台，回调 `consumer.consume` 允许任意线程（平台内部已处理）。
- **动态卸载边界**：提交进行中插件被禁用/更新的窗口极小，提交链路整体 `runCatching` 包裹，异常只记日志不再上报（防递归）。
- **262 平台 read access 硬抛**：本功能无 PSI/VFS 读取，纯 Swing + HTTP，规避已知陷阱。
- **提交内容即隐私边界**：默认只上堆栈 txt（可取消、可预览），永不读取工程源码/SQL 历史；描述文本用户可见即可见。
- **共享出口 IP**：企业 NAT 下多名用户共享 5/h 限额，429 文案已引导；接受为低频场景。
- **平台兼容**：errorHandler EP 与本文所列 API 在 243~262 全区间稳定（ITNReporter 同款机制），verifyPlugin 既有 243/262 目标已覆盖；无新旧双名需求。
