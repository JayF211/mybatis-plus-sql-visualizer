## 二、根因分析

### 2.1 T-FeedbackDlg-03：弹窗过宽（先修，它是宽度主因）

**证据链**：
- `ErrorReportDialog.kt:43`：`titleField = JTextField(ErrorReportComposer.TITLE_MAX)`。`JTextField(int columns)` 的列数语义是**首选宽度按列数计算**，把「最大长度 200」当「显示列数 200」传入，首选宽 ≈ 200 × 当前字体 m 宽 ≈ 1400px+。
- DialogWrapper 按 centerPanel 首选尺寸 pack，GridBag 第 1 列 `weightx=1.0 + HORIZONTAL` 拉伸不改首选，于是对话框直接撑到 1272px（截图实测）。
- 次因：`descriptionArea = JBTextArea(8, 46)`、`stackPreview = JBTextArea(10, 46)`（ErrorReportDialog.kt:46-47）46 列 ≈ 420px，叠加后仍偏宽，但非主因。

**修复**：
- 标题框列数 200 → 30（`JBTextField(30)`），长度上限不靠列数表达（见 2.2 提交校验兜底 >200）。
- 描述/堆栈两处 `JBScrollPane` 显式 `preferredSize = JBUI.size(620, 140)` / `JBUI.size(620, 180)`，文本域列数相应回落到 40（首选宽被滚动面板钳制）。
- 目标宽度：对话框 ~660px（label 列 + 字段列 + 边距），与 IDE 常规模态对话框同量级。

### 2.2 T-FeedbackDlg-01：灰色占位提示缺失

**证据链**：
- `titleField` 为裸 `JTextField`、`descriptionArea` 为 `JBTextArea`（ErrorReportDialog.kt:43/46），均未设空文本占位。
- 官网需求池 web 表单有占位提示且与 IDE 空窗场景完全对应（`feedback/i18n.ts:36/38`）：标题「请简要描述您的需求或问题（至少 5 个字符）」、描述「请详细描述您的问题或需求场景（至少 10 个字符）」；web 标题另有 `maxlength="200"`（FeedbackForm.vue:37）。
- 服务端契约 title 5~200 / description ≥10（T-ErrReport 计划 §2.2 契约表，FeedbackApi.kt:16 注释同）。手动形态 `collectRequest()` 原样透传输入（ErrorReportDialog.kt:145-146），不足下限直接吃服务端 400——缺的不只是提示，还有客户端校验闭环。

**平台 API 已按铁律用本机 262 平台 jar 反编译实锤**（`lib/intellij.platform.ide.jar` 常量池核对）：
- `JBTextField.getEmptyText(): com.intellij.util.ui.StatusText`，实现 `com.intellij.util.ui.ComponentWithEmptyText`；
- `JBTextArea` 同样有 `getEmptyText(): StatusText`（当前代码用的正是 JBTextArea，直接可用）；
- `StatusText.setText(...)` 存在（同 jar）。

**修复**：
- 标题框换 `JBTextField`（裸 JTextField 无空文本能力），与描述域一起 `getEmptyText().setText(bundle...)`，文案与 web 逐字对齐。
- `ErrorReportComposer` 的 `TITLE_MIN`/`DESCRIPTION_MIN` 由 private 升 internal，供对话框校验引用，单一事实源。
- 补 `doValidate()` 客户端校验（DialogWrapper 原生机制，平台 jar 实锤 `doValidate(): ValidationInfo?` 存在）：标题 <5 或 >200 → ValidationInfo 定位标题框；描述 <10 → 定位描述域。不通过时对话框不关闭、不触网，错误文案走 i18n。错误形态预填天然满足契约不受影响；用户改短了同样被拦。
- i18n 新增 4 键（zh 与默认 en 双 bundle 同步，parity 守卫测试自动把关）：
  - `error.report.dialog.subject.placeholder` = 请简要描述您的需求或问题（至少 5 个字符）/ Briefly describe your request or issue (at least 5 characters)
  - `error.report.dialog.description.placeholder` = 请详细描述您的问题或需求场景（至少 10 个字符）/ Describe your issue or use case in detail (at least 10 characters)
  - `error.report.dialog.validation.title` = 标题需 5~200 个字符 / Title must be 5-200 characters
  - `error.report.dialog.validation.description` = 描述至少 10 个字符 / Description must be at least 10 characters

### 2.3 T-FeedbackDlg-02：描述/堆栈预览不可拖拽

**证据链**：
- DialogWrapper 默认不可拖拽调尺寸（`setResizable` 需显式调用，平台 jar 实锤 `setResizable(boolean)`/`isResizable()` 存在），本对话框未调用。
- GridBag 布局所有行 `weighty=0`（createCenterPanel 只设了 `weightx`），即使对话框可拖高，多出的高度也不分给描述/堆栈两行。

**修复**：
- `setResizable(true)`；`getDimensionServiceKey()` 返回常量 key（如 `"MpSqlVisualizer.ErrorReportDialog"`），用户拖拽后的尺寸经 DimensionService 跨会话记忆（平台原生机制，平台 jar 实锤存在）。
- 描述行与堆栈预览容器行 `fill = BOTH + weighty = 1.0`（labelRow 变体：label 仍 WEST 不拉伸，仅字段侧纵向吃高）。两行都 weighty=1：都可见时均分增高，堆栈未勾选（不可见）时 GridBag 跳过不可见组件、描述独享——无需动态改约束。
- 描述域 `lineWrap` 已开（ErrorReportDialog.kt:70），增高即多显行数；堆栈预览 `lineWrap=false` + 滚动面板，增高加宽都自然生效。无需引入逐组件 resize grip（Swing 对话框无此惯例，IDE 原生对话框一律走「对话框可拖拽 + 内容区随伸」形态）。

### 可测试性设计（三任务共用）

现有 FeedbackReportingContractTest 明确回避了 DialogWrapper 构造（注释「弹窗 UI 形态不可 headless 验证」），本任务把可纯测面抽出来对齐「UI 只做编排 + 纯函数单测」家规：
- `createCenterPanel` 改为 internal 纯函数 `buildCenterPanel(fields: ReportFormFields): JComponent`（fields 持有全部输入控件），dialog 持有 fields 调用它——测试直接 new fields + build，零 DialogWrapper peer 依赖。
- 校验逻辑抽纯函数 `internal fun validateForm(title: String, description: String): String?`（返回 i18n key 或 null），`doValidate()` 委托之。

**测试**（新建 `ErrorReportDialogLayoutTest`，平台测试桶）：
- 占位：titleField 空文本含 placeholder 键解析文案（≠ 键名原样，防缺键回退）；
- 宽度防回归：`buildCenterPanel(...).preferredSize.width ≤ 800`（200 列旧实现 >1200 必炸，阈值两侧余量充足）；
- 可拖拽：`isResizable == true`、dimensionServiceKey 非空、GridBag 描述行/堆栈行约束 `weighty > 0` 且 `fill == BOTH`；
- 校验：validateForm 纯函数表驱动（空/3 字标题/12 字标题/200 字标题/201 字标题 × 空/9 字描述/10 字描述）；
- 既有 FeedbackReportingContractTest 的分类/bundle 契约不动；新 4 键被 bundle parity 守卫自动覆盖。
