# SQL 日志列表 EDT 冻结修复 开发计划

> 问题：打开 SQL 日志面板时 EDT 冻结 25 秒（`Freeze in EDT for 25 seconds`）。
> 根因：`SqlLogPanel.refreshList` 调用 `DefaultListModel.addAll` 触发全量布局重排，`WideSelectionListUI.updateLayoutState` 对每个 cell 调用 `LogEntryListCellRenderer.getListCellRendererComponent`，每次 `JLabel.setText("<html>")` 走 `BasicHTML$Renderer` 解析，200 条 SQL × (词法高亮 + HTML 解析) = EDT 阻塞。
> 分支：`perf/sql-log-list-edt-freeze`（git worktree 独立目录，并行会话隔离）。
> 范围：仅 `SqlLogPanel.refreshList` + `LogEntryListCellRenderer`，不改日志捕捉语义、不改 buffer 行为。

## 问题分析

### 调用链（采样栈）

```
FileEditorManagerImpl.openFile → NavigationUtil.openFileWithPsiElementAsync
  → SqlLogPanel._init_$lambda$2 (SqlLogPanel.kt:317)   ← 订阅回调
    → SqlLogManager.notifyUi (SqlLogManager.kt:288-292) ← invokeLater
      → SqlLogPanel.refreshList (SqlLogPanel.kt:736)
        → DefaultListModel.addAll(sorted) (line 753)    ← fireIntervalAdded
          → WideSelectionListUI.updateLayoutState
            → getItemPreferredSize → ExpandedItemListCellRendererWrapper
              → LogEntryListCellRenderer.getListCellRendererComponent (line 1207)
                → JLabel.setText("<html>...")
                  → BasicLabelUI.propertyChange
                    → BasicHTML.updateRenderer
                      → BasicHTML$Renderer.<init>        ← 卡 18.5 秒
```

### 关键事实

| 事实 | 源码位置 | 影响 |
|------|----------|------|
| `addAll` 一次性灌入 200 条 | `SqlLogPanel.kt:753` | 触发全量 `updateLayoutState` |
| 每条调用 `SqlListHtmlRenderer.render` 做词法高亮 | `SqlLogPanel.kt:1205` | SqlLexer + 8 色 span 拼接 |
| 输出用 `<html>` 包裹触发 BasicHTML | `SqlLogPanel.kt:1207` | `JLabel.setText` 走 `BasicHTML$Renderer.<init>` |
| `WideSelectionListUI.updateLayoutState` 遍历所有行算 preferred size | 平台代码 | N 次 renderer 调用 |
| `refreshList` 在 init 时即调用（line 318） | `SqlLogPanel.kt:318` | 打开面板即冻结 |

### 性能成本分解（200 条 SQL，每条 ~200ms 渲染）

- **词法高亮**：`SqlLexer.start + advance` 对每条 SQL 完整分词 → ~0.1ms/条
- **HTML span 拼接**：8 种 token 类型的 `<span style='color:#xxx'>` 包裹 → ~0.05ms/条
- **BasicHTML 渲染**：`BasicHTML$Renderer.<init>` 创建 `HTMLDocument` + `View` 树 → **~5-10ms/条**（大头）
- **总计**：200 × ~10ms = **~2s 纯 CPU**，与观察的 18.5s 采样一致（EDT 还有其他开销）

### 为什么现有代码无法自我修正

- `addAll` 注释说「fireIntervalAdded 仅触发一次布局计算（M46：O(N²) → O(N)）」——这是模型层的事件次数，但每次事件仍触发全量 `updateLayoutState`，renderer 仍被调用 N 次
- `LogEntryListCellRenderer` 继承 `DefaultListCellRenderer`（即 `JLabel`），`setText` 检测到 `<html>` 前缀即走 `BasicHTML` 路径，无法关闭

## 目标

打开含 200 条历史 SQL 的日志面板，EDT 冻结 < 500ms（降低 95%+）；滚动流畅不掉帧；SQL 列表着色能力保留。

## 任务

### T-LogListFreeze-01 批量布局抑制（快速收益，~60% 改善）

- `refreshList` 中 `addAll` 前后加批量抑制，阻止 `updateLayoutState` 在中间状态反复触发：

  ```kotlin
  list.ignoreRepaint = true        // 抑制 repaint + 布局
  listModel.clear()
  if (sorted.isNotEmpty()) listModel.addAll(sorted)
  list.ignoreRepaint = false
  list.revalidate()                // 一次性重算布局
  list.repaint()
  ```

- **风险**：`ignoreRepaint` 仅跳过绘制请求，不跳过模型事件触发的布局；实际效果需 runIde 截图验证（layout state 仍会在 `addAll` 时触发，但 EDT 中间帧被抑制，用户感知改善）。
- **兜底**：若 `ignoreRepaint` 对此场景无效（仍卡），转 T-LogListFreeze-02 主攻。

### T-LogListFreeze-02 渲染结果缓存（核心收益，~90% 改善）

- **问题**：每次 layout pass、每次滚动，`getListCellRendererComponent` 都被调用，重复执行 `SqlListHtmlRenderer.render` 和 HTML 解析。
- **方案**：在 `LogSqlEntry` 上新增内部字段 `cachedListHtml: String?`，惰性计算并缓存；`LogEntryListCellRenderer` 直接取缓存，不重复渲染。

  ```kotlin
  // LogSqlEntry 新增（或加在 wrapper 层）
  data class LogSqlEntry(
      // ... 现有字段
      internal var cachedListHtml: String? = null,
  )
  ```

- **失效时机**：`refreshList` 重新执行时清空全部缓存（`snapshot.forEach { it.cachedListHtml = null }`），保证排序/过滤/设置变更后 HTML 重新生成。
- **HTML 仍保留**：缓存的是最终 HTML 字符串，`JLabel.setText(cachedListHtml)` 仍走 BasicHTML，但每 SQL 仅解析一次（首次 layout pass），后续滚动取缓存无额外开销。
- **内存**：200 条 × ~2KB/条 = ~400KB，可接受。

### T-LogListFreeze-03 分批 EDT 写入（防首屏卡顿）

- **问题**：即使有 T-LogListFreeze-02，首次 `addAll` 仍触发 200 次 `BasicHTML$Renderer.<init>`（每行首次 layout），累积 ~2s。
- **方案**：首屏只加载可见行 + 缓冲（如 30 条），剩余行通过 `invokeLater` 分批追加。

  ```kotlin
  private fun refreshList() {
      // ... 过滤排序 ...
      listModel.clear()
      val batchSize = 30
      val firstBatch = sorted.take(batchSize)
      val remaining = sorted.drop(batchSize)
      listModel.addAll(firstBatch)
      if (remaining.isNotEmpty()) {
          // 异步追加剩余（每批一次 invokeLater，让 EDT 处理事件）
          val iterator = remaining.iterator()
          fun appendNext() {
              if (!iterator.hasNext()) return
              val chunk = mutableListOf<LogSqlEntry>()
              repeat(30) { if (iterator.hasNext()) chunk.add(iterator.next()) }
              listModel.addAll(chunk)
              if (iterator.hasNext()) ApplicationManager.getApplication().invokeLater { appendNext() }
          }
          ApplicationManager.getApplication().invokeLater { appendNext() }
      }
  }
  ```

- **首屏时间**：30 条 × ~10ms = ~300ms，可接受。
- **副作用**：列表在追加期间可交互但可能看到滚动条变化；可通过 `list.ensureIndexIsVisible(0)` 保持顶部稳定。
- **与 T-LogListFreeze-02 协同**：缓存让追加阶段的 HTML 解析每行只做一次。

### T-LogListFreeze-04 换用 JTextPane + StyledDocument 替代 HTML（高亮保留，消除 BasicHTML）

- **问题**：`BasicHTML$Renderer.<init>` 是 Swing 已知昂贵路径——即使 T-02 缓存后，首次 layout pass 仍对每条 SQL 解析 HTMLDocument，200 条累积 ~2s 不可接受。
- **方案**：`LogEntryListCellRenderer` 改用 `JTextPane` + `StyledDocument` 承载 per-token 着色，彻底绕开 HTML：
  - `JTextPane` 替换 `JLabel`（`DefaultListCellRenderer` 继承链保留，内部文本载体换 `JTextPane`）
  - `StyledDocument.setCharacterAttributes(offset, len, attrs, false)` 按 SqlLexer 分词结果逐 token 设色
  - 颜色体系不变（`SqlHighlightColors` → `EditorColorsScheme` → `SimpleAttributeSet.foreground`）
  - 时间戳 / 来源 / 去重徽章仍用纯文本拼接，仅 SQL 主体走 StyledDocument
- **优势**：高亮保留 + `BasicHTML$Renderer` 彻底消失 + StyledDocument 设色比 HTML 解析快 10x+。
- **风险**：`JTextPane` 在 `JList` cell 中需调 `setOpaque(true)` + `setBackground` 同步选中色，避免默认灰色背景；选中态切换需在 `getListCellRendererComponent` 里同步改 `StyledDocument` 背景色或 `JTextPane.background`。
- **决策**：T-06 验证 T-02 后若仍 >500ms，则启用本任务。

### T-LogListFreeze-05 单元测试

- **缓存一致性**：`LogSqlEntry.cachedListHtml` 在 `refreshList` 后清空（断言 snapshot 中所有 entry.cachedListHtml == null）。
- **缓存命中**：同一 entry 连续两次调用 `getListCellRendererComponent`，第二次 `SqlListHtmlRenderer.render` 未被调用（mock/spy 计数）。
- **分批写入**：mock `invokeLater` 捕获追加调用次数，验证 200 条分 7 批（30+30+30+30+30+30+20）。
- **HTML 禁用分支**（若实施 T-LogListFreeze-04）：`getText` 返回非 `<html>` 前缀文本。
- **既有测试**：`SqlLogPanelTest` / `LogEntryListCellRendererTest` / `SqlListHtmlRendererTest` 全绿。

### T-LogListFreeze-06 真实环境验证

- runIde 打开含 200 条历史 SQL 的日志面板，用 IDEA 性能采样（`Help → Diagnostic Tools → Activity Monitor`）验证 EDT 峰值 < 500ms。
- 滚动列表验证无掉帧（`WideSelectionListUI` 缓存命中后不重新渲染）。
- 切换类型过滤 / 搜索 / 排序验证缓存正确失效。
