# 快捷模板三动作默认键位摘除与冲突检测下线 — 开发计划

> 来源：2026-09-21 用户走查中贴出的两条启动告警（「COUNT Selected Table：快捷键 shift alt pressed C 同时被 RecentChanges 占用」「Sample 10 Rows：快捷键 shift alt pressed T 同时被 tasks.switch 占用」，两条均为「自动改绑失败」分支），用户追问键位价值后**定案：三个动作都不设默认键位**。
> 本计划只处理默认键位与随之作废的冲突检测；三个动作本身（右键入口、执行链、设置页录制入口）一行不动。

---

## 一、结论与实测依据

### 1.1 为什么必须摘（不是「价值不大」的软理由）

默认键位与备选键位**同时**落在平台既有键位上，所以告警里的「自动改绑失败」是代码路径决定的必然结果，不是环境偶发：

| 键位 | 2024.3.7.1（= 插件最低支持版本，也是 runIde 沙盒平台，IU-243.28141.41） | 2026.2.3（本机日常 IDE，262.10968.63） |
|---|---|---|
| Alt+Shift+E（EXPLAIN 默认） | 空闲 | 空闲 |
| Alt+Shift+C（COUNT 默认） | `RecentChanges`（`lib/product.jar!META-INF/plugin.xml`） | `RecentChanges`（`lib/intellij.idea.ultimate.customization.jar!META-INF/plugin.xml`） |
| Alt+Shift+T（Sample 默认） | `tasks.switch`（`plugins/tasks/lib/tasks-core.jar!META-INF/plugin.xml`） | 键位资源里查不到该绑定（262 的 tasks 插件已不占此键） |
| Ctrl+Alt+Shift+C（插件备选） | `CopyReference`（`lib/app-client.jar!keymaps/$default.xml`） | `CopyReference`（`lib/intellij.platform.ide.impl.jar!keymaps/$default.xml`） |
| Ctrl+Alt+Shift+T（插件备选） | `Refactorings.QuickListPopupAction`（同上 keymap） | 同左 |

备选键被占 → `conflictOwner(fallback) != null` → `rebound=false` → 必走 manual 文案。两条告警同时出现，正是这个判据的结果。

### 1.2 两处需要一并订正的表述

- `SqlTemplateShortcutConflictCheck` 的 KDoc 与 T-PreviewUx-Pack 计划把失败原因写成「当前 scheme 不可写」——**与实测不符**。243 源码 `com/intellij/openapi/keymap/impl/KeymapImpl.kt` 的 `addShortcut` / `doAddShortcut` 里没有任何 `canModify` 守卫（该类中 `canModify()` 唯一调用点是 `deriveKeymap`），捆绑键位表上 `addShortcut` 不会抛异常；本次失败的真实原因是**备选键被占**。
- `addShortcut` 只加不摘（KDoc 自述），所以即便换绑「成功」，原冲突键位仍在——冲突没被解决，只是多了一个触发入口。

### 1.3 附带发现（本计划不改，只登记）

同族的两个老动作从未纳入启动检测，而它们同样撞车（两版平台都在）：`ConvertSqlToJava` 的 Alt+Shift+J = 平台 `UnselectPreviousOccurrence`；`ConvertToSql` 的 Alt+Shift+Q = bundled 插件 webDeployment 的 `PublishGroup.UploadAllOpenFiles`。这两个是主入口，换键影响面大，留独立议题。

### 1.4 关键前提：这三个键位从未随任何发行物交付

四条独立证据：

1. CHANGELOG 该条目仍在 `## [Unreleased]`（`CHANGELOG.md:37`，Unreleased 段为 5–141 行），已发布段（142 行起）无任何相关条目；
2. 本机已装发行版 `mybatis-plus-sql-visualizer-2026.9.18-beta.4.jar` 实测：`plugin.xml` 中 `CountSelectedTable` / `SampleSelectedTable` / `ExplainSelectedTable` / `SqlTemplateGroup` / `SqlTemplateShortcutConflictCheck` 全部不存在，jar 内也无对应 class；
3. `git tag --contains 7c77640`（T-PreviewUx-Pack 交付提交）与 `git tag --contains 69fac4b`（T-ShortcutSettings）**均为空**——全仓 23 个 tag 无一包含它们；同一命令对 `2026.9.9` 的提交返回 `2026.9.10 / 2026.9.11 / 2026.9.14`，可证查询本身有效（非命令失灵）；
4. 插件仓 `docs/发行说明/` 无任何一条提到过这三个动作。

因此本次摘除对已装用户零影响（不存在「用户已经习惯这个键」），也允许直接修订 [Unreleased] 条目而非新增 Changed 条目。

用户看到的那两条告警来自 runIde 沙盒（243 平台）——这也与告警里的占用者完全吻合：`RecentChanges` 两版都有，`tasks.switch` 只有 243 有。
