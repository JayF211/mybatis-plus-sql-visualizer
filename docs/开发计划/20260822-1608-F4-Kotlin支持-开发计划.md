> **调研结论**：MP 的 `mybatis-plus-kotlin` 模块（3.5.17）提供 `ktQuery()`/`ktUpdate()` 扩展函数，不是独立的 KtQueryWrapper 类。需 Kotlin PSI 基础设施。

---

## 0. 目标

支持 Kotlin 代码中调用 MyBatis-Plus 的 Wrapper 链预览。覆盖 `ktQuery()`/`ktUpdate()` 扩展函数形态。

**用户价值**：Kotlin + MP 用户群体持续增长，当前插件无法识别 Kotlin 中的 Wrapper 调用。

---

## 1. 技术方案

### 1.1 Kotlin 中的 MP 调用形态

```kotlin
// 形态 1： IService.ktQuery() 扩展函数
service.ktQuery().eq(User::name, "x").like(User::email, "@").list()

// 形态 2： IService.ktUpdate() 扩展函数
service.ktUpdate().set(User::name, "y").eq(User::id, 1).update()

// 形态 3：直接构造 LambdaQueryWrapper
LambdaQueryWrapper<User>().eq(User::name, "x").list()
```

### 1.2 Kotlin PSI 关键类

| Java PSI | Kotlin PSI 对应 | 说明 |
|----------|----------------|------|
| `PsiMethodCallExpression` | `KtCallExpression` | 方法调用 |
| `PsiNewExpression` | `KtCallExpression` | 构造函数调用 |
| `PsiLambdaExpression` | `KtLambdaExpression` | Lambda 表达式 |
| `PsiReferenceExpression` | `KtReferenceExpression` | 引用表达式 |
| `PsiClass` | `KtClass` | 类定义 |
| `PsiMethod` | `KtFunction` | 函数定义 |

### 1.3 依赖

```kotlin
// build.gradle.kts 新增
implementation("org.jetbrains.kotlin:kotlin-compiler-embeddable:2.3.20")
// 或使用 IntelliJ 平台内置的 Kotlin PSI（需确认是否可直接引用）
```

**注意**：IntelliJ 平台已内置 Kotlin PSI 支持（`org.jetbrains.kotlin` 模块），优先使用平台内置版本，不额外引入 kotlin-compiler。

### 1.4 架构

```
Kotlin 文件中的 PsiElement
  → KtWrapperDetector.detect()           [新增]
      → 检测 KtCallExpression
      → 匹配 ktQuery() / ktUpdate() 扩展函数名
      → 或匹配 LambdaQueryWrapper 构造
      → 返回 WrapperType + 链信息
  → KtChainParser.parse()                 [新增]
      → 解析 KtCallExpression 链
      → 处理 KtLambdaArgument（实体属性引用）
      → 转换为 WrapperChain 模型（复用现有模型）
  → 后续复用现有 ConverterRegistry → SqlGenerator → 预览
```

## 4. 边界与降级

- Kotlin 文件未启用 Kotlin 插件（极少数情况）：不识别，不报错
- Lambda 参数解析失败：降级到原始文本展示
- MPJ Kotlin 链：如果解析成本高，可先仅支持 Java 形态，Kotlin 标注 TODO

---

## 5. 预估风险与备选

| 风险 | 影响 | 备选方案 |
|------|------|----------|
| Kotlin PSI API 不稳定 | 跨版本兼容问题 | 锁定 since-build 范围 + 反射隔离 |
| Kotlin 扩展函数 resolve 成本高 | 性能问题 | 仅按方法名匹配（不 resolve），O(1) |
| kotlin-compiler 依赖体积大 | 插件膨胀 | 优先使用 IntelliJ 平台内置 Kotlin 模块 |
