# SQL 历史面板两级导航（文件列表 → SQL 列表 → 预览）开发计划

> **创建日期**：2026-08-31 17:47
> **触发**：用户实测反馈历史面板应分层展示——默认文件列表（文件名 + 文件大小 + SQL 条数），
> 双击文件进入该文件的 SQL 列表，再双击 SQL 才打开预览面板。
> **优先级**：中高（面板当前将多文件全部 SQL 平铺一屏，文件一多难以定位；用户明确要求分层）。

---

## 一、现状与目标

### 1.1 现状（HistorySqlLogPanel.kt，F-44）

```
工具栏：[刷新] [搜索框]
列表：全部 .sql 文件的所有 SQL 条目平铺（每条 = 耗时 + 时间戳 + 源码 + SQL 摘要）
双击条目 → 预览弹窗
```

- `refresh()` 调 `SqlLogFileReader.readAll(dir)` 把所有文件的条目合并成一个 `List<LogSqlEntry>`；
- 单列表模型、单 renderer、无文件概念——文件越多越难定位，也无法按文件浏览。

### 1.2 目标（用户要求）

```
一级（默认）：文件列表
   行 = 文件名 | 文件大小 | SQL 条数
   双击 → 二级
二级：单个文件的 SQL 列表
   行 = 耗时 + 时间戳 + 源码 + SQL 摘要（沿用现有高亮 renderer）
   双击 → SQL 预览面板（现有 openPreview）
   顶部提供「返回」回到一级
```

### 1.3 非目标

- 不改动 `SqlLogFileReader` 的解析逻辑（保持向后兼容已由 F-44-2 完成）。
- 不增加文件删除/改名等管理操作（本计划仅视图分层）。
- 不改动 F-7 `SqlHistoryPanel`（收藏面板，另一套功能）。

## 二、实现设计

### 2.1 数据结构

新增文件摘要模型（`HistorySqlLogPanel.kt` 内）：

```kotlin
/** 历史 SQL 文件摘要（一级列表数据源）。 */
data class HistoryFileEntry(
    val file: File,
    val sqlCount: Int,
) {
    val displayName: String get() = file.name
    val sizeBytes: Long get() = file.length()
}
```

### 2.2 面板布局（CardLayout）

```
HistorySqlLogPanel (BorderLayout)
├─ NORTH 工具栏（恒定）：
│   [← 返回（仅二级可见）] [刷新] [搜索框]
├─ CENTER cards (CardLayout)：
│   ├─ card-file：文件列表（JBList<HistoryFileEntry> + HistoryFileCellRenderer）
│   └─ card-sql：SQL 列表（SqlEntryList<LogSqlEntry> + HistoryCellRenderer，复用现有关键
│        Ctrl+C 复制纯 SQL 链路）
```

- `showFileList()`：切 card-file，隐藏返回按钮，emptyText 改「暂无历史 SQL 文件」。
- `showFileContent(fe)`：读取该文件条目 → 填 sqlListModel，切 card-sql，显示返回按钮，
  emptyText 改「该文件暂无 SQL 条目」。

### 2.3 事件

| 位置 | 事件 | 动作 |
|------|------|------|
| 一级列表 | 双击 | `showFileContent(selected)` |
| 二级列表 | 双击 | `openPreview(entry)`（现有逻辑不变） |
| 二级列表 | 右键 | 现有菜单（复制 SQL / 跳转源码）——**仅二级可用** |
| 返回按钮 | 单击 | `showFileList()` |
| 刷新按钮 | 单击 | `refresh()` |
| 搜索框 | 实时输入 | 一级按文件名过滤；二级按 SQL/源文件过滤 |

### 2.4 刷新语义

- `refresh()`：
  - 扫描目录 → 生成 `allFiles`（文件名 + 大小 + SQL 条数）；
  - 若当前在二级且 `currentFile.file` 仍存在 → 保持二级，重载该文件条目；
  - 否则 → 回一级（面板首次打开默认即一级文件列表）。
- `SqlLogPanel` tab 切换监听调 `historyPanel.refresh()`——切回历史 tab 时若正在浏览某文件，
  保持二级不打断（仅重载内容）；新打开面板默认一级。

### 2.5 文件大小与条数

- 大小：`file.length()`，格式化 B/KB/MB（<1KB 显示 B；<1MB 显示 KB 保留 1 位小数；否则 MB）。
- 条数：新增 `SqlLogFileReader.countInFile(file)` —— 只数头部行（`-- source:` / `-- 日期`），
  不构建 `LogSqlEntry`，避免大文件列表加载卡顿；与 `parseContent` 的判定逻辑保持一致。

### 2.6 搜索

- 一级：`allFiles.filter { it.displayName.contains(query, ignoreCase = true) }`
- 二级：沿用现有 `applySearch` 逻辑（restoredSql / sourceFile contains）
- 搜索框 emptyText 动态切换：一级「搜索文件名...」/ 二级「搜索 SQL 或源文件...」

### 2.7 新增 bundle 文案

| key | zh | en |
|-----|----|----|
| `log.history.back` | 返回 | Back |
| `log.history.files.empty` | 暂无历史 SQL 文件 | No SQL history files |
| `log.history.entries.empty` | 该文件暂无 SQL 条目 | No SQL entries in this file |
| `log.history.sqlCount` | {0} 条 SQL | {0} SQL |
| `log.history.search.files` | 搜索文件名... | Search file name... |

2. 沙盒运行（若可用）：历史 tab 默认显示文件列表（文件名/大小/条数）；
   双击文件 → SQL 列表；双击 SQL → 预览弹窗；返回按钮回一级；搜索两态过滤正确；
   历史文件存在 3 种格式（F-43 / F-44 / F-44-2）时条数统计正确；
3. 空目录时一级显示「暂无历史 SQL 文件」。

## 五、风险

| 风险 | 缓解 |
|------|------|
| 大文件 `countInFile` 逐行扫描耗时 | 只数头部行不构建对象；行级 IO 由 `useLines` 惰性读取，内存 O(1) |
| CardLayout 切卡时列表滚动位置丢失 | 保留两个独立 JBList 实例，各自滚动状态天然保留 |
| 搜索过滤与视图状态耦合 | 一级/二级各自维护过滤后模型；切卡时按当前数据源重算 |
