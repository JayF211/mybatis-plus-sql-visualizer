# 用户实测两处缺陷修复——语言切换写穿持久化 + 执行 SQL 去弹框直建临时文件（M19）

> 本文档记录 **MyBatis-Plus SQL Visualizer** 的 M19 增量修复：用户实测报告的两个问题——
> ① 设置中界面语言切换**仍无效果**（M16.3 roaming 修复后复测；确定后重开设置还是原样）；
> ② 预览面板点「执行 SQL」弹出的数据源框**没有内容**（要求去掉该弹框，直接创建临时文件，让用户自行选择数据源）。
>
> 当前基线：v1.12（M18.2 已提交，260 测试全绿）。

---

## 1. 问题与根因（2026-08-13，平台源码反编译验证）

### 1.1 语言切换无效果（M16.3 修复未覆盖 apply 门控链路，根因修正）

**用户症状**：设置切 English → 确定 → 再次打开设置仍中文（原样）。

**M16.3 结论回顾**：定位为应用级轻服务 + `PersistentStateComponent` 未禁用 roaming
（`RoamingType.DISABLED`），已按官方规范修复——该修复解决的是**磁盘持久化（重启回滚）**链路；
用户复测仍无效，说明存在另一层根因：**状态写入依赖平台调用 `Configurable.apply()`，而该调用
在 Settings 框架下有门控，可被静默跳过**。

**根因（本次确认，反编译本地 IDEA Ultimate 2026.2.1 `intellij.platform.ide.impl.jar`）**：

`SettingsDialog.doOKAction()` → `applyAndClose(true)` → `SettingsEditor.apply()` →
`ConfigurableEditor.apply()`：

```java
// com.intellij.openapi.options.newEditor.ConfigurableEditor
protected boolean apply() {
    updateIfCurrent(configurable);        // ① 重新轮询 configurable.isModified() → 决定 Apply 按钮启用
    ConfigurationException error = apply(
        myApplyAction.isEnabled() ? configurable : null);   // ② 未启用 → 传 null
    return setError(error);
}
static ConfigurationException apply(Configurable configurable) {
    if (configurable != null) configurable.apply();   // null → 直接跳过，不调用插件 apply()
    ...
}
```

且 Settings 对话框的 OK 动作**只对「当前选中页」的 configurable 调用 apply()**（2021 起 Settings
新 UI 行为，`SettingsEditor.apply()` 仅代理当前页的 `ConfigurableEditor`）。由此产生两个真实失败场景：

1. **改完语言后切换到其他设置页再点确定** → 插件页非当前页 → `apply()` 从未被调用 → 改动静默丢弃；
2. 修改检测（`updateCurrent` 轮询 `isModified()`）未触发 → Apply 按钮未启用 → apply 被门控跳过。

结果：`settings.state.language` 从未写入 → 重开设置自然"还是原样"。
M16.3 的 roaming 修复（磁盘持久化）与 M14.7 的 bundle 修复（`getFallbackLocale` 回退）均不覆盖
「apply 从未被调用」——三处修复共同构成完整链路，本次补齐最后一环。

**修复方向**：语言下拉**写穿式持久化**——`languageCombo` 选中变化时**立即**写入
`settings.state.language`（不依赖 OK→apply 链路），并立即 `rebuild()` 让设置页文案即时切换
（M14.7 既定体验）。值变化守卫防循环；`apply()` 保持幂等（写穿后返回 `languageChanged=false`）。
其余字段维持 OK→apply 语义不变。代价：「取消」无法回退语言选择（可接受——语言为全局偏好，
且原实现依赖 OK 保存同样不可回退）。

### 1.2 数据源弹框无内容（ChooseByNamePopup 空词不显示列表，平台设计行为）

**用户症状**：点「执行 SQL」→ 弹出的数据源选择框**没有内容**；要求**去掉该弹框**，
直接创建临时文件，让用户自行选择数据源。

**根因（本次确认，反编译构建平台 2025.3.5 `lib/app.jar` `gotoByName` 包）**：

`DatabaseConsoleLauncher.chooseDataSource` 多数据源时使用 `ChooseByNamePopup`（GotoClass 同款）。
其核心 `ChooseByNameBase.rebuildList()`：

```java
String trimmedText = getTrimmedText();                    // 打开时搜索框为空 ""
if (!canShowListForEmptyPattern() && trimmedText.isEmpty()) {   // ← 命中
    myListModel.removeAll();      // 清空列表
    hideList();                   // 隐藏列表
    myTextFieldPanel.hideHint();
    myCard.show(myCardContainer, "chkbox");
    return;                       // ← 元素计算根本不执行 → 列表永远为空
}
```

`canShowListForEmptyPattern()` = `isShowListForEmptyPattern() || (打开方式为补全键)`——
插件用 `invoke()` 直接打开、从未调用 `setShowListForEmptyPattern(true)` → **false** →
空搜索词时列表被强制清空隐藏，元素计算不执行。**只有用户输入任意字符后列表才会出现**——
这就是"弹框中没有内容"的确切原因（平台设计行为；GotoClass 空词显示 Recent Files 是因其显式
开启了该开关）。

**修复方向（按用户要求）**：**移除数据源选择弹框**，`execute()` 直接创建临时 `.sql` 文件并打开
编辑器——Ultimate + Database 插件的 SQL 文件编辑器**自带右上角数据源选择器**
（已确认 `com.intellij.database.editor.*` 提供 `.sql` 文件编辑器），用户自行选择数据源后
Ctrl+Enter 执行（IDE 原生行为）。同步删除 `listDataSources / chooseDataSource /
DataSourceByNameModel / DataSourceCellRenderer / JdbcConsole 会话与 attach` 一整套
database 反射面（顺带减少脆弱 API 依赖）。

## 2. 修复方案

| 编号 | 修改点 | 说明 |
|------|--------|------|
| T-M19-01 | `config/PluginSettingsPanel.kt` | ① `init` 中（初值设置后）给 `languageCombo` 注册 `ActionListener`：值守卫（与 `state.language` 不同才动作）→ 写入 `settings.state.language`（写穿）→ `rebuild()` 即时刷新文案；② 抽取 `internal fun selectLanguage(value: String)` 供测试（设置 combo 并触发同一写穿路径）；③ `apply()` 保持幂等（写穿后返回 false，不再重复 rebuild） |
| T-M19-02 | `database/DatabaseConsoleLauncher.kt` | `execute()` 改为：临时文件（`FileUtil.createTempFile("mpsql-exec-", ".sql", true)` + 写 SQL + `LocalFileSystem.refreshAndFindFileByIoFile`）→ `FileEditorManager.openFile(vf, true)` → 提示文案；**删除** `listDataSources / chooseDataSource / displayName / DataSourceByNameModel / DataSourceCellRenderer / createTempConsole`（会话、JdbcConsole、attachConsole 全移除）；保留 `execute(project, sql)` 签名、`runCatching` 兜底与 Community 降级（`ExecuteSqlSupport.isAvailable()` 守卫不变） |
| T-M19-03 | `resources/messages/MpSqlVisualizerBundle.properties` + `_zh.properties` | `execute.done` 改为无参数文案（英文/中文："已创建临时文件，在编辑器右上角选择数据源后按 Ctrl+Enter 执行"）；删除废弃键 `execute.chooseDataSource` |
| T-M19-04 | 测试 | `PluginSettingsPersistenceTest` 新增：① `testLanguageWriteThroughOnSelection`——模拟选中 en 后**不调用 apply()**，断言 `state.language` 已为 en（写穿生效）；② 写穿后 `apply()` 幂等（返回 false）、重复选同值不触发变化。`ExecuteSqlSupportTest` 现有降级测试不变（沙盒无 database jar，launcher 不可加载，维持现状） |
| T-M19-05 | `CHANGELOG.md` | 按项目习惯追加 M19 记录（根因 + 验证） |

## 4. 验收

- `./gradlew clean test` 260 既有 + 新增全绿 + `buildPlugin` 成功；
- 手动清单（真实 IDE Ultimate 2026.2.1）：
  1. 设置切 English → **页面文案即时变英文** → 确定 → 重开设置（英文）→ **重启 IDE**（仍英文）；
  2. 设置切 English 后**先切到其他设置页再点确定** → 重开本插件设置页仍为英文（写穿绕过 apply 门控）；
  3. 预览面板点「执行 SQL」→ **无数据源弹框** → 临时 `mpsql-exec-*.sql` 文件打开（含当前 SQL）→
     编辑器右上角选择数据源 → Ctrl+Enter 执行出结果；
  4. Community（无 database 插件）：点按钮提示升级，不崩溃。
