## 一、背景与依据

238 下载、0 票 0 评论、需求池零真实帖子的现状下，产品与用户的每次接触都珍贵。竞品高频差评集中在「会不会坏」（误报/卡顿/兼容），本插件在工程质量面已防御充分，但「知不知道有好东西」维度零投入。三件套全部复用既有通知与设置惯例，不新增弹窗形态（弹窗克制红线维持）。

## 二、现状核实（实测）

| 面 | 现状 | 位置 |
|---|---|---|
| 通知基建 | 预览组 notificationGroup 已注册（BALLOON） | `plugin.xml` preview 组 |
| 空状态 | 工具窗四 tab 与预览面板空态为纯空白，无引导文案 | SqlLogPanel/SqlPreviewPanel 各空态分支 |

## 三、方案

**T-UX-01（首锚点一次性通知）**：项目内首次检测到可预览锚点（Wrapper 链/XML mapper/注解 SQL 任一）时，经预览组发一次性通知：「检测到可预览的 SQL 代码，选中后按 Alt+Shift+Q 即可查看真实 SQL」。实现约束：探测挂低频入口（项目级服务 + 编辑器打开节流），禁止进 gutter provider O(1) 快速路径；「已展示」状态持久化到既有插件设置（application 级，一次即可）；设置页界面节加开关（默认开）。

**T-UX-02（空状态引导文案）**：工具窗四 tab 与预览面板空态加单行引导（如日志 tab：「打开带 SQL 日志的控制台后自动捕获；也可从下方日志转 SQL 手动粘贴」）。i18n 双语新键走 bundle，parity 守卫同步。纯文案，不加组件层。

**T-UX-03（首次捕获成功指路）**：会话内首次捕获到 SQL 时发通知指路工具窗（带「打开面板」动作）。会话级一次性（companion 记忆），历史非空则跳过，防打扰。

三件共用「一次性/会话级」防打扰语义，通知总数控制在用户全生命期 1~2 条。

## 四、验收标准

1. 新开项目含 Wrapper 链时收到一次 T-UX-01 通知，重开项目不再出现；设置关闭后全程静默。
2. 四 tab 与预览空态文案双语齐备，bundle parity 守卫绿。
3. 首条 SQL 捕获触发一次 T-UX-03，同会话不重复；无头测试（平台通知 API 在测试进程的降级路径）不炸。
4. 全量 testShards 绿，gutter 快速路径性能零变化（不新增探测调用）。

## 五、真机走查清单（留人工）

新装态走一遍三件套触发时机与文案观感；确认通知动作（打开面板/无动作）跳转正确。

## 六、风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 通知打扰 | 引导变骚扰即负体验 | 三件全一次性/会话级 + 设置开关 + 预览组（BALLOON 非模态） |
| 探测误触发性能 | 锚点探测进热路径 | 挂项目级低频服务，与 gutter 快速路径隔离 |
| 空态文案硬编码 | 漏 i18n | parity 守卫 + 双语同轮交付 |

## 七、实施顺序

```
T-UX-01（通知+开关）→ T-UX-02（空态文案）→ T-UX-03（捕获指路）→ 全量门禁 → 真机走查
```
