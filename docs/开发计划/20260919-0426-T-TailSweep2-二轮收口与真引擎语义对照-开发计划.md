## 二、G1 真引擎语义对照测试集（P2，新立）

**目的**：把「真 MyBatis 引擎」的语义背书变成**回归资产**——在测试基建里用真引擎批量生成期望产物钉住自研求值行为，**不进生产渲染路径**（零生产风险）。成本 1~2 人天。

### T-FS-01 对照基建：隔离 classloader + 真引擎驱动

- **零 mybatis 依赖红线**：真引擎类必须从隔离 classloader 经反射驱动（对齐 spike 与 `ui/highlight/DatabaseSchemaResolver.kt:37-40` 的跨 classloader 反射纪律：`Class.forName(name, true, isolated)` + `Method/Constructor` 从声明类取）。
- **首个决策点（须先定）**：mybatis jar 怎么进测试 classpath——(a) 加 `testImplementation("org.mybatis:mybatis:3.5.19")`（显式、可复现、生产依赖图不变）；(b) 从本地缓存路径手工加载 jar（不进依赖图，但需写路径探测、CI 上不稳）。**建议 (a)**，并在计划 §七 记录「红线边界＝仅测试域」。
- 真引擎侧构造：`Configuration` + `XMLMapperBuilder`/`SqlSessionFactoryBuilder` 解析被测 mapper XML → `MappedStatement.getBoundSql(params)` 取 `BoundSql.getSql()`。
- 可复用的探测先例：`log/ProjectTypeDetector.kt:226` 已有 `facade.findClass("org.apache.ibatis.session.SqlSessionFactory", …)` 判定用户项目是否具备真引擎条件（本任务不需要它，但说明「探测真引擎可用性」在本仓有既有形态）。

### T-FS-02 对照协议（绕开 mock 层）

- 自研侧 `XmlSqlRenderer().render(node, bindings, …)` **接受任意 `Map<String, Any?>` bindings**（`xml/XmlSqlRenderer.kt:10-49`），因此可**绕开面板 mock 层**，把同一批**真实值**（`Integer 0`、`List<Integer>`、DTO 实例）分别喂给真引擎与自研渲染器，两套产物直接对照。
- **断言面只覆盖标签语义**：`if` / `choose` / `trim` / `foreach` / `bind` / `${}` / `#{}` 队列顺序。
- **纪律（关键）**：mock 值语义差异（引号、类型、`?` 占位形态等）**登记为「已知差异清单」而非失败**——否则对照集会被 mock 差异淹没，失去判别力。

### T-FS-03 场景集与产出

- 场景来源：评估报告 §1.2 的 **15 条缺陷账逐条反推**，重点是标签语义那 3 条——#1 官方 DOCTYPE 解析（`d5dcd55`）、#2 OGNL 静态字段 `@class@field`（`18fadbe`）、#3 判真与 or/and 语义 + `||X||` 剥壳（`0e2eb2c`，注意此条是**我方超集**：真引擎对 `||X||` 抛 `ExpressionSyntaxException`，对照时按「已知差异」登记而非失败）。
- 叠加未修缺口场景：`foreach` 体内 `if` 求值失败（与 T-FS-07 呼应）。
- 产出：①对照测试类（**放哪个桶须先验**：真引擎驱动是纯 JVM 操作，理论上可进 `testFast` 快桶，但 mybatis jar 在 testFast 的 classpath 可达性需实测；不达标则留平台桶）；②`docs/` 下一份「自研 vs 真引擎 已知差异清单」（含每条差异的成因与是否可修）。
- **不覆盖**：`${ew.customSqlSegment}`（需 wrapper 对象，非引擎能力）、MCP 出口链、性能面、面板回填链。

## 三、G2 代码侧遗留收口

### T-FS-04 4 处 Wrapper 模型穿参（P3，**唯一带功能影响项**）

- 现状：`converter/MpjLambdaConverter.kt:490/874/928`、`converter/WrapperConverter.kt:167` 的兜底路径仍按 `openProjects.firstOrNull()` 取项目级表配置 → 多项目同开且项目级配置不同时**产出错误表名**。
- 修法二选一，**先做方案评估再动手**：
  - (a) 把 `project` 穿进 `WrapperCall`/`WrapperChain`（`model/` 侧），需改 SPI `WrapperConverter.convert(chain, table)` 签名 → 11 个实现 + `ConverterRegistry` 连带；
  - (b) 给模型加平台字段（会破 `model/` 包「零 `com.intellij` 依赖」的边界，需评估是否可接受）。
- 若评估结论是成本仍超批，**必须留档说明**（不许默默搁置）。

### T-FS-05 结果区「过闸」补测试断言（P3）

- 现状：`log/SqlToJavaPanel.kt` 的 `setResultText` 已过 `DocWriteContext.runWriteSafe`，但**只有源码扫描守卫兜底**，无运行期断言。
- 做法：复用 `execute/ExecDocSyncTest` 的 `deferredCount` / `writeAllowedProbe` 形态，钉住「写不安全时转投递、写安全时就地写」。

### T-FS-06 守卫两缺口（P3/P4）

- **双规则盲区**：`invokeLater(ModalityState.any()) { … }`（实参 + 尾随 lambda）两条规则都不覆盖（尾随规则要求 `invokeLater` 后紧跟 `{`，`any()` 规则只扫括号实参区）。做法：扩 `any()` 规则到尾随 lambda 体，或新增合并规则；**先红后绿**（构造该形态的写文档站点证明会红）。当前仓内 0 处，属预防性。
- **配平过报**：花括号配平跑在未剥注释文本上，字符串/注释里不成对 `{` 会过报（`}` 则漏报）。做法：配平前先剥注释（复用同文件既有 `stripComments`，注意保行）。

### T-FS-07 `foreach` 体内 `if` 求值失败不产 errors（P3，方案 B 的尾款）

- 现状：`xml/PrefixedContext`/`FilteredContext` 各自持有 `DynamicContext.errors` 且**未转发**，故 `<foreach>` 内的 `<if test="非法表达式">` 失败后 `errors=[]`（实证：T-ExprAstPrecheck 计划 §八）。`${}`/`bind`/顶层 `if` 的失败都已记 errors 走 `⚠` 警示行，形态健康——**只有这一处静默**。
- 做法（计划原文给的方向）：`DynamicContext.errors` 转 `open` + 两个子上下文按既有 `bindings`/`staticFieldValues` 同款委托覆写，**约 5 行**；**代价**=逐迭代重复同一错误行 → 需去重（同一表达式同一原因只记一次）。
- 自证：构造 `<foreach>` 内非法 `if test` → 断言 `errors` 非空且去重后仅一行；再断言开关覆盖路径不受影响。

### T-FS-08 开启态清空文本框后 `isModified` 恒报已修改（P4）

- 现状（G7 遗留，既有不一致）：开启态把某文本框清空后 apply，控件显示空串而 state 推导值为全局值 → `isModified()` 持续报已修改（修复前同形）。
- 做法：先定语义（「清空=跟随全局」还是「清空=显式空值」），再让 `isModified`/`apply`/回灌三处同源；若判定为可接受边界，则补 KDoc + 用例钉住。

### T-FS-09 G7 P3 的 `navigateTo` 高亮弱项（P3，先核实再定）

- 现状：设置搜索能命中项目页条目（headless 已验），但项目页走 DSL v2（`row(label)` 生成普通 `JLabel`），**方言/推断下拉与 4 个文本框大概率不高亮**。
- 做法：先核实平台 `focusTarget` 的匹配机制能否覆盖 DSL v2 生成的组件；能低成本修则修（例如给控件挂可被匹配的文本/tooltip），否则在设置页 KDoc 与验收文档记录边界（**不留「看起来能跳但不亮」的隐性缺陷**）。

### T-FS-10 PSI 路径 auto 推断不生效（P4，**决策点，默认不做**）

- 现状：`DialectRegistry.effective(project=null)` 落回手动值，psi 侧 14 处 `currentDialect()` 均为无参调用 → auto 推断在 PSI 路径永不生效（与合流前行为一致，无回归；KDoc 已记为有意边界 + 用例钉住）。
- **建议保持现状**（写集大、收益低：PSI 路径只影响补全/高亮的方言判定）。若要做，需把 `project` 传进 14 处调用点并回归 psi 全链。本计划**默认不做**，仅在 §七 留决策记录。
