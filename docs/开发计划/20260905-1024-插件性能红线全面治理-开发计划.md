# 插件性能红线全面治理 开发计划

> 红线：性能问题一律视为插件红线——禁止卡死、禁止拖慢 IDEA、禁止弹出插件报错信息。
> 审查方式：五个子智能体并行审查（EDT 线程纪律 / PSI 解析与重复计算 / UI 渲染 / 内存泄漏与并发 / 报错弹窗与阻塞 IO），覆盖 src/main 全部 236 个源文件，逐处人工读上下文，全部问题带精确行号证据。
> 里程碑：M54，任务号 T-Perf-01 ~ T-Perf-24。
> 分支：`perf/redline-hardening`（git worktree 独立目录，并行会话隔离）。
> 行号说明：以下行号为 2026-09-05 工作区快照（master f724fbf）的行号，实施时以符号定位为准。

## 审查结论总览

五个维度共报告 45 项问题，去重合并后收敛为 24 个治理任务：P0 级 6 项（必现卡死或必现报错）、P1 级 15 项（大数据量或特定场景触发）、P2 级若干打包处理。

| 维度 | P0 | P1 | P2 | 结论摘要 |
|------|----|----|----|----------|
| 报错弹窗与阻塞 IO | 2 | 6 | 6 | 主链执行失败弹模态框；历史 100MB 文件 EDT 全量读；自动保存逐条 flush 在控制台热路径 |
| PSI 解析与重复计算 | 1 | 4 | 8 | CustomDaoHql gutter 在 daemon 热路径上做类型 resolve + 正则；四类缓存持 PsiFile 强引用且清理函数是死代码 |
| UI/Swing 渲染 | 2 | 4 | 7 | 日志列表每条 SQL 触发全量重建；参数输入每击键全文重生成+重格式化+重分词 |
| EDT 线程纪律 | 0 | 5 | 4 | PSI 创建/解析在 EDT 裸调残留点；数据源 schema 全量遍历无缓存；EDT write action 内跑格式化器 |
| 内存泄漏与并发 | 0 | 6 | 6 | Buffer 无锁读 ArrayDeque 会 CME 弹错；面板监听器只加不减；dedupeCounts 无上限 |

正面结论（不需要动的部分）：全项目 `LOG.error` 为 0（红色 IDE 气泡已系统规避）；无 `invokeAndWait`、无 EDT 上 `Future.get` 死等、无 `Task.Modal`；网络出口仅 update 检查一处且全后台、走 IDE 代理、启动路径静默失败；无直接 JDBC（SQL 执行全部委托原生 Database 插件）；messageBus 连接均绑定 Disposable；ParamHistoryCache/SqlPerfAnalyzer/JoinFkRegistry 等缓存均有界有回收。

- 验收：执行失败（拔掉数据库/停用数据源）时无任何模态框与 balloon，面板内可见错误与详情。

### T-Perf-02 CustomDaoHql gutter 消除 daemon 热路径 resolve

- 问题：`ui/gutter/CustomDaoHqlGutterLineMarkerProvider.kt:55` 对每个方法名 identifier 无预筛直接调 `locate`；`psi/jpa/CustomDaoHqlLocator.kt:228-231` 判定顺序是先跑 4 条 HQL 正则再查 O(1) 的 DAO qualifier 名；`psi/PreviewReceiverResolver.kt:47` 的 `classify` 用 `qualifier.type` 触发引用 resolve。daemon 每趟对项目内每个方法调用执行一遍。
- 修复：调用 locate 前加纯文本预筛（referenceName/qualifier 名启发）；判定顺序反转为 qualifier 名 → 方法名 → 最后才 HQL 内容匹配；`classify` 仅在名字启发失败后才碰 `qualifier.type` 并按 per-file modificationStamp 缓存。
- 验收：在含大量方法调用的大文件编辑，daemon 高亮延迟不随本 provider 增长；CustomDaoHql 图标覆盖率不回退（跑既有 gutter 测试）。

### T-Perf-03 日志列表流式刷新风暴治理

- 问题：`log/SqlLogEntryBuffer.kt:54-71` 每入队一条 SQL 即 `notifyChanged`（去重丢弃也触发）；`log/SqlLogManager.kt:269-274, 288-291` 每次变更一个 `invokeLater` 无合并；`log/SqlLogPanel.kt:744-796` `refreshList` 每次全量 snapshot、对每条跑 2 个正则、`snapshot.forEach { it.cachedListHtml = null }` 全量清 HTML 缓存后 clear+重建。流式场景每条 SQL = 一次 O(N) 重建 + 缓存全失效，会话代价 O(N²)。另外 773-787 的异步追加链无代际守卫，新 refresh 的 clear 不会取消旧链，旧快照剩余条目继续追加造成幽灵/重复条目。
- 修复：`notifyUi` 改置脏 + 单个幂等 Alarm flush；HTML 缓存只对新增/变更条目失效；条目增量 append 替代 clear+重建；追加链加 generation 守卫。
- 验收：捕捉开启后灌入 200 条 SQL，EDT 无冻结告警；流式追加期间滚动流畅；快速切换过滤条件后列表内容无重复/缺行。

### T-Perf-04 参数输入击键路径防抖与算法降阶

- 问题：`ui/SqlPreviewPanel.kt:1856-1860, 1696-1700` 每击键一次 `renderSql`，`1757-1772` foreach 输入框每击键两次；`1182-1198` 默认设置下每击键全量 `SqlFormatter.format` + `doc.setText` 触发全文重分词；`2065-2082` `detectInClauseParams` 对每个 `?` 复制并大写化整个前缀（O(L×P)）；`xml/Ognl.kt:75, 95` 每次求值重新 parse，无表达式缓存。
- 修复：`renderSql` 加 100-200ms 防抖（复用 500ms historyAlarm 的 Swing Timer 模式）；`detectInClauseParams` 改单趟 O(N) 扫描记录最近 `IN (` 位置；Ognl 增加 `ConcurrentHashMap<String, OgnlExpr>` 表达式解析缓存。
- 验收：50KB 动态 SQL + 多参数场景逐键输入无可感知延迟（<50ms/键）；预览结果与逐键全量计算一致。

### T-Perf-05 历史 SQL 文件读取后台化

- 问题：`log/HistorySqlLogPanel.kt:185-204` `refresh()` 在 EDT 对目录内每个 `.sql` 文件逐行全量扫描计数，`173-179` `showFileContent` 用 `file.readText()` 整读；自动保存单文件滚动阈值 100MB（`log/SqlLogAutoSaver.kt:31`），长期开启必然长出大文件。切到历史 tab 即冻结（`log/SqlLogPanel.kt:307-315`）。同时 `HistorySqlLogPanel.kt:420-457` 渲染器无 HTML 缓存，滚动每可见行重跑词法高亮 + BasicHTML。
- 修复：refresh/showFileContent 移入 `Task.Backgroundable` + 进度；countInFile 结果按 lastModified 缓存；渲染器照抄 SqlLogPanel 的 cachedListHtml 方案；搜索输入加防抖（`233-245` 每击键全量 clear+add）。
- 验收：目录含 100MB 单文件时打开历史 tab EDT 冻结 < 500ms；滚动不再持续高 CPU。

### T-Perf-06 SqlLogEntryBuffer 并发竞争修复（CME 弹错风险）

- 问题：`log/SqlLogEntryBuffer.kt:122-125` `isDuplicate` 在 `synchronized(entries)` 之外无锁遍历 ArrayDeque，而 `54-57` 在进锁前调用它；控制台出线程写、EDT 清空/删除（`131-135, 149-151`）并发修改同一非线程安全 ArrayDeque → `ConcurrentModificationException` 经 `LogFilterProxyHandler`（无 catch）上浮为 IDE 红色报错弹窗。
