# F-42 JOIN 图渲染失败修复 — 开发计划

> **创建日期**：2026-08-25
> **状态**：✅ 已完成（commit abd8c49 + cc80d0e 后补三层根因修复，2484 测试全绿）
> **优先级**：高

## 问题描述

JOIN 关系图（PlantUML 渲染）在 IDE 中无法正常显示，标签页持续显示"关系图渲染中..."（进度条动画），或最终只显示一段 SVG XML 源码文本 / Graphviz 错误图，而不是实际图像。

沙盒 IDE (2024.3.7.1 + `--add-opens`) 与主 IDE (2026.2.1) 均失败（失败点不同）。

---

## 最终修复结论（三层根因，2026-08-25 沙盒实证）

### 根因 A（最终）：模态弹窗阻塞 invokeLater 回调 —— UI 永远卡"渲染中"

**现象**：渲染在后台线程 0.4s 完成，但 `Application.invokeLater { onDone }` 延迟 40 秒才执行（日志实证 22:27:45 渲染完成 → 22:28:15 回调）。

**根因**：SQL 预览弹窗 `SqlPreviewDialog` 是模态弹窗（`DialogWrapper(project, true)`）。默认 `invokeLater` 在 `ModalityState.defaultModalityState()` 下执行，模态弹窗打开期间回调被推迟到弹窗关闭。

**修复**：`DiagramRenderTask.run()` 两个 `invokeLater` 均改 `invokeLater(runnable, ModalityState.any())`。

### 根因 B：skinparam linetype ortho 依赖 Graphviz —— 渲染出错误图

**现象**：回调修复后能看到内容，但显示 `Dot Executable: null / Cannot find Graphviz` 错误图（用户环境实证，图 274x237 / 6467 字节）。

**根因**：`skinparam linetype ortho` 正交线型强制使用 Graphviz dot 引擎；无 Graphviz 时 PlantUML 输出错误图。

**修复**：`JoinDiagramGenerator` 移除 `linetype ortho`（保留 `hide circle`），默认线型走 Smetana 纯 Java 引擎。验证：渲染 274x243 正常图（5359 字节）。

### 根因 C：渲染完成时组件 hidden —— swapContent 不生效

**现象**：渲染完成时"JOIN 图"标签页未被选中，`DiagramPanel` 处于 hidden，`swapContent`/`revalidate` 对 hidden 组件无效。

**修复**：`JTabbedPane` 注册 `ChangeListener`，切到"JOIN 图"标签页时调用 `DiagramPanel.refreshAfterVisible()` 强制重渲染。

### 根因 D（前期已修复）：PNG 模块限制 + JavaFX 缺失

见下方"已解决：前 8 个根因"，Batik 栅格化方案落地（commit cc80d0e）。

## 已解决：前 8 个根因（commit abd8c49 已落地）

### 问题 1：IllegalAccessError 未捕获（已修复，`catch(e: Throwable)`）

`DiagramRenderTask.run()` 原用 `catch (e: Exception)`，无法捕获 `IllegalAccessError`（`Error` 非 `Exception` 子类）。异常直接传播 → `onDone` 永不执行 → UI 卡在"渲染中"。

### 问题 2：PNG 渲染失败无降级（已修复，`renderWithFallback()`）

主 IDE 的 JVM 无 `--add-opens java.desktop/com.sun.imageio.plugins.png`（该参数只存在于 `runIde` 沙盒配置，插件无法给主 IDE 加 JVM 参数）。已用 javap 实证：`PlantUML PngIO` 经 `javax.imageio.ImageIO.write(...,"png",...)` 写 PNG，内部加载 `com.sun.imageio.plugins.png.PNGMetadata`；JDK 17+ 强封装下必抛 `IllegalAccessError` → 主 IDE 中 **PNG 必定失败**。

`renderWithFallback()` 捕获 `IllegalAccessError` → 自动降级 SVG。SVG 为纯文本渲染，无 imageio 依赖，任何环境都成功。

### 问题 3：indicator.fraction 在 indeterminate 进度条上设值（已修复残留警告，见"附带修复 2"）

### 问题 4：taskId/期龄检查导致回调丢失（已修复，移除期龄检查）

`DiagramPanel` 被反复 `dispose()` 后 `currentSource/taskId` 被置 null，回调中 `currentSource != plantUmlText` 恒为 true → `applyZoom()` 从不执行。修复：回调直接处理结果（有字节就显示，无字节就报错）。

### 问题 5：`!theme plain` 指令 PlantUML 8059 不支持（已修复，移除指令）

静默渲染出 105x61 错误图（此前 `applyZoom: image=105x59` 的判错信号）。已从 `JoinDiagramGenerator` 移除，保留 `hide circle` + `skinparam linetype ortho`。

### 问题 6：无动态条件时 previewModel=null（已修复，始终创建 SqlPreviewModel）

### 问题 7：swapContent 未维护 currentCenter（已修复）

`init` 直接 `add(placeholderLabel, BorderLayout.CENTER)` 未记录 `currentCenter` → 后续 `swapContent(scrollPane)` 不去除旧组件，placeholder 遮挡图像。已改为用 `swapContent()` 初始化。

### 问题 8：EDT read access 等其它（M46 已修复，不赘述）

## 真实失败原因（主 IDE 日志实证，2026-08-25 13:14）

**当前仍失败的根因：SVG 显示依赖 JavaFX `WebView`，而 IntelliJ IDEA 不捆绑 JavaFX。**

主 IDE（2026.2.1）实际执行链路（`%APPDATA%/JetBrains/IntelliJIdea2026.2/log/idea.log`，含发布版 [DIAG] 调试输出）：

```
13:12:56 [DIAG] run: format=PNG, textLen=399
13:12:56 [DIAG] render succeeded, bytes=2347          ← PNG 抛 IllegalAccessError 被静默吞掉，降级 SVG 成功（2347 字节）
13:14:09 [DIAG] invokeLater: calling onDone           ← 渲染完成到 onDone 执行间隔 132 秒（EDT 排队，见"待观察"）
13:14:09 [DIAG-PANEL] callback: bytes=2347, error=null  ← 期龄检查移除后回调正常执行
13:14:09 [DIAG-PANEL] applyZoom: bytes=2347, isSvg=true
13:14:09 [DIAG-PANEL] applyZoom: detected SVG, calling showSvgWithWebView
13:14:09 STDERR java.lang.ClassNotFoundException: javafx.embed.swing.JFXPanel
         at DiagramPanel.showSvgWithWebView(DiagramPanel.kt:297)
         at DiagramPanel.applyZoom(DiagramPanel.kt:259)
         at DiagramPanel.renderAsync$lambda$0(DiagramPanel.kt:212)
         at DiagramRenderTask.run$lambda$0(DiagramRenderTask.kt:46)
```

失败点：`showSvgWithWebView()` 里 `Class.forName("javafx.embed.swing.JFXPanel")` 抛 `ClassNotFoundException` —— **IDEA 2026.2 运行时不含 JavaFX 模块**，反射打开任何 JavaFX 类都必然失败。异常被 `catch (e: Exception)` 捕获 → `showSvgTextFallback()` → 面板显示一坨 SVG XML 源码文本。用户看到"不是图"，体验等同失败。

与旧计划的差异：问题 3（"SVG 无法预览 → 反射 JavaFX WebView"）当初的修复方向本身在 IDE 里行不通——JavaFX 是 Swing 时代各 JetBrains 产品引入过的可选依赖，2020+ 各 IDE 早已不再捆绑（Plugin Verifier 也拦）。所以"SVG 显示链路"是尚未真正解决的根因。

## 修复方案

### 方案 A（推荐）：Apache Batik 栅格化 SVG → BufferedImage，删除 JavaFX 依赖

引入 `org.apache.xmlgraphics:batik-transcoder`（implementation，随插件打包进 `lib/`），自定义 `ImageTranscoder` 子类把 SVG 栅格化为 `BufferedImage`，完全复用现有 `ImageIcon` + 缩放/滚轮路径：

```kotlin
// SvgRasterizer.kt（新增）
object SvgRasterizer {
    fun rasterize(svgBytes: ByteArray): BufferedImage {
        val reader = new XMLResourceDescriptor().getXMLParserClassName()  // 实现时以 jar 反编译为准
        val transcoder = object : ImageTranscoder() {
            var image: BufferedImage? = null
            override fun createImage(w: Int, h: Int): BufferedImage =
                BufferedImage(w, h, BufferedImage.TYPE_INT_ARGB)
            override fun writeImage(img: BufferedImage, output: TranscoderOutput) {
                image = img
            }
        }
        transcoder.transcode(TranscoderInput(ByteArrayInputStream(svgBytes)), null)
        return transcoder.image ?: throw RuntimeException("SVG rasterize produced no image")
    }
}
```

- 纯 Java、全平台一致：沙盒、主 IDE、无头测试同一行为，不依赖 IDE 捆绑模块
- 导出 PNG 同步修复：Batík `PNGTranscoder` 用自身 PNG 编码器（`org.apache.batik.ext.awt.image.codec.png`），不经 `javax.imageio`，主 IDE 导出 PNG 不再撞 `IllegalAccessError`
- 移除 `showSvgWithWebView()`/`showSvgTextFallback()` 及 JavaFX 反射代码
- 体积：Batik 全树约 6-8MB（batik-core/bridge/codec/dom/… + xmlgraphics-commons），与现有 jsqlparser/plantuml 同策略打 `lib/`，可接受

### 方案 B（备选，不推荐）：JCEF `JBCefBrowser` 加载 SVG 文件

IDEA 捆绑 JCEF（`plugins/jcef-plugin`，本机 2026.2 实证存在），`com.intellij.ui.jcef.JBCefBrowser` 是公共 API，可直接 `loadUrl(file://…)` 渲染 SVG。但 JCEF 是可选平台模块，远程开发/瘦客户端可能不可用，且 Chromium 组件开销远大于一张小图，`sinceBuild` 兼容性校验更复杂。仅当 Batik 体积不可接受时才考虑。

### 方案 C（放弃）：保留 PNG 为主渲染

主 IDE 无 `--add-opens`，PNG 必定 `IllegalAccessError`（javap 实证），此路在主 IDE 不通。

### 渲染策略结论

保留"PNG 优先（沙盒 `--add-opens` 可用即 PNG）→ 失败降级 SVG（Batík 栅格化显示）"。`DiagramRenderTask.renderWithFallback()` 与 `--add-opens` 配置不动。

## 附带修复（同批处理）

1. **导出 PNG 内容错乱**：`exportDiagram(FileFormat.PNG)` 走 `currentBytes!!`——主 IDE 常态下缓存的是 SVG 字节，会写出"SVG 内容 + .png 后缀"的损坏文件。需按字节格式判断：SVG 则 `PNGTranscoder` 栅格化重编码后导出。
2. **indeterminate 进度条 `indicator.fraction` 残余**：`DiagramRenderTask.kt` 第 34/41 行仍有 `fraction = 0.0/1.0`，主 IDE 日志实证每次渲染打 WARN（"indeterminate … call setIndeterminate(false)"）。移除这两行（或该任务用可取消 indeterminate 显示即可）。
3. **`renderAsync` 注释声称"10 秒超时"但无实现**：`DiagramRenderTask` 没有超时机制，注释与代码不符。落实超时（`CancellableTask` + `TimeoutFuture`）或删除注释，二选一，避免误导。
4. **`dispose()` 里 `Disposer.dispose(this)` 自处置**：`DiagramPanel` 自身是 `Disposable`，`dispose()` 中再调 `Disposer.dispose(this)` 语义可疑（既是叶节点又被父组件注册），事件 storm 排查时顺带确认（M46 冻结相关，本计划不展开）。
