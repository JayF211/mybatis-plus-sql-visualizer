## 二、逐项修法

### P13 提示链路口径（采纳 ①；**剪贴板预填已被用户否决**）

**现状链路**：`SqlPreviewPanel.importParamsFromClipboard()`（`:3413-3420`）→ `ParamImportDialog(proj, preFill)` → `doOKAction()`（`ParamImportDialog.kt:189-194`）末句 `if (text.isNotBlank()) onConfirm(text)` → 空内容 return → `importParams(emptyMap())` 从未调用 → `showEmptyClipboardHint()` 从未执行。

**改法（仅一处，对话框侧，不动 `SqlPreviewPanel.kt`）**：
- `doOKAction()`：去掉 `isNotBlank` 守卫（其自带注释「避免空串走解析浪费」是性能微优化，与 T-Perf-20「空剪贴板给行内警示」的产品口径相互矛盾），空提交也回调 → `ParamImportParser.parse("")` 得空 map → `importParams(emptyMap())` → 触发「未识别到有效参数」行内提示 + 「复制错误信息」按钮。

**⛔ 已否决：入口自动预填剪贴板（原 ①c）**。用户 2026-09-20 明确否决，原话：「不要主动获取用户剪切板信息填充 **可能用户并不想填充**」——主动读剪贴板属越权行为，用户可能并不想把自己的剪贴板内容灌进这个输入框。**本项一律不得引入剪贴板读取**（`CopyPasteManager` / `ClipboardManager` 都不用）。
**连带影响**：原 ①c 兼带的「入口名 `importParamsFromClipboard` 名实不符」问题**本轮不处理**——改名会牵动别的调用点，属独立事项，只在报告里记一笔。
**保留不动**：已有参数时对话框预填当前参数 JSON（`serializeParamsToJson`）——那是本面板自己的数据，与剪贴板无关。

### 横幅文案（采纳 (b)）

`panel.banner.degradedPsi` 中英两处，把「IDE 索引完成后重新打开预览即可恢复完整支持」改为与同级 `degradedPlain` 一致的「关闭并重新打开预览即可恢复完整支持」（英文同理）。理由：预览链路无任何 DumbService 判据，走查实测真正生效的解法就是关掉重开。

### N1 写安全（采纳路线 B）

`SqlPreviewPanel.kt:523-524` 的 dispatcher 由 `invokeLater(runnable, ModalityState.any())` 改为写安全模态（`ModalityState.defaultModalityState()`）。依据：`PrewarmAwait` 由 `11e2671` 引入时选 `any()` 的理由仅为「派发不被模态挡住、EDT 零阻塞」，**无「必须在模态期间装配」的场景**；而写安全模态在模态挂起时会推迟派发，此时面板本就在模态框后面（用户看不见），观感代价接近零。
**边界**：`any()` 在控制台挂载/回填链路（M36.5 那几个提交）另有用途，**本项只动 `PrewarmAwait` 的 dispatcher 这一处**。
**护栏**：`BannedApiSourceScanTest` 的写安全规则是词法的，看不到「回调间接调用里的写」→ 补一条**运行期断言**（测试里走一次回调装配，断言无 `Write-unsafe context!`；平台在测试模式会把该告警升格为失败）。

### N2 临时文件冲突（采纳路线 A）

1. **先复现确认**：连续预览 ≥3 次 + 主动选 Load File System Changes，确认「编辑区只剩占位文案」是否由冲突重载导致（若成立，本项优先级从观感升到功能）；
2. 临时文件名由固定 `mpsql-preview.sql` 改为**每次预热唯一**（如带序号/时间戳后缀）；
3. **补清理**：现逻辑只删 `previewTempFile` 一个，改名后必须保证 `preview/` 目录不随预览次数增长（保留上限或复用同一文件池，二选一，实施时给出选择理由）。

### 集成与真机验收结果（2026-09-20）

- **集成门禁**（五车道全合入后）：`testShards` **482 类 / 5461 例 / 0 失败 / 0 错误 / 6 跳过**（合流前基线 479/5450/6）；`:sql-visualizer-agent:test` 14 类 / 65 例 / 0 失败。C 与 D 同改 `SqlPreviewPanel.kt` 但 hunk 相距远，**合并零冲突**。
- **补的守卫**：`i18n/DegradedBannerWordingGuardTest` 3 例（负向「横幅不得把等索引写成恢复条件」+ 正向「必须写出关掉重开这条出路」+ 扫描自检），变异实验：改回旧文案 → 负向规则转红并指名 offending 键值。
- **真机验收（集成提交 `423560b`，记录见走查记录第七节）**：
  - ✅ **P13 提示态真机通过**——留空点确定即出现红字「未识别到有效参数」+「复制错误信息」按钮（首轮走查没出现的那条），悬停保留基线、重复提交幂等、换语句复位、按钮实复制内容正确。
  - ✅ **N2 命名/回收真机通过**——每次打开只新建 1 个唯一名文件、**关闭后目录回到空**；编辑区是真 SQL。
  - ✅ **N2 方言映射真机通过**（单测覆盖不到的那条）——`Push all on [SqlDialectPusher…]` 全程**仅 1 组**（改前每次一组），`sqldialects.xml` **只有一条且指向目录** `<file url="….idea/sql-visualizer/preview" dialect="MySQL" />`。
  - ⚠️ **横幅文案**：首开文案**逐字正确**；但「重开无横幅」未达成（重开仍降级）。
  - ⚠️ **N1 与 N2 的冲突链未验成**：全日志 `Write-unsafe` = 0、`MemoryDiskConflictResolver` = 0，**但这两个 0 都不构成证据**——它们依赖**主路径**对临时文件文档 `setText`，而本轮 **23 次打开 100% 走降级**，那次写从未被触发。
  - ⚠️ **N1 的模态挂起期装配不可观察**（试过 23 轮、预置下一临时文件名、负载 65%→39%）。
- **结论**：**四条修法本身全部落地并有单测/变异实验支撑，但 N1 与 N2 的冲突链在真机上未获证实**——共同拦路石是 `PREWARM_WAIT_MS = 60ms` 在本机覆盖不了预热耗时（23/23 降级，与实测报告 0/7 一致）。**建议把「补预热耗时打点 + 空闲机取 10+ 样本 + 定预算」立为下一步独立事项**：它同时是首开观感与 N1/N2 真机可验证性的共同前提。
- **真机验收顺带发现两条既有缺陷**（非本轮引入）：**N3** `ParamImportDialog` 在 Disposer 树泄漏（优雅退出时平台记 SEVERE，blame 08-20/21）；**N4** 在「更多」popup 内直接弹模态触发平台 SEVERE `Showing dialogs in PopupStep.onChosen`，真机后果是**第一次点确定被吞**（需先聚焦对话框窗口）。
