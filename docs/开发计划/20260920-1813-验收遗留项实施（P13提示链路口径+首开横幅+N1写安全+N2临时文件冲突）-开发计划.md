## 二、逐项修法

### P13 提示链路口径（采纳 ①c）

**现状链路**：`SqlPreviewPanel.importParamsFromClipboard()`（`:3413-3420`）→ `ParamImportDialog(proj, preFill)` → `doOKAction()`（`ParamImportDialog.kt:189-194`）末句 `if (text.isNotBlank()) onConfirm(text)` → 空内容 return → `importParams(emptyMap())` 从未调用 → `showEmptyClipboardHint()` 从未执行。

**改法**（两处，均在对话框侧，**尽量不动 `SqlPreviewPanel.kt`**）：
1. `ParamImportDialog`：无预填时（`preFill` 为空）从剪贴板取文本作为初始内容——入口名 `importParamsFromClipboard` 与菜单项「导入参数」都承诺「导入」，当前却要求用户自己粘贴，名实不符；
2. `doOKAction()`：去掉 `isNotBlank` 守卫（其自带注释「避免空串走解析浪费」是性能微优化，与 T-Perf-20「空剪贴板给行内警示」的产品口径相互矛盾），空提交也回调 → 解析得空 map → 触发「未识别到有效参数」行内提示 + 「复制错误信息」按钮。

**注意**：已有参数时对话框会预填当前参数 JSON（`serializeParamsToJson`），**剪贴板预填只在预填为空时生效**，不得覆盖参数回显。

### 横幅文案（采纳 (b)）

`panel.banner.degradedPsi` 中英两处，把「IDE 索引完成后重新打开预览即可恢复完整支持」改为与同级 `degradedPlain` 一致的「关闭并重新打开预览即可恢复完整支持」（英文同理）。理由：预览链路无任何 DumbService 判据，走查实测真正生效的解法就是关掉重开。

### N1 写安全（采纳路线 B）

`SqlPreviewPanel.kt:523-524` 的 dispatcher 由 `invokeLater(runnable, ModalityState.any())` 改为写安全模态（`ModalityState.defaultModalityState()`）。依据：`PrewarmAwait` 由 `11e2671` 引入时选 `any()` 的理由仅为「派发不被模态挡住、EDT 零阻塞」，**无「必须在模态期间装配」的场景**；而写安全模态在模态挂起时会推迟派发，此时面板本就在模态框后面（用户看不见），观感代价接近零。
**边界**：`any()` 在控制台挂载/回填链路（M36.5 那几个提交）另有用途，**本项只动 `PrewarmAwait` 的 dispatcher 这一处**。
**护栏**：`BannedApiSourceScanTest` 的写安全规则是词法的，看不到「回调间接调用里的写」→ 补一条**运行期断言**（测试里走一次回调装配，断言无 `Write-unsafe context!`；平台在测试模式会把该告警升格为失败）。

### N2 临时文件冲突（采纳路线 A）

1. **先复现确认**：连续预览 ≥3 次 + 主动选 Load File System Changes，确认「编辑区只剩占位文案」是否由冲突重载导致（若成立，本项优先级从观感升到功能）；
2. 临时文件名由固定 `mpsql-preview.sql` 改为**每次预热唯一**（如带序号/时间戳后缀）；
3. **补清理**：现逻辑只删 `previewTempFile` 一个，改名后必须保证 `preview/` 目录不随预览次数增长（保留上限或复用同一文件池，二选一，实施时给出选择理由）。

**同文件不同 hunk 的处理**：C（`:523` 附近）与 D（`:680` 附近）都改 `SqlPreviewPanel.kt`，但 hunk 相距远，各自分支改完后由主智能体合并；**合并后必须复跑全量门禁**，不得以「各自绿」代替集成绿。
**并行纪律**：各车道开工前 `python C:\Users\USER\.zcode\cli\parallel_tasks.py check` → 用**自己工作树的 build 目录**作 sandbox 登记 → 收工 `done --name <任务名>`；不得 kill 不属于自己的进程（判活查进程命令行，不看登记表的 `expected_end`）。
