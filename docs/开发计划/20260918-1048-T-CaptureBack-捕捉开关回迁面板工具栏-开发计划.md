# T-CaptureBack 捕捉开关回迁面板工具栏 — 开发计划

- 日期：2026-09-18 10:48
- 任务编号：T-CaptureBack（T-UiNative T-UN-11 形态回调，P1）
- 来源：用户真机反馈——SQL 日志面板「捕捉」按钮不见了；第二轮截图实证按钮悬停后出现在工具窗标题栏右上角，用户预期其常驻面板内工具栏
- 性质：不是按钮丢失缺陷，是 T-UN-11 形态变更与新 UI 渲染行为叠加造成的可用性回归

---

## 一、现象与归因（2026-09-18 实测）

用户两轮截图（IDE 2024.3 新 UI，深色主题）：

1. 第一张：SQL 日志面板工具栏行只剩清空/设置/搜索/帮助四钮，标题栏右侧空白，空态文案仍写着「点击『捕捉』后开始监听控制台」——按文案找按钮找不到。
2. 第二张：鼠标悬停工具窗后，标题栏右上角浮现绿色 ▶（`AllIcons.Actions.Execute`）捕捉钮——按钮存在，只是平时不渲染。

代码侧事实链：

- `SqlLogPanel.kt:523`：`toolbarGroup = DefaultActionGroup(ClearAction, SettingsAction, ShowSearchAction, HelpAction)`——T-UN-11 起面板工具栏不再含捕捉钮，与截图一致。
- `SqlLogPanel.kt:518`：`captureToggleAction: AnAction = CaptureAction()` 暴露给工厂挂标题栏。
- `SqlLogToolWindowFactory.java:53`：`toolWindow.setTitleActions(java.util.List.of(panel.getCaptureToggleAction()))`。
- 迁移出自提交 720ca21（2026-09-16，T-UiNative P1a 后半），动机记录于 `docs/开发计划/20260916-0238-UI与功能原生化四批次实施-开发计划.md` §T-UN-11：退役「uiTraverser + 反射 getAction + setIcon」面板内强改图标 hack，回归平台 presentation 更新机制。

## 二、根因本质

T-UN-11 把捕捉钮从面板工具栏迁到 `ToolWindow.setTitleActions`，解决了刷新 hack 问题，却引入两个新问题：

1. **新 UI 标题栏动作非激活不渲染**：工具窗未获得焦点/未悬停时 header actions 不可见（两轮截图对照实证），捕捉入口在用户视角「消失」。
2. **入口与引导文案割裂**：空态文案 `log.panel.empty`（「点击『捕捉』后开始监听控制台」）指向的是面板内工具栏心智，实物却在悬停才可见的标题栏——首用用户沿文案找不到按钮。

捕捉开关是面板的主操作入口，不适合挂在平台行为不可控的标题栏；T-UN-11 的技术收益（反射 hack 退役、presentation 驱动刷新）与按钮位置无关，回迁面板后依然成立。

## 三、方案

### T-CB-01 捕捉钮回迁面板工具栏首位

- `SqlLogPanel.kt` `toolbarGroup` 首位加回 `CaptureAction()`，恢复 T-UN-11 前布局「捕捉/清空/设置/搜索/帮助」（搜索在帮助左侧的用户指定排序不变）。
- `SqlLogToolWindowFactory.java:53` 移除 `setTitleActions` 挂载（单一入口；标题栏形态悬停才可见，保留只会造成两处状态显示且标题栏处无增量价值）。
- 状态刷新沿用既有链路：`capturingUiListener` → `_toolbarRef?.updateActionsImmediately()`（`SqlLogPanel.kt:539-549` 已在，回迁后捕捉钮随面板工具栏一起被该链刷新）。禁止回退 uiTraverser+反射强改图标形态——BannedApiSourceScanTest 守卫钦定 `updateActionsImmediately()` 正典（T-UN-11 方向修正后的规则，不得反转回去）。
- `CaptureAction.update()` presentation 逻辑现成（capturing ? Suspend/「停止」: Execute/「捕捉」），不动；`SqlLogPanel.kt:404` 区域注释同步回「捕捉/清空/设置/帮助 + …」口径。

### T-CB-02 i18n 顺修：waiting 提示走 bundle

- `SqlLogPanel.kt:949` 硬编码中文 `"已开启 SQL 监听，等待项目运行"` 改用既有键 `log.panel.capture.waiting.desc`（T-UN-11 引入时漏接，键已在 zh/en bundle）。改后需核对两语文案语义贴合（「等待项目运行——控制台出现后自动开始捕捉」），不贴则微调 bundle 文案。

### T-CB-03 测试同步

- `SqlLogPanelLayoutTest.kt:46-48`：断言更新——工具栏组 ≥5 个动作、`captureToggleAction` 在 `toolbarGroup` 内（不再仅「存在性」断言）；可加初态 presentation 断言（icon=Execute、text=`log.panel.capture`），沿用「直读 presentation、不依赖按钮刷新」的既有测试形态。
- `HelpDialogTest.kt:26`：「工具栏组余 4 项」改 5 项（捕捉/清空/设置/搜索/帮助）。
- `HelpUiTest.kt`：按 Help 图标定位，不依赖组内位置与数量，预计零改动，跑一遍确认。
- 新增守卫面（防再漂移）：断言 `SqlLogToolWindowFactory` 不再调 `setTitleActions` 不做（平台行为非代码错误，无需禁令）；捕捉钮回迁的防回退由 LayoutTest 的组内断言承担即可。
