```java
package cn.song.mybatisplusdemo.r2verify;

import cn.song.mybatisplusdemo.entity.User;
import cn.song.mybatisplusdemo.service.UserService;
import com.baomidou.mybatisplus.core.toolkit.Wrappers;
import com.baomidou.mybatisplus.extension.conditions.query.QueryChainWrapper;

/** R2 真机验证场景（O-8），验证完成后可删或保留为常备场景文件。 */
public class R2O8StrWrapperScenarios {

    private UserService userService;
    private NoEntityService noEntityService;

    /** 场景一 S88：var + 工厂 + remove 消费，预期 DELETE */
    public void s88VarFactoryRemove() {
        var w = Wrappers.<User>query().eq("id", 3L);
        userService.remove(w);
    }

    /** 场景二 S89：服务链 query()，预期 SELECT */
    public void s89ServiceQueryChain() {
        User one = userService.query().eq("id", 3L).one();
    }

    /** 场景三 S90：无实体解析线索服务链，预期红字警示 */
    public void s90NoEntityChain() {
        Object r = noEntityService.query().eq("id", 3L).one();
    }

    interface NoEntityService {
        @SuppressWarnings("rawtypes")
        QueryChainWrapper query();
    }
}
```

两点说明。demo 是 Java 8 源级，场景一的 var 会标编译错误，这是预期而不是环境问题：修复实现按 typeElement 文本判定 var，不依赖类型推断成功，Java 8 下 var 必然推断失败，恰好确定性地走修复新增的「类型不可识别」判定路径；该红线不影响插件的 gutter 图标与预览。场景三用 raw QueryChainWrapper 返回类型使三条实体解析通道全部落空，只有 rawtypes 警告，无编译错误。

```java
package cn.song.mybatisplusdemo.r2verify;

import com.baomidou.mybatisplus.extension.conditions.query.LambdaQueryChainWrapper;

public class R2O6JumpScenarios {

    private GadgetService gadgetService;

    /** gadget 表全项目唯一服务链，单候选直跳目标 */
    public void gadgetSingleChain() {
        LambdaQueryChainWrapper<Gadget> q =
                gadgetService.lambdaQuery().eq(Gadget::getId, 1L);
        System.out.println(q);
    }

    /** 打印 MyBatis StdOutImpl 格式日志行供插件控制台捕获，无需连库 */
    public static void main(String[] args) {
        System.out.println("==>  Preparing: SELECT id, name FROM gadget WHERE id = ?");
        System.out.println("==> Parameters: 1(Long)");
        System.out.println("<==      Total: 1");
        System.out.println("==>  Preparing: SELECT id, username FROM user WHERE id = ?");
        System.out.println("==> Parameters: 3(Integer)");
        System.out.println("<==      Total: 1");
    }
}
```

设计说明：gadget 表在项目里只有这一处服务链，制造 Single 场景；user 表在 demo 既有代码里有至少四处服务链起点（WrapperExtServiceImpl 118/129/141、UserServiceImpl 156，已 grep 核实），天然构成 Multiple 场景。main 打印的行含 `Preparing:` / `Parameters:` 关键字，插件的日志行识别是「行内含关键字即命中」（HibernateLogParser.kt:341-347），纯控制台输出即可被捕获，不需要启动 Spring Boot 和连库。

### 4.4 操作步骤

1. Reload All from Disk 后打开 R2O6JumpScenarios.java，在编辑器内右键点 Run 'R2O6JumpScenarios.main()'。首次运行若提示选 JDK，选项目 JDK 1.8；Maven 首次导入要等索引建完。
2. 切到 SQL Visualizer 工具窗 SQL 日志 tab，screenshot：应出现 gadget 与 user 两条条目。若没有，点捕捉按钮后重跑 main。
3. Single 场景：右键 gadget 条目，菜单点「跳转源码」（bundle 键 log.panel.jumpToSource）。screenshot 留档，随后看编辑器。
4. Multiple 场景：右键 user 条目点「跳转源码」，应弹「选择 Wrapper」列表框，保持弹窗 screenshot 留档，任选一条候选。
5. 跳转后的编辑器状态各 screenshot 一张（含光标所在行）。

### 4.5 预期结果

- gadget 条目：无弹窗直跳，编辑器打开 R2O6JumpScenarios.java，光标落在 gadgetSingleChain 方法内 `gadgetService.lambdaQuery()` 链所在行。
- user 条目：弹「选择 Wrapper」多候选框（log.panel.jumpToSource.multipleTitle），候选里能看到 WrapperExtServiceImpl 的 `userService.lambdaQuery()` / `userService.lambdaUpdate()` 行与 UserServiceImpl 的 `this.lambdaQuery()` 行——候选含服务链行就是服务链通道生效的直接证据；选中后跳到对应文件行。

### 4.6 通过判据与失败处理

- 失败处理：两表都提示未找到，确认 demo 未配拦截器（MybatisPlusConfig 无 SQLVIS 相关）后仍如此，判 T3 失败，截图留证。user 条目候选数量与预期不完全一致不算失败——搜索按表名聚合，工厂形态（UserServiceImpl:143 的 `Wrappers.<User>lambdaQuery()`）现在也在修复后的静态工厂通道搜索范围内，会出现属正常；Multiple 的判据是「弹出了选择框且候选含服务链行」。
