## 1. 问题现象

用户开启设置「项目启动时自动开始监听」（`settings.log.autoCapture`）后，项目（Spring Boot）启动运行，日志监听没有生效：图标不变、无 SQL 捕获。复现路径为「项目已打开 → 开启设置 → 运行项目」。

## 2. 根因分析

### 2.1 证据链（沙盒 idea.log，单次会话 14:57:54 ~ 16:09）

| 时间 | 日志行 | 内容 |
|------|--------|------|
| 14:58:33 | 325 | `LogStartupCapture.execute: 触发（project=mybatis-plus-sql-visualizer-demo, logAutoCaptureOnStart=false, suppressed=false）`——项目打开时设置关，正确跳过 |
| 15:39:00 | 4039 | `LogStartupCapture.execute: 触发（project=easy-code-demo, logAutoCaptureOnStart=false, suppressed=false）`——第二个项目打开，设置仍关 |
| 15:39:29 | 4224 | `PluginSettingsPanel.apply: state.after=false ... loadState(s.copy())`——全日志唯一一次设置 apply（用户此刻勾选并保存） |
| 15:39:33 ~ 15:40:53 | — | easy-code-demo 编译（0 错误）+ `HttpRequestGlobalContext created`——项目实际运行窗口 |

关键缺失：15:39:29 apply 之后到日志结束，**没有任何** `PluginSettingsConfigurable.apply` / `startCapture` / `startListeningOnly` / `onConsoleAppeared` / `startPolling` 日志。桥从未挂载，轮询从未启动，运行控制台出现时自然无人感知。

### 2.2 直接根因：边沿联动代码挂在未注册的死类上

「设置在项目已打开后才开启 → apply 时检测关→开边沿 → 遍历 openProjects 调 startCapture + 清 suppressed」这一修复是踩坑记录第九轮（2026-08-20，`pitfall-log-startup-capture-regression.md` §第九轮）的产物，代码现在完整存在于 `PluginSettingsConfigurable.apply()`（`config/PluginSettingsConfigurable.kt:45-63`）。

但设置页后来重构为「文件夹 + 分区子页」架构：plugin.xml（`src/main/resources/META-INF/plugin.xml:88-132`）注册的是 `PluginSettingsFolderConfigurable` + 五个 `SectionConfigurable` 子类（UiActions / SqlPreview / TableMapping / **SqlLog** / About）。`PluginSettingsConfigurable` **未注册**——从未实例化，apply 中的边沿联动是死代码。

用户实际勾选开关的位置是「SQL 日志」子页 → `SqlLogConfigurable` → `SectionConfigurable.apply()`（`SectionConfigurable.kt:31-35`），它只透传 `panel.apply()`（写状态、发 `SETTINGS_CHANGE_TOPIC`），没有边沿检测。`SqlLogManager` 对 `SETTINGS_CHANGE_TOPIC` 的订阅（`SqlLogManager.kt:115`）也只做 `applySettings()` + `refreshConsoleContexts()` + autoShow 逻辑，刻意不启动捕捉。

于是：`LogStartupCapture`（postStartupActivity）已随项目打开以 `false` 跑过一次不再触发；设置 apply 又无人调 `startCapture()`；运行控制台出现时无桥无监听，`onConsoleAppeared` 无从产生。这正是踩坑记录第九轮修的问题在设置页架构改造后的回归——**修复代码还在，挂载点死了**。

### 2.3 排除项（已核验，非本次根因）

- 沙盒 jar 部署正确：`plugins/.../lib/*.jar`（14:57）与 `build/libs` 一致；javap 确认含 `startListeningOnly`、`onConsoleAppeared` 等最新方法。
- `PluginSettingsPanel.apply` 持久化链完整：`loadState(s.copy())` 已修过 XmlSerializer 不落盘问题；勾选值写回在 `PluginSettingsPanel.kt:1065`。
- `mp-sql-visualizer.xml` 中无 `MpSqlVisualizerSettings` 组件属平台延迟保存（apply 后未到落盘周期），非缺陷；但真机验证时要防止误判。
- 日志中 `SlowOperations` SEVERE（Plugin to blame: SQL Visualizer）是既有独立问题（15:23:59，EDT 上 PSI findDirectory），与本问题无关，另案处理。

## 3. 修复方案

### 3.1 方案对比

| 方案 | 内容 | 结论 |
|------|------|------|
| A（采纳） | 边沿联动迁到 `SectionConfigurable.apply()` 基类：apply 前读旧值 → `panel.apply()` → 读新值 → 关→开则清 suppressed + 遍历 openProjects 调 `startCapture()` | 最小改动；覆盖任意承载该开关的子页；与原修复语义完全一致 |
| B | `SqlLogManager` 的 SETTINGS_CHANGE_TOPIC 订阅里做边沿 | 回调拿不到「变更前值」需新增 lastSeen 字段；且服务是 project 级、无项目时不存在，遍历 openProjects 的原语义反而别扭 |
| C | 恢复注册 `PluginSettingsConfigurable` | 与 Folder+Section 架构重复整页设置，不可行 |

### 3.2 行为语义（对齐踩坑第八/九/十/十一轮结论）

- 「关→开」边沿成立：`logAutoCaptureSuppressed = false`（重新表达诉求）+ `openProjects.forEach { startCapture() }`（`startCapture` 自带幂等守卫与无控制台 armed 态）。
- 非「关→开」apply（如改前缀后 Apply）：不做任何捕捉联动。
- `onConsoleAppeared` 现行守卫不动（`suppressed && !userArmed` 拦截、不清零语义维持 dev 现状）。

## 5. 风险与边界

- Settings 的 OK 会依次 apply 所有 isModified 的 Configurable：边沿检测在基类中天然只对承载该开关且值变化的子页生效，无重复触发（`startCapture` 幂等兜底）。
- 多项目同时打开：遍历 openProjects 对每个项目进入 armed，与原第九轮行为一致。
- 勾选后未点 OK/Apply 直接关设置：不生效（平台语义），与原行为一致，不额外处理。
- 本计划只修联动挂载点；`LogStartupCapture` 重试链、suppressed 状态机、armed 语义均不动。
