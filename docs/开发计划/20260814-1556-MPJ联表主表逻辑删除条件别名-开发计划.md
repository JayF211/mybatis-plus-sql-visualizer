# MPJ 联表主表逻辑删除条件缺别名——开发计划（T-M23.10）

> 本文档是 **MyBatis-Plus SQL Visualizer** 的 T-M23.10 增量计划：2026-08-14 用户实测——
> MPJ 联表查询生成的 SQL 中，主表逻辑删除注入条件 `AND deleted = 0` **没有主表别名**（应为
> `t.deleted = 0`），而 JOIN ON 中的副表逻辑删除条件均带别名（`carDeviceInfoEntity.deleted = 0`）——
> 主表条件裸列名在 MySQL 执行时与副表 deleted 列**歧义**（`Column 'deleted' in where clause is ambiguous`），
> 生成 SQL 无法直接执行。
>

## 1. 问题与动机（用户反馈，证据驱动）

**用户复现**：`MPJLambdaWrapper<CarDevicePortInfoEntity>` 三表 LEFT JOIN + 主表 `@TableLogic deleted`，
生成 SQL：

```sql
SELECT t.id, t.device_code, ..., t.port_power AS portPower
FROM biz_car_device_port_info t
LEFT JOIN biz_car_device_info carDeviceInfoEntity ON carDeviceInfoEntity.id = t.device_id AND carDeviceInfoEntity.deleted = 0
LEFT JOIN biz_car_station_info carStationInfoEntity ON carStationInfoEntity.id = t.station_id AND carStationInfoEntity.deleted = 0
LEFT JOIN biz_car_device_product_info carDeviceProductInfoEntity ON carDeviceProductInfoEntity.id = t.product_id AND carDeviceProductInfoEntity.deleted = 0
WHERE t.station_id IN (?)
    AND ((t.number LIKE ? OR t.device_code LIKE ?) OR t.station_name LIKE ?)
    AND t.dic_insert_status = 1
    AND (t.dic_status = 1 OR t.dic_status = 2)
    AND deleted = 0        -- ← 主表逻辑删除注入，缺 t. 前缀
ORDER BY t.create_time DESC
```

**根因（代码证据）**：`SqlPreviewService.injectLogicDeleteCondition`（`ui/SqlPreviewService.kt`）——
- 主表注入（SelectStatement 分支 262-267 行）：`Condition.Simple(ColumnRef(columnName = column), ...)` **未带
  `statement.tableAlias`**；函数注释 247 行明示「保持既有无别名格式」——M15（T-M15-07）单表时代的设计，
  M20-05 精确化时沿袭，**从未覆盖 MPJ 主表别名场景**；
- 副表注入（274-275 行）：`ColumnRef(tableAlias = join.alias, ...)` **带别名** ✓（所以 ON 里正确）；
- `SelectStatement.tableAlias`（MPJ 主表别名：构造别名 > setAlias > 默认 `t`，`MpjLambdaConverter` 124 行
  `mainAlias` 注入）**存在于语句模型，但主表注入未使用**；
- 不一致旁证：① M23.4 起 SELECT 展开列已统一 `ColumnRef(tableAlias = statement.tableAlias, ...)`
  （`SqlGenerator.kt:134`）；② 用户示例中 helper 注入的显式条件（`t.dic_insert_status = 1`、
  `(t.dic_status = 1 OR ...)`）解析期均带 mainAlias——**解析期条件有别名、注入期条件无别名**；
- 存量测试把无别名格式固化为断言（M15/M20 系列），掩盖了该缺陷。

**同类风险（同函数内一并处理）**：
1. `injectLogicDeleteCondition` DeleteStatement 分支（287-294 行）：同样缺别名。单表 DELETE（tableAlias=null）
   无别名正确，但 **DeleteJoinConverter 多表删除**（`DeleteStatement(..., tableAlias = mainAlias, joins = joins)`，
   `converter/DeleteJoinConverter.kt:61`）与 SELECT 同病；
2. `injectOptimisticLockCondition`（318-326 行）：`SET version = version + 1` 与 `AND version = ?` 均无别名；
   `UpdateStatement.tableAlias` 存在（UpdateJoinWrapper 联表更新形态 `UPDATE 表 别名 SET`，
   `SqlGenerator.kt:209/223`）→ **@Version 实体 + UpdateJoin 组合**同病（低概率但同类，顺带修）。

**约束**：
- 单表场景（tableAlias = null）渲染必须**逐字节不变**——大量存量断言依赖 `AND deleted = 0`（1610/1637、
  1857/1889、1899/1929、1967、1974/2000、2224、5053 等）；
- `ColumnRef.qualifiedName(dialect)` 已含 M23.5 方言关键字引用——带别名后自动 `t.deleted`，无额外处理；
- 修复点收敛在 `injectLogicDeleteCondition` / `injectOptimisticLockCondition` 两个函数，
  **不动 converter/parser/渲染器**。

## 2. 设计方案（T-M23.10）

### 2.1 主表注入带 `statement.tableAlias`（`ui/SqlPreviewService.kt`）

- **SelectStatement 分支**：`ColumnRef(columnName = column)` →
  `ColumnRef(tableAlias = statement.tableAlias, columnName = column)`；
- **DeleteStatement 分支**：同样处理（tableAlias 为 null 时 `qualifiedName` 渲染裸列名，单表零变化）；
- **乐观锁注入**：
  - `SetClause(column = ColumnRef(tableAlias = update.tableAlias, columnName = versionColumn), ...)`；
  - rawSql `"$versionColumn = $versionColumn + 1"` → 别名前缀拼接
    （`val p = update.tableAlias?.let { "$it." } ?: ""`，`"$p$versionColumn = $p$versionColumn + 1"`；
    alias 为 null 时退化为现状 `version = version + 1`）；
  - `Condition.Simple(ColumnRef(tableAlias = update.tableAlias, columnName = versionColumn), ...)`。

### 2.2 测试（`ui/SqlPreviewServiceTest.kt` 为主）

- **存量断言更新**（仅 MPJ 主表注入场景，`AND deleted = 0` → `AND t.deleted = 0`）：
  - MPJ 单表带 t 别名形态：3988 / 4017 / 4047；
  - MPJ 联表形态：4091-4093 / 4134-4137 / 4178 / 4220-4222 / 4265-4266 / 4307-4309 / 4351-4353；
  - 单表场景（1610/1637、1857/1889、1899/1929、1967、1974/2000、2224、5053）**保持不动**
    ——验证无别名兼容回归；
  - 3958（`AND t.deleted = 0`）为解析期显式条件路径，不动（对照）。
- **新增回归测试**：
  1. MPJ 三表 JOIN + @TableLogic 主表：WHERE 末尾 `AND t.deleted = 0`（用户复现形态全链路）；
  2. DeleteJoinWrapper 多表删除 + @TableLogic：主表条件带别名；
  3. UpdateJoin + @Version：`SET t.version = t.version + 1` + `AND t.version = ?`；
  4. 单表 @TableLogic：`AND deleted = 0` 不变（防回归锚点）。
- 全量 `clean test` 通过（500 → 预计 502+）。
