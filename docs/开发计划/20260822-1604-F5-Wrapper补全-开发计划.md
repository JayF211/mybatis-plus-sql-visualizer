## 0. 目标

在开发者编写 Wrapper 链时，提供上下文感知的智能补全。例如在 `.eq(` 之后提示 `.ne()` / `.ge()` / `.gt()` 等后续方法，以及按当前实体类的字段名提示 lambda 引用。

**用户价值**：降低新用户学习成本，减少查文档/源码的频率，提升编写效率。

---

## 1. 技术方案

### 1.1 核心 API

- `CompletionContributor`（`com.intellij.codeInsight.completion`）
- `CompletionType.BASIC`（显式触发）+ `SMART`（智能触发）
- `PlatformPatterns.psiElement()` + 自定义 PSI 位置判断
- `LookupElementBuilder` 构建补全项
- `PrioritizedLookupElement` 控制优先级

### 1.2 架构（参考 MyBatisX SyntaxAppender 模式）

```
用户输入 . 触发补全
  → WrapperCompletionContributor.addCompletions()
      → detectChain(position)      检测是否在 Wrapper 链中
          → WrapperLocator 复用     回溯链首 + 检测 WrapperType
          → EntityResolver 复用     解析实体类字段
      → 根据链状态生成补全项
          → 已调用 eq → 提示 ne/ge/gt/lt/like/in/isNull...
          → 已调用 select → 提示列名/别名方法
          → 链首 → 提示 eq/like/in/orderBy/groupBy...
          → 实体字段 → 提示 field name + 适用方法（eq/like/set...）
```

### 1.3 新增文件

| 文件 | 职责 |
|------|------|
| `ui/completion/WrapperCompletionContributor.kt` | CompletionContributor 入口 |
| `ui/completion/ChainStateDetector.kt` | 检测链状态（链首、已调用方法、当前位置） |
| `ui/completion/MethodLookupFactory.kt` | 构建方法名补全项（eq/ne/gt/ge/lt/le/like/in/orderBy...） |
| `ui/completion/FieldLookupFactory.kt` | 构建实体字段补全项（带 lambda 图标） |

### 1.4 改动文件

| 文件 | 改动 |
|------|------|
| `plugin.xml` | 注册 `completion.contributor` for language="JAVA" |
| `psi/WrapperLocator.kt` | 复用 `detectWrapperType` + 链首回溯逻辑（只读） |

## 2. 补全场景设计

### 2.1 方法名补全

**触发**：在 Wrapper 链中输入 `.` 后

**上下文感知规则**：

| 当前链状态 | 优先提示 |
|-----------|---------|
| 链首（无已调用方法） | eq, ne, gt, ge, lt, le, like, notLike, in, notIn, isNull, isNotNull, between, notBetween, orderBy, groupBy, having, select |
| 上一个方法是 eq/ne/gt 等条件方法 | and, or, eq, ne, gt, ge, lt, le, like, in, orderBy, groupBy, limit, last, exists |
| 上一个方法是 select | selectAs, selectIgnore, selectCount, groupBy, having, orderBy, limit |
| 上一个方法是 orderBy | orderByAsc, orderByDesc, limit, page, last, exists, list, one |
| UPDATE 的 set 后 | set, setSql, setIncrBy, setDecrBy, eq, ne, where |
| 链终结点附近 | list, one, count, exists, page, getOne, getMap |

### 2.2 实体字段补全

**触发**：在 `.eq(` / `.like(` / `.set(` 等方法内输入第一个参数

**提示**：当前实体类的所有字段名（驼峰），带字段类型图标

```kotlin
LookupElementBuilder.create("name")
    .withIcon(AllIcons.Nodes.Field)
    .withTypeText("String")
    .withInsertHandler { context, item -> 
        // 自动补全 lambda: UserInfo::getName
    }
```

### 2.3 JOIN 方法补全（MPJ）

**触发**：MPJ LambdaWrapper 链中

**提示**：leftJoin, rightJoin, innerJoin, fullJoin, selectAll, selectAs, selectIgnore

## 5. 边界与降级

- 非 Wrapper 链：不触发补全，不干扰正常代码补全
- 实体类解析失败：仅提供方法名补全，不提供字段补全
- 性能：补全触发时解析链状态需在 50ms 内完成（复用 WrapperLocator 的 O(1) 快速路径）
