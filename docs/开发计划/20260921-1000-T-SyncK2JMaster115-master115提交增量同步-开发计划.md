## 5. 移植规则（既定清单全量生效）

1. **生产代码 100% Java，绝不 merge .kt 进生产树**；本仓 `KOTLIN_TO_JAVA_RULES.md` 为准；
2. Kotlin→Java 机械转换缺陷清单逐条生效（static import / `drop` 越界守卫 / `LinkedHashSet` 保序 /
   `Map.of` 拒 null / `assertEquals` 装箱 / `throws Exception` / test 前缀 / record 访问器 `x()` /
   `split("\n")` 丢尾空串 → 须 `split("\n", -1)` 等）；
3. 互操作铁律：① **Java record 禁 extends 只可 implements**（sealed 层级降为接口 + record 实现）；
   ② Kotlin 调 Java 方法**禁命名实参**（直取 .kt 测试须机械转位置实参）；③ Java 静态成员/嵌套类型
   在 Kotlin 无默认导入（须补 import）；④ 非 `get`/`is` 前缀 Java 方法不合成 Kotlin 属性

1. **`HistorySqlLogPanelJumpToSourceTest` 的「环境此刻为空」型脆弱前置**（master 同形）：该用例断言
   历史目录此刻恰好 1 个文件，而本类不清理目录。**取证**：shard1 内 `HistorySqlLogPanelNavigationTest`
   时间戳 `08:40:57` 跑完（setUp 清理、tearDown 不清理）后，`JumpToSourceTest` `08:41:32` 读到 2 个
   文件而红。修法：本类 setUp 自清理（含旧目录名）+ NavigationTest 的 tearDown 补清理。
2. **`SqlLogAutoSaverPruneGuardTest#写批后裁剪_经submit链路生效且受节流约束` 的负载敏感时序**：该用例

   200ms 不足即假失败。**取证**：满负荷下红、静置时连跑 5 次全绿；**另建 pre-sync 基线 worktree

   （上限 5s，断言语义不变）。

> 被并行会话锁住**（`Unable to delete directory`），测试根本没跑；② 后续 2 次「红」实为**缓存被前次
> 竞争删坏**（`Cannot resolve product-info.json`）。**判红前必须先确认测试真的执行了**（看报告

### 9.7 实施偏离与发现（供下轮参考）

1. **Java 侧 `Companion` 不是伴生对象**：k2j 的 `McpStringArg.Companion` 是「静态字段 + 同名嵌套类」，
   Kotlin 测试**不能**写 `McpStringArg.Companion.string(...)`（kotlinc 报 unresolved reference）——
   须先把静态字段读进局部 `val` 再调其方法。生产侧已改为三参必填（无默认值），不受影响。
2. **`mergeCachedColumns` 的查询器返回可空 Map**：Java 侧签名是 `Function<String, Map<…>>`，Kotlin
   测试用显式 SAM 构造器时必须写 `Function<String, Map<…>?>`（可空类型实参），否则 `{ null }` 报
   `Argument type mismatch`。
3. **`McpArgKind` 等新枚举的常量产出点须写限定形态**：Java 惯例的裸常量名（`return OBJECT;`）会让
   本仓 `EnumReachabilityGuardTest` 判「零产出」假违规——这是该守卫在 Java 树的**已知判据边界**，
   移植任何枚举时都要注意。
4. **k2j 的 MCP 工具方法非 suspend 且无默认参数**：Java 方法无法表达 Kotlin 默认参数，
   kotlin-reflect 对 Java 形参恒报 `isOptional()=false`（本轮探针实证），故平台生成的 inputSchema 会
   把 `dataSource`/`maxTables` 标为必填，与 master 的 optional 语义有差。此为 **k2j 全部 MCP 工具的
   共性限制**（非本轮引入），已在 `SqlVisualizerSchemaContextTool` 的类 Javadoc 里如实登记。
5. **`testDatabase` 的环境前置（非代码问题，已修复并如实记录）**：首跑 2 红（`DbDriverPipelineTest`
   两例：artifact 清单解析不到 `MySQL ConnectorJ@9.7.0`、`options/test-database-artifacts.xml` 未落盘）。
   根因在 `buildSrc/.../mpv-testing.gradle.kts:288-357` 的驱动种子链：① 从 **k2j 工作树的 runIde 沙盒**
   （回退到 dev 工作树沙盒）复制 `jdbc-drivers.xml`——**该沙盒在本机不存在**（`jdbc-drivers.xml` 实际
   只存在于 master 工作树的 runIde 沙盒，而脚本不查那一处）→ ① 静默跳过 → ④
   `test-database-artifacts.xml` 无源可种 → 两例红。**处置**：把 master 工作树 runIde 沙盒的
   `jdbc-drivers` 目录（IDE 生成的驱动元数据，非手工编造）复制到 k2j 工作树脚本期望的沙盒路径，
   使 ①/④ 正常生效——复跑 **5 套件/10 用例/0 失败**，日志可见
   `jdbc-drivers.xml pre-seeded` 与 `test-database-artifacts.xml seeded (options/)` 两行。
   ⚠️ **教训**：实施期清 `build/test-sandbox` 会连带清掉历史已种好的 `jdbc-drivers.xml`，而种子源
   一旦缺失即静默跳过、测试随后变红——清沙盒前先确认种子源在位。
6. **并行会话推进 master 且共享 gradle 缓存**：本轮三次撞上 `transforms/cfd911...` 目录的锁竞争与
   缓存损坏（见 9.6 归因备忘）。对策：遇 `Unable to delete directory` / `Timeout waiting to lock` /
   `Cannot resolve product-info.json` 一律等待重试，**不要据此判代码红**。
7. **master 在途分支不宜追**：收官时 master 本地领先 origin 22 个未推提交（agent 心跳/重连批次），
   其计划文档自述仍有未修项。锚点取推送态是更稳的口径。
