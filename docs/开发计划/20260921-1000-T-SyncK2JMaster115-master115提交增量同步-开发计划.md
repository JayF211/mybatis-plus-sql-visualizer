## 5. 移植规则（既定清单全量生效）

1. **生产代码 100% Java，绝不 merge .kt 进生产树**；本仓 `KOTLIN_TO_JAVA_RULES.md` 为准；
2. Kotlin→Java 机械转换缺陷清单逐条生效（static import / `drop` 越界守卫 / `LinkedHashSet` 保序 /
   `Map.of` 拒 null / `assertEquals` 装箱 / `throws Exception` / test 前缀 / record 访问器 `x()` /
   `split("\n")` 丢尾空串 → 须 `split("\n", -1)` 等）；
3. 互操作铁律：① **Java record 禁 extends 只可 implements**（sealed 层级降为接口 + record 实现）；
   ② Kotlin 调 Java 方法**禁命名实参**（直取 .kt 测试须机械转位置实参）；③ Java 静态成员/嵌套类型
   在 Kotlin 无默认导入（须补 import）；④ 非 `get`/`is` 前缀 Java 方法不合成 Kotlin 属性
   （`currentPopup()` → `getCurrentPopup()`；布尔访问器是 `isXxx()` 而非 `xxx()`）；⑤ `internal` → `public`
   （跨包测试可见性）；⑥ 行级并集用 `git merge-file --union` 后取 mine，**union 后必须做两侧行集合校验**；
   ⑦ **`object` → `final class` + `INSTANCE` + 全 static；顶层函数 → `XKt.java`；默认参数 → 重载**；
   ⑧ **Java 测试侧访问平台 fixture 用 `getProject()`**（`project` 是 Kotlin 属性名，Java 无此符号）；
4. **基线一致性判定** `git show <sha>:<f> | diff --strip-trailing-cr - <f>`（CRLF 检出对 LF git-show
   裸 diff 会整文件假差异）；一致文件用 `git checkout <masterSHA> -- <paths>` 整取，**多 pathspec
   任一失效会整体中止**，事后逐一复核；
5. **守卫适配先行**：本轮新增三守卫（`BundlePlaceholderArityTest` / `DegradedBannerWordingGuardTest` /
   `InsertColumnInlayPanelWiringTest` 的 inlayProvider 注册读数），**必须做「移除修复分支 → 必红」
   反向验证**，防「扫描根不匹配 → 命中 0 文件 → 断言恒真」的静默假绿（本仓守卫类已三次绿灯下失效）；
6. **反射入口登记**：`DatabaseSchemaResolver` 重构新增 `DasAccessors` / `ModelTraversal` 反射遍历面，
   须核对该链上反射调用的平台签名是否变化；如有新增反射入口，登记 `PlatformSignatureCrossVersionTest`；
7. **gradle 前必跑 `parallel_tasks.py check`**；本会话登记名 `T-SyncK2JMaster115`、沙盒 `MPSV-K2J115`；
   **登记表滞留的 T-GifRec-MCP / T-CopyTest 条目不 kill、不触碰其沙盒**；收官后 `done` 注销并还原
   沙盒临时行；push 留用户 GUI；
8. **移植引发测试假失败先清 `build/classes` + `build/kotlin`**（陈旧产物劫持三形态），再排逻辑；
9. **多路共用单工作树时 gradle 三类互抢**（沙盒 jar 被对方 JVM 锁 / 编译竞态 / test-results 被清）——
   一律等待重试，别据「表里只两条」判无人并行；
10. **收口禁用 `&&` 串联**（合并失败会让门禁静默未启动，被误读成「还在跑」）；多步收口用分号或显式检查退出码。
