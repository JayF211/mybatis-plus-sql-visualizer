## 一、需求概述

M36.4 落地后用户实测反馈三个体验问题：

| # | 问题 | 现象（用户截图） |
|---|------|------------------|
| 1 | 底部空白无用占位 | 控制台结果区下方有大片空白；仅执行出错时才需要提示区 |
| 2 | 白色内边框割裂感 | 面板左侧参数区、上侧有白色内边框，与 IDEA 原生 UI 不融合 |
| 3 | 原生控制台非默认显示 | 只有点击「执行 SQL」后原生控制台才出现；期望面板打开即显示（社区版回退） |

---

## 二、根因分析

### 2.1 问题一：底部空白占位

当前布局（`SqlPreviewPanel.init`）：

```
BorderLayout
├── NORTH: topRow（元信息 + 工具栏）
└── CENTER: verticalSplit（JSplitPane.VERTICAL）
    ├── top:    ThemedSplitPane（参数区 | editorHolder=拼合控制台）
    └── bottom: consoleHolder（NORTH: resultPanel 状态行；CENTER: 空）
```

M36.4 将控制台移入右侧 `editorHolder` 后，`consoleHolder` 仅剩 `resultPanel` 一行状态文字，
但 `verticalSplit` 仍按分割比例给下半区保留高度 → **结果区下方大片空白**（截图实证）。

### 2.2 问题二：白色内边框

多个边框来源叠加：

| 位置 | 来源 |
|------|------|
| 左侧参数区 | `paramScroll`（`JBScrollPane`）默认 viewport border（Metal LAF 亮色描边） |
| 面板四周 | `ThemedSplitPane` / 外层 `JSplitPane` 的 LAF 默认 border（仅 `background` 覆写不分隔条，border 仍在） |
| 顶部 | `topRow.border = empty(6,0,4,8)` 右侧 8px 留白与原生工具行不对齐；弹窗 contentPane 默认内边距 |

### 2.3 问题三：原生控制台非默认显示

当前执行链为「按需创建」：点击「执行 SQL」→ 选数据源 → `attachConsole` → `executeQueries` → 内嵌。
控制台的创建绑定在执行动作上，因此面板打开时不显示。

**原生 Database Console 的本质**：控制台（JdbcConsole）与「执行」是两个独立动作——
打开 Console 时只创建 session + 编辑器，执行是后续 Ctrl+Enter。
本插件当前把两步合并在一次点击里，导致控制台无法提前出现。

## 三、技术方案

### 3.1 Phase 1：去除底部空白（布局简化）

```
【目标布局】
BorderLayout
├── NORTH: topRow（元信息 + 工具栏）
├── CENTER: ThemedSplitPane（参数区 | editorHolder=拼合控制台）
└── SOUTH: resultPanel（仅在有状态/错误内容时占位，showEmpty 时隐藏）
```

改动点：
1. **删除 `verticalSplit`**：`split` 直接放 CENTER
2. **`resultPanel` 移到主面板 SOUTH**：`consoleHolder` 整个删除
3. **状态行为**：`showLoading`/`showError`/`showQueryResult` 时 `resultPanel.isVisible = true`；`showEmpty` 时 `isVisible = false`（不占高度）
4. 清理 `verticalSplit` 相关字段与 `embedConsole` 中的分割线定位逻辑

### 3.2 Phase 2：白色内边框清理

| 目标 | 改动 |
|------|------|
| 参数区 | `paramScroll.border = JBUI.Borders.empty()`；保留滚动功能 |
| 分栏 | `ThemedSplitPane` 构造中显式 `border = JBUI.Borders.empty()` |
| 顶行 | `topRow.border` 收敛为 `empty(4, 8, 2, 8)`（与原生工具行对齐） |
| 宿主弹窗 | 检查 `SqlPreviewDialog` contentPane 是否有默认内边距，有则清零 |

验证方式：亮/暗主题下截图对比 IDEA Database 工具窗口，边缘无白色描边。

### 3.3 Phase 3：默认显示原生控制台（核心）

**目标交互**：面板打开（`showResult`）即展示原生 Database 控制台（含 SQL 文本），
「执行 SQL」按钮仅触发执行；社区版（无 Database 插件）保持现状自研编辑器回退。

#### 3.3.1 执行链拆分：控制台准备 与 执行 解耦

`DataSourceSelector` 新增两个入口：

```kotlin
// ① 准备控制台（不执行）：选数据源 → 建 session → attachConsole → 拼合组件回调
fun prepareConsole(
    project: Project,
    sql: String,
    onConsole: (JComponent) -> Unit,      // 拼合组件（编辑器+结果区）
    onEditor: (Editor) -> Unit,           // 补全上下文注入 + 文档引用
    onError: (String) -> Unit,
    callback: (Boolean) -> Unit,
)

// ② 在已准备的控制台上执行（复用缓存 console/editor/scriptModel）
fun executePrepared(project: Project): Boolean
```

内部重构：
- 从现有 `selectAndExecute` 中抽出公共链 `createConsoleInternal(...)`（临时文件 → runners → session → attachConsole → 拼合）
- `prepareConsole` = 公共链，**不调 executeQueries**
- `executePrepared` = 对缓存的 `console/editor/scriptModel/execOption` 反射调 `executeQueries`（后台线程 + 5s 超时，沿用 M36.3）
- 控制台生命周期缓存：`preparedConsole` 字段持有，面板 `clear()`/`dispose()` 时释放引用（JdbcConsole 本体仍由 IDE 管理）

#### 3.3.2 数据源选择策略（面板打开时）

| 场景 | 行为 |
|------|------|
| 存在唯一数据源 | 静默使用，直接出控制台 |
| 多个数据源 | 弹一次原生选择弹窗（复用现有 `showRunnerPopup`），选择后记住（`PropertiesComponent` 按 project 存 last-used） |
| 无数据源 | 右侧显示引导占位（「配置数据源」按钮 → 打开 Database 工具窗口），不打扰 |
| 用户点「执行 SQL」时控制台尚未就绪 | 走现有 `selectAndExecute` 全链（准备+执行合一） |

#### 3.3.3 面板集成（`SqlPreviewPanel.showResult`）

```
showResult(result)
  ├── 渲染参数面板 + 自研编辑器（现状不变——参数回填/条件勾选仍依赖自研编辑器）
  └── 若 Database 可用 && 尚无 preparedConsole：
        SqlExecutor.prepareConsole(sql, onConsole = { embedConsole(it) }, ...)
        → 控制台就绪后 embedConsole 内嵌右侧（覆盖自研编辑器）
        → 后续参数变更经 nativeEditorDoc 同步（M36.4 已有）
```

#### 3.3.4 社区版回退

`ExecuteSqlSupport.isAvailable() == false` → 不发起 `prepareConsole`，
保持自研编辑器 + 现有降级提示（验收项）。

### 3.4 Phase 4：i18n 与测试

**新增 key**：
```properties
execute.datasource.placeholder=请先配置数据源以启用原生控制台
execute.datasource.configure=配置数据源
```

**测试**（`ExecuteSqlErrorHandlingTest` 扩展）：
- `prepareConsole` 在插件不可用时调用 `onError`（复用现有断言模式）
- `executePrepared` 未准备控制台时返回 false 且不抛异常
- `resultPanel` 隐藏行为：`showEmpty` 后 `isVisible == false`

## 五、风险评估

| 风险 | 等级 | 缓解 |
|------|------|------|
| 面板打开即弹数据源选择打断用户 | 中 | 唯一数据源静默；多数据源仅首次弹（记住选择） |

| 拼合 SplitPane 中编辑器 0x0 复发 | 低 | M36.4 已实证 SplitPane 布局可撑起编辑器；不回归单独提取方案 |

| 3 | 右侧缺原生工具栏（"不像原生控制台"） | 反射 `JdbcConsoleUtil.addLeftToolbarConsoleActions(group, consoleView)` 注入标准控制台动作；**第二参须 `console.getConsoleView()`（LanguageConsoleView）**——首轮误传 JdbcConsole 本体类型不匹配必失败 |

#### 关键教训（防复发）

1. **反射 invoke 参数类型严格匹配**：`addLeftToolbarConsoleActions` 第二参是
   `com.intellij.execution.ui.ConsoleView`，JdbcConsole 本体不实现该接口（javap 实证继承
   AbstractQueryLanguageConsole）——必须经 `getConsoleView()` 取 LanguageConsoleView。
2. **SplitPane 构造会 reparent 子组件**：预建完整 SplitPane 再内嵌顶部块时，构造调用把
   顶部块从宿主"偷走"，预建实例永久缺顶部子组件——完整 UI 须在换入时按需构建并缓存
   （`preparedFullComponent` 仅在"全链内嵌"或"首次换入"时赋值）。
3. **embedConsole 同实例防抖**：缓存完整 UI 在重复执行时回调同一实例，直接重内嵌会闪烁。
4. **executeQueries 触发失败/密码弹窗超时不换入结果区**：`executionStarted` 标志保证
   onResultsReady 只在真实触发成功后回调。

### M36.5.3 实施记录（2026-08-29，沙盒日志定位两实测问题）

> M36.5.2 沙盒实测（截图 + idea.log）：① 嵌入面板顶部只有 4 个 console 通用动作，
> 缺 ▶执行/Tx/会话/数据源选择器——"不像原生控制台"；② 执行偶发"失败"（超时提示
> 密码/驱动，实际数据源正常）。

| # | 问题 | 根因（沙盒日志/javap 实证） | 修复 |
|---|------|------|------|
| 1 | 缺原生运行工具栏 | 原生工具栏是 `JdbcConsole.buildHeaderComponent(Editor, JdbcConsole)` public static 构建的编辑器**头部组件**（`Console.Jdbc.Left`＝▶执行/Debug/历史/参数/设置 + `Console.Jdbc.Right`＝Tx/会话/数据源选择器，EditorHeaderComponent 左 CENTER/右 EAST）；M36.5.2 注入的 4 动作来自 `addLeftToolbarConsoleActions`（= consoleView.createConsoleActions 过滤，仅软换行/滚动/打印/清除） | 反射调用 `buildHeaderComponent`（与 IDE 同一构建路径）；失败回退原精简工具栏 |
| 2 | 执行"失败"误报（提示密码/驱动，实际数据源正常） | 沙盒 idea.log 实锤：两次失败 run 均发生在 **dumb mode（索引）窗口内**——临时文件 PSI 创建时的方言替换（GenericSQL→MySQL）依赖 SqlDialectPusher push-all，索引中被推迟到索引完成；期间 `executeQueries` 按 GenericSQL PSI 解析**静默不执行**（失败 run 连数据库连接尝试都未发起，成功 run 方言在执行前已解析），4s 重试超时后误报凭据提示 | ① `createTempPsiFile` 在 findFile **前**显式 `SqlDialectMappings.setMapping(vf, MySQL)`（IDE 自身 ChangeDialectAction.setDialectImpl0 同路径；映射命中不依赖 pusher/ProjectFileIndex，顺带消除映射查找途中的 isInContent 慢操作告警）；② 结果 Tab 重试 dumb-aware：索引中窗口 10 次（4s）→40 次（16s）；超时提示按状态区分——索引中给"索引推迟"提示（新增 `execute.indexing.hint` 中英 key），非索引才提示密码/驱动检查 |

#### 关键教训（防复发，M36.5.3）

1. **`addLeftToolbarConsoleActions` ≠ 原生控制台工具栏**：它只装 console 通用动作；
   完整原生工具栏（执行/Tx/会话/数据源）在 `JdbcConsole.buildHeaderComponent` 的
   编辑器头部组件里——复用 IDE 构建路径而非自行拼装。
2. **dumb mode 下新建 .sql 文件的方言替换会被推迟**：任何"建临时 SQL 文件→立即执行"
   的链路都必须保证方言确定（显式 setMapping），否则查询按 GenericSQL 静默不执行、
   且无任何错误输出——表象是"超时/无结果"而非报错，极易误判为凭据/驱动问题。
3. **grep 二进制 class 必须加 `-a`**：本仓库多轮反编译调查中 grep 无 `-a` 静默漏配
   （JdbcConsoleUtil 自身的方法名字符串都匹配不到），浪费排查时间。
