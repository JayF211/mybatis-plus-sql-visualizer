# 插件介绍页底部展示作者微信与群二维码——开发计划（M18）

> 本文档是 **MyBatis-Plus SQL Visualizer** 的 M18 增量计划：在**插件介绍页最下方**展示**作者微信二维码**与**交流群二维码**，
> 让用户在插件市场/IDE 插件管理页看到插件的同时即可扫码联系作者、加入交流群。
>
> 当前基线：M17（执行 SQL 按钮，260 测试全绿）。

## 1. 需求与约束分析（2026-08-13）

### 1.1 用户诉求

> 「在**插件介绍页的最下方**，展示**作者微信**和**群二维码**」

**「插件介绍页」定义**：插件对外展示的介绍页面共有两处，本需求两处均覆盖：

| 展示面 | 内容来源 | 备注 |
|--------|----------|------|
| **JetBrains Marketplace 插件页**（网页） | 发布时上传的 `plugin.xml <description>`（经 Marketplace 处理） | 网络用户浏览的主要入口 |
| **IDE 插件管理页**（Settings → Plugins → 插件详情） | 浏览市场时 = Marketplace 元数据；查看已安装插件时 = 本地 `plugin.xml <description>` | IDE 内展示 |

另：项目 Gitee 仓库 README 页也承担「介绍」职能，本次一并补充二维码区块（成本极低，与介绍页展示互通）。

### 1.2 关键约束（本功能的核心决策点）

| 约束 | 现状/事实 | 影响 |
|------|-----------|------|
| **Marketplace 描述不支持 base64 data URI 图片** | JetBrains 官方社区确认（[Can a plugin embed an image for its `<description>`?](https://intellij-support.jetbrains.com/hc/zh-cn/community/posts/115000569230)）：`<img src="data:image/png;base64,...">` 渲染为**破图**；原因：IDE 浏览插件市场时**只下载插件元数据**，描述内嵌资源不可用 | **排除 base64 方案**（否则两张图 ≈ 400KB base64 文本，Marketplace 不显示，纯属污染描述） |
| **描述内相对路径图片同样不显示** | 同帖确认：`<img src="resources/test.png">` 渲染进程根本不尝试加载（插件包内资源在浏览元数据阶段不可用） | 排除「图片打进 jar 用相对路径」方案 |
| **官方推荐：描述图片用外部 URL** | 同帖官方人员结论：浏览插件页本就需要联网，**外链图片可正常显示** | 主方案：图片托管到公网 URL + `<img src="https://...">` |
| **Marketplace 对描述 HTML 有白名单** | 官方文档：`<description>` 仅支持有限 HTML（`b`/`i`/`br`/`p`/`ul`/`li` 等）；社区反馈 `h1/h2` 标题在 Marketplace 描述**可能被过滤不显示**；**`<img>` 外链是否在 Marketplace 网页版展示存在不确定性**（官方建议截图走媒体库轮播区） | ① 现有描述已用 `<h2>`/`<hr/>`，本次顺带核查；② 描述内 `<img>` 以「IDE 插件管理页必达、Marketplace 网页版尽力」为预期，兜底方案见 R1 |
| **源图规格与对应关系** | 用户确认 + OCR 复核：`mmqrcode1786584544689.png`（958×1415，223KB，图内文字「扫二维码，添加我为朋友」）= **作者微信**；`mmqrcode1786584627943.png`（1203×1726，182KB，图内文字「群聊：MyBatis-Plus SQL Visualizer 交流群」）= **交流群**——竖版**截图**（二维码 + 周边留白/文字） | 需**裁剪二维码主体 + 缩放 + 压缩**（目标每张 ≤ 50KB、显示宽 ~220px），避免大图拖慢插件页、长宽比异常 |
| **二维码限时有效** | 群二维码图内标注「**7 天内（8月20日前）有效，重新进入将更新**」；微信个人「添加朋友」码同样为限时码（约 7 天） | **二维码必然过期**：R6 由「可能」升级为「确定」——需建立定期重新生成/替换/重新发布的维护流程；**发布 Marketplace 前务必换用最新生成的码** |
| **托管渠道** | 作者仓库在 **Gitee**（remote 已确认：`https://gitee.com/songrenshuo/mybatis-plus-sql-visualizer`，master 分支，与本地同步）；无自有图床/OSS | 首选 **Gitee 仓库 raw 直链**（`https://gitee.com/songrenshuo/mybatis-plus-sql-visualizer/raw/master/docs/images/xxx.png`）；备选 GitHub raw / 图床 / **Marketplace 媒体库 CDN**（`plugins.jetbrains.com/files/...`，最稳但需发布后在编辑页上传） |
| **图片随仓库分发** | 图片需入库（`docs/images/`）供 README 相对路径渲染 + 作为 raw 直链源 | 新增 `docs/images/` 目录，两张二维码入库 |

### 1.3 技术调研结论

| 环节 | 结论 |
|------|------|
| base64 内嵌 | ❌ 不可用（官方确认破图） |
| 相对路径 | ❌ 不可用（官方确认不加载） |
| 外部 URL `<img>` | ✅ 官方推荐；IDE 插件管理页可显示 |
| Marketplace 网页版 `<img>` | ⚠️ 官方文档白名单不含 img 的明确表述，存在过滤可能；兜底见 2.4 |
| README（Gitee） | ✅ 仓库内相对路径直接渲染，无任何限制 |

## 2. 方案设计

### 2.1 图片资源准备（T-M18-01）

1. **裁剪**：从两张源图截取**二维码主体正方形区域**（微信二维码中心定位角特征明显，手动框选一次即可）；
2. **缩放**：二维码显示尺寸 ~220×220px（QR 最小识别尺寸远小于此，可扫性无损）；
3. **压缩**：PNG 8bit / 适当降色，目标**每张 ≤ 50KB**（源图 182~223KB → 压缩 ~75%）；
4. **落盘**：`docs/images/wechat-qr.png`（作者微信，源图 `mmqrcode1786584544689.png`）、`docs/images/group-qr.png`（交流群，源图 `mmqrcode1786584627943.png`），随仓库提交。

> 工具：PowerShell（.NET System.Drawing）或 ImageMagick 均可，一次脚本完成两张源图 → 两张成品。
> ⚠️ 源图均为**限时码**（群码 8月20日前有效）：本轮生成的成品即绑定当前码，**正式发布前请用最新生成的码重新执行本任务**。

### 2.2 托管与直链（T-M18-02）

1. **首选**：Gitee 仓库 raw 直链——`https://gitee.com/songrenshuo/mybatis-plus-sql-visualizer/raw/master/docs/images/wechat-qr.png`（提交推送到 origin 后浏览器 + curl 验证**匿名可访问、无登录墙**）；
2. **备选**：Gitee raw 不可匿名访问 → GitHub raw / 公共图床（如路过图床等）；
3. **终选（最稳）**：发布到 Marketplace 后，用 Marketplace 编辑页**上传图片**获得 `plugins.jetbrains.com/files/...` CDN 链接回填描述（JetBrains 自家 CDN，IDE 内加载零障碍）。

### 2.3 plugin.xml 描述改造（T-M18-03）

在 `<description>` **最末尾**（中文段落之后）追加双语「联系作者」区块：

```html
<hr/>
<h2>Author / 联系作者</h2>
<p>Scan to add author's WeChat / 扫码添加作者微信</p>
<img src="https://gitee.com/songrenshuo/mybatis-plus-sql-visualizer/raw/master/docs/images/wechat-qr.png" width="220" height="220"/>
<p>Scan to join the WeChat group / 扫码加入交流群</p>
<img src="https://gitee.com/songrenshuo/mybatis-plus-sql-visualizer/raw/master/docs/images/group-qr.png" width="220" height="220"/>
```

要点：
- 两张图**并排或上下排列**（并排用 inline-block 需要样式支持，HTML 白名单内保守起见**上下排列**最稳妥）；
- `width/height` 显式指定，避免大图撑破布局；
- 现有 `<h2>`/`<hr/>` 沿用（顺带核查 Marketplace 兼容性，见 R5）；
- **不动** bundle 与其余描述内容，纯追加，`verifyPlugin` 描述校验通过。

### 2.4 Marketplace 网页版兜底（T-M18-04，条件执行）

若发布后 Marketplace 网页版描述中 `<img>` 被过滤（调研确认的不确定点）：
1. Marketplace 编辑页 → 描述末尾补**文字引导**：「作者微信/交流群二维码见 IDE 插件详情页，或加作者微信 xxx（微信号）」；
2. 或将图片上传至 Marketplace **截图/媒体库**（轮播区展示，官方推荐做法）；
3. 最终效果以发布后页面截图验收为准。

### 2.5 README 更新（T-M18-05）

`README.md` 末尾新增「📞 联系作者」区块（Gitee 相对路径渲染，零外链依赖）：

```markdown
## 📞 联系作者

| 作者微信 | 交流群 |
|----------|--------|
| ![微信](docs/images/wechat-qr.png) | ![交流群](docs/images/group-qr.png) |
```

### 2.6 测试与验收（T-M18-06/07）

- **自动校验**：`./gradlew verifyPlugin`（描述 HTML 合法、长度达标）+ `buildPlugin` 打包成功；
- **手动验收清单**：
  1. `runIde` 沙盒 → Settings → Plugins → **已安装插件详情页**：底部显示两张二维码，可正常渲染、大小合适；
  2. 浏览器打开 Gitee raw 直链：匿名可访问、加载正常；
  3. （发布后）Marketplace 插件页：二维码展示或走 2.4 兜底文案；
  4. （发布后）IDE 内**浏览市场**详情页：二维码展示；
  5. Gitee README：二维码区块渲染正常；
- 全量测试（260 既有）保持全绿——本功能零代码改动，属文档/资源类变更。

## 4. 风险与应对

| 编号 | 风险 | 影响 | 应对 |
|------|------|------|------|
| M18-R1 | **Marketplace 网页版过滤描述中的 `<img>`**（官方白名单无明确支持，社区反馈不确定） | 网页版看不到二维码 | 预期管理（IDE 内必达）+ 2.4 兜底（文字引导 + 媒体库截图）；以发布后实测为准 |
| M18-R2 | **Gitee raw 直链不可匿名访问 / 限流**（Gitee 对部分资源有登录墙） | IDE 内破图 | 提交后立即 curl 验证；备选 GitHub raw / 图床 / **Marketplace 媒体 CDN**（发布后回填，最稳） |
| M18-R3 | **二维码可扫性受损**（裁剪误伤定位角、压缩过度、220px 过小） | 用户扫码失败 | 裁剪后人工扫码验证（T-M18-01 验收项）；压缩上限 50KB 但可放宽至 100KB 保质量 |
| M18-R4 | **描述大图拖慢插件管理页**（原图 958~1203px 宽） | IDE 卡顿 | 220px 显示尺寸 + ≤50KB 文件体积双约束 |
| M18-R5 | **现有 `<h2>`/`<hr/>` 在 Marketplace 被过滤**（社区反馈 h 标签不显示） | 现有描述排版在网页版失效 | 本次顺带核查；如被过滤，将 `h2` 降级为 `p`+`<b>` 重排（白名单内标签） |
| M18-R6 | **二维码限时有效（已确认）**：群码 8月20日前有效、微信码约 7 天，过期后仓库图与发布描述中的码全部失效 | 用户扫码失败、联系渠道断裂 | **维护流程固化**：每次新码生成后 → 重跑 T-M18-01 替换 `docs/images/` 两图 → 提交推送（raw 直链不变，URL 无需改）→ 重新发布 Marketplace（描述 URL 相同，仅图片内容变化） |
