## 1. 目标

1. **P0-1 XML mapper 语句补全**：`<select|insert|update|delete>` 文本内提供——
   SQL 关键字、表名（FROM/JOIN 后）、列名（子句感知 + `别名.` 前缀感知）、`#{}` 参数名。
2. **P0-2 注解 SQL 字符串补全**：`@Select/@Insert/@Update/@Delete` 的 value 字符串（含
   `<script>` 写法）提供与 P0-1 相同能力（关键字/表/列/`#{}` 参数名）。
3. **P0-3 联表补全**（用户点名）：FROM/JOIN 多表场景下——JOIN 后联表候选、`别名.` 前缀
   列补全按别名对应实体的列过滤、ON 双侧列可用。
4. **P1-1 XML 动态标签补全**：语句内 `<if>/<foreach>/<where>/<set>/<trim>/<choose>/<when>/
   <otherwise>/<bind>/<sql>/<include>` 标签名与属性（test/collection/item/refid 等）、
   `test`/`collection` 属性值内 OGNL 补全（参数名 + 实体字段）。
5. **P1-2 渲染对齐 M16 预览补全**：列名 tailText 灰色注释、注释关键词中文检索、表名带表注释。

**非目标**：SQL 语法高亮/错误检查、数据源 schema 补全（方案 C，P-立项-06，后期）；
Provider 注解（SQL 由 Java 生成，静态不可取文本，不补全）；`<resultMap>`/`<sql>` 片段
refid 跳转（未立项）。

## 2. 效果预览

### XML 场景（mapper.xml 内手写 SQL）

```
<!-- 光标在 FROM 后 -->
SELECT <caret> FROM user u
           ↓ Ctrl+Space
SELECT id | name | phone | ...（列名，tailText 灰色注释，输入中文注释可检索）

<!-- 光标在 JOIN 后 -->
SELECT u.id FROM user u LEFT JOIN <caret> ON ...
           ↓ Ctrl+Space
user | device_info | merchant_entity ...（主表 + 项目内 @TableName 实体候选，tailText 表注释）

<!-- 光标在 别名. 后（联表，别名感知） -->
SELECT u.id, d.<caret> FROM user u LEFT JOIN device d ON d.user_id = u.id
           ↓ Ctrl+Space
d.id | d.name | d.dic_status ...（仅 device 实体列，前缀自动带入）

<!-- 光标在 #{} 内 -->
SELECT * FROM user WHERE id = #{<caret>}
           ↓ Ctrl+Space
id | name | phone ...（方法参数名 + 实体字段名）

<!-- 光标在语句内输入 < -->
WHERE 1=1 <caret>
          ↓ Ctrl+Space（P1-1）
<if> <foreach> <where> <set> <trim> <choose> <bind> <sql> <include> ...
```

### 注解场景（Java Mapper 方法）

```
@Select("SELECT u.id, d.<caret> FROM user u LEFT JOIN device d ON d.user_id = u.id")
DeviceInfoEntity getWithDevice(...)
                ↓ Ctrl+Space
d.id | d.name | d.dic_status ...（同一链路，与 XML 一致）
```

## 3. 方案设计

### 3.1 总体架构（方案 B：自研补全贡献器，零新依赖）

```
                    ┌─ XML contributor ─┐
用户光标 ──守卫(O(1))─┤                  ├─→ SqlTextAnalysis ─┐
   （祖先语句标签 /   └─ 注解 contributor ┘        (文本提取/子句/别名) ├─→ SourceSqlSuggestionFactory
     SQL 注解字符串）                                          ┌───────────────────→  LookupElement
                    └→ XmlSqlCompletionContextResolver（PSI）──┘
                       namespace→接口→实体（泛型基类/方法参数）
                       + @TableName 实体候选（注解索引）
                       + 方法参数名（@Param 感知）
```

- 注册：plugin.xml 两个 `<completion.contributor>`（language="XML" / "JAVA"）；
- 守卫复用 gutter 的 O(1) 语法判定模式（XmlSqlGutterLineMarkerProvider /
  AnnotationSqlGutterLineMarkerProvider 同款：祖先标签名 ∈ 语句集且根是 `<mapper>` /
  字符串字面量的所属注解 ∈ SQL 注解集合且为该注解 value）；
- 实体解析仅补全触发时执行（用户主动触发，容忍一次 findClass + EntityResolver），
  不在 daemon 路径，不破 gutter 性能红线。

### 3.2 补全上下文链路

**XML 语句 → 主实体**（优先级从高到低，对齐 M26-B XmlEwResolver 的关联链路）：
1. Mapper 接口泛型基类实参（`BaseMapper<Entity>` / `MPJBaseMapper<Entity>`）——最稳，
   与调用点无关；
2. 语句 id 对应方法参数中第一个实体类型参数（非 Wrapper/基本类型）；
3. 均失败 → 无主实体，降级只补关键字 + 动态标签（见 §7）。

**注解方法 → 主实体**：所在接口即 Mapper 接口，同 1/2 链路（无 namespace 环节）。

**联表候选**（JOIN 后表名补全）：主实体 + **项目内 `@TableName` 实体**
（`AnnotatedElementsSearch` 注解索引，非全文件遍历；测试环境已有 libs.mp.core 真实
MP jar，fixture 实体可带真实注解——T-M23.13 先例）+ 当前文件其它语句已出现的表名。
结果集上限 cap（防大项目候选爆炸，建议 50）。

**参数名**：方法参数名（`@Param` 值优先 + 实际名，复用 AnnotationSqlPreviewService
paramNames 逻辑——提取为共享入口）。

**上下文载体**：联表场景用 `List<SqlCompletionContext>`（主表 + 联表各一，复用 M16
现成模型：tableName/columns/columnComments/tableComment）。

### 3.3 联表支持（别名感知，纯文本反解析）

- 语句文本提取后（XML 剥离动态标签子元素、`#{}`/`${}` 保留原文），词法扫描
  `FROM`/`JOIN`（含 LEFT/RIGHT/INNER/CROSS/FULL 修饰与 `AS`）与逗号多表
  `FROM a a1, b b1`，跳过括号内子查询，产出 `(表名 → 别名)` 清单；
- 表名 ↔ 实体绑定：按 EntityResolver 的推断表名/`@TableName` 值匹配候选集合；
  未命中（物理表无实体）→ 记录别名但该别名列补全跳过；
- 光标处 `别名.` 前缀检测：向左取 `[\w$]+\.`，查别名映射 → 该实体列；
  前缀不存在 → 降级主表列；
- ON 子句双侧：带前缀按别名过滤；无前缀按主表列（简化决策，见 §9）。

### 3.4 位置感知与补全内容矩阵

`detectClause` 从 SqlCompletionContributor（M16）**迁移为公共纯函数**
（`sql/SqlTextAnalysis.kt`），预览与源码补全共用，行为不变（已有单测回归兜底）；
FROM/JOIN 后表名、SELECT/WHERE/ON/GROUP BY/ORDER BY/HAVING 后列名。

| 光标位置 | 补全内容 | 里程碑 |
|---|---|---|
| 语句文本（XML/注解），子句内 | SQL 关键字（复用 SqlLexer.KEYWORDS + JOIN 子句词 ON/AS/USING 等按需核对补充） | T-M27-03/05 |
| FROM/JOIN 后 | 主表 + @TableName 候选（表注释 tailText） | T-M27-03/05 |
| SELECT/WHERE/ON/GROUP BY/ORDER BY/HAVING 后 | 主表列（M16 样式） | T-M27-03/05 |
| `别名.` 后 | 别名对应实体列（联表） | T-M27-03/05 |
| `#{}`/`${}` 内 | 方法参数名 + 实体字段名 | T-M27-03/05 |
| 语句内 `<` 后 | 动态标签名（P1-1） | T-M27-04 |
| 标签名后空格/属性内 | 标签属性（test/collection/item/separator/open/close/refid…） | T-M27-04 |
| `test`/`collection` 值内 | OGNL：参数名 + 实体字段（含 `param.field` 第二段） | T-M27-04 |

### 3.5 性能红线

- 守卫 O(1) 语法判定，零 resolve、零遍历（gutter 同款）；
- 实体候选走注解索引（AnnotatedElementsSearch），不做文件树遍历；
- 补全结果集 cap；
- 补全路径的 findClass/EntityResolver 仅在用户主动触发补全时执行，不进入 daemon 高亮。

## 7. 边界与降级

- XML 无 namespace / 接口找不到 / 方法或实体参数缺失 → 仅关键字 + 动态标签，表列跳过
  （不弹错、不阻塞补全）；
- 非 mapper XML（根不是 `<mapper>`）→ 守卫不触发；非 SQL 注解字符串 → 不触发；
- Provider 注解 → 不触发（SQL 由 Java 生成，无静态文本）；
- 联表文本中无实体对应的物理表名 → 别名记录但列补全跳过；
- 未知 `别名.` 前缀 → 降级主表列。
