# P-立项-06 竞品精华融合功能开发计划

> **创建日期**：2026-09-01
> **触发**：`20260830-0002-竞品横向对比与功能建议-调研报告.md` 结论——Wrapper 静态预览仍是全市场空白，窗口期存在；竞品评论区沉淀出五类可吸收的精华优点与四类普遍抱怨。
> **定位约束**：所有新功能必须强化「写前预览—跑后还原—原地执行」闭环，偏离定位的一律不做（见第六节）。
> **优先级**：M37.0 零开发成本先行；M37.1/M37.2 为 P0 主体。

## 三、各里程碑要点

### M37.0 描述改版 + 参数拼接回归集（O-3 + O-2）

**O-3 描述改版**：
- Marketplace 描述、README、`marketplace-custom-page.html` 三处同步改版。
- 核心锚点：**「别的插件给你文本，我们给你可执行的 SQL」**；三个支撑点——Wrapper 静态预览全市场独家、预览即执行闭环、国产数据库方言（达梦/金仓，信创场景）。
- 对照竞品描述页自查：竞品普遍只讲功能清单，我们讲「旅程」（写代码时→跑起来后→验证）。

**O-2 参数拼接回归集**：
- 把竞品翻车场景沉淀为显式回归用例：参数含逗号、含空格、LocalDate/日期时间、IN 多值引号、NULL、二进制/十六进制。
- 用例跑三族解析器（MyBatis Preparing/Parameters、Hibernate binding、JdbcTemplate）+ 9 方言渲染。
- 真实引擎验证走既有 DBX MCP「渲染导出→执行」通道（P-立项-05 同款工作流）。

**验收**：描述三处一致且包含新锚点；回归用例全绿并纳入常规分片。

### M37.1 日志↔源码双向深链（N-2）

**目标**：日志条目与产生它的代码互跳。

- 现状基础：日志/历史面板条目已携带源文件信息并支持右键跳转（F-44 链路）。
- 差距一（源码→日志）：编辑器 gutter/Wrapper 链锚点无「查看最近执行记录」入口，用户跑到一半想回看某条链的真实 SQL 得去日志面板翻。
- 差距二（日志→源码精度）：跳转定位依赖日志中的类名/方法名，缺行号级锚定；同方法多条链时无法区分。

**设计要点**：
- 捕获侧从控制台堆栈（若日志框架输出位置信息）或执行时刻 PSI 锚点匹配，把 `LogSqlEntry` 与源码位置（文件+PSI 锚点 id）双向绑定并持久化到历史文件。
- 源码侧入口：Wrapper 链 gutter 右键菜单/行尾图标「最近执行」，弹出该锚点关联的日志条目列表（复用预览面板）。
- 具体方案在开工前按 M36 系列已验证的 PSI/EDT 陷阱（read access、SlowOperations）出子计划。

**验收**：从任一 Wrapper 链可一步看到其最近真实执行 SQL 并打开预览；日志条目跳转落在锚点行而非仅文件。

### M37.2 真实 EXPLAIN 联动（N-1）

**目标**：预览/还原出的 SQL 一键跑 EXPLAIN，静态规则引擎结果与真实执行计划并排展示。

**设计要点**：
- 入口：预览面板工具栏新增「EXPLAIN」按钮（仅 Ultimate 且已选数据源时可用，Community 置灰带 tooltip）。
- 方言适配：EXPLAIN 语句形态按 Dialect SPI 扩展（MySQL `EXPLAIN [FORMAT=JSON]`、PG `EXPLAIN [ANALYZE, FORMAT JSON]`、Oracle 走 `EXPLAIN PLAN FOR` + 查询 `PLAN_TABLE`、达梦/金仓按实测支持情况降级为隐藏入口）。新增 `Dialect.renderExplainStatement(sql)` SPI 方法。
- 结果展示：新增结果 Tab（与现有数据结果 Tab 并列），文本计划做表格化呈现；JSON 形态做关键字段摘录（type/key/rows/Extra 或 PG 的 cost）。
- 与静态规则引擎联动：同一视图左右分栏，静态标注（JSqlParser 规则引擎结论）+ 真实计划对照。
- 约束：EXPLAIN 属只读，不走 M36 系列的事务提交链也可，但必须复用原生控制台复用/等 smart 等已验证链路，避免重蹈滞后一轮覆辙。

**验收**：MySQL/PG 真机各验证一条含索引与全表扫描的 SQL，计划正确展示；Community 与未配数据源时入口优雅降级。

### M37.3 会话感知捕获 + 面板体验（N-3 + O-4）

**目标**：Run/Debug 会话启动即进入捕获态，首条 SQL 出现时自动展开工具窗（可配置）；捕获开关状态在工具窗标题栏可见。

**设计要点**：
- 订阅 `ExecutionListener`（messageBus 编程注册，plugin.xml 不支持 listener topic 的老坑）感知 Run/Debug 会话。
- 自动展开遵循用户设置页新增开关（默认开，可关）；ToolWindow 激活用 `ToolWindowManagerListener` 兜底（contentRemoved 不可靠的老坑）。
- 标题栏状态徽章：捕获中/已暂停，用自绘图标轮换（ActionToolbar 刷新 API 沙盒不可靠，沿用 UIUtil+反射 setIcon 方案）。
- 面板固定性：检查现有面板 register 到正确 disposable 树，重启后自动恢复显示状态。

**验收**：启动一个带 SQL 的 Spring Boot 会话，工具窗自动展开且首条 SQL 已捕获；关闭自动展开后行为静默；IDE 重启面板状态恢复。

### M37.4 Wrapper→测试资产生成（N-4）

**目标**：从 Wrapper 链/接口方法一键生成测试资产，两种形态：
1. **SQL 回归脚本**：按方言渲染的 .sql 文件（INSERT 前置数据 + 目标语句 + 断言查询），落盘项目 `src/test/resources/sql-visualizer/`。
2. **JUnit 用例骨架**：生成可编译的测试方法骨架，内嵌目标 SQL 字符串与 TODO 断言位（不引入运行时依赖）。

**设计要点**：
- 入口：预览面板工具栏「生成测试」按钮 + gutter 右键菜单。
- 生成走 PSI 短期模组（PsiFileFactory 需包 ReadAction 的老坑）。
- MybatisCodeHelperPro 的 testcase 卖点是表级 CRUD；我们的差异是**从真实 Wrapper 语义生成**（含逻辑删除/乐观锁/拦截器模拟后的最终形态），正确性可由 M37.0 回归集背书。

**验收**：对 sample 项目三条典型链（单表查询/JOIN/批量 UPDATE）生成两种形态资产且可编译执行。

### M37.5 MyBatis-Flex 可行性调研（N-5，只调研）

- 调研 QueryWrapper API 与 MP Wrapper 的结构差异、解析器抽象层改造成本、Flex 用户基数与重叠度。
- 产出独立调研报告，不写实现代码。结论倾向「可低成本复用」才立项子计划。
- **结论（2026-09-02，分支 feature/m37-competitive-fusion 报告 `20260902-0120-MyBatis-Flex支持可行性-调研报告.md`）：暂缓不接**——两段式条件 API 与 MP 单段式结构性不同，边际成本约 60-80% 远超 15% 门槛；同名 QueryWrapper 类有锚点误解析风险；重启条件见报告第五节（另建议单独评估「工厂方法名锚点提示」低成本兜底）。

### 持续项：O-1 新版 IDE 适配保障

- 新 IDEA 正式版/EAP 发布后：verifyPlugin + 关键路径 runIde 冒烟（预览、日志捕获、原生执行三链路），当日出结论。
- 结论同步到 Marketplace 描述（「2024.3+ 全版本持续适配」），把优势写成承诺。

## 四、验证策略

- 单测/集成：沿用 4 分片并行体系，新功能测试随各里程碑落位；M37.0 回归集纳入常规分片。
- 真机：EXPLAIN 与方言相关验证走 DBX MCP 七家族通道；UI 行为（M37.3）须真机截图验证，单测通过不等于视觉正确（JOIN 图的教训）。
- 每里程碑收尾按惯例更新 CHANGELOG 与发行说明。

## 五、风险

1. **范围蔓延**：N-4 生成资产容易膨胀成代码生成器，守住「测试资产」边界即可，不碰业务代码生成（M37.4 非目标）。
2. **EXPLAIN 方言碎片化**：达梦/金仓计划表行为不明，先 MySQL/PG 落地，国产库降级隐藏，不做硬编码猜测。
3. **框架官方跟进**：窗口期策略——M37.0 描述改版与 M37.1/M37.2 尽早发行，把「SQL 可视化」心智绑在本插件上。
4. **AI 替代**：不与文本处理竞争，M37.2 的真实计划与 M37.1 的零拷贝流转是 AI 做不到的深度集成。

## 六、不做清单

延续 20260822 结论并新增：

- 不做代码生成（MyBatisX 地盘）、数据库连接管理（Ultimate 已有）、Spring 导航。
- 不做付费订阅（MyBatis Log 激活差评是前车之鉴）。
- 不做纯格式化/美化工具（红海且稀释定位）。
- 不做 EXPLAIN 结果的自动改写建议（N-1 只呈现计划与静态对照，「改写建议」等有数据积累后再议）。
