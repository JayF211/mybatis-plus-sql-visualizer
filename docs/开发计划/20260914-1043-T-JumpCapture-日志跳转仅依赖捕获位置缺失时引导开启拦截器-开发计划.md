# T-JumpCapture：日志跳转源码仅依赖捕获位置，缺失时引导开启 SQL 拦截器

- 立项日期：2026-09-14
- 任务性质：用户功能反馈改造（跳转语义定案 + 死路回退移除 + 缺失引导）
- 反馈来源：用户 2026-09-14 反馈——「SQL 跳转到源码默认按 Wrapper 查询定位，这种方式实际不可用；应完全依赖捕获的代码位置，没有捕获时应引导用户在插件设置中开启 SQL 拦截器或直接弹框提示」
- 目标：跳转源码 100% 以拦截器捕获的 file:line 为唯一依据；无捕获位置时弹框引导（打开设置页 / 立即注入拦截器），Wrapper 表名启发式回退路径整体移除；全量测试绿

## 二、现状与根因分析

### 2.1 实时日志跳转的三级回退链（本次要砍掉后两级）

`SqlLogPanel.resolveEntryJump`（SqlLogPanel.kt:1178-1197）现逻辑：

1. 条目带 `sourceFile`（F-44-6/7：应用内 `SqlSourceInterceptor` 沿线程栈取用户代码帧，经 `SQLVIS-SOURCE|path|line` 标记行由控制台桥解析写入，见 CallerSourceLocator.kt / SqlSourceMarker.kt）→ `SourcePathResolver` 解析 VirtualFile → 精确 file:line 跳转；解析不到 → NotFound 提示。**这一级是用户认可的唯一可信路径，保留。**
2. 无 `sourceFile` → `resolveLiveJump` 提取表名 → `searchByTable` 后台 `WrapperSearchService.search` 全项目 `ReferencesSearch` 搜 Wrapper 工厂方法引用、按 `@TableName` 匹配表 → 单候选直跳 / 多候选弹选择框 / 无候选提示（SqlLogPanel.kt:1257-1305）。**用户定性：不可用，整体移除。** 表名相同不等于该 SQL 出自该 Wrapper——多表 join、动态表名、XML SQL、同名表复用场景下命中即误导，跳转语义上是错误答案而非「尽力而为」。
3. 提不到表名 → NoTable 提示（SqlLogPanel.kt:1247-1252）。随第 2 级一并移除。

### 2.2 历史面板：唯一分支已有，但提示是死路

`HistorySqlLogPanel.resolveJumpTarget`（HistorySqlLogPanel.kt:462-470）本就只有「有位置精确跳 / NoSource / NotFound」三分支（与用户诉求天然一致，无需砍回退），但 NoSource 只弹「该条目未记录源码位置（F-44 之前捕获）」一句.info（:484-491），用户下一步该做什么零指引——与实时面板统一改为引导弹框。

### 2.3 开启拦截器的能力已齐备，缺一个「从跳转失败进入」的编排

- 设置页已有开关：SQL 日志 → 「源码捕获」组 `autoInjectInterceptorCheck`（PluginSettingsPanel.kt:627-639），勾选即触发 `triggerInterceptorInjection`（:992-1042）→ `SqlSourceInterceptorAutoInjector.injectAsync` 在用户项目生成 `SqlSourceInterceptor.java` + `SqlVisualizerConfig.java`，重启应用后实时日志携带位置。
- 打开设置页并定位子页的能力已有：`ShowSettingsUtil.showSettingsDialog(project, SqlLogConfigurable::class.java)`（PluginSettingsFolderConfigurable.navigateToPage 的兜底路径同款，:143-157）。
- 缺口：跳转失败处没有任何入口连到上述能力；注入结果四类弹窗文案（成功/已存在/类型不支持/结构不可检测）目前硬编码中文在 PluginSettingsPanel 内，引导弹框若复制一份即双份维护——须抽公共编排。

### 2.4 WrapperSearchService 消费方清点（可净删依据）

全仓 grep：`WrapperSearchService` 仅 SqlLogPanel.kt（searchByTable/showCandidateChooser 两处）+ 自身测试 WrapperSearchServiceTest.kt 引用。`WrapperLocator`（gutter 图标、正向往返匹配）与 `EntrySourceMatcher`（源码→日志反向匹配）是独立能力，不动。连带可删 i18n 键 5 个（双语 bundle）：`log.panel.jumpToSource.noTable` / `.noWrapper` / `.multipleTitle` / `.multipleHeader`，以及 `resolveLiveJump`/`LiveJumpResolution`/`LogJumpTarget.SearchByTable`/`.NoTable` 整组死代码。

## 三、修复设计

### 3.1 引导弹框公共编排（新文件 `log/SourceCaptureGuide.kt`）

```kotlin
internal object SourceCaptureGuide {
    /** 无捕获位置时的引导弹框（实时/历史面板共用）。返回用户选择（测试驱动枚举，不触 UI）。 */
    internal enum class GuideChoice { OpenSettings, InjectNow, Cancel }
    internal fun resolveChoice(project): GuideChoice        // Messages.showDialog 三按钮封装
    fun showMissingSourceDialog(project: Project)           // 弹框 + 按选择执行两出口
    fun runInjection(project: Project, onResult: (InjectionResult) -> Unit = ::showInjectionResult)
    fun showInjectionResult(project: Project, result: InjectionResult)  // 四类结果文案（原 PluginSettingsPanel 私有弹窗迁入，i18n 化）
}
```

- 弹框用 `Messages.showDialog(project, message, title, arrayOf(打开设置, 立即注入, 取消), null, Messages.getQuestionIcon())`（平台既有 API，PluginSettingsPanel 已大量使用同族 Messages API，无新平台依赖）。
- 文案要点（zh/en 双语）：说明「该 SQL 未携带源码位置——插件依赖运行期 SQL 拦截器捕获真实调用点」；两出口语义：**打开设置**= `ShowSettingsUtil.showSettingsDialog(project, SqlLogConfigurable::class.java)` 落到 SQL 日志页（源码捕获开关所在页）；**立即注入**= 直接调 `runInjection`，成功后提示「重启应用后新生成的 SQL 即可精确跳转」。
- 注入结果文案补一句 MP 分页 COUNT 之外的通用提醒不扩范围；`InjectionResult.Success` 文案沿用「重启应用后生效」。
- PluginSettingsPanel.triggerInterceptorInjection 改为委托 `SourceCaptureGuide.runInjection`，勾选回滚（`isSelected = false`）保留在面板侧（仅它持有 checkbox）。

### 3.2 实时面板改造（SqlLogPanel）

- `LogJumpTarget` 收敛为 `Precise / NotFound / MpCount(原 NoSource 语义改名可保留 NoSource) / MissingSource` 四支：`sourceFile == null` → `MissingSource`（不再提表名）。
- `jumpToSource` 对 `MissingSource` 调 `SourceCaptureGuide.showMissingSourceDialog(project)`；`NoSource`（MP 分页 COUNT 标记）维持纯 info 提示——COUNT 查询无用户调用点，引导开拦截器也无意义。
- 删除 `resolveLiveJump` / `LiveJumpResolution` / `searchByTable` / `showCandidateChooser` 及 `SqlTableExtractor` 在此处的调用（`SqlTableExtractor` 本体他处仍用，不删）。
- `jumpToSourceForTest` 保留；`resolveEntryJump` 保持纯函数（MissingSource 分支不触 UI），headless 测试断言分支。

### 3.3 历史面板（HistorySqlLogPanel）

`NoSource` 分支由 `showInfoMessage` 改为 `SourceCaptureGuide.showMissingSourceDialog(project)`；`NotFound` 维持原提示（文件在、位置在，只是项目结构变了，与拦截器无关）。

### 3.4 移除清单

- 删文件：`log/WrapperSearchService.kt`、`test/.../WrapperSearchServiceTest.kt`。
- 删 i18n 键（双语各 5 处）：`log.panel.jumpToSource.noTable`、`.noWrapper`、`.multipleTitle`、`.multipleHeader`，及 `log.history.jumpToSource.noSource`（历史面板 NoSource 改走引导弹框后无消费方；实时面板同名键 `log.panel.jumpToSource.noSource` 仍服务 MP COUNT 提示，保留但文案改为「分页 COUNT 查询由 MyBatis-Plus 自动发出，无用户调用点」语义，消除「F-44 之前捕获」旧表述）。
- 新增 i18n 键（双语）：
  - `log.jump.guide.title` = 无法跳转到源码 / Cannot Jump to Source
  - `log.jump.guide.message` = 该 SQL 条目未携带源码位置。插件通过运行期 SQL 拦截器捕获真实调用点实现精确跳转。\n\n可打开插件设置启用源码捕获，或直接生成拦截器代码（生成后需重启应用生效）。 / (en 同义)
  - `log.jump.guide.openSettings` = 打开设置 / Open Settings
  - `log.jump.guide.injectNow` = 立即注入拦截器 / Inject Interceptor Now
  - `log.jump.guide.cancel` = 取消 / Cancel
  - 注入结果四键（从 PluginSettingsPanel 硬编码文案 i18n 化迁入）：`log.inject.success` / `log.inject.alreadyExists` / `log.inject.unsupported` / `log.inject.cannotDetect`（zh 沿用现文案原文）。
  - bundle parity 守卫测试自动把关双语对称。

### 3.5 测试
