## 一、需求分析与截图语义

### 1.1 截图逐行解读

截图（存档 `docs/images/t-vstack-requirement.png`，右上「压缩」按钮即本插件预览弹窗多行模式的 modeButton）：

```sql
INSERT
INTO `user`
(
  username,
  password
)
VALUES
(
  username 'zhangsna',
  password '123456'
)
```

三个诉求层：

1. **主子句竖排**：INSERT / INTO `user` / 列清单 / VALUES / 值清单各占一行；
2. **列清单逐行**：括号内一列一行；
3. **列-值配对（截图的灵魂）**：VALUES 区每行「列名 + 值」并排出现——大 INSERT 里哪个值对应哪列一目了然，不用数逗号。

### 1.2 与现有显示形态的定位差异

| 形态 | 入口 | INSERT 括号清单现状 |
|---|---|---|
| 压缩 | modeButton / `result.compactSql` | 全挤一行 |
| 多行（原始） | modeButton | 原样保留 |
| 格式化（全展开） | 格式化按钮 / Ctrl+Alt+L | **括号内同行**——`INTO t (a, b, c) VALUES (1, 2, 3)`（SqlFormatter.kt:126-134 `parenNewlined=false` 路径，测试基线 `testClauseLineInsertValues` 同证） |
| 关键字换行 | 关键字换行按钮 | **括号内同行**（SqlFormatter.kt:292-306，设计即「子查询同行」） |
| **竖向排列（本计划）** | 新按钮 | 列清单逐行 + VALUES 逐行配对——现有四形态的空缺带 |

结论：竖向排列不是又一个「整体风格」变体，而是补上**括号清单展开 + 列-值对位标注**这一格。

## 二、设计决策（含备选否决）

### D1：VALUES 配对语义——合法 SQL + 行尾 `-- 列名` 对齐注释（推荐）

```sql
INSERT
INTO `user`
(
  username,
  password
)
VALUES
(
  'zhangsna',  -- username
  '123456'     -- password
)
```

预览编辑器是**活文档**：复制 SQL / 复制可执行 SQL / 执行 SQL / 差异对比 / 分享全部直接吃编辑器文本（copySql :1230、copyExecutableSql :1258、showSqlDiff）。配对标注若以破坏语法为代价会顺着这些链路外流成坏 SQL，这是不可接受的副作用。

- **备选 B（截图原样 `username 'zhangsna'` 直排）——否决**：产物非法。截图来源工具是纯展示视图，我们是可编辑可执行的文档，本质不同。
- **备选 C（改写为 MySQL `INSERT ... SET col=val`）——否决**：改写语句形态、方言绑定、批量多行 VALUES 无法表达。
- 行尾注释用 `-- 列名`（双横线 + 空格，MySQL/标准兼容），按值列最长显示宽补空格对齐；复制 SQL 已有 `SqlCommentStripper.strip` 剥注释先例（:1236），注释不污染复制产物；执行时注释天然无效化。

### D2：语句覆盖面——INSERT 专用路径，其余全部委托 `format()`

逐语句核对 `format()` 现状后确认，竖排缺口**只在 INSERT**：

- SELECT：列清单已换行（:101 `SELECT` → newline+4）、顶层 AND/OR 已缩进换行（:106-115）；
- UPDATE：SET 赋值清单已换行（:101 `SET` 分支 + :152 SET 逗号换行）——`col = val` 天然配对；
- DELETE：WHERE 条件已换行；
- IN (…) 清单：**决策不展开**（保持 format 现状同行）——IN 元素普遍量少且横排语义紧凑，展开徒增弹窗高度；后续有反馈再立项。

因此 `formatVertical()` = 首主子句为 INSERT 时走专用展开，否则原样委托 `format()`。

### D3：一次性文本变换，非持久模式

与格式化/关键字换行同形（`WriteCommandAction` + `doc.setText`，:1187-1204 先例），不新增持久状态。理由：压缩模式 × 关键字换行 × 竖向排列若组合成持久态，模式矩阵爆炸且「刷新=回到默认状态」语义（M19.3）需为每个组合定义复位值；一次性变换刷新即复位，天然兼容。

### D4：按钮直显，置于「关键字换行」之后

格式化族高频动作直显（与 T-PreviewTopOverlap F2 分组决策「格式化/关键字换行直显」同理由）。工具栏折叠后现直显 5 个（模式/格式化/关键字换行/刷新/更多），加 1 个约 +64px，总宽约 394px 仍低于折叠前 450px 基线，宽度预算成立。

### D5：XML 预览场景不设守卫

XML 渲染模式下编辑器文本为 XML 时，点竖向排列的最坏结果是文本被 SQL 化重排——与既有「格式化/关键字换行」按钮在同场景的行为完全一致，单步 undo 可回（WriteCommandAction 一个命令）。不为新按钮单造守卫，不扩大范围。

## 三、方案设计

### F1：`SqlFormatter.formatVertical(sql)`（ui/highlight/SqlFormatter.kt）

**路由**：`lex()` 分词后，token 流首个主子句关键字（跳过注释）为 `INSERT` → 专用路径；否则 `return format(sql)`。

**INSERT 专用路径**（复用 lex token 流，在顶层重组）：

1. 列清单组：INSERT 语句中第一个 depth 0→1 的括号组（VALUES 关键字之前），组内按 **depth==1 的逗号** 切分元素，一元素一行、缩进 2、行尾逗号紧贴；
2. VALUES 组：`VALUES` 之后每个 depth 0→1 括号组为一个行组：
   - 组内按 depth==1 逗号切分值表达式；**depth 守卫整段保留**——函数调用（`NOW()`、`CONCAT(a,b)`）内部逗号/括号原样（值表达式内部原文空格保留，不重排）；
   - 每值一行缩进 2，行尾逗号紧贴；最后一个值行不带逗号；
   - **配对注释**：与列清单按序对位，行尾补空格至对齐宽后追加 `-- 列名`；对齐宽 = 各列名 `String.length` 最大值；值个数少于列数（部分插入）按实际个数标注，多于列数不标注不抛错；
3. 批量多行 INSERT：行组间 `),` 换行 `(` 接排（每组竖排同上）；
4. 其余 token（INSERT/INTO/表名/VALUES 关键字、句尾内容）沿用 `format()` 排布规则——INSERT/INTO/VALUES 主子句顶格各一行（NEW_LINE_KEYWORDS 已含三者）；
5. 既有 SQL 内注释 token：原位保留（COMMENT token 透传），不参与对位标注。

**输出不变式**（测试断言利器）：剔除 COMMENT 后重 `lex()`，token 序列与原文完全一致——竖向排列只改空白与新增行尾注释，绝不动任何 SQL 语义 token；且 `formatVertical(formatVertical(x)) == formatVertical(x)` 幂等。

## 七、API 权威核实清单与风险

| # | 疑点 | 核实方式 |
|---|---|---|
| 1 | SqlLexer 对 `--` 行尾注释新增文本的分词（我们**输出**含 `--` 注释的 SQL，再次点击按钮时**输入**含注释） | SqlLexer.kt 通读 COMMENT 分支；F3-12 用例覆盖「含注释再变换」——lex 剔注释后的 token 等价断言天然消化二次输入 |
| 2 | `-- ` 注释在 MySQL 方言执行链路的合法性 | 标准 SQL/MySQL 均要求双横线后空格，输出固定 `-- ` 带空格；执行走 Database 控制台原生执行器，注释为语法级无害 |
| 3 | JButton + bundle 新键 | 与 keywordWrap（M-KeywordWrap 70f8383 已交付）完全同构，先例即权威，零新平台 API |
| 4 | WriteCommandAction 写共享控制台文档 | formatSql/formatClauseLine 同路径现网先例（:1187-1204），T-RefreshDbSteal 卫队只管监听归属不改写路径 |

风险：① 中文列名对齐宽按 `String.length` 非显示宽——注释对齐仅观感项，可接受，不引入字体度量复杂度（T-PreviewTopOverlap F3 已有度量先例，确有反馈再复用）；② 「竖向排列」与「格式化」在 SELECT 等语句上输出相同、用户困惑两按钮区别——tooltip 写明 INSERT 专属增强；③ 深度嵌套子查询 INSERT（`INSERT INTO t SELECT ...`）——路由只认 INSERT 主子句，SELECT 形态 INSERT 直接退化 format()，不硬解。
