## 一、背景与依据

本插件的 XML 引擎（M24 复刻 MyBatis 渲染算法）在预览时对 `${}` 做直替——字符串原样拼进 SQL，无参数转义，这是 MyBatis 语义的忠实复刻，也是注入风险的第一现场。竞品 Analyzer 把「`${}` 注入标注」做成了它的差异化细节；本插件渲染正确性远强于对方，但这个提示位是空的。第三轮立项建议后第四轮 grep 复核仍零实现（预览渲染链无任何 ${} 警示）。本轮收口，且刻意收敛为**低风险形态**：先做横幅提示（DegradationBanner 既有机制），不做行内高亮（需要渲染管线跟踪替换区间，成本收益比差，留二期）。

## 二、现状核实（dev 实测）

| 面 | 现状 | 位置 |
|---|---|---|
| ${} 直替点 | XML 引擎预览求值时直替（XmlPreviewService 占位展开链；引擎本体 xml/ 包节点求值） | `ui/XmlPreviewService.kt`、`xml/` 包 |
| 横幅机制 | DegradationBanner 非模态单行，RENDER_WARNING/DEGRADED 双类别优先级，三个触发面接线完成（SqlPreviewPanel.updateMeta、createEditor 降级链、LogToSqlPanel 转换区）——T-PreviewUx-Pack #2 交付 | `ui/DegradationBanner.kt:23` |
| 渲染产物 | 预览文本 = 渲染后 SQL（含模拟参数/直替结果），行尾标注链已有先例（(new) 列 annotate） | `ui/highlight/SqlFormatter.kt` |
| 现状缺口 | 渲染结果对「是否含 ${} 直替片段」零记录、零提示；用户无法区分 #{} 安全替换与 ${} 直替产物 | — |

## 三、方案

**T-DI-01（引擎侧点位记录，纯逻辑）**：XML 引擎求值链在 ${} 直替发生时记录计数（渲染结果附带 `dollarSubstitutions: Int` 或复用既有渲染结果元结构新增字段）；不记录区间（区间跟踪留二期）。核心是**纯函数、零 UI 依赖**，对齐引擎既有测试风格。历史双击预览、单击预览、gutter 预览三条产物链同源，一处记录全链受益。

**T-DI-02（横幅接线）**：`dollarSubstitutions > 0` 时，预览面板 DegradationBanner 显示提示行（新类别或复用 RENDER_WARNING 类别，措辞中性）：「预览含 N 处 ${} 直接替换——文本未转义，注意注入面」。banner 可关闭（沿用既有交互），不阻塞任何操作。三个触发面（SqlPreviewPanel/LogToSqlPanel 转换区/createEditor 降级链）只接预览主面板两处，LogToSqlPanel 转换区是否需要看产物形态定（多语句产物通常来自日志还原，不含 ${} 语义——默认不接，除非 T-DI-01 记录显示该链有直替发生）。

**T-DI-03（i18n + 测试）**：双语新键 2~3 个（banner 文案 + 关闭态 tooltip）；测试：引擎侧计数纯函数表驱动（含 `${}` 嵌套在 `<if>`/`<foreach>` 内、字符串内 `${}` 不计、转义形态）；banner 触发条件用例（0 处不显示、N 处显示且计数正确、关闭后本会话不再弹）。

**T-DI-04（文档同步）**：CHANGELOG [Unreleased] Added、变更记录总册行、第四轮报告 §8.4 O-11 状态回填。

## 四、验收标准

1. 含 ${} 的 mapper 预览显示横幅且计数正确；纯 #{} 预览零横幅（无误报）。
2. 引擎侧计数为纯函数、有表驱动测试；渲染产物文本逐字节零变化（只加元数据，不改渲染——防回归断言）。
3. 弹窗克制红线不触（横幅非模态、可关闭、无新弹窗）。
4. 全量 test 绿（基线 4246/0/0/6 + 新增数），跑前按铁律并行登记。

## 五、真机走查清单（留人工）

1. 真 mapper（含 `<if>` 内 `${orderBy}` 动态排序列）预览：横幅出现、计数与 ${} 出现次数一致、SQL 文本与标注前逐字节一致。
2. 纯 #{} mapper 预览：无横幅。
3. 关闭横幅后切其他文件再回来：交互符合设计（会话内记忆或重新显示，以实现为准记录行为）。

## 六、风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 渲染管线改动引入回归 | 计数字段穿透多层渲染结构 | 只在渲染结果元结构追加字段，默认值 0，既有消费者无感；逐字节断言兜底 |
| 横幅疲劳 | 常用 `${orderBy}` 场景每次都弹提示惹人烦 | 可关闭 + 措辞中性（提示不警告）；必要时阈值化（≥1 处显示，不逐条计数刷屏） |
| 字符串内 `${}` 误计 | SQL 字面量里的 `${}` 不是 MyBatis 占位 | 计数只在引擎求值路径发生，字符串字面量内的 `${}` 不走求值——测试样例锁死该语义 |
| Analyzer 同款形态抄袭嫌疑 | 无（提示位是通用正确性实践） | 文案自写，不搬对方措辞 |
