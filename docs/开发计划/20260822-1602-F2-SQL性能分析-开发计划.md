## 0. 目标

在预览 SQL 生成后，对其进行静态分析，输出性能风险警告和优化建议。不需要连接真实数据库——完全基于 SQL 文本结构分析。

**用户价值**：写完 Wrapper 链后立即发现潜在性能问题（如 LIKE 前导通配符、JOIN 无条件、子查询过深等），避免上线后慢查询。

## 1. 技术方案

### 1.1 核心依赖：JSqlParser 5.3

| 指标 | 值 |
|------|-----|
| Maven 坐标 | `com.github.jsqlparser:jsqlparser:5.3` |
| 体积 | ~1.26 MB |
| 依赖 | 零编译/运行时依赖 |
| 方言 | MySQL、PostgreSQL、Oracle、SQL Server、H2 等 |
| 许可证 | LGPL 2.1 / Apache 2.0 双许可 |

**选型理由**：体积最小、零依赖、MySQL 支持好、Visitor 模式便于提取 JOIN/WHERE/子查询结构。

### 1.2 架构

```
PreviewResult.sql（已有）
  → SqlPerfAnalyzer.analyze(sql)           [新增，核心入口]
      ├── JSqlParser 解析为 Statement AST
      ├── PerfRuleEngine.apply(statement)   [新增，规则引擎]
      │   ├── MissingWhereRule              [已有 UPDATE/DELETE 无 WHERE 警示]
      ├── LeadingWildcardLikeRule           [LIKE '%xxx' 前导通配符]
      ├── JoinWithoutOnRule                [JOIN 缺少 ON 条件]
      ├── SelectStarWithJoinRule           [SELECT * + 多 JOIN]
      ├── SubqueryDepthRule                [子查询嵌套 > N 层]
      ├── InClauseOverflowRule             [IN 子句 > 100 项]
      ├── FunctionOnIndexedColumnRule      [WHERE UPPER(col) = ...]
      ├── OrderByWithoutLimitRule          [ORDER BY 无 LIMIT]
      ├── ImplicitTypeConversionRule       [隐式类型转换]
      ├── OrConditionRule                  [多个 OR 条件]
      ├── CorrelatedSubqueryRule           [关联子查询]
      ├── NoLimitOnLargeResultRule         [无 LIMIT + 多 JOIN]
      ├── DistinctWithJoinRule             [SELECT DISTINCT + JOIN]
      ├── GroupByWithoutAggregateRule      [GROUP BY 无聚合]
      ├── OrderByRandRule                  [ORDER BY RAND()]
      ├── UnionInsteadOfUnionAllRule       [UNION 可改 UNION ALL]
      └── ...（可扩展）
      → List<PerfWarning>                  [输出：性能警告列表]
  → SqlPreviewPanel 警告区展示            [新增 UI]
```

### 1.3 新增文件

| 文件 | 职责 |
|------|------|
| `sql/SqlPerfAnalyzer.kt` | 核心入口：SQL 文本 → 警告列表 |
| `sql/perf/PerfRule.kt` | 规则接口（id, severity, message, check()） |
| `sql/perf/PerfRuleEngine.kt` | 规则引擎：注册 + 执行所有规则 |
| `sql/perf/PerfWarning.kt` | 警告数据类（ruleId, severity, message, line） |
| `sql/perf/rules/` | 各规则实现（每个规则一个文件） |

### 1.4 改动文件

| 文件 | 改动 |

## 2. 规则清单（20 条，分三批实施）

### 第一批（基础规则，无需 AST 解析，正则即可）

| # | Rule ID | 严重度 | 检测逻辑 |
|---|---------|:------:|----------|
| 1 | `missing_where` | 🔴 ERROR | UPDATE/DELETE 无 WHERE（已有，迁移到规则引擎） |
| 2 | `leading_wildcard_like` | 🟡 WARN | `LIKE '%xxx'` 前导通配符，无法使用索引 |
| 3 | `select_star` | 🟡 WARN | `SELECT *` 多表 JOIN 时风险 |
| 4 | `order_by_without_limit` | 🟢 INFO | ORDER BY 无 LIMIT，可能返回大量数据 |
| 5 | `order_by_rand` | 🟡 WARN | `ORDER BY RAND()` 全表排序 |
| 6 | `union_instead_of_union_all` | 🟢 INFO | UNION 去重有额外开销 |

### 第二批（需要 AST 解析，JSqlParser）

| # | Rule ID | 严重度 | 检测逻辑 |
|---|---------|:------:|----------|
| 7 | `join_without_on` | 🔴 ERROR | JOIN 缺少 ON 条件（笛卡尔积风险） |
| 8 | `subquery_depth` | 🟡 WARN | 子查询嵌套 > 2 层 |
| 9 | `in_clause_overflow` | 🟡 WARN | IN 子句 > 100 项 |
| 10 | `function_on_column` | 🟡 WARN | `WHERE UPPER(col) = ...` 函数包裹列 |
| 11 | `or_condition_count` | 🟢 INFO | WHERE 中 OR 条件 > 3 个 |
| 12 | `distinct_with_join` | 🟢 INFO | SELECT DISTINCT + JOIN（可能缺 JOIN 条件） |
| 13 | `group_by_without_aggregate` | 🟢 INFO | GROUP BY 无聚合函数 |
| 14 | `no_limit_large_result` | 🟡 WARN | 无 LIMIT + 多 JOIN + 无 WHERE |

### 第三批（高级规则）

| # | Rule ID | 严重度 | 检测逻辑 |
|---|---------|:------:|----------|
| 15 | `correlated_subquery` | 🟡 WARN | 关联子查询（每行执行一次） |
| 16 | `implicit_type_conversion` | 🟡 WARN | WHERE 列与字面量类型不匹配 |
| 17 | `between_on_dates` | 🟢 INFO | BETWEEN 日期范围查询 |
| 18 | `nested_subquery_in_select` | 🟢 INFO | SELECT 子句子查询 |
| 19 | `offset_pagination` | 🟢 INFO | 大偏移量 LIMIT（如 LIMIT 10000, 10） |
| 20 | `multiple_group_by_orders` | 🟢 INFO | 复杂 GROUP BY + ORDER BY 组合 |

## 5. 边界与降级

- JSqlParser 解析失败（极少数 MySQL 特有语法）：降级到纯正则规则，不阻塞预览
- 单表简单查询：无警告，不显示警告区
- 规则执行异常：单规则 try-catch 隔离，不影响其他规则
- 警告数量上限：最多显示 10 条，超出折叠
