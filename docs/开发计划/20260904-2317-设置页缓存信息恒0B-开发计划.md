# 设置页缓存信息恒 0 B——根因分析与修复开发计划

> 任务名：cache-info-0b-fix（任务 ID：T-CacheInfo）　日期：2026-09-04　状态：已实施

## 一、问题描述

设置页「更新与诊断」分组的插件缓存行（`settings.cache.info=当前缓存：{0}`）在真实使用中**一直显示 0 B**，用户怀疑缓存功能未生效。

## 二、根因分析

展示链路本身是通的：`PluginSettingsPanel.refreshCacheInfo()` 在面板构造时读取
`PluginCacheManager.sizeBytes(project)` 并写入标签（`PluginSettingsPanel.kt:845`）。问题出在**统计口径**：

1. **只统计了几乎不会填充的缓存**。`PluginCacheManager.sizeBytes` 仅累计
   `EntityClassFinder.reverseLookupCacheSizeBytes`（@TableName 反查兜底缓存）。该缓存只在
   「类名推断快路径未命中」时才填充（`EntityClassFinder.kt:72` findByTableNameAnnotationCached）。
   真实 MP 项目实体命名惯例（`XxxEntity` ↔ `xxx`，含去首段变体）下快路径恒命中，
   反查缓存恒为空 → 展示恒 0 B。
2. **真正积累的两类缓存完全未计入**：
   - `EntityResolver` 解析缓存（T-EntityCache，companion 全局静态 `ConcurrentHashMap`）——
     每次转换都会填充；`clearAll` 有清它，统计没算它；
   - `SqlPreviewService` 的 `WrapperCache`（项目服务实例）——预览解析结果按文件+锚点积累、
     只增不减；`clearAll` 既不清也不算（与「清除插件全部缓存」的 tip 承诺不符）。

结论：机制「正常」，但指标选错对象——对用户而言功能未达预期，需修复。

## 三、修复方案

### 3.1 统计口径扩展

- `EntityResolver` 新增 `cacheSizeBytes()`（internal）：键/值字符串按 UTF-16 每字符 2 字节 +
  每条目/每列固定开销近似（展示用，与反查缓存估算同一口径；PsiFile 引用不计）。
- `WrapperCache` 新增 `clear()` / `size()` / `sizeBytes()`（每条目固定开销近似）。
- `SqlPreviewService` 暴露 `clearWrapperCache()` / `wrapperCacheEntryCount()` / `wrapperCacheSizeBytes()`。
- `PluginCacheManager`：
  - `totalSizeBytes(projects)`：Σ 项目级反查缓存 + **全局解析缓存（只计一次）** + Σ Wrapper 缓存；
  - `entryCount(projects)`：三类缓存条目数合计（给用户「缓存确实在积累」的直观信号）；
  - `clearAll(project)` 增加 Wrapper 缓存清除，经 `getServiceIfCreated` 访问——**清除动作不得触发服务实例化**；
  - 原 `sizeBytes(project)` 保留（项目级反查部分，语义不变）。
- `PluginSettingsPanel.refreshCacheInfo()` 改用 `totalSizeBytes` + `entryCount`。

### 3.2 文案（en/zh 同步）

- `settings.cache.info`：`Cache size: {0} ({1} entries)` / `当前缓存：{0}（{1} 项）`
- `settings.cache.tip`：更新为「实体解析、反查、预览解析等」。

### 3.3 测试

- 新增 `PluginCacheManagerCoverageTest`（HeavyPlatformTestCase，依赖真实索引）：
  快路径命中复现恒 0 B 场景 / totalSizeBytes·entryCount 非零 / 慢路径对照 / clearAll 归零 /
  clearAll 不实例化服务。
- 新增 `WrapperCacheTest`（BasePlatformTestCase）：put → size/sizeBytes 非零 → clear 归零。
- 存量 `PluginCacheManagerTest`、`PluginSettingsPanelBindingTest.testCacheInfoAndClearButton`
  应保持通过（后者断言含 "B"，新文案仍满足）。
