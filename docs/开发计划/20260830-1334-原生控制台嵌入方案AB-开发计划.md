## 一、背景与问题（M36.5 反复横跳的总结）

M36.5 系列目标：把 IDE **原生 SQL 控制台**（DBN：Database 工具窗的 JdbcConsole）融合进插件的「SQL 预览面板」右侧，获得原生能力（▶ 执行按钮、SQL 语法高亮、Result 数据表格、CSV 导出、Console output）。

**反复出现的问题链**（08-28 至 08-30 实测）：

| 问题 | 根因（沙盒日志实证） |
|---|---|
| 首次预览 SQL 被遮住/塌缩 | 只嵌顶部块（无 SplitPane divider 修复），BorderLayout 按 preferred=0 分配 |
| ▶ 执行按钮灰 + 无绿色选中框 | `ScriptModel` 基于 console vf PSI 的 model 缓存陈旧（isActual 只比较 splitScriptMode）；后定位到 `isStatement` 过滤失败（language 不匹配） |
| 执行后结果区不显示/整个右侧空白 | **根因级**：把 DBN 的 RunnerLayoutUi 组件直接 add 进我们面板 → DBN `results refreshed` 期间**临时拿走该组件/祖先链 show=false 1-2s**，我们面板显示链被波及 |
| 8s 误报凭据提示 | 复用 console 时 DBN 复用 Result tab 不改名 → `newTab=false` |
| 补全字段错误/无候选 | 复用 console 时 `onNativeEditorReady` 不再触发，console editor userData 停留在旧表 |

**结论**：M36.5 的"拆解 DBN 组件再自行组装"路线（buildConsoleSplitPane = 工具栏 + 编辑器 + 结果区）是错误方向——DBN 内部重建时我们的组装必然被破坏。**必须改为"整个 DBN 控制台作为一个整体嵌入"**，并解决 DBN 重建期的显示链隔离。

---

## 二、目标

1. 预览面板右侧 = **整个 DBN 原生 SQL 控制台**（▶ 工具栏 + SQL 编辑器 + Tx/Result 结果区），布局由 DBN 自己管理。
2. DBN `results refreshed` 期间面板显示链**不断裂**（结果区不消失）。
3. ▶ 执行按钮可用、语句绿色选中框恢复、补全字段跟随当前表。
4. **Community（社区版）IDE**：无 Database 插件 → **回退自研面板**（自研 SQLEditor + 参数区），功能不退化。

## 四、方案 A：包装容器隔离 + 自动重挂（M36.5.39 已实施）

### A1 身份探针（已实施）

- **目的**：判定 DBN results refreshed 后 console 组件是同一对象（A 可治）还是被替换（需 B）。
- **实现**：`SqlPreviewPanel.embedConsole` 入口打点
  `embedConsole identity: id=…, prevEmbedded=…, sameAsPrev=…, prevId=…`；
  新增字段 `lastConsoleEmbeddedId`。

### A2 持久包装容器 consoleHost（已实施）

- **目的**：DBN 拿走 console 组件时，只清空 consoleHost 子层，editorHolder/显示链稳定。
- **实现**：
  - `consoleHost = JBPanel(BorderLayout)`，只 `add` 到 `editorHolder` **一次**；
  - `performEmbed` 改走 `hostIntoConsoleHolder(consoleComponent)`（removeAll + add + validate）；
  - `detachConsole` 改为清空 consoleHost（容器保留）。
- **对比**：旧实现直接 `editorHolder.add(consoleComponent)`，DBN 拿走时整个 holder 显示链断裂（12:20/12:45 日志 `holderShowing=false, spDisplayable=false`）。

### A3 hierarchy 自动重挂（已实施）

- **目的**：DBN 释放组件后自动重新挂回，无需等 30s 轮询。
- **实现**：`consoleComponent.addHierarchyListener` 监听 `PARENT_CHANGED`；
  - **仅当 `parent == null`（DBN 完全释放）且 `=== embeddedConsole`（同一对象）时**，
    `invokeLater { rehostConsoleForTest(component) }` 重挂；
  - **不抢** DBN 临时 reparent（`parent != null`）的组件，避免竞争；
  - rehost 检查逻辑抽为同步方法 `rehostConsoleForTest`（可单测）。

### A4 直接 embed `JdbcConsole.getComponent()`（2026-08-30 已实施，API 有偏差，见第十一节）

- **目的**：不再拆解 DBN（buildConsoleSplitPane / divider 强制 / 工具栏注入全部移除）。
- **实现**：`onConsole` 回调直接传 `console.getComponent()` 给 embedConsole；
  - DBN Console 自带"▶ 工具栏 + SQL + Tx/Result"完整布局；
  - 删掉 `buildConsoleSplitPane`、`startSplitPaneForce`、`buildHeaderComponent` 调用等拆解逻辑；
  - DataContext 链自然完整（▶ 灰、补全失效问题随 DBN 自身能力恢复）。
- **前置**：A1 确认 sameAsPrev=true 后实施。

### A5 验证（每步）

| 验证项 | 判据 |
|---|---|
| 布局 | 两个 SQL 连续执行，结果区都出现在 SQL 下方（`resultH > 100`） |
| 显示链 | 不再出现 `GAVE UP ... holderShowing=false` 超过 30s |
| ▶ 工具栏 | 绿色可点击 + SQL 绿色选中框（`statementsRange` 非零） |
| 补全 | 不同表间切换，补全字段跟随当前表 |
| 身份探针 | `sameAsPrev=true`（确认 A 路线有效） |

### A6 单测（已实施）

`ConsoleHostTest`（5 用例全通过）：
- `testEmbedGoesThroughPersistentHost`：嵌入走 consoleHost，容器稳定在 holder；
- `testDbnTakingChildKeepsHostAndRehosts`：DBN 拿走 → 显示链不断 + rehost 条件成立重挂；
- `testSameInstanceReembedIsIdempotent`：重复执行幂等；
- `testReembedReplacesOldChild`：换入新组件，旧组件摘除；
- `testDetachClearsHostButKeepsContainer`：清空预览时容器保留。

## 五、方案 B：主动接管 DBN 内容重建（A 失效时启用）

### B1 主动监听 contentManager 重建

- **目的**：A1 显示 `sameAsPrev=false`（DBN 替换 console 对象）时，主动获取新对象。
- **实现**：
  - 监听 `ui.getContentManager().addContentManagerListener`（现有 `attachResultsHook` 的
    `contentAdded`/`contentRemoved` 基础上扩展）；
  - `contentRemoved`（旧 console 组件被 DBN 移除）→ 记录旧 id，启动重取轮询；
  - `contentAdded` / RunnerLayoutUi 组件变化 → `ui.getComponent()` 取新组件 → 重新 embed。

### B2 重建时取新组件

- 复用 `refreshResultsComponent` 的 `ui.getComponent()` 路径；
- 扩展：不只换结果区，**整个 console component** 被替换时整体换入（`consoleHost` 重新 host 新对象）；
- 保证旧对象的 hierarchy 监听解绑（避免泄漏）。

### B3 自建 console（极端兜底）

- **触发**：B1/B2 仍不稳定，或 DBN API 不开放独立生命周期。
- **实现**：`SqlPsiFacade.createScriptModel` + `DatabaseConsoleView`/`SqlConsoleView`
  自建实例、自己 attach/detach、自己 dispose（不依赖 DatabaseConsoleManager 的 ToolWindow 模式）。
- **风险**：DBN 内部 API 可能不开放，需反射；工时最高。

## 六、社区版回退（自研面板，必须保持）

**Community（社区版）IDE 没有 Database 插件**，DBN 控制台不可用。此时必须**静默回退自研面板**：

- **预览阶段**：自研 SQLEditor（`renderSql` 创建）+ 参数区铺满右侧（M36.5.25g 方案）；
- **执行阶段**：无 DBN → 使用自研执行通道（或提示安装 Ultimate）；
- **判据**：`SqlExecutor` 检测不到 Database 插件时 `isPrepared()=false`、`prepareConsole` 回调 `false`，
  `SqlPreviewPanel` 保持自研 editor 显示（`executeSql` 走非 DBN 路径）；
- **回归**：`testPrepareConsoleSilentFallbackWhenPluginUnavailable`（已有单测）必须保持通过。

**实施注意**：方案 A/B 的所有 DBN 依赖代码必须包在 `isDatabasePluginAvailable()` 判断后，
社区版不加载 DBN 相关类（避免 NoClassDefFoundError）。

### A4 的 API 偏差说明

计划中 A4 写的是"直接 embed `JdbcConsole.getComponent()`"，**该 API 不存在**（javap 本地
`intellij.database.impl.jar` 实证：`JdbcConsole` 只有 `getConsoleView/getUi/getView/getDocument/

- `ui.getComponent()`（RunnerLayoutUi）= **结果区**（M36.5 全系列沙盒实证，非整控台）；

  装入**持久 SplitPane**，构建一次不再重建，结果刷新原位换底——达成 A4 的真实目标：
  面板侧 embedConsole 身份稳定（sameAsPrev=true）+ 不拆解重组 DBN 组件。

### M36.5.43 沙盒实证修正（2026-08-30，方案 A 首测暴露两处）

首次沙盒验证（.idea/mpsql-exec.sql 执行链）暴露两个问题，均已修正：

**问题 1：File Cache Conflict 模态弹窗（阻塞执行链）**
- 日志实证：16:05:39 `MemoryDiskConflictResolver - reload mpsql-exec.sql from disk?`
  `documentStamp:1742 vs oldFileStamp:779`。
- 根因：`projectExecFile` 原实现 `existing.setBinaryContent(sql.toByteArray())` 只更新
  VFS+磁盘；console 编辑器在上次执行后已 hold 该文件的 document（内存副本），document 与
  磁盘 stamp 不一致 → MemoryDiskConflictResolver 弹模态框，冻结后续换入链。
- 修正：优先 **document 驱动**三方同步——`FileDocumentManager.getDocument(vf)` 存在时用
  `fileDoc.setText(sql)` + `PsiDocumentManager.commitDocument`（与 executeOnConsole 里
  "console doc synced+committed to vf" 已验证无冲突的同一模式）；仅 `fileDoc == null` 才
  `setBinaryContent`。

**问题 2：结果区被守卫拦在面板外（结果显示在 DBN 服务视图 IDE 控制台）**
- 日志实证：`result component held by DBN (parent=ServiceViewComponentWrapper) - skip this tick`
  连续数十拍（16:05:28→16:05:58），结果区始终未进预览面板。
- 根因：`swapResultIntoPersistentConsole` 的守卫 `liveResult.parent != null && != sp → 跳过`
  过度保守——`ServiceViewComponentWrapper` 是 DBN 服务视图的**长期宿主**（结果组件的"老家"，
  非 DBN 临时 reparent 中转），守卫把它误判为"临时持有"而每拍跳过，结果永远进不了面板。
- 修正：去掉该守卫，改为**强制换入**——只要 `liveResult` 是当前结果实例且 `parent !== sp`，
  就摘出挂回 SplitPane（保持 `sp.bottom == liveResult` 不变式）；被 DBN 抢走则下拍换回（幂等）。
  返回类型从 `JComponent?` 改为非空 `JComponent`（三处调用点同步简化）。

### M36.5.44 沙盒实证修正（2026-08-30，第二/三次执行暴露三问题）

用户实测两个 SQL 连续执行：布局已正常（A4 生效），但暴露三问题——页面持续闪烁、
首个 SQL 报"执行超时"误报、结果显示第二个 SQL 的旧数据（滞后一轮）。日志实证与修正：

**问题 1：页面持续闪烁（re-host 无限循环，最严重）**
- 日志实证：`console component released by DBN (id=238281604) → re-host` 在 16:40:50→16:42:21
  毫秒级刷屏 2753 次，`idea.log` 整文件被刷成 re-host + prompt cleared。
- 根因：`attachRehostListener` 监听整控台 SplitPane，DBN 在 results refreshed 窗口内**高频**
  reparent 它（parent 在 null↔consoleHost 间横跳）；`rehostConsoleForTest` 无防抖，每次
  parent==null 都重挂，挂回后 DBN 又拿走 → 死循环（闪烁）。
- 修正：rehost 加**最小间隔去抖** `REHOST_MIN_INTERVAL_MS=800ms`——两次释放间隔 < 800ms
  视为"DBN 仍忙于 reparent"，跳过不抢；真正释放（间隔 > 门槛）才挂回，兜底不丢。

**问题 2：滞后一轮（结果显示上一个 SQL 的数据）**
- 根因：`afterSubmitted` ③ 换入 `preparedResultComponent`（prepare 时捕获的**占位组件**，
  从未更新）。第二次执行时 ③ 把"首个 SQL 已换入的真实结果"覆盖回占位；随后
  `refreshResultsComponent` 的换入若时序落后 → 显示旧结果。
- 修正：③ 改用**实时结果组件**（`ui.getComponent()`），与 refresh 一致；拿不到则跳过，
  交由 refresh 兜底。

**问题 3：8s 执行超时误报（首个 SQL 实际成功却红字"执行超时"）**
- 根因：8s watch 判定 `!newTab || !namespaceOk` 双条件**任一为假即报超时**。首个 SQL 连接
  建立慢时（1-8s），`namespace` 暂空 + 结果 Tab 未出 → 误报。
- 修正：放宽为**只有"既无新 Tab 又无 namespace"**才提示凭据/驱动；任一生效即视为成功
  （`newTab || namespaceOk`）。

**新增换入代际（防跨执行 refresh Timer 互踩）**
- 字段 `swapGeneration`：`afterSubmitted` 真实提交时递增；`startResultTabRetry` 与
  `refreshResultsComponent` 捕获当前代际，Timer 回调时若代际已变（新执行覆盖本 watch）
  则丢弃并停止——彻底杜绝 SQL1 的 refresh Timer 晚到后覆盖 SQL2 新结果。
- `BUILD_STAMP` → `M36.5.44-swap-gen`。

| 风险 | 缓解 |
|---|---|
| A3 rehost 与 DBN 内部 reparent 竞争 | 只在 `parent==null` 时重挂，不抢 `parent != null` 的组件 |
| A4 直接 embed 后 DBN 布局期望不符（窄容器） | 保留 `buildConsoleSplitPane` 代码为 feature flag，可回退 |

| DBN API 不开放（B3 自建 console） | 反射兜底；或接受"换入完整工具窗"折中方案 |
| 30s 轮询资源占用 | `scheduleEmbedWhenShown` 到 30s 停止；A3 生效后轮询很少触发 |

## 十、关键教训（M36.5 全系列，防复发）

1. **缓存对象"新鲜度"判定必须与内容变更挂钩**（isActual 只比较配置，永不重建）。
2. **强制重建要用对数据源**——先找功能正常路径的构造方式，再让被修复对象走同一路径。
3. **探针必须区分"事件触发"与"主动触发"**——否则被上一次的正常数据误导。
4. **一次性监听（触发即移除）不能无条件触发后移除**——未就绪时的无效触发会永久吞掉后续机会。
5. **布局修正不能依赖"单次时机猜测"**（invokeLater/resize 都可能扑空），用"轮询到条件满足"的幂等重试。
6. **GridLayout 等"固定格子"布局，换入前必须 removeAll**——残留未知组件时静默失效。
7. **依赖"尺寸变化"事件的布局修正，在"换入同尺寸新组件"时静默失效**——必须主动强制。
8. **DBN 内部组件不要拆解重组**——DBN 重建时会破坏我们的组装，必须"整体嵌入 + 容器隔离"。
9. **isShowing 守卫不能放入口**——破坏测试和正常路径；"始终 add + 异步补救"更稳。
10. **Community 回退必须时刻保留**——DBN 是 Ultimate 专属，插件必须双版本兼容。
