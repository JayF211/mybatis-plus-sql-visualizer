# 开发计划

> 本文档是 **MyBatis-Plus SQL Visualizer** 的分阶段开发计划，任务编号（`T-xx`）稳定，供后续开发跟进与验收。
> 配套文档：[项目介绍](../项目介绍.md)、[功能概览](../需求文档/20260812-1058-MP-SQL可视化-需求文档.md)（功能编号 `F-xx` 在本计划中被引用）。
> 当前项目基线：Kotlin 2.3.20 + IntelliJ Platform Gradle Plugin 2.18.1 + IDEA 2025.3.5，基础包 `cn.song.mybatisplus.visualizer`，已生成模板骨架（`MyToolWindow` 示例可删除）。

---

## 1. 目标与原则

- **目标**：交付一个稳定、可发布到 JetBrains Marketplace 的 MP SQL 可视化插件；首个可用版本 v0.1 覆盖"查询类"闭环，v1.0 覆盖 CRUD + 联表 + 配置。
- **原则**：
  1. **核心先行**：转换引擎（纯逻辑）先于 UI 完成，保证可单测。
  2. **PSI 解析为主**：不依赖目标项目 classpath 动态加载 MyBatis-Plus，通过解析源码调用链 + 实体注解生成 SQL；若后续需精确对齐 MPJ 行为，再评估引入 MPJ 依赖做对照测试（见风险 R2）。
  3. **每里程碑可验收**：每个里程碑结束都有可运行的产物与通过的命令。
  4. **增量演进**：一个 Wrapper 类型跑通全链路后，再横向扩展其他类型。

### M1 核心转换引擎 v1（3~4 天）

**目标**：`LambdaQueryWrapper` 完整调用链 → 结构化 SQL 模型 → SELECT 文本（F-01），并具备表名/列名解析（F-13）。

| 任务 | 说明 | 依赖 | 验收 |
|------|------|------|------|
| T-M1-01 | 定义内部模型：`WrapperChain`、`Condition`、`SqlStatement`、`SelectStatement` | M0 | 模型类 + 单测 |
| T-M1-02 | PSI 定位：从 `PsiElement` 向上找 Wrapper 变量声明与调用链（支持链式 + 变量接力） | M0 | 单测：链式/分步两种写法均识别 |
| T-M1-03 | PSI 解析 Lambda：`Entity::getXxx` → 字段 → 列名；`new LambdaQueryWrapper<Entity>()` 泛型提取 | T-M1-02 | 单测：getter 反解、泛型提取 |
| T-M1-04 | 实体解析（F-13）：`@TableName` / `@TableField` / `@TableId` 注解读取 + 命名策略推断（下划线转驼峰） | T-M1-03 | 单测：注解/无注解两种场景 |
| T-M1-05 | 条件解析：`eq/ne/gt/ge/lt/le/like/in/notIn/between/isNull/isNotNull/and/or(嵌套)` | T-M1-03 | 单测：每操作一个用例 |
| T-M1-06 | 结构解析：`select()`、`groupBy()`、`having()`、`orderByAsc/Desc`、`last()`/`limit` | T-M1-03 | 单测：完整 SELECT 文本 |
| T-M1-07 | SQL 生成器：模型 → 文本（含 `?` 占位符、关键字大写） | T-M1-05, T-M1-06 | 单测：与手写 SQL 逐字比对 |
| T-M1-08 | 健壮性：无法解析的调用 → 可读占位提示，不抛异常 | T-M1-05 | 单测：异常输入用例 |
| T-M1-09 | 缓存（F-20）：按 `PsiFile`+modificationStamp 缓存解析结果 | T-M1-07 | 缓存命中/失效单测 |
| T-M1-10 | 创建 `docs/验收脚本.md`：runIde 手动验收步骤 + 预期 SQL 对照表（M3/M4 里程碑沿用并增量补充） | T-M1-07 | 脚本覆盖 M1 验收场景 |

> 里程碑验收：
> - `./gradlew test` 全绿（本里程碑新增单测 ≥ 30 个）
> - `runIde` 中手动验证：把示例 `LambdaQueryWrapper` 代码转出正确 SELECT（按 T-M1-10 创建的 `docs/验收脚本.md` 执行）

## 4. 测试策略

| 层级 | 工具 | 覆盖范围 |
|------|------|----------|
| 单元测试 | JUnit 4（现有）+ Kotlin 测试 | converter/model/sql 纯逻辑：SQL 文本、参数替换、格式化、方言（不依赖 IDE，可快速运行） |
| PSI 测试 | `com.intellij.testFramework.fixtures.BasePlatformTestCase`（LightPlatform） | psi 包：调用链定位、Lambda 解析、实体注解读取 |
| 手动验收 | `runIde` + `docs/验收脚本.md` | 右键/快捷键/悬停/工具窗口/配置联动 |
| 发布校验 | `verifyPlugin` / `buildPlugin` | 插件描述、兼容性、打包 |

**测试文件规范**：`src/test/kotlin/...`，每个 converter 一个测试类，命名 `XxxConverterTest`，SQL 断言用多行字符串逐字比对。

## 5. 关键风险与应对

| 编号 | 风险 | 影响 | 应对 |
|------|------|------|------|
| R1 | PSI 解析 Lambda/泛型在复杂代码（继承、泛型擦除）下失败 | 转换不准 | 降级提示 + 增量补用例；解析器抽象隔离，允许按类逐项增强 |
| R2 | MPJ 联表别名/`on` 规则与实现不符 | 联表 SQL 错误 | 以 MPJ 官方 javadoc/测试输出为准建立对照用例（T-M4-06）；必要时本地引入 MPJ 源码做参考 |
| R3 | 实体表名/列名推断与用户项目实际配置不一致 | 表名列名错误 | 支持注解优先 + 配置覆盖（F-13/F-16）；提供"手动指定表名"兜底（P2） |
| R4 | 悬停触发频繁导致卡顿 | 体验差 | 解析缓存（F-20）+ 悬停延迟；全部在后台线程计算，EDT 仅渲染 |
| R5 | IDEA 版本 API 变动 | 兼容性问题 | 锁定 2025.3.5 基线；对易变 API（PSI、高亮）做薄封装层 |
| R6 | 方言差异（分页/字面量）实现成本被低估 | 工期超支 | M5 先只做 MySQL（P0 场景），PG/Oracle 作为 P1 增量，不影响主线 |
