# 更新安装失败与通知修复——开发计划（T-M28.3）

> 状态：✅ 已交付（2026-08-15，812 测试全绿，804 → 812 +8；含并行会话 T-M29.4/29.5 增量）。
> 交付备注：路径归一化根因实证（2026.2 descriptorPath URL 风格）；通知标题/内容按用户要求调整；权限加固按用户要求补充。
> 需求来源：2026-08-15 用户实测（日常 IDE）——① 提示新版本时没有提示插件名，更新内容只需保留标题；② 更新失败（`current installation is not under the IDE plugins directory`）；③ 用户补充：下载后的插件包文件权限不得导致安装失败。
> 方案选定：用户确认——① 目录守卫 `normalizeDescriptorPath` 归一化（URL 风格/驱动字母前导斜杠）；② 通知标题带插件名、内容只留标题行、失败专用标题；③ `ensureReadable` POSIX 644 加固。
> 当前基线：T-M28.2 已交付（800 全绿）+ 并行会话 T-M29.2/29.3 已交付；HEAD 随并行会话推进。
> 任务编号源：本文档（T-M28.3-xx）。

## 1. 目标

1. **P0-1 更新安装恢复**：修复目录守卫误拒（2026.2 descriptorPath URL 风格），「立即更新」可走完安装调度 → 重启提示。
2. **P0-2 通知体验**：发现新版通知标题带插件名、内容只保留变更日志标题行；失败通知标题「更新失败」。
3. **P0-3 权限加固**：下载包持久化副本显式可读（POSIX 644），防 Mac/sudo 场景安装失败。
4. **P1-1 诊断**：守卫拒绝时日志含原始 descriptorPath。

## 2. 方案设计

- **T-M28.3-01 路径归一化**：`normalizeDescriptorPath` 纯函数——剥 `!` 后缀、`jar:file:`/`file:` 前缀（大小写不敏感）、Windows 驱动字母前导斜杠（`/C:/` → `C:/`）；`isUnderPluginsDir` 用归一化结果（toRealPath + Path.startsWith + 兜底字符串比较），拒绝记日志。
- **T-M28.3-02 通知修复**：标题 `{plugin.name}：发现新版本 {v}`（bundle 双参）；内容 `notificationContent` 纯函数（首行截断 100 字符省略号，无则默认文案）；`update.notification.failed.title`（更新失败）。
- **T-M28.3-04 权限加固**：`persistZip` 后 `ensureReadable`——`Files.setPosixFilePermissions(rw-r--r--)`，Windows（UnsupportedOperationException）静默跳过，其他失败仅日志不阻断。
- **T-M28.3-03 验证**：定向（update 包 + 设置页）+ 全量（worktree 隔离）+ 日常 IDE 实证（立即更新走通安装调度）+ 文档三处同步。

## 4. 边界与降级

- 归一化后仍拒绝：记日志（原始+归一化路径），用户可报日志定位；
- 权限设置失败不阻断安装（读取失败由安装环节报错兜底）；
- 通知内容截断仅影响通知，设置页变更日志区仍全文。
