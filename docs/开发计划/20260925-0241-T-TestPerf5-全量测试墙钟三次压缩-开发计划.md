## 二、瓶颈画像与剩余空间

warm 全量墙钟 ≈ max(各片墙钟)，而片墙钟 = 固定开销（≈17s，四片并行发生）+ 片内串行执行。执行总量 687s 是物理下界，4 路并发的理想墙钟 = 687/4 + 17 ≈ 189s；实测 196~210s，**差距全部来自片间争用与失衡**。剩余空间按预期收益排序：

1. **S-A 测试 JVM 线程面治理（本轮主攻）**：6C12T 机器上 4 路并发测试 JVM，每路都按 12 逻辑核自适应铺设线程面——G1 GC 线程（≈12 个/路）、C2 JIT 编译线程、ForkJoinPool commonPool 等，合计数十个非测试线程在片间互抢。`-XX:ActiveProcessorCount=N` 把每路 JVM 的线程面钉到 N，是 JVM 层消争用的标准手段，零语义风险（grep 实测仓内 src/ 无 `availableProcessors` 依赖；EDT 单线程模型不受影响）。若争用膨胀（+14~20%）被 reclaim 一半，墙钟预期 −7~10%。
2. **S-B GC 形态补测**：已有实验只测过 ParallelGC（吞吐优先、线程面同样大）。在多 JVM 互抢的场景下 SerialGC（单线程 GC、无线程面）反而可能占优——这是 ParallelGC 实验没覆盖的形态，借同一开关补一档 `-PtestGc=serial`，对照定去留。
3. **S-C 片数复测**：S-A/S-B 若有效，每路 JVM 线程面变窄，5 片（甚至 6 片）的竞争损耗随之下降——2026-09-24「5 片回劣」的边界条件可能再次右移。纯 `-PtestShardCount` 调参复测。注意 execSum 随并发度膨胀的另一半（内存带宽/磁盘）不是线程层可消的，5 片仍可能回劣，以实测为准。
4. **S-D 关键路径时序审计**（顺带）：每跑提取各片 START/END 与 agent 通道时序，确认并发重叠度与 agent 不拖尾；固定开销占比复测（保质期判据的数据维护）。

**诚实的天花板声明**：调度层全部兑现的预期墙钟 ≈ 2m50s~3m05s（−10~15%）；再往下只剩测试源码层（签名护栏族 ProcessBuilder 重活、SqlPreviewPanelTest 的 72 例 UI 负载），按红线只登记不实施。若 S-A/S-B/S-C 实测全部 <5%，本轮结论如实写「调度层已触底」，保留开关与数据，不硬凑收益。

## 三、待验证前提（实施者先证伪再动手）

1. **「线程面超额认领是争用主因」未验证**：片间争用也可能主要来自内存带宽/磁盘 IO（T-BuildConcurrency 实测内存提交量是构建瓶颈维度）。判据＝cap 后 4 片 execSum 总和较基线下降 ≥5% 才算成立；不成立则 S-A 销账，S-C 单独评估。
2. **SerialGC 在平台测试负载未必占优**：512m 默认堆 + 平台大对象短命态，单线程 GC 可能拉长单类耗时。对照读数定去留，收益 <5% 不落默认。
3. **cap 后 5/6 片仍可能回劣**：execSum 膨胀的内存带宽分量不可消；5 片实测不优于 4 片即维持 4 片定案。
4. **ActiveProcessorCount 语义中立**：grep 已实证 src/ 无 availableProcessors 依赖（2026-09-25 实测，本计划内已做）；实施者不必重做，但若实验中出现成片新失败，先回退开关再归因。
5. **主树 1528s execSum 是双开伪象**：Phase A 单路 warm 基线若也是 1500s 量级，说明测试负载本身变质（新守卫类过重之类），本计划重心转向逐类画像诊断，S-A~S-C 降级。预期概率低（头部类膨胀同向 +2.6% 规模增长解释不了 +122%），但必须先复核。
6. **权重表可能被争用轮污染**：主树 `build/test-results` 里 14:36 争用轮的 XML 会进后续权重采样（K=2 中位数削不干净同侧膨胀）；新工作树 build/ 全新不受影响，且 Phase A 两轮单路跑完权重自动回正。新工作树天然规避，无需修码。
