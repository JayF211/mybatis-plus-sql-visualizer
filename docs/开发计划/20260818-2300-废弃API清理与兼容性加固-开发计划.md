## ⚠️ 背景：Marketplace 拒绝通知

JetBrains Marketplace 审核团队邮件（2026-08-18）：

> Your plugin uses the Internal API, which is private and must not be used outside the IntelliJ Platform itself.

Plugin Verifier 扫描出的 **Internal API** 使用：

| Internal API | 调用点 | 根因 |
|---|---|---|
| `ToolWindowFactory.getAnchor()` | `SqlLogToolWindowFactory` | Kotlin 编译器为接口默认方法生成 synthetic bridge（源码未显式覆写） |
| `ToolWindowFactory.getIcon()` | `SqlLogToolWindowFactory` | 同上 |

**官方文档**（[api-internal.html](https://plugins.jetbrains.com/docs/intellij/api-internal.html)）：
- Internal API 标记 `@ApiStatus.Internal` 或 `@IntellijInternalApi`，**禁止在 IntelliJ Platform 外部使用**
- Marketplace **会阻断**包含 Internal API 的插件发布
- 必须提供公开替代方案或移除

**官方文档**（[tool-windows.html](https://plugins.jetbrains.com/docs/intellij/tool-windows.html)）：
- `anchor` / `icon` 应在 `plugin.xml` 中声明（`toolWindow` 扩展点属性），**不应在代码中覆写** `getAnchor()` / `getIcon()`
- 内容管理应使用 `createToolWindowContent()` + `ToolWindow.getContentManager()`，**不应覆写** `manage()`

#### T-M51-00：`SqlLogToolWindowFactory` 改写为 Java 类

| 项目 | 内容 |
|------|------|
| 问题 | Kotlin 编译器为 `ToolWindowFactory` 接口的全部默认方法生成 synthetic bridge（`getAnchor`、`getIcon`、`manage`、`isDoNotActivateOnStart`、`isApplicable`），Plugin Verifier 检测到这些 bytecode 级"覆写"并报告为 Internal API 违规 |
| 解决方案 | **将 `SqlLogToolWindowFactory` 从 Kotlin 改写为 Java**——Java 编译器只为源码中**显式声明**的方法生成 override 注解，不会为接口默认方法生成 bridge。改写后仅 `createToolWindowContent()` 一个 override，消除全部 synthetic bridge |
| 兼容性 | Java 类与 Kotlin 代码完全互操作（同项目混合编译），不影响其他 Kotlin 文件 |
| 风险 | 低——Java 实现与 Kotlin 逻辑完全等价，仅语言切换 |
| 影响文件 | 删除 `src/main/kotlin/.../log/SqlLogToolWindowFactory.kt` → 新建 `src/main/java/.../log/SqlLogToolWindowFactory.java` |
| 验证 | `verifyPlugin` 不再报告 `ToolWindowFactory.getAnchor()` / `getIcon()` / `manage()` / `isDoNotActivateOnStart()` / `isApplicable()` 的 Internal API 使用 |

**Java 实现要点**：
```java
// 仅覆写 createToolWindowContent，不覆写 getAnchor/getIcon/manage
public class SqlLogToolWindowFactory implements ToolWindowFactory {
    @Override
    public void createToolWindowContent(@NotNull Project project, @NotNull ToolWindow toolWindow) {
        // 现有 Kotlin 代码的 Java 等价实现
    }
}
```

**注意**：`anchor="right"` 和 `icon="/icons/sqlLog.svg"` 已在 `plugin.xml` 中声明，无需代码覆写。

#### T-M51-02：`ToolWindowManagerListener.stateChanged()` 三参版 → 拆分独立监听器类

| 项目 | 内容 |
|------|------|
| 调用点 | `SqlLogToolWindowFactory.kt:99-117`（匿名内部类覆写 `stateChanged(TWM, ToolWindow, EventType)` 三参版） |
| 问题 | 三参版 `stateChanged` 同时标记 `@ApiStatus.Experimental` 和 `@ApiStatus.Internal`（verifier 实证为 Internal API） |
| 解决方案 | **将监听逻辑提取为独立的 Java 类** `ToolWindowVisibilityListener`，实现 `ToolWindowManagerListener` 接口，仅覆写**非 internal 的两参版 `stateChanged(ToolWindowManager)`**——在两参版内部自行判断目标 ToolWindow 的可见性变化 |
| 兼容性 | 两参版 `stateChanged(ToolWindowManager)` 是公开 API（非 experimental/internal），三平台可用 |
| 功能等价 | 两参版在**任何** ToolWindow 状态变化时触发，需在监听器内部判断 `if (toolWindow == targetTw)` 并检查 `toolWindow.isVisible` 状态转换 |
| 风险 | 低——逻辑等价，仅过滤范围从"仅目标窗口"变为"全窗口 + 手动过滤" |
| 影响文件 | 新建 `src/main/java/.../log/ToolWindowVisibilityListener.java`；修改 `SqlLogToolWindowFactory.java`（波次 0 的 Java 版） |

**Java 实现要点**：
```java
public class ToolWindowVisibilityListener implements ToolWindowManagerListener {
    private final ToolWindow targetTw;
    private final SqlLogManager manager;
    private boolean wasVisible = false;

    public ToolWindowVisibilityListener(ToolWindow targetTw, SqlLogManager manager) {
        this.targetTw = targetTw;
        this.manager = manager;
        this.wasVisible = targetTw.isVisible();
    }

    @Override
    public void stateChanged(@NotNull ToolWindowManager toolWindowManager) {
        // 两参版：任何窗口状态变化时触发，手动过滤目标窗口
        boolean visible = targetTw.isVisible();
        if (wasVisible && !visible) {
            PluginSettings settings = PluginSettings.getInstance();
            if (settings.state.logStopOnToolWindowClose && manager.capturing) {
                manager.stopCapture();
            }
        }
        wasVisible = visible;
    }
}
```

## 风险评估

| 风险 | 缓解 |
|------|------|
| Java 改写后与 Kotlin 代码互操作问题 | Java/Kotlin 混合编译已验证（项目已有 Java 编译任务），互操作 100% 兼容 |

| `updateActionsAsync()` 在旧平台行为差异 | javap 实证三平台签名一致，语义等价 |
| `addDocumentListener` Disposable 生命周期错误导致监听泄漏 | 每个 Disposable 绑定到对应面板的 `dispose()` 生命周期 |
