## §二 范围与非目标

做：mapper XML 编辑器内的高亮注入（`#{}`/`${}` 表达式、`if/when test`/`bind value`/`foreach collection` 属性、SQL 关键字）+ 输入辅助（typedHandler）+ 补全缺口（resultMap column 族）。

不做（非目标，留痕防范围蠕动）：
- **任何 inspection/annotator 错误标注**——竞品第十二轮红线「不做校验器形态回应 CodeHelperPro」继续有效（调研报告 §9）。
- 引用导航/重命名（OgnlOrParamReference 同款）、OGNL 语法级 parser、live template、颜色设置页——本批不碰，落地后按反馈另立项（颜色页若决策点 3 选 B 顺带评估）。
- Java 注解字符串内高亮（`@Select` 场景）——平台已有注解字符串 SQL 注入，不重叠。

## §三 现状与可复用基建

- 空白确认：全仓无 multiHostInjector/自定义 Language/syntaxHighlighterFactory/typedHandler 注册（EP 与手写实现双重 grep 反证，调研报告 §7）。自研 `SqlLexer`/`SqlSyntaxHighlighter` 只服务插件自家预览面板。
- 直接复用：`xml/TokenParser.kt`（`#{}`/`${}` 扫描含 `\#` 转义，与竞品 al.j 区间扫描同型）、`xml/Ognl.kt`（OGNL 词法知识来源）、`sql/Dialect.kt`（方言关键字集，竞品 Community 轨没有）、`EntityResolver`+`EntityCache`（缓存模式参照）、`ui/highlight/SqlHighlightColors.kt`（颜色常量风格参照）。
- 守卫与测试参照：`config/PluginXmlStructureGuardTest`（plugin.xml 结构守卫）、`ui/highlight/XmlSqlCompletionContributorTest`（手工构造 CompletionParameters 的测试形态）。

## §四 方案与决策点（用户定案前不动工；定案后未选项按惯例保留删除线不删）

### 决策 1：普通 SQL 文本关键字高亮路线

| 选项 | 方案 | 利 | 弊 |
|---|---|---|---|
| A（推荐） | 自研语言整段语句文本注入，lexer-only；**门控双让位**——①Ultimate 平台注入在场（Database 插件/平台注入器探测，判据按前提 1 实证写）或②已激活的第三方 MyBatis 注入插件在位（显式探测 `com.ccnode.codegenerator.MyBatisCodeHelperPro` 插件 ID + 其 Profile `valid=true`，读不到状态文件视为未激活不让他位），命中任一即本插件**全族注入**（D2 语句文本 + D3 属性 OGNL）让位；设置页「与其他 MyBatis 插件共存时让位」开关默认开；通用兜底：注入前查宿主是否已有他方注入（`InjectedLanguageManager`，有时序不确定性只兜底不主判） | Community/Ultimate 全覆盖，占住竞品没做的差异化空位；方言感知（Dialect 关键字集）；与 CodeHelperPro 共存零冲突（对方自己就是「探测平台让位」同型设计；2026-09-24 用户就共存问题确认此修正） | 门控判据两套（平台 + 第三方），需真机验证平台注入行为（前提 1）与对方门语义（前提 8） |

注（保留痕迹）：若用户希望自己在「Ultimate + CodeHelperPro 已激活」机器上也看到本插件表达式着色，可把 D3 属性注入从让位清单单独摘出——平台不做属性注入，D3 只与对方 `OgnlMultiHostInjector` 撞（撞面取决于前提 8 的 `i.b.c()` 门语义）。当前按全族让位实施。
| B | 同 A 但无门控，全版本恒注入 | 实现最简 | Ultimate 下与平台注入双写叠色/竞态，不可接受 |
| C | 不做 SQL 关键字，只做 `#{}`/`${}`/OGNL 表达式高亮（对齐竞品 Community 轨） | 范围最小 | Community 用户 SQL 文本依旧无色，差异化让出 |

### 决策 2：语言实现深度

| 选项 | 方案 | 利 | 弊 |
|---|---|---|---|
| A（推荐） | lexer-only：Language + Lexer + SyntaxHighlighter，无 parserDefinition/PSI 类型 | 着色管线不依赖 PSI 解析，成本最小；竞品 Param 高亮器同构可参照 | 注入区间内 PSI 是 PlainScriptLanguage 形态，若前提 2 证实 M27 补全断供，需补挂 contributor 转发（增量小） |
| B | 完整语言（parserDefinition + PSI 元素 + 引用） | 可承接后续引用导航 | 成本高一个量级，本批明确不做，留作引用导航前置立项 |

### 决策 3：`#{}`/`${}` 表达式着色粒度

| 选项 | 方案 | 利 | 弊 |
|---|---|---|---|
| A（推荐） | 整体 token：表达式整段着 TEMPLATE 底色 + 关键字色，单语言方案（表达式 token 内嵌在 SQL-like 词法里） | 一个语言搞定，区间切割只到语句文本级，实现/测试面最小 | `${}` 内部 OGNL 不细着色（无关键字/字符串分色） |
| B | OGNL 词法级细着色：独立 OGNL-like 语言注入 `${}` 内部与四个属性值（竞品同构） | 表达式内部细色，观感对齐竞品 | 两个语言 + 两套注入区间，成本约 +60% |

### 决策 4：D 波次取舍

| 选项 | 方案 | 利 | 弊 |
|---|---|---|---|
| A（推荐） | 本批含 D5（typedHandler + resultMap column 补全） | 用户感知最强的两件一次到位 | 批次变大，收口周期拉长 |
| B | 本批只做高亮主线，D5 剥离另立项 | 收口快 | 补全缺口继续裸奔 |

## §五 待验证前提（实施者先证伪再动手，逐条给判据）

1. **平台注入行为**：IU 2026.2 真机 + Community 262 runIde 沙盒各开一个 mapper XML，验证 statement 文本是否被平台注入 SQL（肉眼高亮 + `InjectedLanguageManager` 日志探针）。决定决策 1-A 门控判据的真实性；若 Community 某版本平台也注入，门控按「探测平台注入器存在」而非「Ultimate 插件存在」写。
2. **注入区间内补全断供**：自研语言注入后，光标在注入区间触发补全，`language="XML"` 的 M27 contributor 是否仍收到请求。若断供：自研语言补挂一个转发 contributor（复用 `XmlSqlCompletionContributor` 的 provider 层）。
3. **CDATA 形态**：`<![CDATA[ ]]>` 内文本在 PSI 里是否仍属 XmlText、`getTextLength()` 覆盖范围——mapper 大量用 CDATA 包 SQL，直接决定区间扫描的宿主元素判据。竞品按 XmlTextImpl 一把扫，但我方须实证 262 平台行为。
4. **SqlLexer 边界行为**：注入区间已切割后 lexer 只见普通 SQL 文本，但边界外残片（如未闭合 `#{` 被切给宿主的情形）在词法里产生的 token 形态需实测调整。
5. **沙盒断言可行性**：Light 沙盒（BasePlatformTestCase + myFixture）能否断言注入高亮（`doHighlighting` 含 injected 层与否）。不可行则退到区间扫描纯逻辑单测 + 真机走查，不硬凑平台测试。
6. **卸载安全**：新 EP 全部声明式（plugin.xml），无新反射入口，不触 PlatformSignatureCrossVersionTest 登记；但注入语言类在插件卸载时的释放路径按动态卸载屏障记忆核查一遍（Disposer 树挂接）。
7. **性能基线**：注入器回调频率（每 XmlText 每次 PSI 变更）实测；竞品熔断设计（长度上限 + reformat 时间窗冷却 + O(1) 守卫）照抄为默认实现，不以「先裸跑看看」开局。
8. **共存门控判据（2026-09-24 共存冲突评估后新增）**：①对方属性 OGNL 注入在 Ultimate 模式下是否仍工作——其门控 `i.b.c()` 语义未证实（实现类因解包大小写折叠丢失，只有调用点反推）；②平台（Database 插件）对属性值是否做任何注入（预期只注入语句文本不做属性）。两项决定双让位门控对 D3 的覆盖写法；对方激活状态读 `%APPDATA%/JetBrains/<IDE>/options/MyBatisCodeHelper.xml` 的 `Profile.valid` 字段，须兼容其版本演进（读不到视为未激活→不让他位），且只做探测不写不依赖其内部格式细节。

## §七 测试与反向验证纪律

- 守卫类改动必做反向验证：摘掉 Ultimate 门控行 → 在模拟平台注入在场的夹具下必须出现双注入可观测信号（两次读数落验收文档）；摘掉熔断 → 超长样本必须进入慢路径计数。
- 「非 mapper 文件零注入」不构成精度证据，必须配真实 mapper 语料命中用例（防空绿）。
- 全量门禁按三档分层收口：实施子代理只跑定向；收口单派只读代理跑全量；**大改动判定命中**（plugin.xml 新增 EP）→ 加 `verifyPlugin` 构建校验（发版前再 `buildPlugin`）。
- 真机走查双机：Community 262 runIde 沙盒 + 用户日常 IU 2026.2（demo 仓 mapper 语料，注意 demo 默认 dev 档无 SQL 日志与本任务无关，走查对象是编辑器高亮）。
