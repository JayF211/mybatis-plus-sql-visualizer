## 二、现状核实（立项前锚点核实，2026-09-23 实测）

1. **【关键口径修正】四处直接 `CCJSqlParserUtil` 的失败语义并不相同**，原报告 §5 F15「统一改走 SqlAstParser（一行/处）」的口径被证伪收窄：
   - `McpSelectGuard.kt:67-77`：解析失败 **fail-closed 拒绝**（deny `SQL_BLOCKED`，注释明写防解析器对恶意输入抛 StackOverflowError）——收拢 = 方括号 SELECT 从「拒绝」变「可解析可执行」，属**安全闸门能力扩展**，不该混入性能 sweep → 拆出为决策点 D1；
   - `ConnectionErrorClassifier.kt:72-84`（DdlTargetExtractor）：失败 fail-through 正则兜底，且 `CREATE_TABLE_REGEX`（`:65-66`）本就认 `[`、`normalize()`（`:87-91`）本就剥方括号——收拢后该处**无可见行为差异**（无先红，只能等价保绿）；
   - `SqlPerfAnalyzer.kt:97`：失败返 null 降级纯正则规则——收拢后方括号 SQL 的 AST 规则全量生效，**有真先红**；
   - `BatchPredicateMerge.kt:116-121`：失败返 null 判不可合并——收拢后方括号 DELETE 可参与合并预览，**有真先红**。
   - 另核实：`SqlAstParser` 目前只暴露 `parseStatements`；`SqlPerfAnalyzer`/`BatchPredicateMerge` 用的是**单语句 `parse`** → 收拢须先给 `SqlAstParser` 补 `parseSingle`（共享既有 `features` 常量），非一行改动。
2. **`SenderLoopBackoffTest` 夹具无慢拨号能力**（`ClosingServer` 立即 accept+close）：F2 的误判形态「拨号 >2s 后连上即被关」在 loopback 上不可自然复现 → 判别力缝拆出为决策点 D2。
3. 切分器定向测试落点：`src/test/kotlin/cn/song/mybatisplus/visualizer/util/SqlStatementSplitterTest.kt`（仓内另仅 `ExecutionTimeoutGuardTest` 引用切分器）。
4. **T-PerfSweep7 代号无占用**（`git log --all --grep` 零命中、计划目录无同名件）。

## 三、方案

### T-PS7-01 切分器 END 分支前视收口（中低头号）

- **落点**：`SqlStatementSplitter.kt:118-120` 与 `:449-451`（`nextWordIs`×5 两处复制：CASE/IF/LOOP/WHILE/REPEAT 各自独立重扫同一空白注释段）、`:267-268`（DECLARE 头 `hasWordAhead("BEGIN")` + `hasMatchingEndAhead` 两次全文前视；后者即 `hasWordAhead(…,"END")`，`:568`）。
- **方案**：新增「单次取词」helper——向前跳过空白/注释取下一个词**一次**，与 5 个内层终结词比对返回命中项（两处复制点共用）；DECLARE 头把两次全文前视合并为一趟带深度语义的扫描（或至少共享同一词法游标，取实现简单者）。**等价性红线**：空白/注释跳过语义、大小写不敏感、`beginEndBalance` 与主循环两处复制点必须同步改（只改一处即引入分叉）。
- **验收**：`SqlStatementSplitterTest` 全绿；新增测试缝计数（END 分支每语句的前视调用数阈值）先红后绿——退回旧实现（5 次独立前视）计数超阈值即红；新增边缘用例：注释内 END、END 作标识符/列名、嵌套 BEGIN 内层 IF。

### T-PS7-02 退避复位改 connectedAt 起算（agent 子项目）

- **落点**：`SenderLoop.java:187`（`attemptStartMs` 在 `new Socket` 之前且无 connect 超时）、`:282`（`aliveMs` 判据）、`:298-301`（复位分支）。
- **方案**：连接成功后另记 `connectedAtMs`，复位与 fastDrops 判据改 `now - connectedAtMs`；拨号提为**包内可注入函数字段**（默认真拨号，沿用 T-PS6-05「包内构造器注入、不新增生产可配置面」先例）。**不改帧协议**（`AgentProtocolSyncTest` 帧守卫不触）。
- **验收**：`SenderLoopBackoffTest` 新增「慢拨号（注入 >2s）+ 连上即被关 → 不复位且 fastDrops+1」用例——退回 `attemptStartMs` 起算即红（误判为正常掉线复位），有修复则绿；既有 3 用例保持绿。

### T-PS7-03 解析入口收拢（非安全链三处）＋ 决策点 D1

- **落点**：`SqlAstParser.kt`（补 `parseSingle`）、`ConnectionErrorClassifier.kt:73`、`SqlPerfAnalyzer.kt:97`、`BatchPredicateMerge.kt:117`。
- **方案**：三处改走 `SqlAstParser`（前两处语义为 `parse` 单语句，用新 `parseSingle`）；`McpSelectGuard` **不在本任务内**（D1 已定案：收拢增量登记 O-61 §八）。
- **验收**：方括号样本三类——①BatchPredicateMerge：`DELETE FROM [user] WHERE id = 1` 合并预览改前「不可合并」、改后可合并（先红后绿）；②SqlPerfAnalyzer：方括号 SELECT 某条 AST-only 规则改前不命中、改后命中（先红后绿）；③DdlTargetExtractor：方括号 CREATE TABLE 提取结果改前后一致（**无先红，等价保绿**，不得伪造先红）。

**D1（T-PS7-03 范围）：`McpSelectGuard` 是否一并收拢？——已定案（2026-09-23，用户确认按推荐）**

| 选项 | 利 | 弊 |
|------|----|----|
| **C. 目的地 A、载体 O-61 — 已定案** | 安全闸门能力扩展获完整安全论证与真机走查（负样本四组判据挂进 O-61 的待验证前提框架）；性能 sweep 保持「行为保持型」纯度；O-61 本就动 `McpSelectGuard.kt`（KDoc 订正），同文件同批免二次协调 | 收拢晚于本 sweep 落地（方括号 SELECT 经 MCP 的可用性缺口多存续一个批次） |
| ~~B. 不收拢，注释登记口径（原推荐）（弃用）~~ | 安全闸门零行为变化；避让 O-61 写集 | 方括号 SELECT 经 MCP 仍被拒，缺口只留档无去处，将来在 bug 压力下补课 |
| ~~A. 一并收拢（弃用）~~ | 方括号 SELECT 可执行；入口全仓唯一 | 性能 sweep 混入安全闸门语义变更，验收责任错配；fail-closed 放宽需真机走查但本 sweep 无此预算 |

**定案理由**（2026-09-23）：用户问「长远角度推荐 A 还是 B」。答复：终局是 A——产品方言层为 SQL Server 自产方括号形态，自己生成的语法被自己的闸门拒是永久自相矛盾；fail-closed 的长期价值在语义保守（单语句、纯读、无副作用）不在方言覆盖，结构判定在方括号开启后一条不少；单一解析入口的不变量应闭合，带最显眼例外的 invariant 会复活散装 parse 的 bug 类。但载体不是性能 sweep——O-61 本就动该文件且已有安全论证框架，收拢增量连负样本清单登记进 **O-61 §八**。
