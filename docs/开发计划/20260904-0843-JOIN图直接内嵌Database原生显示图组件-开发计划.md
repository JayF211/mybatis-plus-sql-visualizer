# JOIN 图直接内嵌 Database 原生「显示图」组件开发计划

> 源自 2026-09-04 用户真机反馈：T-NativeUI 交付后字段已正常显示，但注释样式、字段分区与工具栏仍与原生 IDEA Database「显示图」不一致。用户目标升级为**直接内嵌原生组件**——插件只控制「哪些字段展示」和「JOIN 连接线」，渲染零自研。
> 基线：ideaIU-2024.3.7.1，`com.intellij.diagram.Provider` EP 已通，自实现 `SqlJoinDiagramProvider` 已能原生渲染（提交 8d1e370）。

## 背景与截图差异（真机 2026-09-04）

用户提供了同库同表（car_device_info）两张截图对比：

| 维度 | 原生 Database「显示图」 | 本插件现状 |
|------|------------------------|-----------|
| 字段注释 | `station_id /* 站点ID */ int(11)`——注释 `/* */` 斜体紧跟字段名，类型右对齐独立列 | 注释缺失或跟在类型后（getItemType 尾部），非 `/* */` 样式 |
| 类型写法 | DB 真实类型 `int(11)` / `varchar(64)`（来自数据源 schema） | Java 映射类型 `INT` / `VARCHAR`（大写、无长度） |
| 主键分区 | PK 在字段列表**底部独立分区**（分隔线 + 金色钥匙图标） | PK 在顶部、无独立分区 |
| 表头 | `car_device_info /* 设备信息表 */`（`/* */` 斜体） | `表名 (别名) 注释`（灰斜体、括号别名） |
| 工具栏 | 含分类切换按钮（关键列钥匙 / 注释气泡）等 Database 图专属动作 | 通用图框架工具栏，无分类切换按钮 |
| JOIN 表字段 | 全字段原生展示 | JOIN 表（station_info t1）节点字段行为空（列提取疑似缺口） |

## 方案决策

### 方案 B（主攻）：直接复用 Database 原生显示图

不再自实现 `DiagramProvider` 的渲染部件，而是走 Database 插件自己的开图链路：SQL 解析出的表名 → 当前数据源定位真实 `DbTable` → 以原生「显示图」语义打开（`UmlVirtualFile` + Database 图 provider）→ 注释/类型/分区/工具栏/图例全部原生。插件只做两件事：

1. 控制进图的表清单（JOIN 涉及的表）；
2. 注入 JOIN 连接线（ON 条件 + JOIN 类型语义）。

连接线注入首选 **virtual foreign keys** 机制——`DbDiagramProvider$1` 字节码已实证存在 `VIRTUAL_FOREIGN_KEYS` 分类，Database 原生支持"虚拟外键"画线；把 ON 条件注册为虚拟外键即可让原生图自动连线，边样式/标签全走原生。备选：DataModel 层自定义 `DiagramRelationshipInfo` 边（沿用 T-NativeUI-04 的箭头/线型成果）。

前置条件：用户已配置数据源且 SQL 涉及表在数据源中存在（用户实测场景成立，demo 项目已连库）。无数据源 / 子查询 / Community → 降级方案 A。

### 方案 A（兜底，独立交付价值）：自实现 Provider 渲染细节逐项对齐

无论 B 成败都值得做的低成本修正（B 成功后作为无数据源场景的降级路径打磨）：

- 注释内联 `getItemName`：`字段名` + ` /* 注释 */`（GRAYED_ITALIC），`getItemType` 只留类型右对齐——复刻原生三段式行布局；
- 表头改 `表名 (别名) /* 表注释 */` 样式；
- 分类数组顺序调整（COLUMNS 在前、KEY_COLUMNS 收尾）：框架按 enabled 分类顺序逐组 append 并插分隔符，KEY_COLUMNS 放最后即得到原生「PK 底部独立分区」效果；
- 类型显示升级：数据源可用时经 `DatabaseSchemaResolver`（M35 已有反射取 DB COMMENT 的通道）取真实 DB 类型 `int(11)`；
- JOIN 表字段为空的真机缺陷排查（见任务 T-Embed-07）。

## 任务

### T-Embed-01 原生开图链路字节码调研

javap `database-plugin.jar` / `uml-support.jar`（IU-243 实证，铁律）：

- Database「显示图」动作链入口：`DatabaseViewActions` / `DbDiagramSelectInDbView` / ShowDiagram 语义（UmlVirtualFile name 的 providerId 段、元素 FQN 形态）；
- `DbDiagramDataModel` 建边来源（FK / virtual FK 读法）、`DbDiagramExtras`、`VIRTUAL_FOREIGN_KEYS` 分类的数据通道；
- 工具栏分类切换按钮的组装点（为什么原生有钥匙/气泡按钮、我们的 provider 没有）；
- 输出：可行性结论 + 打开方式（能否复用 `NativeJoinDiagramOpener` 反射桥）。

### T-Embed-02 SQL 表名 → 数据源 DbTable 定位

- 表名收集：`stmt.table.tableName` + `join.tableName`（子查询除外）；
- 数据源选择：复用 M36 执行链的数据源策略（唯一数据源静默选 / 多数据源选择弹窗 / 上次使用）；
- `DasTable` 定位（DAS API），表名含库名前缀/大小写宽容匹配；
- 定位失败（无数据源/表缺失）→ 返回降级标记。

### T-Embed-03 原生图打开与嵌入

- 按 T-Embed-01 结论以原生语义开图，嵌入 SqlPreviewPanel「JOIN 图」标签页（复用现反射桥 + Disposable 挂接 + disposeNativeEditor 释放链）；
- 独立标签页入口同步。

### T-Embed-04 JOIN 连接线注入

- 首选：ON 条件 → 虚拟外键注册（研究 persistence 通道与清理时机，避免污染用户 schema 配置——优先会话级/项目级可回收）；
- 备选：DataModel 自定义边（JOIN 类型箭头 + ON 标签，复用 T-NativeUI-04 的 `DiagramRelationshipInfoAdapter.Builder` 成果）；
- 验收：连接线两端表正确、ON 标签可见、无重复 FK 线。

### T-Embed-05 字段展示控制

- 原生分类（列 / 关键列 / 注释）默认态确认：默认全开即为原生行为，用户可工具栏自切；
- 主表裁剪策略（MAX_COLUMNS>50 仅 PK）在原生路径下的等效实现或放弃（原生自己管）。

### T-Embed-06 降级链与设置

- 触发矩阵：数据源缺失 / 表定位失败 / 子查询 / Community / 框架异常 → 现有 `SqlJoinDiagramProvider` 路径；
- 设置页「JOIN 图渲染方式」：自动（默认，原生优先）/ 总是自实现 / 总是原生；
- 失败静默降级 + 日志（对齐 NativeJoinDiagramSupport 门面语义）。

### T-Embed-07 方案 A 兜底细节对齐（见方案 A 节）+ JOIN 表字段空缺陷修复

- 排查真机 station_info (t1) 字段行为空：`extractJoinColumns` 对 selectAs / ON 引用的别名匹配（`resolveJoinAlias` uniquify 与 `ColumnRef.tableAlias` 一致性）；
- 其余方案 A 四项渲染修正。

### T-Embed-08 测试与真机验收

- 纯单测：表定位/降级标记/虚拟外键注册参数；
- Heavy：原生开图链（数据源 mock 或 testDatabase 通道）；
- 真机截图对比原生（铁律：单测通过≠视觉达标），逐项核对上表 6 个维度。

### T-Embed-09 表头注释优先数据库（2026-09-04 真机反馈）

- 真机验证发现表头注释仍取实体类注释（`DiagramSchemaEnricher` 只富化列级类型/注释，未覆盖 `EntityNode.tableComment`）；
- `DatabaseSchemaResolver` 新增 `tableMeta(project, tableName)`：表 COMMENT（`DasTable.getComment()` 反射）与列元数据一次遍历同取，`columnMeta` 改为委托 `tableMeta().columns` 保持兼容；
- 富化逻辑抽顶层纯函数 `applyTableMeta`（metaFor 可注入）：表注释 DB COMMENT 优先，数据库没写（null/空白）回落实体类注释；表在数据源匹配不到整表保留原值；
- 单测补 3 个正向注入用例（覆盖/回落/仅表注释列缺失）。

## 风险与对策

| 风险 | 对策 |
|------|------|
| 原生 Database 图强依赖真实 DbTable（PSI/DAS），测试环境难建 | Heavy 用 testDatabase 通道；纯单测只测定位/降级逻辑 |
| 虚拟外键持久化污染用户 schema 配置 | 优先会话级方案；持久化须可回收 + 设置开关明示 |
| Database 图动作链为 internal API（反射桥成本） | 沿用 UmlEditorProvider 反射桥模式；javap 全程实证 |

| 方案 B 不可行 | 方案 A 独立交付，降级链天然成立 |
