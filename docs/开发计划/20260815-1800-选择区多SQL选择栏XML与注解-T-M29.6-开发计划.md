## 1. 问题分析（三条 SQL 来源的「选择区 → 选择栏」链路对比）

### 1.1 现状链路

| 场景 | 选择区处理 | 选择栏 |
|------|-----------|--------|
| Java Wrapper/批量方法 | `ConvertToSqlAction` 分支 A（T-M23.7）：`WrapperLocator.sqlCandidatesInRange(file, selStart, selEnd)` 扫选择区内链首 + 批量方法调用 → 0/1/多分发 | ✅ 多条时弹 `SqlSelectionDialog` |
| XML mapper | action 入口 `file is XmlFile` 分支**不读 selection**（ConvertToSqlAction.kt:50），直接 `previewXmlStatement` | ❌ 选择区被忽略 |
| 注解 SQL | `sqlCandidatesInRange` 只收集 `PsiMethodCallExpression`（`isSqlCandidate` = 链首 || 批量方法名），**SQL 注解不在候选集内** | ❌ 选择区内多条注解不弹选择栏 |

### 1.2 XML 侧根因（代码级定位）

- `ConvertToSqlAction.actionPerformed`（ConvertToSqlAction.kt:50-53）：`file is XmlFile` 分支先于分支 A（selection 检查）返回——选择区存在时也不会被读取。
- `previewXmlStatement`（ConvertToSqlAction.kt:170-217）：只按**光标**定位——光标在语句内 → 直接预览该语句（无选择栏）；光标不在任何语句内 → 收集**全文件**语句候选（`findChildrenOfType(file, XmlTag)` 全文件范围），可能包含选择区外语句，非「选择区内候选」语义。
- 弹窗层已就绪：`SqlSelectionDialog<T>` 泛型（T-M25-01 已支持 `XmlTag` 候选，全文件回落路径在用），展示文本计算模式（`tag.name id（第 N 行）` + 语句文本）已有现成实现（ConvertToSqlAction.kt:190-200）。**缺口只在「选择区 → 候选收集」**。

### 1.3 注解侧根因（代码级定位）

- `WrapperLocator.sqlCandidatesInRange`（WrapperLocator.kt:168-172）只收集 `PsiMethodCallExpression`；`isSqlCandidate`（WrapperLocator.kt:156-157）= 链首 || 批量方法名——`PsiAnnotation`（@Select/@Update/Provider 族）不在候选集内。
- 结果：Mapper 接口文件选中含多个 `@Select` 方法的段落 → 选择区内 Wrapper 候选为 0 → 弹「未找到可转换的 Wrapper」提示，无选择栏。
- 现有注解候选交互 `showAnnotationCandidates`（M26-A，ConvertToSqlAction.kt:128-155）是**全文件**范围、且只在**光标路径** Wrapper 未命中时触发——不覆盖选择区场景。
- 选择区判定语义与 Java 对齐：`textRange.startOffset in selStart until selEnd`（语句/注解开头在选择区内才计入）。

## 2. 目标

1. **XML 选择区候选**：XML mapper 文件选中段落时，扫描**选择区内** mapper 语句（`<select|insert|update|delete>`）→ 0/1/多分发，多条弹 `SqlSelectionDialog`（与 Java 选择区交互一致）；无选择区时行为不变（光标定位 / 全文件候选）。
2. **注解选择区候选**：Java 选择区内 Wrapper 候选为 0 时，回落扫描**选择区内** SQL 注解 → 0/1/多分发；仍为 0 → 维持现有「未找到」提示。
3. **定位跳转补全**：`locateEditorTo` 泛化为任意 PSI 元素（Wrapper 链首 / XML 语句 / 注解），XML 与注解候选选中后同样「光标到行首 + 滚动居中 + 整行选中」（对齐 T-M23.8 Java 体验；顺带补上 XML 全文件候选路径与 M26-A 全文件注解候选路径的定位跳转）。

**非目标**：gutter 图标路径（单语句单图标，语义正确，不动）；选择区内 Wrapper 与注解并存时 Wrapper 优先（与 M26-A 全文件回落优先级一致）；`<sql>` 片段标签不作为语句候选（STATEMENT_TAGS 不含）。

## 3. 方案设计

### 3.1 Fix-1：XML 选择区候选（ConvertToSqlAction.kt + XmlSqlGutterLineMarkerProvider.kt）

- `XmlSqlGutterLineMarkerProvider` companion 新增 internal 纯函数（单一来源 STATEMENT_TAGS 已在 companion，可单测）：
  ```kotlin
  internal fun statementsInRange(file: XmlFile, start: Int, end: Int): List<XmlTag> =
      PsiTreeUtil.collectElementsOfType(file, XmlTag::class.java)
          .filter { it.name in STATEMENT_TAGS && it.textRange.startOffset in start until end }
          .sortedBy { it.textRange.startOffset }
  ```
- `ConvertToSqlAction.actionPerformed` XML 分支：先检查 `editor.selectionModel.hasSelection()`——有选择 → 后台 ReadAction 收集选择区内语句 + 预计算展示文本（`tag.name id（第 N 行）` + `tag.text`，复用全文件候选路径格式）→ 0/1/多分发（多条 → `SqlSelectionDialog`，onSelect = 定位跳转 + `previewXml`）；无选择 → 现有 `previewXmlStatement` 不变。

### 3.2 Fix-2：注解选择区候选（ConvertToSqlAction.kt + AnnotationSqlPreviewService.kt）

- `AnnotationSqlPreviewService` 新增（`annotationCandidates` 复用，加范围过滤）：
  ```kotlin
  fun annotationCandidatesInRange(file: PsiFile, start: Int, end: Int): List<PsiAnnotation> =
      annotationCandidates(file)
          .filter { it.textRange.startOffset in start until end }
          .sortedBy { it.textRange.startOffset }
  ```
- `ConvertToSqlAction` 分支 A：`sqlCandidatesInRange` 结果为空时 → `showAnnotationSelectionCandidates(project, file, selStart, selEnd)`（新私有方法，仿 M26-A 结构：后台 ReadAction 预计算摘要/行文本 → 0/1/多分发；摘要格式复用「方法名（注解类型）+ sqlSnippet」）；注解也为 0 → 现有「未找到」提示。

### 3.3 Fix-3：定位跳转泛化（WrapperLocator.kt + ConvertToSqlAction.kt）

- `WrapperLocator.lineOffsetsOf(call: PsiMethodCallExpression)` 泛化为 `lineOffsetsOf(element: PsiElement)`（实现不变，参数放宽）——现有调用点（action + WrapperLocatorTest）传 `PsiMethodCallExpression` 天然兼容。
- `ConvertToSqlAction.locateEditorTo(editor, call)` 参数放宽为 `PsiElement`。
- 接线：XML 选择区 onSelect、注解选择区 onSelect、XML 全文件候选 onSelect（顺带）、M26-A 全文件注解候选 onSelect（顺带）全部加定位跳转。

## 6. 风险与边界

- **选择区判定**：与 Java 一致用 startOffset（语句/注解开头在选择区内才计入）；XML 语句不嵌套语句（MyBatis 语法），`collectElementsOfType` 嵌套 tag 由 STATEMENT_TAGS 过滤天然排除。
- **EDT 慢操作守卫**：候选收集 + 展示文本预计算全部后台 ReadAction（2025.3+ SlowOperations 守卫，仿 T-M23.8 既有模式）。
- **并行会话**：T-M29.5 在途改动文件（XmlPreviewModel.kt/XmlParamTypeResolver.kt）与本任务（ConvertToSqlAction.kt/AnnotationSqlPreviewService.kt/WrapperLocator.kt/gutter）无交集；跑测试前登记并行协调表（parallel_tasks.py），避免共享 daemon/沙盒互锁。
- **行为一致性**：选择区内同时含 Wrapper 与注解 → Wrapper 优先（0 候选才回落注解）；光标路径行为全部不变（M26-A 全文件回落保留）。
