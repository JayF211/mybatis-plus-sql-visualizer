# T-UiCoord：预览「回滚 SQL」折叠进「更多」+ SQL 日志工具栏单行定构 — 开发计划

> 来源：2026-09-21 用户真机走查现场提出两项 UI 调整（附两张截图：SQL 预览弹窗、SQL 日志工具窗）。
> F1 是**入口位置调整**（用户明确要求，推翻此前「保持一键直达」的定案）；F2 是**既有布局缺陷整改**（2026-09-16 / 09-18 两次功能叠加造成，非本轮引入），并在同日追加约束「不要两行」，最终形态=**单行定构**（决策记录见 §三 F2）。
> 相邻但**不在本计划范围**：P12（极窄面板下预览 meta 行整行消失，`docs/验收文档/20260920-待分析问题清单.md` §P12）——F1 会把它在 680px 下的余量从约 33px 抬到约 115px，但**不关闭它**。

## 一、现象与影响

### F1 预览弹窗：回滚 SQL 直显在按钮行

截图 1（预览弹窗，1176×695）按钮行实测 8 枚直显按钮（y 55–82，高 28px）：

| 按钮 | x 区间 | 宽 |
|---|---|---|
| 压缩 | 521–592 | 72 |
| 格式化 | 599–670 | 72 |
| 关键字换行 | 677–759 | 83 |
| 竖向排列 | 766–837 | 72 |
| 执行计划 | 844–915 | 72 |
| **回滚 SQL** | **922–995** | **74** |
| 刷新 | 1002–1073 | 72 |
| 更多 | 1080–1151 | 72 |

按钮行理想宽 ≈ 631px（含按钮间 7px 间距），占 topRow 宽度（≈1144px）的 55%；左侧 meta 行（`表: user`）之后到 521 之间是约 430px 空档。

用户诉求：回滚 SQL 属低频动作（只在当前语句是 INSERT/UPDATE/DELETE 时才有意义），不应与格式化/刷新等同列直显，折叠进「更多」。

### F2 SQL 日志工具窗：工具栏折成两行，用户要求压回一行

截图 2（工具窗，506×658，内容区约 460px 宽）实测：

| 元素 | 实测位置 | 块宽 |
|---|---|---|
| 图标组（捕捉/清空/设置/搜索/帮助） | 第 1 行，图标墨迹 x 28–141（组件块约 14–152） | ≈133 |
| SQL类型单元（`SQL类型：` + 下拉按钮） | 第 1 行，x 166–303 | ≈145 |
| 移除重复的sql 勾选 | 第 1 行右侧贴边，x 352–452 | ≈102 |
| 排序单元（`排序：` + 下拉按钮） | **第 2 行，x 18–156** | ≈145 |

行结构：第 1 行 y 98–125，第 2 行 y 134–161（行距 36px），工具栏分隔线 y 167。

三个具体的不协调点：

1. **第 2 行只有一个控件**（排序），右侧约 300px 空档；第 1 行 `SQL类型` 按钮（x 303）与勾选框（x 352）之间另有 49px 空洞。整体像「控件撒在两行上」而不是一个有结构的分区。
2. **两行左边缘差 10px**：第 1 行首个图标墨迹在 x 28，第 2 行 `排序：` 标签墨迹在 x 18——因为 ActionToolbar 组件自带左内边距，而标签直接贴流式区起点。
3. **结构随宽度和文案漂移**：折行点是「谁最后谁折」，不携带语义。同一块面板在侧边栏拖宽时变一行、拖窄时变三行；`SQL类型` 按钮文案在多选类型时从「全部」变长（`updateTypeFilterButton`，`SqlLogPanel.kt:836`），慢查询计数标签出现时也会再加宽——折行位置随之改变。

**用户追加约束（2026-09-21 当日）**：不要两行，工具栏恒为一行。

一行预算对账（同一批量测）：

```
一行需要 ≈ 542px = 图标组 133 + 4 + SQL类型单元 145 + 4 + 排序单元 145 + 4 + 勾选 102
一行可用 ≈ 460px（面板内容区实测 6..465）
差额 ≈ 83px —— 必须有控件让位，见 §三 F2
```

## 二、根因

### F1：按钮行是「全直显」，没有频率分层

`SqlPreviewPanel.toolbar()`（`ui/SqlPreviewPanel.kt:872-902`）逐枚 `add(smallButton(...))`，8 枚平铺、无优先级分组；折叠机制（`moreActions()` `:905-909` + `showMoreActionsPopup()` `:915`）已经存在，且当前只收三项（导入参数 / 差异对比 / 分享）。回滚 SQL 是 2026-09-12 T-RollbackSql 交付时按「一键直达」定案直显的（`:895-897` 注释留痕，`T-MergeR2IntoMaster §3.2` 定死「执行计划之后、刷新之前」），本次用户要求改判。

### F2：三次功能叠加把流式行撑爆，而折行没有结构

`buildToolbar()`（`log/SqlLogPanel.kt:711-770`）把「图标组 + SQL类型单元 + 排序单元 + 慢查询计数」放进一个 `WrapLayout` 流式区（`:725-741`），「移除重复的sql」勾选单独挂在 `BorderLayout.EAST`（`:759-765`）。

预算对账（按截图 2 量测，单元宽为墨迹外扩估算 ±10px）：

```
流式区可用宽 ≈ 460 − 勾选块(≈110) − 面板右内边距 ≈ 345
流式区理想宽 = 图标组 ≈133 + 4 + SQL类型单元 ≈145 + 4 + 排序单元 ≈145 ≈ 430  >  345
→ 最后一项（排序单元）折到第 2 行
```

成因链（都是合理需求，叠加后没有重新分配版面）：

| 时间 | 改动 | 对行的宽度影响 |
|---|---|---|
| 2026-08-15 M31.5/M31.6 | 图标组（4 图标）+ `SQL类型` 单元 + `移除重复的sql` 勾选；勾选后按用户要求移出流式区、右侧贴边 | 基线 |
| 2026-09-16 T-LogSortModes | 新增 `排序：` 单元进同一流式区（`变更记录.md` 当日条目：与 SQL类型单元同构、折行时同进退） | +145 |
| 2026-09-18 T-CaptureBack | 捕捉动作回迁为图标组首位（第 5 枚图标） | +26 |

即：图标组 4→5 枚、流式区 2 单元→3 单元，而勾选框的 110px 右侧占位与 345px 的可用宽从未重新核算。`WrapLayout`（`:1745-1791`）只保证「折行后高度不被裁」，不保证折行结果有结构——于是折出一行只剩一个控件。

## 三、修法

### F1：回滚 SQL 折叠进「更多」（写集：`ui/SqlPreviewPanel.kt` + 两处测试）

1. `toolbar()` 删除 `add(smallButton(panel.rollbackSql) { showRollbackSql() })`（`:898`），注释块（`:895-897`）改写为「2026-09-21 用户要求折叠进『更多』，推翻原一键直达定案」。
2. `moreActions()`（`:905-909`）在**首位**插入 `panel.rollbackSql to { showRollbackSql() }`——四项按使用频率排序，回滚 SQL 最常用，放首项也最易发现（折叠会降低可发现性，首项是最低成本的补偿）。
3. `showRollbackSql()`（`:952-977`）实现**一字不改**：菜单项与按钮走同一条路径。其内部分支（UNABLE 且无快照 → `Messages.showInfoMessage`；否则 `RollbackSqlDialog(...).show()`）都在 `moreActionsStep.onChosen` 的 `invokeLater`（N4 修复，`:930-942`）之后执行，**不新增焦点风险**。
4. `showMoreActionsPopup()` 的锚点解析（`:917` 取工具栏最后一个 `JButton`）不受影响：末位仍是「更多」。

顺带收益（**不据此关闭 P12**）：按钮行理想宽 631 → 约 549px，680px 弹窗宽下 meta 行可用宽从约 33px 抬到约 115px，P12 的「整行消失」现象缓解但未根治（根治属 P12 自己的修法）。

### F2：工具栏单行定构（写集：`log/SqlLogPanel.kt` + 中英 bundle + 布局测试）

**结构**（一行，`BorderLayout`，结构上不存在折行可能）：

```
┌──────────────────────────────────────────────────────────────┐
│ CENTER：ActionToolbar 图标组（拿剩余宽度）  EAST：控制组          │
│  ■  🗑  ⚙  🔍  ?            [全部 ▾] [时间升序 ▾]  ☑ 移除重复的sql │
└──────────────────────────────────────────────────────────────┘
```

- **CENTER = `toolbar.component`**：图标组靠左，拿剩余宽度；极窄宽度下由平台 ActionToolbar 自带的溢出机制接管（`setReservePlaceAutoPopupIcon`，待真机确认形态，见 §七）。
- **EAST = 控制组**：`[SQL类型下拉] [排序下拉] [去重勾选]`，固定宽度，勾选仍在最右（保留用户 2026-08-15「移到右侧、与 SQL类型 垂直居中平行」的要求）。
- `WrapLayout` 从这个行撤出（`focusTabBar` 仍在用，类保留）。

**四个配套改动**：

1. **去标签**：删掉 `typeFilterLabel`（`:408`）与 `sortLabel`（`:420`）两个 `JLabel`，以及它们在两个单元 `FlowLayout` 里的挂载（`:728-741`）。两个键不删、转作**动态 tooltip 前缀**——`log.filter.type.label`（"SQL类型："）与 `log.sort.label`（"排序："）：
   - 类型按钮 tooltip = `SQL类型：` + 当前状态全文（如 `SQL类型：查询, 更新`）；
   - 排序按钮 tooltip = `排序：` + 当前方式（如 `排序：时间升序`）。
   这样两个键仍在 `src/main` 被引用（不产生幽灵键），也不必新增键。原 `log.filter.type`（"SQL类型"）改造后零引用，一并从两个 bundle 删除（该键不在幽灵键守卫扫描前缀内，删是清理不是必需）。
2. **定宽省略**：两个下拉按钮设**宽度上限**（类型 ≈100px、排序 ≈100px），超限用省略号截断显示文本，tooltip 恒全文。实现走本项目既有 `ellipsize(text, metrics, budget)` 路线（预览面板 meta 行同款），在 `updateTypeFilterButton()` / `updateSortButtonText()` 里按预算截断后 `setText`。
   顺带解决现状的**结构漂移**：多选类型后按钮文案变长不再改变行宽（上限封顶），一行恒成立。
3. **慢查询计数标签**：现在挂在流式区末尾（`:744-750`，文案 `log.toolbar.slowQueryCount`="慢查询: {0}"，约 65px）。一行定构下余量约 40px，容不下，改为**短徽章**——复用已存在但零引用的键 `log.panel.slowQueryBadge`（"慢"）拼计数（如「慢 3」），tooltip 用 `log.toolbar.slowQueryCount` 全文。位置放控制组左端（列表状态的指示器与控制组同侧）。该键现为存量幽灵键，复用即顺手清掉。
4. **不折行的保证**：`BorderLayout` 本身不折行；行内所有控件都有确定 preferred 宽度（两个按钮上限封顶、勾选固定、图标组可压缩），故任意宽度下都只有一行，窄了是图标组交给平台溢出、而不是折到第二行。

**不改的东西**：5 枚动作图标的数量与顺序、两个下拉的弹层内容与点击路径（类型仍是多选弹窗、排序仍是五选项单选菜单）、勾选的位置与语义、`SortMode` 与 `activeFilter` 的状态逻辑。

**决策记录（2026-09-21，用户定案）**：

| 方案 | 状态 | 说明 |
|---|---|---|
| 单行：两个下拉去标签（+ 定宽省略 + tooltip 补语义） | **采纳** | 控件数量、点击路径、勾选形态与位置全不变；余量约 40px（多选类型封顶后仍 ≥ 13px） |
| 两行定构（动作行 / 列表控制行） | **弃用** | 用户 2026-09-21 明确「不想要两行」；本计划初版曾以它为主方案 |
| 类型与排序合并成一个下拉 | 备查 | 余量最宽（约 77px），但推翻 T-LogSortModes「排序恒为独立选择器」定案 |
| 「移除重复的sql」移出工具栏进设置页 | 备查 | 余量约 36px，但推翻用户 2026-08-15 让它在面板里的要求 |
| 「移除重复的sql」改图标开关 + 去排序标签 | 备查 | 余量约 29px，但勾选形态变化、图标易被读成一次性动作 |
| 折叠 2~4 枚图标进「更多」 | **弃用** | T-CaptureBack 已证伪（入口被折叠/悬停隐藏后用户在视角里「不见了」） |

**为什么一行必须让出约 83px**（三个杠杆都会推翻既有定案）：

| 杠杆 | 省 | 代价 |
|---|---|---|
| 去掉「排序：」标签 | 36 | 无（本次采纳）——按钮文案已含当前方式，tooltip 补全语义 |
| 去掉「SQL类型：」标签 | 59 | 无（本次采纳）——同上，tooltip 显示完整状态 |
| 折叠 2 枚图标进 popup | 48 | T-CaptureBack 已证伪，弃用 |

两个标签（省 95px）刚好把 542px 压到 447px ≤ 460px；其余杠杆要么不够、要么代价更大。

## 六、真机验收口径

**F1**：打开预览弹窗 → 按钮行恰 7 枚（压缩/格式化/关键字换行/竖向排列/执行计划/刷新/更多）→ 点「更多」→ 4 项且首项为「回滚 SQL」→ 点它：
- INSERT 预览 → 出可执行 DELETE 的回滚弹窗（与改前一致）；
- UPDATE/DELETE 预览 → Unable 提示框或快照工作流（与改前一致）；
- **第一次点弹窗按钮即生效**（N4 回归点：不再需要先聚焦对话框窗口）。

**F2**：SQL 日志工具窗 →
- 用户日常宽度（本次截图约 460px）下**恒为一行**，全部 8 个控件可见，右端无裁切；
- 悬停两个下拉按钮，tooltip 分别是「SQL类型：<当前状态>」「排序：<当前方式>」；
- 选中多个 SQL 类型（文案变长）后**仍是单行**，按钮显示省略号、tooltip 是完整状态；
- 出现慢查询时行仍为单行（短徽章 + tooltip 全文）；
- 侧边栏从 400 拖到 800：行数不变，无裁切；拖到 400 以下记录实际形态（图标组交给平台溢出的表现，见 §七）。

## 七、待验证前提（实施者先证伪再动手）

1. **预算数字来自截图量测**（506×658 截图，比例 1:1；块宽为墨迹外扩估算 ±10px）。实施时以 headless holder 打印 `preferredSize` 复核两条：「460px 下现状流式区理想宽 > 可用宽」（折行根因）与「去标签后一行总宽 ≤ 460px」（单行可行性）。
2. **ActionToolbar 在 CENTER 收缩时是否走平台溢出**（`setReservePlaceAutoPopupIcon` / 自动 chevron popup），还是直接裁掉尾部按钮。这决定极窄宽度（< 约 400px）的降级形态是「图标收进溢出菜单」还是「图标消失」；真机拖窄确认。若是后者，需给图标组加最小宽度兜底或改用可压缩包装。
3. **ActionToolbar 的留白是 border 还是内部 insets**：决定「图标组左内边距能否收敛到与面板边距一致」（现状首个图标墨迹距面板左缘 22px，偏大）。本机 IDE 安装包内未定位到 `ActionToolbarImpl` 字节码，**未做反编译核实**；实施时用 `javap -c` 或真机 `insets` 打印定案。此项只影响观感微调，不影响单行契约。
4. **定宽省略的实现落点**：`ellipsize` 是纯函数（文本+像素预算→文本），但按钮宽度上限的施加方式（`preferredSize` 覆盖 vs 文本预截断）需在真机确认 LaF 不会再把宽度撑开——**文本预截断**是更稳的一条（宽度由文本决定，截断即封顶）。
5. **慢查询徽章文案**（「慢 3」）是否被用户接受：这是本次唯一新增的文案形态变化，若用户不接受，退路是保留 `慢查询: 3` 全文并允许图标组溢出（依赖前提 2 成立）。
6. **极窄宽度（< 300px）**：本计划不承诺全部控件可见（平台侧边栏的实际最小宽以真机为准），只承诺**不折行、不出现单元素行**。
7. 基线测试计数（483 类 / 5463 例）取自 N4 计划，**实施时以 `testShards` 实测为准**。
