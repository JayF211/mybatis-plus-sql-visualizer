## 三、测试修复记录（合并后暴露的问题）

### 问题 1：bundle 守卫 2 例失败（BundleParityGuardTest）
- **现象**：`英文 bundle 缺键：[?#]` + `键数量应一致 expected:<625> but was:<626>`
- **根因**：冲突解决时用 PowerShell `Set-Content -Encoding utf8`（PS 5.1 语义）写 bundle，带入了 UTF-8 BOM（EF BB BF）。`java.util.Properties` 把 BOM+首行注释解析成幽灵键 `U+FEFF#`（显示为 `?#`），zh 侧多出 1 键。
- **修复**：改用 .NET `[System.IO.File]::WriteAllText` + `UTF8Encoding($false)` 无 BOM 写回；同时复原 master 原版首行注释。
- **验证**：单类重跑通过；全量 testShards 通过。

### 问题 2：AgentProtocolSyncTest 3 例失败（M56 既有缺陷，非合并引入）
- **现象**：`agent 源文件未找到: agent/src/main/java/.../EventBus.java`
- **根因**：M56 提交 `a1bf63e` 把 agent 子项目从根目录 `agent/` 迁到 `sub-projects/sql-visualizer-agent/` 时，漏改这个 IDE 侧协议同步测试的源码定位链。该测试当时的全量验证（bea1751，3359 用例）在迁移提交**之前**跑的，迁移后只重跑了 agent 子项目门禁与 buildPlugin，IDE 全量未复跑——缺陷一直潜伏到本次合并后首次全量。
- **修复**：readAgentSource 定位链补 `sub-projects/sql-visualizer-agent/` 前缀（repoRoot 上溯定位模式，与 BundleParityGuardTest 同款），调用处去掉 `agent/` 前缀；保留旧路径兜底。
- **验证**：单类重跑通过；全量 testShards 通过。
