# SQL 面板字段补全 + 注释提示——开发计划（M16）

> 本文档是 **MyBatis-Plus SQL Visualizer** 的 M16 增量计划：增强 SQL 预览面板（`SqlPreviewPanel`）的可编辑 SQL 编辑器的**代码补全**——在输入列名前缀（如 `nam`）时提示当前语句实体表的字段（`name`），并在补全列表中**显示字段注释**（实体代码中的 javadoc / 行注释），且**输入注释关键词（如"设备名"）也能匹配到对应字段**。
>
> 背景：M9 已实现 SQL 编辑 + 基础补全（关键字 + 表名/列名/表别名，见 `SqlCompletionContributor`），但补全项**无注释信息**——列名提示是裸字符串，用户无法区分同名/相似列，也无法用业务注释检索字段。用户要求"输入 nam 提示 name 字段，最好连注释也能提示出来"。
>
> 配套文档：[测试清单](../MPJ用法收集与兼容性测试清单.md)、[主开发计划](../开发计划/20260812-1058-MP-SQL可视化-开发计划.md)。
> 当前基线：v1.9（M15 真实语料兼容 + 官方 API 全覆盖已提交，217 测试全绿）。

## 1. 现状分析（证据驱动）

### 1.1 已有补全链路（M9，无需重构）

```
SqlPreviewPanel.createEditor(sql)
  └─ PsiFileFactory.createFileFromText("preview.mpsql", SqlPreviewLanguage, sql)
      └─ psi.putUserData(SqlCompletionContext.KEY, SqlCompletionContext(tableName, columns, tableAlias))
          └─ SqlCompletionContributor（plugin.xml <completion.contributor> 注册）
              └─ 关键字（SqlLexer.KEYWORDS）+ 表名 + 列名 + 别名（prefixMatcher 过滤）
```

- `SqlCompletionContext`（23 行）：`tableName: String?` / `columns: List<String>` / `tableAlias: String?`——**列名无注释**；
- `SqlCompletionProvider` 接口 + `DefaultSqlCompletionProvider`（35 行）：方案 A 上下文补全，预留 Database 方案 B 切换点；
- `SqlCompletionContributor`（57 行）：`LookupElementBuilder.create(col)`——**无 tailText/description**；
- 上下文绑定点：`SqlPreviewPanel#refreshCompletionContext`（166 行）与 `createEditor`（266 行）——列来自 `PreviewResult.columns`（= `table.allColumnNames`，SqlPreviewService:161）；
- `PreviewResult`（模型）：`columns: List<String>`——**无注释维度**。

### 1.2 差距（本计划补齐）

| # | 差距 | 现状 |
|---|------|------|
| G1 | **列注释未读取** | `ColumnInfo`（TableInfo.kt）无 comment 字段；`EntityResolver.resolveColumn` 不读 `PsiField` 的 javadoc / 行注释 |
| G2 | **注释未传递** | `PreviewResult.columns` 与 `SqlCompletionContext.columns` 均为纯 `List<String>`，注释无载体 |
| G3 | **补全项无注释展示** | `LookupElementBuilder.create(col)` 无 `withTailText` / `withTypeText`，列表里只有裸列名 |
| G4 | **注释不可检索** | prefixMatcher 只匹配 lookup 主串（列名），输入"设备名"无法命中 `name` 列（`withLookupString` 未用） |

### 1.3 不在范围（本里程碑明确不做）

- 数据源 schema 补全（方案 B：`com.intellij.database`）——**与 Community 兼容冲突**：database 插件仅 IntelliJ 商业版/旗舰版捆绑，引入依赖将破坏 Community 兼容性与「方案 A 上下文补全」的既有架构；接口 `SqlCompletionProvider` 已预留切换点，如后续确需 schema 补全应作为**独立里程碑**单独评估（可选依赖、降级回退策略），不混入本里程碑。

### 1.4 本计划纳入的用户补充需求（2026-08-13 评审）

| 需求 | 说明 |
|------|------|
| **注解形式注释（当前最高优先级）** | 支持 `@Schema(description = "描述")`、`@ApiModelProperty(value = "描述")`、`@ExcelProperty(value = "描述")` 等注解注释；**优先级：注解 > JavaDoc > 字段上方行注释**（注解与 JavaDoc 同时存在时优先注解，两者皆无时行注释兜底） |
| **位置感知补全** | WHERE 后只提示列、FROM 后只提示表、SELECT 列位提示列——从可选增强升级为正式任务 |
| **实体类注释 / 表注释** | `@TableName` 类级 javadoc / 注解 → 表名补全项展示注释 |
| **数据源 schema 注释（最高优先级，逻辑预留）** | 后期若接入数据源 schema（方案 B），**schema 的表/列注释为最高优先级**（高于注解注释）；本里程碑不实现 schema 查询，但**预留优先级链与合并逻辑**（见 §2.1/§2.5），未来接入时 schema 源自动生效 |

## 2. 方案设计

### 2.1 注释读取（T-M16-01，四级优先级 + schema 预留）

`ColumnInfo` 增加 `comment: String? = null`；`EntityResolver.resolveColumn` 按**四级优先级**读取字段注释：

0. **数据源 schema 列注释（最高优先级，逻辑预留）**：方案 B（`com.intellij.database`）接入后，从数据库 schema 读取列注释——**高于一切代码内注释**。本里程碑不实现 schema 查询（无数据源依赖），但预留**注释来源优先级链**（见下）；
1. **注解注释（当前实际最高）**：遍历字段注解，按**白名单注解 + 白名单属性**提取字符串值——
   - 白名单注解：`@Schema`（swagger 3）、`@ApiModelProperty`（swagger 2，属性 `value`/`description`）、`@ExcelProperty`（easyexcel，`value`）、`@DictField` 等自定义注解（属性 `description`/`name`/`comment`/`desc`）；
   - 白名单属性：`description` / `value` / `name` / `comment` / `desc`（字符串字面量）；
   - **排除 MP 注解**（`@TableField`/`@TableName`/`@TableId`/`@TableLogic`）：其 `value` 是列名/表名而非注释，不参与提取（`@TableField(comment = ...)` 的 comment 属性除外，MP 3.4+ 支持）；
   - 复用既有 `attributeString(annotation, attribute)`（EntityResolver:108）；
2. **JavaDoc（次优先）**：`field.docComment?.text`（`/** 设备名称 */` 或多行 javadoc）→ 提取描述文本（去除 `/**`、`*/`、行首 `*`，取 `@` 标签前段落，空行折叠）；
3. **行注释（兜底）**：字段上方相邻的行注释（`// 设备名称`）——遍历字段前的兄弟叶子找 `PsiComment`（跳过空行与 `@` 注解行，注释紧贴字段上方）。

**schema 预留设计（本里程碑落地）**：

```kotlin
/** 注释来源优先级（SCHEMA 最高，未来方案 B 接入即生效）。 */
enum class CommentSource { SCHEMA, ANNOTATION, JAVADOC, LINE_COMMENT }

// 注释提取返回 (文本, 来源)；合并时取最高优先级非空来源：
// 当前实现 schema 源返回 null（未接入），实际生效顺序 = 注解 > javadoc > 行注释；
// 未来实现 SchemaCommentProvider（方案 B）后，将其结果注入合并链即自动覆盖代码内注释。
```

- 提取函数签名：`resolveColumnComment(field): Pair<String?, CommentSource>`（或内部记录来源后合并为 `comment` 字段）；
- `ColumnInfo.comment` 保持**最终合并值**（最高优先级非空），不暴露来源给补全层（补全只关心文本）；
- 预留扩展点：`CommentProvider` 抽象（可选实现，当前仅 EntityResolver 内置链），方案 B 接入时新增 schema 实现并置于链首——**补全展示/检索层（T-M16-03）零改动**。

> 真实项目形态：swagger 注解（`@Schema`/`@ApiModelProperty`）是主注释来源，javadoc 次之，行注释少量。四级全无 → `comment = null`。

### 2.2 注释传递（T-M16-02）

- `PreviewResult` 增加 `columnComments: Map<String, String> = emptyMap()`——`SqlPreviewService.buildPreviewResult` 从 `table.columns` 提取（`ColumnInfo.comment` 非空时 `columnName → comment`）；
- `SqlCompletionContext` 增加 `columnComments: Map<String, String> = emptyMap()`（**保持 `columns: List<String>` 向后兼容**，既有调用点不动）；
- `SqlPreviewPanel` 两处绑定点（`refreshCompletionContext` / `createEditor`）传入 `current?.columnComments ?: emptyMap()`。

### 2.3 补全展示与检索（T-M16-03）

`SqlCompletionContributor` 列名补全升级：

```kotlin
provider.columnsWithComments(ctx).forEach { (column, comment) ->
    if (prefix.prefixMatches(column)) {
        val builder = LookupElementBuilder.create(column)
            .withTailText(if (comment != null) "  $comment" else null)   // G3：灰色注释尾缀
        if (comment != null) builder.withLookupString(comment)            // G4：注释关键词可匹配
        result.addElement(builder)
    }
}
```

- `withTailText`：补全列表列名右侧显示注释（IDE 灰色小字）；
- `withLookupString(comment)`：输入"设备名"等注释关键词也能命中 `name` 列（IDE 对 lookup string 集合做前缀匹配）；
- `SqlCompletionProvider` 接口增加 `columnsWithComments(context): List<Pair<String, String?>>`（默认实现取 `context.columns` 与 `context.columnComments` 合并，兼容无注释场景）。

### 2.4 位置感知补全（T-M16-04，正式任务）

按输入位置所在 SQL 子句过滤候选（轻量文本方案，不动 AST）：
- 从 `CompletionParameters.position` 的文档文本**向前扫描最近的结构关键词**（`SELECT` / `FROM` / `WHERE` / `GROUP BY` / `ORDER BY` / `HAVING` / `ON` / `JOIN`），推断当前子句：
  - `FROM` 之后 / `JOIN` 之后 → 提示**表名**；
  - `WHERE` / `ON` / `HAVING` / `GROUP BY` / `ORDER BY` 之后 → 提示**列名**；
  - `SELECT` 列位（关键词之间）→ 提示**列名 + 聚合函数**（COUNT/SUM/MAX/MIN/AVG，可后续加）；
  - 子句无法判定（SQL 片段起始）→ 保持全量候选（现状行为）。
- 表名/列名候选仍来自 `SqlCompletionContext`（当前语句实体），注释展示/检索逻辑与 T-M16-03 共用。

### 2.5 表 / 实体注释（T-M16-05，schema 预留同字段注释）

- `TableInfo` 增加 `comment: String? = null`（表级注释）；
- `EntityResolver.resolve` 读取类级注释（优先级同字段：**schema 表注释（预留最高）** > 类注解白名单（`@Schema(description=)` / `@ApiModelProperty(value=)` 等，排除 `@TableName` 的 value）> 类 javadoc > 类上方行注释）；
- 传递：`PreviewResult` / `SqlCompletionContext` 增加 `tableComment`；
- 展示：表名 lookup 加 `withTailText("  注释")` + `withLookupString(注释)`（同字段列）；
- **schema 预留**：与字段注释共用 `CommentSource` 优先级链——未来方案 B 接入后，schema 表注释自动覆盖类级注解/javadoc，补全层零改动。

## 4. 风险与应对

| 编号 | 风险 | 影响 | 应对 |
|------|------|------|------|
| M16-R1 | 注解注释误取：`@TableField("col")` 的 value 是列名、`@Schema(name = ...)` 的 name 是标识符，被当作注释 | 注释错乱 | **排除 MP 注解**（TableField/TableName/TableId/TableLogic）不参与提取；白名单注解按**属性白名单**取（Schema 只取 description、ApiModelProperty 取 value/description、ExcelProperty 取 value）；非白名单注解仅取 description/name/comment/desc 属性（不取 value） |
| M16-R2 | javadoc 多行文本清洗（`*` 前缀、空行、@param 标签）导致注释杂乱 | 补全列表可读性差 | 提取规则：取 javadoc 描述段落（`@` 标签前），逐行去 `*` 与首尾空白，空行折叠为空格；单行即首行 |
| M16-R3 | 行注释归属误判（字段下方/右方注释、多个连续注释） | 注释错位 | 仅取字段**上方**最近的非空行注释（跳过空行与 `@` 注解行），最多取 1 条；无法确定时返回 null |
| M16-R4 | `withLookupString` 引入注释词误匹配（如注释含通用词"状态"命中多列） | 补全列表膨胀 | 可接受（多列同注释时按列名区分）；后续可加"注释匹配权重低于列名"（不在本里程碑） |
| M16-R5 | 位置感知的轻量文本方案误判子句（如子查询内 WHERE、字符串字面量含关键词） | 候选过滤错误 | 仅向前扫描**行首/空白后的独立关键词 token**（排除字符串字面量内）；判定失败时回退全量候选（不劣于现状）；复杂场景留待 AST 方案 |
| M16-R6 | 模型重生成（动态条件勾选/参数回填）后 context 未刷新 | 注释与列不同步 | `refreshCompletionContext` 在每次 renderSql 前已调用（现网行为），T-M16-02 在该方法同步传入 columnComments |
| M16-R7 | 数据源 schema 补全（方案 B）与 Community 兼容冲突；schema 注释优先级预留的实现成本 | 架构决策 / 过度设计 | 本里程碑仅**预留优先级链与合并逻辑**（`CommentSource` 枚举 + 合并函数，schema 源当前返回 null，成本约 20 行）；不引入 database 依赖；方案 B 接入作为独立里程碑（`SqlCompletionProvider`/`CommentProvider` 接口已预留切换点，可选依赖 + 降级回退） |

## 5. 验收清单（M16）

1. **注释读取（四级优先级 + schema 预留）**：`@Schema(description = "设备名称")` 字段 → `comment == "设备名称"`；注解与 JavaDoc 并存 → 取注解；仅 javadoc → 取 javadoc 描述（多行清洗为单行）；行注释 `// 设备名称` 兜底；`@TableField("col")` 的 value 不误取；全无 → null；`CommentSource` 合并链：schema 源为空（未接入）时注解生效、schema 源非空（模拟注入）时覆盖注解；
2. **注释传递**：`PreviewResult.columnComments` 含注释列；`SqlCompletionContext.columnComments` 绑定正确（含模型重生成后刷新）；
3. **补全展示与检索**：SQL 编辑器输入 `nam` → 补全列表出现 `name` 且右侧灰色尾缀显示注释；输入 `设备`（注释关键词）→ 同样命中 `name`；
4. **位置感知**：FROM 后输入 → 提示表名；WHERE 后输入 → 提示列名；SELECT 列位 → 提示列名；无法判定子句 → 全量候选（回归）；
5. **表注释**：类级 `@Schema`/javadoc → 表名补全项展示注释；`TableInfo.comment` 预留 schema 覆盖链（同字段）；
6. **回归**：无注释实体列名补全行为与 M9 一致（裸列名）；关键字/别名补全不受影响；
7. **质量**：`./gradlew clean test --no-build-cache` 全绿；`./gradlew buildPlugin` 成功；
8. **文档**：CHANGELOG 记录 M16；README 功能特性更新（如适用）。
