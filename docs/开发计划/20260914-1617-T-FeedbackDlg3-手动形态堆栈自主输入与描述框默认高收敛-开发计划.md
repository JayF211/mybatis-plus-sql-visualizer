# T-FeedbackDlg3 手动形态堆栈自主输入与描述框默认高收敛 — 开发计划

- 日期：2026-09-14 16:17
- 来源：用户真机反馈（截图：手动「报告到需求池」弹框，勾选附带异常堆栈后预览区显示自动带入的最近错误池堆栈；描述区占掉大半窗口）
- 前置：T-FeedbackDlg（8ccb0ac）/ T-FeedbackDlg2（af01346）——同一对话框第三波真机反馈

## 一、问题

1. 手动形态勾选「附带异常堆栈」后，预览区显示的是打开对话框时自动从错误池抓的
   「最近一条插件错误」——用户预期是**自己决定附什么**：粘贴一段堆栈，或者从 IDEA
   内部错误列表里挑一条（且列表要过滤出本插件的）。自动塞最近一条既不受控，也没有
   任何换一条/清空的入口。
2. 描述框默认过大（滚动面板首选高 140 + 文本区 6 行，叠加 weighty=1 首屏占掉大半窗口）。

## 二、根因

1. T-FeedbackDlg2 对手动堆栈的定位是「附件候补自动预填」，形态选错了：错误池里未
   必有用户当下想报的那条（可能有多条、可能想报刚在别处看到的），预填单条 = 替用户
   做了决定。正确形态=自主选择输入（粘贴）+ 按需从错误池导入。
2. 首屏高度参数拍得偏大（T-FeedbackDlg 收敛宽度时未动纵向）。

## 三、修复设计

`ErrorReportDialog`（手动形态 prefill==null 分支重写）：

- 勾选行恒显示（不再依赖错误池有无）。
- 堆栈区改**可编辑**（emptyText 占位提示「粘贴异常堆栈，或点上方从 IDE 错误池导入」），
  错误形态维持只读预览。
- 勾选行右侧新增「从 IDE 错误池导入…」按钮（错误形态隐藏）：点击时经构造参数
  `stackPoolProvider: () -> List<String>` **实时**拉候选（弹窗时点菜单才读池，反映实时
  状态），JPopupMenu 每项以堆栈首行（异常类: 消息，超 80 字符截断）为文本，点击填入
  堆栈区（覆盖式，可再编辑）；空池显示禁用的说明项。
- `collectStackAttachment`：错误形态仍用 event 全文（预览仅截断展示）；手动形态取文本区
  实际内容（勾选但内容为空视同不附带）。
- `FeedbackReporting.latestPluginErrorStack()` 重构为 `pluginErrorPoolStacks()`：同数据源
  （MessagePool.getFatalErrors(true,true)，T-FeedbackDlg2 javap 双版本签名结论沿用）、
  同包名归属过滤，返回最近在前、按堆栈去重、至多 10 条。
- 描述滚动面板首选高 140→90、描述文本区 6→4 行；勾选行为「勾选框+导入按钮」FlowLayout
  同行容器（buildCenterPanel 形态变化：stretch 行仍为描述+堆栈两行）。
- i18n 双语各 +4 键：`error.report.dialog.stackImport` / `.tip` / `.empty` /
  `stackPreview.placeholder`。

## 四、验收

- `ErrorReportDialogLayoutTest` +1 例：字段类默认态=错误形态基线（堆栈区只读、导入按钮
  隐藏）+ 4 枚新键 bundle 落地（缺键原样显示键名即炸）。
- 全量裸命令 test 绿即门禁（verifyFull/buildPlugin 按用户口径跳过）。

## 五、真机走查清单（留人工）

1. 手动入口（Help 菜单/设置页）：勾选行恒显示；勾选后堆栈区可编辑、出现占位提示。
2. 点「从 IDE 错误池导入…」：菜单列出本插件错误（最近在前、首行为文本）；点击填入；
   错误池无本插件错误时显示禁用说明项。
3. 粘贴一段任意堆栈并勾选 → 提交后需求池附件 .txt 内容=粘贴内容（含环境头）。
4. 错误形态（Internal Errors 报告）回归：预填只读预览、附件=event 全文、无堆栈隐藏勾选行。
5. 描述框首屏明显变矮；拖拽拉伸行为不变；勾选/取消跳动补偿（T-FeedbackDlg2）仍正常。
