## 二、逐项根因与修法

### P1 预览恒降级模式（回归，`11e2671f` 引入）

**根因**：`SqlPreviewPanel.kt` 的产物发布侧各 new 了一个 `Pair`——`:580` `prewarmedTempFile = vf to psi` 与 `:581` `await.complete(vf to psi)`；消费侧 `:2509` 用**引用相等** `prewarmedTempFile === prewarmed` 判「产物未被消费」→ 两个实例恒不等 → 恒走 `:2542` 的 `fallbackPreviewDocument`（内存 PSI + DEGRADED 横幅）。
旧码是 `val ready = prewarmedTempFile?.also{…}`（直接读字段），重构把「读字段」换成「比对 await 交付值」时引入了两个实例。

**修法**：发布侧收成单次构造（新方法 `publishPrewarmProduct(await, product)`），字段与 await 收到**同一个实例**——「同一实例」由结构保证而非两处各写一遍；消费侧 `===` 保留并加注语义来源。一次性消费语义不变（首次装配消费置 null、`releaseEditor` 后二次装配仍判不可用）。

**测试**：新增 `SqlPreviewPanelPrewarmConsumeTest` 3 例（交付值与字段同实例 / 产物可用时走临时文件分支不落内存 PSI / 已消费后二次装配降级）。**反向验证**：把发布侧改回「写两遍」重跑，3 例全红，随后还原。

**顺带**：`clear()` 新增 `metaLabel.toolTipText = null`（此前清空后残留上一份预览的 tooltip）。

### P2 回滚口径文档

**实测口径（以代码为准，`sql/rollback/RollbackSqlGenerator.kt`）**：
- **只有 INSERT 能自动生成回滚**（`:158-176` 分派 → `:184-250`）：要求有列清单（`:205`）、值是 VALUES 而非 SELECT（`:196-203`）、无 `ON DUPLICATE KEY UPDATE`（`:190-192`）；
- **谓词恒为整行等值**：生成器支持主键偏好（`:210-211`/`:229`），但**预览面板调用点不传主键**（`ui/SqlPreviewPanel.kt:817` 是 `generate(sql)`，`:922` 注释明说 `primaryKeyColumns` 现无生产调用点）→ 面板产出的 INSERT 回滚一律 `DELETE FROM t WHERE 列=值 AND …`（`NULL` → `IS NULL`，`:513-515`）；
- **UPDATE / DELETE 不可自动生成**（`:172`/`:174`，statements 恒空），只给快照查询 + 粘贴回填（`ui/RollbackSqlDialog.kt`，主键输入框只对 UPDATE 生效）；
- SELECT 等类型 → 「PlainSelect 语句不支持自动回滚。」（`:175` + bundle `:129`）；
- 警示：整行谓词（`:215`）、未回填占位符（`:217-219`）、500 条/256KB 截断（`:234-238`）；COUNT 自查模板 `:239-242`。

**修法**：`features/xml-preview.md` 的「回滚 SQL」节按上述口径重写（原「INSERT 按主键生成 DELETE、UPDATE 还原 SET 原值、DELETE 按 WHERE 重插」三句均不成立），`en/features/xml-preview.md` 同步。按钮实际文案是「**回滚 SQL**」而非「回滚」。

### P3 `sqlv_schema_context` 参数类型错抛内部异常

**根因不在插件代码**：平台 `mcpserver.jar` 的 `CallableBridge.call:52` 用 kotlinx 反序列化参数，遇到类型不符（`tables` 传 JSON 数组）时在 `TaggedDecoder.popTag` 对空 tag 栈 `ArrayList.remove(-1)` → `Index -1 out of bounds for length 0`；该次调用**没有 `[MCP-AUDIT]` 行**，证明工具方法体根本没进。插件侧唯一可控点是**参数声明类型**。

**修法**：入参改为容错载体 `McpStringArg` / `McpIntArg`（自定义 serializer + primitive descriptor，对任意 JSON 形态都不抛，形态记进 `McpArgKind`）；取值校验收敛为纯函数 `parseTableNames` / `parseDataSource` / `parseMaxTables`，形态不符与取值不符一律 `[INVALID_ARGUMENT]`（空串/纯分隔符/超 50 沿用原文案逐字不变）。
**契约零变化**：对编译产物实跑 262 的 `parametersSchema`，`inputSchema` 与改前逐字节相同（`tables`/`dataSource`: string、`maxTables`: integer、`required: ["tables"]`）。

**测试**：`McpSchemaContextArgsTest` 12 例（数组形态/空串/纯分隔符/超 50/合法清单/object+null/标量标签/dataSource 形态/maxTables 形态与取值/描述符契约）。

### P4 `tables` 跨 schema 污染

**根因**：`McpSchemaContextService.buildContext` 走 `DatabaseSchemaResolver.tableMeta`，而 `DatabaseSchemaResolver.kt:437` **只比表名不看 schema**、`:459` 把命中表的列并进同一个 `out` Map → `tables:"user"` 同时收 `mp_demo.user` 的 9 列与 `mysql.user` 的 51 列（真机日志 `scan: table=user, ds=jpa_demo@localhost, tablesScanned=335, hit=true, foundColumns=60`）。

**修法**：`McpSchemaContextService` 自建「表名 → 目标库那张表」索引，四层限定：① 别名命中时只扫该数据源；② 数据源内用 `JdbcUrlDatabase.nameFromUrl(连接 URL)` 取目标库名，只收祖先链含该库名的表；③ URL 无库名时退回按名匹配（不新增失败模式）；④ 索引调用内共享且**不读 resolver 的正缓存**（那份缓存按表名存的就是合并结果）。同名表不再合并列。工具 `@McpDescription` 同步写明该口径。

**测试**：`McpSchemaContextScopeTest` 8 例（同名跨 schema 只收目标库/目标库无表不拿别库顶替/无库名退回按名/无列无注释不算命中/库名大小写/取数只返回目标库且列不合并/首个数据源只有系统表同名不得冒充命中/一次调用只遍历一次模型）。

### P5 meta 行调用栈摘要未接通

**根因**：`updateMeta` 只拼 `metaLineText = meta + warningLine`，摘要只进 `toolTipText`。
**修法**：`metaLineText = meta + warningLine + stackText.inlineLine`；tooltip 内容不变。
**测试**：`SqlPreviewPanelStackDigestTest` 由 8 例扩到 9 例——原「现状锁定」用例改写为 `test可见meta行含调用栈摘要_截断到120字符`，新增 `test窄窗_可见行中段省略_tooltip恒全文`。
**宽度预算实测**（300 字符链）：w=870/900（小屏）预算放不下 meta 前缀 → 可见行只剩链尾约 46 字符，**看不到「调用栈:」文案**；w=1190（1920 屏默认）标签可见；w=1920 标签 + 约 85 字符链头 + 链尾。完整链恒在 tooltip 内。

### P6 参数提示态覆写 meta tooltip

**判定**：顺手写坏，非刻意设计（`T-Perf-20` 注释只声明行内警示 + toast 语义，未提丢弃 tooltip；提示文案在可见行已全文可见）。
**修法**：空剪贴板分支前置为 `showEmptyClipboardHint()`（纯行内状态、不弹窗），tooltip 由「覆写」改「拼接」：`hint + "\n" + metaTooltipBase`；新增基线缓存字段保证重复触发幂等，`clear()` 复位。
**测试**：`SqlPreviewPanelMetaHintTooltipTest` 3 例（提示态保留完整链/重复触发不叠加/下次预览恢复纯 meta tooltip）。
