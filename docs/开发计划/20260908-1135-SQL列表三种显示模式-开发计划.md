# SQL 列表 SQL 三种显示模式（单行/关键字换行/格式化） 开发计划

> 需求：SQL 日志与 SQL 历史两个列表中，SQL 行内文本目前是单行展示，长 SQL 阅读不便——要求支持三种显示模式且可切换：**单行**（现状）、**关键字换行**（子句顶格换行、同行内容压一行，**默认**）、**格式化**（多行缩进全展开）。先制定开发计划文件，再实施。
> 术语沿用预览面板既有按钮文案：「关键字换行」（`panel.keywordWrap`）与「格式化」（`panel.format`），与用户口语「关键词换行」同义。
> 工作目录：dev worktree；上一交付 T-TwoLine（832e100~0260f07）之后。

## 一、现状定位

两个渲染点沿用 T-TwoLine 后的结构「元信息行 `<br>` SQL 高亮行」，SQL 行内是单行原文：

| 列表 | 渲染点 | SQL 段现状 |
|------|--------|------------|
| SQL 日志 tab | `SqlLogPanel.kt` → `LogEntryListCellRenderer.computeRowHtml`（aae6768 后 ~L1420） | `SqlListHtmlRenderer.render(withTerminator(entry.summary))` |
| SQL 历史 tab 二级 | `HistorySqlLogPanel.kt` → `HistoryCellRenderer`（~L520） | 同上 |

**现成能力盘点（本计划零新算法）**：

- **关键字换行变换器已存在**：`SqlFormatter.formatClauseLine`（M-KeywordWrap，SqlFormatter.kt L211~362）——主子句顶格换行、列清单/条件压一行、AND/OR 前双空格、括号内不展开、字符串原文保留；预览面板「关键字换行」按钮在用，`SqlFormatterTest` 已有 5+ 用例覆盖。
- **格式化变换器已存在**：`SqlFormatter.format`（M9/T-M27.4）——多行缩进全展开，预览「格式化」按钮与 `settings.logFormatSql` 预览链路在用。
- **多行渲染通路已存在**：`SqlListHtmlRenderer.escapeHtml` 把 `\n` 转 `<br>`；两列表 `fixedCellHeight = -1` 可变行高；`cachedListHtml` 惰性缓存按条目生效。
- **复制链路不受影响**：Ctrl+C 走 `SqlEntryList.itemToText`（纯 `restoredSql`）、tooltip 也是 `restoredSql`——显示模式只影响视觉。

**平台陷阱（本计划唯一技术点）**：Swing BasicHTML 按 HTML 规则折叠连续空白——`format` 的 AND 缩进 4 空格/子查询缩进、`formatClauseLine` 的 AND 前双空格渲染后会塌成单个空格，缩进层次丢失。须在 HTML 转义时把空格替换为 `&nbsp;`（列表场景无 word-wrap，无副作用）。

## 二、方案决策

**方案 A（选定）：渲染前按模式变换 SQL 文本 + 全局持久化模式 + 工具栏下拉切换**

- 渲染管线：`withTerminator(entry.summary)` → 按模式变换（单行=原文 / 关键字换行=`formatClauseLine` / 格式化=`format`）→ `SqlListHtmlRenderer.render`。变换器全部现成，改动只在两处渲染点的 SQL 段与一个模式枚举。
- 模式存 `PluginSettings`（新字段，默认 `KEYWORD_WRAP`）——两列表共享同一模式，跨会话保留；用户切到「单行」不用每次会话重设。
- 切换控件：两列表工具栏各一个 `JComboBox`（三选项）。变更后写 state 并**发布 `SETTINGS_CHANGE_TOPIC`**——SQL 日志面板既有订阅者会清全部 `cachedListHtml` + `refreshList`（零新增刷新逻辑）；历史面板补一个订阅（见 T-ListMode-5）。
- 发布 topic 而非各自本地刷新的理由：日志 tab 的条目缓存在长生命周期 manager buffer 里，若只在历史 tab 切模式、本地清理，回到日志 tab 时旧模式缓存永不失效（tab 切回不触发重读）；topic 广播让两侧缓存同时失效，combo 选中态也可在同一监听里对齐。

**方案 B（弃）：面板内存态模式（不持久化）**——实现最简，但每次会话重置回关键字换行，用户固定偏好「单行/格式化」时反复重设，体验差。
**方案 C（弃）：换 JBTable/自绘渲染器**——为缩进这类渲染细节推翻列表结构，改动面与收益不成比例。

**边界与行为细则**：

- 关键字换行/格式化会大写化关键字（既有变换器规则，预览按钮同款行为，非缺陷）；字符串/标识符原文保留。
- `summary` 超 160 字符截断逻辑不变（显示层截断在变换之前——截断后的文本再变换，行数可控）。
- 历史面板一级（文件列表）不受影响；二级打开的文件切模式即时生效（缓存清空+repaint）。
- 两个 combo 选中态经同一 topic 监听对齐（含日志面板自身——监听里同步 combo，加防重入守卫防循环触发）。

## 五、风险与回滚

- 每条目行数增多（格式化档最多，超长 SQL 可能几十行）——列表高度自适应已启用，属用户主动选择的形态；关键字换行档行数 = 子句数，通常 ≤10 行。
- 渲染开销：变换只在条目首次渲染（或模式切换后首次渲染）执行一次并进 `cachedListHtml`，滚动零重算；模式切换一次 O(可见行) 重算，符合 T-LogListFreeze 纪律。
- `&nbsp;` 替换作用于所有模式的渲染文本——单行模式视觉无差异（连续空格本就会被折叠，替换前后显示一致）。
- 旧用户升级后默认形态变化（单行→关键字换行）——本需求明确要求，非回归。
- 回滚：渲染点两处 + 设置字段 + bundle + 测试，单提交 `git revert` 即可（设置字段残留旧 XML 值由 valueOf 容错兜底）。
