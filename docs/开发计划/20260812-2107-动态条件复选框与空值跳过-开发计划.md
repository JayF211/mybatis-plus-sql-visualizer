# 动态条件支持（布尔重载复选框 + 空值不拼接）——开发计划（M12）

> 本文档是 **MyBatis-Plus SQL Visualizer** 的 M12 增量开发计划：**支持 MyBatis-Plus 动态条件**（布尔条件重载 `.eq(true, "name", "张三")` / `.eq(flag, col, val)` / `.eq(false, ...)`），在 SQL 预览弹窗左侧面板为动态条件提供**复选框开关**，并支持「**值为空不拼接、填写值才拼接**」的交互规则。

> 当前基线：Kotlin 2.3.20 + IntelliJ Platform Gradle Plugin 2.18.1 + IDEA 2025.3.5，v1.5（M11）已提交（commit e84e0aa），测试全绿。展示已收敛为**恒弹窗**（`SqlPreviewDialog`），左栏为参数输入区、右栏为可编辑 SQL 编辑器。

## 1. 概述与目标

**用户需求**：希望插件支持 MyBatis-Plus 的动态条件写法，典型形态：

```java
// 布尔条件重载（MP 动态条件）：condition 为 true 才拼接，false 不拼接
wrapper.eq(true, "name", "张三");                 // 恒拼接
wrapper.eq(isActive, "name", "张三");             // 运行时布尔，未知
wrapper.eq(StringUtils.isNotBlank(name), "name", name); // 值空 → 不拼接
wrapper.eq(false, "station_id", "2");             // 恒不拼接
```

**期望的交互**（在 SQL 预览弹窗**左侧面板**上）：
1. 每个**动态条件**显示一个**复选框**：勾选 → 该条件拼接进 SQL；取消勾选 → 从 SQL 移除，其余条件不受影响；
2. **值为空时不拼接**：动态条件若带未解析参数（值输入框），值为空时该条件默认不拼接；手动填写值后拼接。删除值再次不拼接；
3. **空字符串语义区分（用户补充，须实现）**：「值为空」不能一刀切，须按布尔条件实参的**判空方式**区分：
   - **判空/空白**（`StrUtil.isNotBlank` / `StringUtils.isNotBlank` / `isNotEmpty` / `hasText` 等）：值出现**空字符串** → 不拼接；
   - **判非 null**（`isNotNull` / `nonNull` / `!= null` 等）：**空字符串是合法值，需要拼接**（渲染为 `name = ''`），仅 **null** 才不拼接。

**为什么要做**（现状）：
- 插件当前只把布尔重载做**静态处理**（`QueryWrapperParser.skipConditionFlag`）：`true`/运行时布尔 → 剥离标志保留条件；`false` → 整体丢弃。用户无法在预览时**交互式**控制某个动态条件的开/关，也无法直观看到 `.eq(flag, col, var)` 这类「值空就不生效」的条件在 SQL 里到底拼没拼。
- 弹窗左栏目前只有「未解析参数输入框」（`#source` 标签 + 文本框），无条件级开关，`?` 按位置替换；动态条件的开/关需要模型级重生成，现有 DTO（`PreviewResult` 只携带 SQL 文本）不足以支撑。

**范围控制**：
- 动态条件 = **布尔条件重载的方法**（与现有 `CONDITION_METHODS` 对齐：`eq/ne/gt/ge/lt/le/like/notLike/likeLeft/likeRight/in/notIn/between/notBetween/isNull/isNotNull`）+ `apply(condition, sql, args)` 布尔前缀形式。
- 「空值不拼接」规则**仅作用于动态条件**（带 `toggle` 元数据的条件），普通未解析参数（无布尔标志，如 `eq(col, var)`）保持现有行为（空值保留 `?`）——避免行为变更面扩大。
- 展示收敛为弹窗（M11），本里程碑只增强 `SqlPreviewPanel` 左栏与模型/生成层，不动入口与展示方式。

## 2. 现状与影响面（代码清单）

### 2.1 现状：布尔重载的静态处理

| 位置 | 现状 | M12 改动 |
|------|------|----------|
| `converter/QueryWrapperParser.kt` `skipConditionFlag()` | 对 `CONDITION_METHODS` 首参布尔标志**剥离**：字面量 `false` → 返回空 args → 条件**整体忽略**；`true`/运行时布尔 → 剥离标志保留条件 | 改为 **`markConditionFlag()`**：不再剥离/丢弃，而是把布尔标志固化为条件的 **toggle 元数据**（`flagSource`、`defaultEnabled`）；`false` 条件**进入模型但默认排除** |
| 同文件 `parseApply()` | `apply(condition, sql, args)` 布尔前缀字面量 `false` → 返回 null 丢弃；`true` → 透传 | 同样标记 toggle（`Condition.Raw` 可勾选），不丢弃 |
| `model/Condition.kt` | 密封类 7 种节点，无「可勾选」元数据 | 各子类增加 `toggle: ConditionToggle? = null`（默认 null，旧逻辑/旧测试不受影响） |
| `sql/SqlGenerator.kt` | 纯渲染，无条件过滤 | 支持 `enabledConditionIds` 过滤（默认 null = 按 `toggle.defaultEnabled`），递归进 Group |
| `ui/SqlPreviewPanel.kt` | 左栏按位置渲染参数输入行，`backfillParams` 文本级替换 `?` | 左栏改「动态条件复选框行 + 值输入框」，参数**按 source 绑定**，变更即**模型级重生成** |
| `model/PreviewResult.kt` | 只携带 SQL 文本 + 参数来源列表，无模型 | 增加 `previewModel: SqlPreviewModel?`（statement + dialect + formatSql + conditionViews），供面板重生成 |
| `ui/SqlPreviewService.kt` `buildPreviewResult()` | 生成 `PreviewResult` 文本 | 组装 `SqlPreviewModel` 与 `conditionViews` |

### 2.2 依赖核验（已确认）

- **生成层默认行为必须与 M11 基线逐字节一致**：现有测试 `QueryWrapperParserTest.布尔条件重载_字面量true保留_false忽略`（断言 `eq(false,...)` 不出现在 SQL）、`apply字面量false忽略` 依赖「false 丢弃」。M12 中这些条件改为**进入模型但默认排除**，`SqlGenerator` 默认（无 enabledIds）按 `defaultEnabled=false` 过滤 → 生成 SQL 不变 → **旧测试断言原样通过**（回归兜底，见 T-M12-02/03）。
- **批量操作路径零影响**：`BatchOperationConverter` 直接产 `PreviewResult`（无 statement 模型），`previewModel` 为 null，左栏走旧逻辑。
- **入口与展示零影响**：`ConvertToSqlAction` / gutter 点击走 `SqlPreviewService.showResult` 弹窗，本里程碑不触碰。

## 3. 方案设计

### 3.1 总体数据流

```
源码 Wrapper 链
   │  ArgResolver（psi）——布尔标志保留为实参（不改）
   ▼
QueryWrapperParser.markConditionFlag()   ← 替换 skipConditionFlag
   │  生成 Condition + toggle 元数据（id / flagSource / defaultEnabled / label / valueSource）
   ▼
SelectStatement.conditions（Condition 树，含 toggle）
   │
   ├─ SqlGenerator.generateWithParams(statement, compact, dialect, enabledIds)  ← 默认渲染
   ▼
SqlPreviewService.buildPreviewResult → PreviewResult.sql + previewModel(statement, dialect, formatSql, conditionViews)
   ▼
SqlPreviewPanel（弹窗左栏）
   ├─ 动态条件行：☑ label  + (值输入框)
   ├─ 普通参数行：#source + (值输入框)
   ├─ 勾选/填值/清空 → enabledIds / paramValues(按 source) 变更
   ▼
renderSql() = SqlGenerator.generateWithParams(statement, compact, dialect, enabledIds) → 按 source 回填
```

### 3.2 模型层：`ConditionToggle` 元数据

新增 `model/ConditionToggle.kt`：

```kotlin
/**
 * 动态条件「空值」语义（M12，用户补充）：布尔条件实参的判空方式决定空字符串是否拼接。
 *
 *  - SKIP_ON_BLANK：判空/空白（isNotBlank/isNotEmpty/hasText/StrUtil 等）→ 空字符串不拼接；
 *  - SKIP_ON_NULL ：判非 null（isNotNull/nonNull/!= null）→ 空字符串是合法值需拼接（name = ''），仅 null 不拼接；
 *  - UNKNOWN      ：无法识别判空方式 → 默认按 SKIP_ON_BLANK（用户主诉求「值为空不拼接」）。
 */
enum class EmptyValueRule { SKIP_ON_BLANK, SKIP_ON_NULL, UNKNOWN }

/**
 * 动态条件元数据（M12）：布尔条件重载的解析产物，决定该条件在预览面板可否勾选开关。
 *
 * @param id            稳定标识（条件树 pre-order 索引，如 "c0" / "n1-c0"），UI 复选框 ↔ 条件关联键；
 *                      面板维护的启用集合（Set<String>）以 id 为元素
 * @param flagSource    布尔条件实参源码文本（"true"/"false"/"isActive"/"StringUtils.isNotBlank(name)"），
 *                      用于复选框 tooltip 展示；null 表示该条件非布尔重载（保留扩展位）
 * @param defaultEnabled 默认勾选态：字面量 true→true、false→false；运行时布尔→true；
 *                      若判空方法可静态求值（值已知字面量）→ 按语义求出（如 isNotBlank("")→false）
 * @param emptyRule     空值语义（[EmptyValueRule]），由判空方法名/表达式形态判定，默认 SKIP_ON_BLANK
 * @param label          人读条件文本（如 "name = '张三'" / "name = ?"），复选框行标签
 * @param valueSource    关联的未解析参数来源（该条件有值输入框时非 null，用于按 source 绑定与空值联动）
 */
data class ConditionToggle(
    val id: String,
    val flagSource: String?,
    val defaultEnabled: Boolean,
    val label: String,
    val emptyRule: EmptyValueRule = EmptyValueRule.SKIP_ON_BLANK,
    val valueSource: String? = null,
)
```

`Condition` 各子类（`Simple/Unary/In/Between/Like/Group/Raw`）增加 `val toggle: ConditionToggle? = null`。**非动态条件 toggle 为 null**——渲染、面板均不受影响（兼容旧逻辑与旧测试）。

### 3.3 转换层：`skipConditionFlag` → `markConditionFlag`

- **识别**：沿用现有 `CONDITION_METHODS` 与「首参非 ColumnArg/NestedArg/OnConditionArg 且 args≥3」判定（即首参为布尔）。
- **标记**（不再剥离/丢弃）：
  - `eq(true, col, val)` → `Condition.Simple(col, "=", val, toggle = Toggle(id, "true", defaultEnabled=true, label, valueSource?))`
  - `eq(false, col, val)` → 同一条件，`defaultEnabled=false`（进入模型，生成默认排除）
  - `eq(flagVar, col, val)`（运行时布尔）→ `defaultEnabled=true`，`flagSource=flagVar.text`
  - 列名/值取参逻辑不变（`argAsColumn`/`argAsValue` 已支持字符串列名 QueryWrapper 形式 `.eq(true, "name", "张三")`）。
- **判空语义识别（用户补充）**：从布尔实参**源码文本**判定 `EmptyValueRule`（运行时布尔已是 `SqlValue.Placeholder(source=表达式文本)`，直接文本匹配，无需 PSI）：
  - 含判空/空白方法名（`isNotBlank` / `isNotEmpty` / `hasText` / `isBlank` 等，含 `StrUtil`/`StringUtils` 任意限定）→ `SKIP_ON_BLANK`；
  - 含判非 null 形态（`isNotNull` / `nonNull` / `Objects.nonNull` / `!= null` / `null !=`）→ `SKIP_ON_NULL`；
  - 其余（纯布尔变量/无法识别）→ `UNKNOWN`（默认按 `SKIP_ON_BLANK` 兜底）。
  - 反向判空（`isNull` / `isEmpty` / `isNullOrEmpty`，值空才拼接）→ 文档化边界情况，第一版按 `SKIP_ON_BLANK` 处理并在 tooltip 提示，行为对齐待反馈（见 M12-R7）。
- **判空方法静态求值（增强，随 T-M12-02）**：当布尔实参是**已知判空方法调用**（`isNotBlank(x)` 等）且**值可静态求值**（`ExpressionEvaluator` 追踪变量 → 字面量）时，直接求出布尔结果作 `defaultEnabled`：
  - `StrUtil.isNotBlank(name)` 且 `name=""` → `defaultEnabled=false`（不拼接）；
  - `name != null` 且 `name=""` → `defaultEnabled=true`（拼接 `name = ''`）；
  - `name != null` 且 `name=null` → `defaultEnabled=false`。
  - 实现：`ExpressionEvaluator` 新增对已知判空方法的求值分支（纯静态、不 resolve 外部库，仅按方法名 + 实参字面量计算）。
- **label 生成**：从已构建的 `Condition` + 占位值渲染人读文本（复用 `SqlGenerator` 抽取的 `renderConditionText`，占位符渲染为 `?`）。
- **valueSource**：条件值为 `SqlValue.Placeholder` 时取 `source`（该条件有值输入框）；字面量值无输入框。
- **`parseApply`**：布尔前缀字面量 `false` 不再返回 null，而是 `Condition.Raw(sql, toggle=Toggle(defaultEnabled=false))`；`true`/运行时 → `defaultEnabled=true`。
- **嵌套 `and/or` Group**：lambda 体解析（`resolveNestedLambda`）走同一 `parse`，内部条件同样打 toggle，id 按树路径生成（`n<父id>-c<组内序号>`）。

### 3.4 生成层：按启用集合过滤

`SqlGenerator.generateWithParams(statement, compact, dialect, enabledConditionIds: Set<String>? = null)`：

- `renderConditionList` / `renderCondition` 增加 `enabledIds` 参数：对每个条件，若 `toggle != null` 且：
  - `enabledIds == null` → 按 `toggle.defaultEnabled` 决定是否跳过（**默认行为，与 M11 输出逐字节一致**）；
  - `enabledIds != null` → 仅当 `id in enabledIds` 才渲染。
- `Group` 递归：`id in enabledIds` 时继续渲染子节点（子节点各自按 id 过滤）；组内全空 → 组整体不渲染。
- 附带：抽取 `internal fun renderConditionText(condition: Condition): String`（占位符渲染为 `?`），供转换层生成 `ConditionToggle.label` 复用（避免渲染逻辑重复）。
- **纯逻辑、无 PSI 依赖**，可独立单测。

### 3.5 服务/UI 层：`PreviewResult.previewModel` + 左栏复选框

新增 `model/SqlPreviewModel.kt`：

```kotlin
data class SqlPreviewModel(
    val statement: SqlStatement,        // 重生成输入
    val dialect: Dialect,               // 方言
    val formatSql: Boolean,             // 多行/单行
    val conditionViews: List<ConditionView>, // 动态条件行（扁平化，含嵌套组内）
)
data class ConditionView(
    val id: String,
    val label: String,
    val flagSource: String?,
    val defaultEnabled: Boolean,
    val emptyRule: EmptyValueRule,      // 空值语义（驱动输入框空值行为）
    val valueSource: String?,           // 有值输入框时为非 null
)
```

`PreviewResult` 增加 `val previewModel: SqlPreviewModel? = null`（默认 null → 批量操作等旧路径零影响）。

`SqlPreviewPanel` 左栏改造（`rebuildParamPanel` → `rebuildLeftPanel`）：

```
左栏（示意，右栏为 SQL 编辑器）：
┌──────────────────────────────┐
│  动态条件                      │
│  ☑ name = '张三'              │  ← .eq(true, "name", "张三")，无值框
│  ☐ station_id = '2'           │  ← .eq(false, "station_id", "2")，默认排除
│  ☑ name LIKE %?%  [张三]       │  ← .like(flag, name, var) 判空：填值→勾选，清空→取消
│  ☑ name = ?        []         │  ← .eq(name != null, "name", name) 判非null：
│                               │     空值仍拼接为 name = ''；取消勾选才排除
│  ────────── 参数 ────────────  │
│  #deviceId         [ 1001 ]    │  ← 普通未解析参数（无 toggle）
└──────────────────────────────┘
```

- **状态**：`enabledIds: MutableSet<String>`（初值 = 各 view 的 `defaultEnabled`）、`paramValues: MutableMap<String, String>`（**按 source 绑定**，替代现有位置 `MutableList`）。
- **动态条件行**：`JCheckBox`（默认勾选态 = defaultEnabled；带值输入框时与值联动）+ 条件 label +（若有 valueSource）`JBTextField`。
- **勾选事件**：`enabledIds` add/remove → `renderSql()` 重生成。
- **值变更事件**（空值行为按 `emptyRule` 区分）：
  - 更新 `paramValues[source] = text`；
  - 动态条件（valueSource 非 null）按判空语义联动：
    - `SKIP_ON_BLANK`（判空，默认）：**空值 → 自动从 `enabledIds` 移除**（不拼接），非空 → 自动加入（拼接）；
    - `SKIP_ON_NULL`（判非 null）：**空值也保持勾选并拼接**——回填时渲染为 `''`（空字符串字面量，因为 `'' != null` 通过判空）；仅用户**手动取消勾选**才排除；
    - 手动勾选可覆盖联动，直到值再次变化；
  - 非动态条件的参数（无 toggle）保持旧行为：空值保留 `?`。
- **renderSql()**：`previewModel` 非 null 时 → `SqlGenerator.generateWithParams(statement, compact, dialect, enabledIds)` → 按 source 回填 `?`（遍历 `unresolvedParams` 定位 source → `paramValues[source]`；**`SKIP_ON_NULL` 来源空值渲染 `''`**）；`previewModel` 为 null → 走旧文本路径（`current.sql`/`compactSql` + 位置回填）。
- **普通参数行**：保留现有「#source 标签 + 值输入框」，但值存储改为 source 键（同一 source 多处出现共享一个输入框与值——对齐 MP 实参语义）。

### 3.6 交互规则汇总（与需求逐条对齐）

| 需求 | 规则 |
|------|------|
| `.eq(true, "name", "张三")` 支持复选框 | 左栏一行 `☑ name = '张三'`，默认勾选；取消勾选 → 该条件从 SQL 移除 |
| `.eq(false, ...)` | 默认**不勾选**、SQL 默认排除；用户勾选后拼接（比当前「丢弃」更灵活） |
| 判空动态条件 `eq(isNotBlank(name), col, name)` | `SKIP_ON_BLANK`：值空 → 自动取消勾选（不拼接）；填写 → 自动勾选（拼接）；删除值 → 再次取消 |
| 判非 null 动态条件 `eq(name != null, col, name)` | `SKIP_ON_NULL`：**空值也拼接为 `name = ''`**（空字符串是合法值）；仅手动取消勾选才排除 |
| 运行时布尔 `eq(flag, col, var)`（无法识别判空方式） | `UNKNOWN` → 默认按 `SKIP_ON_BLANK` 兜底：值空不拼接；tooltip 显示 `flagSource` |

## 6. 风险与应对

| 编号 | 风险 | 影响 | 应对 |
|------|------|------|------|
| M12-R1 | 现有测试依赖「`eq(false)` 丢弃」语义 | 行为升级破坏旧断言 | `false` 条件**进入模型但默认排除**，生成层默认输出与 M11 逐字节一致（T-M12-02/03 回归兜底）；旧断言不改动 |
| M12-R2 | 动态条件开/关后 `?` 位置变化，现有**位置绑定**参数会串值 | 填错参数 | 参数改**按 source（Map<String,String>）**绑定，值随条件位置变化不串；同一 source 共享一个输入框（对齐 MP 语义） |
| M12-R3 | 嵌套 Group 内动态条件 id 不稳定 | 勾选错位 | id 用条件树 pre-order 路径（`n<父id>-c<序号>`），同一 `previewModel` 内稳定；生成层递归按 id 过滤 |
| M12-R4 | 批量操作路径无 statement 模型 | 左栏报错/回归 | `PreviewResult.previewModel` 默认 null，面板走旧文本路径；T-M12-04 测试覆盖 |
| M12-R5 | 勾选/输入频繁触发重生成导致 EDT 卡顿 | 交互卡顿 | 重生成仅调用纯 `SqlGenerator`（无 PSI、无 IO、毫秒级），复用已缓存的 statement（`WrapperCache` 命中）；不新增后台线程/轮询 |
| M12-R6 | `previewModel` 与「格式化/单行切换」「刷新」等既有交互耦合 | 功能回归 | 重生成统一收敛到 `renderSql()` 单点（含 `compactMode` 与 formatSql 传递），复用现有渲染入口 |
