# SQL 关键字标识符引用——开发计划（T-M23.4）

> 本文档是 **MyBatis-Plus SQL Visualizer** 的 T-M23.4 增量计划：2026-08-14 用户反馈——
> SQL 中可能出现**数据库关键字**（如字段 `table`），需要特殊处理（字段用反引号包裹）。
> 用户示例（批量 INSERT，字段名 `table` 为 MySQL 保留字，直接执行报错）：
>
> ```sql
> INSERT INTO biz_banner (title, name, table, image_url, dic_jump_type, jump_url, sort, dic_status, create_time, update_time)
> VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
> -- 期望：table → `table`（MySQL 反引号；方言不同符号不同）
> ```
>
> 当前基线：M23.3 已交付（472 测试全绿，提交 2a01ae1/dff06f3）。
>
> 任务编号源：本文档（T-M23.4，延续 M23 系列增量）；交付后按仓库约定同步矩阵/清单/变更记录。

## 1. 问题与动机（用户反馈，证据驱动）

**用户反馈**：字段名可能是数据库关键字（如 `table`），生成的 SQL 需要把关键字标识符包裹
（MySQL 反引号 `` ` ``）。示例 `INSERT INTO biz_banner (..., table, ...)` 中的 `table` 是
MySQL 保留字，不包裹执行报错。

**现状盘点**（M23.3 交付后）：
- `Dialect.quoteIdentifier` **已定义但从未被调用**（`Dialect.kt:31`，MySQL 反引号 / PG·Oracle·H2·SQLite·DM·KingBase 双引号 / SQLServer 方括号）——基础设施已有，只差「判定 + 接入」；
- 渲染点全部是**纯字符串拼接**：`ColumnRef.qualifiedName/rendered`（`ColumnRef.kt`）、`BatchModel.renderSql`（列清单/表名/ON CONFLICT）、`SqlGenerator`（SELECT 列/WHERE/GROUP BY/ORDER BY/SET/JOIN/表名）——均输出原始标识符；
- 模型层列名是**匹配数据源**（参数对照 `quoteHint`、补全、勾选 activeColumns 匹配）——**引用只能发生在渲染层**，模型数据不得包裹，否则破坏匹配。

**方案约束**：引用是**幂等安全**的（`` `table` `` 在 MySQL 合法、`"table"` 在 PG 合法）——
**宁可多包、不可漏包**：关键字判定用多方言并集，被引用的词在某方言下都是保留字，
包裹后在任何方言下合法（跨方言只是多余引用，不改变语义）。

## 2. 设计方案（T-M23.4）

### 2.1 关键字集合（新 `sql/SqlKeywords.kt`）

**按方言判定**（用户确认：不止 `table` 且**数据库方言有多种**——判定与符号都随方言走；
MySQL 只判 MySQL 保留字：`number` 是 Oracle 保留字但 MySQL 合法，MySQL 场景不包裹）：

- 五个独立保留字集合（小写，来源为各数据库官方关键字文档）：
  - `MYSQL_RESERVED`：MySQL 8.0 官方保留字全量（`dev.mysql.com/doc/refman/8.0/en/keywords.html`）——
    含 `table`/`order`/`group`/`user`/`key`/`index`/`desc`/`asc`/`rank`/`rows`/`range`/`select`/
    `from`/`where`/`having`/`union`/`join`/`primary`/`foreign`/`check`/`default`/`references` 等全部保留字；
  - `SQLITE_RESERVED` / `PG_RESERVED` / `ORACLE_RESERVED` / `SQLSERVER_RESERVED`：各自官方全量；
- 近似归组（文档化）：MariaDB → MySQL；H2 → PostgreSQL（关键字表高度重叠）；DM（达梦）→ Oracle；KingBase → PostgreSQL；
- 判定：`identifier.lowercase() in 本方言集合`——**大小写不敏感**（包裹保留原大小写）；
- 纯函数（无 IDE 依赖），可独立单测；
- **范围边界**：各方言**非保留字**（如 MySQL 的 `name`/`status`/`type`、PG 的 `value`——
  不包裹不报错）**不包含**——包裹反而产生输出噪音（`name` 全量加反引号可读性差）；
  「宁可多包、不漏包」的范围 = **本方言保留字**（被引用的词在本方言是保留字，包裹后合法）。

### 2.2 方言（`sql/Dialect.kt`）

接口新增 `reservedWords` 属性（本方言保留字集合）+ 默认方法（既有方言仅补集合，零行为破坏）：

```kotlin
/** 本方言保留字集合（T-M23.4，小写；判定用）。 */
val reservedWords: Set<String>

/** 标识符按需引用：命中本方言保留字 → [quoteIdentifier]，否则原样返回。 */
fun quoteIfKeyword(identifier: String): String =
    if (identifier.lowercase() in reservedWords) quoteIdentifier(identifier) else identifier
```

### 2.3 SqlGenerator（渲染层统一入口）

新增三个私有渲染函数，替换全部**结构化渲染点**（raw 形态除外）：

- `renderColumnRef(col: ColumnRef, dialect)`：完整列表达式（rawExpr 原样 / `function(qualified)` / qualified），列名本体过 `quoteIfKeyword`，别名前缀（`t.`）不包；
- `renderQualified(col: ColumnRef, dialect)`：`alias.col` 形态（别名不包、列名按需包）；
- `renderTableName(name, dialect)`：表名按需包（FROM / UPDATE / DELETE FROM / JOIN / INSERT INTO）。

替换点（`SqlGenerator.kt`）：
| 位置 | 现状 | 改后 |
|------|------|------|
| 133/141 | SELECT 全列展开（`prefix + it` 拼进 columnName） | 改为 `ColumnRef(tableAlias = ..., columnName = it)` 构造 + `renderColumnRef`（顺带修复 quoteHint 前缀匹配隐患） |
| 168/183 | GROUP BY / ORDER BY `qualifiedName` | `renderQualified` |
| 372/375/390/395/400/409 | WHERE/HAVING/IN/BETWEEN/LIKE/列对列 `qualifiedName` | `renderQualified` |
| 231 | UPDATE SET 列（`set.column != null` 分支） | `renderQualified`（rawSql 分支不动） |
| 148/220/262/265/313 | FROM/UPDATE/DELETE/JOIN 表名 | `renderTableName` |

`renderCondition` 系列加 `dialect: Dialect = MySqlDialect` 参数（调用点 4 处：renderConditionText/174/338/递归）。

### 2.4 BatchModel（批量路径——用户示例所在）

- `BatchModel` 增加 `dialect: Dialect = MySqlDialect` 字段（`Dialect` 为纯对象，BatchModel 保持纯函数、可独立单测）；
- `renderSql` 内部引用：INSERT/UPSERT 列清单、UPDATE SET 列与 WHERE 固定列、`ON CONFLICT (..)` 冲突键、`EXCLUDED.列`（只包列名本体）、`INSERT INTO/UPDATE` 表名；
- `BatchOperationConverter.modelBuild`（唯一构造点，`BatchOperationConverter.kt:143`）读 `PluginSettings` 方言传入（psi 层读设置有先例——`EntityResolver.inferTableName`；测试环境兜底 MySQL）；
- **面板零改动**（`SqlPreviewPanel.kt:211` `batch.renderSql(active)` 用模型自带方言）。

### 2.5 边界（文档化，不实现）

- **raw 形态不处理**：`Condition.Raw`（apply/子查询）、`SetClause.rawSql`、`ColumnRef.rawExpr`（selectFunc）、字符串 wrapper 列——解析期已拼好含列名的文本，渲染层无法拆解（文档化：用户手动引用或后续正则增强）；
- **别名不引用**（`AS xxx` / 表别名 `t.`——开发者自定义，非实体解析产物）；
- **非标准标识符**（数字开头/含特殊字符）不在本次范围（关键字引用为主，顺带修复 133 行 prefix 隐患）；
- **模型层列名不包裹**：参数对照（`quoteHint` 按 `columnName` 匹配）、补全、批量勾选（activeColumns 按列名匹配）全部不受影响。
