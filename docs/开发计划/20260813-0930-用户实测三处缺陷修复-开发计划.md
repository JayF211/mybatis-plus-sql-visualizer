# 用户实测三处缺陷修复——分析与修复记录（M16.3）

> 本文档记录 **MyBatis-Plus SQL Visualizer** 的 M16.3 增量修复：用户实测报告的三个问题——
> ① 设置中切换语言**仍不持久化**（M16.1 修复后复测）；② 字段可补全但**看不到注释**；
> ③ 生成 SQL 出现**空列名**（`SELECT id, , , deleted, ...`）。
>
> 当前基线：v1.10（M16.2 已提交，250 测试全绿）。

---

## 1. 问题与根因（2026-08-13，证据驱动）

### 1.1 语言切换保存失效（M16.1 修复未生效，根因修正）

**用户症状**：设置切 English → 确定 → 再次打开设置仍中文。

**M16.1 结论回顾**：定位为 `PluginSettings` 双注册（@Service 注解 + plugin.xml applicationService 并存），
已移除 XML 注册（保留 `@Service(Service.Level.APP)`）——但用户复测**仍未生效**，说明根因定位不完整。

**根因（本次确认）**：`PluginSettings` 现在是**应用级轻服务**（`@Service(Service.Level.APP)`）+ `PersistentStateComponent`，
而 **IntelliJ Platform 官方规范（SDK Services 文档）明确要求：应用级轻服务 + PersistentStateComponent
必须禁用 roaming**：

> "If an application-level service is a PersistentStateComponent, roaming must be disabled
> (roamingType = RoamingType.DISABLED)."

原 `@Storage("mp-sql-visualizer.xml")` 使用**默认 `RoamingType.DEFAULT`**——状态进入设置同步
（Settings Sync）管理通道，与轻服务持久化机制不兼容 → 内存中语言切换即时生效，但**写盘/重载链路失效**，
确定后重开（或重启）读回旧值。

**修复**：`@Storage` 显式声明 `roamingType = RoamingType.DISABLED`。

### 1.2 补全看不到注释（不可变 builder 返回值被丢弃）

**用户症状**：字段可以补全了（M16.2 双载体修复生效），但补全项**没有注释**。

**根因**：`SqlCompletionContributor` 中 `LookupElementBuilder` **不可变**——`withTailText`/`withLookupString`
返回**新实例**。原实现：

```kotlin
val builder = LookupElementBuilder.create(col)
if (comment != null) {
    builder.withTailText("  $comment")   // ← 返回值被丢弃，无任何效果
    builder.withLookupString(comment)    // ← 返回值被丢弃
}
result.addElement(builder)               // ← 添加的是原始 builder，tailText 从未设置
```

注释的**提取与传递链路**（EntityResolver → TableInfo → PreviewResult → SqlCompletionContext）全部正常，
**展示层**因不可变 builder 用法错误导致 tailText 从不生效——字段补全正常（裸 builder）、注释全无，与用户症状吻合。
M16 测试只验证了数据链路（`columnsWithComments`），未验证 LookupElementBuilder 渲染，故未暴露。

**修复**：抽 `withComment(builder, comment)` 链式装饰（表名/列名两处统一），渲染测试验证
`LookupElementPresentation.tailText` 与 `allLookupStrings`。

### 1.3 SELECT 空列名（注解默认值被解析为列名）

**用户症状**：

```sql
SELECT id, , , deleted, station_id, scheme_name, remark, dic_status
FROM biz_bike_station_share_scheme_info
```

实体 `BaseEntity` 字段 `createTime`/`updateTime` 标注 `@TableField(fill = FieldFill.INSERT/INSERT_UPDATE)`
（**未指定 value**），列名解析为空串。

**根因**：真实项目注解类**可解析**（classpath 上有 MyBatis-Plus）时，
`PsiAnnotation.findAttributeValue("value")` 对未显式声明的属性返回**注解默认值**——
`@TableField` 的 `value() default ""` → `attributeString` 返回 `""`（非 null）→
`annotationValue(...) ?: NamingStrategy.toSnakeCase(...)` 的 `?:` 不回退 → `columnName = ""`。
测试环境注解类不可解析（`findAttributeValue` 返回 null），故 250 个既有测试全部未暴露。

**修复**：`attributeString` 空白视为未指定（`takeIf { it.isNotBlank() }` 返回 null）——
列名与逻辑删除列计算（同用 `annotationValue`）一并修复。

## 2. 修复方案

| 编号 | 修改点 | 说明 |
|------|--------|------|
| T-M16.3-01 | `PluginSettings.kt` `@Storage` | `Storage("mp-sql-visualizer.xml", roamingType = RoamingType.DISABLED)`——官方规范要求 |
| T-M16.3-02 | `SqlCompletionContributor.kt` | 抽 `withComment` 链式装饰（不可变 builder），表名/列名注释展示与关键词检索生效 |
| T-M16.3-03 | `EntityResolver.kt` `attributeString` | 空白字符串视为未指定（回退命名策略），修复空列名 |
