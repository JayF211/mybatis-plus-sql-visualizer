# 更新机制改为「内测版抢先体验」通道

**日期**：2026-08-22
**优先级**：P1（插件已上架 Marketplace，内部更新机制需与官方渠道解耦）
**影响范围**：`update/` 包（核心）+ `config/PluginSettings.kt`（配置默认值）+ `config/UpdateSection.kt`（UI 文案）+ `messages/` 双 bundle（文案）+ `build.gradle.kts`（清单生成任务）+ 测试体系

---

## 一、需求背景

### 1.1 现状

插件已上架 JetBrains Marketplace（v2026.8.20 起），平台内置更新机制已能覆盖**正式版**推送。当前内部更新链路（M28）仍指向 `update/update.json` 作为稳定版清单，存在以下问题：

| # | 问题 | 说明 |
|---|------|------|
| 1 | **双更新源冲突** | Marketplace 自动推送正式版 + 内部机制也推正式版 → 用户可能收到双重提示或安装冲突 |
| 2 | **默认行为不当** | `autoCheckUpdate` 默认 `true`，启动即检查——但正式版应由 Marketplace 管，内部机制应只服务内测 |
| 3 | **文案误导** | 「检查更新」「发现新版本」等文案未区分内测/正式，用户无法辨别来源 |
| 4 | **清单文件错位** | `update/update.json` 当前存的是稳定版（2026.8.20），`preview.update.json` 存的是 2026.8.21（实际更新）——两者并存但逻辑未分离 |

### 1.2 目标

将内部更新机制**完全转为内测通道**：

1. **内部更新 = 内测版通道**：只检查 `preview.update.json`（Gitee 抢先体验），不再触碰正式版
2. **默认关闭自动检查**：`autoCheckUpdate` 默认 `false`，用户主动勾选才开启内测
3. **文案全面调整**：所有 UI/通知文案明确标注「内测版」「抢先体验」，与 Marketplace 正式版区分
4. **发布流程对齐**：发布正式版前先在 Gitee 发布内测版 → 用户抢先体验 → 稳定后上架 Marketplace

### 1.3 版本号约定

#### 1.3.1 基本格式

| 通道 | 版本号格式 | 示例 | 说明 |
|------|-----------|------|------|
| 内测版（Gitee） | `YYYY.M.D-beta.N` | `2026.8.22-beta.1` | prerelease 标识 + 同日序号 |
| 正式版（Marketplace） | `YYYY.M.D` | `2026.8.22` | 纯数字，Marketplace Stable 通道展示 |

#### 1.3.2 同日多版本策略

内测期间一天可能发多个版本，采用 semver 点分序号递增：

```
同一天内测迭代：
  2026.8.22-beta.1  （第一轮内测）
  2026.8.22-beta.2  （修了个 bug，再发一轮）
  2026.8.22-beta.3  （又改了点）

稳定后上架：
  2026.8.22          （正式版，比所有 beta 都大）
```

#### 1.3.3 semver 比较安全性

semver 规范 prerelease 逐标识符比较（数字按数值、字符串按字典序）：

```
2026.8.22-beta.1 < 2026.8.22-beta.2 < … < beta.9 < beta.10 < 2026.8.22
```

✅ 数字标识符**按数值排**（非字典序），`beta.10 > beta.9` 正确。IDE 自身 EAP 版本即用此模式。

#### 1.3.4 升级路径验证

- 用户装 `beta.1` → 内测通道推 `beta.2` ✅ 提示新版内测
- 用户装 `beta.3` → Marketplace 推 `2026.8.22` ✅ 提示升级正式版
- 用户装 `2026.8.22` → 内测通道推 `2026.8.23-beta.1` ✅ 提示抢先体验
- **发布 Marketplace 时必须去掉 `-beta.N` 后缀**（Stable 通道只展示纯数字版本）

### 1.4 发布流程变更

```
变更前：改版本号 → buildPlugin → 上传 Gitee Release → writeUpdateManifest → 提交推送 → Marketplace 审核

变更后：
  内测阶段：版本号加 -beta.N → buildPlugin → 上传 Gitee Release → writePreviewManifest（生成 preview.update.json）→ 推送
  稳定阶段：去掉 -beta.N → Marketplace 提交正式版审核（内部更新通道不参与）

双 JSON 文件工作流：
  update/preview.update.json ← 草稿/备用（开发者随时编辑，不参与自动检查）
  update/update.json        ← 内测通道（writeUpdateManifest 输出目标，内部 updater 检查）
  发布内测时：复制 preview.update.json 内容 → 改版本号为 -beta.N → 写入 update/update.json → 推送
  同日多版：N 递增（-beta.1 → -beta.2 → -beta.3），无需改日期
```

### 2.4 新增功能：忽略此版本（仅抑制自动通知）

#### 2.4.1 功能描述

用户在通知点「忽略此版本」后，**仅抑制该版本的自动启动通知**（跨重启持久化）。
手动在设置页检查更新时**不受影响**，仍正常提示。

| 场景 | 行为 |
|------|------|
| 用户点通知的「忽略此版本」 | 该版本加入忽略列表，通知关闭，后续启动不再自动提示 |
| 用户在设置页手动检查更新 | **忽略此设置**，始终正常提示可用更新 |
| Gitee 发布了比忽略版本更新的版本 | 正常提示（忽略只针对特定版本号，不阻塞后续版本） |

> 设计原则：忽略 =「别再弹窗烦我」，不等于「我永远不想要这个版本」。
> 手动检查是用户主动意愿表达，不应被忽略列表阻挡。
> 设置页不展示忽略列表、不提供取消忽略操作（简洁优先；真要取消忽略，删配置文件或等下一版本发布即可）。

#### 2.4.2 数据存储

```kotlin
// PluginSettings.State 新增字段
/**
 * Gitee 更新通道已忽略的版本号集合（`；` 分隔）；仅抑制这些版本的自动启动通知。
 * 手动在设置页检查更新时不受影响。为空字符串表示无忽略。
 */
var ignoredUpdateVersions: String = ""
```

> 用 `；` 分隔（与 `ignoredFields`、`logFilterKeywords` 等已有字段约定一致）。
> 持久化到 `mp-sql-visualizer.xml`，IDE 重启后恢复。

#### 2.4.3 忽略判断与操作（纯函数）

新建 `update/VersionIgnore.kt`：

```kotlin
/** 版本是否在忽略列表中（纯函数）。 */
internal fun isVersionIgnored(version: String, ignoredVersions: String): Boolean =
    ignoredVersions.split("；").map { it.trim() }.filter { it.isNotEmpty() }.contains(version)

/** 加入忽略列表（纯函数，返回新字符串）。 */
internal fun ignoreVersion(version: String, ignoredVersions: String): String {
    if (version.isBlank()) return ignoredVersions
    val current = ignoredVersions.split("；").map { it.trim() }.filter { it.isNotEmpty() }.toMutableList()
    if (!current.contains(version)) current.add(version)
    return current.joinToString("；")
}
```

#### 2.4.4 接入点（仅启动自动检查）

**唯一接入点**：`StartupUpdateCheck.checkAndNotify()` 中增加守卫：

```kotlin
override fun run(indicator: ProgressIndicator) {

    ApplicationManager.getApplication().invokeLater {
```

## 六、风险评估

| 风险 | 影响 | 缓解 |
|------|------|------|
| 已安装用户的 `autoCheckUpdate=true` 持久化状态 | 老用户升级后仍保持自动检查（因为 XmlSerializer 读旧值） | 可接受——老用户已主动开启，保持行为一致；新用户默认关闭 |
| 已忽略版本列表膨胀 | 长期使用后 `ignoredUpdateVersions` 字符串变长 | 正常现象（XmlSerializer 字符串无上限）；可在「取消全部忽略」时清空 |
| 已安装用户的 `autoCheckUpdate=true` 持久化状态 | 老用户升级后仍保持自动检查（因为 XmlSerializer 读旧值） | 可接受——老用户已主动开启，保持行为一致；新用户默认关闭 |
| 内测版与正式版版本号重叠 | 内测版版本号可能与后续正式版相同 | 内测版用 `YYYY.M.D-beta.N`（semver prerelease 永远小于正式版）；正式推 Gitee 时用纯数字 |
