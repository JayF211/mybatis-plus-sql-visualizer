# 日志捕捉性能优化 开发计划

> 源自《性能分析/20260902-0054-IDEA性能影响-性能分析.md》第 3 节与第 9 节的 4 条优化建议。
> 分支：`perf/log-capture-optimization`（git worktree 独立目录，并行会话隔离）。
> 范围：仅日志捕捉链路（`SqlLogConsoleBridge` / `SqlLogManager`），不改捕捉语义与对外行为。

## 目标

消除捕捉态的常驻 EDT 开销：快速轮询从 100ms 常驻降为 500ms 起步指数退避（上限 2s），热路径反射查找缓存化，已挂载控制台跳过组件树遍历，逐行配置同步改为设置变更事件驱动。捕捉功能行为（捕获时序、设置生效性）不变。

## 任务

### T-LogPerf-01 快速轮询 500ms 起步 + 指数退避

- `FAST_POLL_INTERVAL_MS` 100 → 500，`scanAll` 定时回调抽为 `onCatchUpTick`：每拍先执行扫描，未检测到主控制台则间隔翻倍（上限 = 常规轮询 2s）。
- `startPolling` / `startFastPolling` 重置退避基线；检测到主控制台切常规轮询逻辑不变（`startNormalPolling`）。
- 同步对齐 KDoc（原文 100ms/500ms 混用）与 `startPolling` 日志文案。

### T-LogPerf-02 反射 Method 缓存

- `companion` 增加按 `(Class, 方法名)` 维度的 `ConcurrentHashMap<Class<*>, ConcurrentHashMap<String, Method?>>` 缓存，helper `methodOf(clazz, name)` 统一查找。
- 替换热路径（每拍执行）：`hasMainConsole` / `scanAll` 描述符循环中的 `getComponent`、`getProcessHandler`、`isProcessTerminated`、`isProcessTerminating`、`getAllDescriptors`。
- 冷路径（attach/detach 的 `addMessageFilter` / `removeContentManagerListener` 等）不动，保持原样。

### T-LogPerf-03 已挂载控制台短路

- 新增 descriptor 身份 → console 的缓存（`IdentityHashMap`，`detachAllFilters` 时清空，超 64 项整体失效防死 descriptor 强引用滞留）。
- `scanAll` 描述符循环：缓存命中的 console 若已在 `attachedConsoles`，直接跳过 `scanComponent`（不遍历 Swing 组件树）；未命中或未挂载照旧扫描并回写缓存。
- 短路判定抽纯函数供单测。

### T-LogPerf-04 逐行配置同步改事件订阅

- `SqlLogManager` init 订阅 `PluginSettings.SETTINGS_CHANGE_TOPIC`（`messageBus.connect(this)`，随服务 dispose 自动注销）→ 回调执行 `applySettings()` + `bridge.refreshConsoleContexts()`。
- `SqlLogConsoleBridge.refreshConsoleContexts()`：遍历 `consoleContexts` 同步三解析器配置 + 刷新 `timePrefix` 缓存字段（bridge lambda 不再每行读 `PluginSettings`）。
- `processConsoleLine` 移除逐行 `configProvider()` 同步块与 `syncBufferConfig()` 调用（函数签名不变，4 参测试调用兼容）；`ParserConfig` 快照在挂载与刷新时写入 `BridgeLineContext`。
- 兜底：`startCapture` 已有 `applySettings()` 调用，捕捉启动时配置必然就绪。

### T-LogPerf-05 单元测试

- 退避计算纯函数（500→1000→2000 封顶）。
- 短路判定纯函数（缓存命中且已挂载 → skip）。
- `refreshConsoleContexts` 同步断言（改前缀后 parser 字段更新、timePrefix 缓存更新）。
- 既有 log 包测试全绿（`SqlLogConsoleBridgeTest` / `SqlLogConsoleBridgeMarkerTest` / `SqlLogManagerBehaviorTest` / `SqlLogCaptureRealtimeScenarioTest` / `DualParserIntegrationTest` / `LogFilterProxyHandlerTest`）。
