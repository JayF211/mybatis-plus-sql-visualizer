## 四、待验证前提（实施者先证伪再动手，证伪即回计划 §八偏离点）

1. **F37 A 案前提**：MultiHostInjector 的 `elementsToInjectIn()` 接受 `XmlFile::class.java`（PsiFile 级类型）——B 路已实证平台按 `context.getClass()` 索引喂入，但「PsiFile 级类型可否注册进 injector map」未直接实证；实施前先写探针（或查 243 sources `MultiHostInjector` 契约注释）证伪后再动手。
2. **F37 与 F38 的时序约束**：修复激活后门控从「不可达」变「每文件每 pass 一次」——F38 缓存必须与 F37 **同提交或先行**，否则激活瞬间每文件付 ~百次反射。
3. **平台版本面**：B 路平台契约证据取自 243 发行物（ideaIC-243.28141.41 sources + app-client.jar 2024.3.7.1）；253/262 的 multiHostInjector 喂入语义以 runIde 真机复验为准（验收含真机两用例的原因）。
4. **F36 修法等价性**：现接线 `runCatching { ...state.showGutterIcon }.getOrDefault(true)` 的失败回退语义，收敛后由调用方既有 `gutterEnabled()` 的 runCatching 承接——真值表用例钉住（含服务异常分支）。
5. **F40 缓存键**：`modificationStamp` 在补全 lookup 会话内的稳定性（PSI commit 后失效）——实施时验证，失效键退化为每次重扫即本条前提被证伪，须换指纹（如 length+stamp 组合）。
6. **F44 守卫判据**：源码扫描「写点邻近配对」对测试夹具/非生产调用点的误伤面——扫描范围限 `SqlLogManager.kt` 生产段，测试侧置位路径（4d51056 已有显式置位先例）入豁免清单。
