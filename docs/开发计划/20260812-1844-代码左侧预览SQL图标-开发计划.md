# 代码左侧预览 SQL 图标（Gutter Icon）——可行性分析 + 开发计划（M10）

> 本文档分析新方案「**检测到可转换 SQL 的 Wrapper 调用链后，在 IDEA 代码编辑器左侧 gutter 区域显示预览 SQL 图标**」的可行性，并在可行前提下给出开发计划（编号 **M10**，版本 **v1.4**）。
> 配套文档：[主开发计划](../开发计划/20260812-1058-MP-SQL可视化-开发计划.md)（M0~M9 已交付，本文档为其增量 M10）、[项目介绍](../项目介绍.md)。
> 当前基线：Kotlin 2.3.20 + IntelliJ Platform Gradle Plugin 2.18.1 + IDEA 2025.3.5，基础包 `cn.song.mybatisplus.visualizer`，v1.3（M9）已交付。

---

## 1. 方案概述

**用户想法**：插件在**不触发任何操作**的情况下，自动检测文件中「可以转换为 SQL 的代码」（即 MyBatis-Plus / MPJ 的 Wrapper 调用链），并在该代码所在行的**编辑器左侧 gutter**（行号区）显示一个预览图标。点击图标即弹出 SQL 预览（复用现有弹窗/工具窗口链路）。

**预期效果**：

```
  行号区(gutter)       代码编辑区
  ┌────────────┐   ┌───────────────────────────────────┐
  │      SQL  ▸│   │ LambdaQueryWrapper<Device> w =     │  ← wrapper 声明行出现图标
  │            │   │     new LambdaQueryWrapper<>()     │
  │            │   │     .eq(Device::getSn, sn)         │
  └────────────┘   └───────────────────────────────────┘
                     （点击图标 → 弹窗/工具窗口展示转换后的 SQL）
```

**语义澄清**：插件转换的对象是 **Wrapper 调用链**（SQL 是转换产物），因此 gutter 图标标记的是「**可转换为 SQL 的 Wrapper 调用链**」的锚点位置，包括链式 `new ...` 表达式与分步变量声明两种写法（与 `WrapperLocator` 支持的三种写法对齐）。

**与现有 5 种触发方式的关系**：本方案是**第 6 种触发入口**（右键 / 快捷键 / 悬停 / 工具窗口 / 编辑器跟随之外），属于**被动发现式入口**——用户无需把光标放到代码上即可"看见"哪里有 SQL 可转。转换链路完全复用，不新增转换逻辑。

**性能定位（硬性约束）**：gutter 图标是**常驻型 UI**——daemon 高亮时对文件内每个元素逐个回调，且与用户输入实时竞争资源，是插件被 IDEA 性能警告（"Plugin … is causing slow"）的高发区。因此本方案**以性能为第一验收标准**（见 §2.4 性能预算、T-M10-05 压测验收）：任何环节不得引入可感知延迟，任何实现若触发性能警告即为**未通过**。

## 2. 可行性分析

### 2.1 技术路线（IDEA 官方机制核验）

IntelliJ Platform 提供 **Line Marker** 机制在 gutter 显示图标，官方文档与本仓库源码核验结论如下：

| 项目 | 结论 | 依据 |
|------|------|------|
| 扩展点 | `com.intellij.codeInsight.lineMarkerProvider`，**支持 `language` 属性**（注册为 `language="JAVA"` 只作用于 Java 文件） | [官方文档 Line Marker Provider](https://plugins.jetbrains.com/docs/intellij/line-marker-provider.html) 注册示例 |
| 推荐基类 | `RelatedItemLineMarkerProvider`，覆写 `collectNavigationMarkers(PsiElement, Collection<RelatedItemLineMarkerInfo<?>>)` | 官方文档 SimpleLineMarkerProvider 示例 |
| 图标构建 | `NavigationGutterIconBuilder.create(icon).setTooltipText(...).createLineMarkerInfo(element)`，一行生成 `LineMarkerInfo` | 官方文档示例代码 |
| 点击行为 | `LineMarkerInfo` 携带 `GutterIconNavigationHandler`，点击时在 **EDT** 回调 `navigate(MouseEvent, T)` | 平台源码 `GutterIconNavigationHandler.java` |
| 显示开关 | 继承 `GutterIconDescriptor` 可让图标出现在 IDE 原生 **Settings \| Editor \| General \| Gutter Icons** 开关列表（可选增强） | 官方文档"Extending from GutterIconDescriptor"段落 |
| 性能路径 | 图标分两阶段生成：① 编辑器可见区元素（快速）② 文件其余元素（慢速 `collectSlowLineMarkers`，后台高亮线程 + read action，可做 PSI resolve） | 官方文档 Best Practices + 平台源码 `LineMarkersPass` |

**结论：技术路线完全成立，且是官方一等公民机制**，不涉及任何 deprecated API 或社区版兼容性风险（不依赖 `com.intellij.sql` / Database 插件，维持 Community 兼容，符合 M8 既定约束）。

### 2.2 与现有架构的对接点（复用清单）

本方案**零新增转换逻辑**，全部复用现有组件：

| 现有组件 | 复用方式 |
|----------|----------|
| `WrapperLocator.detectWrapperType(PsiType)`（现为 private） | 抽取为 internal 供 `WrapperAnchorDetector` 使用：仅用**类型 canonicalText 文本匹配**判断是否 Wrapper（纯语法级，不 resolve、不遍历） |
| `SqlPreviewService.preview(anchor)` + `previewAsync(...)` | 点击图标的转换入口：后台线程 + ReadAction + `WrapperCache` 文件级缓存（F-20），与悬停/快捷键完全同链路 |
| `SqlPreviewDialog(project, result)` / `SqlToolWindow.showResult(project, result)` | 按 `displayMode`（F-16：DIALOG / TOOL_WINDOW / BOTH）展示结果 |
| `ConvertToSqlAction` 中的展示分支逻辑 | 抽取公共方法（如 `SqlPreviewService.showResult(project, result)`）供 Action 与 gutter 点击共用，消除重复 |
| `PluginSettings` + `PluginSettingsPanel`（F-16） | 新增 `showGutterIcon` 配置项（默认开）+ Settings 开关 UI + bundle 文案（中/英） |
| `WrapperCache`（F-20） | 点击转换直接命中缓存；同文件多图标点击零重复解析 |

### 2.3 关键设计决策

**① 锚点判定（新增 `WrapperAnchorDetector`，单元素 O(1)，禁止全文件扫描）**
Line marker 快速路径是**逐元素回调**（IDEA 遍历文件元素并逐个调用 provider），因此**不需要、也不允许**在快速路径做 `scanFile(file)` 式全文件扫描——O(n) 且随每次高亮重复执行，属性能红线。改为单元素判定器：
- `WrapperAnchorDetector.isWrapperAnchor(element): Boolean`：对**单个叶子元素** O(1) 判定，只允许：
  - **场景 A（链式/内联）**：元素是 `PsiKeyword("new")` 且其父 `PsiNewExpression` 的类型 canonicalText 以 Wrapper 类名结尾 → 锚点；
  - **场景 B（分步变量）**：元素是变量名 `PsiIdentifier` 且其父 `PsiLocalVariable`/`PsiField` 的类型为 Wrapper → 锚点；
  - 判定过程只访问 `parent` / `type.canonicalText`，**零 resolve、零 `PsiTreeUtil` 遍历、零文件级操作**；
- **去重规则**：场景 B 中变量初始化即 Wrapper 构造（`... w = new ...;` 同行）时，**只标变量声明**（它是调用链的根），跳过 `new` 关键字——该规则同样在单元素判定内完成（判定变量声明元素时校验其初始化表达式类型，O(1)）。

**② 叶子元素原则（防闪烁，官方 Best Practices 硬性要求）**
LineMarker 分两阶段生成（可见区 / 全文件），若 marker 挂在非叶子元素（如整个 `PsiNewExpression`）上，可见区通过而全文件阶段可能被清除，导致**图标闪烁**。因此锚点一律取叶子节点（`PsiKeyword` / `PsiIdentifier`），并按官方模式在 `collectNavigationMarkers` 中判断父链上下文。

**③ 快速路径只做语法判断**
`collectNavigationMarkers` 中仅依据**父节点类型文本**（`PsiNewExpression.type.canonicalText` 末尾匹配 `LambdaQueryWrapper` 等类名；变量声明的 `PsiType` 同理）决定是否返回 marker。**不做 PSI resolve**（快速路径禁止慢操作），O(1) 每次判断。

**④ 点击即转换，tooltip 静态**
- tooltip 固定文案（如"转换为 SQL 预览"），**不预生成 SQL 内容**——避免为文件内所有 Wrapper 做全量转换拖慢高亮 pass；
- 点击后走 `GutterIconNavigationHandler.navigate`（EDT 回调）→ `SqlPreviewService.previewAsync`（后台 + 缓存）→ 按 `displayMode` 展示，与快捷键体验一致（含"未找到 Wrapper 的友好提示"）。

**⑤ 工厂方法（清单 P03/P16）降级策略**
`baseWrapper()` 这类无 qualifier 的工厂调用**无法在快速路径语法级识别**（方法名不在已知集合，返回类型需 resolve）。降级：
- 第一版：这类锚点**不显示图标**（用户仍可用悬停/快捷键/编辑器跟随）；
- 可选增强（排入 M10 之后或慢速路径）：在 `collectSlowLineMarkers` 中仅对**候选方法调用**（无 qualifier 的方法调用表达式）`resolveMethod` 判断返回类型，标到调用处。

**⑥ 范围控制（第一版）**
- 语言：仅 Java（EP `language="JAVA"`，与 M1 聚焦一致；Kotlin 后续里程碑）；
- 锚点：仅 Wrapper 调用链；批量操作调用（`updateBatchById` 等，`BatchOperationConverter` 支持）列为后续增强（快速路径可按方法引用名静态匹配，成本低，但不挤占第一版）。

### 2.4 性能预算（红线，硬性约束）

**目标**：在任何文件规模 / 任何编辑操作下，插件不得引入可感知延迟，不得触发 IDEA 性能警告（PerformanceWatcher 的 "Plugin … is causing slow" / daemon 高亮超时提示）。

| 执行路径 | 允许的操作（仅此） | 红线（禁止） |
|----------|--------------------|--------------|
| 快速路径 `collectNavigationMarkers`（逐元素，daemon 高亮 pass） | 单元素 `instanceof` + `parent` 访问 + `type.canonicalText` 字符串比较；构建静态 `LineMarkerInfo` 对象 | ❌ PSI resolve / 索引查询；❌ `PsiTreeUtil` 遍历 / 全文件扫描；❌ 任何转换、解析、IO、锁、热路径日志；❌ 动态 tooltip 计算 |
| 慢速路径 `collectSlowLineMarkers` | **第一版不覆写**（默认委托，无额外成本） | ❌ 预计算 SQL / tooltip 内容（即使后台，也为文件其余元素重复执行，得不偿失） |
| 点击（`navigate`，EDT） | 仅捕获锚点元素并转 `SqlPreviewService.previewAsync`（后台 + ReadAction + `WrapperCache`） | ❌ EDT 上任何 PSI 慢操作（复用 M3 已验证模式） |
| tooltip 查询（EDT） | 返回静态字符串（如"转换为 SQL 预览"） | ❌ 生成 / 拼接 SQL 内容 |
| 后台空闲 | 无任何定时任务 | ❌ Alarm 轮询、常驻后台线程、全量预转换 |

配套手段：
- **缓存**：转换结果复用 `WrapperCache`（F-20，文件级 + modificationStamp 失效）——同文件多次点击/悬停零重复解析；
- **降载开关**：`showGutterIcon` 配置可一键关闭（性能兜底，见 T-M10-04）；
- **规模无关**：快速路径 O(1)/元素，天然与文件规模线性无关；不引入"仅可见区"等额外逻辑（平台两阶段 pass 已覆盖）。

### 2.5 风险与应对

| 编号 | 风险 | 影响 | 应对 |
|------|------|------|------|
| G1 | marker 挂在非叶子元素导致**图标闪烁**（两阶段 pass 机制） | 体验差 | 严格遵循官方 Best Practices：只返回叶子节点（`PsiKeyword`/`PsiIdentifier`）；PSI 测试覆盖"跨可见区边界"形态 |
| G2 | 同一行多个锚点（变量声明 + new 表达式）出现双图标 | 视觉重复 | 去重规则（见 2.3①）：变量初始化即构造时只标变量声明；单测断言 |
| G3 | 大文件/多 Wrapper 下图标生成拖慢高亮，触发 IDEA 性能警告（"Plugin is causing slow"） | 编辑器卡顿 + 用户信任受损 | 快速路径严格按 2.4 预算（单元素 O(1)、零 resolve）；不预转换、不覆写慢速路径；`showGutterIcon` 一键关闭兜底；验收含 2000+ 行 / 多 Wrapper 压测样例（T-M10-05） |
| G4 | 工厂方法（P03/P16）语法级无法识别 | 部分场景无图标 | 明确降级（第一版不标，悬停/快捷键仍可用）；慢速路径增强排后 |
| G5 | 点击处理在 EDT 上做 PSI 转换触发 "Slow operations on EDT" | 报错/卡顿 | handler 内只捕获锚点元素，转换一律走 `SqlPreviewService.previewAsync`（后台 + ReadAction，M3 已验证模式） |
| G6 | 与 IDEA 自带 gutter 图标（run/实现/覆盖）视觉冲突 | 可读性 | 自定义 SVG 图标 + `GutterIconDescriptor` 开关（可选增强）；图标样式在 runIde 验收中人工确认 |
| G7 | 实现走偏：把全文件扫描 / resolve 等慢操作放进快速路径 | 高亮 pass 超时 → 性能警告 | 代码评审强制对照 2.4 预算表逐项核对；单测断言判定器对非 Wrapper 元素零成本（不触碰 `PsiFile`、不 resolve） |

### 2.6 可行性结论

**✅ 可行，且成本低**：
- 官方一等公民机制（Line Marker + 官方文档最佳实践），无 Community 兼容风险；
- 转换链路 100% 复用，新增代码集中在「单元素锚点判定 + gutter provider + 点击接线 + 配置开关」四块，预计 **1.5~2.5 天**（单人）；
- **性能可保证**：快速路径严格限定为单元素 O(1) 纯语法判定（§2.4 预算表），转换全部后台 + 缓存，不覆写慢速路径、不预计算——按此实现不会出现"插件拖慢 IDEA"类提示；
- 唯一"能力边界"是工厂方法/批量操作锚点第一版不覆盖，但均有明确降级路径与后续增强点。

## 4. 测试策略

| 层级 | 覆盖 |
|------|------|
| 单元/PSI 测试（新增 ≥6） | `WrapperAnchorDetectorTest`（锚点识别/去重/负例/**负例零成本断言**）、`SqlGutterLineMarkerProviderTest`（BasePlatformTestCase：marker 行号与类型、开关联动）、配置读写 |
| 手动验收（runIde） | 链式/分步两种写法的图标显示与点击预览、亮/暗主题图标可见性、Settings 开关、**性能压测**：2000+ 行 / 多 Wrapper 文件滚动与连续编辑无卡顿、无性能警告气泡 |

**性能回归断言（写入测试）**：判定器对**非 Wrapper 元素**不得触发 resolve / 文件访问（结构性断言：仅访问 `parent` / `type`）；provider 快速路径输出与文件规模无关（相同元素集合下 marker 数量恒定）。

测试文件规范沿用主计划：`src/test/kotlin/...`，SQL 断言不涉及（本里程碑无 SQL 生成变更）。
