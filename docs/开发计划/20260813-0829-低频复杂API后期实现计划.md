# 低频复杂 API 后期实现计划（M15 遗留项）

> 本文档是 **MyBatis-Plus SQL Visualizer** 的**后期增量计划**：收录官方 API 全覆盖（M15 增补 1~3）过程中评估为 🟡（部分支持）与 ⬜（暂不支持）的**低频复杂 API**，作为后续里程碑的实现清单。当前基线：M19.4（282 测试全绿，2026-08-13）。**M19.5 起与《[用户实测两类未识别形态修复](./20260813-1536-用户实测两类未识别形态修复-开发计划.md)》一起开工。**
>
> 背景：插件已覆盖 MP 3.5.15 / MPJ 1.5.6 官方文档的**高频与中频 API**（条件构造器全集、链式调用、消费方法、MPJ 联表/聚合/子查询/union/逻辑删除控制等，见《MPJ 用法收集与兼容性测试清单》§5.6）。剩余项真实项目均 0 使用、实现成本高或依赖外部条件（如 MP 版本升级），按「优先级 × 成本」排期。
>
> 配套文档：[测试清单 §5.6 官方 API 覆盖矩阵](../需求文档/MPJ用法收集与兼容性测试清单.md)、[M15 开发计划](../开发计划/20260813-0216-真实语料兼容补全-开发计划.md)、[M16 开发计划（SQL 面板字段补全）](../开发计划/20260813-0812-SQL面板字段补全与注释提示-开发计划.md)。

## 1. P1——低成本补全（每项 0.5~1 天，可随时插入任意里程碑）

| # | API | 现状 | 实现思路（定位） | 难点/说明 |
|---|-----|:----:|------------------|-----------|
| P1-01 | `enableLogicDel` / `logicDelToWhere` 等逻辑删除控制剩余形态 | 🟡 | `SqlPreviewService.LOGIC_DELETE_DISABLE_METHODS` 扩展；logicDelToWhere 需把 deleted 条件**移到 WHERE 末尾**（当前仅跳过注入） | logicDelToOn 需在 MPJ ON 条件追加 deleted——依赖 parseJoin 扩展 |
| P1-02 | `selectByIds` / `deleteByIds`（3.5.9+ 新名） | 🟡 | `BatchOperationConverter.BATCH_OPERATIONS` 加 deleteByIds→DELETE；selectByIds→SELECT 模板（IN 列表） | 与 removeByIds 同族，低风险 |
| P1-03 | `service.query()` / `service.update()` 字符串链 | 🟡 | `WrapperLocator.serviceChainMethodNames` 加 query/update（需限定 qualifier 非消费场景——`service.update(wrapper)` 是消费！需按实参形态区分） | **风险点**：update 同时是消费方法名，链起点判定需看后续是否有终结点 |
| P1-04 | 链上 `update(T entity)` 终结点 | 🟡 | `chainTerminalMethodNames` 已有 update；`update(entity)` 形态 → 实体字段展开 SET（复用 `SqlPreviewService.updateEntityConsumed` 分支思路） | 与 P1-03 联动 |
| P1-05 | `ChainWrappers` 静态工厂（`queryChain(BaseMapper)` / `lambdaQueryChain(Class)` 等） | 🟡 | `WrapperLocator.isWrapperFactoryCall` 的 qualifier 识别扩展（ChainWrappers 类名） | 工厂名集合扩展，低风险 |
| P1-06 | `having` 多条件 | 🟡 | `QueryWrapperParser.parseHaving` 取嵌套链全部条件（当前仅第一个）→ `Condition.Group(AND, children)` | M1 遗留限制，改动局部 |

## 2. P2——中等成本（每项 1~2 天，建议并入 M17）

| # | API | 现状 | 实现思路（定位） | 难点/说明 |
|---|-----|:----:|------------------|-----------|
| P2-01 | `select(Class, Predicate)` / `selectFilter` 谓词精确求值 | 🟡（全列近似） | psi 层解析 predicate lambda 引用的 `TableFieldInfo` 字段名集合（静态分析 lambda 体 `t -> !t.getProperty().equals(...)` 不可行——改为识别**白名单/黑名单字段引用**），converter 据此过滤列 | predicate 是 `TableFieldInfo -> boolean` 运行时判定，静态只能近似；需设计启发式 |
| P2-02 | `leftJoin` 5 参 rightAlias、子表 MConsumer（1.5.2+）、ext MFunction 形态 | 🟡 | `MpjLambdaConverter.parseJoin` 扩展：5 参（右列带别名）→ ColumnRef 补 rightAlias；子表 MConsumer（`leftJoin(Class, t -> {...}, left, right)`）→ 子查询 JOIN（复用 parseCollection 的子查询渲染）；ext MFunction（4/9 形态的 on 内附加条件） | 子表 join 需渲染 `LEFT JOIN (SELECT ...) alias ON ...`，与 selectCollection 子查询结构可复用 |
| P2-03 | `selectCollection/selectAssociation` prefix / free 映射形态 | 🟡 | `MpjLambdaConverter.parseCollection/renderCollectionSubSelect` 扩展：`selectCollection(String prefix, ...)` 列前缀；free 映射（`selectCollection(SFunction, MFunction<MybatisLabelFree.Builder>)`）→ 列映射表来自 lambda 体 | free 形态的 Builder API 需对照 MPJ 源码 |
| P2-04 | `allEq`（6 重载，Map 参数） | 🟡（占位符近似） | psi 层解析 `Map.of(...)` / `Map<String,Object> map` 实参：字面量 Map → 展开为多条 eq；变量 Map → `WHERE (col1 = ? AND col2 = ? ...)` 占位 | 需支持 null2IsNull 语义（null 值 → IS NULL） |
| P2-05 | `setEntity(entity)`（AbstractWrapper） | 🟡 | 实体参与 where：EntityResolver 解析 entity 字段 → 非 null 字段追加等值条件（与 MP 语义对齐：非 null 字段生成 where） | 与 update(entity, wrapper) 的字段展开共用逻辑 |
| P2-06 | `selectFunc(BaseFuncEnum)` 8 形态 | 🟡 | `ArgResolver`/`QueryWrapperParser.parseSelectFunc` 扩展：第一参为 `DefaultFuncEnum.XXX` 枚举引用 → 映射到内置函数模板（SUM/COUNT/MAX/MIN/AVG/LEN 等） | 需维护枚举 → SQL 函数模板映射表 |
| P2-07 | `from(子查询主表)` | ⬜ | `SelectStatement` 主表改为子查询：`from(w -> w.selectAll().ge(...))` → `FROM (SELECT ...) alias`；parseUnion/parseSelectSub 的子查询渲染可复用 | 主表 TableInfo 与子查询模型冲突，需新增"主表子查询"字段 |
| P2-08 | `selectByIds` SELECT 模板 | 🟡 | `BatchOperationConverter` 加 SELECT 类操作（当前只有 UPDATE/INSERT/DELETE/UPSERT） | 低风险 |

## 3. P3——高成本/低频（每项 2~4 天，按需立项）

| # | API | 现状 | 实现思路（定位） | 难点/说明 |
|---|-----|:----:|------------------|-----------|
| P3-01 | `UpdateJoinWrapper` / `DeleteJoinWrapper` 直接构造 | ⬜ | `detectWrapperType` 加两种类型 + 新 converter（UpdateJoin：entity SET + 联表 WHERE；DeleteJoin：`delete("t1,t2")` 多表删除） | 联表更新/删除的 SQL 形态需对照 MPJ 官方输出 |
| P3-02 | `fill` 关联填充（Fill 接口 6 形态） | ⬜ | `fill(SFunction field, SFunction tagField)` 等 → 关联子查询列填充，SQL 形态复杂（需对照 MPJ 官方输出） | 依赖 selectSub 子查询渲染的成熟度 |
| P3-03 | ResultHandler 流式重载（selectList/selectMaps 等带 ResultHandler 参数） | ⬜ | 消费识别：方法名相同（selectList 等），仅多一个 ResultHandler 参数——渲染同为 SELECT，主要补锚点识别 | 低技术风险，但官方文档低频 |
| P3-04 | `eqOrIsNull` | ⬜ | **依赖 MP 版本升级**（3.5.17 新增）：升级后 `eqOrIsNull(col, val)` → `col = val`（val 为 null 时 `col IS NULL`） | 阻塞项：当前目标版本 3.5.15 无此方法 |
| P3-05 | `KtQueryWrapper` / `KtUpdateWrapper`（Kotlin） | ⬜ | Kotlin PSI 支持（插件当前聚焦 Java PSI，WrapperLocator 注释已声明） | 需 Kotlin PSI 基础设施，独立评估 |
