## 一、立项背景

内网 / 离线部署是政企与金融类客户的常见形态（插件描述里「达梦 / 人大金仓等信创方言」这一卖点本身就指向这类客户）。当前 README 与官网均未声明插件的网络行为，内网用户无从判断「装进来会不会因为连不上外网而卡住 / 报错 / 功能残缺」，往往需要先做一轮试点验证才敢推开。

本轮对全仓库做了一次网络路径审计（结论见 §二），结论是**核心链路零网络依赖、内网完全可用**，但有两处「说不清」之处：

1. **无公开声明**：零外联这一事实只存在于代码里，用户侧零可见度。
2. **换源入口未文档化**：`mpvs.update.manifest.url` 系统属性可以整体替换更新源（含内网私有更新通道），但目前只写在 `UpdateSource.kt` 的代码注释里，没有用户文档，也没在诊断输出中暴露生效值。

顺带一个实测发现：该属性的解析**只在进程启动时读一次**（Kotlin object `manifestUrl()` 首次调用即触发 `UpdateSource` 类初始化并缓存 `DEFAULT_MANIFEST_URL` 字符串）——「改 `-D` 后立即生效」的直觉不成立。内网部署恰好依赖这个属性，必须写清楚。

**在文档里把「内网可用」讲成一句可核查的事实，比让它成为一个待验证的疑问更有价值**，因此本轮交付以文档为主，代码侧只补一处诊断日志。

## 二、审计结论（本轮实测，出证到 文件:行）

全仓库运行期仅有 2 个网络出口、4 处调用点，均属可选功能，且均已包裹超时与降级：

| 出口 | 调用点 | 目标 | 超时 | 失败表现 | 级别 |
|---|---|---|---|---|---|
| 更新通道 | `update/UpdateApi.kt:25`（拉清单）、`:41`（下载包） | Gitee raw（`update/UpdateSource.kt:22`） | connect 15s / read 30s | 启动检查静默（`update/StartupUpdateCheck.kt:50` 非 Available 直接 return）；设置页手动检查显示红字 `settings.update.checkFailed` | 可选 |
| 反馈通道 | `feedback/FeedbackApi.kt:272`（帖子 + 附件） | `sql-visualizer.jvtools.cn`（`feedback/FeedbackApi.kt:35`） | connect 10s / read 10s | 状态行显示失败原因（`describeHttpFailure` 已识别代理拦截页，`feedback/FeedbackApi.kt:100`），非模态 | 可选 |

明确**不存在**的网络面（均已 grep 实证）：

- 无遥测 / 埋点 / 统计上报模块（无 `telemetry`、`analytics`、`beacon`、`track(`）
- 无 AI / LLM 接口调用（插件全部 SQL 处理为本地纯算法）
- 无内嵌 web server（`src/main` 下无 `ServerSocket`、无监听端口、无入站网络面）
- 无许可证 / 激活 / 账号 / token 校验（首次运行无联网前置步骤）
- 不自行加载 JDBC 驱动、不下载驱动（执行 SQL 走 IDE 原生控制台，插件只创建临时 `.sql` 文件：`database/DatabaseConsoleLauncher.kt:41`）
- 不联网拉取 DTD：XML 解析器已装空 `EntityResolver` 并关闭外部实体（`xml/XmlMapperParser.kt:108`、`xml/PagesXmlParser.kt:109`）——**这一条对内网最关键**，否则 DNS 黑洞环境下会卡在 DTD 请求上
- 帮助页为 jar 内本地 HTML（`log/SqlLogPanel.kt:914` 读 `html/marketplace-custom-page.html`），该文件纯内联样式、无 `link/script/img/url()`，零外部请求

启动期默认零请求：`autoCheckUpdate` 默认 `false`（`config/PluginSettings.kt:151`），`plugin.xml:236` 的 `postStartupActivity` 首行即被该开关拦下（`update/StartupUpdateCheck.kt:33`）；另一个启动钩子 `log/LogStartupCapture` 只读配置挂监听，无网络。

依赖面：硬依赖仅 `com.intellij.java` + `com.intellij.modules.xml`（`plugin.xml:64,66`，均为平台 bundled），三个可选依赖（Kotlin / database / diagram）缺失只降级不阻断安装，`<idea-version since-build="243"/>` 不设上限。

**结论**：默认配置下，插件在内网 / 全离线环境可完整使用，无网络请求、无阻塞、无功能残缺；唯二退化点（更新检查、反馈提交）均失败即降级且用户可见原因。

## 三、任务分解

### T-Intranet-01 换源生效值的诊断日志（代码，1 行 + 1 测试）

**现状**：`UpdateSource.manifestUrl()`（`update/UpdateSource.kt:32-33`）在系统属性 `mpvs.update.manifest.url` 非空白时优先返回该值。生产代码里无任何对「当前生效 URL 是默认还是被覆盖」的日志——内网运维排查「明明是内网源，怎么日志里在打 Gitee」时没有落脚点。

**方案**：

1. `manifestUrl()` 内加一次性 `LOG.info`（`UpdateApi` 已有 `Logger` 用法可参照；`UpdateSource` 当前无 Logger，新增实例）——仅在系统属性生效（即 `manifestUrl() != DEFAULT_MANIFEST_URL`）时打印一行 `update manifest url overridden by system property: <url>`。**实施修订**：改为独立 `internal fun logOverrideIfAny(url: String)` 由调用点显式调用——原设想「object 类初始化天然单次」成立，但把副作用内嵌进 `manifestUrl()` 会让类初始化由该行触发时读到尚未赋值的 `LOG` 字段（Kotlin object 字段按声明序初始化、函数体后置），有 NPE 面；独立方法语义更清晰且零初始化顺序耦合。
2. **只打印被覆盖的情况**，不打印默认值——默认路径是绝大多数用户的路径，打日志属噪音。

**测试**：`UpdateSourceTest` 新增 2 例纯函数断言：属性未设 / 空白 → 返回 `DEFAULT_MANIFEST_URL`；属性设为自定义值 → 返回该值。（日志有无不作为断言目标——`Logger` 输出在单测中不可靠，不为测试引入 seam。）

**不做**：不新增设置项、不在设置页显示当前源、不解析 `-D` 之外的配置来源。内网换源是部署期一次性的动作，文档写清即可，做进 UI 属于自我加戏。

### T-Intranet-02 README 内网可用性声明（文档）

在 `README.md`「安装常见问题」之后新增 **## 内网与离线环境** 一节，内容四段：

1. **结论先行**：核心功能全部离线可用；插件不联网也能完整工作（预览 / 反转换 / 日志还原 / JOIN 图 / 格式化 / CRUD 生成）。
2. **网络行为清单**：两个可选出口（更新检查、反馈提交）各自的目标、默认状态与失败表现，明确「无遥测、无埋点、无账号校验、不上传代码」。
3. **执行 SQL 的驱动提示**：功能走 IDE 原生 Database 控制台，插件不下载驱动；**驱动缺失时是 IDE 平台联网去下载**，内网需提前把驱动放进 IDE 的 `jdbc-drivers` 目录或改走内网 Maven 私服（IDE 级设置，非插件配置）。这是内网用户最容易踩的坑，必须写明。
4. **内网私有更新通道**：给出 `-Dmpvs.update.manifest.url=<内网地址>` 用法、清单 JSON 字段（`version` / `downloadUrl` / `changeNotes` / `publishDate` / `sinceBuild`，必填前两项）、`downloadUrl` 指向内网文件服务即可；并**显式标注「该属性在 IDE 启动时读取，修改后需重启 IDE」**（本轮实测结论，见 §一）。

同时把「开发环境」节的构建期网络依赖补一句提示：构建 / 发版需访问 Maven 仓库与 JetBrains 插件门户（`settings.gradle.kts` 仓库配置 + `intellijIdeaUltimate` 发行版下载），纯内网需预置私服与离线缓存——把「运行期可用」与「构建期需网」两件事分开说，避免用户混淆。

## 六、风险与边界

1. **文档口径风险（本轮最大风险）**：把「内网可用」写过头 → 用户在「执行 SQL 缺驱动」或「点检查更新失败」时反噬。缓解=§二 出证逐条落到代码行，README/官网均显式列明两个失败点，不用「完全离线」「零网络」这类绝对措辞。
2. **01 日志**：`LOG.info` 不影响性能与行为；不打印默认值避免噪音。若后续发现 `manifestUrl()` 被高频调用需改缓存——当前调用点仅在更新检查路径，不必提前优化。
3. **不引入** `-Doffline` 之类的全局离线开关：功能本身已可离线工作，加了开关反而暗示「不开就不能离线用」，与事实相反。
4. **平台侧不可控项**：IDE 自身（Marketplace 插件市场、Database 驱动下载、趋势统计）的网络行为不属本插件，文档只提示边界不代为承诺。
