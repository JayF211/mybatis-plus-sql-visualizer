## 1. 问题与动机（用户建议，证据驱动）

**用户建议**：添加和修改的时候做成参数可选的比较合适——① 添加时可能 id 并不需要
（`StoreCouponEntity` 为 `@TableId(type = IdType.AUTO)`，真实 MP 的 INSERT SQL **不含主键列**，
插件当前渲染全列 `INSERT INTO ... (id, ...)`）；② 修改时有些字段可能不需要修改（MP 默认
FieldStrategy.NOT_NULL：null 字段不进 SET，插件当前渲染全列 SET（update-strategy: always 全列语义，
文档化近似））；③ **id 默认不勾选比较合适**。

**现状盘点**（M23 交付后）：
- 批量参数面板已有参数行（T-M23-02）：`save(entity)` 每 `?` 一行 `#entity.列名` 输入框——但**只能填值、不能取舍列**；
- 动态条件复选框机制（M12/M13）只服务于 Wrapper 路径的 `Condition.toggle`（`previewModel` 驱动），批量路径是纯文本模板（`previewModel = null`），无模型可复用；
- `BatchOperationConverter` 各 builder 直接拼 SQL 字符串（INSERT/UPSERT/UPDATE 模板），无列级结构；
- `EntityResolver` 只标记 `isId`（`EntityResolver.kt:97`），未读取 `@TableId(type = IdType.AUTO)`——无法区分自增主键。

**对齐语义**（MP 官方）：
- `IdType.AUTO`：INSERT 不含主键列（数据库自增）；`IdType.INPUT` / `ASSIGN_ID`（默认）：INSERT 含主键列（应用侧赋值）；
- `updateById` 默认 FieldStrategy.NOT_NULL：null 字段不进 SET（静态不可知 → 勾选近似）。

## 2. 设计方案（T-M23-04）

### 2.1 核心：`BatchModel`（新 model，纯函数渲染）

新增 `model/BatchModel.kt`（不依赖 PSI，可独立单测，参照 `DialectTest` 纯 JUnit 风格）：

```kotlin
/** 批量模板种类（决定渲染形状）。 */
enum class BatchKind { INSERT, UPDATE, UPSERT }

/** 批量列（勾选行）：columnName=列名；source=参数来源（`entity.id`，面板标签）；quote=回填引号；checked=默认勾选态 */
data class BatchColumn(val columnName: String, val source: String, val quote: Boolean?, val checked: Boolean)

/**
 * 批量可选参数模型（T-M23-04）：INSERT/UPDATE/UPSERT 的列级勾选结构，
 * [renderSql] 按活跃列重建 SQL（唯一渲染源——转换器初始 SQL 与面板勾选重建共用，保证一致）。
 */
data class BatchModel(
    val kind: BatchKind,
    val tableName: String,
    val toggleColumns: List<BatchColumn>,      // 可勾选列（INSERT 全列 / UPDATE SET 列 / UPSERT 非主键列）
    val fixedColumns: List<BatchColumn> = emptyList(),  // 固定列（UPDATE 的 WHERE 主键+@Version / UPSERT 主键，恒参与、无勾选）
    val versionColumn: String? = null,          // UPDATE @Version：SET 追加 `version = version + 1`（字面量，固定）
) {
    /** 按活跃列重建 SQL（活跃集为空时渲染空列清单形态，面板不设保护——用户自选，文档化边界）。 */
    fun renderSql(activeColumns: Set<String>): String
    /** 渲染顺序的列（`?` 顺序 = 参数行顺序）：UPDATE 先 SET 后 WHERE；INSERT/UPSERT 固定列在前。 */
    fun orderedColumns(activeColumns: Set<String>): List<BatchColumn>
    fun orderedSources(activeColumns: Set<String>) = orderedColumns(activeColumns).map { it.source }
    fun orderedHints(activeColumns: Set<String>) = orderedColumns(activeColumns).map { ParamHint(quote = it.quote) }
}
```

渲染形状：
- **INSERT**：`INSERT INTO t (活跃列...) VALUES (?, ...)`
- **UPDATE**：`UPDATE t` `SET 活跃列 = ?, ...`（+ `, version = version + 1`）`WHERE id = ?`（+ ` AND version = ?`）
- **UPSERT**：`INSERT INTO t (固定主键 + 活跃列...) VALUES (?, ...)` `ON CONFLICT (主键) DO UPDATE SET 活跃列 = EXCLUDED.列`

### 2.2 转换器改造（`BatchOperationConverter`）

- `buildInsertBatch` / `buildUpdateBatch` / `buildUpsertBatch` 改为先构造 `BatchModel`，再 `renderSql(初始活跃集)` 得初始 SQL、`orderedSources/Hints` 得参数登记——**删除手工拼串**（唯一渲染源）；
- 默认勾选态：
  - INSERT 全列可勾选；**id 列默认不勾选**：`ColumnInfo.idTypeAuto == true`（`@TableId(type = IdType.AUTO)`）；非 AUTO（INPUT/ASSIGN_ID/无 type）→ 勾选（对齐 MP INSERT 含主键语义）；
  - UPDATE SET 列（非主键、非 version）默认全勾选；WHERE 主键与 @Version 为 fixed（无勾选）；
  - UPSERT 主键为 fixed（ON CONFLICT 依赖），其余默认全勾选；
- `insertBatchSomeColumn` 的 UPDATE-fill 排除列不进入 toggleColumns（维持现状）；
- `BatchPreview` 增加 `batchModel: BatchModel?`（DELETE 软删除 / SELECT 单主键等无列级选择的方法为 null）。

### 2.3 实体解析（`EntityResolver` + `ColumnInfo`）

- `ColumnInfo` 增加 `idTypeAuto: Boolean = false`；`EntityResolver` 主键字段读取
  `@TableId(type = ...)` 属性文本含 `AUTO` → true（`findAttributeValue("type")?.text?.contains("AUTO")`；
  全限定名与短名形态均含 `AUTO`，与既有注解短名兜底策略一致）；fixture 写全限定名。

### 2.4 面板（`SqlPreviewPanel`）

- `PreviewResult` 增加 `batchModel: BatchModel? = null`（默认 null，存量预览不受影响）；
- `showResult`：batchModel 非空时用默认勾选态初始化 `enabledIds`（列名作 id；与条件 toggle 互斥——批量预览无 conditionViews）；
- `rebuildLeftPanel`：batchModel 分支——toggle 列渲染**复选框 + 值输入框**行（复用 `paramValues` 按 source 绑定、`paramFields` 收集），fixed 列渲染**纯值输入框**行（无复选框）；批量列区**不提供全选/全不选**（避免误操作清空列清单，与动态条件区按钮互不影响）；
- `renderSql`：batchModel 分支优先——`batchModel.renderSql(enabledIds)` + `backfillParamsBySource(sql, orderedSources, orderedHints)`；`previewModel` 分支与旧文本路径不动；
- 勾选变更：`enabledIds` 增删 + 重渲染（复用 `onParamChanged` 语义）。

### 2.5 边界（文档化，不实现）

- 活跃集为空：渲染空列清单形态（`INSERT INTO t () VALUES ()` / `UPDATE t SET  WHERE id = ?`）——用户自选，不做保护；
- `updateById` 的 NOT_NULL 语义仍为静态近似（勾选是手工近似，非自动判 null）；
- UPSERT 取消全部非主键列 → `ON CONFLICT (id) DO UPDATE SET `（空）——同为空集边界；
- 软删除/单主键批量（SELECT/DELETE 族）无列级选择，不引入 batchModel。
