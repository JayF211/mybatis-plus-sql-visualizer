## 二、目标与非目标

**目标**：当 INSERT 的列清单**包含自增列**且方言需要包装时，生成「包装 + INSERT + 解除包装」的完整可回放语句（SQL Server：`SET IDENTITY_INSERT <table> ON; …; SET IDENTITY_INSERT <table> OFF;`），使回滚/回放与手动勾选自增列的 CRUD **都能实际执行成功**。

**非目标**：不改「默认不勾自增列」的既有默认（那是对的）；不为不需要包装的方言造包装（默认返回 null）；不做达梦的包装**除非**真机证伪（DBX 有 DM 实现，但我方无 DM identity 真机证据——见 §八 待验证前提 2）；不改 upsert 分支（已有独立形态）。

## 三、方案

**T-IIW-01（方言钩子）**：`sql/Dialect.kt` 新增 `fun renderInsertWrapper(tableName: String, sql: String): String?`，**默认返回 null**（不包装）；`SqlServerDialect` 覆写为 `SET IDENTITY_INSERT <t> ON;\n<sql>\nSET IDENTITY_INSERT <t> OFF;`。**注意表名须按方言引用规则处理**（复用 `quoteIfNeeded`，与 T-IFF/O-42 的引号策略一致）。

**T-IIW-02（判定与接线）**：
- **CRUD 侧**：`generator/CrudSqlGenerator.kt` 在渲染 INSERT 时判定「列清单是否含 `autoGenerated` 列」——含则过 `renderInsertWrapper`；来源直接用 `CrudTableSpec.autoGenerated`（`CrudTableSpec.kt:27`）。
- **回滚侧**：`RollbackSqlGenerator.backfillInsert`（`:402`）同法，但 identity 信息**需先解决来源**（T-IIW-03）。
- 渲染落点 `model/BatchModel.kt:114-117`：加前置/后置钩子（与既有 UPSERT 的 `:129-146` 后缀分支同规）。

**T-IIW-03（回滚侧 identity 来源，二选一，须定案 D1）**：

| 选项 | 内容 | 代价 | 推荐度 |
|---|---|---|---|
| **A（扩 SnapshotEntry）** | `RollbackSnapshotStore.kt:50-57` 增 `dialect` + `identityColumns` 字段，生成快照时写入 | 改动快照持久化格式（**须考虑向后兼容**：旧快照无字段 → 视为「未知」不包装） | ★★★ |
| B（生成时反查） | 生成回滚 SQL 时经 `DbTableSpecAdapter` 按表名反查 identity 列 | 需项目上下文与数据源模型（回滚对话框可能无上下文）；慢 | ★★ |

**D1 建议**：**A**——快照本就在生成时持有上下文（`RollbackSnapshotStore` 由预览链写入），扩字段是最自然的落点；向后兼容用「字段缺失 = 不包装」处理（与既有「未知语义不臆造」口径一致）。

**T-IIW-04（测试与文档）**：
- CRUD 侧：勾选自增列 + SQL Server → 产物含包装；不勾 → 产物**逐字节不变**（防回归，这是最重要的不变式）；
- 回滚侧：快照含 identity 列 + SQL Server → 产物含包装；旧快照（无字段）→ 不包装（向后兼容用例）；
- 其他方言：产物**逐字节不变**；
- 文档：CHANGELOG `[Unreleased]` + 变更记录行 + 第十轮报告 §8 #61 落地备注。

## 四、验收标准

1. **默认路径逐字节不变**：不含自增列的 INSERT（两条链）产物与改前完全相同（硬不变式）。
2. SQL Server + 含自增列：产物含 `SET IDENTITY_INSERT … ON/OFF` 包装，且表名按方言引用规则处理。
3. 回滚侧向后兼容：旧快照（无 identity 字段）**不包装**且不报错。
4. 其他方言（PG / MySQL / Oracle / DM / KingBase / H2 / SQLite / MariaDB）产物逐字节不变。
5. **真机端到端**：SQL Server 上回放一条含 identity 列的 INSERT **实际执行成功**（改前报 544）。
6. 全量 testShards + testDatabase + agent 绿。

## 六、风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| **默认路径被改坏**（最大风险） | 加钩子若改变了不含自增列的 INSERT 产物，会影响所有用户 | 验收 1「逐字节不变」+ 既有全部 INSERT 用例（CRUD / 批量 / 回滚 / MCP 五处）作为回归门 |
| **快照格式变更** | D1=A 会改 `SnapshotEntry` 的持久化形态 | 向后兼容用例（验收 3）；字段缺失按「未知不包装」处理，不臆造 |
| 无 SQL Server 环境 | 端到端验证可能做不了 | §五-1 先查连接；无则**如实登记为环境受限未验证**，不得拿单测读数冒充 |
| 达梦行为未知 | DBX 有 DM identity 实现，但我方无真机证据 | **默认不为 DM 造包装**（不照抄）；若 §五-3 证伪为需要，另立增量 |
| 表名引用不一致 | 包装里的表名若与 INSERT 里的引用形态不同，SQL Server 可能不匹配 | 包装与 INSERT **共用同一引用函数**（`quoteIfNeeded`），用例断言两者一致 |
| 多语句整段提交 | `RollbackSqlDialog.kt:217` 把多语句整段提交，`SET IDENTITY_INSERT` 与 INSERT 是否同会话同批生效未验 | §五-2 端到端确认；若不同批生效则须改提交形态（届时另议） |
