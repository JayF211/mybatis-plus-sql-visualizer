# 方言全兼容与反向分页解析 开发计划（T-M43）

- 日期：2026-08-16
- 状态：✅ **已交付（2026-08-16，530d588，1175 测试全绿领地验证，并入 v2026.8.17）**

- 背景来源：用户反馈——「设置里出现 = 承诺可用」方言全兼容 + 反向 SQL→Java 分页解析尚不支持 LIMIT/OFFSET 等形态

## 1. 需求分析

| # | 需求 | 现状 | 目标 |
|---|------|------|------|
| 1 | UPSERT 按方言渲染 | `BatchModel.renderSql` 仅支持标准 INSERT/UPDATE，UPSERT 无分支 | Dialect SPI 第 4 差异点 `renderUpsert`：MySQL/MariaDB → `ON DUPLICATE KEY UPDATE + VALUES()`；PG/H2/SQLite/KingBase → `ON CONFLICT + EXCLUDED`；Oracle/SQLServer/DM 降级纯 INSERT |
| 2 | 反向分页解析宽容 | `SqlReverseParser` 仅识别 `LIMIT ?` 单形态，`LIMIT n OFFSET m` / `OFFSET ... FETCH` / `FETCH FIRST` 不识别 | 三形态全解析（含 `?` 占位）；`consumeOptionalAlias` 防护列表补 OFFSET/FETCH（`FROM t OFFSET` 被当表别名吞掉实证）；`isClauseStart/isClauseToken` 列名防误判 |
| 3 | DM 实证 | DM 达梦数据库支持 `LIMIT M,N` 语法但未验证 | DM8 实证通过（`LIMIT M,N` 为 4 种写法之一） |

## 2. 实现要点

- `Dialect` SPI 接口新增 `renderUpsert` 方法，6 种方言各自实现
- `BatchModel.renderSql` 分支：根据 `conflictColumn` 是否非空 + 方言能力选择渲染路径
- `SqlReverseParser` 分页识别扩展：正则 + 词法双路径，防护列表补 OFFSET/FETCH 关键字
- 零面板改动：`modelBuild` 注入方言实例
