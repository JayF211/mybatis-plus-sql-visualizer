# JPA 嵌套对象 JOIN 查询支持开发计划

> 创建日期：2026-08-20
> 状态：**计划中**
> 优先级：P1（阶段一遗留：嵌套属性路径暂不支持 JOIN，降级为 Condition.Raw）

## 问题描述

当前 `findByAddressCity` 形式的 Spring Data JPA 推导查询不支持嵌套对象关联（JOIN），只能降级为 `Condition.Raw("关联查询: addressCity")`。

**根因**：
1. `PartTreeParser.decamelize()` 仅首字母小写（`AddressCity` → `addressCity`），不做关联字段识别
2. `TableInfo` 无关联元数据（缺少 `@ManyToOne` 目标实体信息）
3. `DerivedQueryConverter.isNestedProperty()` 只检查含 `.` 的路径，不支持驼峰嵌套
4. 无自动 JOIN 构建逻辑

## 目标

支持 Spring Data JPA 嵌套属性路径自动展开为 JOIN：

```
findByAddressCity           → SELECT ... FROM user t LEFT JOIN address t1 ON t1.id = t.address_id WHERE t1.city = ?
findByAddressCityAndName    → ... LEFT JOIN address t1 ON t1.id = t.address_id WHERE t1.city = ? AND t.name = ?
findByDepartmentName        → ... LEFT JOIN department t1 ON t1.id = t.department_id WHERE t1.name = ?
```

## 技术方案

### 整体链路

```
方法名 → PartTreeParser.parse()
         ↓ propertyPath = "addressCity"
         ↓ 识别 "address" 是关联字段 → 拆分为 associationPath="address" + remainingPath="City"
         ↓
DerivedQueryConverter.convert()
         ↓ 从 TableInfo.associations 查找 "address" → AssociationInfo
         ↓ 构建 JoinClause: LEFT JOIN address t1 ON t1.id = t.address_id
         ↓ 条件列归副表: t1.city = ?
         ↓
SqlGenerator 渲染（已有 JOIN 渲染逻辑，直接复用）
```

### 改动一：TableInfo 扩展 — 关联元数据

**文件**：`src/main/kotlin/.../model/TableInfo.kt`

新增 `AssociationInfo` 数据类和 `TableInfo.associations` 字段：

```kotlin
/**
 * 关联信息（JPA @ManyToOne / @OneToOne 关联）。
 *
 * @param fieldName    关联字段名（Java 字段名，如 "address"）
 * @param joinColumn   外键列名（主表侧，如 "address_id"）
 * @param targetTable  目标表名（副表，如 "address"）
 * @param targetAlias  建议别名（实体类名首字母小写，如 "address"）
 */
data class AssociationInfo(
    val fieldName: String,
    val joinColumn: String,
    val targetTable: String,
    val targetAlias: String,
)

// TableInfo 新增字段
data class TableInfo(
    // ... 现有字段不变
    val associations: List<AssociationInfo> = emptyList(),  // 新增
) {
    /** 按字段名查找关联信息 */
    fun associationByField(fieldName: String): AssociationInfo? =
        associations.firstOrNull { it.fieldName == fieldName }
}
```

**兼容性**：新增字段有默认值 `emptyList()`，所有现有构造点零改动。

### 改动二：JpaEntityResolver — 解析关联元数据

**文件**：`src/main/kotlin/.../psi/jpa/JpaEntityResolver.kt`

在 `resolveInternal()` 中增加关联收集逻辑：

```kotlin
private fun resolveInternal(entityClass: PsiClass): TableInfo {
    // ... 现有字段解析不变

    // 新增：收集 @ManyToOne / @OneToOne 关联元数据
    val associations = fields.mapNotNull { field -> resolveAssociation(field) }

    return TableInfo(
        entityClassName = className,
        tableName = tableName,
        columns = columns,
        logicDeleteColumn = null,
        versionColumn = null,
        comment = comment,
        associations = associations,  // 新增
    )
}

/**
 * 解析单个字段的关联信息。
 *
 * @ManyToOne + @JoinColumn → 外键列名 + 目标实体类名 → 目标表名
 * @OneToOne + @JoinColumn  → 同上
 * 其他 → null
 */
private fun resolveAssociation(field: PsiField): AssociationInfo? {
    val isManyToOne = hasAnnotation(field, MANY_TO_ONE_ANNOTATION)
    val isOneToOne = hasAnnotation(field, ONE_TO_ONE_ANNOTATION)
    if (!isManyToOne && !isOneToOne) return null

    val fieldName = field.name
    // 外键列名：@JoinColumn(name="xxx") 或默认 {fieldName}_id
    val joinColumn = annotationAttributeValue(field, JOIN_COLUMN_ANNOTATION, "name")
        ?: NamingStrategy.toSnakeCase(fieldName) + "_id"

    // 目标实体类：从字段类型的泛型参数或直接类型获取
    val targetClass = resolveTargetEntityClass(field) ?: return null
    val targetTableName = resolveTargetTableName(targetClass)

    // 别名：实体类名首字母小写
    val targetAlias = (targetClass.name ?: fieldName).replaceFirstChar { it.lowercaseChar() }

    return AssociationInfo(
        fieldName = fieldName,
        joinColumn = joinColumn,
        targetTable = targetTableName,
        targetAlias = targetAlias,
    )
}

/**
 * 解析 @ManyToOne/@OneToOne 字段的目标实体类。
 *
 * 策略：
 * 1. 字段类型直接是 PsiClassType → 取 PsiClass
 * 2. 泛型字段（如 Optional<Address>）→ 取第一个泛型实参
 * 3. 无法解析 → null（降级：不作为关联处理）
 */
private fun resolveTargetEntityClass(field: PsiField): PsiClass? {
    val type = field.type as? com.intellij.psi.PsiClassType ?: return null
    val resolveResult = type.resolve() ?: return null
    return resolveResult
}

/**
 * 从目标实体 PsiClass 获取表名。
 *
 * 优先 @Table(name="xxx")，否则按命名策略推断。
 */
private fun resolveTargetTableName(targetClass: PsiClass): String {
    val explicitTable = annotationAttributeValue(targetClass, TABLE_ANNOTATION, "name")
    if (explicitTable != null) return explicitTable
    val className = targetClass.name ?: return NamingStrategy.toSnakeCase("unknown")
    return decorateTableName(inferTableName(className))
}
```

### 改动三：PartTreeParser — 嵌套属性路径识别

**文件**：`src/main/kotlin/.../converter/jpa/PartTreeParser.kt`

新增 `NestedPropertyPath` 数据类和路径拆分逻辑：

```kotlin
/**
 * 嵌套属性路径解析产物。
 *
 * @param associationPath 关联路径段（如 "address"），null 表示非嵌套属性
 * @param remainingPath   剩余属性路径（如 "City"），非嵌套时等于原始 propertyPath
 */
data class NestedPropertyPath(
    val associationPath: String?,
    val remainingPath: String,
) {
    val isNested: Boolean get() = associationPath != null
}
```

修改 `Condition` 数据类，增加嵌套路径信息：

```kotlin
data class Condition(
    val propertyPath: String,      // 原始属性路径（如 "addressCity"）
    val type: PartType,
    val ignoreCase: Boolean,
    val nestedPath: NestedPropertyPath? = null,  // 新增：嵌套路径解析结果
)
```

修改 `parseCondition()` 方法，在解析条件时尝试拆分嵌套路径：

```kotlin
private fun parseCondition(part: String, globalIgnoreCase: Boolean): Condition {
    val matchResult = matchConditionKeyword(part)

    if (matchResult != null) {
        val (propertyPart, partType) = matchResult
        return Condition(
            propertyPath = decamelize(propertyPart),
            type = partType,
            ignoreCase = globalIgnoreCase,
            nestedPath = splitNestedPath(propertyPart),  // 新增
        )
    }

    return Condition(
        propertyPath = decamelize(part),
        type = PartType.SIMPLE_PROPERTY,
        ignoreCase = globalIgnoreCase,
        nestedPath = splitNestedPath(part),  // 新增
    )
}

/**
 * 拆分嵌套属性路径。
 *
 * 策略：按 camelCase 边界切分 token，从头部开始匹配关联字段名。
 * 例如 "AddressCity" → tokens: [Address, City]
 *       第一个 token "Address" 的小写 "address" 匹配到关联字段 → associationPath="address", remainingPath="City"
 *
 * @param propertyPart 属性部分（驼峰形式，如 "AddressCity"）
 * @return 嵌套路径解析结果（非嵌套时 associationPath=null）
 */
fun splitNestedPath(propertyPart: String): NestedPropertyPath {
    if (propertyPart.isEmpty()) return NestedPropertyPath(null, propertyPart)
    val tokens = splitCamelCase(propertyPart)
    if (tokens.size < 2) return NestedPropertyPath(null, propertyPart)

    // 第一个 token 小写后作为候选关联字段名
    val firstToken = tokens[0]
    val candidateAssociation = firstToken.replaceFirstChar { it.lowercaseChar() }
    val remainingTokens = tokens.subList(1, tokens.size)
    val remainingPath = remainingTokens.joinToString("")

    return NestedPropertyPath(
        associationPath = candidateAssociation,  // 仅候选，需 TableInfo 确认
        remainingPath = remainingPath,
    )
}
```

**注意**：`splitNestedPath` 仅做候选拆分（第一个 token 作为关联字段候选），真正的关联确认在 `DerivedQueryConverter` 中通过 `TableInfo.associationByField()` 完成。

### 改动四：DerivedQueryConverter — 自动 JOIN 构建

**文件**：`src/main/kotlin/.../converter/jpa/DerivedQueryConverter.kt`

修改 `convert()` 方法，在构建 SelectStatement 时处理嵌套属性：

```kotlin
fun convert(partTree: PartTree, tableInfo: TableInfo): SqlStatement {
    val converter = PartTreeConverter(tableInfo)
    return converter.convert(partTree)
}

private class PartTreeConverter(private val tableInfo: TableInfo) {

    fun convert(partTree: PartTree): SqlStatement {
        // 步骤 1：收集所有嵌套属性路径，构建 JOIN
        val joins = buildJoins(partTree)

        // 步骤 2：转换条件（嵌套属性列归副表）
        val conditions = convertPredicates(partTree.predicates, joins)

        // 步骤 3：转换 ORDER BY（嵌套属性列归副表）
        val orderBy = convertOrderBy(partTree.orderBy, joins)

        // ... 构建 SelectStatement（传入 joins）
    }

    /**
     * 从所有条件中收集嵌套属性路径，构建 JOIN 子句。
     *
     * 规则：
     * - 遍历所有条件的 nestedPath
     * - associationPath 在 TableInfo.associations 中存在 → 构建 JoinClause
     * - 同名关联只构建一次 JOIN（去重）
     * - 别名冲突时递增后缀（address → address1, address2...）
     */
    private fun buildJoins(partTree: PartTree): List<JoinClause> {
        val joinMap = mutableMapOf<String, JoinClause>()
        val usedAliases = mutableSetOf<String>()

        for (predicate in partTree.predicates) {
            for (condition in predicate.conditions) {
                val nested = condition.nestedPath ?: continue
                if (!nested.isNested) continue

                val association = tableInfo.associationByField(nested.associationPath) ?: continue
                if (joinMap.containsKey(association.fieldName)) continue

                // 别名冲突检测
                var alias = association.targetAlias
                var suffix = 1
                while (alias in usedAliases) {
                    alias = association.targetAlias + suffix
                    suffix++
                }
                usedAliases.add(alias)

                joinMap[association.fieldName] = JoinClause(
                    type = JoinType.LEFT,
                    tableName = association.targetTable,
                    alias = alias,
                    onConditions = listOf(
                        Condition.ColumnComparison(
                            left = ColumnRef(tableAlias = alias, columnName = "id"),
                            right = ColumnRef(columnName = association.joinColumn),
                        )
                    ),
                )
            }
        }
        return joinMap.values.toList()
    }

    /**
     * 转换条件，嵌套属性列归副表。
     *
     * 例如：Condition("addressCity", SIMPLE_PROPERTY) + joins 中存在 address → address_id
     *       输出：Condition.Simple(ColumnRef(tableAlias="address", columnName="city"), "=", ?)
     */
    private fun convertConditionToModel(
        condition: Condition,
        joins: List<JoinClause>,
    ): cn.song.mybatisplus.visualizer.model.Condition {
        val nested = condition.nestedPath
        if (nested != null && nested.isNested) {
            // 嵌套属性：列归副表
            val association = tableInfo.associationByField(nested.associationPath)
            if (association != null) {
                val joinClause = joins.firstOrNull { it.tableName == association.targetTable }
                if (joinClause != null) {
                    val column = resolveNestedColumn(nested.remainingPath, joinClause.alias)
                    return buildCondition(column, condition.type, condition.ignoreCase)
                }
            }
            // 关联未找到 → 降级
            return cn.song.mybatisplus.visualizer.model.Condition.Raw("关联查询: ${condition.propertyPath}")
        }

        // 非嵌套属性：现有逻辑
        return convertConditionToModelExisting(condition)
    }

    /**
     * 解析嵌套属性列引用。
     *
     * 例如：remainingPath="City", alias="address"
     *       输出：ColumnRef(tableAlias="address", columnName="city")
     */
    private fun resolveNestedColumn(remainingPath: String, alias: String): ColumnRef {
        val columnName = NamingStrategy.toSnakeCase(remainingPath)
        return ColumnRef(tableAlias = alias, columnName = columnName)
    }
}
```

## 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 目标实体类 PSI 不可解析 | 关联信息缺失 | 降级：不生成 JOIN，条件走 Condition.Raw |
| 别名冲突（同名关联多次使用） | SQL 别名重复 | 递增后缀：address → address1 → address2 |
| 循环关联（A→B→A） | 无限递归 | 不递归解析关联的关联，只处理一层嵌套 |
| 驼峰歧义（`AddressCity` 可能是单一字段） | 误判为嵌套 | 仅在 `TableInfo.associations` 中确认后才走 JOIN |
| 副表列名推断不匹配 | 列名错误 | 使用 NamingStrategy.toSnakeCase 兜底，与 JPA 默认命名一致 |
