# T-SyncK2JMaster90：master 新增功能同步到 Java 端口分支

## 目标与边界

用户要求先生成开发计划，再把主分支最近更新的功能同步到 feature/kotlin-to-java，解决冲突、完成全量测试并修复失败，确保插件构建校验通过。

本轮只做功能移植，不执行 master→feature/kotlin-to-java 的 merge，也不把 Kotlin 生产文件复制进 Java 生产树。保留端口分支既有 Java 互操作、MCP 序列化和异常透传适配。测试可保持 Kotlin/Java 混合，按实际承载类型补齐用例，不产生同包同名测试类。

## 二、待验证前提

1. 3730a927 是冻结目标的祖先，已通过 git merge-base --is-ancestor 核验；后续一律用完整 SHA 读取，避免混用移动中的 master。
2. Kotlin 文件与 Java 承载并非一对一。每个变更声明均需找到对应 Java 类、门面或拆分件；新增文件不等于新增类型，文件名相同不等于功能已同步。
3. 增量中的实体解析、捕获/列表交互、HQL 提取、性能与资源改动，以冻结版本实际 diff 为准，不能把 dev 或其他未合入分支的功能混入本轮。
4. 共享构建/资源文件可能有端口专属内容。直取前比较 base/Java HEAD/冻结 master 三个 blob；有分歧的文件逐块合并，不能目录覆盖。docs 索引保留 Java 分支专属记录并核对链接。
5. 测试中的缺失 .kt 可能由同名 .java 承载。先查类型和用例，再决定更新承载件或新增测试；不能把缺失路径当成空白直接创建。
6. 规则扫描必须覆盖 src/main/java 的真实站点，守卫空扫描不可算绿。变更规则做精确反向验证，不靠调宽白名单或机械增大基线消除失败。
7. 全量分片配置缓存可能漏新增类。权威 testShards 使用 --no-configuration-cache，核对五片 XML、测试类覆盖和失败/跳过原因。
8. 当前检测到 T-DevFullUI-243 活跃走查任务。构建前再次 check，非零不直接启动 Gradle；确认可用隔离方式并登记独立沙盒。不得杀对方进程或更改对方沙盒。全量测试独占构建验证时段，普通构建最多两路。
9. 兼容性门禁不能用编译代替。verifyGate 必须记录三目标结果及新增 API 告警，buildPlugin 回读 ZIP 内 version、plugin.xml 与 SHA-256。
10. 数据库集成测试是否真正执行，要看 XML 和跳过原因。Docker 不可用或数据库测试被 skip 时如实列出，不以 BUILD SUCCESSFUL 代替覆盖证据。

## 三、实施顺序

### 阶段 A：精确清单与写集

两个只读调研任务分别核验生产映射和测试/共享资源/构建增量。按功能闭环形成映射清单：master 路径与声明、Java 落点、关联测试、验证方式。检查删除/重命名、调用入口和默认值变化，记录未证平台 API。

本计划先落盘，之后才允许代码修改。调研发现写集重叠时由主控裁定唯一写入者，不按“当前没脏改动”判断所有权。

### 阶段 B：增量移植

- 基础模型与公共入口先落；依赖方后执行。独立写集最多三个异步子代理，不允许再派下级代理。
- 更新既有 Java 实现，以 master 增量语义为准，保留旧构造器/便捷重载、可空与短路行为、集合顺序、getter 虚分派及 fatal 原对象透传。
- 新平台 API 先查本地 jar/源码签名；不臆造 API。MCP Java 结果载体保留既有 kotlinx serializer 适配，不回退到裸 String。
- 每组生产功能与对应新增/改动测试一起移植。Kotlin 测试对 Java API 使用位置实参、真实静态门面/INSTANCE 与 record 访问器。
- 构建、plugin.xml、双语资源和文档按三方差异同步；发行描述版本与产物一致。不修改 update/update.json 的用户手改内容以外的额外范围，不发版、不部署、不推送。

### 阶段 C：集成校验和独立复核

先完成 compileJava、compileTestKotlin、compileTestJava，三项缺一不可。用完整日志保存真实退出码，不用 grep/tail 的退出码冒充 Gradle 成功。语法修复不得改变断言意图。

各实施者只做本任务相关定向测试，统一全量仅在全部写入停止后执行。守卫变更验证其能看见真实 Java 站点，修复前应红、恢复后应绿。独立复核关注跨调用链绕过、模型字段透传、异步回调/生命周期和新增功能只完成数据模型未接入口的问题。

### 阶段 D：权威门禁

1. 资源登记、Commit 内存水位、Docker daemon 活性预检；使用独立沙盒与实际构建参数。
2. testShards 默认五片，--no-configuration-cache；核实 testExternal 是否被依赖覆盖，不重复计算套件。
3. :sql-visualizer-agent:test，记录实际执行或 up-to-date 状态及 XML 计数。
4. testDatabase，核查五个子任务、驱动种子及所有 skip 的原因。
5. verifyGate 三目标兼容性、buildPlugin 构建，检查 ZIP 文件及其 SHA-256。
6. 任一生产修改后重跑受影响定向及最终全量；最终 ZIP 和兼容性报告必须属于最后一份生产代码，不能在门禁后补代码仍引用旧绿灯。

所有长任务后台启动，依完成通知继续，不用 sleep 或 TaskOutput 阻塞等待。门禁期间主控只整理文档，不修改生产源码。

### 阶段 E：收官

冻结目标内逐项对账，无漏移植后再推进 .port-sync。计划、台账和索引同步更新，记录提交/未提交状态及验证命令、真实计数、skip、未覆盖边界、产物路径和校验和。清理仅限本轮临时配置，按任务名注销登记。

如 master 在运行中继续前进，列出冻结目标以后的提交，不静默扩大已测范围；需要补入时先更新清单并重新验证，不能先推进锚点再补测。本轮不主动 push、不合入 master/dev、不打 tag。
