## §一 现状盘点（20261006 主仓 master `e24eb6d` 实测）

反向链路（SQL→Java）已具备的底座：

| 组件 | 规模 | 能力 |
|---|---|---|
| `SqlReverseParser` | 1381 行 | 自研 tokenizer+递归下降；SELECT/UPDATE/DELETE/INSERT 四语句型；JOIN 全类型（含子查询 JOIN 的 MConsumer 形态）；OR 分组建模为 Group；三方言分页（LIMIT n / LIMIT o,c / OFFSET-FETCH）；`?` 占位符；不支持的表达式降级 `Condition.Raw`（apply 透传+warning） |
| `JavaCodeGenerator` | 1084 行 | 五形态生成（字符串列名 QueryWrapper / LambdaQueryWrapper / Wrappers 工厂 / MPJ 两形态）；invocation 上下文（Service/Mapper 真实方法集反查）；VO 查询 |
| `SqlToJavaConverter` | 299 行 | 两入口共享编排（编辑器动作+工具窗面板）；批量拆分 parseBatch 错误隔离 |
| MCP `reverse_sql` | — | `sqlv_reverse_sql` 工具在役（SELECT/UPDATE/DELETE/INSERT，JOIN 支持） |
| 测试 | 8 类 4346 行 | 含 `SqlToJavaRoundTripTest`（模型→SQL→反解→模型→SQL 逐字符闭环），但语料为手工构造子集 |

正向链路（Java→SQL，主功能）：PSI 解析 Wrapper 调用链 → `QueryWrapperParser`（纯逻辑无 PSI 依赖，可单测）→ `SelectStatement` 模型 → `SqlGenerator` 渲染 SQL。

**结构性不对称（往返断链根因）**：正向模型 `SelectStatement` 已支持 `distinct / groupBy / having / unions` 且 `SqlGenerator` 能渲染（`SelectStatement.kt:56-92`、`SqlGenerator.kt:142-204`），反向 `SqlReverseParser` 对同一批子句**直接报错不支持**（`SqlReverseParser.kt:300-302`）。正向能生成的 SQL，反向解析不回去——这是「Java→SQL→Java」往返最先撞上的墙。

Beta 文案面：仅 bundle 两行（`log.tab.sqlToJava`，en/zh 各一）；plugin.xml 与 MCP 描述无 Beta 字样。

## §二 缺口台账（转正验收项）

|---|---|---|---|---|

| G2 | `HAVING ...` | 报错 unsupported | 生成 `.having("...", params)` 字符串形态（MP 该签名天然容纳聚合表达式）；聚合条件走参数化透传 | P0 |
| G3 | `SELECT DISTINCT` | DISTINCT 被静默吞掉、select 生成放弃 | 字符串形态 `select("DISTINCT ...")`；lambda 形态按 MP API 实证结果落地（无 API 则回落字符串形态并在注释说明） | P0 |
| G4 | `FOR UPDATE` | 报错 unsupported | 生成 `.last("FOR UPDATE")`（MP 生态惯用形态；正向模型无此建模，单向透传即可） | P0 |

## §三 里程碑与实施编排

车道原则：生产码改动集中在 reverse 包+model 少数文件，单实施车道顺序推进（不拆并行子代理互抢同一批文件）；M1 纯测试基建可先行或并行；每完成一件可提交的立即提交。

- **M1 语料库与往返门禁基建（纯测试，不动生产码）**
  1. 语料库三源：①规范形 SQL 集（现有 RoundTripTest 用例扩容：四语句型×条件矩阵×JOIN 矩阵×分页三方言×G1~G12 全形态×方言宽容清单）②正向模型语料（手工构造 WrapperCall 链→SqlGenerator 产出）③demo 语料转录（mybatis-plus-demo / mybatis-plus-join-demo 真实 service/mapper 的 Wrapper 链人工转录为测试用例；PSI 真实链路由 M4 runIde 走查兜底，不做自动抽取脚本——成本收益不划算）。语料存放先查既有测试资源目录惯例，无则 `src/test/resources/reverse/`。
  2. 往返门禁参数化测试：全语料逐条「SQL1 → 反解 → 反向模型 → 桥接正向模型 → SqlGenerator 渲染 SQL2」，规范化比对（关键字大小写/空白折叠）。现有 RoundTripTest 里手工重建正向模型那段的逻辑正式化为测试桥接函数（`SqlReverseResult` → `SelectStatement`）。
  3. **基线报告**：M1 完成时用现有解析器跑全语料，产出三档分布（纯 Wrapper 映射 / Raw 降级 / 报错）读数留档——这是转正前的「差距」证据底座，也是 M2/M3 每一项的先红清单。
- **M2 解析与建模 P0（G1~G6）**：反向模型补字段（groupBy/having/distinct/unions/forUpdate 语义槽位）→ 解析器补分支 → 生成器补方法映射（MP 签名 javap 实证先行，见 §五 前提）。G5 的语义修复（聚合列不再丢弃）单独提交并登记行为变化。
- **M3 透传升级与评估项（G7~G11）**：G7 参数化 apply；G8 UNION 递归解析（按 §五 前提 1 实证结果定落地或降级）；G9 updateJoin 实证评估；G10 方言宽容收敛（tokenizer 层为主，影响面小）；G11 确认+钉语料。
- **M4 demo 双跳与真机走查**：①生成代码→WrapperChain 的**测试适配解析器**（只解析本生成器输出的受控字符串形态 `.eq("col", v)` 序列，非生产码）→ 形成「Wrapper 链→SQL1→Java 文本→WrapperChain→SQL2」双跳闭环；②runIde 沙盒+demo 项目真机走查批 5~8 条真实链路（含 JOIN/分组/分页各一），截图留档。
- **M5 转正收尾**：全量门禁收口（单派只读收口代理，主控并行写文档）→ 文案面五处同步 → CHANGELOG → 转正宣告。

依赖关系：M2 依赖 M1 的语料与基线（先红）；M3 依赖 M2 建模基建；M4 依赖 M2+M3；M5 收口。M1 可与「用户拍板」并行先行。

## §四 验证设计（用户点名的往返方式如何落实）

三层验证金字塔：

1. **SQL 层往返（门禁级，全语料）**：SQL1 → 反解 → 桥接 → SQL2，规范化逐字符比对。已知的结构性非对称（如 `LIMIT 10 OFFSET 5` 反解建模后正向统一渲染 `LIMIT 5, 10`）属语义等价形态差，入白名单并注明；其余不等一律按缺陷处理。
2. **Java 层双跳（demo 语料）**：Wrapper 链样本 → 正向 SQL1 → 反向 Java 文本 → 适配解析器还原 WrapperChain → 正向 SQL2 → SQL1≈SQL2。这是用户点名的「Java 转 SQL 再 SQL 转 Java」的直接实现，能暴露「生成的代码正向解析不回去」类断链（反向生成的 API/参数形态与正向 PSI 解析器支持面不一致时会在这里现形）。
3. **真机走查（runIde+demo 项目）**：真实 PSI 链路端到端，覆盖前两层覆盖不到的 PSI 上下文/实体解析/多候选弹窗交互；读数入验收文档。

反向验证纪律：每项缺口修复必须「先红后绿」——M1 基线里该项语料为红（报错或降级），修复后转绿，两次读数入实施记录。守卫类改动（若有）按「删修复分支必红」执行。

## §五 待验证前提（实施者先证伪再动手）

1. **MP 3.5.15 API 签名**：`groupBy(String...)`、`groupBy(SFunction...)`、`having(String, Object...)`、`union/unionAll(Wrapper...)`（3.5.4+ 引入，3.5.15 在役版本签名）——一律以本地依赖 jar javap 为唯一权威，文档与记忆不作为依据。证伪即走降级路线（last/apply 透传），禁止生成不存在的 API。
2. **MPJ 1.5.6 API**：`MPJLambdaWrapper` 的 groupBy/selectDistinct/updateJoin 族签名同上实证；MPJQueryWrapper（字符串形态）的对应能力另证。
3. **UNION 递归解析边界**：UNION 各支自身的 ORDER BY/LIMIT 归属语义（MySQL 中尾部子句作用于整体）——实现前用语料固定行为，不清不楚的形态降级 Raw。
4. **生成代码形态受控假设**：M4 的适配解析器只成立在本生成器输出形态上；若发现生成形态多样性超出可控（嵌套 lambda、invocation 完整语句形态），双跳覆盖面收缩为「纯表达式形态」，invocation 语句形态由真机走查兜底。
5. **demo 语料形态代表性**：demo 项目 Wrapper 链为教学形态，真实工程更杂——转录时按 G10 方言清单同步补边界用例，不以「demo 过了」当全覆盖证据。
6. **G5 行为变化**：现状「函数列丢弃变全列」可能在被用户依赖（虽然属缺陷）；修复登记 CHANGELOG 并在生成代码注释保留 warning 提示，不静默。
7. **编号快照时效**：本册预定占用 O-110/R55/D64/V82 快照号——并行会话高频推进，落库登记前 git 实测防撞号。
