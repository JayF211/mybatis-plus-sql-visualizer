## 背景

## 未实施部分（暂缓）

以下文件经评估不适合盲目拆分，记录决策依据供后续参考：

### `SqlPreviewPanel.kt`（1775 行）

**不拆原因**：God 面板，`paramValues`/`enabledIds`/`current`/`editor`/`paramPanel` 等 20+ 状态字段在 50+ 方法间交叉使用。拆分要么把私有状态变 `internal`，要么用委托模式，改动面大且无法用现有测试完全覆盖回归风险。测试依赖 18 个 `xxxForTest()` 方法直接访问面板私有状态。

**可行的后续优化**：
- 提取纯工具函数（`ellipsize`/`detectInClauseParams`/`renderSingleValue`/`reformatShortcuts`）到 `util` 包（~100 行，收益小）
- 按 UI 区域拆子面板（`conditionSection`/`editorSection`/`toolbar`），但需重写大部分 init 逻辑

### `SqlReverseParser.kt`（1374 行）

**不拆原因**：Kotlin `object`，方法呈递归下降解析器网络——`parseJoin` 调用 `parseOnConditions`，后者调用 `parseCondition`，后者调用 `parseColumnRef`/`parseBinary`/`parseIn` 等。拆分边界切不断调用网，且 `Cursor` 类是 private inner class，拆出方法需改为同包 internal。

**可行的后续优化**：
- 末尾数据类（`SqlReverseResult`/`SelectColumn`/`ReverseJoin` 等）已独立在文件底部，可提取到 `model` 包（零风险但收益小）
- 按语句类型（SELECT/UPDATE/DELETE/INSERT）拆为独立 object（需 Cursor 可见化 + 大量方法 internal 化）

## 第二轮（T-M53-II，2026-10-10 立项）

- 占号：O-142/R88/D148~D149/V171~V172（引用前已实测未占用）
- 来源：T-RepoLayout（O-138）§六 C④ 登记项
- 立项理由：首轮只拆了 `SqlPreviewServiceTest.kt`，其余候选经评估暂缓；**此后文件继续增长**——`SqlPreviewPanel.kt` 从首轮时的 1775 行涨到 5991 行（3.4 倍），`DataSourceSelector.kt` 等新晋 4000+ 行。首轮「收益小/风险高」的判断需要按新体量重估。

### 红线（最高优先级，一票否决）

- **拆分后不允许出现任何回归问题**：所有既有功能的行为、输出、边界处理与拆分前**完全一致**。本轮唯一目的是文件组织，不接受任何「顺手优化」「顺带修复」——只要行为有变化即判不合格。
- **不允许影响之前的功能**，具体到四条硬约束：
  1. 方法体/函数体**逐字符原样搬运**（沿用首轮做法，用脚本对账，不手改一字）；
  2. **不改变类名、方法签名、可见性**——除非拆分必需，且必须同步全部引用点；
  3. **不动 `plugin.xml` / EP 注册 / 反射入口涉及的符号名**（这些是平台与运行时按名寻址的，改名即断）；
  4. **测试缝保持可达**（`xxxForTest()` 等既有测试直访私有状态的入口不得因拆分失效）。
- **一票否决**：任一被拆文件对应测试出现红（含既有 flaky 的复现），**立即回退该文件拆分**，不得带红提交、不得以「与本次无关」放行。
- **验证须是「拆前拆后对照」，不是「拆后绿」**：同一测试集在拆分前后的读数必须一致——**用例数、通过数、失败数三者相同**。用例数减少即判回归（漏搬用例）。

### 方案与决策点

- **D1（先测试后生产）**：测试类拆分沿用首轮已证形态（按连续区间 + 主题拆为多个独立测试类，样板方法复制，方法体逐字符原样搬运，零逻辑改动），风险低、收益直接（token 读取量）。**优先拆测试**。
- **D2（生产 God 面板用「按 UI 区域抽子面板」而非「切方法网」）**：`SqlPreviewPanel` 这类首轮判为「状态字段交叉使用、拆分改类结构」的，第二轮改走**组合式抽取**——把工具栏/参数区/编辑器区/状态区各自抽成内部子面板类，状态留在外壳、通过构造参数或回调传入。**不切递归解析器的方法网**（`SqlReverseParser` 类，首轮结论仍成立）。
- **D3（一次一个文件、独立提交、逐文件回归）**：每个文件拆分单独提交 + 该文件对应测试类定向回归，禁止一次性大重构。
- **D4（红线：不改行为）**：所有拆分以「零行为变更」为红线，方法体逐字符搬运；涉及生产码的拆分须补/跑该模块定向测试。
- **D5（收益门槛）**：单文件拆分后最大子文件建议 < 1500 行；低于此收益不明显的文件（如 1000~1200 行的测试类）可延后。

### 待验证前提

- **P1**：`SqlPreviewPanel` 等 God 面板的 `xxxForTest()` 测试缝在子面板抽取后仍可达（首轮已记录测试依赖 18 个 `xxxForTest()` 直访私有状态）——须先盘点测试缝，再定抽取边界。
- **P2**：`BannedApiSourceScanTest.kt`（2825 行）是**守卫扫描类测试**，拆它前须确认其扫描逻辑（文件遍历/白名单）不依赖「同类内相邻方法」的隐含假设。
- **P3**：拆分只动文件组织，`plugin.xml`/EP 注册/反射入口不受影响（若某类名被反射引用，改名会破坏——拆分保留原类名或同步改引用）。
