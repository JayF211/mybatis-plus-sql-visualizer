# T-JumpPath：多模块工程拦截器标记路径解析缺失与捕获自位污染修复

- 立项日期：2026-09-14
- 任务性质：用户真机缺陷反馈（T-JumpCapture 上线后首个多模块真机场景实锤三缺陷）
- 反馈来源：用户多模块工程（demo 聚合项目 4 个 Maven 模块）——SQL 日志条目带位置 `[SqlSourceInterceptor.java:62]` 但跳转弹「源码文件未找到：cn/song/mpdemo/config/SqlSourceInterceptor.java（项目结构可能已变更）」；业务代码行 gutter 右键「最近执行记录」弹「未找到该代码位置的捕获记录」
- 目标：拦截器捕获位置必须是真实业务调用点；包式标记路径在单模块/多模块 Maven/Gradle 工程都能解析跳转；源码→日志反向反查在实时捕获下可用；多模块工程可经插件按模块注入，不再依赖手工拷贝

## 二、根因清单

### RC1 捕获自位污染——`isSelf()` 编译期常量脆弱（模板缺陷）

`SourceInterceptorTemplates.generateInterceptorClass` 生成的 `isSelf(cn)` 用**注入期 basePackage 拼出的全限定名常量**做 `equals`。运行类包名与常量一旦分叉（手工拷贝改包、改包重构、跨模块复制），自位跳过失效；`appPackages` 前缀过滤反而放行拦截器自身（它就在业务包内）。栈序 `getStackTrace → emitSource → beforeQuery →（MP/ibatis 框架帧跳过）→ 用户代码`，头两个非框架帧即拦截器自身 → 位置 = `SqlSourceInterceptor.java:62`（恰为拷贝件中 `locateSource` 的 for 循环行号，实锤吻合）。

手工拷贝的诱因在 RC4。**修复方向**：自位判定不得依赖生成期常量，改运行时 `getClass().getName()` 比对（自身帧与其调用帧同类名，一处判定即覆盖）。`docs/instrumentation/SqlSourceInterceptor.kt` 手工示例同样没有自位跳过，一并修。

### RC2 跳转解析失配——`SourcePathResolver` 缺源码根策略（多模块必然 NotFound）

拦截器标记路径 = 包名 + 文件名（`cn/song/xxx/Service.java`），**相对源码根**（`src/main/java`），模板注释与 `SqlSourceMarker` 文档口径一致。现行解析链（`EntrySourceMatcher.kt` 的 `SourcePathResolver`）：

1. 项目根直拼：`<project>/cn/song/...`——不存在；
2. 模块 contentRoots 直拼：Maven 模块 content root = 模块目录，`<module>/cn/song/...` 同样不含 `src/main/java` 段——不存在。

→ **Maven/Gradle 标准布局下拦截器标记路径全形态解析失败**，多模块只是让现象更扎眼。历史面板条目是 `src/main/java/...` 项目根相对形态，走第 1 级能中，所以该缺陷只在实时拦截器条目上暴露。

关键关联：旧 `SqlLogPanel.findSourceFile`（F-44-7 时代，策略 2 即遍历 `ModuleRootManager.sourceRoots`）本已覆盖此形态，但 T-JumpCapture（2c7426c）把它当死代码整族删除，`SourcePathResolver` 未收编 sourceRoots 语义——删除时全仓 grep 零调用属实，语义回收缺口在删除后才被真机暴露。**须把 sourceRoots 遍历策略收回 `SourcePathResolver`**。

### RC3 反向反查失配——三种路径形态未对齐，「最近执行记录」恒空

gutter 反查链（`SqlGutterLineMarkerProvider.showRecentEntriesPopup` → `EntrySourceMatcher.match`）：锚点路径 = 项目根相对（多模块含模块前缀，如 `mybatis-plus-join-demo/src/main/java/cn/song/mpjdemo/...`），条目 `sourceFile` = 拦截器包式路径（相对源码根）。`match` 的 `normalize` 等值比较对「A 是 B 的段对齐后缀」这一形态差无解——即使位置捕获正确，反查依然恒空（本次截图弹框即叠加了 RC1 与 RC3）。

### RC4 注入只认第一模块——多模块工程的能力缺口（RC1 的诱因）

`ProjectTypeDetector` 取第一个含 main 源码根的模块定 basePackage/sourceRoot；`SqlSourceInterceptorAutoInjector` 只注入该模块，`interceptorExists` 也只查该模块。多模块工程想给其它模块启用捕获只能手工拷贝改包——正是 RC1 的触发路径。用户诉求「我是多模块项目」指向的正是这个缺口。

## 四、修复设计

### 4.1 T-JumpPath-01 模板

`emitSource` 前无改动；`locateSource` 帧循环内自位判定替换：

```java
private boolean isSelf(String cn) {
    return cn.equals(getClass().getName());   // 运行时类名，拷贝/改包/改类名均自适应
}
```

不改 `appPackages` 过滤逻辑（它仍负责把调用点限定在业务包，拦截器自身帧由 isSelf 消化）。`SqlVisualizerConfig` 模板无此问题，不动。模板注释「删除后回退表名搜索」旧表述顺带清理（T-JumpCapture 后回退链已删）。

### 4.2 T-JumpPath-02 SourcePathResolver

在现有 contentRoots 段之后追加：

```kotlin
ModuleManager.getInstance(project).modules.asSequence()
    .flatMap { ModuleRootManager.getInstance(it).sourceRoots.asSequence() }
    .map { it.path }
    .firstNotNullOfOrNull { root -> fs.findFileByPath("$root/$rel") }
```

`sourceRoots`（含 SOURCE/TEST 源根）语义与被删 `findSourceFile` 策略 2 对齐；三级顺序天然按精确度递减（项目根全相对 → 模块目录相对 → 源码根相对），三种形态前缀互斥不产生歧义命中。Kotlin/Groovy 源根同被 `sourceRoots` 覆盖。历史面板 `HistorySqlLogPanel.resolveJumpTarget` 与实时 `SqlLogPanel.resolveEntryJump` 共用本解析器，一处修复双面板受益。

### 4.3 T-JumpPath-03 EntrySourceMatcher

`match` 内 `normalize(it.sourceFile) == key` 改为后缀互含判定（抽 `internal fun sameFile(a, b)` 便于表驱动单测）。段对齐（以 `/` 为界）杜绝 `mpjdemo` 误配 `ampjdemo` 类假命中；两形态本就是同一文件的不同长度前缀，语义安全。反向（源码→日志）与正向（日志→源码，RC2）解耦：正向靠解析器定位文件，本任务只保反查匹配。

### 4.4 T-JumpPath-04 多模块注入

- `ProjectTypeDetector`：新增 `detectAll(modules)`，逐模块判定 `ProjectStructure`（无 MP 依赖模块判 UNSUPPORTED 跳过，如 jpa-hibernate-demo）；保留单模块入口供既有调用方。
- `SqlSourceInterceptorAutoInjector`：`injectAsync` 改为逐「支持的且未注入过的」模块执行既有单模块注入链（各模块用自己的 basePackage/sourceRoot）；聚合结果：
  - 全部已存在 → AlreadyExists；
  - 至少一模块新注入成功 → Success（消息含成功模块清单，i18n 三参形态扩展为模块数+文件+包名摘要）；
  - 无支持模块 → UnsupportedProject；检测/写入失败并入消息。
- `SourceCaptureGuide.showInjectionResult` 与设置页勾选回滚读聚合结果，语义不变（成功=有任一模块新注入）。
- 边界：聚合消息为多行 i18n，新增键双语 parity；`interceptorExists` 按模块源根判定（现有实现天然支持，传对应 sourceRoot 即可）。

## 七、风险与留观

- 弹框路径 `cn/song/mpdemo/...` 与 demo 仓库实锤类包 `cn.song.mpjdemo` 差一字母 j，全仓 grep 无 `cn.song.mpdemo`——或为用户本地变体包名或显示截断；两形态下根因链完全相同（行号 62 + isSelf 常量分叉均在案），不影响修复有效性。
- RC2 属 T-JumpCapture 删除 `findSourceFile` 时未回收 sourceRoots 语义的缺口收编，本计划在案；`SqlTableExtractor` 零消费方留观不变。
- 已注入旧模板的用户工程不会自动更新 `isSelf`（模板只在生成期生效）：引导弹框「立即注入」对已存在文件是 AlreadyExists 短路。是否提供「升级已生成文件」能力未在本期范围，视用户反馈另行立项。
