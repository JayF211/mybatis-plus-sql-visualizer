## 1. 实证结论（已逐项核实）

| 项 | 结果 |
|---|------|
| 生成代码在 MPJ 1.5.6 + MP 3.5.14 下 javac | **编译通过**（wrapper 链构造/select(SFunction...)/eq/selectPage 全部存在，普通 mapper 与 MPJBaseMapper 两个场景实测） |
| MPJ 1.5.6 `MPJBaseMapper` 源码 | `extends BaseMapper<T>, JoinMapper<T>`——selectPage 从 BaseMapper 继承（core 源码实证） |
| MPJ 1.4.13 `MPJBaseMapper`（central 最新稳定版） | `extends BaseMapper<T>`——selectPage 继承（javap 实证） |
| **用户项目 MPJBaseMapper** | **无 selectPage**（用户 IDE 实证）——用户项目 MPJ 依赖与 1.4.13/1.5.6 实证结构不同（版本/坐标差异无法穷尽） |

**结论**：不能假设调用类有 BaseMapper/IService 的普通方法——**必须按调用类继承链的真实方法集选择调用方法**（插件现有 `invocationHasMpj` 反查先例可扩展）。

## 2. 方案设计

### 2.1 方法集反查（`reverse/SqlToJavaConverter.kt`）

```kotlin
/** 调用类继承链方法名集合（接口 default 方法含父接口；this/baseMapper 特殊值无法反查返回空）。 */
fun invocationMethods(project: Project, callerClass: String): Set<String> {
    if (callerClass.isBlank()) return emptySet()
    if (callerClass == "this" || callerClass == "baseMapper") return emptySet()
    val clazz = PsiShortNamesCache.getInstance(project).getClassesByName(callerClass, GlobalSearchScope.projectScope(project))
        .firstOrNull() ?: return emptySet()
    return collectMethodNames(clazz, mutableSetOf())
}

private fun collectMethodNames(clazz: PsiClass, seen: MutableSet<PsiClass>): Set<String> {
    if (!seen.add(clazz)) return emptySet()
    return clazz.methods.map { it.name }.toSet() +
        clazz.interfaces.flatMap { collectMethodNames(it, seen) } +
        (clazz.superClass?.let { collectMethodNames(it, seen) } ?: emptySet())
}
```

（须 ReadAction 内调用——与 invocationHasMpj 同块，面板 `SqlToJavaPanel.convert` 的 ReadAction 计算处一并获取）

### 2.2 能力透传（`reverse/JavaCodeGenerator.kt`）

`InvocationTarget` 加字段：`val methods: Set<String> = emptySet()`（调用类方法集；空 = 特殊值/类不可解析 → 用普通方法保守生成）。

### 2.3 方法选择回退链（`selectInvocation`/update/delete）

`private fun InvocationTarget.prefer(primary: String, vararg fallbacks: String): String = if (methods.isEmpty()) primary else (listOf(primary) + fallbacks).firstOrNull { it in methods } ?: primary`

| 场景 | 优先 | 回退 | 依据 |
|---|---|---|---|
| mapper 分页 | `selectPage` | `selectJoinPage(page, Class, wrapper)` | JoinMapper.selectJoinPage（1.4.13/1.5.6 实证） |
| mapper 列表 | `selectList` | `selectJoinList(Class, wrapper)` | JoinMapper.selectJoinList |
| service 分页 | `page` | `selectJoinListPage(page, Class, wrapper)` | JoinService.selectJoinListPage |
| service 列表 | `list` | `selectJoinList(Class, wrapper)` | JoinService.selectJoinList |
| mapper UPDATE | `update(null, wrapper)` | `updateJoin(null, wrapper)` | JoinMapper.updateJoin(T, MPJBaseJoin) |
| mapper DELETE | `delete(wrapper)` | `deleteJoin(wrapper)` | JoinMapper.deleteJoin(MPJBaseJoin) |
| service UPDATE | `update(wrapper)` | `updateJoin(null, wrapper)` | JoinService.updateJoin(T, MPJBaseJoin) |
| service DELETE | `remove(wrapper)` | `deleteJoin(wrapper)` | JoinService.deleteJoin(MPJBaseJoin) |
| INSERT | `insert`/`save`/`saveBatch` | 无 join 对应，保持 | — |

注意参数形态差异：join 回退方法多为 `(page, Class, wrapper)` 三参或 `(Class, wrapper)` 两参——回退时泛型参数用当前实体（entityName）或 VO（voQuery 场景已有 selectJoinPage 三参形态）；UPDATE/DELETE 回退时实体参数用 null（对齐现有 update(null, wrapper) 形态）。

VO 查询（selectJoinList/selectJoinPage 必须）场景：方法集不含时**明确报错**（现有 mpj=false 报错逻辑增强——"调用类无该方法"）。

### 2.4 边界

- `this`/`baseMapper` 特殊值：无法反查 → methods 空 → 普通方法（现状）；用户后续若在特殊值场景遇同问题，可引导改选真实类名（类名可反查）；
- 类名反查失败（拼写错误/未导入）：methods 空 → 普通方法（现状，文档化）；
- 分页+VO：`selectJoinPage(page, Vo.class, wrapper)` / `selectJoinListPage(page, Vo.class, wrapper)`（MPJ 独有，方法集不含时报错提示）。
