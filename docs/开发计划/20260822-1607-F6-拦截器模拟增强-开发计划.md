## 0. 目标

增强现有拦截器模拟能力，让预览 SQL 更接近真实运行时效果。覆盖 TenantLine（完善）、DynamicTableName（新增）、DataPermission（占位提示）、BlockAttack（标记）。

**用户价值**：真实项目几乎必用拦截器，不含拦截器的预览与运行时 SQL 存在语义差异。

## 2. 功能设计

### 2.1 TenantLine 增强

**现状**：仅追加 WHERE 条件 `AND tenant_id = ?`。

**增强**：
- INSERT 语句：追加 `tenant_id` 列 + 值（配置的 tenantColumnName + 占位值）
- UPDATE 语句：追加 `tenant_id` SET（如果是 `updateEntity` 场景）
- 配置扩展：
  ```kotlin
  // PluginSettings 新增
  var tenantColumnDefault: String = "1"  // tenant_id 默认值
  var injectTenantOnInsert: Boolean = true  // INSERT 也追加
  ```

### 2.2 DynamicTableName 模拟

**场景**：MP 的 `DynamicTableNameInnerInterceptor` 运行时动态替换表名（如 `order_2024` → `order_202401`）。

**方案**：
- 设置页新增「动态表名映射」规则列表（正则 → 替换模板）
- 预览时按规则替换表名
- 支持 `${tableName}` 变量引用原始表名

**配置示例**：
```
规则1: user_(\d+) → user    (分表合并查询)
规则2: order → order_${yyyy}  (按年分表，需用户填写实际值)
```

**实现**：
```kotlin
// PluginSettings 新增
var dynamicTableNameRules: List<TableNameRule> = emptyList()

data class TableNameRule(
    val pattern: String,      // 正则
    val replacement: String,  // 替换模板
    val enabled: Boolean
)
```

### 2.3 DataPermission 占位提示

**场景**：DataPermissionInterceptor 运行时根据用户角色动态追加条件，无法静态模拟。

**方案**：
- 设置页新增「数据权限提示」开关
- 开启后，预览 SELECT/UPDATE/DELETE 时在警告区显示：
  > ⚠ DataPermissionInterceptor 会根据用户角色动态追加条件，预览可能与运行时存在差异
- 提供占位条件输入框（用户可手动填写模拟条件）

### 2.4 BlockAttack 标记

**场景**：BlockAttackInnerInterceptor 阻止无 WHERE 的 UPDATE/DELETE 和全表 UPDATE。

**方案**：
- 现有「⚠ 无 WHERE 条件」警示已覆盖核心功能
- 增强：标记为 BlockAttack 风格（更醒目的红色 + 拦截器名称标注）
- 新增 `DataIntegrityViolation` 检测：SET 所有列但无 WHERE

## 7. 边界与降级

- DynamicTableName 规则正则编译失败：跳过该规则，日志警告
- TenantLine 表已有 tenant_id 条件：不重复追加
- 拦截器叠加顺序：TenantLine → DynamicTableName → 逻辑删除 → 乐观锁
