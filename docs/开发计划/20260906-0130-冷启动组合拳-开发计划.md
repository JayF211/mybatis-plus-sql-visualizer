## 1. 问题

第二轮报告 §5.1 的判断：功能密度已是赛道第一，市场存在感是零（110 下载、0 评论），本任务补分发侧的三件事——

1. **渠道版本分叉风险**：Marketplace API 返回本插件 `hasUnapprovedUpdate=true`（第二轮报告 §3.1 主表行、§6.3）。本地已知最新上架版是 v2026.9.4（`update/update.json` 与 `update/preview.update.json` 均为 2026.9.4），待审核的是哪次上传、是否预期，目前无人能答；长期滞留会让 Gitee 抢先体验通道与 Marketplace 正式渠道版本对不上。发布流程文档（`docs/发行说明/Marketplace发布流程-说明文档.md`）从上传到上架后检查（§10）没有任何一步要求确认审核状态。
2. **首屏没把王牌亮出来**：JPA 是全市场竞品评论区点名率最高的求而不得（第二轮报告 §4.6），IDE 全版本兼容是对全市场第一抱怨（§4.1）的正面回答，但两句话都不在首屏——README.md 第 1~14 行的引言与能力全景里，JPA 只在「编码期」长句中出现一次，「支持 IDEA 2024.3 及以上版本」埋在第 14 行改名说明段落的末尾；`docs/发行说明/marketplace-custom-page.html` 的 `<body>`（第 140 行）之后直接进 `<h2 id="features">Feature Matrix`（第 143 行），没有首屏定位段，JPA 只是功能矩阵一行（第 176 行），兼容信息埋在 FAQ（第 316~320 行）。竞品侧 MyBatis Log Free 用户 2025-10 的「如果能支持 jpa 就好了」看到的不是我们。
3. **110 下载、0 评论的冷启动死结**：评论大盘死寂意味着自然口碑流转更慢（第二轮报告 §6.2）。Gitee 抢先体验通道（内测用户）是最贴近的一批真实用户，目前没有任何一处引导他们去 Marketplace 页评分留言。

## 2. 方案

三件事全部是市场动作与文档改动，不改任何生产代码。

### 2.1 审核状态确认（运营动作 + 发布流程补一步）

**确认动作**：登录 Marketplace 作者后台（plugins.jetbrains.com/author/me）→ My Plugins → SQL Visualizer → 版本列表，核对处于 Pending 状态的更新是哪个版本号、哪天上传的什么包，二选一处置并留档结论：

- 预期内的新版本 → 核对 changeNotes 与 Gitee 通道内容一致，等审核放行；
- 误传/过期/内容不明的包 → 后台撤回，消除与 `update/update.json`（2026.9.4）的版本分叉。

**发布流程文档落点**（已逐节探查两个文档）：

- `docs/发行说明/Marketplace发布流程-说明文档.md` **§10.2「日常版本更新流程」**：流程表「Marketplace 上传」行之后插入一行「审核状态确认」（后台核对 Pending 版本号与内容，放行或撤回），同节 mermaid 图在 `M`（Marketplace 上传）节点后补确认节点；**§11 发布检查清单**追加第 12 条「上传新版后后台确认审核状态（Pending 清零或结论留档）」。
- `docs/发行说明/版本号规范-说明文档.md` 经全文核对（§1~§7 均为版本号位置/格式/发布规则/SemVer 合规/注入方式/里程碑解耦/CHANGELOG 同步），**不含发布流程步骤，本次不改**。

### 2.3 第一批评论引导（不弹窗导流）

探查结论：更新通知正文由 `StartupUpdateCheck.notificationContent`（`src/main/kotlin/cn/song/mybatisplus/visualizer/update/StartupUpdateCheck.kt` 第 162~180 行）从清单 `changeNotes` 逐行渲染成有序列表（最多 8 条、单条 60 字截断），而 `changeNotes` 是 `writeUpdateManifest` 任务生成后**人工补充**的字段（`build.gradle.kts` 第 346~371 行，注释明示「changeNotes 生成后人工补充」，草稿写 `update/preview.update.json`、发布时复制到 `update/update.json`）。因此引导话术**零代码改动**即可上线：

- **落点一（更新通知文案）**：下一次内测版生成清单时，在人工补充的 changeNotes 末尾加一行 ≤60 字的中性引导，例如「好用的话，欢迎到 Marketplace 页评分留言（搜 SQL Visualizer）」，随既有的发现更新通知自然下发；通知末尾已带 Gitee 发布页链接（bundle 键 `update.notification.viewGitee`），不新增任何通知/弹窗代码。
- **落点二（README）**：第 78~80 行「检查更新（Gitee 抢先体验通道）」节补一句引导：内测用户若觉得好用，欢迎到 Marketplace 插件页（plugins.jetbrains.com/plugin/33633-sql-visualizer）评分留言；并提示迁移路径（发布流程 §10.3：内测磁盘安装不收市场自动更新，在 Marketplace 搜索页点一次 Update 即完成迁移+自动更新接管——到页面这一步顺手评分，正好是转化点）。

红线（承接第二轮报告 O-7）：引导只骑「既有更新通知出现时」与静态文档两个载体，不做启动弹窗、不做频率提醒、不做物质激励。

## 5. 风险

- Pending 审核的原因与内容无法从 API 判断，只能后台人工核对；撤回动作不可逆，处置前对版本列表截图留档。
