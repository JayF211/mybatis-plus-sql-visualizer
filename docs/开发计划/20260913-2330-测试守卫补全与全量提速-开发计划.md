# T-TestGuard / T-TestPerf：测试守卫补全与全量提速开发计划

> 立项：2026-09-13。用户需求原话：「插件开发过程中，经常有一些问题无法通过测试用例复现，例如 UI 相关交互等——分析踩坑记录和记忆，全方面补充一次测试用例，并想办法缩短全量测试用例运行时间提效。」

## 二、方案设计

### A. 约定守卫测试族（把「无法复现的 UI 坑」变成结构性断言）

守卫测试全部为纯逻辑/headless 可跑，不增加平台 fixture 负担。每条规则注释注明出处坑档，失败信息给出修复指引。

**G1 bundle 完整性守卫**（新 `i18n/BundleParityGuardTest.kt`）
- 中英 bundle key 集合双向全等（缺键打印完整清单，拦 m41 族）。
- 两份 bundle 值中的占位符必须全部匹配 `\{\d\}`（拦 `__URL__` 自定义占位符）。
- 扫描 src/main 源码中 `MpSqlVisualizerBundle.message("...")`/`messageOrDefault` 的字面量 key，断言键存在于 bundle（拦拼错键静默回退）。

**G2 plugin.xml 结构守卫**（新 `config/PluginXmlStructureGuardTest.kt`，读取 classpath plugin.xml、剥注释后断言）
- 不含 `<listener topic=`（平台不支持，须 messageBus 编程注册）。
- 每个 `<action` 元素必须有 `class=` 属性（缺 class 整插件加载失败）。
- `<description>` 不含 `src="http` 外链图（Marketplace 302 防盗链）。
- 不存在 `<projectConfigurable`（防与 applicationConfigurable 同名套娃；未来真需要分区设置时本守卫连带改造，注释说明）。
- `completion.contributor` 必须带 `language=` 属性（全语言注册静默失效）。
- `notificationGroup` 不含 `displayName=` 属性（分组显示名走 bundle key）。
- `<toolWindow>` 不含 `title=` 属性（不支持，stripe 名须 Factory.init 里 setStripeTitle）。

**G3 禁用 API 源码扫描守卫**（新 `convention/BannedApiSourceScanTest.kt`，walk src/main/kotlin）
- `updateActionsAsync(`/`updateImmediately(` 禁用（ActionToolbar 刷新 API 沙盒不可靠）。
- `ContentManagerListener` 禁用（243 实证完全不可用，检测靠轮询）。
- IPGP 裁剪平台类禁 import：JBIconButton、SmallIconButton、IconUtil（名单可追加）。
- 含 `BrowserUtil.browse(` 的文件必须同时含 `isUnitTestMode` 短路（防测试沙盒弹真机浏览器）——本守卫落地同时**修复现存三文件四处**（UpdateSection.kt、FeedbackReporting.kt、ErrorReportDialog.kt）。
- `setStripeTitle(` 只允许出现在 ToolWindowFactory 实现文件内。
- `createFileFromText(` 调用点所在文件必须含 `ReadAction`（262 EDT read access 硬抛防护）。

**G4 死测试复活**：SqlAutoFoldPlannerTest 14 方法补 @Test 注解，逐个跑通（若暴露 planner 真实缺陷则甄别修复）。

**G5 无守卫逻辑缺口**（按既有测试风格补用例）
- exists 裸链实参：`service.exists(new LambdaQueryWrapper<E>().exists("id = {0}", 1))` 与 `.exists(cond).eq(...)` 中间段不被误判终结点（挂 SqlPreviewService 端到端系）。
- JSON 参数格式化：数值形态字符串保持引号不丢（SqlLogParamCodec 侧）。
- settings 引用替换：`panel.apply()` 后 `PluginSettings.state` 引用身份变化（assertNotSame，拦 loadState(s.copy()) 被 refactor 掉）。

**G6 渲染器防回退守卫**（集中一条，T-LogListFreeze 家族收口）：SqlLogPanel 与 HistorySqlLogPanel 的 SQL 列表 renderer 必须是本插件 SimpleColoredComponent 系内部类、`fixedCellHeight > 0`（拦 JLabel-HTML 逐行解析 + 可变行高 O(N²) 测量的 EDT 冻结回退）。

**G7 零覆盖区补测**（行为级，能 headless 的才做，平台强耦合的记录后跳过）：按零覆盖 14 类逐个读码，纯逻辑面直接补（ProjectTypeDetector/SqlTokenizer/TokenParser/DynamicContext/PsiDialect/SourceInterceptorTemplates/UpdateWrapperConverter/UpdateDeleteStatement 等）；弹窗与 action 类测数据装配与状态机（ErrorReportDialog 参数装配、FeedbackReporting 回执状态、两个 GenerateCrudSql action 的 update() 判定与表名提取）；每类 2~6 用例，总量控制在 ~100 用例内。

### B. 提速族

**P1 build cache 收口**：gradle.properties `org.gradle.caching=false` + 注释注明三次实证根因。增量编译不受影响（缓存只影响「复用历史产物」），彻底消除「忘带 --no-build-cache → 成片 NoSuchMethodError → 整轮重跑」的最大隐性耗时。同步修订各文档中「必须 --no-build-cache」的惯例表述。

**P2 网络型慢测试解耦**：定位全量中触网用例（历史记录 UpdateSectionTest 时代 32s/gitee 302 超时；grep src/test 中 gitee.com 直连点），改为本地 HttpServer stub 或无网 Assume 跳过，消除外网波动拖累与 flake。

**P3 纯逻辑快测分桶 `testFast`**（实证驱动，两步走）：
1. 注册 `testFast` Test 任务：配置期扫描 src/test/kotlin，按「源码是否含 BasePlatformTestCase/HeavyPlatformTestCase」自动分桶（零手工白名单），纯逻辑桶 `maxParallelForks = 4`（无沙盒共享，fork 并行安全），同样排除 3 个 DB 集成类。
2. 默认 `test` 任务反选平台桶。两任务同项目串行执行（Gradle 限制），总时长 ≈ 平台桶 + 纯逻辑桶/4；额外红利是平台桶 JVM 独立、长跑泄漏压力更小。
3. 先小样实验验证自定义 Test 任务在 IPGP 2.18 下的 bootstrap（平台类在 runtimeClasspath 可见即可，纯逻辑桶不需要平台测试框架 bootstrap）；不通则降级为「默认 test 直接 maxParallelForks 实验」并验证沙盒共享是否安全，两条路都实证后取可行者。

**P4 testShards 白名单自动分区**：shard1/2 的 include 白名单改为配置期扫描 src/test 自动均分（类名哈希），消除「新增测试类不进分片」的漂移陷阱；注释修正为 2 片事实与双开终端用法。

### T-TestPerf-03 实验结论（不交付并行分桶，证据驱动否决）

三轮实证全部记录在 build.gradle.kts 注释：

1. **平台测试不能 fork 并行**：默认 test 任务 `maxParallelForks=4` 实测成片 `PersistentFSConnector` 异常——多 worker 共享默认 test 沙盒互踩（与分片任务注释「191 失败」同根因先例）。平台桶保持串行。
2. **纯逻辑分桶技术上可行**（三个坑都趟过：classpath 须复用默认 test 任务成品——IPGP 把平台 jar 直配任务不进 sourceSets.runtimeClasspath；排除须统一走 filter 机制——legacy exclude 与 filter 混用时 filter 优先级覆盖 exclude、159 条 exclude 全被忽略；自动识别按源码含 BasePlatformTestCase/HeavyPlatformTestCase 判定）。
3. **但正确性否决**：2246 个纯逻辑分类用例中 **68 个（forks=1 对照同败，排除并行争用）隐性依赖同 worker JVM 里平台测试先建立的 Application/LaF 状态**，脱离平台桶即红——作为快测任务会持续误报，属「测试隐性顺序耦合」债务，清偿需逐用例补平台引导，超出本次范围。已撤销该任务，结论沉淀于 build.gradle.kts。
