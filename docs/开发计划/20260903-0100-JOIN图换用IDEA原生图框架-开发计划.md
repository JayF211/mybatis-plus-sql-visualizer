# JOIN 图换用 IDEA 原生图框架 开发计划

> 源自 2026-09-03 会话调研《IDEA 图框架（类图/关系图内核）复用可行性》（反编译 ideaIU-2024.3.7.1 + JetBrains 官方论坛确认，证据链见项目记忆 `project-idea-diagram-framework.md`）。
> 分支：`feature/join-diagram-native-framework`。
> 范围：预览面板 JOIN 图标签页的渲染层替换（`ui/diagram/`），不改 `JoinDiagramGenerator` 的 SQL 解析语义与「无 JOIN 不出现标签页」交互。

## 背景与结论

现有 JOIN 图为自绘 Swing 引擎（DiagramPanel 261 行 + DiagramRenderer 779 行），缩放/布局/导出/右键全部手维护，真实截图仍有标签重叠遗留问题。调研确认 IDEA 类图/数据库表关系图/EXPLAIN 计划图共用的图框架可供第三方插件复用：

- 渲染内核（`com.intellij.openapi.graph.*`）在平台核心 `lib/app.jar`，全 IDE 可用。
- 图框架 API（`com.intellij.diagram.*`）在捆绑插件 `com.intellij.diagram`（"Diagrams"，`plugins/uml/lib/uml-support.jar`），Ultimate 捆绑；本插件已依赖 `com.intellij.database`（Ultimate-only），兼容面不变。
- 扩展点 `com.intellij.diagram.Provider`；DatabaseTools 的 `QueryPlanProvider`（EXPLAIN 计划图，纯数据模型无 PSI 依赖）是最佳参照。
- 打开路径（字节码实证）：`UmlVirtualFileSystem.findFileByPath("<providerId>/<fqn>")` → `FileEditorManager.openFile()`。
- 非公开契约：无稳定性承诺，API 面集中封装在适配层；jar 内 `com.intellij.diagram.v2.dsl`（新 DSL）本计划不碰。

## 目标

JOIN 图渲染换用 IDEA 原生图框架，获得缩放/平移、自动布局、节点折叠、右键菜单、内容类别开关（列/主键显隐）、导出（图片/Mermaid/PlantUML）等全套框架能力，消除自绘布局重叠问题。`JoinDiagramGenerator` 解析逻辑与预览面板交互不变，旧自绘面板以设置项开关过渡一个版本。

## 任务

### T-Dgm-01 最小 PoC：打通 openFile 链路（风险收敛点）

- 最简 `SqlJoinDiagramProvider : DiagramProvider<TableElement>`：两张静态表 + 一条 JOIN 关系线，`getID` / `getPresentableName` / `createDataModel` / `createVisibilityManager` / `getElementManager` / `getVfsResolver` / `getRelationshipManager` 全部最小实现。
- `build.gradle.kts` 增加 `bundledPlugin("com.intellij.diagram")`。
- runIde 真机验证三件事：`UmlVirtualFile` 构造与 `openFile` 打开、节点/边渲染、自动布局引擎正常。
- PoC 通过后才进入后续任务；失败则记录字节码偏差，回炉调研。

### T-Dgm-02 模型适配层

- 复用 `JoinDiagramGenerator` 输出（`DiagramModel` 中间模型不动），新增 `JoinDiagramModelAdapter` 把实体/关系适配为框架模型。
- 节点：`DiagramNodeBase<TableElement>`，列作为 node items，`DiagramNodeContentManager` 类别实现「列 / 仅主键」显隐开关（样式参照反编译 `DbDiagramElementManager`）。
- 边：`DiagramEdgeBase` + `DiagramRelationshipInfo`，JOIN 类型映射箭头样式，ON 条件作为关系标签。
- 主表/JOIN 表区分沿用现有配色语义（isMain）。

### T-Dgm-03 Provider 完整实现与注册

- `DiagramElementManager`：标题（displayName）、图标、tooltip（表名+别名+JOIN 类型）。
- `DiagramVfsResolver`：以「表名(别名)」为 FQN 的轻量解析，不解析 PSI。
- `plugin.xml` 注册 `com.intellij.diagram.Provider` EP（注意 bundle+key 命名约定）。
- i18n 双语：图例、类别名、右键菜单相关文案。

### T-Dgm-04 集成到预览面板

- JOIN 图标签页改为嵌入框架 `DiagramBuilder` 组件（保持现有标签页出现/移除时序，`refreshAfterVisible` 等交互语义对齐）。
- `UmlVirtualFile` + `openFile` 作为「独立标签页打开」入口（备选弹层模式，视 PoC 结果取舍）。
- fail-safe：Diagrams 插件异常缺席时 try/catch 降级回现有自绘 `DiagramPanel`。
- 设置项「JOIN 图渲染方式：原生框架（默认）/ 经典（自绘）」，过渡期并存。

### T-Dgm-05 测试与视觉验证

- 模型适配层 fixture 风格纯单测（实体→节点 items、JOIN 类型→关系样式映射、FQN 往返解析）。
- fail-safe 降级路径单测（模拟 Provider 缺席）。
- 真机截图验证（铁律）：runIde 下多表 JOIN（含 3+ 表、别名≠表名、长列名）截图确认无标签重叠、布局可读，对比自绘版效果留档。
- 既有 diagram 包测试全绿；全量回归按并行铁律登记后跑。

### T-Dgm-06 收尾

- 旧 `DiagramRenderer` 标记 deprecated（保留一个版本，下版本删除）。
- CHANGELOG、`docs/变更记录.md`、发行说明三处同步；`project-idea-diagram-framework.md` 记忆补充实施结论。

## 风险与对策

| 风险 | 对策 |
|------|------|
| 非公开 API，262 平台可能演进 | 编译基线锁定 2024.3.7.1；API 调用集中适配层；升级 IDE 时 runIde 回归 JOIN 图 |
| 类图「类框」观感不完全等同 | 数据库图已证明「表+列清单」样式成熟；T-Dgm-05 真机截图对比验收 |
| Diagrams 插件缺席/异常 | try/catch 降级回自绘面板（T-Dgm-04） |
| 沙盒跑旧代码假象 | `--rerun-tasks` + grep jar 内 class 验证（铁律） |

## 并行隔离（铁律）

- 跑任何 `./gradlew` 前先 `python C:\Users\USER\.zcode\cli\parallel_tasks.py check`；有活跃任务则 `register --name "JOIN图原生框架" --sandbox <独立沙盒>`，跑完 `done`。
- 本任务在独立分支/沙盒进行，提交只含本任务文件。
