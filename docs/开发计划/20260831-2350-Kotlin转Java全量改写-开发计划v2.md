## 3. 转换策略（修订）

### 3.1 总体方针
**增量共存式迁移**（推翻 v1 的原子切换）：
1. 在 `feature/kotlin-to-java` 分支，单个 Kotlin 文件 → 同包 Java 文件 → 删除 `.kt` → 该模块编译+测试绿 → commit。
2. Kotlin/Java 在同 source set 共存期间，互相引用天然成立（`internal` 字节码为 public，Java 可访问），无需任何桥接。
3. 全程 `./gradlew compileKotlin compileJava test` 保持绿，可随时暂停/回退到任意 commit。

### 3.2 工具链
- **首轮**：IntelliJ `Convert Kotlin File to Java` 逐文件生成初稿（保留结构）。
- **次轮**：人工精修（data class 重写、null 安全补充、scope 展开简化、sealed/switch、移除 synthetic bridge）。
- 不引入自动翻译器（如 Shoal/J2K 反方向不适用）；保持人审。

### 3.3 Data Class 三档（**已决策（00:10 修订）：允许 Lombok；用 `record` 时必须为每个字段写注释**）

| 档 | 条件 | Java 方案 | 文件估算（实测分布） |
|----|------|----------|----------------------|
| ① 纯数据载体 | 全 val、无继承、无逻辑 | `record`，**每个组件须写 `@param` 字段注释**（保留原 data class 属性文档） | 约 90（model 41 + 部分 psi/xml/log） |
| ② 含 var/少量方法 | mutable 或 1-2 方法 | `Lombok @Data`/`@Value` 或 手写 POJO（二选一；见 delombok 约束） | 约 66 |
| ③ 继承/复杂逻辑 | 继承、业务方法 | 手写 POJO（Lombok 对超类 equals/hashCode 需 `@EqualsAndHashCode(callSuper=true)`，或直接手写更稳） | 约 26 |

#### 注释强制约定（档① record 必遵）
Kotlin data class 的属性 KDoc 必须平移为 Java `record` 的 Javadoc 组件注释，禁止「裸字段」：
```java
/**
 * SQL 条目（日志还原结果）。
 *
 * @param rawSql    原始带 ? 占位符的 SQL
 * @param params    参数值列表（与 ? 顺序对应）
 * @param sourceFile 触发该 SQL 的源文件相对路径，无则 null
 */
public record LogSqlEntry(String rawSql, List<String> params, String sourceFile) {}
```
> 若原 Kotlin 属性无注释，转换时须补一句语义说明，不允许留空——这是本计划对可维护性的硬约束。

#### Lombok 使用约束（档②/③）
- **已批准使用**，但须在 **阶段 0** 完成 delombok 预验证：IntelliJ Platform 插件运行时不含 Lombok，必须在编译期 delombok（推荐 `io.freefair.lombok` Gradle 插件，或手动 `delombok` task），使 `runIde` 沙盒与 `verifyPlugin` 在无 Lombok 依赖下通过；**预验证未通过前，任何文件不得用 Lombok 注解**。
- 配合 `lombok.addLombokGeneratedAnnotation = true`，避免 Lombok 生成的方法干扰 IDE 结构与 Verifier。
- 与现有 3 个手写 Java 文件（无 Lombok）共存无碍，仅要求新增 Lombok 类风格统一。

### 3.4 Null 安全统一工具类
新建 `util/Nulls.java`：
```java
public final class Nulls {
    public static boolean isNullOrBlank(String s){ return s==null || s.isBlank(); }
    public static boolean isNullOrEmpty(String s){ return s==null || s.isEmpty(); }
    public static <T> T orElse(T v, T d){ return v!= null ? v : d; }
    private Nulls(){}
}
```
所有 `?.`/`?:`/`isNullOrX` 优先经此收敛，降低 NPE 回归面。

### 3.5 Sealed / When
`sealed class X` + `permits A,B,C`；`when(x)` → `switch(x)` 表达式，依赖穷尽性（Java 17 `switch` 对 sealed 可无 `default`；非穷尽须补 `default` 抛 `AssertionError`）。

### 3.6 Suspend（仅 2 处）
- `execute.execute(project)`：`CompletableFuture.runAsync(() -> ..., AppExecutorUtil.getAppExecutorService())`。
- `update` 检查：`ProgressManager.getInstance().runProcessWithProgressSynchronously(...)` / `runAsync`。

### 3.7 构建脚本语言（待决策，见 §6）
功能等价不要求改 `build.gradle.kts`（Kotlin DSL 仍属构建配置，非插件运行时代码）。是否一并转 Groovy `build.gradle` 取决于「纯 Java」口径。

### 阶段 0 详解：Lombok delombok 预验证（硬关卡，未过不得用 Lombok）

> IntelliJ Platform 插件运行时 classpath **不含 Lombok**，若直接注解 Lombok 类，沙盒与 `verifyPlugin` 会找不到生成的方法/类。必须在**编译期**把 Lombok 注解 delombok 成普通 Java，使产物零 Lombok 依赖。本阶段即先验证此链路，再允许任何文件使用 `@Data`/`@Value` 等。

#### 0.1 依赖与插件接线（`build.gradle.kts` 修改）

```kotlin
// 1) 版本目录（gradle/libs.versions.toml）新增
// [versions]
// lombok = "1.18.34"
// [libraries]
// lombok = { module = "org.projectlombok:lombok", version.ref = "lombok" }

// 2) build.gradle.kts：引入 freefair Lombok 插件（自带 delombok + generated 注解）
plugins {
    id("org.jetbrains.kotlin.jvm")
    id("io.freefair.lombok") version "8.6"   // 与 Gradle 8.x / Kotlin 2.x 兼容
}

dependencies {
    compileOnly(libs.lombok)
    annotationProcessor(libs.lombok)         // Kotlin/JVM 插件编译 Java 时跑 Lombok
    testCompileOnly(libs.lombok)
    testAnnotationProcessor(libs.lombok)
}

// 3) delombok + 生成方法带 @Generated（避免 Verifier/IDE 结构误判）
lombok {
    addLombokGeneratedAnnotation = true      // 生成方法带 lombok.Generated
    // disableConfig = true                 // 如项目有 lombok.config，先关掉避免副作用
}
```

> 备选（不引插件，手动 delombok task）：用 `org.projectlombok:lombok` 的 `delombok` 入口写 `Delombok` 任务输出到 `build/delombok`，再把该目录加入 `sourceSets["main"].java.srcDir`。插件方案更省心，推荐首选。

#### 0.2 冒烟样例（置于 `src/main/java/.../util/LombokProbe.java`）

import lombok.Data;

/** 仅用于阶段 0 验证 Lombok + delombok 链路，验证通过后可删除。 */

@EqualsAndHashCode(callSuper = false)
public class LombokProbe {
