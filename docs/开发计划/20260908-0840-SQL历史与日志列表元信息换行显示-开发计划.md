# SQL 历史与日志列表元信息换行显示 开发计划

> 现象：SQL 日志与 SQL 历史两个列表条目把元信息（时间戳/耗时/来源）和 SQL 挤在同一行，SQL 稍长就把元信息后面的内容顶出可视宽度，阅读不便（用户截图：SQL 历史 tab，`[—] [2026-09-03 09:38:22] [UserServiceImpl.java:34] SELECT ...` 单行铺开）。
> 用户要求：改成换行显示，元信息一行在上、SQL 一行在下。先制定开发计划文件，再实施。
> 工作目录：dev worktree（`F:/code/Java/Gitee/SongRenShuo/mybatis-plus-sql-visualizer-dev`）。

## 一、现状定位

两处渲染点，均为 `DefaultListCellRenderer` + HTML 通道单行拼接：

| 列表 | 渲染点 | 现状 HTML 结构 |
|------|--------|----------------|
| SQL 日志 tab 条目列表 | `SqlLogPanel.kt` → `LogEntryListCellRenderer.computeRowHtml`（L1406~1414） | `<html>{时间戳}{耗时}{来源}{SQL高亮}{去重徽章}</html>` |
| SQL 历史 tab 二级 SQL 列表 | `HistorySqlLogPanel.kt` → `HistoryCellRenderer`（L494~536，HTML 构建在 L508~524） | `<html>[$耗时] [$时间戳] [$来源] {SQL高亮}</html>` |

配套机制盘点：

- **可变行高已具备**：两处列表均已 `fixedCellHeight = -1`（SqlLogPanel.kt:835、HistorySqlLogPanel.kt:154），条目高度按内容自适应——HTML 里插 `<br>` 即可渲染成两行，无需行高改造。`SqlListHtmlRenderer.escapeHtml` 已把换行转 `<br>`，多行 SQL 摘要在 cell 中的渲染通路是现成的。
- **HTML 缓存**：两处都走 `entry.cachedListHtml` 惰性缓存（T-LogListFreeze-02/T-Perf-05）。两行格式是常量（不随设置变化），会话内不存在缓存格式混用；设置变更监听（SETTINGS_CHANGE_TOPIC）已有整包清缓存逻辑兜底，无需新增失效点。
- **复制链路不受影响**：`SqlEntryList.itemToText`（SqlLogPanel.kt:91~93）覆写 Ctrl+C 输出纯 SQL；tooltip 仍是 `restoredSql`。两者都不读渲染 HTML。
- **死代码澄清**：`history/SqlHistoryPanel.kt` 带 T-Perf-24 死代码标注（未注册任何工具窗口/弹窗，F-7 视图由历史 tab `HistorySqlLogPanel` 承接）——**本计划不改它**，防止误改错对象。

## 二、方案决策

**方案 A（选定）：HTML 通道插 `<br>`，元信息行在上、SQL 行在下**

- 元信息行（第一行，灰色系）：SQL 日志 = 时间戳 + 耗时 + 来源 + 去重 ⨉N 徽章；SQL 历史 = `[$耗时] [$时间戳] [$来源]`。
- SQL 行（第二行）：现有 `SqlListHtmlRenderer` 高亮 SQL（`withTerminator(entry.summary)`），内容与配色完全不动。
- 零结构改造：仍是 DefaultListCellRenderer + HTML，缓存机制、选中态实时渲染分支（T-Perf-23）原样保留，改动只在两处 HTML 拼接串。

**决策点：去重徽章归元信息行尾**。徽章描述重复次数，属元信息而非 SQL 内容；移出后 SQL 行视觉纯净，阅读/复制锚定一致。原位置在 SQL 尾部（`${sqlHtml}${dedupeBadge}`），随迁到第一行末尾。

**边界：空元信息行守卫（仅日志 tab 需要）**。时间戳（`logTimestampEnabled` 关）、耗时（`showDurationInLogList` 关）、来源（`sourceFile == null`）、徽章（无计数）四段都可单独为空——全空时若仍插 `<br>` 会渲染出空首行。`computeRowHtml` 需按元信息段是否为空决定带不带 `<br>`。历史 tab 的耗时/来源恒有占位值（`—`/`unknown`），无此问题。

**方案 B（弃）：双 JLabel 拼 JPanel 渲染器**——自建组件树渲染，丢失 HTML 缓存通道与现有「直接断言渲染文本」的测试路径，改动面大且视觉收益与 `<br>` 无差别。
**方案 C（弃）：改 Table 分列展示**——列宽挤压 SQL 阅读宽度，与诉求相反；列表改表格牵动过滤/搜索/差分/右键全链，不成比例。

1. `<br>` 恰好出现在元信息与 SQL 之间：`text.substringBefore("<br>")` 含时间戳/来源片段，`text.substringAfter("<br>")` 含 `SELECT`；

4. 历史 tab 专项：`[—]` 占位耗时与 `[unknown]` 占位来源渲染在第一行。

## 五、风险与回滚

- 每条目高度约翻倍，同屏可视条目数减少——用户主动要求的形态，非回归。
- Swing BasicHTML 对 `<br>` 的支持是标准行为，无平台差异；可变行高两处均已启用，长 SQL 自动换行（`\n`→`<br>`）与本次两行结构叠加属既有能力。
- 回滚：两处渲染点 + 两个测试文件，单提交 `git revert` 即可。
