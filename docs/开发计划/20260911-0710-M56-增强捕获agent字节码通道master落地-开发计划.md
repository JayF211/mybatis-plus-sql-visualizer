## 1. 为什么仍要做：捕获层级的代差（原案结论，继续成立）

控制台桥捕获链（`SqlLogConsoleBridge` → 三解析器 → `SqlLogEntryBuffer`）有三个结构性局限：依赖日志格式（格式一变即断）、数据不完整（参数反解析有失败面、无影响行数、报错靠时序反向关联）、拿不到执行上下文（调用栈要靠向用户工程注入拦截器）。agent 在应用 JVM 内 hook JDBC 执行点，与日志格式完全解耦：**JDBC 层一个 hook 全覆盖 MyBatis/MP/MPJ/Hibernate/JPA/JdbcTemplate/裸 JDBC 九框架族**，SQL 文本、绑定实参、精确耗时、影响行数、执行异常、调用栈全部结构化直取。

产品定位沿 457d8e6 修订不变：对外称「**增强捕获**」，对用户不出现 agent 字样；默认关，未开启用户体验与现状逐字一致；开启后 agent 接管捕获源，attach 失败/关闭自动回落控制台捕获（零劣化）。安全四件套（注入确认/数据脱敏/禁用不卸载/失败回落）不随技术简化放宽。

## 5. 技术方案（master 版）

### 5.1 总体架构（沿 r2 原案，不变）

```

┌─────────────────────────┐                ┌──────────────────────────┐
│ AgentManager (project)  │ attach+load    │ agent.jar（ASM 9.10.1）  │
│  ├ 进程发现/pid（反射桥） │◄──────────────►│  ├ JDBC 层 hook（主）    │
│  ├ 惰性 attach/幂等表    │  loopback      │  │   prepare/setXxx/     │
│  ├ ServerSocket 收流     │  Socket 事件流  │  │   execute 三族        │

│      ▼                  │                │  │   Executor ms.getId() │

└─────────────────────────┘                └──────────────────────────┘
```

### 5.2 attach 挂载要点（T-M56-01）

1. **进程发现**：复用桥的反射骨架（§3 表 4 行）拿 `ProcessHandler` → `getNativePid()`（反射能力探测，243 缺失回退 `getProcess().pid()`）；或订阅 `EXECUTION_TOPIC` 的 `ExecutionListener.processStarted`。
2. **惰性挂载（本轮新增约束）**：不随 project open 挂载。时序 = 用户开启「增强捕获」（且过注入确认）→ 后台线程等待主运行进程就绪 + 去抖（如 3s）→ attach → loadAgent。全程后台线程，不进 EDT；挂载期间 UI 显示「增强捕获：连接中…」，不阻塞面板使用（桥通道照常工作，事件到达后自然切换）。
3. **agent jar 落盘**：插件内嵌 agent jar（Java 编写、独立自包含、无 Kotlin stdlib；manifest 含 `Agent-Class` + `Can-Redefine-Classes/Can-Retransform-Classes: true`）解压到临时文件 + `deleteOnExit`。loadAgent 只收磁盘路径，目标 JVM system classloader 加载，插件 classpath 不可见（探针实证）。
4. **挂载**：`Class.forName("com.sun.tools.attach.VirtualMachine", true, platformClassLoader)` 反射 `attach(pid)` → `loadAgent(path, "port=xxxx")` → 记 pid→会话幂等表 → `detach()`。
5. **幂等**：插件侧 pid 表 + agent 侧 system property 标记双保险（实测 JDK8 目标二次 loadAgent 抛 `AgentLoadException: 0`）。
6. **失败降级**：attach 异常/远程 SSH/容器/`DisableAttachMechanism`/未来 JDK 默认禁止动态 agent（JEP 451 演进）→ 记日志自动回落控制台桥，零劣化；检测到策略性拒绝时设置页给「目标 JVM 可能需要 -XX:+EnableDynamicAgentLoading」提示（仅提示，不自动改配置）。
7. **agentmain 必须挂 transformer（DebugTools 调研回填，硬性验收）**：竞品 DebugTools 的 `agentmain` 只 `createExtensionJar()+startServer()`、**不注册 SQL transformer**（SQL 增强仅存在于 premain，`DebugToolsAttach.java:74 vs :94-97`），导致「hot attach 后打印 SQL」实际失效——这是 attach 路线最容易踩空的一环。本插件 M56 的 agentmain 内必须显式 `inst.addTransformer(...)` + 对已加载的驱动类 `retransformClasses`，否则增强开启后对已运行进程的 JDBC 调用无捕获。此项列为 T-M56-01 PoC 门禁的硬性验收项（demo JDBC8/JDK17 目标各实证一次「attach → SQL 事件到达」）。
8. **attach 参数与容错（竞品可复用手法）**：参数契约用「反射自省 `k=v` 逗号分隔 + 配置文件兜底」（DebugTools `AgentArgs.format/parse`），新增参数零协议改动，替代手写 args 字符串；JDK 版本错配视为可容忍（`IOException` 含 `Non-numeric value found`、`AgentLoadException("0")` 两个魔数视为「可能仍成功」继续连接，`finally detach`）——hot attach 产品化的关键容错。

### 5.3 agent 侧字节码增强（Java 编写）

- **JDBC 层 hook**（6~10 个固定方法）：`Connection.prepareStatement/prepareCall`（记语句）、`PreparedStatement.setXxx`（按实例身份记实参）、`Statement/PreparedStatement.execute/executeQuery/executeUpdate/executeBatch`（执行前取调用栈 + 起始时间，执行后取耗时与 `getUpdateCount`，异常直捕）、`Connection.close` 清理。回调类经 instrumentation 注入到目标可见 classloader（`java.sql.*` 是 bootstrap 类）。
- **「动态代理包装 Connection」备选主路径（DebugTools 调研回填）**：竞品只 hook 一个 `Driver.connect`，返回时把 `Connection` 用动态代理包装、`prepareStatement/createStatement/prepareCall` 再包装 Statement/PreparedStatement（`SqlPrintInterceptor`）——比 hook 6~10 个固定方法更鲁棒，且**自动覆盖连接池复用路径**（所有拿到该 Connection 的代码路径都被代理）。本计划实施期在「逐方法 hook」与「connect 动态代理包装」两路对照选型（ASM 均可实现，代理路更省字节码工作量）；无论选哪路，竞品的分库格式适配思想（`DataSourceDriverClassEnum` 9 类驱动策略枚举 + 反射驱动内部字段兜底）都是「JDBC 驱动兼容矩阵」的现成素材，照搬组织方式。
- **驱动 SQL 提取与参数还原（两条竞品路径合流）**：setXxx 实参跟踪（拿真实类型，本插件主路径）+ 驱动自带 `asSql`/`getSQL`/`toString`（Cool Request 捷径）+ 分库反射字段兜底（DebugTools 达梦/GBASE/KBase 字段漂移解法）三者合流为「分库 SqlFormat 策略」：默认 setXxx 实参还原，个别驱动实参不可靠时降级驱动自带 SQL，再兜底反射驱动内部字段。注意竞品共同之坑：`startsWith("set")` 宽泛匹配会误记 `setFetchSize/setMaxRows/setQueryTimeout`（须显式枚举 setXxx 签名）、`currentTimeMillis` 毫秒计时（本插件用 `nanoTime`）、每次 execute 都 `getStackTrace`+JNI 反查代理（本插件栈过滤缓存短路）。
- **回调类 classloader 可见性（DebugTrees 最易翻车点，直接复用）**：注入到驱动字节码的代码用 `ClassLoader.getSystemClassLoader().loadClass(...)` 定位回调类（驱动 loader 可能看不见 agent 类），配「驱动 loader 隐藏 agent 类时回退 system loader」的针对性单测（DebugTools `SqlDriverClassFileTransformerTest` 的 `HiddenAgentClassLoader`）；transformer 注入代码保持纯净、不引外部库（防 ClassFileTransformer 上下文额外类加载死锁）。
- **retransform 兼容已实证（Cool Request 调研回填，风险降级）**：竞品用 ByteBuddy `AgentBuilder` 的 `RedefinitionStrategy.RETRANSFORMATION` + `disableClassFormatChanges()` 对 MySQL8/5、PG、ClickHouse 四类**已加载**驱动在生产插件里稳定插桩——只注入方法前后增强、不改变方法签名/字段/类结构。本计划沿「只对 `Executor` 等稳定接口 retransform、失败降级仅 JDBC 事件」的原对策，但把它从「待验证」降为「有开源先例实证」，PoC 门禁的 retransform 项可对标竞品四驱动矩阵补测。
- **SQL 提取捷径（Cool Request 调研回填，降低参数还原权重）**：竞品不插桩 setXxx，而是 hook 驱动的 `executeInternal`/`executeWithFlags`/`getInputStream` 后直取驱动已拼 SQL（MySQL `getQuery().asSql()`、MySQL5 `asSql()`、PG `toString()`、ClickHouse `getSQL()`）。本计划把「setXxx 逐调用跟踪 → 参数还原」立为主路径（拿完整实参/类型），但把「execute 入口直取驱动 SQL」列为**轻量降级路径**——当目标只需 SQL 文本、或 setXxx 跟踪在个别驱动上不可靠时启用；实施期在 demo 驱动矩阵上两路对照，决定默认策略。注意竞品的坑：其 `MethodHandle` 每帧现查（未缓存）且 `currentTimeMillis` 毫秒计时，本插件须静态缓存 handle + `nanoTime`。
- **MyBatis 层 hook**（补 `ms.getId()`）：`Executor.query/update` 首参 MappedStatement 取 id，与 JDBC 事件按线程 + 时序关联；关联不可靠或 retransform 动态代理类失败则降级为仅 JDBC 事件（statementId 为空，跳转回退 Java）。**agent 生效期间禁止与「注入 InnerInterceptor 源码」双写**（两者拦截点同为 Executor 代理，冗余）。
- **代码红线**：拦截点只做采集入队；有界队列 + 丢弃策略（丢事件不丢线程）；热路径零分配；agent 内异常静默自吞不泄漏到应用；全局禁用开关短路（禁用 = 停采集，不做卸载承诺）。
- **事件协议**（loopback Socket，JSON 或紧凑自定义文本实施期定）：`sql/params/durationMs/updateCount/error/callerFile/callerLine/statementId/requestTag/source=AGENT`，字段截断上限见 §4 #5。

### 5.4 事件 → 条目适配与双通道共存（T-M56-02）

`AgentEventAdapter`（纯函数可单测）：`AgentEvent` → `LogSqlEntry`（含 §T-M56-00 新字段）→ `SqlLogEntryBuffer.addEntry`（master `:67`）。`SqlSource.AGENT` 新枚举值，渲染加轻微角标区分通道。切换语义：**增强接管、失败回落**——增强开启且 attach 成功 → agent 为捕获源、桥暂停挂载（避免同源同 SQL 双采，dedupeKey 指纹天然一致但解析成本翻倍）；attach 失败/会话结束/关闭增强 → 自动回落桥。事件到达即挂载完成，UI 据「最近 N 秒收到 agent 心跳/事件」判定在线态。

- 不内嵌 Arthas（Ultra 59.7MB 路线）；不做远程/生产环境 attach（远程场景即降级桥；Ultra 4.0.16 的远程 Arthas 包路线不跟进）。
- 不承诺 agent 卸载（Instrumentation 不可逆；禁用 = 停采集，还原尽力而为）。
- 一期不 hook Web 层做请求边界（T-M56-06 可选，请求上下文一期允许为空）。
- 不做 agent 内 SQL 格式化/高亮（agent 只采集传输，展示复用 IDE 侧渲染）。
- 不自动改用户运行配置（含 `-XX:+EnableDynamicAgentLoading`——只提示）。
- 不替代模板注入方案（F-44-6/7 保留为「用户项目零依赖、代码可见」信任底座与无 attach 环境通道，仅增强在线时跳过注入）。
- 同类工具精华中不吸收：原文拼接去重键（弱于本插件指纹键）、druid 控制台彩色回显、可配置前缀（P3 需求池）、尾部公共后缀降噪（P3 需求池）。
