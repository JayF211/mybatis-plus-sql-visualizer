# N4「更多」popup 内弹模态致第一次点确定被吞 — 开发计划

> 来源：2026-09-20 真机走查（`docs/验收文档/20260920-真机走查记录-验收问题修复.md` §7.3 N4）与集成后真机验收（同文件第七节）发现并记录；2026-09-21 立项并实施。
> 相邻但**不在本计划范围**：N3（`ParamImportDialog` 在 Disposer 树泄漏）——见文末「N3 状态」。

## 一、现象与影响

- **现象**：预览面板「更多」菜单里点任一项（导入参数 / 差异对比 / 分享），平台记 SEVERE：
  `Showing dialogs in PopupStep.onChosen can result in focus issues. Please put the dialog showing code into invokeLater…`
  （`#c.i.u.p.u.PopupImplUtil`）。
- **真机后果（比日志噪音严重）**：**第一次点「确定」被吞**，需先聚焦对话框窗口再点才生效——用户感受就是「点了没反应」。
- **出现频次**：集成后真机验收 3 次（每打开一次该对话框一次，idea.log:1676 / 1829 / 2395）；更早两轮各 6 次但当时未记录。
- **性质**：既有代码缺陷，**非本轮（验收问题统一修复）引入**。

## 二、根因（代码实证）

`SqlPreviewPanel.moreActionsStep()` 的 `onChosen` **同步调用**动作体：

```kotlin
override fun onChosen(selectedValue: String?, finalChoice: Boolean): PopupStep<*>? {
    actions.firstOrNull { it.first == selectedValue }?.let { it.second() }   // ← 同步
    return PopupStep.FINAL_CHOICE
}
```

而三项动作**都会弹模态对话框**：

| 菜单项 | 动作 | 是否弹模态 |
|---|---|---|
| 导入参数 | `importParamsFromClipboard()`（`:3413`）→ `ParamImportDialog(...).show()` | 是 |
| 差异对比 | `showSqlDiff()`（`:2385`） | 是 |
| 分享 | `showShareDialog()`（`:2370`）→ `ShareDialog(project, this).show()` | 是 |

即在**弹层尚未销毁**时同步把模态对话框塞进去 → 平台判为焦点风险（弹层与对话框争焦点，第一次点击被弹层收走）。

平台告警栈直接指到 `SqlPreviewPanel$moreActionsStep$1.onChosen(SqlPreviewPanel.kt:891)` → `importParamsFromClipboard(:3482)`，与代码完全对应。

## 三、修法（按平台给出的原文）

平台告警自带修法：**「Please put the dialog showing code into invokeLater…」**。故把动作体从 `onChosen` 内同步执行改为**延后到弹层销毁之后**执行：

```kotlin
override fun onChosen(selectedValue: String?, finalChoice: Boolean): PopupStep<*>? {
    val action = actions.firstOrNull { it.first == selectedValue }?.second
    if (action != null) {
        // 延后一拍：弹层在本方法返回后即销毁，invokeLater 的体在弹层已销毁时才跑
        ApplicationManager.getApplication().invokeLater { action() }
    }
    return PopupStep.FINAL_CHOICE
}
```

**一处修复覆盖三条动作**（它们共用同一 `onChosen`）。

**取舍与边界**：
- 代价是菜单点击到对话框出现之间多一个 EDT 事件轮次（亚毫秒级，用户不可感知）；
- 只动 `moreActionsStep`，不动三项动作各自的实现（它们的模态语义不变）；
- `PopupStep.FINAL_CHOICE` 返回值不变（弹层单选语义保留）。

## 四、测试

- **新断言**（本项的可测点）：`onChosen` 命中真实项时**不得同步执行动作**（N4 回归点），且仍返回 `FINAL_CHOICE`。单测禁弹模态，故只断言「未同步触发」——延后体在不抽干 EDT 队列的前提下不会执行。
- 既有 `SqlPreviewTopRowLayoutTest#test更多菜单step_命中失败项安全返回FINAL_CHOICE` 保持通过（未命中路径语义不变）。
- 定向 + 全量门禁（当前基线：`testShards` 483 类 / 5463 例 / 0 失败 / 6 跳过；agent 14 类 / 65 例）。

## 五、真机验收口径

独立沙盒开 demo 工程，打开预览面板 → 「更多」→ 点「导入参数」：
- idea.log 中 `Showing dialogs in PopupStep.onChosen` 计数 **0**；
- 对话框出现后**第一次点「确定」即生效**（不再需要先聚焦对话框窗口）；
- 另两项（差异对比 / 分享）各点一次，同样无该 SEVERE。

## 六、N3 状态（不在本计划范围）

`ParamImportDialog` 在 Disposer 树泄漏：优雅退出时平台记 SEVERE，注册栈 `addDocumentListener(:1072) ← createCenterPanel(ParamImportDialog.kt:81) ← importParamsFromClipboard(:3482)`，blame 落在 08-20/21。

**暂不实施的硬原因**：复现前提是**优雅退出**，而 262 沙盒的正常退出路径本身是坏的（`InternalError: couldn't create component peer`，16 次运行全部只能强制结束）——不先解决退出路径，改完也验不了。**建议与「262 沙盒退出路径」一起另行立项**。
