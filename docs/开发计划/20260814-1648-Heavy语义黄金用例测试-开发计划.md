## 1. 问题与动机（证据驱动）

**LightPlatform 盲区清单**（本系列实证）：

| 盲区 | 实证 | 影响 |
|------|------|------|
| 方法引用 resolve 返回 null | T-M23.10：`PsiMethodReferenceExpression.resolve()` 在 Light 下不可用 | `inferEntityFromChain` 走文本兜底（列缺失/无注解） |
| lambda 参数类型推断不可用 | T-M23.12：`wrapper.and(o -> ...)` 的 `o.type` 为空 | 真实 IDE 三图标复现不出 |
| 外部库（MP/MPJ）类不可解析 | 注解须全限定名；M16.3 注解默认值差异 | 类/注解元数据相关路径与真实 IDE 行为不同 |

**根因**：Light 是 fixture 层（轻量内存 project，无完整 Java 语义/索引）；测试 module 无真实 MP/MPJ 依赖。
IPGP test 任务本身运行在**完整平台**上——语义分析缺的是「真实项目 module + 方法签名来源（jar）」。

## 2. 设计方案（T-M23.13，混合分层）

### 2.1 测试分层（保留 Light 全量 + 新增 Heavy 黄金用例）

- **LightPlatform 全量快速回归**（现有 507 条，~1 分钟）：日常开发主力，**不动**；
- **Heavy 语义黄金用例**（`HeavyPlatformTestCase`，完整语义/索引）：只放「语义敏感」场景——
  锚点判定、WrapperLocator 定位、转换器全链路的关键形态；每类 5~10 用例；
- **约定**：新增语义敏感逻辑时，对应在 Heavy 类补黄金用例（测试约定文档同步）。

### 2.2 真实 MP jar 进测试 classpath（方法签名/注解元数据来源）

- `testImplementation` 加 `com.baomidou:mybatis-plus-core:3.5.17`（与官方 API 覆盖矩阵基准一致；
  仅影响测试，插件运行时零依赖不变）；
- **MPJ 依赖实证结论（不加）**：`com.github.yulichang:mybatis-plus-join` 1.5.7~1.5.9 均不在
  Maven Central（404，Central 最新仅 1.4.13，JitPack 亦无）；锚点/定位黄金用例所需签名
  （`and(Consumer)` 类型推断、`@TableLogic`/`@Version` 注解元数据）均由 mp-core 提供；
- Heavy 平台下 `wrapper.and(Consumer)` 真实方法签名可解析 → lambda 参数推断可用 →
  真实 IDE 行为可复现（Light 盲区实证）；
- **风险（预期）**：jar 进 classpath 后 Light 测试中「原本不可解析」的注解类变为可解析
  （如 fixture 全限定名注解 `@TableLogic`）→ 部分断言行为变化；逐一核对——新行为与真实
  IDE 一致则更新断言（这正是测试真实化的收益），不一致则调查。

### 2.3 黄金用例（HeavyAnchorSemanticsTest，先实证环境能力再扩展）

**已交付（509 测试全绿，含 2 条 Heavy 用例）**：
1. **lambda 参数类型推断**：Heavy 下可推断（Light 下为 null）——T-M23.12 三图标缺陷的复现/回归手段
   （fixture 自定义函数式接口，不依赖外部库）；
2. **场景 B lambda 参数守卫**：Heavy 语义环境下与 Light 一致（lambda 不标锚点、变量行标锚点，恒 1 个图标）。

**环境能力实证结论**：
- lambda 推断：Heavy ✓ / Light ✗；
- **方法引用 resolve：Heavy 亦返回 null**（测试环境平台限制，与真实 IDE 不同）——
  T-M23.10 的 inferEntityFromChain 文件级类名解析补偿在两种环境都需要；
- 真实 MP 场景（`eq(DeviceEntity::getId)` 等）的方法引用 resolve / `@TableLogic` 注解类解析
  依赖 mp-core 的 module classpath 挂载（§2.4 后续项）。

### 2.4 mp-core 的 module classpath 挂载（待调研，后续项）

**2025.3.5 平台实证的 API 变化**（本次探索记录）：
- `JavaModuleFixtureBuilder` 编译 classpath 不可用（IPGP 平台分片，类在 testFramework.jar 但编译不可解析）；
- `ProjectLibraryTable` / `LibraryTablesRegistrar` 已移除（2025.2+ 库 API 重构）；
- `ModuleRootModificationUtil.addModuleLibrary` 3 参版已删除（仅剩 2 参空库版）；
- Heavy 自带 project 的 module classpath 不含测试依赖。

挂载方案（二选一，待实施时验证）：① 新库 API（workspace 库）挂载测试 classpath；
② `ModuleRootModificationUtil.addModuleLibrary(module, name)` 2 参 + 手动 roots 编辑。
落地后升级黄金用例：真实 MP 场景（`wrapper.and(o -> ...)` 推断、短名 `@TableLogic` 解析）。
