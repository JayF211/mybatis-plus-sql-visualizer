## 2. 官方策略依据（已核实原文）

1. **编译基准 = 最低支持版本**：官方兼容策略要求以最低支持版本为编译基准构建，
   公共 API 向后兼容保证更高版本可运行；`since-build` 声明最低版本，不设 `until-build`。
   （项目 M17 起已按此执行，本次把基准从 253 降为 243。）
2. **Kotlin stdlib 规则**（using-kotlin.html#kotlin-standard-library）：
   - "Using Kotlin 2.x is recommended for plugins targeting 2024.3 or later"；
   - "If a plugin supports multiple platform versions, it must either **target the lowest
     bundled stdlib version** or **the specific version must be provided in plugin distribution**"；
   - 捆绑 stdlib 表：2024.3 → **2.0.21**；2025.3 → 2.2.20；2026.1 → 2.3.20；2026.2 → 2.4.0。
3. **构建链硬约束**：IPGP 2.x 最低要求 **Gradle 9.0.0**（本项目 Gradle 9.7 + IPGP 2.18.1 不可降级）
   → 排除"降 Kotlin 到 2.0.21"路线（需连带降 Gradle 与 IPGP，等于重写构建链）。

## 4. 方案

### 4.1 Kotlin/stdlib 策略（决策树）

- **方案 A（主）**：构建基准改 2024.3.7.1 后，编译 classpath 的 stdlib 自动为 2.0.21
  （来自 243 发行版）→ 恰好满足官方"target the lowest bundled stdlib version"。
  编译器基于 classpath stdlib 生成引用与内联；830 测试在 243 沙盒（flat classpath = stdlib 2.0.21）
  全量跑为强验证网，任何新 API 引用以 NoSuchMethodError 暴露。
- **方案 B（兜底）**：若试编译硬报错或测试暴露 stdlib 兼容问题 →
  `kotlin.stdlib.default.dependency=true` 打包 stdlib 2.3.20（官方第二选项，发行包 +约 1.5MB），
  需 243 沙盒实测类加载优先级（测试环境 flat classpath 不覆盖此路径）。
- 验证门：阶段 5 试编译。
