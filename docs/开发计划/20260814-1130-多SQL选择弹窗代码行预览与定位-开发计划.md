## 1. 问题与动机（用户反馈，证据驱动）

**用户反馈**：选择弹窗出来了，但每项只有 `L3 LAMBDA_QUERY  biz_banner_entity` 式摘要——**不够明细
（看不到代码内容）、不能立刻定位到代码位置**；期望类似 IDEA 原生搜索：列表预览**代码行**，
选中后**定位到编辑器对应行**。

**现状盘点**（M23.7 增量修复后）：
- `SqlSelectionDialog`（`ui/SqlSelectionDialog.kt`）：`JList` 显示 `WrapperLocator.sqlCandidateSummary(call)`
  单行文本（`L{行号} {类型} {表名}` / 批量方法 `L{行号} {方法名}`）——无代码内容、无跳转；
- `ConvertToSqlAction` selection 分支：多候选 → 弹窗，`onSelect` 回调仅 `preview(service, head, project)`
  （后台转换 + 预览）——**无编辑器定位**；
- `WrapperLocator.sqlCandidateSummary` 已能取行号（`PsiDocumentManager` → document 行号）；
  **代码行文本**可直接从 document 按行截取（候选调用 `textRange.startOffset` 所在行）——信息都在，缺展示与跳转；
- 编辑器操作先例：`SqlPreviewPanel` 有 caret/selection 操作（M19.3），IDE 标准 API
  （`CaretModel.moveToOffset` / `ScrollingModel.scrollToCaret` / `SelectionModel`）可用。

**约束**：
- 弹窗总是由编辑器触发（`CommonDataKeys.EDITOR` 必非空）——跳转链路 editor 引用可经
  `ConvertToSqlAction` 持有传入；
- 超长代码行须**截断**（防止撑爆弹窗宽度）；
- headless 测试环境：渲染/跳转为 UI 交互，**显示文本构造与行 offset 计算抽纯函数**单测。

## 2. 设计方案（T-M23.8）

### 2.1 代码行信息获取（`psi/WrapperLocator.kt` 扩展）

```kotlin
/** T-M23.8：候选调用所在代码行完整文本（trim；供选择弹窗预览）。 */
fun sqlCandidateLineText(call: PsiMethodCallExpression): String {
    val doc = PsiDocumentManager.getInstance(call.project).getDocument(call.containingFile) ?: return ""
    val line = doc.getLineNumber(call.textRange.startOffset)
    return doc.getText(TextRange(doc.getLineStartOffset(line), doc.getLineEndOffset(line))).trim()
}
```

- 行文本截断（`displayText` 层做，`MAX_LINE_LENGTH = 80`，超出加 `…`）；
- 现有 `sqlCandidateSummary` 保留（第一行摘要）。

### 2.2 弹窗增强（`ui/SqlSelectionDialog.kt`）

- 列表项 = **两行信息**（Swing JLabel HTML 布局，`DefaultListCellRenderer` 覆写）：
  ```
  L3  LAMBDA_QUERY  biz_banner_entity
      Wrappers.<BannerEntity>lambdaQuery().like(StringUtils.hasText(...), ...)…
  ```
  第一行 = 现有摘要（行号 + 类型/方法名 + 表名），第二行 = 代码行内容（缩进两空格 + 截断 80 字符）；
- 显示文本构造抽 **internal 纯函数**（可单测）：
  ```kotlin
  internal fun displayText(summary: String, lineText: String): String =
      "<html>$summary<br>&nbsp;&nbsp;&nbsp;${lineText.escapeHtml().take(MAX) + "…"?}</html>"
  ```
  或纯文本拼接形态（实施时定，保证 headless 单测可用）；
- `JList` 数据源改为 `List<Pair<String, String>>`（摘要 + 代码行），renderer 按索引取回候选。

### 2.3 定位跳转（`actions/ConvertToSqlAction.kt`）

`onSelect` 回调扩展（选中确定后）：

```kotlin
// ① 编辑器定位：光标移到候选调用行首 + 滚动居中 + 选中整行（Find 定位风格）
editor.caretModel.moveToOffset(lineStartOffset(call))
editor.scrollingModel.scrollToCaret(ScrollType.CENTER_UP)
editor.selectionModel.setSelection(lineStart, lineEnd)
// ② 预览 SQL（现状不变）
preview(service, call, project)
```

- 行 offset 计算抽 internal 纯函数（`lineOffsetsOf(call): Pair<Int, Int>`，可单测）；
- 跳转不改变预览行为（预览照常弹出）。

### 2.4 边界（文档化）

- 代码行截断 80 字符（超长行省略展示，定位不受影响）；
- 单候选/无候选分支不变（仍直接预览/提示）；
- 弹窗无编辑器场景不存在（弹窗仅由编辑器动作触发）；跳转失败（编辑器已关闭等）runCatching 兜底不中断预览。

## 4. 验收标准

1. 多 SQL 选择弹窗每项显示**两行**：摘要 + 代码行内容（截断 80 字符），一眼定位代码位置；
2. 选中确定 → **编辑器跳转**（光标到行首、滚动居中、整行选中高亮）+ 预览 SQL 照常弹出；
3. 超长行/含特殊字符代码行不破坏弹窗布局（截断 + 转义）；
4. 存量 497 + 新增测试全绿；文档三处同步（矩阵/清单 §8/本文档变更记录），提交分两步。
