## 1. 问题与动机（用户需求，证据驱动）

**用户需求**：
1. 当前快捷键（`ConvertToSqlAction`）与右键（EditorPopupMenu）都要求光标在 Wrapper 上——
   希望支持在**任意相关位置**触发（`eq` 调用处、`.list()` 调用处等链中/链尾位置）；
2. **选择代码块后右键**：选中区域含多个 SQL 时，**弹出提示让用户选择**要预览哪一个。

**现状盘点**（M23.5 交付后）：
- 触发入口 `ConvertToSqlAction`（`actions/ConvertToSqlAction.kt:26`）：只读 `editor.caretModel.offset`
  → `file.findElementAt(offset)` → `SqlPreviewService.preview(element)`——**无 selection 处理**；
- 定位入口 `WrapperLocator.locateWithTable(anchor)`（`psi/WrapperLocator.kt:82`）三类来源：
  - `findWrapperVariable`（94-136）：沿 **parent 链向上**找 Wrapper 变量——`wrapper.eq(...)` 等
    **变量形态**在任意调用处已能定位 ✅；
  - `findWrapperNewExpression` / `findWrapperFactoryCall`（266-282）：**「向下扫子树只在锚点
    初始位置一次，向上只检查元素自身」**——`new LambdaQueryWrapper<>().eq(...).list()` /
    `service.lambdaQuery().eq(...).list()` 等**无变量链式形态**，只有光标在**链首**（new 关键字 /
    工厂调用自身或其子树）才命中；**链中/链尾（eq/list 调用处）定位失败** ❌——用户痛点根因；
- gutter 图标（`SqlGutterLineMarkerProvider`）锚点行右键已可用（`WrapperAnchorDetector` O(1) 锚点），
  本次不改 gutter 锚点语义（性能红线，M10）；
- 预览缓存（`SqlPreviewService.preview:86-100`）按**锚点 offset** 缓存——多 SQL 选择场景
  各链用各自锚点预览即可，缓存天然隔离，无需改。

**定位增强算法（核心）**：从任意元素沿 parent 找**最近的方法调用**（`eq`/`list` 等），再沿
`methodExpression.qualifierExpression` **回溯到链首**，链首形态判定（new wrapper 构造 /
Wrappers 工厂 / service 链 / wrapper 变量）命中即构建链——覆盖用户全部「任意相关位置」。

## 2. 设计方案（T-M23.7）

### 2.1 定位增强（`psi/WrapperLocator.kt`）

新增定位路径（保持现有路径不动，向后兼容）：

```
locateWithTable(anchor) 现有三路径不变 →
新增 locateFromChainCall(anchor)：
  1. 沿 anchor.parent 链找第一个 PsiMethodCallExpression（无 → null）；
  2. 从该调用沿 methodExpression.qualifierExpression 回溯到链首（与 buildChainFromFactory
     的收集逻辑同构）；
  3. 链首判定：new wrapper 构造（detectWrapperType）→ buildChainFromNew；
     Wrappers 工厂调用（isWrapperFactoryCall）→ buildChainFromFactory；
     qualifier resolve 为 Wrapper 变量 → buildChain（变量形态兜底，正常已由
     findWrapperVariable 命中）；
  4. 非 wrapper 链首（普通方法调用）→ null（防误伤：普通方法 `foo().bar()` 链首不是 wrapper）。
```

- 防误伤：步骤 3 链首判定与现有 `isWrapperFactoryCall` / `detectWrapperType` 完全一致；
  普通方法调用（`helper.applyFilter(w)` 等）链首非 wrapper → null，行为不变；
- 与现有路径的冲突：光标在链首时现有路径先命中（保持现有行为/缓存键不变）；
- 性能：仅在**用户显式触发**（快捷键/右键）时调用，无 M10 daemon 红线约束。

### 2.2 触发入口增强（`actions/ConvertToSqlAction.kt`）

```
actionPerformed：
  selection 非空（editor.selectionModel.hasSelection）→ 分支 A
  else → 分支 B（现状，光标处定位）

分支 A（选择代码块，新）：
  1. 扫描 selection 文本范围内所有「链首方法调用」（PsiTreeUtil 收集 PsiMethodCallExpression，
     按 2.1 链首判定过滤 + 链首 offset 去重）；
  2. 结果：
     - 0 个 → 现有「未找到 Wrapper」提示；
     - 1 个 → 直接预览（锚点 = 该链首调用）；
     - 多个 → **选择弹窗**（2.3），选中后预览；
  3. 扫描在后台线程执行（previewAsync 同款模式），回调 EDT 弹窗/渲染。

分支 B：element = findElementAt(caret offset) → preview(element)（内部增强定位已覆盖 eq/list 处）；
  仍失败 → 现有「未找到 Wrapper」提示。
```

### 2.3 多 SQL 选择弹窗（新 `ui/SqlSelectionDialog.kt`）

- 自定义 `DialogWrapper` + `JList`（或 `Messages.showChooseDialog` 简易形态，实施时定）：
  每项 = 「行号 + Wrapper 类型 + 表名」摘要（如 `L12  LAMBDA_QUERY  biz_banner_entity`）；
- 确定 → 返回选中项锚点 → `SqlPreviewService.previewAsync` 预览；取消 → 不动作；
- 文案走 bundle（新增 `dialog.selectSql.title` 等 key，中英双语，插件语言独立于 IDE）。

### 2.4 边界（文档化）

- gutter 图标锚点语义不变（锚点行才显示图标——M10 性能红线）；
- 选择区扫描仅限**显式选择**（用户行为），不涉及 daemon 高亮性能；
- 多 SQL 判定 = 链首唯一性（同一链的 eq/list 不重复计数）；嵌套子查询链首在同一选择区内
  只计最外层链（链首 offset 去重天然覆盖——子查询链首在实参子树内，仍为独立链首，文档化：
  子查询 wrapper 同样可被选择，属合理行为）。

## 4. 验收标准

1. 快捷键/右键在 `eq` 调用处、`.list()` 调用处可正常预览（链式 new 与服务链两种形态）；
2. 选择代码块右键：1 个 SQL 直接预览；多个 SQL 弹选择列表（行号 + 类型 + 表名），选中后预览；
   无 SQL 保持「未找到」提示；
3. 光标在链首/变量形态行为不变（存量 490 断言全绿）；
4. 文档三处同步（矩阵/清单 §8/本文档变更记录），提交分两步。
