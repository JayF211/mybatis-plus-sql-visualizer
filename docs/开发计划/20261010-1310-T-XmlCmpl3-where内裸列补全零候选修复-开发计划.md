# T-XmlCmpl3：where 内裸列补全零候选修复——stripXmlTags 动态标签语义替身（薄账）

> 20261010 用户真机报告（dev-bak 沙盒实证复现）；主控亲历诊断+修复。占号说明：小缺陷薄账，未占 O/R/D/V 新号（测试注释内工作代号 T-XmlCmpl3 延续 T-XmlCmpl/T-XmlCmpl2 序列）。

## 一、现象

同一 `UserMapper.xml` 内：`selectUserWithOrdersXml`（140 块）字段补全正常；`selectUserPageXml`（160 块）`<where>`/`<if>` 内裸列（`deleted`→`dele`、`username`→`userna`）补全 **No suggestions**。着色两块均正常（注入无差）。

## 二、矩阵实验（runIde 243 沙盒，主控亲跑；v7/v8 截图在 mpsv-walk/）

| 位置 | 结果 |
|---|---|
| 160 块 161 行 select 行末 | ✓ 列名候选（`deleted.create_time` 等） |
| 160 块 163 行 `from u` 行末 | ✓ 表/实体候选（user/user_address/k_user） |
| 160 块 **165 行 where 内 `dele`** | ✗ No suggestions |
| 160 块 **170 行 if 内 `userna`** | ✗ No suggestions |

## 三、根因（纯函数层，`sql/SqlTextAnalysis.kt`）

`stripXmlTags` 对动态标签**纯空白占位**，把 `<where>` 剥成空白 ⇒ SQL 关键字 `WHERE` 从分析文本中消失，两处连锁误判：

1. `detectClause`：`FROM` 成为光标前最后可见关键字 → where 内位置被误判 `TABLE` → **`SourceSqlCompleter` 列名分支整体跳过**（TABLE 分支只出表名，`user` 对前缀 `dele`/`userna` 不匹配 → 零候选）；
2. `parseTableAliases`：表清单吞掉 `WHERE` 终止词 → 把 where 内第一个裸词（`deleted`）**误判为 `user` 表的别名**（污染候选：p2 弹窗顶部的 `deleted.create_time` 即误判别名列）。

## 四、修复

`stripXmlTags`：开标签 `<where>`/`<set>`（含带属性/大小写形态）换**等长关键字替身** `WHERE`/`SET`——**前导空格**与左侧词分隔（防 `user<where>` 剥成 `userWHERE` 粘连词）+ 尾部补空格保 1:1 偏移映射；闭合标签、注释/CDATA、其余标签（if/include/trim/foreach 等无子句关键字语义）照旧纯空白。消费方（XmlSql/AnnotationSql 补全贡献器、SourceSqlCompleter）零改动。

## 七、同批追加（用户验收后两新点，20261010 下午）

### 1. 二段：别名.列名补全插入别名重复（o.o.user_id）——已修（`e4ba261`）

用户验收 where 补全生效后发现 140 块 149 行 `on o.user_i` 选补全 `o.user_id` 后插成 `o.o.user_id`。机理：prefixedColumn 带点主 lookupString 被平台整体替换进已敲前缀 token 位。修复（平台标准形态）：**主 lookupString=裸列名**（插入只替换点后 token）+**附加 lookupString=`别名.列名`**（平台按任一 lookup string 匹配保留，多别名同表仍可按别名区分）；两贡献器过滤改 `item.allLookupStrings.any`；新增工厂直测（主串裸名+附加串集合，反向换回带点主串恰 4 红）。中间「matcher 切点后段」方案因语义缺陷（a./b. 同表列无法区分+空点后段全滤）废弃。

### 2. 日志→SQL 页灰字提示（用户优化点）——已修（A）

编辑器原生 placeholder 仅聚焦时可见，未聚焦空态观感「无提示」。对齐 SqlToJavaPanel 形态：LogToSqlPanel 两区下方挂恒显灰字 JBLabel（复用既有键 `log.panel.hint.input/result`），intellij DocumentListener（243 已 Kotlin 化无 SAM，object 表达式）随空文档显隐。

平台历史钮数据源=**IDE 全局 Find 历史**（`FindInProjectSettings`，与本项目无关的串线词+空串杂质）。三处置：①`NativeSearchTextField` 构造传真 `project`（null 时平台 `removeNotify→addTextToRecent→getInstance(null)` 必 NPE）；②`withAddSearchResultsToGlobalSearch(false)` 止住搜索词写全局；③**接管历史钮**——组件树定位平台 `ShowHistoryAction` 钮（类名匹配，找不到静默降级）原位换成本组件「最近搜索」（会话级 `recentSearches`，容量 20，空词不记，`recordSearchQuery` 由面板在过滤真正应用时喂词——HistorySqlLogPanel.applySearch 单点/SqlLogPanel.refreshList）。跨会话持久化未做（登记后续）。
