## 1. 问题

MyBatisX（baomidou 官方）最新两条用户抱怨均无人回复：2026-04-08 与 2026-08-31 报告 Map 参数在 XML 中 `#{map.xxx}` 被标"无法解析符号"；2026-02-24 报告多模块项目同名实体触发 "Result type not match" 误报（调研报告 §4.2）。同款问题若在本插件出现，将直接动摇"正确性"人设。

"竞品缺陷反哺本插件回归"是既有做法：M37/M38 已将九项预览问题修进 81 场景金样矩阵（`docs/架构设计/M37M38竞品融合新增功能-说明文档.md` §三）。N-8 把这两个竞品翻车场景做同样的防御性处理——先核对本插件真实行为，再把语义锁定进金样场景。

## 2. 方案

立项前已对本插件两条链路做代码探查与探针实测，结论：**两个场景本插件行为均正确，不存在 MyBatisX 同款缺陷**。因此本计划不修任何生产代码，方案是「补金样场景锁定」——把当前正确语义固化成回归资产，防后续迭代无感劣化。

### 2.1 探查结论一：`#{map.xxx}` 预览链路行为正确

XML 预览对 Map 参数的处理链（全部为本地代码实证）：

| 环节 | 位置 | 行为 |
|------|------|------|
| `#{}` token 解析 | `xml/XmlSqlRenderer.kt:75-82`（parseParameterMappings） | `#{map.xxx}` → `?` + ParameterMapping(property="map.xxx")，纯收集不做符号解析——不存在"无法解析符号"的报错面（插件不为 XML mapper 注入引用/检查器） |
| OGNL test 表达式 | `xml/Ognl.kt:371-391`（property）、`428-433`（index）、`394-426`（方法白名单） | Map 属性访问 `map.status`、索引 `map['status']`、`containsKey/size/isEmpty` 白名单方法均支持 |
| 条件真值 | `xml/XmlPreviewModel.kt:95-96`（renderSql conditionOverrides） | if/when 真假由面板开关决定，表达式求值仅无开关时兜底——`map.status != null` 不会被 mock 值误判 |
| 参数回填引号 | `ui/XmlParamTypeResolver.kt:38-52`（Map/基本类型 → 键=参数名）+ `xml/XmlPreviewModel.kt:80-83`（quoteFor 前缀匹配） | `@Param("map") Map<String,Object>` → 键 `map`（Map → true 引号），任意 `map.xxx` 属性经前缀匹配命中；`XmlPreviewModel.kt:68-71` 注释已文档化该设计 |
| mock 绑定 | `xml/XmlPreviewModel.kt:102-121`（mockBindings）+ `xml/Ognl.kt:196-247`（rootPaths 取基名） | `map.xxx` 根路径收集为 `map` 并占位，`${map.xxx}` 求值为空时输出显式提示（`xml/TextSqlNode.kt:44-57`），不是静默错值 |

补全侧（`ui/highlight/XmlSqlCompletionContributor.kt:83-92、128-149`）在 test/collection 属性值内补参数名与主实体字段名，`map.` 前缀后补的是主实体字段——对 Map 参数语义不够精确，但只影响候选列表、不产生任何错误标注。列为已知边界随文档记录，不在本计划修（见 2.3 可选步骤）。

### 2.2 探查结论二：多模块同名实体无误报面

全源码检索无 "Result type not match" 或等价判定文案——该误报是 MyBatisX 自有 inspection 的产物，本插件没有同构检查面。插件中实体解析仅两处经 `JavaPsiFacade.findClass(allScope)`：`ui/XmlParamTypeResolver.kt:34-35`（引号映射）与 `ui/XmlPreviewService.kt:103-104`（`@class@field` 静态常量求值），同名实体命中其一的后果至多是引号判定取自另一个同名类（同为用户实体类，字段大概率一致），不影响预览 SQL 文本本身——XML 预览的 SQL 来自 mapper 原文（`ui/XmlPreviewService.kt:37-49`），不经过实体表名推导。

### 2.3 具体改动

金样场景放 **XML 侧专用矩阵类**（与 M38.2 建 `SqlPreviewSpecMatrixTest` 同一先例）：模型层纯逻辑，不依赖 IDE resolve 的场景进新类；需要真实 PSI 解析的引号场景补进既有 `HeavyXmlParamTypeResolverTest`。

| 文件 | 改动 |
|------|------|
| `src/test/kotlin/cn/song/mybatisplus/visualizer/xml/XmlMapParamSpecMatrixTest.kt`（新建） | Map 参数金样矩阵，spec(name, mapper, 期望) 快照风格与 SqlPreviewSpecMatrixTest 同构；场景 X1~X6、X7 见下表 |
| `src/test/kotlin/cn/song/mybatisplus/visualizer/ui/heavy/HeavyXmlParamTypeResolverTest.kt` | 补两条：@Param("map") Map 参数 → 键=参数名且值为引号；同 FQN 双实体共存时 resolveQuotes 不抛错、Map 键不受影响（X8） |
| `docs/架构设计/M37M38竞品融合新增功能-说明文档.md` §三 | 表格补一行「竞品翻车场景防御性验证（N-8）：Map 参数 `#{map.xxx}` 与多模块同名实体进金样矩阵，行为锁定」 |

新矩阵场景清单（每条一行预期语义）：

| # | 场景 | 预期语义 |
|---|------|---------|
| X1 | `<select>` 内 `WHERE name = #{map.userName}` | SQL 渲染 `?`，mappings 恰含 property=`map.userName`，errors 为空 |
| X2 | `@Param("map") Map` + `#{map.userName}` 参数行 | quoteFor(`map.userName`) 命中前缀键 `map` → 引号回填 true |
| X3 | `<if test="map.status != null">...` | 条件开关默认勾选（defaultTruth），勾选后 WHERE 渲染条件、取消后消失 |
| X4 | OGNL Map 取值：`map.status`、`map['status']`、`map.containsKey('k')` | 属性/索引/白名单方法求值与 MyBatis OGNL 语义一致（OgnlEvaluator 同构断言） |
| X5 | `<foreach collection="map.items" item="it" ...>` | collection 表达式全文作 mock 键精确命中，默认展开 2 元素 |
| X6 | `${map.column}` 求值为空 | errors 显式提示"求值为空（可在预览中填写覆盖值）"，SQL 不出现 `null` 字面量 |
| X7 | 同 FQN 实体双份共存（myFixture.addClass 复制一份同名类） | 预览 SQL 输出与单实体完全一致，errors 为空（无误报） |
| X8 | 同 FQN 双实体 + Map 参数引号解析 | resolveQuotes 正常返回，`map` 键存在且不受同名类影响（Heavy 类实测） |

可选步骤（非本计划验收项，发现即记录）：X9 补全候选精确化——`map.` 前缀时按参数真实类型（Map 键集不可静态知）回退为仅补参数名与 `<include>`/bind 变量，涉及 `ui/highlight/XmlSqlCompletionContributor.kt` 与 `SourceSqlSuggestionFactory`，以实施期确认为准，若做则单独立项。

## 5. 风险

- MyBatis 真实 OGNL 对 Map 的属性访问在键不存在时返回 null 而非报错，X4 期望值按 MyBatis `ExpressionEvaluator`/`OgnlOps` 语义手工核对，若快照与真实引擎有出入以官方语义为准修正快照（与矩阵"MP 升级语义 diff 审阅"同一约定）。
- X7/X8 的同名实体在 LightPlatform 的 findClass 命中顺序不确定，断言只锁定「输出一致、不报错」，不锁定命中哪一个类——避免顺序敏感的脆弱用例。
- 矩阵扩量后 `XmlMapParamSpecMatrixTest` 与既有 `XmlPreviewModelTest` 存在场景重叠的可能，实施期先检索既有用例，重叠场景改为在既有用例上加注释指向矩阵行，不重复铺。
