## 1. 问题与根因（证据驱动）

### 1.1 批量操作缺逻辑删除条件（getById 无 `deleted = 0`）

**用户症状**（`StoreCouponEntity extends BaseEntity`，`@TableLogic private Integer deleted;`）：

```sql
-- 插件当前输出（错误）：
SELECT id, create_time, update_time, deleted, merchant_id, ...
FROM biz_store_coupon
WHERE id = ?

-- 真实 MP 输出（对齐 @TableLogic 语义）：
SELECT id, create_time, update_time, deleted, merchant_id, ...
FROM biz_store_coupon
WHERE id = ? AND deleted = 0
```

**根因**：`SqlPreviewService.preview()` 两条路径分流（`ui/SqlPreviewService.kt:86`）：
- **Wrapper 路径**（分支 1）：`effectiveLocated?.let { ... }` 内调用 `injectLogicDeleteCondition`（T-M15-07，`@TableLogic` 实体查询/删除自动追加 `AND deleted = 0`，受 `settings.injectLogicDelete` 开关约束）——逻辑删除注入**只在此路径**；
- **批量操作路径**（分支 2，`SqlPreviewService.kt:178-191`）：`BatchOperationConverter.convert` 生成的 `BatchPreview` 是**纯文本 SQL 模板**（`psi/BatchOperationConverter.kt`），直接透传 `PreviewResult.sql`，**完全绕过逻辑删除注入**。

真实 MP 语义（BaseMapper 内置 SQL 注入，MP 官方文档「逻辑删除」节）：
- **查找**（selectById/selectBatchIds/selectByMap 等）：WHERE 追加 `AND deleted = 0`；
- **删除**（deleteById/deleteBatchIds/deleteByMap 等）：**DELETE 转变为 UPDATE**——`UPDATE t SET deleted = 1 WHERE ... AND deleted = 0`（LogicDeleteSqlInjector 把 Delete 族替换为 LogicDeleteById 等）；
- **更新**（updateById）：WHERE 追加 `AND deleted = 0`（MP 文档「更新: 追加 AND 逻辑删除字段 = 0」）。

**波及面**（批量操作 21 方法，`BatchOperationConverter.BATCH_OPERATIONS`）：
- SELECT 族：`getById` / `getOptById` / `listByIds` / `selectByIds` / `selectByMap` / `listByMap` / `selectAll` → 缺 `AND deleted = 0`；
- DELETE 族：`removeById` / `deleteById` / `removeByIds` / `deleteByIds` / `removeBatchByIds` / `removeByMap` / `deleteByMap` → 缺条件 **且** 硬删除形态与 MP 软删除不符。

**决策（2026-08-14 用户确认）**：**删除操作的软删除转换仅在有 `@TableLogic` 的实体上触发**——此时删除操作实际是修改操作（UPDATE），对齐 MP LogicDeleteSqlInjector 语义；**无 `@TableLogic` 的实体删除操作维持既有 DELETE 模板**（真实物理删除，存量行为不变）。软删除模板中 `deleted = 1` / `deleted = 0` 均为字面量（非 `?`），不进入参数行（与 T-M23-02 联动）。

**边界（沿用插件既有文档化决策）**：批量 UPDATE 族（`updateById` / `updateBatchById`）**不注入**逻辑删除——插件 Wrapper 路径 T-M15-07 已明确「UPDATE 不注入——更新可能修改 deleted 本身，真实项目发票域显式 `.eq(getDeleted, 0)`」，批量路径保持一致（与 MP 官方差异文档化，不本次修正）。

### 1.2 save / removeById 无参数填入口（面板「无未解析参数」）

**用户症状**：`storeCouponService.save(entity)`（INSERT 模板 N 个 `?`）与 `storeCouponService.removeById(id)`（`WHERE id = ?`）的 SQL 中 `?` 无法填值，左栏显示「无未解析参数」。

**根因**（`SqlPreviewService.kt:183-190`）：

```kotlin
return PreviewResult(
    sql = batch.sql,
    compactSql = batch.sql,
    unresolvedParams = emptyList(),   // ← 参数行由它驱动，恒空 → 「无未解析参数」
    paramTable = batch.paramGroups,   // ← 文本注释（"-- 实际参数: [col=?] × N"），UI 未渲染（死字段，仅测试断言）
    ...
)
```

- 面板左栏参数行完全由 `unresolvedParams` 驱动（`ui/SqlPreviewPanel.kt:345`：`views.isEmpty() && result.unresolvedParams.isEmpty()` → 显示「无未解析参数」；`rebuildLeftPanel` 按 source 逐行建输入框）；
- `paramTable`（`-- 实际参数: [...]`）在 `SqlPreviewPanel` 中**无任何渲染点**——批量操作的参数组说明从未展示给用户；
- 与 Wrapper 路径对比：Wrapper 路径每个未解析 `?` 都有 source（实参表达式文本）并生成参数行，批量路径完全没有 source。

### 1.3 参数回填引号判定错误（LocalDateTime 等非数值类型未加引号）

**用户症状**（`storeCouponUserMapper.update(Wrappers.lambdaUpdate()...set(Entity::getUseTime, now))`，`useTime` 为 `LocalDateTime`）：
`now` 运行时值不可静态求值 → `?` 占位 + 面板输入行；用户填入 `2024-01-01 00:00:00` 后回填渲染为：

```sql
-- 插件当前输出（错误，无引号）：
SET use_time = 2024-01-01 00:00:00
-- 应输出：
SET use_time = '2024-01-01 00:00:00'
```

**根因**（`sql/SqlGenerator.kt:453-456`）：

```kotlin
private fun quoteHint(table: TableInfo?, column: ColumnRef): Boolean? {
    val type = table?.columns?.firstOrNull { it.columnName == column.columnName }?.fieldType ?: return null
    return if ("String" in type || "CharSequence" in type) true else false  // ← 非 String 一律 false（不带引号）
}
```

`fieldType` 为全限定名（如 `java.time.LocalDateTime` / `java.lang.Long`）：除 String/CharSequence 外**一切类型**（LocalDateTime / Date / Boolean / char / 枚举 / UUID …）恒返回 `false` → 面板回填（`SqlPreviewPanel.renderSingleValue` 的 `hint?.quote == false` 分支）不渲染引号。
用户期望：**除确定的数值类型（int / long 等）外，其他类型默认带引号**。

## 2. 修复方案（定位到现有代码）

### T-M23-01：批量操作逻辑删除 / 软删除对齐（问题 1.1）

**触发条件（用户确认）**：逻辑删除注入与软删除转换**仅当实体含 `@TableLogic`（`TableInfo.logicDeleteColumn` 非空）时触发**；无 `@TableLogic` 的实体批量操作输出与存量完全一致（SELECT 无 `deleted = 0`、DELETE 维持物理删除）。

**改动点**：
1. `psi/BatchOperationConverter.kt`：
   - `convert(call)` 增加参数 `injectLogicDelete: Boolean`（由 `SqlPreviewService` 传 `settings.state.injectLogicDelete`，默认 true；测试环境 settings 未注册时兜底 true——与 Wrapper 路径 `?: true` 一致）；
   - `buildSelectBatch`：实体含 `table.logicDeleteColumn` 且开关开启 → WHERE 追加 `AND deleted = 0`（`getById` / `getOptById` / `listByIds` / `selectByIds` / `selectByMap` / `listByMap` / `selectAll` 全覆盖；`selectAll` 无 WHERE 时追加 `WHERE deleted = 0`）；
   - `buildDeleteBatch` / `buildMapConditionBatch`：**仅当**实体含 `table.logicDeleteColumn` 且开关开启 → **软删除模板**（有 @TableLogic 时删除即修改操作，对齐 MP LogicDeleteSqlInjector）：
     - 主键等值（removeById/deleteById）：`UPDATE 表\nSET deleted = 1\nWHERE id = ? AND deleted = 0`
     - 主键 IN（removeByIds/deleteByIds/removeBatchByIds）：`UPDATE 表 SET deleted = 1 WHERE id IN (?, ?, ...) AND deleted = 0`
     - Map 条件（removeByMap/deleteByMap）：`UPDATE 表 SET deleted = 1 WHERE <Map 等值条件...> AND deleted = 0`
     - 无 `@TableLogic` 实体维持既有 DELETE 模板（存量测试不破）；
2. `ui/SqlPreviewService.kt:182`：`BatchOperationConverter.convert(it, injectLogicDelete = settings?.state?.injectLogicDelete ?: true)`；
3. 与 T-M23-02 联动：软删除模板的 `deleted = 1` / `deleted = 0` 是字面量（非 `?`），不进入参数行（对照 MP 行为）。

**依赖**：`TableInfo.logicDeleteColumn` 已存在（Wrapper 路径在用，`model/TableInfo.kt`）。

**验收**：① `getById(id)` fixture → `WHERE id = ? AND deleted = 0`；② `removeById(id)` @TableLogic fixture → UPDATE 软删除模板；③ 开关关闭（`injectLogicDelete=false`）→ 不注入；④ 无 @TableLogic fixture 输出不变。

### T-M23-02：批量操作参数面板（问题 1.2）

**改动点**：
1. `psi/BatchOperationConverter.kt` 各 builder 生成 **unresolvedParams + paramHints**（与 SQL 中 `?` 出现顺序一一对应）：
   - **单参方法**（`getById`/`getOptById`/`removeById`/`deleteById`）：实参经 `ExpressionEvaluator` 求值（受 `resolveVariables` 开关控制，对齐 Wrapper 路径 `ArgResolver`）——字面量/可追踪变量 → **内联**（`WHERE id = 100`，无参数行）；不可求值 → `?` + source=实参表达式文本（参数行 `#id`）；
   - **实体/集合方法**（`save`/`saveBatch`/`insert`/`updateById`/`updateBatchById`/`saveOrUpdate`/`insertOrUpdate`/`saveOrUpdateBatch`/`insertBatchSomeColumn`/`listByIds`/`selectByIds`）：每个 `?` 的 source = `实体变量名.列名`（如 `entity.merchantId`，列顺序与 SQL 一致；实体变量名取首实参文本）→ 面板每列一个输入行；主键 IN 模板 `(?, ?, ...)` 重复同一 source（`ids`×3，共享一行）；`version = ?`（updateById @Version）与逻辑删除 `deleted = 0` 字面量不登记；
   - **paramHints**：按列类型引号（复用 T-M23-03 抽出的公共判定）；
   - **Map 条件方法**：维持占位文本（键不可枚举，不登记参数行）；
2. `ui/SqlPreviewService.kt` 批量路径：`resolveVariables = settings?.state?.replaceParams ?: true` 传入 converter；`unresolvedParams` / `paramHints` 透传 `PreviewResult`；
3. 面板零改动（`rebuildLeftPanel` / `backfillParamsBySource` 已按 source 驱动）；
4. `paramTable` 死字段：本次顺带将 `batch.paramGroups`（`-- 实际参数: [...]` 说明）**追加到 SQL 文本末尾**作为注释行（对齐 `ParameterReplacer.annotate` 思路），或维持现状仅清理——实施时二选一，倾向追加（信息不丢失）。

**验收**：① `save(entity)` 面板出现 N 行参数（`#entity.列名`）；② `removeById(id)` 1 行 `#id`，回填生效；③ `removeById(1L)` 字面量内联（无行）；④ 回填值引号按列类型正确（与 T-M23-03 联动）。

### T-M23-03：参数回填引号判定白名单化（问题 1.3）

**改动点**：
1. `sql/SqlGenerator.kt` 的 `quoteHint` 改为**白名单判定**：

```kotlin
/** 数值类全限定名/原语（确定原样渲染，不加引号）。 */
private val NUMERIC_TYPES = setOf(
    "int", "long", "short", "byte", "float", "double",
    "java.lang.Integer", "java.lang.Long", "java.lang.Short", "java.lang.Byte",
    "java.lang.Float", "java.lang.Double", "java.math.BigDecimal",
)

private fun quoteHint(table: TableInfo?, column: ColumnRef): Boolean? {
    val type = table?.columns?.firstOrNull { it.columnName == column.columnName }?.fieldType ?: return null
    // 数值类确定原样；其余（String/CharSequence/LocalDateTime/Date/Boolean/char/枚举等）默认引号
    return if (type in NUMERIC_TYPES) false else true
}
```

2. 抽出公共判定（新 `sql/ParamQuote.kt` 或 `SqlGenerator` 内部函数 + 批量侧调用）供 T-M23-02 复用；
3. 行为对照：String 列恒引号（不变）、Long/Integer/BigDecimal 列原样（不变）、LocalDateTime/LocalDate/Date/Boolean/char/枚举 → **由无引号改为带引号**（本次修复）；列/类型未知 → 仍返回 null（面板 NUMBER_REGEX 启发式兜底，不变）。

**验收**：`.set(Entity::getUseTime, now)` 回填 `2024-01-01 00:00:00` → `use_time = '2024-01-01 00:00:00'`；数值列回填 `100` → `= 100`（无引号）。
