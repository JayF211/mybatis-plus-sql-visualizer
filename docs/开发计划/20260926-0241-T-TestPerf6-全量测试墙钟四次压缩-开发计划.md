> 立项 2026-09-26，分支 `t-testperf6`（自 `t-testperf5` 8d30f15 切出，独立工作树 mybatis-plus-sql-visualizer-testperf6）。
> 任务代号 T-TestPerf6，接续 T-TestPerf4/5 的全量测试墙钟系列；O 编号本任务不占用（O-84/O-85 已被竞品候选预登记）。

## 一、背景与问题重述

T-TestPerf4（20260924）与 T-TestPerf5（20260925）两轮已把**调度层**杠杆实测到地板：片数定案 4、GC/堆/fork/线程面/构建缓存全部销账，warm 全量（`./gradlew testShards`，不含编译）收口 3m10s（6064 用例 0F/0E/skipped=9），经验总结明示「零测试源码改动前提下这就是地板水位，再往下只剩测试实现层」。

本轮用户授权恰好放开了这条约束：允许改测试实现，只要求**测试效果不变、不删用例**。因此本轮的增量空间＝**测试实现层的重复劳动消除**——不动任何断言语句、不动任何判红条件、不删任何 @Test，只消除「同一个类里被反复执行的相同扫描/发现工作」和「本可并行却串行排队的等待」。

### 不动的部分（及理由）

- **SqlPreviewPanelTest 43.0s/73 例**：单例 0.2~1.3s 分布均匀，top10 仅占 22%，无结构性浪费，属 UI 平台测试（EDT+fixture）固有成本。压缩它只能合并用例或共享可变 fixture——前者撞「不删用例」红线，后者改变测试隔离语义。
- **top50 其余 UI/PSI 类**（0.3~0.8s/例）与 484 类长尾（合计 237s，均值 0.5s/类）：同为平台测试固有成本，无重复劳动可消除。
- **调度层**（片数/GC/堆/fork/分桶/build cache/线程面）：T-TestPerf2/3/4/5 已全部实测销账，不再碰。
- **agent 子项目通道**：`org.gradle.parallel=true` 下与分片并发，warm 不拖尾（T-TestPerf4 S4 时序审计结论），非关键路径。

## 三、改动方案

### S1 签名护栏族：发现单次化 + 并行核验 + skip 前置（62.4s → 预计 ~15s）

1. 新增 `src/test/kotlin/cn/song/mybatisplus/visualizer/testutil/SignatureDistroDiscovery.kt`：**单次**深遍历 transforms，一次性产出四类各自需要的全部发现结果（IDEA 发行版清单、ml-llm 制品清单+companion 排序、platform-acp companions、平台 lib 目录映射），object 内 JVM 级 lazy。同片 JVM 内四类共享，一次遍历替代原来的至少 5 遍（类内多函数遍历 + 跨类重复遍历）。
   - 发现口径逐条照抄各类现有私有实现（目录判据、segmentOf 排序、装机兜底、distinctBy canonicalPath），仅合并遍历，不改变任何发现结果。
2. `AcpSignatureCrossVersionTest`：
   - 三个发现函数改为读单例；
   - 第二个测试方法的 `implClassesDir()` skip 判定**前移到发现之前**（便宜判定先做，结构性 skip 时不付全盘遍历）；注意这会改变「无制品且无 impl」场景下 assumeTrue 的理由文本选择（原来报制品理由、改后报 impl 理由），本机形态（有制品、无 impl）skip 行为不变，§五 V3 登记验证；
   - 双制品 `runChecker` 由串行改并行（固定 2 线程），结果按制品原顺序收集、println 输出顺序与原来一致，判红聚合逻辑不变。
3. `McpDbSignatureCrossVersionTest` / `PlatformSignatureCrossVersionTest`：`discoverDistros` 改读单例；逐发行版串行核验改并行（池大小 3，按发行版序收集输出），`McpDbSignatureChecker`/`PlatformSignatureChecker` 本体零改动。
4. ~~`AcpTransportIsolationTest`：`discoverDistros` 改读单例，留沙盒片内不动其他。~~ **实施订正（20260926）**：该类实为 BasePlatformTestCase 沙盒 fixture 测试（9.4s 是沙盒启动固有成本），类内没有发现与外部进程逻辑（前期的 grep 盘点把 PlatformSignature 的同名行误记到它头上），**零改动**。

预期：族 A 62.4s → ~15s（遍历 5+ 遍收 1 遍；McpDb 核验 4×~2.5s 串行收 ~4s 并行；AcpSignature 白付遍历消除）。

### S2 守卫扫描族：源码快照单次化（32.5s → 预计 ~8s）

`SettingsRealityGuardTest` / `BannedApiSourceScanTest` / `EnumReachabilityGuardTest` 三类各加类内 lazy 源码快照（companion object 级，walkTopDown+readText 一次，存 `相对路径 → 原文` 表）；各 @Test 的断言改读快照。要点：

- 断言逻辑、判红条件、报错文案**逐字节不动**——快照内容与重复扫描读到的内容在同一次 JVM 内逐字节相同，「效果不变」由此可证；
- `BannedApiSourceScanTest` 多棵树 + stripComments 变体：快照存原文，`stripComments` 在使用处惰性计算并缓存（Map<relPath, stripped>），保持两种读法语义；
- 三个类的 `repoRoot()` 私有实现保持原样（快照初始化内部使用）。

预期：三类 32.5s → ~8s（每类一次扫描 + 断言遍历）。

### S3（可选进阶，视 V1 验证结果）：三个纯 JUnit 护栏类挪出沙盒片，进并行非沙盒桶 `testExternal`

- `buildSrc/src/main/kotlin/mpv-testing.gradle.kts`：`discoveredTestClasses` 排除 McpDbSignatureCrossVersionTest / PlatformSignatureCrossVersionTest / AcpSignatureCrossVersionTest 三类（AcpTransportIsolationTest 是 BasePlatformTestCase，**留片**）；注册普通 `Test` 任务 `testExternal`（非 intellijPlatformTesting.testIde，无沙盒），classpath 照 testFast 的三段构造（main+test output 前置 / 平台 jar 复用默认 test 成品 / 剔除插件自身 jar），`maxParallelForks=1`；`testShards` 增加 `dependsOn("testExternal")`，与 4 片 + agent 通道并发。
- 聚合报告的 parity 扫描目录补上 `build/test-results/testExternal`（否则三类报「无结果 XML」WARN）。
- 预期：片 execSum 再降 ~12s（三类优化后残量移出关键路径）；testExternal 自身 ~10s 并行不拖尾。墙钟直接收益小（~4s），结构性价值＝护栏族后续扩容不再挤占片墙钟。
- 若 V1 验证不过（隐性平台依赖），S3 整体放弃，S1/S2 照常交付。

- S1 并行化的偶发假失败按 V4 处置纪律（定向复跑判别，不洗白不采信）；
- 收益不达预期（<5%）时如实登记并保留改动（重复劳动消除本身是正确性中性、结构向好的，不因收益大小回退）；S3 单独按收益定去留；
- 若全量出现 skipped 数变化（≠9），先排查 skip 语义是否被求值顺序影响（V3），排除后方可继续。
