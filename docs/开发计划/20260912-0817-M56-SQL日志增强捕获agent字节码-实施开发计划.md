## 1. 目标：现有捕获链的三个结构性局限，agent 通道一次解决

现有 SQL 日志捕获（`SqlLogConsoleBridge` → 三解析器 → `SqlLogEntryBuffer` → 面板）依赖控制台日志格式：格式一变即断；参数从文本行反解析有失败面；无影响行数；报错与 SQL 靠时序反向关联；调用栈要向用户工程注入拦截器。agent 字节码增强在应用 JVM 内 hook JDBC 执行点，与日志格式完全解耦——**一个 hook 点覆盖 MyBatis/MP/MPJ/Hibernate/JPA/JdbcTemplate/裸 JDBC 全家族**，SQL 文本、绑定实参、精确耗时、影响行数、执行异常、调用栈全部结构化直取。

对用户的最终形态（产品定位沿 f1abb2c 不变）：设置页一个「**增强捕获**」开关（对用户不出现 agent 字样），默认关；未开启的用户体验与现状逐字一致；开启并确认后 agent 接管捕获源，面板出现带角标的增强条目（参数实参直取、精确耗时、影响行数、报错同列、精确跳转），attach 不可用/关闭自动回落现有控制台捕获，零劣化。安全四件套（默认关/注入确认/数据脱敏/禁用不卸载）不放宽。

## 4. 技术方案

### 4.1 总体架构

```
IDE JVM（插件）                                 用户应用 JVM
┌──────────────────────────┐                   ┌──────────────────────────────┐
│ AgentManager (project)   │ attach+loadAgent  │ agent.jar（Java 8 字节码，    │
│ ├ 进程发现/pid（复用桥反射）│◄────────────────►│   ASM shade relocate 自包含） │
│ ├ 惰性挂载/幂等/JEP451     │ 端口经 args 下发   │ ├ premain/agentmain 双入口    │
│ ├ LoopbackServer 收流     │ loopback Socket   │ │ （agentmain 挂 transformer  │
│ ├ 在线态/心跳/断线重连     │ 长度前缀+JSON      │ │  + retransform 已加载驱动）  │
│ ├ AgentEventAdapter      │                   │ ├ Driver.connect 织入（ASM）  │
│ ▼                        │                   │ │  → JDK Proxy 包装 Conn/Stmt │
│ SqlLogEntryBuffer.addEntry（与桥共用）        │ ├ 三层 SQL/参数提取策略       │
└──────────────────────────┘                   │ ├ 有界队列（丢事件不丢线程）   │
                                               │ └ Socket 客户端 + 心跳        │
                                               └──────────────────────────────┘
```

### 4.2 agent 侧（Java 编写，独立 Gradle 源集）

1. **插桩主路径：「Driver.connect 织入 + JDK 动态代理包装」**。只对已知驱动类的 `connect(String, Properties)` 做方法出口织入（ASM），把返回的 `Connection` 用 `java.lang.reflect.Proxy` 包装；Connection 代理的 `prepareStatement/createStatement/prepareCall` 再包装 Statement/PreparedStatement 代理；之后 setXxx/execute 全部是普通代理逻辑，**零新增字节码**。优势（DebugTools 实证）：覆盖连接池复用路径（所有拿到该 Connection 的代码自动被代理）、字节码面从 6~10 个方法缩到 1 个、对驱动版本漂移最不敏感。对照组：逐方法 hook（prepare/setXxx/execute 三族直织），PoC 阶段两路在 demo 驱动矩阵上对照（插件点：连接池 HikariCP/Druid 下的覆盖完整性、代理开销、异常路径），实测后定主路径。
2. **织入工具决策**：ASM 9.10.1 `AdviceAdapter`（asm-commons）手织为默认；PoC 中若「connect 多 return 路径/异常路径」编织成本失控（工时或正确性风险），切换 ByteBuddy `@OnMethodExit`（shade + relocate 到私有命名空间）——决策标准写死：PoC 门禁内未完成编织即切，不恋战。
3. **agentmain 必须挂 transformer（DebugTools 半成品陷阱，硬验收）**：premain 与 agentmain 共用初始化函数，`agentmain` 内必须 `inst.addTransformer(new SqlHookTransformer(), true)` + 对已加载驱动类 `retransformClasses`（manifest `Can-Retransform-Classes: true`）；T-M56-01 PoC 门禁要求「runIde demo 已运行 → attach → SQL 事件到达」在 JDK8 与 JDK17 目标各实证一次。
4. **SQL/参数三层提取策略**（合流三竞品）：
   - 主：setXxx 实参直取（显式枚举 `setString/setInt/setLong/setObject/setTimestamp/.../setNull` 签名匹配，**禁用 `startsWith("set")` 宽泛匹配**——DebugTools 误记 setFetchSize 坑）；参数值按 `SafeObjectSerializer` 式草稿序列化防循环引用炸栈。
   - 次：驱动自带 SQL（分库枚举策略：MySQL `getQuery().asSql()`/`toString()`、PG `toString()`、ClickHouse `getSQL()` 等，沿 DebugTools `DataSourceDriverClassEnum` 组织方式），当 setXxx 跟踪在该驱动不可靠时降级使用。
   - 兜底：反射驱动内部字段（`inOutParam`/`userSQL`/`sqlObject`/`rpstmt.originalSql` 形态，字段漂移按策略表登记），覆盖达梦/GBASE/Kingbase 等国产库。
5. **采集红线**：耗时 `System.nanoTime()`（毫秒级用 `currentTimeMillis` 是两竞品共同坑）；`getUpdateCount` 直取影响行数；异常直捕（类名+消息+堆栈截断）；调用栈只在 execute 取一次、按 `CallerSourceLocator` 规则过滤框架帧并**按调用方缓存**（禁 per-execute 重复全栈解析 + JNI 反查代理——DebugTools 热点）；静态缓存反射 `MethodHandle`；有界队列 + 丢弃策略（丢事件不丢线程）；agent 内异常 `catch(Throwable)` 静默自吞；全局禁用开关 = volatile 短路（纳秒级）。
6. **classloader 契约（最易翻车点）**：织入代码通过 `ClassLoader.getSystemClassLoader().loadClass(...)` 定位回调类（驱动 loader 可能看不见 agent 类——agent 由 system classloader 加载故必然可见），配「驱动 loader 隐藏 agent 类仍工作」的针对性单测（仿 DebugTools `HiddenAgentClassLoader`）；transformer 注入代码纯净不引外部库（防 ClassFileTransformer 上下文额外类加载死锁）。
7. **构建**：独立 Gradle 源集，产物单 fat jar：Java 8 字节码（`--release 8` + `disableAutoTargetJvm`，覆盖 JDK8~26 目标）、ASM shade relocate 到私有命名空间（`mergeServiceFiles` 保 SPI）、manifest `Premain-Class`/`Agent-Class`（同类双入口）+ Can-Redefine/Can-Retransform、内嵌插件资源 `resources/lib/`，运行时解压落盘 + `deleteOnExit`，**落盘失败显式上报**（通知/日志，禁静默吞）。

### 4.3 通信协议与在线态

- **端口前置协商**：IDE 侧 `getAvailablePort()` 算空闲端口 → `loadAgent(path, "port=<n>;logLevel=...")` 参数下发（参数契约用「反射自省 k=v 逗号分隔」编解码，新增字段零协议改动；外部配置文件兜底优先级低于 args——DebugTools `AgentArgs` 范式）。
- **协议**：loopback TCP，长度前缀帧（4 字节 len + 1 字节 command + JSON body），命令三值起步：`EVENT`（SQL 事件流）/ `HEARTBEAT`（10s）/ `CONFIG`（禁用开关/脱敏开关下发）。单向为主，不引入 RPC。
- **线程模型**：agent 侧采集线程只入队，单发送线程消费（断线重连、批量 flush）；IDE 侧读线程只 decode + 分发，解析入 buffer 走既有后台链路；两侧均 IO 与业务分离 + 有界队列反压。
- **在线态与切换**：UI 据「最近 N 秒心跳/事件」判定增强在线；增强接管 → 桥暂停挂载；心跳丢失/attach 失败/关闭开关 → 自动回落桥（capturing 状态机联动，面板状态行显示「增强捕获：已挂载 pid=x / 已回落控制台捕获 / 连接中」）。

### 4.4 IDE 侧接线

`AgentManager`（project 级服务，与 SqlLogManager 并列）：attach 生命周期、幂等表（插件侧 pid 表 + agent 侧 system property 标记双保险，JDK8 二次 loadAgent 抛 `AgentLoadException: 0` 实证）、ServerSocket、事件分发、降级切换、随 project dispose 摘除、**惰性挂载**（开启增强 + 注入确认后，后台线程等进程就绪 + 去抖 3s 再 attach，全程不进 EDT——Ultra 4.0.20「异步增强避免启动耗时增长」教训）。`AgentEventAdapter` 纯函数：`AgentEvent` → `LogSqlEntry`（字段映射 + dedupeKey 一致性）→ `buffer.addEntry`。

### 4.5 安全与产品化

- **注入确认**：首次启用弹确认（目的/采集范围/数据留本机不回传/回落路径/**JDK21+ 目标控制台会出现动态挂载告警属预期**——JEP 451，仅告警未禁止；未来硬禁止走回落路径并提示 `-XX:+EnableDynamicAgentLoading`，不自动改配置）。
- **脱敏**：默认对疑似敏感形态打码（列名/参数名含 password/token/secret/身份证/手机号等关键词形态），设置页开关开启完整采集（形态对齐 BatsLog `desensitize`）；脱敏在 agent 采集层执行（数据不出应用 JVM 前已处理）。
- **禁用不卸载**：关闭增强 = CONFIG 命令下发 → agent volatile 短路停采集（已 retransform 的类不还原，Instrumentation 不可逆，文档明示）。
- **attach 容错**：JDK 版本错配魔数容忍（`Non-numeric value found` / `AgentLoadException("0")` 视为可能仍成功继续连接，finally detach）。
