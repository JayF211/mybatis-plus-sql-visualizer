## 1. 目标

1. **P0-1 设置页手动检查更新**：设置页新增「更新」分区——当前版本/最新版本展示、`检查更新` 按钮、状态反馈（检查中…/已是最新/发现新版本 vX/失败原因）、新版本变更日志展示。
2. **P0-2 自动安装**：`下载并安装` 一键完成——下载（进度条）→ 平台 PluginInstaller 安装 → 面板提示「更新完成，重启 IDE 后生效」+ `重启 IDE` 按钮（弹 IDE 原生重启确认框，可选「稍后」）。
3. **P0-3 启动自动检查**（用户拍板：开关默认开）：`启动时自动检查更新` 勾选项；勾选时 IDE 启动静默检查，发现新版弹通知（`[立即更新]` 直接后台下载安装、`[稍后]` 关闭）；不勾选则完全跳过启动检查（手动检查不受影响）。
4. **P1-1 更新源可迁移**：清单 URL 集中 `UpdateSource` 常量 + 系统属性覆盖（`mpvs.update.manifest.url`，沙盒验证/未来换源用）。
5. **P1-2 兼容性提示**：清单含 `sinceBuild` 时，若高于当前 IDE build 仅提示不阻塞下载。

**非目标**：上架 JetBrains Marketplace（方案 C，用户暂不）；JetBrains 自定义插件仓库格式（方案 B）；安装包签名校验（自定义源与「从磁盘安装」同信任域）；安装后自动重启（用户选「提示+按钮」）；同日多构建/多通道（版本号规范 YYYY.M.D 不支持）；CI 自动发布（当前发布全手动）。

## 3. 方案设计

### 3.1 总体架构

新包 `update/`（纯函数层与平台粘合层分离，fetch/install 全部注入 seam 可单测）：

```
设置页 UpdateSection ──► PluginUpdateRunner（编排/状态机）──► UpdateApi（HttpRequests）
启动检查 StartupActivity ─┘        ▲  ▲                          │
                                   │  └── PlatformPluginInstaller（安装封装，探测编译）
                                   └── 注入 seam：fetch/install 函数参数（单测用 fake）
```

数据流：清单 JSON（Gitee raw）→ UpdateManifest（Gson/兜底解析）→ VersionComparator
比较 → Available → 下载 zip（临时目录 + 进度）→ PluginInstaller 安装 → 重启提示。

### 3.2 更新源与清单

- 清单固定路径：仓库根 `update/update.json`，URL = `https://gitee.com/songrenshuo/mybatis-plus-sql-visualizer/raw/master/update/update.json`（公开仓库 raw，无需鉴权；支持系统属性覆盖）。
- 安装包：Gitee Release 附件（与现有分发一致），URL 形如 `.../releases/download/v2026.8.14/mybatis-plus-sql-visualizer-2026.8.14.zip`（下载跳转附件 CDN，HttpRequests 跟随 redirect，沙盒实证）。
- 清单字段（version/downloadUrl 必填，其余可选）：

```json
{
  "version": "2026.8.14",
  "downloadUrl": "https://gitee.com/songrenshuo/mybatis-plus-sql-visualizer/releases/download/v2026.8.14/mybatis-plus-sql-visualizer-2026.8.14.zip",
  "changeNotes": "v2026.8.14：……（纯文本，\\n 多行）",
  "publishDate": "2026-08-14",
  "sinceBuild": "253"
}
```

### 3.3 自身版本读取（绕开 PluginId 包迁移）

`PluginVersion`：从**自身 classloader 的 `META-INF/plugin.xml`** 读 `<version>`（IPGP patchPluginXml 构建期注入，打包 jar 与开发态 classes 资源都存在）——零平台 API 依赖，沿用 PluginBuildInfo（T-M23.14）的 codeSource/classloader 手法；不可读（理论兜底）返回 null，UI 显示 "—"。**不使用 `PluginManagerCore.getPlugin(PluginId)`**（PluginId 在 2025.3~2026.2 间有包迁移，编译基线 2025.3.5 / 运行 IDE 2026.2.1 双端兼容风险，ExecuteSqlSupport 注释实证）。

### 3.4 版本比较

`VersionComparator.compare(a, b)`：点分数字段逐段比较（YYYY.M.D）；非数字段按字符串比较兜底；任一解析异常 → 按字符串整体比较；任何异常不得抛出（降级不打扰）。

### 3.5 检查/下载/安装/重启流程

- **检查**：后台任务（Task.Backgroundable 或 BackgroundTask，探测）→ `UpdateApi.fetchManifest(url)`（HttpRequests，connect/read 超时 15s）→ parse → 比较 → CheckResult（UpToDate / Available(manifest) / Failure(message)）。
- **下载**：`UpdateApi.download(url, targetFile, indicator)`——`HttpRequests` + `Request.saveToFile`（进度 fraction，内容长度未知时不确定态）；临时文件 `FileUtil.createTempFile`（.zip 后缀），失败/中断删除。
- **校验**：zip 存在 + 非空 + 后缀（自定义源与从磁盘安装同信任域，无签名校验，文档说明）。
- **安装**：`PlatformPluginInstaller.install(File)`——探测编译优先 `com.intellij.ide.plugins.install.PluginInstaller.installOrUpdatePlugin(PluginId, File, update=true, forceHttps=true)`（新包），兜底旧 `com.intellij.ide.plugins.PluginInstaller`；PluginId 仅在**该封装类内部**使用（单点隔离，若包迁移问题实测暴露则改反射，ExecuteSqlSupport 先例）。**单元测试不调用本类**。
- **重启**：面板/通知提供 `重启 IDE` 按钮 → `RestartDialogImpl.restartWithConfirmation()`（com.intellij.util.ui，T-M23.10 已反编译验证与内置 Restart 动作同实现，用户可「稍后」）。**不做动态加载**（环境 vetoer 定论）。

### 3.6 设置页 UI（PluginSettingsPanel 接线）

- 新组件 `config/UpdateSection.kt`（JPanel 内 GridBag 行，仿 ShortcutEditor 内嵌模式，`updateTexts()` 随语言刷新）；`buildRows` 追加 `addRow("", updateSection)`（仿 buildNumber 行，置于构建号行之前）。
- 状态机：Idle / Checking / UpToDate / Available / Downloading / Installing / Installed / Failed；按状态渲染行可见性与按钮启用（检查中禁用检查/下载按钮防重入）。
- 进度：JProgressBar 行（下载 fraction；下载完成切不确定态）；设置对话框关闭后任务可取消（cancellable indicator），完成回调 invokeLater 判活（面板已销毁则静默）。
- 持久化：`PluginSettings.State` 新增 `autoCheckUpdate: Boolean = true`（默认值即出厂值，XmlSerializer 兼容新增字段）。
- i18n：`MpSqlVisualizerBundle` 中英 properties 各新增约 20 个 `settings.update.*` / `update.*` key（含通知文案），禁止硬编码。

### 3.7 启动自动检查

- plugin.xml 注册：`com.intellij.notificationGroup`（id `cn.song.mybatisplus.visualizer.updates`）+ `com.intellij.postStartupActivity`（T-M23.10 同款机制；displayName 静态写在 plugin.xml——EP 属性不支持 bundle key，实施时探测，若支持则走 bundle）。
- Activity：应用级 AtomicBoolean 单次守卫（postStartupActivity 每项目触发，一个会话只检查一次）→ 开关关则跳过 → 后台静默检查（无进度弹窗，网络失败/解析失败**静默不打扰**）→ 发现新版 → 通知「发现新版本 vX」+ `[立即更新]`（后台下载安装，状态栏进度；成功 → 新通知「更新完成，重启后生效」+ `[重启 IDE]` 动作 → RestartDialogImpl）与 `[稍后]`（dismiss）。
- 并发：与设置页手动下载共用 PluginUpdateRunner，互斥标记防重入。

### 3.8 测试策略

- 纯逻辑（裸 JUnit4）：VersionComparator（等/新/旧/异常兜底）、UpdateManifest（合法/缺字段/坏 JSON/可选字段）、PluginVersion（临时资源解析）。
- 编排（JUnit4 + fake seam）：PluginUpdateRunner——check 各分支（fetch null/坏 JSON/版本比较）、downloadAndInstall（临时目录下载成功+fake install 回调、失败清理临时文件、zip 校验）。
- UI（BasePlatformTestCase，仿 PluginSettingsPanelBuildInfoTest）：UpdateSection 组件树断言（bundle key 定位 label/按钮）、状态渲染切换（internal 测试访问器驱动）、check/install 按钮防重入初始态。
- 启动检查逻辑（JUnit4）：决策函数（开关/已检查守卫/结果→是否通知）注入 seam 全分支；通知 UI 与安装链路沙盒实证。
- **平台 API（HttpRequests/PluginInstaller/Gson/RestartDialogImpl/BackgroundTask）一律不跑单测**——探测编译 + runIde 沙盒端到端（本地 HTTP server 托管假清单+假 zip 验证全链路与「已是最新」分支，再切真实 Gitee URL 验证 redirect 与代理）。

### 3.9 兼容与性能红线

- 运行时零第三方依赖哲学不变（网络 = 平台 HttpRequests，尊重 IDE 代理设置；JSON = 平台捆绑 Gson，不可用则极简手写解析）。
- 不阻塞 EDT：网络/安装全部后台任务；启动检查静默、零 UI 开销（开关关时零联网）。
- 新增 EP（notificationGroup/postStartupActivity）dynamic 属性实施时验证（DynamicEpProbeTest 先例），不引入非动态 EP。

## 7. 边界与降级

- 网络失败/超时（15s connect）：设置页显示失败原因（含「请检查网络/IDE 代理设置」）；启动检查静默；
- 清单 JSON 损坏/字段缺失：同上降级（不弹错误打扰）；
- 下载中断：删除临时文件，报错提示重试；
- sinceBuild 高于当前 IDE build：可下载，安装前提示「该版本可能不兼容当前 IDE」；
- 无签名校验：与「从磁盘安装」同信任域，README 说明（更新源 = 发布者自己的 Gitee 仓库）；
- 设置页与启动检查并发：共用 runner 互斥标记；
- 设置对话框关闭后任务完成：invokeLater 判活，面板已销毁则静默；
- 启动检查网络失败不重试（下次启动再试）；不打断 IDE 启动流程。

## 8. 已确认项 / 简化决策

1. 重启方式：面板提示 + 「重启 IDE」按钮（RestartDialogImpl 原生确认框），**不自动重启**（用户拍板，防丢未保存工作）；
2. 启动自动检查：开关默认**开**（用户拍板，覆盖 T-M23.10 回退时的旧决定——本次为设置页可控入口 + 发现新版才通知，非主动打扰式弹框）；
3. 更新源 = Gitee 仓库 raw 清单 + Releases 附件（与现有分发一致，国内直连）；清单 URL 常量集中 + 系统属性覆盖；
4. 自身版本读取用 META-INF/plugin.xml（绕开 PluginId 包迁移，与 ExecuteSqlSupport 同策略）；
5. 不做动态加载/免重启（T-M23.10 定论：环境 vetoer 否决覆盖更新的动态卸载）。

## 9. 演进方案（不实施）

- **方案 B（JetBrains 自定义插件仓库）**：产出 `<plugin-repository>` 格式 XML 托管，用户插件管理加自定义仓库 → 平台标准「检查更新」链路自动接管（含 IDE 原生安装/重启提示）。缺点：依赖用户手动加仓库、检查时机平台控制。若未来用户量增大可切换。
- **方案 C（上架 JetBrains Marketplace）**：平台原生自动更新最省事。前置：JetBrains 账号 + 插件审核 + 发布流程（M6 总计划 T-M6-05/06 已立项）。迁移时本功能清单 URL 改指向市场即可整体关闭。
