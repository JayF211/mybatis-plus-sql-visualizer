# 帮助页面暗色模式适配 + 设置树 & 转义修复

> **创建时间**：2026-09-02
> **优先级**：P1（用户体验）
> **影响范围**：1 个 HTML 资源文件 + 1 个 Kotlin 类 + 1 个 properties 文件
> **预计改动**：3 文件约 35 行

---

## 一、问题描述

### 1.1 帮助页面暗色模式异常

IDEA 切换为暗色主题（Darcula / New Dark）时，插件帮助页面（`marketplace-custom-page.html`）仍显示白色背景，与 IDE 暗色主题不协调。

### 1.2 设置树 "UI & Actions" 显示为方块

设置页左侧树节点 "UI & Actions" 中的 `&` 显示为 □（替换字符）。同样问题存在于 "Update & Diagnostics"。

---

## 二、根因分析

### 2.1 帮助页面暗色模式

**CSS 媒体查询机制**：`marketplace-custom-page.html` 使用 `@media (prefers-color-scheme: dark)` 实现暗色适配。该媒体查询读取的是**操作系统**的颜色方案设置，而非 IDE 主题。

**JCEF 不传递 IDE 主题**：帮助页面通过 `HTMLEditorProvider.openEditor()` 在 JCEF（内嵌 Chromium 浏览器）中渲染。JCEF 是独立 Chromium 实例：

| 层级 | 颜色方案来源 | 当前行为 |
|------|-------------|----------|
| 操作系统 | Windows "选择默认应用模式" | 可能为亮色 |
| IDEA 主题 | `EditorColorsManager` 全局 Scheme | 用户设为暗色 |
| JCEF 内嵌浏览器 | 读取 OS 的 `prefers-color-scheme` | 亮色（与 OS 一致） |

**关键矛盾**：Windows 用户常见配置是 OS 保持亮色、IDE 设为暗色。此时 JCEF 读取到 `prefers-color-scheme: light`，暗色媒体查询不触发。

### 2.2 设置树 & 显示为方块

`MpSqlVisualizerBundle.properties:368` 中 `settings.section.ui=UI & Actions` 含裸 `&` 字符。

IntelliJ 设置树（`SettingsTreeView`）在渲染节点时，`ConfigurableEP.getDisplayName()` 从 bundle 取值后，经 `SimpleColoredComponent.append()` 渲染。平台内部对显示名做 XML 实体解析：`& Actions` 被当作实体引用（`& Actions;`），解析失败产生替换字符 U+FFFD（显示为 □）。

**受影响条目**（properties 文件中所有含裸 `&` 的 key）：

| 行号 | Key | 当前值 | 显示结果 |
|------|-----|--------|----------|
| 368 | `settings.section.ui` | `UI & Actions` | UI □ Actions |
| 370 | `settings.section.updateDiagnostics` | `Update & Diagnostics` | Update □ Diagnostics |
| 261 | `settings.update.autoCheck.tip` | `...beta & early stable...` | 正常（tooltip 不解析实体） |

仅 368/370 两个设置树节点受影响。

## 三、修复方案

### 3.1 帮助页面暗色模式

**设计思路**：不改 JCEF 行为（无法控制 Chromium 的 `prefers-color-scheme` 来源），由 Kotlin 端检测 IDE 主题并注入暗色 class，CSS 同时支持 class 选择器。

#### 改动 1：`src/main/resources/html/marketplace-custom-page.html`

在 `<style>` 标签末尾（`</style>` 前）追加：

```css
/* === JCEF 暗色适配：class 注入（与 prefers-color-scheme 媒体查询并列）=== */
body.dark { color: #ccc; background: #2b2b2b; }
body.dark h2 { border-bottom-color: #444; }
body.dark table th { background: #2d2d2d; }
body.dark table td, body.dark table th { border-color: #444; }
body.dark code { background: #2d2d2d; }
body.dark .faq-question { border-color: #444; }
body.dark .faq-question:hover { background: #2d2d2d; }
body.dark .faq-answer { border-color: #444; }
body.dark .section-desc { color: #999; }
body.dark a { color: #58a6ff; }
body.dark hr { border-top-color: #444; }
body.dark .tag-new { background: #1a3a1a; color: #7ee787; }
body.dark .tag-beta { background: #3a2a0a; color: #ffa657; }
body.dark .tag-ultimate { background: #1a1a3a; color: #79c0ff; }
```

#### 改动 2：`src/main/kotlin/.../log/SqlLogPanel.kt`

在 `HelpAction.openLocalHtml()` 中增加暗色检测 + class 注入：

```kotlin
private fun openLocalHtml() {
    var htmlContent = loadText("html", "marketplace-custom-page.html")
    if (htmlContent.isBlank()) {
        LOG.warn("[HelpAction] Help HTML resource is empty, falling back to online doc")
        com.intellij.ide.BrowserUtil.browse(HELP_DOCUMENTATION_URL)
        return
    }
    try {
        // 暗色检测：IDE 主题为暗色时注入 class
        if (isDarkTheme()) {
            htmlContent = htmlContent.replace(
                "<body>",
                "<body class=\"dark\">",
                ignoreCase = true
            )
            LOG.info("[HelpAction] Dark theme detected, injected .dark class")
        }
        LOG.info("[HelpAction] Opening local help HTML via loadHTML")
        com.intellij.openapi.fileEditor.impl.HTMLEditorProvider.openEditor(
            project, HELP_TAB_TITLE, htmlContent,
        )
    } catch (ex: Throwable) {
        LOG.warn("[HelpAction] Failed to open local help HTML, falling back to online doc", ex)
        com.intellij.ide.BrowserUtil.browse(HELP_DOCUMENTATION_URL)
    }
}

/** 检测当前 IDE 是否为暗色主题。 */
private fun isDarkTheme(): Boolean {
    return com.intellij.openapi.editor.colors.EditorColorsManager
        .getInstance().globalScheme.dark
}
```

### 3.2 设置树 & 转义

**修复方式**：去掉 `&`，改用 `and`。

> 踩坑记录：
> - `\&`：Java properties 不识别，被当作字面量 `\&` 读取，仍然显示 □
> - `&&`：`DynamicBundle` 解析为 `&` 后，设置树渲染时又把 `&` 当助记符吃掉，显示为空
> - 最终方案：改用 `and`，彻底避开 `&` 解析问题

#### 改动 3：`src/main/resources/messages/MpSqlVisualizerBundle.properties`

```properties
# 修改前

settings.section.updateDiagnostics=Update & Diagnostics

# 修改后

```

## 六、风险评估

- **风险等级**：极低
- **影响面**：仅帮助页面样式 + 2 个 bundle key 值，不涉及功能逻辑
- **回滚难度**：git revert 单行提交即可
- **兼容性**：
  - `EditorColorsScheme.dark` 自 2020.3 起存在，当前基线 2024.3 完全支持
  - `\&` 转义是 IntelliJ `DynamicBundle` 标准语法，所有版本支持
  - class 注入是纯字符串替换，不影响 HTML 结构
  - 保留原有 `@media (prefers-color-scheme: dark)` 作为系统浏览器 fallback 双保险

## 七、备选方案（未采用）

### 帮助页面暗色

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| JavaScript 动态检测 | 可响应主题切换 | JCEF 无 `window.IDE` 对象，无法获取 IDE 主题 | ✗ 不可行 |
| CSS `color-scheme` + 系统级 | 标准方案 | JCEF 不传递 IDE 主题给 Chromium | ✗ 同根因 |
| 维护两套 HTML 文件 | 完全独立控制 | 双倍维护成本，内容同步风险 | ✗ 过度设计 |
| 在线 URL + 服务端暗色适配 | 零客户端逻辑 | 引入网络依赖，违背"零依赖"定稿决策 | ✗ 回退 |

### 设置树 & 转义

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 改用 `&amp;` | XML 标准 | `DynamicBundle` 不解码 HTML 实体，会原样显示 `&amp;` | ✗ 无效 |
| 改用 `&&` | Swing 风格转义 | IntelliJ 设置树不用 Swing 转义语法 | ✗ 无效 |
| 去掉 `&` 改为 `and` | 彻底避免 | 改变产品文案，影响搜索匹配 | ✗ 改变需求 |
| `\&` | IntelliJ DynamicBundle 标准转义 | 无 | ✓ 采用 |
