# 竞品分析与优化建议

**创建时间**：2026-08-22
**文档定位**：对当前插件定位、已有功能、竞品格局的全面分析，输出优化建议与新功能方向，作为 M30+ 立项依据。

> **当前基线**：v2026.8.21 已发行（HQL/JPA SQL 日志捕获双解析器架构 + 子查询 JOIN 反向解析 + Pageable LIMIT + @Query 路由 + JPQL IN 三层修复 + 测试体系加固）。

## 0. 当前插件定位

### 产品定位

> IntelliJ IDEA 插件：把 Java 源码中的 MyBatis-Plus / MPJ 调用静态解析为可预览 SQL，同时支持控制台日志一键还原、SQL 反向转 Java 代码。

核心差异化：**Wrapper 链 → SQL 的「执行前预览」**——市场上唯一能免费做到这一点的插件。

### 已有功能矩阵

| 能力域 | 具体功能 | 竞品对比 |
|--------|----------|----------|
| Wrapper→SQL 预览 | 11 种 WrapperType、9 种 Condition、Lambda/字符串/MPJ 全覆盖 | 独家，无竞品做到 |
| 动态条件面板 | 布尔重载 toggle、参数回填、foreach 值输入 | 独家 |
| 批量操作预览 | INSERT/UPDATE/UPSERT 按列展开、逐列勾选、saveOrUpdate 方言化 | 独家 |
| 逻辑删除注入 | @TableLogic 自动追加条件、MPJ 副表六方法控制 | 独家 |
| 乐观锁注入 | @Version 自动注入 | 独家 |
| XML 动态 SQL 预览 | if/choose/foreach/include/bind + OGNL 判真 | 仅 MybatisCodeHelperPro（付费）有类似能力 |
| 注解 SQL 预览 | @Select/@Update + Provider + `<script>` | 较弱 |
| SQL→Java 反向 | 选中 SQL 转 MP 代码（多形态可选） | 基础，MyBatisX 更强 |
| SQL 日志窗口 | 控制台捕获还原、双击预览 | 与 MyBatis Log Plugin 同质化 |
| SQL 补全 | 表名/列名/#{} 参数名 | 较弱，MyBatisX 更强 |
| 方言支持 | 9 种（含国产达梦/人大金仓） | 覆盖面最广 |

## 1. 竞品详细对比

### 1.1 竞品格局

| 插件 | 定价 | 核心能力 | 短板 |
|------|------|----------|------|
| MyBatis Log Plugin | 免费 | 控制台日志捕获 + 参数还原 | 仅执行后，无预览，无框架感知 |
| MyBatisX（官方） | 免费 | Mapper-XML 双向导航 + 代码生成 | 无 SQL 预览，无日志还原 |
| MybatisCodeHelperPro | 付费（~$15-30） | 代码生成 + 基础 SQL 预览 | 付费阻力大，无 Wrapper 可视化 |
| Mybatis-Friend | 付费（~$19） | SQL 可视化 | 市场份额极小 |
| mybatis-builder | 免费 | MyBatis Generator GUI | 仅代码生成，无预览/日志 |

### 1.2 关键市场空白

1. **Wrapper→SQL 执行前预览** — 完全空白，当前插件唯一
2. **XML 动态 SQL 静态渲染** — 仅付费竞品有基础能力
3. **可视化 JOIN 关系图** — 有 Web 产品验证需求，IDEA 内空白
4. **国产数据库方言** — 达梦/人大金仓支持，其他插件均无
5. **SQL 性能诊断** — 所有竞品均无

## 4. 战略建议

### 核心策略

> 守住「执行前预览」壁垒，向「SQL 诊断平台」演进。

### 演进路线

```
Phase 1（当前）    Phase 2（3-6月）      Phase 3（6-12月）
─────────────────  ──────────────────   ─────────────────────
Wrapper→SQL 预览    + JOIN 可视化图       + 执行计划模拟
XML/注解预览        + 复杂度评分          + 拦截器模拟
日志还原            + Kotlin 支持         + 团队 SQL 共享
SQL→Java 反向       + 智能补全            + SQL 诊断规则市场
```

### 不建议做

1. **代码生成** — 不与 MyBatisX 正面竞争
2. **数据库连接管理** — IntelliJ Ultimate 已有
3. **Spring 导航** — 与 MyBatisX 重叠

## 5. 后续步骤

本文档为立项依据，具体实施需逐项调研后制定子计划。调研方向：

1. MyBatis-Plus 官方文档 + 本地 jar：确认拦截器 API、KtWrapper API
2. MPJ 官方仓库：确认 fill 等新 API
3. 可视化方案：Graphviz/PlantUML/Mermaid 在 IDEA 内的集成方式
4. SQL 解析/分析：开源 SQL 解析器（JSqlParser/Calcite）的适用性
5. IntelliJ 平台：代码补全 Contributor API、ToolWindow API
