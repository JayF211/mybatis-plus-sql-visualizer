# M37.3 会话感知捕获与面板体验开发计划

> **创建日期**：2026-09-02
> **归属**：P-立项-06
> **对应项**：N-3 + O-4
> **优先级**：P1

---

## 一、现状与目标

### 1.1 现状

- **捕获开关已外显**（本计划不重做）：`SqlLogPanel.CaptureAction`（Execute/Suspend 图标随 `capturing` 切换，经 `manager.addCapturingListener` 刷新）；工具窗隐藏自动停捕已有（`ToolWindowVisibilityListener` + `logStopOnToolWindowClose`）。
- **启动自动捕获已有**：`log/LogStartupCapture.kt`（ProjectActivity，重试 3 次）+ 设置 `logAutoCaptureOnStart`——但语义是「IDE 启动即捕获」，不感知 Run/Debug 会话。
- **无 ExecutionListener**；已有 messageBus 编程注册先例：`SqlLogToolWindowFactory`（ToolWindowManagerListener.TOPIC）与 app 级 `PluginSettings.SETTINGS_CHANGE_TOPIC`。
- **无面板状态恢复**：条目在内存 `SqlLogEntryBuffer`，重启仅历史 Tab 靠落盘文件间接可见。
- **设置扩展路径清晰**：`config/PluginSettings.kt`（State）→ `PluginSettingsPanel`（SECTION_SQL_LOG）→ `SectionConfigurable`（SqlLogConfigurable）→ bundle 平铺 key。

### 1.2 目标

1. Run/Debug 会话启动 → 自动进入捕获态（新设置项，默认开）。
2. 会话内首条 SQL 出现 → 自动展开工具窗（新设置项，默认开；每次会话只展开一次）。
3. IDE 重启后恢复工具窗上次可见状态。

### 1.3 非目标

- 不改三族解析与缓冲逻辑。
- 不做会话级日志归档（已有智能分组覆盖）。

## 二、实现设计

### 2.1 会话感知（`log/RunSessionCaptureListener.kt` 新增）

- 编程订阅 `ExecutionListener`（`project.messageBus.connect(disposable).subscribe`，plugin.xml 不支持 listener topic 的铁律）：`processStarted` → 满足设置则 `SqlLogManager.startCapture()`（幂等：`capturing` 已真则跳过）。
- 与 `logAutoCaptureOnStart` 的并存语义：任一命中即 armed，不互相覆盖；`userArmed` 语义不变。

### 2.2 首条 SQL 自动展开

- `SqlLogManager` 新增「首条 SQL 入缓冲」回调（参照既有 `addCapturingListener` 的 listener 模式）：本次会话（processStarted 起计）首次条目入 `SqlLogEntryBuffer` 时触发一次。
- 动作：`ApplicationManager.getApplication().invokeLater`（EDT）→ `ToolWindowManager.getToolWindow(id).show()`——**show 不 activate**，不抢编辑器焦点。
- 防打扰：会话生命周期标记 + 设置项 `logAutoShowOnFirstSql`（默认 true）。

### 2.3 设置项

`PluginSettings.State` 新增 `logCaptureOnRunSession`（默认 true）、`logAutoShowOnFirstSql`（默认 true）；沿 State → Panel（SECTION_SQL_LOG）→ SqlLogConfigurable → bundle 中英四步走。

### 2.4 工具窗状态恢复

工具窗 show/hide 时记录布尔到 `PluginSettings.State`（`logToolWindowVisibleOnExit`，project 无关的应用级即可）；`LogStartupCapture` 启动尾段按记录恢复 show。轻量，不引入新存储。

## 四、验证

- 单测：startCapture 幂等（重复 processStarted 不破坏状态机）；设置项默认值与持久化往返。
- 真机沙盒：跑带 SQL 的 Spring Boot 会话 → 自动展开且首条 SQL 已捕获；关闭开关后行为静默；IDE 重启面板恢复。
- 并行会话（两个 Run 同时启动）不重复展开。

## 五、风险

1. **ExecutionListener 回调线程非 EDT**——所有 UI 动作 invokeLater 包裹。
2. **自动展开打扰**——默认开但可关；单会话单次；show 不 activate 三重约束。
3. **与 M36.5 并行会话遗留经验呼应**——展开逻辑必须挂在「本项目工具窗」，避免多项目窗口串扰。
