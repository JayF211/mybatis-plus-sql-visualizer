# 参数面板布局修复 + 表名推断/忽略字段/移除表名前缀后缀——开发计划（M19.4）

> 本文档是 **MyBatis-Plus SQL Visualizer** 的 M19.4 增量计划：用户实测报告的一个布局缺陷
> （参数名较长时左侧参数显示不全）与三项设置增强（表名推断策略 / 忽略字段名 / 移除表名前缀后缀、
> 现有添加项支持多值）。
>
> 当前基线：M19.3 已提交（264 测试全绿）。

---

## 1. 需求与根因（2026-08-13）

### 1.1 参数名较长时左侧参数显示不全（布局缺陷，用户实测）

**用户症状**：面板左侧参数区显示不全（如 `#productInfo.getDicProtocolType()` 这类长参数名），
输入框贴太近。

**根因**（`SqlPreviewPanel.buildParamRow`）：

```kotlin
add(JBLabel("#$source").apply {
    preferredSize = Dimension(140, preferredSize.height)   // ← 标签固定宽 140px
})
```

- 标签 `preferredSize` **固定 140px**——参数名超过即被截断显示不全；
- 行容器 `FlowLayout(FlowLayout.LEFT, 4, 2)`——水平/垂直间距过小（4/2px），视觉"贴太近"。

**修复**：标签宽度**按文本自适应**（FontMetrics 计算，夹在 140~300px），超长加 tooltip 全名；
间距 `(LEFT, 4, 2)` → `(LEFT, 8, 6)`；标签超出面板宽度时 FlowLayout 自然换行（输入框换到下一行），
不截断。

### 1.2 无 `@TableName` 时的表名推断策略（设置增强）

**现状**（`EntityResolver.resolve`）：

```kotlin
val tableName = annotationValue(entityClass, TABLE_NAME) ?: NamingStrategy.toSnakeCase(className)
```

固定驼峰转下划线（`BikeDeviceInfoEntity` → `bike_device_info`）。用户场景：实体驼峰命名但
数据库表**没有下划线**（如 `bikeDeviceInfo`）——推断结果与真实表名不匹配。

**方案**：设置新增「表名推断策略」下拉（`tableNameInference`）：

| 值 | 语义 | 示例（`BikeDeviceInfoEntity`） |
|----|------|------------------------------|
| `SNAKE`（默认，对齐 MP） | 驼峰转下划线 | `bike_device_info_entity` |
| `CAMEL` | 纯保留驼峰：仅首字母小写，**不去 Entity 后缀**（用户反馈定稿） | `bikeDeviceInfoEntity` |

`@TableName` 显式表名不受影响；`EntityResolver` 推断点接入设置（`runCatching` 兜底默认 SNAKE）。

### 1.3 忽略字段名（设置增强，`;` 分隔）

用户诉求：实体中部分字段不想出现在 SQL（未标 `@TableField(exist=false)` 时也能自行排除），
设置中配置「忽略字段名」，多个用 `;` 分隔。

**方案**：设置新增「忽略字段名」（`ignoredFields`），按 Java **字段名**匹配：
`EntityResolver.resolveColumn` 中字段名命中忽略列表 → 返回 null（跳过）——SELECT 全列展开、
参数对照、补全列集合均不含该字段。

### 1.4 移除表名前缀/后缀 + 现有添加项支持多值（设置增强）

用户诉求：
- 新增「移除表名前缀」「移除表名后缀」（多个用 `;` 分隔）——如实体 `TBikeDeviceInfoEntity`
  推断 `t_bike_device_info`，真实表名 `bike_device_info`；
- 现有「表前缀/表后缀」（添加）**升级支持多值**（`;` 分隔）。

**方案**（`EntityResolver` 统一修饰链，`@TableName` 显式表名同样生效——沿用 T-M16.2-03 全局语义）：

```
最终表名 = 添加前缀们 + 移除后缀(移除前缀(表名)) + 添加后缀们
```

| 配置 | 多值语义 |
|------|----------|
| `tablePrefix`（添加） | `;` 分隔**按序拼接**：`t_;sys_` → `t_sys_xxx` |
| `tableSuffix`（添加） | `;` 分隔**按序拼接**：`_log;_bak` → `xxx_log_bak` |
| `removeTablePrefix`（移除） | `;` 分隔，表名以哪个开头就**移除哪个**（首个匹配） |
| `removeTableSuffix`（移除） | `;` 分隔，表名以哪个结尾就**移除哪个**（首个匹配） |

示例：实体 `TBikeDeviceInfoEntity`（SNAKE 推断 `t_bike_device_info`）+ 移除 `t_` →
`bike_device_info`；再添加 `sys_` → `sys_bike_device_info`。

## 2. 设置页新增项汇总（4 项）

| 行 | 控件 | State 字段 | 默认 |
|----|------|-----------|------|
| 表名推断策略 | 下拉（自动驼峰转下划线 / 保留驼峰） | `tableNameInference` | `SNAKE` |
| 忽略字段名 | 文本（`;` 分隔） | `ignoredFields` | `""` |
| 移除表名前缀 | 文本（`;` 分隔） | `removeTablePrefix` | `""` |
| 移除表名后缀 | 文本（`;` 分隔） | `removeTableSuffix` | `""` |

均接入 `PluginSettingsPanel` 的 `isModified()/apply()/reset()` 联动（沿用表前缀/表后缀行样式）。

## 4. 风险与应对

| 编号 | 风险 | 影响 | 应对 |
|------|------|------|------|
| M19.4-R1 | 推断策略/移除配置与 `@TableName` 显式表名叠加语义不清 | 表名错误 | 明确：推断策略仅作用于**无注解推断**；移除/添加作用于**最终表名**（含显式）；文档与 tooltip 说明 |
| M19.4-R2 | 移除前缀误伤（表名恰好以配置前缀开头但非预期） | 表名错误 | 移除仅首匹配、大小写敏感；用户自查配置；测试覆盖边界 |
| M19.4-R3 | 忽略字段名与 `@TableField(exist=false)` 语义重叠 | 冗余配置 | 两者并存（注解优先）；忽略仅补充 |
| M19.4-R4 | 多值 `;` 分隔与表名本身含 `;` 冲突 | 解析错误 | 项目约定 `;` 为分隔符；文档说明 |
