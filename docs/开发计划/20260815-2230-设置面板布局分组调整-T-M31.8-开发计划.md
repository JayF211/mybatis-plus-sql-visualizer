## 1. 需求

用户要求调整设置面板（`Settings → Tools → MyBatis-Plus SQL Visualizer`）布局：
1. **高频重要选项在上方，低频不重要在下方**；
2. **相似同类的设置放在一起**（分组）；
3. **加分类分隔线**——样式参考 SQL 预览面板左侧参数区（`TitledSeparator` 短标题 + 分隔线，T-M26.3 已按 IDEA Group Header 惯例落地，见 `ui/SqlPreviewPanel.kt:734-740`）。

## 3. 分组方案（5 组，从上到下 = 高频 → 低频）

| 分组（TitledSeparator 标题） | 包含设置项 | 频率理由 |
|------------------------------|-----------|:-------:|
| **SQL 预览** | 数据库方言 / 替换 ? 占位符 / 格式化输出 / 逻辑删除注入 | 最高频（每次预览都相关） |
| **表名映射** | 表前缀 / 表后缀 / 移除表名前缀 / 移除表名后缀 / 忽略字段名 / 表名推断策略 | 预览相关但低频（配置一次长期不变） |
| **代码生成** | SQL 反向转换默认 Wrapper 形态 | 低频（反向转换功能配置；后续生成类设置并入此组） |
| **界面与操作** | 代码左侧显示预览图标 / 界面语言 / 快捷键 | 低频（环境偏好） |
| **更新与诊断** | 更新分区（UpdateSection）/ 内部构建号 | 最低频（更新按需、构建号仅反馈时用） |

i18n 新增组标题键（双语）：`settings.section.preview / tableMapping / codeGen / ui / updateDiagnostics`。

## 4. 实现方案

### 4.1 布局结构（`PluginSettingsPanel.buildRows` 重构为 `buildSections`）

```
rootPanel (GridBagLayout, 2 列)
├─ gridy=n:   TitledSeparator(「SQL 预览」)   gridwidth=2, fill=HORIZONTAL
├─ gridy=n+1: sectionPanel(「SQL 预览」组)    gridwidth=2, fill=HORIZONTAL
│              └─ 内部 GridBagLayout 2 列：addRow(标签, 控件) × 4
├─ ... 每组一个 TitledSeparator + 组面板
└─ 底部 weighty 占位（沿用 M14.1 顶对齐）
```

- `addRow` 改为对**组面板**添加（函数参数化：`addRow(panel, label, component)`）；
- 组面板内部复用现有 GridBag 两列约束（insets 4,6）；
- 复选框/字段**实例复用不变**（M19.2 语言切换即时刷新：`buildSections` 每轮重设文本，rebuild 时随语言刷新——组标题 TitledSeparator 同样每轮重建）；
- 组面板背景与根面板一致（不设边框，仅 TitledSeparator 分隔——对齐 SQL 预览面板左侧分区样式）。

## 6. 风险与对策

- **headless 渲染断言**（既有教训：headless 不布局、peer null）：分组断言只做**组件存在性/文本收集**（TitledSeparator 是普通 JComponent，可递归收集），不做布局坐标断言。
- **语言切换 rebuild 回归**（M19/M19.1 历史坑：ActionEvent 中途改组件树失效）：组标题与组面板随 `buildSections` 整体重建，沿用 invokeLater 调度——定向手动验证（沙盒）语言切换后分组标题即时刷新。
- **UpdateSection 组件嵌套**：作为「更新与诊断」组的整行（gridwidth=2）放置，不改其内部结构（UpdateSectionTest 不受影响）。
