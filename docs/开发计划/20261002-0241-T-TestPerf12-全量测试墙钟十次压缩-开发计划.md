## 二、目标与红线

**目标**：warm 全量（`./gradlew testShards` 单路）墙钟较本轮基线可测量下探。达标判据：
- 墙钟中位较基线中位 **−5% 以上**（同窗交错 A/B 口径；窗口漂移带 ±5~8%，T5 定例）；预期落点 2m38s 带 → ~2m20s 带（−15~20s）。
- 未达判据时如实入账：定案实验（S1）的结论本身是交付物（结构性因素是否可补偿的最终裁决），补偿旋钮留档不落默认。

**红线**：
1. 零删例、零测试源码改动（断言一个不动）、零 `src/main` 改动。改动面限：`buildSrc/src/main/kotlin/mpv-testing.gradle.kts`、`gradle.properties`（旋钮与销账注释）、`dev-support/`（如有）、docs。
2. 已销案路线不重开；S1 对调实验是 T11 指定的定案入口，不是翻案。
3. 计时纪律照抄：全机只跑一路 test、跑前 `python parallel_tasks.py check` 登记 + `timeout 10 docker info` + **Commit 余量 ≥12GB**（T11 新协议：余量 <12GB 避免冷跑类重活）、效应 <10% 必须**同窗交错 A/B**、失败轮先收证再跑下一轮。
4. 失败集合恒等判据：基线＝dev tip 门禁三轮定案 6370/0/0/9 全绿（cb1520b，其后仅 docs 两笔）→ 实验轮期望 0 失败恒等；若实施期出现既有红，判据退为「失败集合逐轮恒等」并先收证。
5. 临时探针（对调旋钮）定案后从代码删除，销案记录入本计划；不随提交留在 mpv-testing.gradle.kts。

## 三、方案

### S0 机制代码与基线轮（准备件+数据件）
一次上齐三件独立提交的改动（默认全关、缺省行为与 dev tip 逐字节等价）：
- ① 对调探针：`-PtestShardSwapProbe=true` 时交换 shard1/shard2 类清单与 loads（S3 拆分默认关、探针轮禁开拆分，避免片段映射交叉）。诊断轮专用，定案后删。
- ② 槽位补偿系数：`-PtestShardHandicap=<因子>` + `-PtestShardHandicapTarget=<槽位号>`，均衡器贪心比较键 `loads[i]/factor[i]`（目标槽位负载被放大比较→更早判满→少装），聚合 expected 行追加补偿标注。默认无补偿。
- ③ 告警漂移归一化：缺权告警判据从「actual_crit > expected_crit×1.10」改为相对散布判据 `rel_crit=(actual_crit/expected_crit)/(Σactual/Σexpected)>1.10`（自参照、零跨轮状态、漂移免疫）；失衡告警（12% 同轮相对量）不动。
然后 warm 基线轮 R1（全关＝现状），记录：BUILD 墙钟、各片 exec、临界片、SHARD TOTAL 计数、parity、告警行。基线读数同时充当 S2 的 A 侧样本。

### S1 shard2 结构性临界定案（核心裁决件）
R2 对调轮：`-PtestShardSwapProbe=true` 跑一轮 warm。判读：
- 临界翻转到 shard1（跟清单走）→ 权重/清单构成问题 → S2 转修权重源（画像刻度 vs 本机执行刻度的系统性偏差，定位偏差类族修正）；
- 临界仍留 shard2（跟槽位走）→ 环境因素（OS 调度/核分配，仓内无根除杠杆）→ S2 上槽位补偿系数。
- 两片差 <5%（翻转不明确）→ 判「混合因素」，S2 保守：只留旋钮不落默认，如实入账。
判读力依据：T11 六轮 shard2 恒临界 + 本轮一轮对调；若对调后 shard1 变临界，结论可信；若 shard2 第七轮仍临界，「环境因素」钉死。

### S2 临界片补偿（核心压缩件，按 S1 定因择形）
环境因素路径（预期主路径）：补偿目标槽位=shard2，因子按 S1 实测幅度**保守取值**（六轮中位 +17%，取保守下界 ~0.87 起步），同窗交错 A/B 各 ≥2 轮（R3 补偿开/R4 补偿关/R5 补偿开，与 R1 基线合并为 A 侧）。
- 达标（墙钟中位 −5% 以上 + 失败集合恒等 + 计数 parity 恒等）→ 落默认（gradle.properties 写死默认值+销账注释），收口轮验证默认态；
- 不达标 → 旋钮保留、默认关，销案证据入册。
权重因素路径（若 S1 如此定案）：修正权重源后同样 A/B 判据，不引入补偿系数。
补偿落默认的过补防线：失衡告警是同轮相对量，补偿过度会立刻以「新临界片」形态现形；默认值宁欠勿过（欠补偿只损失部分收益，过补偿制造新失衡）。

### S3 告警漂移归一化验证（可靠性件，随 S0 提交）
聚合代码在 doLast 内联（配置缓存约束，不可抽函数），验证走：构造三组 XML 样本目录（正常带/全局漂移/真失衡），python 按同款公式手算预期行为对照；再对真实轮读数回归（T11 漂移窗形态下新判据应静默，S2 过补实验若制造真失衡应仍鸣）。weight-refresh.ps1 的污染闸独立，不受影响。

### S4 收口
默认态全量门禁权威一轮（新配置落定后）；评估是否需要 weight-refresh 刷画像（负载分布因补偿搬家，画像语义是「类执行时长」与片位无关，预判不刷，留档判断）；文档三处同步（本计划 §六回填、经验总结新篇「十次压缩」、变更记录台账行）；分 hunk 提交（`T-TestPerf12` 前缀，`git commit -F` 文件式信息）；分支 push 留底；**不自动并 dev/master，报告待用户处置**。

### 已评估不立项清单（防复立项）
- 编译税（冷跑 ~2.5min）：属 build 面，与 0710 计划 P1-3 车道重叠，避撞车；warm 场景占比极小。
- 线程面组合旋钮转正：execSum −5.7% 不转化墙钟（T11 定案），本轮判据是墙钟。
- 6 片：Commit 硬判据未变，T10 豁免论证继续适用。
- S3 巨类拆分重开/扩容：负 EV 销案维持（T10），候选仍唯一且已不可达。
- 片内多 fork/纯逻辑分桶/testExternal 扩容：PersistentFS 互踩/5.3% 占比/平台型不可移，销案维持。
- agent:test 与分片并行化：dependsOn 图本就并行，42.5s 早收不卡墙钟。
- shard2「根除」：若 S1 定案为环境因素，仓内无合法杠杆改 OS 调度（T11 已注记「改任务启动序属 hack」），补偿是唯一合法路径。
- 告警判据放宽到 15%（T11 §五.4 方案 A）：阈值魔法数换魔法数，选方案 B（相对散布归一化，机制性免疫漂移）。

## 四、待验证前提（实施者先证伪再动手）

- **V49 对调探针判读力**：预判一轮对调+六轮历史足以定案。证伪点：若对调后临界幅度仍 <5% 或方向混乱，判「混合因素」→ S2 只留旋钮不落默认。
- **V50 补偿系数接线不破坏确定性与配置缓存**：`loads[i]/factor[i]` 比较键保持确定性（并列取最小下标次序不变）；factor 经 gradleProperty 读入，与 testShardCount 同款顶层声明模式，无脚本对象进 doLast（聚合只读 inputs.property 固化串+补偿标注串）。证伪点：配置缓存拒收或双开终端分区不一致。
- **V51 shard2 结构性幅度跨窗口稳定**：+14~22% 带内（六轮+夜间漂移窗）。证伪点：若 S1 对调轮显示幅度随窗口漂移剧烈（如 >25% 或 <8%），保守因子重新取值。
- **V52 告警归一化不误伤 weight-refresh 闭环**：预判 ps1 污染闸与判据独立。证伪点：归一化后真失衡（新类缺权形态）不再触发缺权告警——构造样本必须覆盖「单类缺权」形态并确认仍鸣。
- **V53 dev tip 失败集合＝空**：依据 cb1520b 门禁三轮定案 6370/0/0/9 全绿，其后 dev 仅两笔 docs。证伪点：R1 基线轮出现失败 → 判据退「逐轮恒等」并先收证（RED PROBE 纪律），不得带病比较。
- **V54 本树画像输入**：本树 `build/test-results` 零历史 → 均衡器吃 `dev-support/test-shard-weights.tsv`（559 类）+中位数插值，R1 起逐轮自喂养（K=2 本地优先）。预判 R1 即为画像均衡态（T11 画像刚刷新过）。证伪点：R1 出现失衡告警 → 先刷一轮本地数据再取基线（基线必须取自画像稳态，否则 A/B 两侧不对称）。
