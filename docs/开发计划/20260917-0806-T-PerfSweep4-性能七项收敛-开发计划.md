## 一、背景与依据

第六轮复查的最大变化是 M56 agent 全链合入带来的常驻面扩张（自有线程 2→4、新增 5s 巡检、常驻 consoleFilterProvider），空载成本经审读仍可忽略；但增强捕获默认开与「拒绝不持久化」的组合让拒绝注入的用户每进程启动挨一次模态弹窗，属默认配置可达路径的交互打断，系列六轮首个「高」级发现。捕捉开启的主流时序还存在 EP+桥双路解析的恒定 ×2 CPU 税。

2026-09-18 第七轮复查（锚点 9def321→4d63a1b，48 提交：预览链根治批次 / SQL 历史全量落盘 / T-SourceJumpFunnel / 构建分治）确认上轮十项**零修复全部在册**，同时新增 2 中 + 2 中低 + 6 低——应用侧每条 SQL 双栈捕获且 fat jar 下缓存防合流设计退化为每执行全量重扫（用户应用 JVM 体验面）、历史保留裁剪删除面过宽（数据安全）、F5 应用级监听裸装不卸载、showSql 写点 P4 闸门前提不成立等。经并账扩项进本计划（T-PS4-09~14）：T-PerfSweep4 尚未实施，两轮发现一次收口、一道门禁，避免两个未实施 sweep 计划并行的管理成本。扩项同时不改变原七项的修法方向。

## 三、方案

**T-PS4-01（确认流语义修正，高）**：两步组合——
1. 触发面收窄：`onProcessAppeared` 的确认弹窗（未 confirmed 分支）仅对主配置启动触发（复用 `isModuleBasedLaunch` 判定，`RunConfigurationProcessListener.kt:101-110` 已有同款），HTTP/测试/profiler 进程静默跳过；已 confirmed 的 attach 链路维持现状（增强捕获主通道语义不变）。
2. 拒绝冷却：拒绝后记冷却时间戳（application 级设置字段或非持久静态，倾向持久化「拒绝时刻」，冷却窗建议 24h——实施时定案并注释），冷却期内同项目不再重复弹；设置页关闭再开启增强捕获时重置冷却，保留用户改主意的入口。
3. 守护测试：拒绝→冷却期内 N 个进程启动零弹窗（consentProvider 计数断言，测试替换 provider 惯例已有）；冷却过期后再弹一次；同意后 confirmed 持久化永不弹。

**T-PS4-02（双路解析封口，中）**：桥 `LogFilterProxyHandler` 内首行加 `SqlCaptureGate.epActive` 短路（平台 filter 链中 EP 先于后挂的桥 filter 执行，行到达时 epActive 必已置位，短路不漏捕）；EP `EpLineFilter` 的 timePrefix 读取接入 per-console 缓存字段（对齐桥侧 timePrefixCache 形态，`SqlLogConsoleBridge.kt:409-412`），configProvider 快照刷新时失效。行为语义零变化：双轨窗口收敛为「桥挂载前到达的首行之前」，条目仍靠缓冲去重兜底。测试：EP+桥双 filter 并发喂行，断言条目解析单路化（计数/日志探针）且捕捉结果与单路一致。

**T-PS4-03（attach 链治理，中低）**：pendingPids 去抖真实化（同 pid 3s 内重复启动不重复排队，声明处 `:64` 注释兑现）；extractAgentJar 提取一次缓存到服务字段复用（deleteOnExit 仅登记一次）；sweepOffline 摘除死会话时顺带 `attachedPids.remove(pid)`。跨 pid 的 3s sleep 串行维持（等应用初始化的合理去抖），加注释说明单线程池串行性质。

**T-PS4-04（正则提常量，一行×2）**：`AgentEventAdapter` 两条正则提 companion 常量；`LogSqlModels.normalizeSqlWhitespace` 的 `\s+` 提文件级 private val（注意该函数被 dedupeKey lazy/stampLogTime/桥嗅探三路共用，提常量即三路同时受益）。守护测试断言走常量引用（照 JdbcTemplateLogParser companion 先例测试形态）。

**T-PS4-05（签名截断，中低）**：`logTimeParamSignature` 对每个参数值截断（上限建议 256 字符，实施时定案）后再 join——两侧（桥嗅探 put 与 agent take）走同一函数天然等价；次级判别失配本就设计为退化为队首配对（`LogTimeCorrelator.kt:16-17` 注释），语义风险可控。同步修正 KDoc `:29` 的量级口径。测试：超长参数（>256 字符）构造 put/take 配对命中断言。

**T-PS4-06（重放守卫区间读 + 并账复核）**：line0Reader 求值分支改 `getCharsSequence` 首行区间读（`[0, 首个\n)`），stamp 缓存语义保持；历史断言逐字复刻防行为漂移。并随合流窗口复核 T-PerfSweep3 #2/#3 的 dev 修复（第六轮报告 §3.1 表逐项销账回填）。

**T-PS4-07（WrapperCache 淘汰，五轮在册）**：容量上限 + LRU（上限取单项目预览产物现实量级上界并注释依据）或按项目挂 Disposer 关闭清空；实施前先实测 dev 是否已由 T-PerfTail 收口（若已收口本任务转复核销账）。Disposer 路线须注册到父 disposable 树（Memory leak detected 教训）。

**T-PS4-09（应用侧栈捕获收敛，中·第七轮扩项）**：四件组合——
1. 一次捕获两用：`StackLocator.locate` 已持有本次栈快照（`StackLocator.java:103`），增加携栈出口（或 `StackDigest.build` 加数组入参重载），`StatementHandler.java:137` 不再第二次 `getStackTrace`；类头 `:18`「只在 execute 取一次」注释随之恢复为真。
