# Kotlin → Java 全量改写开发计划

> **状态**：已被 v2 取代（见 `20260831-2350-Kotlin转Java全量改写-开发计划v2.md`）
> **创建日期**：2026-08-27
> **评估人**：ZCode Agent
> **涉及文件**：210 主源 + 185 测试 = 395 个 Kotlin 文件（**数字已过期，以 v2 实测为准**）

---

## 1. 背景与目标

### 1.1 背景

当前插件 `mybatis-plus-sql-visualizer` 全部以 Kotlin 实现（210 个主源文件 + 185 个测试文件）。出于团队技术栈统一（纯 Java）的未来可能性，评估是否可以将插件**全量改写为纯 Java** 而不损失任何现有功能。

### 1.2 目标

- **功能 100% 等价**：改写后所有功能（SQL 预览、双向转换、日志捕获、直接执行、设置页、JOIN 图、性能分析等）保持现状行为不变
- **零外部依赖新增**：不引入新的运行时三方库（编译期工具除外）
- **构建与发布流程不变**：`buildPlugin` / `verifyPlugin` / `runIde` 等核心流程行为等价
- **测试全部迁移**：185 个测试文件转换为 Java 表达，覆盖率不下降

### 1.3 不在范围内

- 不改功能、不改架构、不改 UI 交互
- 不新增第三方运行时依赖
- 不调整平台版本基线（仍 243+）

## 2. 可行性结论

### 2.1 功能可实现性

| 结论 | 说明 |
|------|------|
| ✅ 100% 可实现 | 代码库中**没有任何 Kotlin 特性在 Java 中无对应表达** |

每一个已使用的 Kotlin 特性都有等价的 Java 写法（Java 17 为基准）。详细映射见 §3。

### 2.2 风险与代价

| 维度 | 评估 |
|------|------|
| 工时 | **~200 小时**（395 文件 × 平均 30min/文件，纯人工转换 + 人工验证，不含调试） |
| 回归风险 | **高**——data class 的手动 equals/hashCode 易遗漏边界，null 安全编译期保障丧失 |
| 收益 | **零**——用户无感知、Marketplace 审核无偏好、运行时性能无差异 |
| 测试返工 | **高**——185 测试需全部重写并通过，heavy 测试需重新跑 runIde 沙盒 |

### 2.3 建议

**不建议实施**。唯一合理场景：团队完全不具备 Kotlin 能力且未来不会引入 Kotlin 人才，同时插件需 5 年以上长期维护。即便如此，更务实的方案是「新代码用 Java、存量 Kotlin 不动」（二者完全互通），而非一次性全量改写。

## 3. Kotlin → Java 特性映射表

### 3.1 语言结构层

| Kotlin 特性 | 出现次数 | Java 替代方案 | 转换难度 | 风险点 |
|------------|---------|--------------|---------|--------|
| `data class` | 176 | Java 17 `record`（简单场景）/ Lombok `@Data` 或手写 equals+hashCode+copy | 🔴 高 | record 不可变且不能继承；手写易漏字段；copy() 需逐个实现 |
| `sealed class/interface` | 14 | Java 17 `sealed` + `permits` + `switch` 模式匹配 | 🟢 低 | 语法结构几乎一一对应 |
| `when` 表达式 | 258+106 | Java 17 `switch` 表达式/模式匹配/箭头语法 | 🟢 低 | `when` 多条件逗号分隔需展开为 `case A, B ->` |
| `enum class` | 31 | Java `enum` | 🟢 低 | 直接对应，含构造函数和方法也等价 |
| `object` 单例 | ~25 | 私有构造 + `static final INSTANCE` 字段 / 枚举单例 | 🟢 低 | 需处理初始化时序 |
| `companion object` | 63 | `static` 字段/方法 + 私有构造 | 🟢 低 | 直接对应 |
| `object` 表达式（匿名） | 56 | 匿名内部类 | 🟢 低 | Java 8+ 匿名类等价 |
| `override` | 403 | `@Override` 注解 | 🟢 低 | 直接对应 |
| `internal` 可见性 | 238 | 包级私有（无修饰符） | 🟢 低 | 模块系统下需确认 exports |
| `private` | 1897 | `private` | 🟢 低 | 直接对应 |

### 3.2 空安全与类型系统

| Kotlin 特性 | 出现次数 | Java 替代方案 | 转换难度 | 风险点 |
|------------|---------|--------------|---------|--------|
| `isNullOrBlank` 等空工具 | 64 | 手动 `!= null && !isBlank()` / Apache Commons `StringUtils` | 🟡 中 | 需全面引入 null 检查或引入三方库；遗漏即 NPE |
| `?.` 安全调用 / `?:` Elvis | 散布各处 | `if (x != null)` 展开 / `Optional.orElse()` | 🟡 中 | 链式调用展开后嵌套深度增加 |
| 智能转换（`is` 后自动转换） | 各处 | 显式类型转换 `(Type) obj` | 🟡 中 | 转换错误 → ClassCastException |
| `?.let {}` 作用域 | 散布 | if 非 null 块 / 临时变量 | 🟢 低 | 展开后多一两行 |

### 3.3 函数式与表达式

| Kotlin 特性 | 出现次数 | Java 替代方案 | 转换难度 | 风险点 |
|------------|---------|--------------|---------|--------|
| scope fn (`let`/`also`/`apply`/`run`) | 332+225+1 | 内联代码块 / 临时变量赋值 | 🟡 中 | 嵌套链展开后失去流畅性；`apply` → 需手动 `return obj` |
| extension function（顶层） | ~10 | 静态工具方法（接收者作为首参） | 🟡 中 | 调用点全量修改（`obj.ext(arg)` → `Util.ext(obj, arg)`） |
| string template `${}` | 358 | `+` 拼接 / `String.format()` / `MessageFormat` | 🟡 中 | 复杂模板可读性下降 |
| destructuring `(a, b) = ...` | 23 | 手动字段提取 `val a = obj.a; val b = obj.b` | 🟡 中 | 多字段时冗长 |
| `buildString {}` | 15 | `StringBuilder` + `append()` 链 | 🟢 低 | 直接对应 |
| range `0 until n` | ~10 | `IntStream.range(0, n)` / for 循环 | 🟢 低 | 直接对应 |
| `to` infix (`"a" to 1`) | 散布 | `AbstractMap.SimpleEntry` / 自定义 Pair 类 | 🟢 低 | Map 构建场景可用 `Map.of()` (Java 9+) |
| `by lazy` | 2 | 双重检查锁 / Supplier memoization | 🟢 低 | 直接对应 |
| operator overloading | 1 | 显式方法调用 (`get(name)` 替代 `this[name]`) | 🟢 低 | 仅 1 处（Ognl MockObject） |

### 3.4 异步

| Kotlin 特性 | 出现次数 | Java 替代方案 | 转换难度 | 风险点 |
|------------|---------|--------------|---------|--------|
| `suspend fun` | 2 | `CompletableFuture<T>` 链 / IntelliJ `ProgressManager` + `AppExecutorUtil` | 🟡 中 | StartupActivity / LogStartupCapture 需重构异步流 |

### 3.5 未使用（无需转换）

`inline`/`reified`、`typealias`、`coroutines`/`Flow`、`infix`（除 `to` 外）、`tailrec`、Kotlin 反射（`KClass`/`KFunction`）、自定义属性委托（`by observable`）。

## 4. 转换策略（如决定实施）

### 4.1 工具链方案选择

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| **A. IntelliJ 自动转换** | 一键转换 + 保留结构 | 产出代码冗长、scope functions 展开不优雅、需大量人工修整 | 首轮批量转换 |
| **B. 手写重写** | 代码质量高、可优化结构 | 耗时巨大（每文件 30-60min） | 核心模型/高频修改文件 |
| **C. 混合策略（推荐）** | 自动转换 + 人工精修 | 需两轮工时 | 全部文件 |

**建议采用方案 C**：
1. 第一轮：IntelliJ `Convert Kotlin File to Java` 批量处理
2. 第二轮：人工逐文件精修（data class 重写、null 安全补充、scope functions 简化）

### 4.2 Data Class 转换方案

176 个 data class 是最大痛点，分三档处理：

| 档位 | 条件 | Java 方案 | 文件数估算 |
|------|------|----------|-----------|
| ① 纯数据载体 | 全 val、无继承、无逻辑方法 | `record` | ~100 |
| ② 含 var / 少量方法 | 有 mutable 字段或 1-2 个方法 | Lombok `@Data` 或手写 POJO | ~50 |
| ③ 含继承 / 复杂逻辑 | 继承其他类、含业务逻辑方法 | 手写 POJO + equals/hashCode/toString | ~26 |

### 4.3 Null 安全策略

```java
// 推荐：统一工具类（避免引入 Apache Commons）
public final class Nulls {
    public static boolean isNullOrBlank(String s) {
        return s == null || s.isBlank();
    }
    public static <T> T orElse(T value, T defaultValue) {
        return value != null ? value : defaultValue;
    }
}
```

所有 `isNullOrBlank` 调用替换为 `Nulls.isNullOrBlank`，保持语义等价。

### 4.4 Extension Function 迁移

```kotlin
// Kotlin（原）
fun ColumnRef.withTableAlias(alias: String): ColumnRef = ...
// 调用：column.withTableAlias("t")
```

```java
// Java（目标）
// 移至 WrapperConverter 类中作为静态方法
public static ColumnRef withTableAlias(ColumnRef receiver, String alias) { ... }
// 调用：WrapperConverter.withTableAlias(column, "t")
```

需批量替换所有调用点（grep 定位）。

### 4.5 Suspend Function 重构

2 处 `suspend fun execute(project: Project)`：
- `LogStartupCapture`：改为 `CompletableFuture.runAsync()` + `AppExecutorUtil`
- `StartupUpdateCheck`：改为 `ProgressManager.getInstance().runProcessWithAsynchronously()`

## 7. 回滚方案

如实施中发现不可控风险：

1. **全量回滚**：git revert 至 Kotlin 版本（Kotlin/Java 在同一 repo 中不共存，故全量为原子切换）
2. **部分回滚**：按阶段分 commit，可 revert 至某阶段起点
3. **回退分支策略**：在 `feature/kotlin-to-java` 分支实施，`master` 保持 Kotlin 不动，直到 Java 版本完整验证通过才合并
