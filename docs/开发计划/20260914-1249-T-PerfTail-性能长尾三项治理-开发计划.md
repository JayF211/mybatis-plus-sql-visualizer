## 二、逐项实施要点

### 2.1 WrapperCache LRU 化

- 保留三维修失效机制不变（文件 modificationStamp + resolveVariables 开关 + 表配置签名，性能报告 §5.2 已确认正确性无虞）
- 新增:容量上限 512、按 LRU 淘汰最旧条目；文件关闭（`VirtualFileListener.fileClosed` 或等价 Disposable 钩子）时主动清理该文件条目
- 兜底：`clearAll` 行为不变（设置页「清除缓存」入口不受影响）
- 测试：容量上限淘汰顺序断言 + 文件关闭清理断言 + 既有缓存命中测试不回归

### 2.2 预热等待异步化

- `awaitPrewarmedTempFile` 现状：EDT 上 Thread.sleep(PREWARM_POLL_MS) 轮询，有上限预算且失败快速降级（T-PreviewExecDs 已加分级日志与重试）
- 改造:预热线程产出 CompletableFuture<Pair<VirtualFile, PsiFile>>，完成回调 invokeLater 回 EDT 消费；超时预算语义保留（orTimeout/completeOnTimeout 等价实现）
- 注意：T-PreviewExecDs 刚交付三级降级链（项目内文件→内存 PSI→裸 document），改造不得破坏降级顺序与快速降级语义
- 测试:预热成功/超时/失败三分支的回调时序断言（headless 可模拟预热线程）

### 2.3 行 0 零拷贝读取

- 现状：重放风暴中同 stamp 只付一次 O(文档大小) 拷贝（T-PerfSweep F1 缓存），残余风险在数十 MB 控制台文档的混合态窗口
- 改造:stamp 缓存值改存「行 0 文本」而非全文档拷贝（读取用 getCharsSequence().subSequence(0, firstLineEnd)），或直接 lineSequence 零拷贝
- 测试：混合态判定行为不变（既有 stamp 测试不回归）+ 大文本下不再全量拷贝的断言

### 2.4 plugin.xml 注释修正

- 单行注释改写，注明代码为权威；顺带核对 KDoc 与注释一致性
