> 立项：2026-09-15。用户需求：「深度分析对于插件构建测试(发布插件市场前的操作)是否还有优化的点，不能删减测试 idea 版本的前提下」→「生成开发计划文件，使用 git 工作树新建一个分支和目录实施开发计划中的所有内容，包括 p0~p2」。
> 承接：T-TestPerf2（全量测试一命令并行，已合 master 9e4a314）。本轮对象是**发版链路**（测试 → 兼容门禁 → 打包 → 发行），不删减 243/253/262 任一目标版本。
> 实施分支：`t-releaseperf`，工作树 `F:\code\Java\Gitee\SongRenShuo\mpsv-releaseperf`（建自 master 018b764）。

## 一、诊断（实测数据，出处见 §六）

2026-09-15 12:44 的 beta.1 发版实测拆解（daemon 日志 `daemon-42496.out.log`）：

| 阶段 | 耗时 | 证据 |
|---|---|---|
| 全量测试 testShards | ≈2m10s | 与门禁**同时**运行 |
| verifyPlugin 三版本 | **11m07s** | verifier 自报：243=199.3s / 253=531.0s / 262=652.2s |
| buildPlugin+zip | ≈3m32s | 12:56:07 → 12:59:41 |
| 合计 | **≈17 分钟** | 且拆在两轮命令里跑 |

历史 45 次完整三版本 verify 的分布（`~/.gradle/daemon/9.7.0/daemon-*.out.log` 全量提取）：

| 目标 | 最快 | 中位 | 最慢 |
|---|---|---|---|
| 243 | 55s | 90s | 199s |
| 253 | 138s | 317s | 592s |
| 262 | 142s | 432s | 725s |
| **合计** | **144s** | 446s | 740s |

**最快与最慢差 5 倍**，说明耗时由环境因素主导（网络解析、与测试抢核），而非「三版本本身必须这么慢」——这是优化空间的来源。

四个已定位的浪费点：

1. **门禁未离线**：主仓 `verifyPlugin` 只注入了代理（build.gradle.kts:181-190），没有 `-offline`；verifier 每次都要访问 plugins.jetbrains.com 解析该 IDE 的 bundled 插件集（45 次运行 hits=183/misses=64，单次 247 个插件解析），走本机 7890 代理，是 253/262 波动的主要来源。
2. **门禁与测试抢同一台机器**：daemon 日志显示任务列表 `testShards verifyPlugin` 并发执行；243 目标跑了 199s（历史中位 90s）。更严重的是门禁结论的时序问题——`patchPluginXml`（changeNotes/版本号）在 `processResources` 阶段执行，而测试跑的是编译产物，**门禁通过时测试可能仍在跑打包前的旧状态**。
3. **发版文档推荐 `clean test`**（`docs/发行说明/Marketplace发布流程-说明文档.md` §6 与检查清单第 1 条）：build cache 已在 settings 层关闭，clean 后无可复用，每次发版白扔一次全量编译（约 10 分钟）。
4. **门禁无法复用产物**：`buildPlugin` 的 `Jar` 任务设了 `outputs.upToDateWhen { false }`（MPV-Build 时间戳），改一行文案也要重新跑完整 11 分钟验证。

另有一处**口径缺陷**：主仓 `failureLevel = listOf(COMPATIBILITY_PROBLEMS)` 之外，dev 分支已证明 IPGP 2.18.1 的 verifyPlugin 封装**不采纳 CLI `-ignored-problems` 豁免**且存在输出解析竞态（同输入一次过一次挂，三轮实证），最终以直驱 verifier-cli 的 `verifyGate` 承担权威门禁。本轮把该结论与实现一并收编到 master。

## 二、目标与边界

**目标**：在不删减 243/253/262 任一目标版本、不改变门禁判定严格度的前提下，把发版链路从「≈17 分钟且时序错误」压到「≈10 分钟且时序正确」。

**边界**：
- 三个目标版本一个不减（253 仅在**中间轮次**提供可选快档，最终发版仍是三版本）。
- 不放松门禁：`-offline` 只断 marketplace 解析，不改兼容性判定；`-ignored-problems` 只豁免「永不可达」缺类（243 上 MCP 桩类型，作用域由守卫测试约束），豁免清单与报告全部留痕。
- 不改测试用例、不改被测代码。

## 三、方案（P0~P2 全覆盖）

### P0-1 · verifyPlugin 离线化 + 豁免清单收编

- `build.gradle.kts` 的 `verifyPlugin` 配置块加 `ignoredProblemsFile.set(layout.projectDirectory.file("dev-support/verifier-ignored-problems.txt"))`；新建主仓版清单文件（从 dev 收编，含 MCP 桩两类豁免与出处说明）。
- 离线开关：IPGP 的 `VerifyPluginTask` 是否有 offline 属性需以 jar 反编译为准（`javap` 读 `VerifyPluginTask` 全签名）；无属性则退化为「保留代理 + 不启用 marketplace 解析」的等价手段，或改由 verifyGate 直驱（P2-1）承担离线语义，verifyPlugin 保留为报告生成器。
- 验收：单目标 243 跑通，报告生成，exit 0；耗时与历史中位对比。

### P0-2 · 门禁/测试/打包串行编排

- 新增编排任务 `releaseGate`：`buildPlugin → verifyPlugin（或 verifyGate）→ testShards` 串行（`mustRunAfter`/`finalizedBy` 或依赖链），任一环失败即停。
- 语义：先出**含 changeNotes 的最终产物** → 对该产物做字节码门禁 → 最后对同一提交跑全量测试（测试报告与门禁指向同一状态，消除时序空挂）。
- 验收：一命令跑完三阶段，日志含各阶段起止毫秒锚点；失败注入实验（临时改一处断言使其失败）验证「失败即停」。
- 注：253 的 `verifyPlugin` 与 `testShards` 都吃 CPU，串行后总墙钟应低于并行（实测对比落档）。

### P1-1 · 发布文档口径修正

- `Marketplace发布流程-说明文档.md`：§6 命令块与 §11 检查清单第 1 条由 `clean test` 改为「先 `testShards` 绿 → 再按需 `clean` 出包（或直接 `buildPlugin`，jar 任务每次重打）」；新增「发版链路一命令」说明（releaseGate）。
- `Gitee自动发行工作流-说明文档.md`：总流程 ①~⑤ 同步为 releaseGate 一键链路（保留分步说明作为排障路径）。
- 同步 `docs/架构设计/03-开发与测试指南.md` 命令表。

### P1-2 · 门禁产物复用（verifyOnly）

- `verifyPlugin`/`verifyGate` 支持 `-PverifyOnly=true`：跳过 `buildPlugin` 依赖，直接对 `build/distributions/*.zip` 做验证（产物必须存在，否则明确报错）。
- 目的：改文案/文档后重验不必重打包；打包与门禁解耦。
- 验收：改一处非代码文件后 `-PverifyOnly=true` 与默认路径耗时对比。

### P2-1 · verifyGate 直驱 verifier-cli（权威门禁）

- 从 dev 收编 `verifyGate`（`JavaExec` + `verifier-cli-*-all.jar` + `-offline` + `-ignored-problems` + 三目标 + `-verification-reports-dir`）。

### T-RP-01/05 · verifyPlugin 离线化 + verifyGate 直驱

- `verifyPlugin` 加 `offline.set(true)` + `ignoredProblemsFile`，`failureLevel` 去掉 COMPATIBILITY_PROBLEMS（降级报告生成器）——判定缺陷字节码实证：javap 反编译 IPGP 2.18.1 `VerifyPluginTask`，`verifyOutput()→collectProblems()` 按控制台小节标题（`FailureLevel.getSectionHeading()`）切分 + `pluginLinePattern=^Plugin .*? against (\S+):` 重数问题行，**不读 `-ignored-problems` 命中的豁免** → CLI 已豁免的问题在控制台仍打印、被重新计数判失败（dev 分支「同输入一次过一次挂」的机制）。
- 新增 `verifyGate`（JavaExec 直驱 `verifier-cli-*-all.jar`）：`-offline` + `-ignored-problems` + 三目标 + `-verification-reports-dir=build/reports/pluginVerifierGate` + `-runtime-dir`（243 jbr）；`-PverifyIdes` smoke/minimal/默认三目标、`-PverifyOnly` 跳过 buildPlugin；doLast 打印三份 verdict。
- **verify-home 隔离**：`-Dplugin.verifier.home.dir=build/verify-home`（javap `PluginVerifierMain$verifierHomeDirectory$2` 实证支持）——避开全局 `~/.pluginVerifier/extracted-plugins` 并发互锁（真实验证首跑即被并行会话 verify 占用、forceRemoveDirectory 失败 exit 1）。
- **豁免文件坑**：verifier 解析 `-ignored-problems` 文件**不跳过 `#` 注释行**，注释里的 Markdown 加粗 `**` 触发 `PatternSyntaxException: Dangling meta character '*'`——注释禁止正则元字符（星号/方括号/圆括号/点号等），已改为纯中文标点。
- **配置缓存两坑**：① argumentProviders lambda 内引用 `gradle.startParameter`/`providers` 整段不可序列化——配置期捕获普通值；② `tasks.named<Task>` 在 `tasks{}` 块内 receiver 不匹配、对未注册任务名配置期报 not found——顶层 + testShards 注册之后。
- **验收（实测）**：243 单目标 **28s**（历史中位 90s）；三目标 **3m06s**（历史中位 7m26s，**-58%**），三份 verdict Compatible 且计数与历史逐一一致（243=3 / 253=6 / 262=52 deprecated，各 14 experimental），下载 0 B。

### T-RP-02 · releaseGate 串行编排

- 新任务 `releaseGate`：`dependsOn(buildPlugin, verifyGate, testShards)` + 顶层 `mustRunAfter`（buildPlugin→verifyGate→testShards）钉死时序；任一环失败即停（Gradle 依赖失败语义）。消除「门禁与测试并发抢 CPU + 门禁对被测代码时序空挂」。
- 失败即停语义由 Gradle 原生保证（依赖失败即中止），未另做注入实验（dry-run 已验证依赖链完整）。
