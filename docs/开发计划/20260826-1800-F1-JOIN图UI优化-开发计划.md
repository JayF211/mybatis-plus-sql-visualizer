## 0. 问题分析

基于用户截图（MPJ_LAMBDA，car_device_info 三表 JOIN），识别到以下问题：

| # | 问题 | 严重度 | 根因 |
|---|------|:------:|------|
| P1 | 表头显示 `station_info (stationInfoEntity)` — 实体类名而非 SQL 别名 | 高 | alias 优先取 `join.alias`（MPJ 实体类名） |
| P2 | 一个表头显示 `(SELECT tt.id, ...)` — 子查询 SQL 作为表名 | 高 | 子查询 JOIN 的 `join.tableName` 是完整 SELECT |
| P3 | 列类型显示 `java.lang.Integer` — Java 类型而非 SQL 类型 | 中 | `typeFromTable()` 取 Java 全限定名 |
| P4 | 布局不协调 — 主表在左、JOIN 表竖排在右 | 中 | 简单左右列布局 |
| P5 | ON 条件标签重叠 — 多个标签在同一 Y 坐标浮空 | 高 | 标签居中在水平线段，间距不足 |
| P6 | 基数标签位置不一致 | 低 | 固定偏移 |

## 1. 技术方案

### 改动文件

| 文件 | 改动 |
|------|------|
| `sql/JoinDiagramGenerator.kt` | ① alias 解析：实体类名 fallback 为默认别名；② 子查询表名标注；③ Java→SQL 类型映射 |
| `ui/diagram/DiagramModel.kt` | `EntityNode` 新增 `joinType` 字段 |
| `ui/diagram/DiagramRenderer.kt` | ① 布局改为上下对称居中；② 连线正交路由；③ 动态间距避免标签重叠；④ 卡片样式优化 |

### 修复点

- **Fix-P1**：alias 解析 — `stationInfoEntity`（含大写）→ fallback 为 `t2`
- **Fix-P2**：子查询 — `tableName` 含 `SELECT` → 显示为 `Subquery`
- **Fix-P3**：类型映射 — `Integer→INT`, `String→VARCHAR` 等
- **Fix-P4**：布局 — 主表居中上方，JOIN 表水平排列在下方
- **Fix-P5**：动态间距 — 根据 ON 标签实际渲染宽度调整卡片间距
- **Fix-P6**：基数 — 在实体端居中标注
