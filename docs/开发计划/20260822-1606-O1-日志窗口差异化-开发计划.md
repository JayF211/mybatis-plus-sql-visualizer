## 0. 目标

将 SQL 日志工具窗口从"与 MyBatis Log Plugin 同质化"升级为"与源码联动的差异化调试工具"。

**用户价值**：从日志快速定位到源码、识别慢查询，提升调试效率。

---

## 1. 功能设计

### 1.1 日志 ↔ 源码关联

**场景**：在日志窗口看到一条 SQL，想找到它在源码中对应的 Wrapper 定义位置。

**方案**：
- 日志条目右键新增「跳转源码」菜单
- 匹配策略：根据 SQL 中的表名 + 条件列，在当前项目搜索对应的 Wrapper 链
- 匹配到唯一结果：直接跳转到 PsiElement
- 匹配到多个结果：弹出候选栏（复用 `SqlSelectionDialog`）

**实现**：
```kotlin
// 从 SQL 提取表名
val tableName = SqlTableExtractor.extractFirst(sql)
// 搜索项目内所有引用该表的 Wrapper 链
val candidates = WrapperSearchService.search(project, tableName)
```

### 1.2 执行耗时叠加

**场景**：日志中已有 `Preparing:` + `Parameters:`，如果项目用了 p6spy 或 MP 的 TimeCount，可在条目旁显示耗时。

**方案**：
- 新增可选日志前缀：`Time:` / `duration:` / p6spy 的 `elapsed` 格式
- 解析后显示在条目列表的耗时列
- 耗时着色：< 100ms 绿、100-1000ms 黄、> 1000ms 红

**配置**：
```kotlin
// PluginSettings 新增
var logTimePrefix: String = "Time:"   // 用户可自定义
var slowQueryThresholdMs: Long = 1000 // 慢查询阈值
```

### 1.3 慢查询标记

**场景**：自动识别慢查询并在工具栏告警。

**方案**：
- 解析到耗时 > 阈值时：
  - 条目图标变红色警告
  - 工具栏慢查询计数器 +1
  - 可选：弹通知提示
- 支持按耗时排序
- 支持筛选「仅慢查询」

## 6. 边界与降级

- 源码关联匹配不到：toast 提示「未找到对应 Wrapper」
- 耗时解析失败：耗时列显示 `-`，不影响其他功能
- 项目内 Wrapper 数量过多（>500）：搜索时加 loading 指示
