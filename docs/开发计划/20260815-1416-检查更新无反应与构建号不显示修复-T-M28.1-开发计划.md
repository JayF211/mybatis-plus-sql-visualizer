## 3. 方案设计

### 3.1 问题一：按钮无事件绑定（根因实证）

`UpdateSection.kt` 全文件 grep 无 `addActionListener`——`checkButton`/`installButton`/`restartButton` 只有声明+布局+文本，点击不触发任何逻辑，状态标签（Idle 时空格）永远不更新。测试盲区：`UpdateSectionTest` 只直接调用 `render*` 测状态渲染，未测按钮点击。

**修复**：`UpdateSection.init` 绑定三按钮事件；`runCheck`/`runInstall` 的网络编排 seam 化（`internal var check: () -> CheckResult` / `internal var install: (UpdateManifest) -> InstallResult`，默认走 `PluginUpdateRunner` 真实实现）——测试注入 fake 断言按钮点击全链路（doClick → state=Checking → render 结果），不触网。

### 3.2 问题二：构建号不显示（根因实证）

实证链：
- 已安装 jar（`AppData/Roaming/JetBrains/IntelliJIdea2026.2/plugins/mybatis-plus-sql-visualizer/lib/*.jar`）manifest **含** `MPV-Build: 1786774067321`——注入正常；
- 截图「当前版本: 2026.8.14」正常——`PluginVersion` 走 **classloader.getResource("META-INF/plugin.xml")** 成功；
- `PluginBuildInfo` 走 **`protectionDomain.codeSource.location`** 失败（返回 null → "—"）——**2026.2.1 PathClassLoader 下 codeSource 不可靠**（JetBrains 自研类加载器对插件 jar 不保证 codeSource 指向 jar 文件）；T-M23.14 只在沙盒/测试环境验证（该环境本就该显示 "—"），日常 IDE jar 形态从未实测——潜伏 bug。

**修复**：`ownJarFile()` 改为 classloader 定位**插件专属类文件资源**：
```kotlin
val url = PluginBuildInfo::class.java.classLoader.getResource("cn/song/mybatisplus/visualizer/util/PluginBuildInfo.class")
if (url?.protocol != "jar") return null            // 开发态 classes 目录（file 协议）→ null → "—"
val jarFileUrl = (url.openConnection() as JarURLConnection).jarFileURL
File(jarFileUrl.toURI()).takeIf { it.isFile }
```
- 类文件相对路径是**插件专属**——父加载器（平台）必然找不到 → 委托必落到插件自身 jar ✓（`META-INF/MANIFEST.MF` 通用路径有父优先命中平台 jar 的歧义，不用）；
- 提取逻辑独立为 `internal fun jarFileFrom(url: URL): File?` 纯函数（单测：临时 jar 构造 `jar:file:` URL）；
- 存量 `PluginBuildInfoTest`（readMpvBuild 临时 jar）与 `PluginSettingsPanelBuildInfoTest`（测试环境 "—"）保持不动回归。

## 7. 边界与降级

- 构建号读取仍可能失败（极端环境 codeSource/资源定位均不可用）→ 保持 "—" 兜底，不抛异常；
- 检查更新结果不变（网络失败显示原因、已最新不打扰）；启动自动检查逻辑零改动；
- seam 注入仅 internal（测试用），对外行为与默认实现一致。

## 8. 已确认项 / 简化决策

1. 按钮绑定为直接根因，不加事件分发框架；
2. 构建号定位方案与 PluginVersion 同款（classloader 资源），不引入平台 API；
3. 测试盲区教训：UI 组件测试必须覆盖按钮点击交互（doClick + seam），不只渲染。
