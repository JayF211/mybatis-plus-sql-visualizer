## 三、方案

### S1 主件：auto-handicap 机制化（触发条件的执行件）

三段式，全部在 `mpv-testing.gradle.kts` 内，默认态（零历史）行为与现状逐字节等价：

**① 失衡历史落盘**（聚合 doLast 末尾追加）：`build/test-results/shard-imbalance-history.jsonl` 每轮一行：
`{"ts":<millis>,"critSlot":<n>,"relCrit":<x.xx>,"classSetHash":"<临界片类清单hash>","execSum":<s>,"mode":"off|manual|auto","factor":<f|null>,"target":<n|null>}`
- doLast 内 critIdx/relCrit/drift 全部现成（当前 833~865 行段）；本轮 mode/factor/target 经 `inputs.property` 固化串传入（CC 约束，沿 mpvExpectedShardLoads 先例）；临界片的类集 hash 由配置期算好的「片序→hash」映射串传入。
- 写入失败静默跳过（runCatching，历史是优化输入不是正确性依赖）。
- build/test-results 每轮变化本就使配置缓存失效重算（T4 实证），下轮配置期读到的一定是含本轮的最新历史。

**② 配置期自动判定**（均衡器贪心前）：读 jsonl 尾部 ≤10 行，执行 T13 触发条件：
- 最近 ≥3 轮连续 relCrit>1.10（与告警判据同源）；
- 且临界槽位恒定（同槽）；
- 且临界片类清单有更替（distinct classSetHash ≥2——「不随清单更替漂移」的机器可判形态：清单换人临界不换槽=结构性恒槽；清单不变=个别类缺权嫌疑，走 weight-refresh 路径不补偿）；
- 且窗口内无补偿活动（mode≠off 的轮次读数不可比，剔除后不足 3 连则不触发）；
- 满足→因子=1/(1+近 3 轮超权比中位)，钳 0.5..1.0，自动启用（等价手工 -P），日志 `AUTO-HANDICAP engaged: shardN factor=x.xx (近期超权 +xx%/xx%/xx%)`。

**③ 过补自愈**（安全阀）：若最近 ≥2 轮 mode=auto 且出现过补形态（目标槽 relCrit<0.90 显著偏轻，或非目标槽 relCrit>1.10 成新临界）→ 本轮停用自动补偿、历史记 cooldown，连续 2 轮 cooldown 后从原始判据重新评估（防振荡）。手参显式给定时手参全程优先（auto 不介入）；总闸 `-PtestShardAutoHandicap=false` 一词关闭（缺省 true，D45）。

**验证法（不烧测试轮）**：判定逻辑先用构造 jsonl 样本离线校验（≥6 组：无历史/3 连恒槽且清单更替→触发/3 连但清单同→不触发/漂移噪声→不触发/窗口含 manual→不触发/过补→cooldown），以 `./gradlew testShards --dry-run` 走配置期读 AUTO-HANDICAP 日志行与 loads 行核对（秒级，不起测试 JVM）；再注入 T13 R1~R3 历史形态验证真实启用轮；真轮 A/B 见 S3。

### S2 次件：D44 testDatabase 并行化转正

`./gradlew testDatabase` 命令名与语义不变（一命令五类全跑），内部重构：
- 现单任务（filter 5 类+forkEvery=1 串行换 JVM）拆为 5 个 testIde 注册任务：`testDbConsole`/`testDbSelector`/`testDbDiagram`/`testDbExecDocGate`/`testDbDriverPipeline`，各 filter 单类、各自 `sandboxDirectory=test-sandbox/database/<任务名>`（IPGP config 目录规则 `config_<任务名>` 天然隔离，M36.5.23d 在案）。
- 隔离语义只增不减：原 forkEvery=1 的动因是 DBN 应用级单例跨类串扰（T-TestDbDriver 20260918 三形态实录）——拆任务后每类独占 JVM **且独占沙盒**（原方案 5 类共享同一 config_testDatabase 目录仅 JVM 级隔离），应用级状态隔离面严格变大；测试侧 DbIntegrationSeedSupport 按 `PathManager.getConfigPath()` 绝对锚定（在案），零测试源码改动自动适配新 config 目录。
- 现有 doFirst 四级种子逻辑（jdbc-drivers.xml/jar 树/driverState/test-database-artifacts.xml）参数化 configDir 后逐任务执行（种子逻辑幂等，目录独立互不干扰）；`testDatabase` 变纯聚合任务（dependsOn 五者，org.gradle.parallel 并行执行）。
- 旧单任务命令兼容：聚合任务名保持 `testDatabase`；`-PmpDemoProjectDir`、代理透传 systemProperty 逐任务复制。
- 先跑一轮**串行基线**（改造前代码，真库在跑，补 T13 留白），再跑并行轮 A/B。若 demo MySQL 认证/introspect 不通致 skip 形态，如实降级（机制绿+并行图验证），收益读数标注证据边界。

## 五、决策点（带推荐）

- **D45 auto-handicap 缺省态**：推荐**机制默认启用**（总闸可关）——T13 已裁定触发条件启用规则，机制化=执行既定裁定；三重安全（总闸/手参优先/过补自愈）+零历史零行为。备选=缺省 false 全 opt-in（更保守但恒临界窗口收益继续搁置，与用户「压缩时间」诉求相悖）。
- **D46 过补 cooldown 策略**：推荐 cooldown 2 轮后从原始判据重评（自动系统必须自愈，防振荡窗口有限）；备选=永久回退待人工（更保守，机制价值减半）。
- **D47 testDatabase 并行度**：推荐 5 类 5 任务全并行（Commit≈5 分片量级 T13 已评估）；备选 2+3 分组（V62 证伪时降级路径）。
