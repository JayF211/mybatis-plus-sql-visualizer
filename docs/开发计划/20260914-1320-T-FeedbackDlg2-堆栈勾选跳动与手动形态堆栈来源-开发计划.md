## 二、根因分析

### 2.1 跳动（T-FeedbackDlg2-01）

T-FeedbackDlg-02 为支持拖拽把描述行与堆栈行都设成 `fill=BOTH + weighty=1`。
GridBagLayout 布局时排除不可见组件：

- 未勾选：堆栈行不参与，纵向富余 `slack = 窗口高 − 可见行首选高之和` 全部给描述行；
- 勾选瞬间：堆栈行进入布局，窗口高度不变，堆栈行（首选高 180）与描述行**争抢空间**——
  富余被两行对分、堆栈行还要吃掉首选高，描述行被压扁，视觉上「勾选框被顶上去」。

即跳动不是「堆栈出现的位置不对」，而是**窗口高度不随堆栈行出现而增长**。

### 2.2 堆栈来源（T-FeedbackDlg2-02）

堆栈全文唯一来源 = 错误形态调用链 `IdeErrorReportSubmitter.submit()` 的
`event.throwableText`（IDE Internal Errors 对话框「报告」按钮带进来的异常）。
手动入口 `FeedbackReporting.openManualDialog()` 硬编码 `stackText = null`，
勾选行可见但永远无内容——死勾选框。

用户诉求：手动形态也应能附带此前遇到的插件报错。平台侧可用数据源 =
IDE 错误池（Internal Errors 对话框同一列表）。

## 三、修复方案

### 3.1 T-FeedbackDlg2-01 窗口高度补偿

`ErrorReportDialog.toggleStackPreview(show)`：

- 纯函数 `toggleResizeDelta`（companion，可 headless 测）给补偿量：
  - 勾选：`Δ = slack + 堆栈行首选高`（描述行被压掉 `(slack+S)/2`，两 weighty 行对分
    新增空间，撑高 2Δ' = slack+S 恰让描述行分毫不差）；
  - 取消：按堆栈行**实际分配高**（兜底 preferred 缩减量）对称缩回；地板高 400。
- 编排函数翻可见性前后各测一次 `contentPane.preferredSize`（GridBag preferred 只统计
  可见组件），得到真实 growth，不依赖行高假设；`window.setSize` 后 `pane.validate()`。
- peer 未建（headless/异常路径）`runCatching` 跳过补偿，显隐照常。
- ItemListener 改调 `toggleStackPreview`；初始勾选态在 init() 内直调可见性
  （监听在初始状态落定后注册，构造期不触发补偿）。

### 3.2 T-FeedbackDlg2-02 手动形态堆栈候补

`FeedbackReporting.latestPluginErrorStack()`：`MessagePool.getInstance()
.getFatalErrors(true, true)`（243 app-client.jar / 262 ide.impl.jar javap 实证公开且
签名一致；即 Internal Errors 对话框数据源）→ 倒序取最近一条堆栈/消息含本插件包名
`cn.song.mybatisplus.visualizer` 的条目（243 无 ErrorsHolder/belongsToPlugin，统一文本
匹配归属；归属判定抽纯函数 `isPluginError`）→ 其 `throwableText`。

- `openManualDialog` 传该值作 `stackText`（错误路径调用方不变，仍以 event 堆栈为准）。
- 对话框 init：`attachStackCheck.isVisible = stackText != null`——无任何可附堆栈时
  整行隐藏死勾选框；默认勾选仅限错误形态（prefill != null），手动形态取到的错误池
  堆栈默认不带、用户自行决定（历史报错未必是本次要报的事）。
- `collectStackAttachment` 现有 `stackText != null && isSelected` 判定天然覆盖新来源。

### 3.3 测试

- `ErrorReportDialogLayoutTest`：+1 例 `toggleResizeDelta` 五分支表驱动
  （撑高含富余/无富余、缩回实占高/退化为 preferred/零释放不动）。
- `FeedbackReportingContractTest`：+1 例 `isPluginError` 归属判定四分支。
