## 1. 问题

M37.4 交付的「生成测试」当前断言是占位 TODO，没有可用内容：

- SQL 回归脚本形态：表名非空时断言区只有一行 `SELECT COUNT(*) AS matched FROM <表>;` 加 TODO 注释（`TestAssetGenerator.kt:54-58`）；表名缺失时只剩 `-- TODO: 补充前置数据与断言查询`（`TestAssetGenerator.kt:54-55`）。
- JUnit 骨架形态：方法体只有内嵌 SQL 常量加一句 `// TODO: 执行 sql 并断言结果（如 assertEquals(...)）`（`TestAssetGenerator.kt:76`）。
- 两形态都不推导前置数据，这是 P-立项-06 交付时明说的边界（`TestAssetGenerator.kt:27-28`：「不自动推导 INSERT 前置依赖数据」）。

缺口实质不在生成器本身——它是零平台依赖的纯函数（`TestAssetGenerator.kt:21`），输入只有 `Input(sql, dialectName, tableName, anchor)` 四项（`TestAssetGenerator.kt:33-42`），手里没有任何表结构信息，想生成真断言也无米下锅。竞品对照（第二轮调研报告 §5.1 N-9）：MybatisCodeHelperPro 的接口方法生成 testcase 是其付费卖点，本插件有数据源 schema 通道（M35 起反射链已通）可以做得更实。

## 2. 方案

断言增强按「有无数据源 schema 信息」分 A/B 两档，自动降档，生成器保持纯函数：

- **A 档**（无数据源 / Community / 目标表查不到 / 表名缺失）：现状保持 TODO 占位与注释引导，输出文本逐字不变。
- **B 档**（数据源查到目标表）：推导目标表 NOT NULL 列清单，生成 SELECT 校验语句骨架 + count 前后对比断言占位。

不做的取舍：**不自动推导 INSERT 前置数据**，维持 M37.4 原边界。理由：前置数据推导需要列级语义（外键指向、默认值、生成策略），推导错了用户会拿到一条「假通过」或「假失败」的回归脚本，误判成本高于省下几行手写 INSERT 的收益；B 档给出「前置数据须覆盖的 NOT NULL 列清单」已经把该补什么指到位，剩余工作留给用户，与 P-立项-06 不做清单一致。

### 2.1 schema 通道探查结论与 NOT NULL 获取

- `DatabaseSchemaResolver.tableMeta(project, tableName)` 返回 `TableMeta(comment, columns: Map<列名, ColumnMeta(comment, typeSpec)>)`，内部 `ReadAction.compute` 包裹（`DatabaseSchemaResolver.kt:91-95`）；Community 无 Database 插件时 `isDatabaseAvailable()`（`Class.forName` 探测标记类，`DatabaseSchemaResolver.kt:131-135`）为 false 直接返回空 `TableMeta`。既有降级模式 = 反射隔离 + 空结果回落，调用方回落实体推断值——本任务沿用，不另造降级分支。
- 现有 `ColumnMeta` 只有 `comment`/`typeSpec` 两个字段（`DatabaseSchemaResolver.kt:100-101`），没有非空约束信息。**javap 实证**（本次，IDE 2026.2.1 `plugins/DatabaseTools/lib/modules/intellij.database.jar`）：`com.intellij.database.model.DasTypedObject` 声明 `public abstract boolean isNotNull()`，且 `DasColumn extends DasTypedObject`——反射 `getMethod("isNotNull")` 即可取列非空标记，与同文件既有的 `getDataType().getSpecification()` 反射链（`DatabaseSchemaResolver.kt:209-210`）同款写法。
- 附带缺口：`collectFromDataSource` 现在只把「注释或类型串非空」的列收进 Map（`DatabaseSchemaResolver.kt:212-214`）——一条没有注释没有类型串的普通 NOT NULL 列会被过滤掉。必须把收录条件放宽为「或 notNull==true」，否则 NOT NULL 清单对干净 DDL 的表恒为空。

### 2.2 断言分档生成（纯函数侧）

- `Input` 尾部追加 `notNullColumns: List<String> = emptyList()`（默认空，存量构造点与既有 7 个用例零影响）。
- B 档 `sqlScript`：断言区生成三段——`-- 前置数据须覆盖 NOT NULL 列（来自数据源 schema）: id, name, ...` 清单注释；`SELECT <NOT NULL 列清单> FROM <表>;` 校验骨架（TODO 引导替换为业务谓词）；count 前后对比占位（`total_before` / 目标 SQL / `total_after` + `-- TODO: 人工核对前后差值`）。A 档输出逐字不变。
- B 档 `junit`：生成 `long countBefore = ...` / 执行 sql / `long countAfter = ...` 骨架与 `// TODO: assertEquals(...)` 占位 + NOT NULL 列清单注释；保持零额外运行时依赖、粘贴即可编译。
- 消费语义保护：`ColumnMeta` 收录条件放宽后，`columnCommentsCached` 等只消费 comment 的调用点会多拿到「仅非空标记」的列（空注释）——`columnCommentsCached` 过滤 blank comment 后再返回（`DatabaseSchemaResolver.kt:52-65` 内一行守卫），保持补全侧消费语义与放宽前一致。

### 2.3 调用侧改造（SqlPreviewPanel.generateTestAsset）

现状：按钮点击（EDT）→ 组 Input → 弹菜单二选一 → onChosen 里生成（`SqlPreviewPanel.kt:515-560`）；脚本落盘已在 pooled thread + invokeLater（`SqlPreviewPanel.kt:563-588`）。改法：onChosen 选中后先取 schema——tableName 非空时调 `tableMeta`（自带 ReadAction 与 T-Perf-09 metaCache，命中零遍历；JOIN 富化后台预取常已填好缓存），提取 `notNull==true` 的列名清单组装进 Input 再生成；落盘形态沿用既有后台链。Community / 无数据源 / 查不到表 → 空清单 → A 档，自动降级，无新增提示分支。

## 5. 风险

- schema 首查遍历代价：metaCache（T-Perf-09，弱键缓存、负命中不缓存）未命中时 DasModel 全量遍历在 ReadAction 内，大 schema 项目可能卡顿——缓解：schema 解析放在 onChosen 之后的后台链上执行（与落盘同链），EDT 只收 invokeLater 结果。
- isNotNull 语义随数据源而异（视图、无约束库返回 false）→ 该列不进清单，自然降为 A 档语义，不会产出错误内容。
- 收录放宽让补全/JOIN 富化多拿到空注释列——`columnCommentsCached` blank 过滤守卫兜底（§2.2），`applyTableMeta` 消费点在实施时同查一遍。
- DasColumn 反射链在个别平台版本的可用性——与既有 getDataType 链同一批 jar，真机步骤先行验证，失败时降级为 A 档（空清单），不影响交付。
