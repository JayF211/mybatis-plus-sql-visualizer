## 一、背景与目标

用户提议：`gitee-token.json` 这类机器本地文件不应散落在仓库根，应统一收进根目录下的 `.local/`，并在迁移后同步更新记忆与相关文档，避免后续找不到文件。

围绕这一提议，对仓库目录结构做了一轮完整复查（源码、测试、根目录散文件与辅助目录、docs、构建配置）。结论是：**整体结构合理且工程化程度高**，包划分内聚、文档体系完整、组合构建取舍有据；主要优化空间集中在「清理历史遗留」与「渐进式拆分巨型文件」，而非架构级重构。

因此本计划的目标分两层：

1. **主任务（本次实施）**：建立 `.local/` 约定并迁移 `gitee-token.json`，同步脚本、文档、记忆。
2. **结构复查产出（分档处置）**：把复查发现的可优化点按「本次顺带做 / 单独立项 / 长期 / 维持现状」四档归档，避免发现的问题只留在会话里。

## 四、主任务：`.local/` 约定与 `gitee-token.json` 迁移

### 4.1 现状与差距

| 项 | 现状 | 问题 |
|---|---|---|
| 凭据文件位置 | 仓库根 `gitee-token.json` | 与 `README.md`/`CHANGELOG.md`/`build.gradle.kts` 同级；新增凭据类文件没有统一去处 |
| 忽略规则 | `.gitignore:84-87`「本地凭据」段：`gitee-token.*` / `*.token` / `.secrets/` | 只按文件名/固定目录名忽略，新增本地文件易漏配而误提交 |
| 引用点（脚本） | `dev-support/gitee-release.py:45` `os.path.join(REPO_ROOT, "gitee-token.json")` | 硬编码根路径，迁移后不同步改则读不到令牌 |
| 引用点（文档） | `docs/发行说明/Gitee自动发行工作流-说明文档.md:135/143/145/234` 四处「仓库根 `gitee-token.json`」 | 迁移后四处全过期 |

| `.zcodeignore` | 1-91 行同步自 `.gitignore` 对应段（含 84-87 凭据段） | 只改 `.gitignore` 不同步它，ZCode 仍会索引 `.local/` |

`gitee-token.json` 未被 git 跟踪（`git check-ignore` 确认命中 `.gitignore:85`），故迁移是**文件系统移动**，不是 `git mv`。

### 4.2 目标

1. 建立根目录 `.local/` 约定：机器本地文件（凭据、令牌、本机路径覆盖、临时本地配置）统一放这里，整目录不进 git。
2. `gitee-token.json` 迁到 `.local/gitee-token.json`。
3. 忽略规则升级为「整目录忽略 + README 白名单」，堵住「新增本地文件忘配忽略」的口子。
4. 发行脚本向后兼容：优先读 `.local/gitee-token.json`，读不到再回退根目录旧路径——已配置过的机器不因迁移中断。
5. 文档与记忆全部同步到新路径，并让 `.local/` 的用途在仓库内自解释（放一份被跟踪的 `.local/README.md`）。

### 4.3 决策点

- **D1（整目录忽略 + README 白名单）**：用 `.local/*` + `!.local/README.md`，而非 `.local/`。git 规则「父目录被排除则无法再包含子文件」决定了必须先通配排除再单独放行；README 入库后新贡献者能在仓库里看到约定。
- **D2（保留旧规则作安全网）**：`gitee-token.*` / `*.token` / `.secrets/` 三条保留不动——即便有人误放根目录，旧规则仍兜住。迁移不删旧闸门。
- **D3（脚本双路径回退）**：`gitee-release.py` 读路径改为「先 `.local/gitee-token.json`，不存在再根目录」。不强制用户手工挪文件，迁移无感。
- **D4（归口范围只收凭据类）**：本任务只把凭据/令牌类归口。本机路径覆盖（§六 C①）涉及改多个跟踪脚本、影响面更大，单独立项。
- **D5（`.zcodeignore` 必须同改）**：不同步则 ZCode 搜索会把令牌内容纳入上下文。

### 4.4 待验证前提

- **P1**：`gitee-token.json` 确为未跟踪（已实测：`git check-ignore -v gitee-token.json` 命中 `.gitignore:85`）。若发现曾被 `git add -f` 入库，须先 `git rm --cached` 并单独提交（会进历史，是否 filter-repo 另议）。
- **P2**：`!.local/README.md` 在 `.local/*` 之后确实生效——实施后 `git check-ignore -v .local/README.md` 应**不**命中，`git status` 显示为 `??` 可添加。反向验证：改 README 一行，确认 `git status` 仍能看到改动（证明真被跟踪）。
- **P3**：`.zcodeignore:92` 是「↑ 以上同步自 .gitignore」分界线，`.gitignore:92-95` 的 `docs/内部/` 段**不在** `.zcodeignore` 同步段内（两文件本就非逐行等价）。本次改动落在 84-87 段内，两侧都改，不触碰边界。
- **P4**：`gitee-release.py` 回退逻辑不破坏 `--verify-only`/`--replace`/`--delete-only` 三模式（改动只在 `load_config()` 取路径处，三模式共用）。
