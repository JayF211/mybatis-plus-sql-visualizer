## §一 现状盘点（20261007 master 实测）

1. **反向生成器无 Maps 形态**（`JavaCodeGenerator.selectInvocation` :610-624）：方法选择仅两族——普通（`selectList/list/selectPage/page`，按 LIMIT 分流）与 VO/join（`selectJoinList/selectJoinPage/selectJoinListPage`，VO 非空时）。返回前缀恒 `List<实体/VO>` 或 `Page<...>`——**`List<Map<String, Object>>` 无法表达**。
2. **MPJ 签名实证**（.m2 `mybatis-plus-join-core-1.5.8.jar` javap `com.github.yulichang.base.JoinMapper`）：
   - `selectJoinMaps(MPJBaseJoin<T>): List<Map<String,Object>>`
   - `selectJoinMapsPage<P>(P, MPJBaseJoin<T>): P`（分页 Maps）
   - **Maps 族不带 Class 参数**——VO 不进签名；Map 的 key = select 列的 AS 别名 → VO 的正确角色是驱动 select 列别名（`selectAs(实体::getX, Vo::getY)`，T-M47 的 `renderSelectCall` voClass 分支已具备该形态），而非调用行 Class 参数。
3. **正向链路不对称**：`psi/WrapperLocator.kt:1397` 与 `BatchOperationConverter.kt:104/116` 已识别 MP 原生 `selectMaps/listMaps/getMap`；**MPJ 的 `selectJoinMaps/selectJoinMapsPage` 全链零识别**——正向（Java→SQL）遇到 Maps 调用不渲染（往返对称缺口）。
4. **面板 UI**：`voField`（提示「返回 VO（可选）」）+ `callerField` 调用类；无「响应形态」概念——形态由 LIMIT/VO 隐式推断。多候选实体弹窗（SqlSelectionDialog）与 VO 无联动。
5. **单表 Maps**（MP 原生 `selectMaps`/`listMaps`）：反向同样未支持（同族形态，随批成本低）。
