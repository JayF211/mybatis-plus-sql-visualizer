## 2. 当前插件功能与定位（v2026.9.4）

**插件**：SQL Visualizer（id `cn.song.mybatisplus.visualizer.mybatis-plus-sql-visualizer`，Marketplace 页 33633），v2026.9.4，免费开源，IDEA 2024.3+（sinceBuild 243，无 untilBuild 上限，2025.1–2025.3 与 2026.1+ 实测全兼容）。运行时仅依赖 JSqlParser。

**一句话定位**：IDEA 内多 ORM 的 SQL 调试闭环——写前静态预览、跑后日志还原、原地执行验证、真实计划诊断、测试资产生成。上轮的"预览—还原—执行"三环，本轮补齐了后两环（诊断、资产），闭环扩为五环。

### 2.2 主轴与周边

主轴仍是三合一闭环，但每环的纵深都变了：预览环从"Wrapper 能转"变成"9 个框架族 + 11 类触发面 + 金样矩阵锁定语义"；执行环从"能提交"变成"内嵌原生控制台 + 7 方言 EXPLAIN"；新增的诊断环和资产环目前全市场无对应物。上轮说周边功能"合起来构成别人没有的完整体验"，本轮这些周边（JOIN 图原生直嵌、拦截器模拟、SQL-Java Diff）已经开始反哺主轴——竞品缺陷场景进金样矩阵、数据源注释进预览补全。

### 3.2 格局变化的三个信号

1. **JPA Buddy 被 JetBrains 收编**。vendor 字段从 Haulmont 变为 JetBrains，发版追到 2026.3 EAP。上轮风险节里"框架官方内置预览"是假设，现在官方生态收编有了实证先例。JPA Buddy 本身仍不做日志捕获、不做参数填充、不做静态 SQL 预览，直接功能重合未变，但它证明了这条路线的存在。
2. **MyBatis Log Free 放弃 2025.x**。1.3.1 起兼容 262.0+，等于把用老版本 IDEA 的存量用户放生。它 40 天拿 1 万下载说明池子里流量仍在，而"2024.3+ 全兼容、无 untilBuild"正是本插件先天优势——这批无主流量第一次有了明确的承接方。

## 4. 竞品用户抱怨清单（2026-09 视角）

先说大盘：2026-08 至今全市场只有 1 条新评论（MyBatisX 08-31），评论区整体死寂——MyBatis Log 已 2 年 5 个月无评论，JTracker/JPA SQL/MySQL Explain/本插件均为 0 评论。口碑争夺的主战场已不在评论区，在适配时效和搜索排名。本插件 110 下载、0 评论，处于上架冷启动期。

对照上轮五条结论的现状：

1. **IDE 新版本适配慢——仍是第一抱怨，且出现信任透支新形态**。MyBatisX 的催更潮（2025-08~12 十余条）过后，评论区出现用户互教"手动改 plugin.xml 版本号""从 GitHub 第三方重打包安装"——官方适配滞后已把用户逼到自装灰色方案。CodeHelperPro 最新一条评论（2026-04-07）是 IDEA 2026.1 + Kotlin K2 模式下插件无法加载、每次启动约 180 条错误日志。MyBatis Log Free 干脆放弃 2025.x。本插件 243+ 无上限 + verifyPlugin 三平台，这条抱怨是可感知的相对优势，但优势还没有被说出来（O-1 残项）。
2. **参数拼接与解析边界错误——仍在，重心移向静态解析误报**。Log Free 的 IN 漏引号（2024-07）、LocalDate 报 ORA-01722（2025-04）是拼接侧老病；MyBatisX 最新两条（2026-04、2026-08-31 且无人回复）都是 Map 参数在 XML 中 `map.xxx` 报"无法解析符号"，另有多模块同实体误报 "Result type not match"。本插件 1538 保留字逐词引擎验证 + 81 场景金样矩阵是赛道内唯一的系统性正确性建设，竞品翻车场景已陆续进金样矩阵（M37 的九项）。
3. **工具窗体验差——仍是 Log Free 最新一条抱怨**（2026-01-21：面板不能固定、debug 到一半才发现没开）。本插件自动捕捉 + 首条 SQL 自动展开 + 会话级抑制已超额解决。
4. **弹窗骚扰是新增反面教材**。Mybatis-Flex-Helper 被"平均一小时一次弹窗，不如直接收费"式评论打出 1 星（2024-10~2025-11 三次）。体验差不止丢功能分，直接丢用户。本插件的更新通知与自动展开均有开关和抑制机制，需要把"零弹窗导流"固化为设计红线（O-7）。
5. **付费教训随产品一起死亡**。MyBatis Log 的激活失败/退款无门评论停在 2023，产品与抱怨同归于尽，警示案例成立，维持不做付费订阅。
6. **JPA 支持是点名率最高的"求而不得"**。Log Free 用户 2025-10 明确留言"如果能支持 jpa 就好了"——这正是本插件已深度覆盖（JPA 派生/JPQL/Criteria/HQL/NamedQuery/Specification/QBE）且竞品全部为零的能力。点名证据拿到了，缺的是让这批用户看到。

## 6. 风险

1. **JetBrains 官方化路线实证化**。JPA Buddy 收编是第一个实证：官方会收编赛道头部而非自研。本插件量级尚小、且做的是官方不屑于做的 Wrapper 生态与信创方言，短期无虞；但若 MyBatis-Plus 官方（baomidou 有 MyBatisX 在手）给自家生态加同款预览，第三方空间会被直接侵蚀。对策不变：趁窗口把"SQL 可视化"与产品名绑定——本轮更名已是一步。
2. **冷启动陷阱**。功能密度第一但 110 下载、0 评论，而评论大盘死寂意味着自然口碑流转更慢——等待不会带来增长，头部竞品的存量优势每周都在复利。N-6/N-7 是市场动作不占开发排期，宜立即做。
3. **待审核更新积压**。hasUnapprovedUpdate=true 若长期滞留，Gitee 抢先体验通道与 Marketplace 正式渠道会版本分叉，用户与文档对不上。发布流程里补一步"审核状态确认"。
4. **AI 替代**（延续上轮，无新变化）。不与文本处理竞争，锚定 IDE 深度集成、执行期确定性、方言正确性背书。

## 7. 落地优先级建议

如果只做三件事：**N-6 冷启动组合拳**（确认审核状态 + 描述首屏 + 第一批评论，几乎零开发成本）、**O-5 适配承诺收尾**（CI + README 一句话，把已有的优势变成可感知的承诺）、**N-7 老版本用户承接**（流量第一次无主，窗口就是现在）。

一句话总结本轮：八个月前的问题是"功能还缺什么"，现在已经回答完了；本轮的问题是"这么强的功能，为什么没人知道"。
