# SQL 预览面板「执行 SQL」按钮——开发计划（M17）

> 本文档是 **MyBatis-Plus SQL Visualizer** 的 M17 增量计划：SQL 预览面板工具栏新增**「执行 SQL」按钮**——
> 点击后选择数据源，**自动创建临时文件**（含当前预览 SQL）并在其中执行/可执行，打通「代码 → SQL 预览 → 实际执行」闭环。
>
> 当前基线：v1.10（M16.2/M16.3 已提交，254 测试全绿）。

---

## 1. 需求与约束分析（2026-08-13）

### 1.1 用户诉求

> 「希望 sql 面板多一个**执行 sql 的按钮**，点击后需要**选择数据源**，**自动创建一个临时文件**」

**期望流程**：预览面板点「执行 SQL」→ 选择数据源 → 自动创建临时文件（内容 = 当前面板 SQL，含参数回填与手动编辑）→ 文件打开/执行。

### 1.2 关键约束（本功能的核心决策点）

| 约束 | 现状 | 影响 |
|------|------|------|
| **数据源能力在 `com.intellij.database` 模块** | 该模块**仅捆绑 IntelliJ IDEA Ultimate / DataGrip**；Community 无数据源功能 | 引入**可选依赖**（`<depends optional="true">`），Community 优雅降级（隐藏按钮） |
| **构建平台当前为 Community** | `build.gradle.kts` 用 `intellijIdea("2025.3.5")`（默认 Community）；注释预留 `local("C:/Users/USER/AppData/Local/Programs/IntelliJ IDEA")` | 编译 `com.intellij.database` 需切 **Ultimate 平台**（下载受限→优先 local 指向本机安装，需确认本机为 Ultimate）；或可选依赖 + 反射隔离（不编译直接引用） |
| **M16 已明确 Community 兼容为项目约束**（方案 B schema 补全因此搁置，`SqlCompletionProvider` 预留切换点） | `com.intellij.database` 引用必须**隔离**（database-optional.xml / 反射加载），主代码不得直接引用 | 社区版安装不崩溃、无按钮 |
| **database 执行 API 处于变动期** | 社区报告：`com.intellij.database.datagrid.GridDataRequest` 在 **2025.2 被移除**；官方答复 `DatabaseSessionManager.facade` + `SmartStatements` "非最终 API" | 执行路径优先用社区验证过的 **`DatabaseSessionManager.getSession` + `DataRequest.RawRequest`**（session 级 API，相对稳定），spike 验证 2025.3.5 实际可用性 |
| **方言一致性** | 预览 SQL 按插件方言配置（MySQL/PG/Oracle）渲染；数据源方言可能不同（分页子句差异） | 风险提示 + 增强项（按数据源方言重渲染），本里程碑不自动适配 |

### 1.3 技术调研（API 候选，spike 定稿）

| 环节 | API 候选 | 备注 |
|------|----------|------|
| 数据源枚举 | `com.intellij.database.dataSource.DataSourceManager.getInstance(project).getDataSources()`（2023+）；备选 `LocalDataSourceManager.getDataSources()` | spike 验证 2025.3.5 返回类型（`DataSource`/`LocalDataSource`） |
| 数据源选择 | 自建轻量对话框（JList：名称 + 数据库类型 + 版本）——零 API 风险；优先尝试复用 IDE 的 `DataSourceChooser`（存在则用，spike 确认） | 0 个→引导创建；1 个→直用；多个→对话框 |
| 临时文件 | 主方案：**Scratch 文件**（`ScratchFileService.createScratchFile(project, path, SqlLanguage)`）——IDE 原生「临时文件」语义、.sql 语言、编辑器原生；备选：`FileUtil.createTempFile` + `VfsUtil` | 若控制台方案可行则改为 **Database 控制台**（见下） |
| 数据源绑定 | **Database 控制台**（`com.intellij.database.console.JdbcConsoleProvider.createConsole(project, dataSource, virtualFile, title)`）——控制台**天然绑定数据源**、自带结果面板、Ctrl+Enter 可执行；spike 验证 2025.3.5 签名 | 控制台文件即「临时文件」的 IDE 原生形态；若 API 不可用→scratch + 编辑器状态栏手动选 DS（兜底） |
| 执行 | `DatabaseSessionManager.getSession(project, dataSource)` → `DataRequest.RawRequest.processRaw(context, connectionCore)` → `connectionCore.getRemoteConnection().prepareStatement(sql).execute()`，`session.messageBus.dataProducer.processRequest(request)` | 社区验证路径（[Query SQL in an IntelliJ Plugin](https://platform.jetbrains.com/t/query-sql-in-an-intellij-plugin/1355)）；结果订阅 `DataConsumer`/`ResponseTopic` 复杂——本里程碑执行结果以「成功/异常」通知呈现，结果面板展示属增强项 |
| 插件可用性判定 | `PluginManagerCore.isPluginInstalled("com.intellij.database")` | 按钮渲染/点击前判定，Community 无按钮 |

## 2. 方案设计

### 2.1 依赖与降级（T-M17-01）

- `build.gradle.kts`：`intellijIdea("2025.3.5")` → **Ultimate**（`intellijIdea(IntellijPlatformType.IntellijIdeaUltimate, "2025.3.5")`，或 `local(...)` 指向本机 Ultimate 安装——网络受限优先 local，spike 确认本机版本）；`bundledPlugin("com.intellij.database")`；
- `plugin.xml`：`<depends optional="true" config-file="database-optional.xml">com.intellij.database</depends>`；
- **隔离策略**：所有引用 `com.intellij.database` 的代码收拢到 `database/` 子包单类（如 `DatabaseExecutor`），主代码经 `ExecuteSqlSupport`（core）**反射加载**调用——Community 下该类永不加载，无 `NoClassDefFoundError`；
- 自检测试：plugin.xml 含 optional depends；无 database 插件时按钮隐藏逻辑单测。

### 2.2 按钮与流程骨架（T-M17-02）

- `SqlPreviewPanel` 工具栏新增「执行 SQL」按钮（`panel.executeSql` bundle 中英文案）；
- 点击流程：取 `editor.document.text`（当前 SQL，含回填与手动编辑）→ 判定 `com.intellij.database` 可用（不可用→隐藏按钮或点击提示）→ 数据源枚举与选择 → 临时文件创建 → 打开/执行；
- 无数据源：提示打开 Database 工具窗口新建（bundle 文案）。

### 2.3 临时文件与执行（T-M17-03/04）

1. **临时文件创建**：spike 结论优先 **Database 控制台**（天然绑定数据源 + 临时文件语义）；不可用则 **Scratch 文件**（内容 = 当前 SQL）打开到编辑器；
2. **执行**：控制台方式打开后**自动触发 run**（spike 确认触发 API，不可行则打开后用户 Ctrl+Enter——仍满足"自动创建临时文件"主诉求）；非控制台方式用 `DatabaseSessionManager` + `RawRequest` 直接执行；
3. **结果呈现**：执行成功 → 通知（影响行数/已完成）；失败 → 异常弹窗（区分连接失败/驱动缺失/SQL 错误）；
4. 临时文件生命周期：Scratch 由 IDE 管理无需清理；系统临时文件在编辑器关闭时删除（可选增强）。

### 2.4 测试与验收（T-M17-05/06）

- 可单测：数据源选择逻辑（0/1/多分支）、`ExecuteSqlSupport` 可用性判定、SQL 文本提取、Community 降级（按钮隐藏判定）；
- 手动验收（Ultimate）：按钮 → 选 DS → 临时文件/控制台打开（绑定 DS）→ 执行有结果/异常提示；多数据源选择对话框；无数据源提示；
- 手动验收（Community）：插件加载正常、无按钮、无日志异常；
- 全量测试 + `buildPlugin` + CHANGELOG/README 更新。

## 4. 风险与应对

| 编号 | 风险 | 影响 | 应对 |
|------|------|------|------|
| M17-R1 | `com.intellij.database` 执行 API 变动（2025.2 已移除 GridDataRequest；facade/SmartStatements 官方标注"非最终"） | 执行链路失效 | spike 先行；优先 session 级稳定 API（`DatabaseSessionManager` + `RawRequest`）；执行失败兜底提示而非崩溃 |
| M17-R2 | 构建切 Ultimate 平台下载受限（CDN 不可达；本机安装可能为 Community） | 无法编译 database 引用 | 优先 `local(...)` 指向本机安装（确认 Ultimate）；gradle.properties 已配代理；最坏方案：database 引用全部反射 + 不编译依赖（`provided` 式），运行时再验证 |
| M17-R3 | 数据源与临时文件的绑定机制不确定（控制台 API 签名/可用性） | 文件打开后数据源未绑定 | 控制台方式 spike 定稿；不可用则 scratch + 编辑器状态栏 DS 选择器（用户手动选，属可接受兜底）；自动执行降级为"打开即可执行" |
| M17-R4 | 无 JDBC 驱动/连接失败（社区实测：沙盒无驱动时回调不触发） | 执行静默失败 | 前置检查（数据源有效）+ 超时/异常提示；手动验收清单含"无驱动环境"用例 |
| M17-R5 | Community 回归（optional 依赖加载异常） | 社区版插件不可用 | 反射隔离（主代码零直接引用）+ 自检测试 + Community 沙盒手动验证任务 |
| M17-R6 | 方言不一致（插件配置 vs 数据源方言） | 分页等子句执行报错 | 文档说明 + 风险提示文案；增强项（按数据源方言重渲染）后续排期 |
