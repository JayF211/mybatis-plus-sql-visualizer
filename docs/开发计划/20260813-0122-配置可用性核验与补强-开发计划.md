# 配置可用性核验与补强 + 动态插件支持——开发计划（M14.7）

> 本文档是 **MyBatis-Plus SQL Visualizer** 的 M14.7 增量计划：对**全部配置项做可用性核验**（是否存在"死配置"——仅设置页存在、业务链路未读取），**补齐配置→行为的集成测试**与文档说明，并**支持动态插件（免重启安装/更新）**。
>
> 背景：① 用户询问「替换 ? 占位符」开关时发现其为**死配置**（M14.6 已接通，commit 3ecfd1e），要求核验其他配置项；② 用户实测安装/更新插件仍需重启，希望免重启（IDEA 2020.1+ Dynamic Plugins 机制）。
>
> 配套文档：[主开发计划](../开发计划/20260812-1058-MP-SQL可视化-开发计划.md)、[M14 开发计划](../开发计划/20260813-0000-设置页修复与弹窗自适应-开发计划.md)。
> 当前基线：v1.8（M14）+ M14.1~14.6 已提交，测试全绿。

---

## 1. 核验结论（已完成，证据驱动）

`PluginSettings.State` 共 **5 个配置项，全部已接通业务链路，无死配置**：

| 配置项 | 默认值 | 业务读取点 | 接通状态 |
|--------|--------|-----------|---------|
| `dialect`（数据库方言） | MySQL | `SqlPreviewService.currentDialect()` → `DialectRegistry.byName` → 分页子句渲染（`generateWithParams(dialect)`） | ✅ 已接通 |
| `replaceParams`（替换 ? 占位符） | true | `SqlPreviewService.preview()` → `WrapperLocator.locateWithTable(resolveVariables)` → `ArgResolver` 变量求值开关 | ✅ 已接通（M14.6） |
| `formatSql`（格式化多行） | true | `SqlPreviewService.formatSql()` → `buildPreviewResult` 多行/单行 + 面板 `compactMode` 初始值 | ✅ 已接通 |
| `showGutterIcon`（gutter 图标） | true | `SqlGutterLineMarkerProvider.gutterEnabled()`（每次渲染读取，切换即生效） | ✅ 已接通 |
| `language`（界面语言） | zh | `MpSqlVisualizerBundle.currentLocale()`（每次 message 读取，切换即生效） | ✅ 已接通 |

**已随功能删除、非配置项**：`autoPreview`/`hoverDelay`（M14.1 悬停预览移除时从 State 同步删除，无残留）。

**测试缺口（本计划补强）**：配置→行为的**集成测试基本空白**——现有测试仅覆盖纯渲染（`DialectTest` 7 个方言渲染用例）与单个开关（`replaceParams` M14.6 新增用例）；`formatSql`/`showGutterIcon`/`dialect` 的「设置值 → 输出差异」链路无测试保障，存在未来回归为死配置的风险。

## 2. 方案设计

### 2.1 集成测试补齐（T-M14.7-01）

在 `SqlPreviewServiceTest`（fixture 环境，可 mock `PluginSettings`）新增配置→行为用例：

| 用例 | 验证点 |
|------|--------|
| `dialect配置_分页子句按方言渲染` | settings.dialect=MySQL/PostgreSQL/Oracle → `last("limit 10")` 预览 SQL 分别渲染 `LIMIT 10` / `LIMIT 10`（PG 同款或 `LIMIT 10 OFFSET`）/ Oracle 分页写法 |
| `formatSql配置_初始多行或单行` | formatSql=true → PreviewResult.sql 多行缩进、compactSql 单行；false → sql 单行（面板 compactMode 初始化对齐） |
| `showGutterIcon配置_关闭不生成图标` | 开关关闭 → gutter provider 返回 null（不渲染图标）；开启 → 生成（现有 fixture 用例扩展） |
| `replaceParams配置_已有用例保留` | M14.6 `testReplaceParamsOffKeepsVariablePlaceholder` 为回归基准 |

> 边界说明：`language` 的 en/AUTO 分支依赖 `PluginSettings.getInstance()`（application service），纯单测无法注入——由**手动验收清单**覆盖（切换 zh/en/跟随系统后弹窗/设置页文案），自检测试已断言默认中文兜底（`PluginDistributionSelfCheckTest`）。

### 2.2 设置变更即时性说明（T-M14.7-02）

**行为澄清（文档化，不改代码）**：
- **瞬时性**：弹窗是瞬态产物——设置变更后**重新触发预览**（快捷键/右键/gutter）即按新配置生效，无需重启 IDE；
- **缓存**：`WrapperCache` 缓存键已含 `resolveVariables` 维度（M14.6）；`dialect`/`formatSql` 不进缓存（渲染阶段），天然即时；
- **弹窗内「单行/多行」按钮**：仅当前弹窗的**临时视图切换**，不写回 `formatSql` 配置（避免意外改全局）；重新打开弹窗按配置恢复。

### 2.3 README 配置表（T-M14.7-03）

README「配置」小节升级为表格：每项**作用 + 默认值 + 生效时机**，消除"开关是否生效"的疑问（对齐用户对死配置的关切）。

## 6. 动态插件支持（免重启安装/更新）——M14.7 增补

**用户反馈**：实测安装/更新插件后 IDEA **仍提示重启**，希望免重启（IDEA 2020.1+ 支持 Dynamic Plugins，条件是启动时逐项检查）。

**已核验的符合项**：无 `require-restart`、无 `<component>`、无自定义 `<group>`、扩展点均为常见动态兼容类型、action id 唯一。

**可疑根因候选（按可能性排序）**：
1. **`<depends>org.jetbrains.kotlin</depends>`（最可疑）**：Kotlin 插件（bundled）历史上不支持动态卸载；**依赖非动态插件 → 本插件被判定非动态**（硬规则）。本插件**不处理 Kotlin PSI**（仅 Java），该依赖为模板遗留——移除后 kotlin-stdlib 仍由构建自动打包（composedJar），功能不受影响；
2. `codeInsight.lineMarkerProvider language="JAVA"` / 自定义语言 EP（parserDefinition/fileType/completion.contributor）：按官方文档为动态兼容，但需日志佐证；
3. `com.intellij.java` 依赖：内置模块常驻加载，大概率非原因（大量 Java 插件为动态）。

**证据收集（T-M14.7-05）**：IDEA 启动日志（Help → Show Log）中插件动态判定记录（grep `mybatis`/`PluginManager`/`dynamic`），定位被拒的具体原因（如 "plugin depends on non-dynamic plugin" / "EP not dynamic"）。

**修复与验证（T-M14.7-06）**：
- 按证据分支：首选**移除 `<depends>org.jetbrains.kotlin</depends>`**（保留 `com.intellij.java`）；若日志指向 EP，再评估对应调整（lineMarkerProvider 若被拒 → 评估替代方案；自定义语言 EP 为核心功能不可移除 → 文档化边界）；
- 验证：`clean buildPlugin` → 实测安装/更新**不提示重启** + 启动日志出现 dynamic 标记；
- 开发期增强（可选）：`build.gradle.kts` 开启 `runIde { autoReload = true }`（Gradle 插件 Auto-Reload，sandbox 中改码即时生效）。
