# SQL 监听手动启动无需等待项目运行

> 创建日期：2026-08-20
> 状态：**已完成**（e63d0db + 91e6939，2026-08-20）
> 优先级：P1（用户反馈：目前 SQL 监听只有项目启动了才能手动开启）
> 最终方案：Option A armed 态（见 `docs/架构设计/02-核心流程详解.md` §6）

## 问题描述

用户点击「捕捉」按钮时，如果项目尚未运行（无主运行控制台），当前实现只挂载桥 + 轮询、**不进入捕捉态**。项目真正启动后，`onConsoleAppeared()` 仅响应「设置项 `logAutoCaptureOnStart`」的自动启动路径，**手动启动的意图被丢失**——用户以为点过了就能自动监听，实际什么都没发生。

## 根因

`SqlLogManager` 有两条启动路径收敛到 `startCapture()`：

| 路径 | 触发方式 | 无主控制台时的行为 |
|------|----------|-------------------|
| 自动启动 | `LogStartupCapture` / `onConsoleAppeared()` | 守卫挂载桥等待，设置开则 `onConsoleAppeared` 触发 |
| 手动启动 | 用户点击「捕捉」按钮 | 守卫挂载桥等待，**但 `onConsoleAppeared` 不识别此意图** |

断裂点在 `onConsoleAppeared()`：

```kotlin
fun onConsoleAppeared() {
    if (capturing) return
    if (!PluginSettings.getInstance().state.logAutoCaptureOnStart) return  // ← 手动启动此处即返回
    startCapture()
}
```

手动启动时 `logAutoCaptureOnStart` 为 false → 直接 return → 控制台出现了也不捕捉。

## 修复方案

### 核心思路：记录「用户主动请求」意图

增加 `userRequestedCapture` 布尔标志——用户手动点击「捕捉」时置 true，`onConsoleAppeared()` 多一个条件分支识别它。

### 改动点

**文件**：`src/main/kotlin/cn/song/mybatisplus/visualizer/log/SqlLogManager.kt`

#### 1. 新增字段

```kotlin
/** 用户主动点击「捕捉」请求标志——项目未运行时置 true，主控制台出现时自动进入捕捉态。 */
@Volatile
private var userRequestedCapture = false
```

#### 2. `startCapture()` 置位

```kotlin
fun startCapture() {
    if (capturing) return
    if (!hasMainConsole()) {
        userRequestedCapture = true  // ← 新增：记录用户意图
        LOG.info("startCapture: 无运行中的主控制台——挂载监听等待项目运行（用户已请求捕捉）")
        if (bridge.attach(project)) {
            bridge.startPolling()
        }
        return
    }
    // ... 后续不变
}
```

#### 3. `onConsoleAppeared()` 识别手动请求

```kotlin
fun onConsoleAppeared() {
    if (capturing) return
    val autoStart = PluginSettings.getInstance().state.logAutoCaptureOnStart
    if (!autoStart && !userRequestedCapture) return  // ← 新增：用户请求也触发
    LOG.info("onConsoleAppeared: 检测到新控制台，自动重启捕捉（autoStart=$autoStart, userRequested=$userRequestedCapture, project=${project.name}）")
    startCapture()
}
```

#### 4. `stopCapture()` 清除标志

```kotlin
fun stopCapture() {
    if (!capturing && !userRequestedCapture) return  // ← 新增：等待态也须幂等守卫
    userRequestedCapture = false  // ← 新增：清除用户意图
    if (!capturing) return
    // ... 后续不变
}
```

#### 5. `dispose()` 清除标志

```kotlin
override fun dispose() {
    userRequestedCapture = false  // ← 新增
    capturing = false
    // ... 后续不变
}
```

#### 6. UI 文案反馈（可选增强）

`SqlLogPanel.CaptureAction.update()` 增加「等待项目运行」中间态提示：

```kotlin
override fun update(e: AnActionEvent) {
    when {
        manager.capturing -> {
            e.presentation.icon = AllIcons.Actions.Suspend
            e.presentation.text = MpSqlVisualizerBundle.message("log.panel.stop")
        }
        manager.isWaitingForConsole -> {  // ← 新增中间态
            e.presentation.icon = AllIcons.Actions.Execute
            e.presentation.text = MpSqlVisualizerBundle.message("log.panel.capture.waiting")
            e.presentation.description = MpSqlVisualizerBundle.message("log.panel.capture.waiting.desc")
        }
        else -> {
            e.presentation.icon = AllIcons.Actions.Execute
            e.presentation.text = MpSqlVisualizerBundle.message("log.panel.capture")
        }
    }
}
```

需要新增测试访问器：

```kotlin
/** 是否处于「等待主控制台出现」中间态（测试断言）。 */
@Volatile
var isWaitingForConsole: Boolean = false
    private set
```

`startCapture()` 中 `userRequestedCapture = true` 后设 `isWaitingForConsole = true`；`onConsoleAppeared()` 触发 `startCapture()` 进入捕捉态后设 `isWaitingForConsole = false`；`stopCapture()` / `dispose()` 也清零。

> ⚠️ 按钮图标在等待态仍为 Execute（不引入新图标依赖），仅文案变化。图标切换由既有 `refreshToolbar()` 链路驱动——进入捕捉态后 `capturingListeners` 触发 → `updateActionsAsync()` → 图标翻 Suspend。

### 状态机

```
[空闲] --点击捕捉(无控制台)--> [等待中: userRequestedCapture=true, isWaitingForConsole=true]
[等待中] --项目启动(console出现)--> [捕捉中: capturing=true, isWaitingForConsole=false]
[等待中] --点击停止--> [空闲: 全部false]
[捕捉中] --点击停止/控制台移除--> [空闲]
[空闲] --点击捕捉(有控制台)--> [捕捉中]  （既有路径不变）
```

| T05 | 有控制台手动启动（回归） | 有主控制台时点击捕捉 | 直接进入捕捉态，`userRequestedCapture` 不被置位（已被捕捉） |
| T06 | dispose 清理（回归） | 等待中关闭项目 | 全部标志清零，无泄漏 |

## 风险与权衡

1. **最小侵入**：核心修复只加一个 bool 字段 + 两处条件判断，不改变既有状态机骨架。
2. **UI 文案增强可选**：中间态文案是锦上添花，核心逻辑不依赖它。可先做核心、后续补 UI。
3. **向后兼容**：`logAutoCaptureOnStart` 自动路径完全不受影响，只新增一条触发路径。
4. **并发**：`userRequestedCapture` 标记 `@Volatile`，单项目内仅 EDT 操作，无竞态风险。
