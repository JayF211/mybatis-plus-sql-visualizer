## 一、背景与依据

MyBatis 批量操作（`foreach` 生成的逐条 DELETE、批处理日志）经日志还原后常呈现几十条同构语句：`DELETE FROM t WHERE id=1; DELETE FROM t WHERE id=2; ...`。多语句确认浮层（T-PreviewUx-Pack #4）会忠实列出全部候选——正确，但用户在 50 条候选里无法一眼看出「这批就是在删 50 个 id」。DBX 在网格批删场景把等值同列谓词合并为 `col IN (k1,...,kN)` 展示，配字节预算与行数上限防爆炸，复杂谓词原样保留——这个「等价简化预览」形态适合本插件的多语句确认浮层。

边界必须先钉死：**合并只用于预览参考，执行文本永远是逐条原样**——合并形态一旦真的替换执行语句，等价性就要本插件背书（NULL 语义、类型、方言函数差异），违背正确性人设。浮层里加一行「可合并为 …」的参考信息，是零风险的形态。

## 三、方案

**T-BI-01（纯逻辑核心）**：新增 `util/BatchPredicateMerge.kt`（object，零 UI 依赖；若 O-13 已交付则依赖 util/SqlStatementSplitter 的切分产物，否则自带简化切分输入约定）。输入语句列表，输出合并预览行（或 null）：

- 仅同表 + 同语句类型（DELETE 优先，UPDATE 不合并——SET 不同构）+ WHERE 为单列等值谓词（`col = literal`）；
- 合并产物 `DELETE FROM t WHERE col IN (k1, k2, ...)`，按 DBX 双约束：字节预算（默认 8KB，合并产物超限即截断计数展示「…等 N 条」）+ 行数上限（默认 500）；
- 复合键、IS NULL、函数包裹、BINARY 前缀、非字面量（子查询/列对列）任一命中 → 不合并返回 null（回退原形态，绝不部分合并）；
- 字面量直接文本拼接（不做类型转换——预览参考形态，非执行文本）。

**T-BI-02（浮层接线）**：多语句确认浮层在候选列表上方增加一行中性提示（可折叠/默认显示）：「检测到 N 条同表等值删除，可合并为：`DELETE FROM t WHERE id IN (…50 个值…)`（仅预览参考，执行仍逐条）」。零新弹窗（弹窗克制红线），文案进 bundle 双语。复制行为零改动（batchCopySql 逐字节同构红线不触）。

**T-BI-03（i18n + 测试）**：双语键 2 个；测试表驱动——合并正例（10/500/501/超字节预算）、各类回退（复合键/IS NULL/子查询/UPDATE/混表）、null 路径、SQL 注入样例（字面量含引号转义原样拼接的显示正确性）。

**T-BI-04（文档同步）**：CHANGELOG [Unreleased] Added、变更记录总册行、第四轮报告 §8.4 O-14 状态回填。

## 四、验收标准

1. 合并纯函数表驱动测试全绿，回退路径（任何不满足条件 → null）全覆盖。
2. 浮层提示为单行参考信息，无新弹窗；执行文本与复制文本逐字节不变（防回归断言）。
3. 50 条批删样例浮层提示正确截断展示；混合样例（5 条同构 + 1 条异构）按可合并子集或 null 诚实处理（不合并异构，不静默丢语句）。
4. 全量 test 绿（基线 4246/0/0/6 + 新增数），跑前按铁律并行登记。

## 五、真机走查清单（留人工）

1. 真机还原一批 foreach DELETE 日志（≥10 条）：浮层出现合并参考行，执行后逐条原样送达控制台。
2. 混合批次（同构+异构）：提示行按实现行为如实展示或缺席，无误导。

## 六、风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 等价性误解 | 用户以为点的是「合并执行」 | 文案双保险（「仅预览参考，执行仍逐条」）+ 执行文本零改动断言 |
| 字面量转义显示走样 | 含引号/转义的值拼进 IN 展示串失真 | 展示串用原字面量文本直接拼接（不做再转义），表驱动含引号样例 |
| 浮层信息过载 | 提示行挤占候选区 | 单行 + 截断计数；超预算只显示「…等 N 条」 |
| 与 O-13 时序耦合 | 依赖统一切分产物 | 若 O-13 未先行，本任务自带最小输入约定（语句列表），接口对齐后续收编 |
