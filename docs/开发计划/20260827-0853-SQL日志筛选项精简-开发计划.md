# SQL 日志筛选项精简 开发计划

- 日期：2026-08-27
- 状态：待开发
- 关联：P-06（日志智能分组/高频折叠）、T-M31.5（去重勾选开关）

## 一、背景

SQL 日志 tab 工具栏下方有一整行筛选条：「全部 / 查询 (0) / 插入 (0) / 更新 (0) / 删除 (0)」五个切换按钮 + 「高频折叠」按钮（检测到耗时信息时还会追加「耗时排序」按钮）。这一行占位较多，在窄侧边栏下还会折行，且受设置页「显示类型筛选条」开关控制——两处入口关联，认知成本高。

用户决定精简：

1. 类型筛选收成单个「SQL类型」下拉框，放在工具栏行「移除重复的sql」勾选框旁边；
2. 「高频折叠」按钮删除，折叠功能整体下线；
3. 开启「移除重复的sql」后，被去重丢弃的条数直接显示在勾选框旁，作为折叠功能的替代——重复多少一眼可见，不需要折叠交互。

## 二、现状分析

两个值得注意的现状行为：

- `applyFilter` 在筛选条隐藏时照样执行，且 `activeFilter` 不含 OTHER——TRUNCATE 等其他语句目前默认被过滤掉。改下拉框后「全部」应显示所有类型（含 OTHER），顺带修正这一隐性过滤。
- 各类型按钮上的计数（如「查询 (0)」）是筛选条的主要占位来源。下拉框方案不保留计数，用户只要求去重计数。

## 三、方案决策

| 决策点 | 结论 | 理由 |
|--------|------|------|
| 类型筛选形态 | 单选 `ComboBox`：「全部 / 查询 / 插入 / 更新 / 删除」，默认「全部」 | 用户明确要求；单选语义比按钮组多选简单直接 |
| OTHER 类型归属 | 「全部」包含 OTHER；下拉不单列 OTHER 项 | 修正现状隐性过滤；OTHER 极低频，单列反而占选项 |
| 高频折叠 | 整体删除（按钮 + 分组逻辑 + LogFrequencyGrouper + 死配置 + 相关测试） | 按钮没了功能无入口；去重计数替代其核心价值（识别重复 SQL） |
| 耗时排序按钮 | 保留，从筛选条挪到工具栏行（去重勾选框之后） | 用户未要求删除；原本仅在检测到耗时信息时出现，不占常驻空间 |
| 去重计数展示 | 勾选框文案动态追加：`移除重复的sql (N)`，N=0 或关闭去重时不显示计数 | 用户原话「在重复sql旁边直接计数即可」；不加新组件 |
| 计数口径 | 本轮捕获以来被去重丢弃的条数；清空列表归零；去重开关重新开启时归零 | 窗口期去重是「捕获时丢弃」，计数与列表内容保持同生命周期 |
| 设置页「显示类型筛选条」 | 删除（状态字段 + 面板行 + bundle 键） | 下拉框常驻工具栏行，无需开关；死配置一并清理 |

## 四、改动清单

### 4.1 SqlLogEntryBuffer.kt — 去重计数

- 新增丢弃计数：`@Volatile var dedupeRemovedCount: Long = 0`（private set），`addEntry()` 命中 `isDuplicate` 分支时 +1 后再返回 false。
- `clear()` 时归零；新增 `fun resetDedupeCount()`，供去重开关从关到开时调用。
- 计数增减不触发 `notifyChanged()`（丢弃本就不通知，维持现状语义）。

### 4.2 SqlLogPanel.kt — 主要改造

删除：

- `activeFilter` 集合、`typeButtons`/`allButton`/`foldButton` 字段及测试访问器；
- `buildFilterBar()`/`updateFilterBar()`/`syncTypeButtonSelection()`/`syncAllButtonSelection()`；
- `filterBarPanel`/`filterSeparator` 字段与 `refreshFilterBarVisibility()`；init 中 tab 切换监听、`SettingsChangeListener`、`refreshList()` 里对它的三处调用（监听器保留 `updateHistoryTabVisibility()` 部分）;
- 折叠链路：`frequencyFoldEnabled`/`groupedEntries`/`findFoldedGroup`/`applyFrequencyFold`/`rebuildListModel` 折叠分支/cellRenderer 折叠徽章/`mouseClicked` 单击展开分支/`isFoldEnabled`/`currentGroupedEntries` 访问器；
- `WrapLayout` 内部类（仅筛选条使用）；
- `labelForType` 若下拉改用枚举 + 现有 bundle 键映射可保留或并入新逻辑。

新增/调整：

- 工具栏行（`buildToolbar()`）在 `dedupeCheckBox` 后追加：`typeFilterCombo`（`DefaultComboBoxModel`，项 = 全部 + 4 类型，内部映射 `StatementType?`，null 代表全部）+ `sortButton`（原耗时排序按钮，逻辑不变）。
- `applyFilter` 改单选语义：选中类型为 null → 全部透传（含 OTHER）；否则只留该类型。
- `refreshList()` 管线简化为 过滤 → 排序 → 直接填充 `listModel`（`GroupedEntry` 概念移除）；类型计数逻辑删除。
- 去重计数刷新：`dedupeCheckBox` 的 ActionListener 中，开启时调 `resetDedupeCount()`；`manager.addUiListener { refreshList() }` 的刷新链路里同步勾选框文案（`log.panel.dedupe` + 有计数时追加 `" (${count})"`，去重关闭时不追加）。
- 测试访问器更新：新增 `typeFilterCombo`（headless 断言选中项），删除折叠相关访问器。

## 七、风险与回滚

- `PluginSettings` 删字段会让老用户 `mp-sql-visualizer.xml` 中的残留键被忽略——PersistentState 机制天然兼容，无需迁移。
- 折叠功能为删除性变更，若有用户依赖高频折叠，回滚需 revert 整个提交（提前在发行说明标注「功能移除」）。
- 下拉框单选替换按钮组多选属交互收窄（原来可同时只看「查询+更新」）：如后续有需求，可在下拉项追加组合选项，本期不做。
