## 二、缺口清单

任务编号规则：J-x = JPA/Hibernate 侧，M-x = MP/MPJ 侧，C-x = 横切。每条附证据位置。

### 2.1 P0：JPA 写路径与断链（用户点名问题所在）

**J1 Spring Data CRUD API 预览（核心缺口）**

`save / saveAll / findById / findAll / existsById / count() / deleteById / delete / deleteAll(ById) / flush / getOne / getReferenceById` 在 psi/jpa、converter/jpa、SqlPreviewService 中零代码引用。现状两类表现：

- `findById` / `findAll` / `existsById` 等不在 MP 批量方法名表（BatchOperationConverter.BATCH_OPERATIONS，psi/BatchOperationConverter.kt L69）内，无 gutter 锚点，完全无预览。
- `save` / `deleteById` 撞 MP 方法名：WrapperAnchorDetector L102 按方法名锚定后走 MP 批量转换器，实体解析经 `isLikelyEntity`（类名含 "Entity" 即命中，L219 附近）后由 MP EntityResolver 解析——**只认 `@TableName`，无 `@TableName` 时回退类名驼峰转下划线**（psi/EntityResolver.kt resolveInternal 开头）。demo 的 `UserEntity`（`@Table(name = "t_user")`、`@Column(name = ...)`）会被输出成 `INSERT INTO user_entity` + 字段名当列名，表名列名全错，比不识别更误导。

方案：BatchOperationConverter 增加 receiver 家族感知——qualifier 类型为 `JpaRepository / CrudRepository / Repository` 系（复用 DerivedMethodLocator 的基类识别）时，实体表列改走 `JpaEntityResolver`（已支持 @Table/@Column/@GeneratedValue/@ManyToOne）；INSERT 模板对齐 Hibernate 语义：`@GeneratedValue(IDENTITY)` 主键不进 INSERT 列，`SEQUENCE` 按方言附序列提示。SELECT/DELETE 族复用既有主键等值模板，注解元数据换源即可。

**J2 UPDATE JPQL/HQL 语句模型**

JpqlConverter/HqlConverter 只对 DELETE 特判（JpqlConverter.kt L98、HqlConverter.kt L123 附近），UPDATE 字符串走 SELECT 管道：statement 恒为 SelectStatement，SET 子句无展开、参数面板无 SET 语义。demo 已有真实用例 `updateStatusByJpql`（`@Modifying + @Query("UPDATE UserEntity u SET ...")`）与 `hibernateHqlUpdate`（`session.createQuery("UPDATE ...")`）。方案：UPDATE 检测 → 解析 SET 子句 → 复用 MP 侧现成的 UpdateStatement 模型生成（模型与渲染器都在，缺的只是 JPA 侧解析入口）；`@Modifying` 注解作为增删改派生方法与 JPQL 的门控/提示信号（当前全项目零引用）。

**J3 派生查询前缀断链（小成本高收益）**

PartTreeParser 支持 `query/search/stream` 前缀（PartTreeParser.kt L208 QUERY_KEYWORDS），但定位门控 DerivedMethodLocator.PART_TREE_PREFIXES（L53-55）只有 `find/findAll/read/get/count/exists/delete/remove`——`queryByStatus` 解析得动但永远进不了预览。同文件 L96 强制要求方法名含 `By`，导致 `findAll()` / `count()` 一律不识别（前缀表里的 `findAll` 是死条目）。补齐门控列表与无 `By` 形态即可。

**J4 半成品收尾三件**

- IgnoreCase：PartTreeParser 剥离了尾部 `IgnoreCase/AllIgnoreCase`，但 DerivedQueryConverter.buildCondition 的 ignoreCase 参数在条件 when 分支中完全未使用——应生成 `LOWER(col) = LOWER(?)`。条件中间位置的 IgnoreCase 会被并入属性名（PartTreeParser 仅认尾部）。
- 派生查询 IN 多值提示：previewDerivedQuery 调 buildJpaPreviewResult 未传 inClauseParams（SqlPreviewService.kt L356 附近），面板缺 `inList` hint，JPQL 路径有。
- CriteriaQuery `distinct(true)`：方法名在 CriteriaQueryLocator 名单（L43）但扫描 when 无分支、CriteriaQueryModel 无字段——死条目。

### 2.2 P1：JPA 高级查询与写扩展

**J5 JpaSpecificationExecutor.findAll(Specification)**：demo `specificationQuery` 已有四条件动态 Specification 用例（lambda 体 `root.get("x")` + `cb.equal/like/isNull`）。方案：把 Specification lambda 当谓词源，复用 CriteriaQueryLocator/CriteriaQueryConverter 的条件解析（同一套 root/cb API），输出 SELECT。

**J6 EntityManager 写/单查 API 与 CriteriaUpdate/CriteriaDelete**：`persist / merge / remove / find(Class, id)` 零引用（EntityManager 目前仅 `createQuery/createNamedQuery/createNativeQuery` 纯方法名命中）；`cb.createUpdate/createDelete`（CriteriaUpdate/CriteriaDelete）零引用。persist/merge → INSERT/UPDATE 模板，remove → DELETE 主键等值，find → SELECT 主键等值；CriteriaUpdate/Delete 建模为 UpdateStatement/DeleteStatement（set/where 已有解析件）。

**J7 JOIN ON 读真实 @JoinColumn**：JOIN FETCH、JPQL JOIN、Criteria JOIN 三路的 ON 条件目前是固定猜测 `alias.id = root.<relation>_id` 并标注「推断的ON条件，请验证」（JpqlConverter L228、CriteriaQueryConverter L328-354）；只有派生查询嵌套属性用真实 `TableInfo.associations`（JpaEntityResolverJoinTest 9 用例基础已在）。三路统一改读 `@JoinColumn(name)` / `@JoinTable`，`referencedColumnName` 优先。

**J8 Hibernate 注解软删除/动态 SQL**：`@Where / @SQLRestriction(6.3+) / @SoftDelete(6.4) / @SQLDelete+@Loader / @DynamicUpdate` 零支持。范围控制：`@Where`/`@SQLRestriction` 静态子句注入全查询（类比 MP @TableLogic 注入点），`@SoftDelete` 按默认模板渲染，`@SQLDelete` 自定义脚本原样透传展示。

### 2.3 P1~P2：JPA 触发面与基建

**J9 调用点锚点**：派生方法/@Query 锚点只在 Repository 声明处，service 里 `userRepository.findByName(x)` 调用点无预览（ConvertToSqlAction.tryJpaFallback L224-227 检查的是宿主方法名而非被调方法）。gutter 反查缓存（T-CacheInfo）与 EntrySourceMatcher（M37.1，未合并分支）已有「声明↔调用」基建可复用。

**J10 Pageable/Sort 全路径**：现仅派生查询 Pageable → LIMIT 占位（applyPageableLimit）；`previewJpql`/`previewHql`/`previewCriteriaQuery` 不处理 Pageable；`PageRequest.of(current,size)` / `Sort.by(...)` 参数零解析。按方言渲染 LIMIT/OFFSET 与 ORDER BY。

**J11 .hbm.xml 两处疑似失效**：HbmXmlEntityResolver 每文件只解析第一个 `<class>`（L62 findFirstSubtag）；文件查找用 `FilenameIndex.getFilesByName(project, "*.hbm.xml", ...)`（L41），该 API 按字面文件名匹配，通配符不展开——多实体 hbm 工程可能整体查不到。需真机/沙盒确认后改用按扩展名过滤遍历。

**J12 自研 DAO/HibernateTemplate 方法族扩展**：HibernateTemplate 仅 `find/findByNamedParam/findByValueBean/iterate` 四方法；`findByCriteria / executeFind / createSQLQuery`（老 Hibernate3 常见）不在 HqlQueryLocator.CREATE_QUERY_METHODS（L73）。NamedQueryLocator 的注解 FQN 写死 `javax.persistence`（L44-47），jakarta 靠短名兜底，应对齐项目惯例（短名兜底 + FQN 常量双轨）。

**J13 JPQL 子查询/UNION 真转换（大工程，按需立项）**：现 detectSubquery 检测后仅附加「仅做基础转换」注释（JpqlConverter L319-334），EXISTS 子查询（demo findWithOrderExists）依赖字符串透传。先做 EXISTS/IN 子查询两类高频形态，UNION 远期。

### 2.6 二轮 API 全集调研增补（2026-09-04，任务 J14~J23）

以下任务来自《[JPA-Hibernate官方API覆盖矩阵](../架构设计/JPA-Hibernate官方API覆盖矩阵.md)》逐行盘点中无法归入 J1~J13 的新缺口，均以本地 jar javap 实证。

**J14 主键与生成值策略**：`@GeneratedValue` 四策略（IDENTITY→INSERT 无该列；SEQUENCE→前置 select nextval；TABLE→序列表 hi/lo；UUID→应用端生成；AUTO→方言回退）+ `@SequenceGenerator/@TableGenerator` + Hibernate `@CreationTimestamp/@UpdateTimestamp/@GenericGenerator/@UuidGenerator/@Generated`。是 J1 INSERT 模板正确性的前置依赖，随 J1 同步实施基础形态（IDENTITY 不进 INSERT 列），策略全量在 M42。

**J15 fetch 与锁语义注解**：`@EntityGraph`（attributePaths→LEFT JOIN FETCH，P0 级——fetch join 查询当前整体丢失 JOIN）+ jakarta `@NamedEntityGraph` 引用链 + `@Lock(LockModeType)`→FOR UPDATE + `@QueryHints` + Hibernate `@Fetch(FetchMode)`/@BatchSize/@FetchProfile + `enableFetchProfile`。

**J16 存储过程与命名原生查询**：`@Procedure`（包名陷阱：`org.springframework.data.jpa.repository.query.Procedure`）+ `createStoredProcedureQuery` 族 → CALL/EXEC 渲染 + `@NamedNativeQuery` + `@SqlResultSetMapping` 族（createNativeQuery 第 3 参）+ `@Loader/@SQLSelect/@HQLSelect`。

**J17 Criteria 函数与子查询全集**：CriteriaBuilder 函数类全缺（字符串 LOWER/UPPER/SUBSTRING/CONCAT/LOCATE/TRIM、数值 ABS/CEILING/FLOOR/ROUND/SQRT/POWER、算术 sum/prod/diff/quot/mod、coalesce/nullif、selectCase、literal/parameter、集合 isEmpty/size/isMember、countDistinct、gt/ge/lt/le Number 变体）+ 子查询（subquery/correlate/exists/all/any/some，与 J13 合并实施）+ `joinCollection/joinSet/joinList/joinMap` 8 重载 + `Join.on` + `fetch()` 6 重载 + `multiselect(List)/orderBy(List)/groupBy(List)` List 重载 + `createTupleQuery` + CriteriaUpdate/Delete 的 where 复用。**名单清理**：`notIn/getRestriction` 为死条目（javap 证 3.1.0 无 notIn 方法）。

**J18 实体映射深水区**：`@Column(insertable/updatable)`、`@Table(schema/catalog)`、`@ElementCollection/@CollectionTable`（N+1 高发面）、`@Embedded/@EmbeddedId/@IdClass/@MapsId/@AttributeOverride(s)`、`@Inheritance` 三策略（SINGLE_TABLE 判别谓词 / JOINED 每子类 JOIN / TABLE_PER_CLASS UNION ALL）+ `@Discriminator*`、`@SecondaryTable(s)`、`@OrderBy/@OrderColumn`、`@MapKey` 族、Hibernate `@DynamicInsert/@DynamicUpdate/@Immutable/@Subselect/@Formula/@ColumnTransformer`。体量大，按子任务立项。

**J19 HQL 高级特性**（原 J13 扩展）：UNION/INTERSECT/EXCEPT（6.1）、WITH CTE（6.1）、INSERT...SELECT、窗口函数 10 种、LISTAGG/ROLLUP/CUBE、派生根/lateral、TREAT/TYPE/ENTRY/KEY/VALUE、集合谓词全集（IS EMPTY/SIZE/INDEX/ELEMENT/KEYS/VALUES，现仅 MEMBER OF）、`fk()/naturalid()` 实体函数、OFFSET..FETCH 标准分页、`processing.@Find/@HQL`（6.4 注解处理器）。

**J20 Query By Example**：`QueryByExampleExecutor` 7 方法 + `Example.of/ExampleMatcher` 全 API（StringMatcher 6 形态→LIKE 映射、NullHandler 决定 WHERE 剔除、MatchMode.ANY→OR 连接）。demo 补用例后随 J5 同管道实施（复用等值条件模板）。

**J21 HibernateTemplate 全方法族**（原 J12 扩展）：现支持 4 方法恰为 deprecated 子集；补 `bulkUpdate`（模板唯一 DML 入口，P0）、`get/load/loadAll`、`save/saveOrUpdate/persist/merge/update/delete/deleteAll/replicate`、`findByCriteria/findByExample`、`findByNamedQuery` 族。

**J22 返回类型与投影**：`Page` count 二连查询与 `@Query.countQuery`、`Slice` 多取一条、`Stream/Streamable` 标注、`Window+ScrollPosition` keyset 滚动（远期）、`Limit` 参数（3.2 新接口）、接口投影按 getter 名收敛 SELECT 列、动态投影（Class<T> 参数）、SpEL `#{#entityName}` 基础支持。

**J23 Querydsl**：`QuerydslPredicateExecutor` 9 方法——依赖 APT 生成的 Q 类，静态解析成本高，定文档化边界倾向，仅当用户需求集中时立项。

**javax/jakarta 双包名**：插件短名兜底大概率已兼容（demo 即 javax 包名全通过），但须加双 FQN fixture 固化，随 J1 验证。

## 五、风险与边界

- 撞名消歧是 J1 最大风险点：`save/deleteById` 等通用方法名在 MP 与 JPA 语境下共存，家族判定依赖 receiver 类型解析（变量类型、参数注入形态 `userRepository` 字段、构造器注入），解析失败时应回退「不识别」而非套错模板——宁可无图标，不可出错误 SQL（与现状误导行为相反）。
- JPA 无 @TableLogic/@Version 语义等价物（@Version 是 jakarta 注解，语义同乐观锁，JpaEntityResolver 尚未识别——J8 范围内一并支持 @Version 注入）；软删除族注解版本差异大（Hibernate 5/6 注解名不同），按短名兜底策略收录。
- J5 Specification 的 lambda 体求值边界：复杂组合（嵌套 Specification、and/or 链式组合变量）静态不可求值时降级为可读占位，不抛异常（M1-T1-08 健壮性原则）。
- M1 依赖 M37/M38 分支合并；合并前 master 上该缺陷保持「已知未修」记录即可，不重复实施。
