#### 本轮新发现：testDatabase 驱动管线打通后暴露的集成断言问题

驱动管线**已打通并加守卫**：根因是 driver 的 artifact ref **版本为 null**（平台不读 `options/databaseDrivers.xml`），而 `ArtifactRef.getElements()` 在版本为 null 时回退恒空的 legacy 元素 → 子进程 `ClassNotFoundException: com.mysql.cj.jdbc.Driver`；另一处是 `test-database-artifacts.xml` 落点错（`DatabaseDriverManagerImpl.existentTestPath` 只认 `<configPath>/options/`，原落 config 根从未被 DBN 读到）。修复走公有 API（`DatabaseDriverImpl.setArtifacts` + `createArtifactRef` + `DatabaseDriverManager.updateDriver`）补齐版本 + buildSrc 落点改 `options/`。新增 `DbDriverPipelineTest` 把链路每一环钉成断言（**2/2 绿**）。

**副作用**：原先靠「introspect 失败即软跳」静默变绿的四个 DB 集成类首次真正执行，暴露 **6 项断言失败**（实测 9 例 6 失败）（沙盒缺真实 IDE 项目/窗口/VFS 夹具：无数据源分支需窗口而 `frame` 为 null、`getAttachDataSourceRunners` 返回 0、`createTempPsiFile` 的 VFS refresh 取不到新建目录）。这些是**测试侧从未验证过的平台行为假设**，不是产品缺陷，也不是驱动管线的问题。

**处置**：分支 `t-testdb-driver` 已按「可合」决策 cherry-pick 落 master（`6017fe4`）并清理分支；把断言改回 skip 等于再次掩盖（本轮正是掩盖导致该债被长期误判为「环境门控、语义正确 skip」），故不做掩盖——**6 项失败列入代码侧修复清单（P2）**。完整记录与修复方向见 `docs/调研报告/20260918-testDatabase驱动管线打通-记录.md`（记录文档已随 cherry-pick 落 master）。
