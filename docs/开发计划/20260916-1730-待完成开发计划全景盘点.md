### 2.8 premain 注入范围待定案（2026-09-23 新发现，仅登记未出计划）

| 任务 | 计划文档 | 内容 | 优先级 |
|---|---|---|---|
| **T-GradleTaskInjectScope** | 未出计划（用户 2026-09-23 要求「先登记」） | premain 的 `-javaagent` 会落进 **Gradle/Maven 任务的 fork JVM**：`PremainRunConfigurationExtension.isApplicableFor` 恒 true（`PremainRunConfigurationExtension.kt:52`）→ 平台对 ExternalSystem 配置同样求值（`ExternalSystemRunConfigurationJavaExtension.updateVMParameters` → `JavaRunConfigurationExtensionManager.updateJavaParameters`）→ 经 `ExternalSystemRunnableState.getJvmParametersSetup()`（:419）→ `GradleTaskManager` → `JavaGradleProjectResolver.enhanceTaskProcessing` 用 init script 加到「请求任务列表里 JavaForkOptions 任务」的 fork JVM（`RunIdeTask : JavaExec()` 实测；**Gradle 工具窗发起同样命中**——`ExternalSystemUtil.runTask` 构造 ExternalSystemRunConfiguration 并塞 `TASK_NOTIFICATION_LISTENER_KEY`，正是 `ExternalSystemRunnableState.execute` 读的那个键）。判据是「配置形态 + 任务是否 JavaForkOptions」，**不看「这个 JVM 是不是用户应用」** | **待用户定案**（premain 随下一个发行版出门，范围需在发行前拍板） |

**为什么判为不合适（四条，均可举证）**：①`runIde` 被注入的是 **IDE 进程**，与同意框文案「在**您的应用 JVM** 内直接挂载捕获点」不符，本仓开发流程更是自指（插件把自己 agent 注进自己 `runIde` 出来的沙盒）；②`test` 类任务命中 **test worker JVM**——agent 常驻 socket/线程，hook 包装失败还会往 stderr 打 `[T-AgentProxyCL] hook 包装失败…`，污染测试输出；③沙盒 IDE 自身用 JDBC（DatabaseTools），驱动类被织入 → 沙盒里查库的事件可能回传 dev IDE 的 SQL 面板（串台）；④**同意面 ≠ 注入面**：知情同意只在「主配置启动」（`ModuleBasedConfiguration`＝Application/Spring Boot/JUnit）时征求，注入却覆盖此后所有 Gradle/Maven 任务，问一次等于对整类任务长期生效。

**为什么不能一刀切排除 ExternalSystem 配置**：attach 链对 Gradle 进程是失败的（日志实证 `onProcessAppeared: resolvePid 失败（handler=…ExternalSystemProcessHandler）——跳过挂载`），而该 handler 本来也不是应用 JVM——**Gradle 用户用 `bootRun`/`run` 启动应用时 premain 是唯一可用通道**，整体排除＝让这批用户静默失去增强捕获，比现在的过宽更糟。

**三条路线**：**A（推荐）按任务语义收窄**——`GradleRunConfiguration.isRunAsTest` 可辨「测试运行」（真机 run 配置 XML 里就有 `<RunAsTest>` 字段），runIde 类按任务名排除，保留 `bootRun`/`run` 这类应用启动任务；**B（最保守）**行为不动，只把同意框与文档口径改成如实说明「覆盖从 IDE 启动的 Gradle 任务 JVM（含测试与 runIde 这类工具任务）」；**C（不推荐）**整体排除 ExternalSystem 配置（丢 `bootRun` 场景）。

**影响面澄清（勿误判）**：现网不受影响——三处真实 IDE 装的 `mybatis-plus-sql-visualizer-2026.9.18-beta.4.jar` 内**无 `Premain*` 类、plugin.xml 无 `runConfigurationExtension` 注册**（jar 解包实测），premain 代码已在 master（`b503c42`，2026-09-18）但未随该 beta 发行；本机 30 次 runIde 沙盒会话的 `JVM options:` **无一次出现我方 agent**（只有 Kotlin `coroutines-javaagent`；09-22 13:12 / 13:24 两次出现第三方 `cool-request-agent.jar`，反证该通道确实可用）。

**待验证前提（实施前先证伪）**：①「IDE 发起 Gradle 任务 → fork JVM 真拿到 `-javaagent`」本机零实例（真实 IDE 装的是无 premain 的 beta.4，沙盒 runIde 多为 CLI 启动或 `confirmed=false`）；②「Gradle 工具窗发起的任务也走 `getJvmParametersSetup`」目前是代码可判、未真机实测。两条的验证动作见 §五。

**与既有计划的关系**：原计划 `docs/开发计划/20260918-1430-T-M56Phase2-Premain启动即捕获补位-开发计划.md` 第 72/158 行把 Gradle/Maven 记为「已覆盖调用点」，即覆盖范围是当时有意接受的，但**未讨论「注入目标是否必须是应用 JVM」**——本条要定的是这个边界，不是「有没有实现」。
