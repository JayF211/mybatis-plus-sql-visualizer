## 二、新增功能

### 2.1 真实 EXPLAIN 联动（M37.2）

**入口**：预览面板「EXPLAIN」按钮（`SqlPreviewPanel.toolbar()`）。

**能力**：按当前方言把预览 SQL 包装为 EXPLAIN 语句，走执行链提交原生控制台，真实执行计划与静态性能规则标注同屏对照。

**方言支持矩阵**（DBX MCP 真机实证）：

| 方言 | 渲染形态 | 状态 |
|------|----------|------|
| MySQL / MariaDB | `EXPLAIN FORMAT=JSON <sql>` | ✅ 真机通过 |
| PostgreSQL | `EXPLAIN (FORMAT JSON, VERBOSE) <sql>` | ✅ 真机通过 |
| KingBase | `EXPLAIN (FORMAT JSON) <sql>` | ✅ 真机通过 |
| DM（达梦） | `EXPLAIN <sql>` | ✅ 真机通过 |
| H2 | `EXPLAIN PLAN FOR <sql>` | ✅ 引擎级单测 |
| SQLite | `EXPLAIN QUERY PLAN <sql>` | ✅ 引擎级单测 |
| Oracle / SQL Server | null（降级提示） | ✅ 结构性不支持 |

**实现要点**：
- `Dialect.renderExplainStatement(sql: String): String?` 接口新增（默认 null 降级），9 个方言 object 覆写
- 按钮灰化模式（全项目首个 `isEnabled=false + tooltip` 先例）：`ExecuteSqlSupport.isAvailable()` + 数据源已选 + 方言支持三条守卫
- EXPLAIN 归 `SqlTypeClassifier` 免确认类，无 DML 二次确认
- 完整复用 `SqlExecutor.execute` 全链与防串机制（swapGeneration / REUSE_ACCEPT_TICKS）

**文件**：`sql/Dialect.kt`(+30)、`ui/SqlPreviewPanel.kt`(+15)、`sql/DialectExplainTest.kt`(新增 66 行)

---

### 2.2 日志↔源码双向深链（M37.1）

**入口**：gutter 图标右键菜单「最近执行记录」。

**能力**：从编辑器锚点（Wrapper 链 / XML / 注解）反查内存捕获的日志条目，选中即打开预览面板；正向（日志→源码）F-44 已实现行级精确跳转。

**实现要点**：
- `EntrySourceMatcher.match(entries, sourceFilePath, anchorLine, window=30)`：同文件条目按捕获时间倒序，行号窗口内（|Δ| ≤ 30）优先，其余同文件条目随后（非排除）
- `SourcePathResolver.resolveVirtualFile()`：basePath 直拼失败后按模块 content root 匹配（多源根容错，O(模块数) 次路径查找）
- `LogEntryPreviewOpener.open()`：gutter 无面板实例时打开条目预览（与 `SqlLogPanel.openPreview` 同链路的独立实现）
- gutter 点击改为两级 `BaseListPopupStep`（单击即选）：首项预览 SQL（原行为）/ 最近执行记录

**文件**：`log/EntrySourceMatcher.kt`(新增 136 行)、`ui/gutter/SqlGutterLineMarkerProvider.kt`(重构)、`log/EntrySourceMatcherTest.kt`(新增 96 行)

### 2.3 Wrapper→测试资产生成（M37.4）

**入口**：预览面板「生成测试」按钮。

**能力**：从 Wrapper 链一键生成两种测试资产：
1. **SQL 回归脚本**：方言渲染后的目标 SQL + 断言查询骨架，落盘 `<project>/src/test/resources/sql-visualizer/`
2. **JUnit 用例骨架**：可编译的 @Test 方法（内嵌 SQL 常量 + TODO 断言位），弹窗预览 + 复制

**实现要点**：
- `testgen/TestAssetGenerator` 纯函数（零平台依赖）：输入 `Input(sql, dialectName, tableName, anchor)` → 输出 `TestAsset(fileName, content)`
- 时间戳等环境量由调用方注入保持纯函数可测
- 不做 INSERT 前置依赖自动推导（列级外键推导复杂度高，记 TODO）；不生成业务 Java 代码
- `JavaCodePreviewDialog` 新增可选标题参数（`@JvmOverloads` 保持二参构造真实存在，避免增量编译 NoSuchMethodError）

**文件**：`testgen/TestAssetGenerator.kt`(新增 107 行)、`testgen/TestAssetGeneratorTest.kt`(新增 77 行)、`ui/JavaCodePreviewDialog.kt`(+8)

---

### 2.4 首条 SQL 自动展开日志工具窗（M37.3）

**能力**：检测到首条 SQL 入缓冲时自动展开日志工具窗（60s 防抖，`show()` 不抢编辑器焦点）。

**背景**：F-44 合并 Tab 时自动打开实现被删但设置项/勾选残留（形同虚设），本里程碑恢复。

**实现要点**：
- `SqlLogManager` 挂**无条件** buffer 监听（面板未创建/未订阅时首条捕获也触发，修 D2 老问题语义）
- `SqlLogManager.shouldAutoShow(enabled, elapsedMs)` 纯函数测试缝
- `logAutoOpenOnCapture` 默认 false → true（竞品「每次手动开面板」是普遍抱怨；已持久化 false 的用户不受影响）

**文件**：`log/SqlLogManager.kt`(+56)、`log/SqlLogManagerAutoShowTest.kt`(新增 75 行)

### 2.5 gutter 左右键交互优化（M38.2）

**能力**：左键单击直接预览 SQL（一键路径最短）；右键弹出菜单（预览 SQL / 最近执行记录）。

**背景**：M37.1 方案左键弹两级菜单，打断一键调试流；且 `BaseListPopupStep.onChosen` 在 `finalChoice=false`（悬停预览）分支误执行动作并返回 `FINAL_CHOICE`，导致 `ListPopupImpl` 抛 NPE。

**实现要点**：
- 重构 `SqlGutterNavigationHandler.navigate()`：通过 `SwingUtilities.isRightMouseButton(e) || e.isPopupTrigger` 区分左右键
- NPE 根因修复：`onChosen` 加 `if (!finalChoice) return null` 守卫
- 同步修复最近执行记录二级列表的 `onChosen` 分支

**文件**：`ui/gutter/SqlGutterLineMarkerProvider.kt`(重构)

### 4.2 MP 语义偏差（M38.2）

| 缺陷 | 修复 |
|------|------|
| `or(w -> w.eq(2).eq(3))` 渲染 `AND (2 OR 3)`（内外连接词颠倒） | `parseGroup` 组内连接词恒 AND，外层由 `orPending` 表达；`or(lambda)` 强制 `addConditionFlagged(..., true)` |
| `ne` 渲染 `!=` 与 MP SqlKeyword.NE = `<>` 不一致 | `QueryWrapperParser` / `WrapperConverter` / `MpjLambdaConverter` 共 5 处对齐 `<>` |
| 负数字面量 `-1` / `-5L` 落 `ExpressionEvaluator` else 误判为运行时占位符 | 新增 `PsiPrefixExpression` 求值（SQL 剥离 Java 数值后缀 fFlLdD） |
| `set(false, col, val)` 布尔前缀剥离后仍渲染 SET | `LambdaUpdateConverter` 加 `isFalseFlag` 守卫（MP 运行时语义：condition=false 整个子句不拼接） |
| `last("LIMIT 5 OFFSET 10")` 的 OFFSET 丢失 | `parseLimit` 正则加 OFFSET 分支 |
| `having(String)` 字符串版静默丢弃 | `parseHaving` 加字符串分支（原生片段透传渲染） |

**文件**：`converter/QueryWrapperParser.kt`(+35)、`converter/WrapperConverter.kt`(+4)、`converter/MpjLambdaConverter.kt`(+4)、`converter/LambdaUpdateConverter.kt`(+10)、`psi/ExpressionEvaluator.kt`(+22)、`converter/QueryWrapperParserTest.kt`(+28)
