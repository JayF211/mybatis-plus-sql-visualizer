## 一、现状与目标

### 1.1 现状（F-44 已完成的部分，本计划不重做）

- **条目已带源码位置**：`LogSqlEntry`（`log/LogSqlModels.kt`）已含 `sourceFile`（相对项目根）+ `sourceLine`；来源是工程内拦截器复制品 `docs/instrumentation/SqlSourceInterceptor.kt` + `CallerSourceLocator.locateFrom`（线程栈跳框架帧）打 `SQLVIS-SOURCE|path|line` 标记行。
- **正向跳转已行级精确**：`SqlLogPanel.jumpToSource` / `HistorySqlLogPanel.jumpToSource` → `OpenFileDescriptor.navigate(true)`；无标记时退化为表名启发式（`SqlTableExtractor` + `WrapperSearchService`）。
- **历史已持久化位置**：`.idea/sql-visualizer/sql-history/*.sql` 头行 `-- source: path:line | time | datetime --`，`SqlLogFileReader.parseSource` 可还原。
- **gutter 只出不进**：`SqlGutterLineMarkerProvider`（Java/Kotlin 同类，Kotlin 走 `kotlin-optional.xml`）+ `SqlGutterNavigationHandler`（200ms 防抖 → `SqlPreviewService.previewAsync`），点击只开 SQL 预览，**无反查日志入口**。

### 1.2 差距

1. **反向（源码→日志）无任何实现**——跑到一半想回看某条链的真实执行记录，只能去日志面板翻。
2. **跳转路径直拼 `basePath + 相对路径`**，多源根/非标准布局项目失效。
3. 历史头行未持久化 `params`/`source`（enum），跨会话丢失。

### 1.3 目标

1. gutter 锚点新增「最近执行」入口：弹出该锚点关联的日志条目列表，选中即打开预览面板。
2. 跳转支持多源根容错。
3. 历史头行扩展持久化 params/source，读取向后兼容。

### 1.4 非目标

- 不做拦截器自动注入工程（工程侵入性强，独立评估后再议）。
- 不做跨项目日志检索。

## 二、实现设计

### 2.1 反向匹配策略（纯函数，新类 `log/EntrySourceMatcher.kt`）

输入 `(sourceFile, anchorLine, 提取的表名)` → `List<LogSqlEntry>`，优先级：

1. sourceFile 相等 + `sourceLine` 落在锚点元素文本区间（链起点到方法体末行）；
2. sourceFile 相等（同文件全部，按时间倒序）；
3. 表名兜底（复用 WrapperSearchService 搜索结果对应的文件）。

注意：拦截器记录的是**调用处**行号，可能与链起点行不同，必须用行号窗口而非等值匹配。匹配逻辑做成纯函数便于单测。

### 2.2 数据源

内存 `SqlLogEntryBuffer` + 落盘 `.idea/sql-visualizer/sql-history/`（`SqlLogFileReader` 已能解析 source 头行）。文件 IO 走后台线程，不在 EDT。

### 2.3 gutter 入口

`SqlGutterNavigationHandler` 改为弹 `JBPopupFactory.createListPopup(BaseListPopupStep)`（单击即选，勿用 setItemChoosenCallback——PopupChooserBuilder 单击不触发的老坑），两项：

- 预览 SQL（现有行为）
- 最近执行记录 → 命中条目列表（≤20 条，时间倒序）→ 选中走 `SqlLogPanel.openPreview` 同款链路（`LogSqlEntry.toRecognizedPreview()` → `SqlPreviewService.showResult`）

无标记数据时第二项显示「未找到关联执行记录（需安装拦截器）」禁用态并附说明。

### 2.4 多源根容错

`jumpToSource` 直拼失败后，改用 `ProjectFileIndex.iterateContent` 按相对路径后缀匹配（后台线程 + ReadAction），命中即 `OpenFileDescriptor`。

### 2.5 历史头行扩展

头行追加可选字段：`-- source: path:line | params: n | src: MYBATIS | ...`；`SqlLogFileReader` 正则改为可选捕获，旧格式兼容。

## 四、验证

- 单测：匹配策略三优先级、行号窗口边界、旧格式头行兼容。
- 真机沙盒：跑 Spring Boot 会话产生带标记日志 → gutter「最近执行」反查命中；未装拦截器工程走禁用态与表名兜底。
- 多源根工程真机跳转验证。

## 五、风险

1. **EDT 陷阱**：反查含文件 IO 与 PSI 读取，必须后台线程 + ReadAction（243 平台 EDT 直读 PSI/慢操作均硬抛）。
2. **拦截器依赖**：无标记用户只能表名兜底，UI 必须明示原因，避免「功能失灵」错觉。
3. **gutter 行为变更**：点击语义从「直接预览」变为「弹菜单」——弹窗首项即原预览行为，保持一键路径最短。
