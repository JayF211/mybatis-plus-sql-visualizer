## 一、背景与现状

### 1.1 问题

宽表 SQL（SELECT 几十列 / INSERT 大列清单 + 多组 VALUES）全部逐行展开，纵向滚动距离长，定位 `FROM`/`WHERE` 等结构困难。现有「竖向排列」「关键字换行」等显示模式（T-ListMode/T-VStack）反而让行数更多。需要一个「结构保留、细节收起」的通道：把超长的字段列表折叠成占位符（如 `… 23 列`），点开再展开——即 IDEA 原生代码折叠的观感。

## 二、IDEA 原生折叠能力调研

### 2.1 平台机制（243 sources jar 核实，API 在 243/253/262 稳定）

折叠的公共入口是 `Editor.getFoldingModel()` 返回的 `com.intellij.openapi.editor.FoldingModel`：

- `runBatchFoldingOperation(Runnable)` —— 增删区域的必须包裹（`addFoldRegion`/`removeFoldRegion` 文档明确要求在批操作内调用）；
- `addFoldRegion(startOffset, endOffset, placeholderText)` → 返回 `FoldRegion` 或 **null**（折叠被禁用、或与既有区域相交时加不进——重叠即拒，规划器必须保证区域互斥）；
- `FoldRegion.setFolded(true)` 收起；gutter 上出现 +/- 轮廓控件（前提 `EditorSettings.isFoldingOutlineShown`），用户可随时手点展开，折叠只是**视觉收起**，文档内容不动；
- `FoldRegion` 底层是文档 RangeMarker，文档局部编辑不丢区域；`getAllFoldRegions`/`getFoldRegion(s,e)` 可查询；`Editor` 本身是 UserDataHolder，可挂本方区域清单（跨类共享应用器的状态载体，见 F0）。

平台另有 PSI 折叠通路（`FoldingBuilder` EP → `CodeFoldingPass` → `UpdateFoldRegionsOperation`），是 IDEA 各语言折叠的来源。

### 2.2 三条实现路线对比

| 路线 | 做法 | 判定 |
|---|---|---|
| ① 给 SQL 语言注册 `FoldingBuilder` EP | 平台在 PSI 变更时自动调 builder 产区域 | **否决**。SQL 语言（`com.intellij.sql`，Database 插件）是全局语言——注册后用户真实 `.sql` 文件、DBN 控制台都吃我们的折叠规则，越界影响；且与平台/DBN 可能已有的 SQL 折叠规则并存冲突；预览高亮本来就是自研 `SqlSyntaxHighlighter`（不依赖平台 SQL lexer），builder 的 PSI 参数也用不上 |
| ② `ConsoleFolding` EP | 控制台堆栈/异常折叠 | **否决**。面向整行堆栈折叠，不适配「字段列表」语义 |
| ③ **程序化折叠**：渲染后对目标 Editor 的 `FoldingModel` 直接增删区域 | 折叠由我们写入管线驱动，纯文本行/偏移层面规划，不依赖 PSI | **选定**。作用域严格限于我们的编辑器；文本层面规划与自研 `SqlLexer` 复用；①~⑥ 六条支链统一经 F0 公共应用器处理 |

### 2.3 路线③的关键风险点（先声明，V 项实证）

`UpdateFoldRegionsOperation`（PSI 变更触发的折叠重算）会按注册 builder 重建区域，**程序化添加的区域是否被重算抹掉**取决于编辑器上是否存在该语言的 folding builder 及重算时机——①②⑥ 关联 SQL FileType PSI，commitDocument 可能触发重算。防御策略：**每次程序性写入后全量重建本方区域**（先摘自己上轮的清单，再按新文本重新规划），把「平台可能抹掉」变成无关变量；不订阅平台折叠事件、不做跨编辑器的区域持久化。

## 三、需求界定

1. **折叠对象**：SQL 中的**顶层字段列表**——SELECT 列清单（`SELECT` 到 `FROM`）、INSERT 列清单（表名后括号）、VALUES 每组元组、UPDATE 的 SET 清单（`SET` 到 `WHERE`/`ON DUPLICATE`）。其余子句（WHERE 条件、JOIN ON）不折叠，避免掩盖语义重心。
2. **触发条件**：该字段列表的**顶层元素个数 ≥ 阈值**（不是行数——NORMAL 模式多列同行，竖排一列一行，语义要一致）且区域跨 ≥ 2 行（同行无折叠价值）。
3. **折叠形态**：整段收起，占位符 `… N 列`（英文 `… N columns`，i18n 键），首行关键字行（`SELECT`/`VALUES` 行）保持可见——折叠区从列表首元素起、止于列表末元素行尾。嵌套子查询内的 SELECT 列清单**不折叠**（外层区域已含内层时 addFoldRegion 返回 null，规划器从外层向内扫描天然互斥）。
4. **开关语义**：配置项默认**关闭**——关闭时写入管线零折叠操作、行为逐字节不变；开启后的下一次程序性写入生效（与 `formatSql`/`verticalPairAnnotation` 同构，各处不订阅 SETTINGS_CHANGE_TOPIC 即时刷新已开窗体，既有语义不扩大）。
5. **与显示模式的关系**（主预览面板）：正交叠加。压缩模式单行无区域可折（自动零区域）；竖向排列下大 INSERT 的每行 VALUES 组正是本功能的主要受益场景。
6. **手改与刷新**：用户手改文本不主动重算（区域随 RangeMarker 自然伸缩，展开/收起仍可用）；任何一次程序性写入（参数改动、模式切换、刷新、回填、转换产出）按当前文本全量重建——与 T-PreviewDisplayMode「手改本就会被重建覆盖」的既有边界一致。
7. **输入区特例（⑥ SqlInputEditor）**：只在**程序性写入**（`setSql`，如从日志回填、示例载入）时重算折叠；用户逐字打字**不触发**重算——打字中途折叠收起光标上下文是负体验，既有 RangeMarker 会自然伸缩，不打扰输入。

## 四、方案设计

### F0：`SqlAutoFolding` 公共应用器（新文件，ui/highlight/）——六条支链唯一收口

```kotlin
object SqlAutoFolding {
    /** 按当前设置对 editor 重建折叠区域；text=当前全文。关/异常 → 清除本方区域后静默返回。 */
    fun applyTo(editor: Editor, text: String)
}
```

- 读设置（`runCatching { PluginSettings.getInstance().state... }` 范式，异常按关处理）；
- `SqlAutoFoldPlanner.plan(text, threshold, placeholder)` → `editor.foldingModel.runBatchFoldingOperation { 摘旧清单; addFoldRegion + setFolded(true) }`，整体 `runCatching` 包裹——折叠是锦上添花，任何平台异常只记 warn 不影响内容展示；
- **本方区域清单挂 Editor UserData**（`KEY_LAST_FOLD_REGIONS`）：跨类共享、随编辑器释放自然消失；清除时**只摘清单内的**，绝不 `getAllFoldRegions` 全清——原生控制台/平台可能挂有 `ConsoleFolding` 等他人区域，越权摘除即事故；
- 附带外观最小接线：开启态下若 `isFoldingOutlineShown == false` 仅补设该一项（④ 紧凑弹窗、① 控制台需要；只动这一项，不碰其余外观设置）；
- EDT 语义：全部调用点已在 EDT，`runBatchFoldingOperation` 是 UI 层批量刷新，无 read/write 锁问题（对照平台 CollapseBlockHandler 同为 EDT 直调）。

### F1：`SqlAutoFoldPlanner` 纯逻辑规划器（新文件，ui/highlight/）

```kotlin
object SqlAutoFoldPlanner {
    data class FoldSpec(val startOffset: Int, val endOffset: Int, val placeholder: String)
    fun plan(text: String, threshold: Int, placeholderTemplate: String): List<FoldSpec>
}
```

- 复用 `SqlLexer`（token 流含括号深度）扫描四类顶层列表；顶层元素数 = 列表自身括号深度内逗号分段数；
- 输出按 startOffset 升序、**互不重叠**（外层命中后跳过内层——addFoldRegion 对相交区域返回 null，规划器自己保证互斥比依赖返回值可靠）；
- 纯函数零平台依赖 → 单测无需平台沙箱，阈值边界/嵌套/压缩态/空文本全在普通 JUnit 覆盖；
- 阈值 ≤ 0 或文本空 → 空列表（防御）。

### F2：PluginSettings 两个字段（State + 默认常量）

```kotlin
/** 字段较多时自动折叠（T-AutoFold）：true=各处 SQL 预览编辑器渲染后自动折叠超长字段列表，默认关。 */
var autoFoldEnabled: Boolean = false,

/** 自动折叠触发的顶层字段数阈值（T-AutoFold）：字段列表元素数 >= 该值才折叠，默认 10。 */
var autoFoldFieldThreshold: Int = DEFAULT_AUTO_FOLD_FIELD_THRESHOLD,
```

阈值做成第二控件（数字输入框，开关勾选才启用编辑——对齐面板既有联动范式）；随 `mp-sql-visualizer.xml` 持久化，`SettingsIO` JSON 导入导出自动覆盖（Gson 全字段）。

### F3：bundle 双语言 + 面板四处接线

- `settings.autoFold.enabled` / `settings.autoFold.threshold`（zh：「SQL 预览字段较多时自动折叠」「自动折叠字段数阈值」，键名以 bundle 现有风格为准）；占位符模板键 `preview.fold.placeholder`（`… {0} 列` / `… {0} columns`）。
- `PluginSettingsPanel`：控件声明（formatCheck/verticalPairAnnotationCheck 之后，同分区 :359-360 邻位）、`buildRows` 两行、isModified、apply、reset 五处同步；**复选框总数台账 `PluginSettingsPersistenceTest` 24 → 25**（T-VPairAnno 台账教训，数字断言必同步）。

### F4：各点位接入（全部经 F0 应用器，一行调用收口）

**F4-a 主预览面板（SqlPreviewPanel，支链①②③）**——`showSql` 三分支各自 setText 完成后统一调 `SqlAutoFolding.applyTo(editorOrNull, text)`：

- nativeDoc 支链需 Editor 对象——见 F5；
- existing editor 支链直接 `applyTo(existing, text)`；
- createEditor 支链对新编辑器 `applyTo(created, text)`；
- 开关关闭时 `applyTo` 内部即「清除本方区域」短路，三分支调用无条件插入、无需各自判开关。

**F4-b 双击快速预览弹窗（SqlClickPreview.buildContent，支链④）**——`SqlClickPreviewContent` 构建尾部（editor 已就绪、文本即入参 sql）调 `applyTo(editor, sql)`。弹窗是即建即弃生命周期，UserData 清单随编辑器释放；560×320 小窗正是折叠收益最大处。紧凑外观仅在**开启态**补设 `isFoldingOutlineShown=true`（关闭态逐字节不变，含无 gutter 外观）。

**F4-c 日志转 SQL 结果编辑器（LogToSqlPanel，支链⑤）**——`setDocumentText(resultEditor, out)` 的产出点（:259 转换成功、:201 清空）后调 `applyTo(resultEditor, 新文本)`。

**F4-d SQL 输入区（SqlInputEditor，支链⑥）**——`setSql()`（:99）程序性写入完成后调 `applyTo(editor, sql)`；构造时初始内容同样走一次。**用户打字不触发**（见 3.7），DocumentListener 不订阅。

### F5：原生控制台支链接入（V1 实证后再定形态）

`onNativeEditorReady`（:572）当前丢弃 consoleEditor 引用——新增弱引用字段 `nativeConsoleEditor: Editor?` 持有（dispose 时置 null，避免 EditorFactory 泄漏告警；`recoverConsole`/失联检测 `attachedToMe=false` 路径清空）。开启配置时对该编辑器同样 `applyTo`。

**V1（沙盒实证项）**：①DBN 控制台编辑器上程序化折叠是否可见可交互；②commitDocument 后区域是否被平台重算抹掉（抹掉则维持「每轮渲染重建」策略即可覆盖，无需额外监听）；③控制台的 `ConsoleFolding` 机制是否与字段折叠区域互相干扰。**V1 失败的降级范围收窄到支链①自身**：该支链 `applyTo` 内部 catch + 一次性 warn，其余支链②~⑥照常交付——「所有地方」= 所有可达处，个别平台不可达处如实标注，不留静默无效开关。

## 六、范围边界（明确不做）

- 非 SQL 编辑器：JSON 参数导入弹窗、Java 结果编辑器、日志输入编辑器、XML 预览 tab、diff 视图编辑器——见 1.2 排除清单；
- 折叠状态持久化/记忆（每次程序性写入即重算，同显示模式不持久化的既有语义）；
- 「全部展开/折叠」工具栏按钮——gutter 原生 +/- 与 IDEA 全局折叠快捷键（Ctrl+Shift+加/减号）天然可用，不自制重复入口；
- WHERE 条件、JOIN ON 折叠——首期只收字段列表，语义噪音低；后续按需扩展只是规划器加规则，六处接线零改动；
- 用户打字过程的实时重折叠（⑥ 明确只在程序性写入重算，见 3.7）。
