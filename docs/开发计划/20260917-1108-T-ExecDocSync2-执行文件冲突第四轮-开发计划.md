## 一、根因分析

### 1.1 关键事实：控制台编辑器文档 = exec 文件文档

`chooseAndPrepare → createTempPsiFile` 产出的 vf 即 `mpsql-exec.sql`，该 vf 直接传入
`prepareInConsole → JdbcConsoleProvider.attachConsole(project, session, vf)`（DataSourceSelector.kt:297/:1146）
——**Database 控制台挂载在 exec 文件本体上**（:281 注释「VF 作为控制台挂载点」同源）。
因此：用户在嵌入控制台里敲的每个键、插件对 console document 的每次 setText，
改的都是 `mpsql-exec.sql` 的 document。

### 1.2 缺口：T-EC-01 纪律只覆盖了插件自有写点，漏了 console 侧四个同步点

T-ExecDocSync 的三点收口（document 驱动写 + 同临界区落盘 / EDT 派发 / 裸写守卫）落在
`projectExecFile` 与 `executeOnConsole` 执行前同步；但以下四处改 console document
（= exec 文件 document）后**不落盘**，document 滞留「已修改未保存」且磁盘停留在旧内容——
这正是冲突弹窗「内存中更改」一半的制造者：

| # | 位置 | 现状 | 窗口 |
|---|------|------|------|
| G1 | `reuseSharedConsole` :384 `editor.document.setText(sql)` | 只改编辑器文档，无落盘 | 复用控制台起，到下一次 projectExecFile 收敛止 |
| G2 | `reuseSharedConsole` :396-409 vf 同步块 | setText-if-differ + **仅 commitDocument，无 saveDocument** | 同上（与 G1 同窗口） |
| G3 | `prepareAfterEditorResolved` :1329-1343 vf 同步块 | 同 G2 形态 | 新控制台准备起 |
| G4 | `contentAdded` 回调 :900-905 `consoleDoc.setText(currentSql)` | WriteCommandAction 改写，无落盘 | 换入触发起 |

「磁盘上更改」一半来自窗口期内的任一外部改盘：git 触碰 `.idea`、另一 IDE 实例同开 demo 项目
（沙盒 + 日常 IDE 双开为真机常态）、外部编辑器；改盘后任一 VFS refresh（文件监视器/自动保存/
插件自身 refreshAndFindFileByIoFile）命中「document 已修改 && 磁盘 ≠ 文档」即由
MemoryDiskConflictResolver 弹出冲突窗。历史对话框点「保留内存更改」后 doc 永久 modified +
磁盘永久分叉，此后任何外部改盘都会反复弹——弹窗本身会自我放大。

### 1.3 残余竞态（G1-G4 修完后仍存的最后一道缝）

用户正在控制台打字（doc modified-unsaved）与 prewarm 的 `refreshAndFindFileByIoFile`
并发（BGT refresh 进行中、EDT 键入落 doc）→ refresh 恰见「modified && 磁盘≠文档」仍可弹。
该窗口只能压缩、不能消除；本轮以「refresh 前强制收敛 + 1.5s 防抖自动落盘」把暴露面压到毫秒级。

## 二、方案

| # | 项 | 改动 |
|---|----|------|
| F1 | console vf 同步落盘收口（G1+G2） | `reuseSharedConsole` vf 同步块的 `when` 三分支收口为 `writeVfTextViaDocument(project, consoleVf, sql)`（语义超集：setText-if-differ + commit + **save** + fileDoc==null 走 setBinaryContent）；G1 的编辑器 setText 保持不动（若 console doc 即文件 doc，紧随的 vf 同步块 text 相等 → 跳 setText → 直接 commit+save，窗口闭合） |
| F2 | prepare vf 同步落盘（G3） | `prepareAfterEditorResolved` 同款收口为 `writeVfTextViaDocument(project, consoleVf, consoleText)` |
| F3 | contentAdded 改写落盘（G4） | `runWriteCommandAction` 块内 setText 后补 `commitDocument + saveDocument`（同写临界区，undo 语义不变） |
| F4 | refresh 前强制收敛 | `prewarmExecTempFileInner` 与 `createTempPsiFile` 在 `refreshAndFindFileByIoFile` 之前，`findFileByIoFile` 命中则过一遍 `syncExecVfContentIfNeeded`（内部 ReadAction 探测分叉 + EDT 派发 doc 写收敛；正常恒 no-op，仅在「写点之后、refresh 之前」被用户键入插入时真实收敛） |
| F5 | 执行文档防抖自动落盘 | EditorFactory 事件多播器挂应用级 DocumentListener（惰性安装一次），路径匹配 exec 文件（`isExecVfPath`）→ 1.5s 防抖后 EDT+WriteAction `saveDocument`（isDocumentUnsaved 才有实效，未改即 no-op）——覆盖插件拦不到的用户手改源；modified-unsaved 暴露面从「分钟级（等帧失活自动保存）」压到 ≤1.5s |
| F6 | 冲突探针 | 项目级 messageBus 挂 `FileDocumentManagerListener.beforeFileContentReload`（与 MemoryDiskConflictResolver 同 topic，先后不保证，仅取证）：vf 命中 exec 路径即 LOG.warn 文档/文件长度与 stamp 指纹，复发时 idea.log 直出现场数据 |
| F7 | 尾款补落 | CHANGELOG [Unreleased] Fixed 补 T-ExecDocSync（第三轮）与 T-ExecDocSync2（本轮）两条；docs/变更记录.md 补行 |

守恒语义：所有落盘均为 doc→disk 方向（saveDocument），不回读不改写用户内容；「插件 SQL 覆盖
控制台手改」的既有裁定（宁内容旧一拍）不变。

## 三、测试计划（ExecDocSync2Test，沙盒无 Database 插件，纯 VFS/PSI 直测）

1. `testSyncConsoleVfPersistsAndClearsUnsavedFlag`——doc 已改未存（text==目标）→ 同步后磁盘==目标 && isDocumentUnsaved=false（F1 核心：text 相等也必须落盘）。
2. `testSyncConsoleVfOverwritesDivergedDoc`——doc 改成别的文本 → 同步以 sql 为准收敛（F1 覆盖分支）。
3. `testSyncVfContentIfNeededConvergesUnsavedDocWithStaleVfs`——doc 改未存 + VFS 陈旧 → `syncExecVfContentIfNeeded` 收敛落盘（F4 依赖的原语补用例）。
4. `testIsExecVfPathTableDriven`——路径匹配器表驱动（exec 命中 / sql-history 不命中 / 嵌套前缀不命中）（F5/F6 过滤器）。
5. `testAutosaveExecDocNowSavesUnsavedDocument`——手动触发自动落盘原语：unsaved doc → 磁盘对齐 + unsaved 清除；未改 doc → no-op（F5 核心原语）。
6. F3 / 弹窗链路（G4、MemoryDiskConflictResolver 交互、双 IDE 实例）——沙盒不可达，留真机走查。

## 六、风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 自动落盘的写放大 | 控制台连续打字期间每 1.5s 一次磁盘写 | 文件为 KB 级 scratch；防抖合并连击；isDocumentUnsaved 才落 |
| 卸载屏障 | 应用级 multicaster listener / daemon 线程驻留 | 不经 Disposer 注册（无 ObjectTree 泄漏报告面）；daemon 线程不阻 IDE 退出；与既有 object 单例字段（hookProjectsClose 同级）形态一致 |
| F4 的 findFileByIoFile 线程语境 | BGT 裸调 | 与 `projectExecFile` :3197 生产既有裸调同形态（prewarm DONE 日志实证），无新增风险 |
| F1 收口改变 undo 粒度 | vf 同步块原为 WriteAction 直 setText | 收口后仍走 writeVfTextViaDocument 的 setText（同 WriteAction 语境内），粒度不变 |
| 陈旧产物劫持 | 新增 internal 函数首跑 NoSuchMethodError（六犯实录） | 首跑测试前清 build/classes + build/kotlin |
