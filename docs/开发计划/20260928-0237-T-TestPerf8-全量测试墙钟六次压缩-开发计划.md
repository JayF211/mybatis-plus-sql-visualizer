## 一、背景与现状画像

**T7 收口（20260927）**：5 片定案（同窗交错 4/5/6 实测，收口 5 片中位 **2m31s**），testExternal 桶扩容 6 类、护栏族与片墙钟解耦；固定开销拆账 wall−exec＝9.5~12.0s/片、Gradle 前后置 ~5.4s，大头＝平台测试框架 bootstrap（Application/VFS/LaF）。已实测 ≈0 销账的路线（勿再立项）：GC 换型（SerialGC/ParallelGC）、堆加大（2g）、线程面（ActiveProcessorCount）、AppCDS（触及面 2~3s/片 <5% 判据）、纯逻辑分桶提速（12.5s 总量无空间）。

**卡巴斯基排除项（20260927 GUI 代操作，T7-D1 落地）**：4 条白名单（worktree 父目录/`F:\gradle-home`/`.jdks`/JDK8）全部启用；唯一干净 warm 轮 **1m48s vs T7 收口 2m31s＝−28%**，落在扫描税 10~30% 假说区间。但这笔收益只有单轮读数（冷跑与并发轮不可比），且 −28% 的 IO 面变化本身就是一次「负载形态再变」——mpv-testing 内置保质期规则（片数拐点随负载形态复测）**第四次触发**。

**当前井位图**（T7 收口 + 卡巴斯基后推算，诚实口径）——调度层全维度与环境税已买完，剩余可动三块：

1. **片数拐点在新 IO 形态下未复测**。6 片当年被否的两个理由：execSum +39% 并发膨胀（机制主因＝IO 争用，卡巴斯基扫描放大——预期收窄）、Commit 余量 8.3GB 贴 8GB 判据（资源面，不随 IO 税变化）。
2. **巨类原子性**。权重均衡器以类为最小调度单元，SqlPreviewPanelTest（73 例、T7 画像 ~43s）是单片内不可分割的原子载荷；T7 收口逐片 119.1/133.0/115.4/121.9/108.9（预期 122.2，±7%）的失衡里头部巨类占大头——「实际临界片」与「理论地板＝片均值」的差就是可收割空间。
3. **等待/轮询型尖刺复扫**（T7-S2 同款方法在刷新后的逐例数据上再扫一遍，命中才动手）。

## 二、改动方案

### S1 基线重建与画像刷新（测量件，先于一切改动）

- 新树 cold 1 轮 + warm 2 轮（权重冷启动滞后一轮，V7——前两轮分片均衡读数不作数）；默认 5 片。
- 记录：墙钟/execSum/逐片/计数四元组；`--profile` 一轮拆 `:sql-visualizer-agent:test` 与 testExternal 桶的墙钟贡献——若 agent:test 实测是地板（＞临界片），转 S6 立项（本计划只登记不展开）。
- 产出＝刷新后的逐类/逐例权重画像，S2/S3/S4 全部判据取自本轮数据。

### S2 片数保质期复测 4/5/6（实验件，规则第四次触发）

- 触发依据＝mpv-testing 脚本内置规则「负载形态再变时按同法重测」：卡巴斯基排除是 execSum −28% 档的负载形态变化。
- 方法：同窗交错 A/B/A/B（4/5/6 片各 ≥2 轮 warm，`-PtestShardCount`），全程 PowerShell 3s 采 Commit 提交量（资源定例 R6）。判据＝中位数差 >5% 且 Commit 峰值余量 >8GB、无换页；**Commit 余量 <8GB 即否决，墙钟再好也不收**。
- 不达标维持 5 片并销账（负结果入台账防复立项）。

### S3 头部巨类方法级跨片拆分（结构性实验件，预期 −4~8s，go/no-go 判据先行）

- 机制：均衡器以类为原子；把头部 1~2 个巨类（S1 画像判据：**类权重 ≥ 片 exec 均值 20% 且含 ≥30 例**）的测试方法按实测逐例权重贪心对半拆成两个片段，片段 B 挂到其他片，片段 A 留原片。
- 实现（buildSrc mpv-testing.gradle.kts，`-PtestSplitHeavy` 开关，**默认 false**）：
  - 配置期解析候选类最新结果 XML 的 testcase 逐例时长（无数据→退化不拆，确定性不破坏）；
  - 片段 B＝`includeTestsMatching("FQCN.methodXxx")` 清单；原片＝include 全类 + exclude 同一清单（同一份片段集配置期生成，天然互补，防双跑/漏跑）；
  - 权重入账：拆分类的类权重＝总量−片段 B 权重，片段 B 权重独立计入其目标片；
  - 自维护：新增用例不在 exclude 清单→自然落原片；已删用例的残留 pattern 无害。
- 红线论证：零用例删减（方法并集＝全类清单，配置期断言）、零断言改动（不动测试源码）、隔离语义只增不减（两 JVM 各自完整平台 bootstrap，TestCase 每例新实例 setUp/tearDown 语义不变）。
- 风险＝类内跨方法静态状态/顺序依赖：候选类先源码审计（companion/共享可变状态/显式顺序假设——SqlPreviewPanelTest 预审 73 例无 companion 状态，实施轮逐类复核）；实验轮拆分配置全量绿 + 该类两片段定向各一轮；任何 flake 第一嫌疑＝拆分，关开关即回退。
- **go/no-go**：S1 画像若头部巨类占临界片 <15% 或片间失衡已 <5%，路线销账不立项（收益吃不出 5% 判据）。

### S4 等待/轮询尖刺复扫＋外部桶候选复审（审计件，命中才动手）

- S1 刷新后的逐例 XML 上扫 p99 尖刺（例时长 ≥ 类内 p50 ×20 或绝对 ≥3s），逐例人工定性；只处理 T7-S2 同款「烧满轮询上限但真实信号早已就位」形态（等待谓词替换，断言与失败形态零改动）；固有成本形态登记销账。
- 外部桶候选复审随本项带过：新画像里纯 JUnit 声明且有分量的类按 T7-S1 口径（testExternal 单跑行为验证）验证后入桶（预期 0~2 类，小分量）。

### S5 低优先实验尾注（时间盒富余才做）

`-XX:TieredStopAtLevel=1` 单档 A/B——机制指向 bootstrap JIT 固定开销，但 UI 重类长跑回退风险与 T5 同款窗口漂移判据风险都在，预期 <5%，排最后，时间不够直接销账。

## 三、基线与验收

- **基线策略**：冷跑 1 轮 + 两轮 warm 起手；对照实验全部同窗交错 A/B（窗口漂移 ±5~8% 与 <10% 效应同量级的定例）；计时跑前查 `parallel_tasks.py check` 并登记独立沙盒；资源定例：全量单路收口、跑前 `timeout 10 docker info` 验 daemon、机器级只跑一路 test。
- **红线**（沿用 T6/T7）：零用例删减、零断言改动、测试效果不变；S3 只动构建脚本不动测试源码；每步开关化可回退。
- **验收门禁**：①parity 全绿——分片+桶计划类全集均有结果 XML，计数与基线轮一致、0F/0E；②同窗交错对照：收口配置墙钟 ≤ 基线，S2/S3 合力改善 ≥5%，或逐项销账的诚实台账；③测试源码零改动（S4 命中除外，逐例定向实证）；④master 侧零触碰（写集＝buildSrc/gradle.properties/文档，全在本任务树）。
- **预期（诚实口径）**：基线 1m48s±漂移带（V1 复核单轮读数）；S2 命中 6 片 → −10~15s；S3 命中 → −4~8s；两项全销账也是合规交付（负结果入台账）。

## 四、待验证前提（实施者先证伪再动手）

- **V1** 卡巴斯基 −28% 单轮读数可在新树复现（两轮 warm 中位入账；复现不了按实测入账并订正记忆）。
- **V2** 6 片在新负载下 execSum 膨胀率显著收窄（若仍 +30% 档＝膨胀主因不是扫描税，S2 销账）。
- **V3** `includeTestsMatching("FQCN.方法名")` 对中文/驼峰方法名的 pattern 匹配可靠（先单类定向证伪再上全量；pattern 特殊字符转义实测）。
- **V4** 候选巨类无类内静态顺序依赖（源码审计＋拆分配置全量绿双证）。
- **V5** testcase 级 XML 解析可行（JUnit XML testcase name/time 属性完整；半截 XML 静默跳过沿用 parseTestSuiteAttrs 口径）。
- **V6** agent:test 与 testExternal 桶都不是墙钟地板（S1 `--profile` 拆账；agent 是地板则转 S6 立项）。
- **V7** 同窗交错纪律（效应 <10% 必须同窗 A/B，单窗成对不作数——T5 定例）＋权重冷启动滞后一轮（前两轮不作数——T6/T7 定例）。
