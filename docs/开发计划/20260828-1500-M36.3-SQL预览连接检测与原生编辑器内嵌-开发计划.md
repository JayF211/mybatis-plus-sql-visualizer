## 一、需求概述

### 1.1 问题一：SQL 显示栏使用 IDEA Database 原生能力

**现状**：SQL 预览面板右侧的 SQL 编辑器是自研的（`EditorFactory.createEditor` + SQL FileType），不是 IDEA Database 的原生控制台编辑器。原生控制台只在执行后才内嵌到下方，用户需要在自研编辑器编辑 SQL → 点执行 → 选数据源 → 结果在下方原生控制台展示。

**目标**：右侧 SQL 显示栏直接使用 IDEA Database 的原生控制台编辑器（含原生工具栏：数据源选择器/Tx/执行按钮），下发结果也使用 IDEA Database 的原生结果区展示。

**关键约束**：IDEA Database 的 SQL 显示页面和结果页面是**两部分**——编辑器（`editor.component`）和结果区（`logView.getContent().getComponent()`）可以分别内嵌到不同位置。

### 1.2 问题二：连接不可用时一直加载中

**现状**：点击「执行 SQL」选择数据源后，如果连接不可用（密码过期或驱动未下载），查询结果窗口一直显示"执行中..."。IDEA 的密码/下载弹窗被模态的 SQL 预览弹窗遮挡，用户无法感知问题原因，只有在关闭 SQL 预览面板后才看到弹窗。

**目标**：连接不可用时立即给出明确的错误提示（含修复引导），不再无限期等待。

## 二、根因分析

### 2.1 问题二根因

当前执行链（`DataSourceSelector.selectAndExecute`）：

```
selectAndExecute() [EDT 同步]
  → runRunner(runner)
    → runner.run()  [同步，EDT]
      → 建 session → consumer 回调
        → executeInConsole()
          → attachConsole()          // 挂载控制台
          → 轮询获取 editor           // 20×20ms
          → executeQueries()         // ← 阻塞点！
          → 内嵌组件 + Timer 重试
```

**根因**：`executeQueries()` 是**同步调用**，在等待 JDBC 连接建立时：
1. 密码过期 → Database 插件弹出**原生密码对话框**（attach 到 IDEA 主窗口）
2. 驱动未下载 → Database 插件弹出**驱动下载对话框**
3. 这些对话框被**模态的 SQL 预览弹窗遮挡**，用户看不到
4. `executeQueries()` 无限期等待用户输入 → 界面卡在"执行中..."
5. 用户关闭 SQL 预览弹窗后，密码/下载对话框才暴露出来

**加重因素**：`selectAndExecute` 整个调用链在 **EDT（事件分发线程）** 上同步执行，`resultPanel.showLoading()` 后 EDT 被阻塞，连 loading 动画都无法刷新。

### 2.2 问题一现状

当前架构：

```
SqlPreviewPanel
├── 顶部工具栏（自研：复制/格式化/刷新...）
├── CENTER: 垂直 JSplitPane
│   ├── 上半: 水平 SplitPane
│   │   ├── 左：参数输入区（自研）
│   │   └── 右：SQL 编辑器（自研 EditorFactory.createEditor）  ← 问题
│   └── 下半: consoleHolder
│       ├── NORTH: SqlResultPanel（自研状态行）
│       └── CENTER: 内嵌原生控制台（logView.getContent）  ← 执行后才出现
└── 底部按钮区（执行 SQL / 复制 SQL 等）
```

## 三、技术方案

### 3.1 问题二：连接检测 + 后台执行

#### Phase A：连接前置测试

在 `executeQueries` 之前测试连接可用性，失败直接提示：

```kotlin
// 在 executeInConsole 中，executeQueries 之前
val connection = tryGetConnection(session)
if (connection == null || !connection.isValid(3)) {
    showError("连接不可用：密码过期或驱动缺失，请先在 Database 工具窗口配置数据源")
    return
}
```

#### Phase B：执行线程 EDT → 后台线程

将 `executeInConsole` 中 `executeQueries` 调用移到后台线程，EDT 只负责 UI 更新：

```kotlin
ProgressManager.getInstance().run(object : Task.Backgroundable(project, "Executing SQL", false) {
    override fun run(indicator: ProgressIndicator) {
        executeQueries.invoke(console, editor, scriptModel, execOption)
        // 完成后 invokeLater 更新 UI
    }
})
```

#### Phase C：超时检测 + 友好提示

Timer 重试中增加超时检测，超时后主动提示用户检查是否有隐藏弹窗：

```kotlin
if (attempts >= 10) {
    LOG.info("result tab not appeared (may need credentials)")
    ApplicationManager.getApplication().invokeLater {
        showCredentialHint()
    }
}
```

### 3.2 问题一：原生编辑器内嵌

#### 方案：原生编辑器 + 结果区分离内嵌

`DataSourceSelector.executeInConsole` 中已经拿到了 `editor`（原生 EditorImpl）和 `component`（原生结果区）。需要：

1. **在 `attachConsole` 后立即将原生编辑器内嵌到右侧**（不等执行完成）
2. **执行后仅内嵌结果区到下方**
3. **自研编辑器 → 原生编辑器的切换**：移除自研 `createEditor`，改为接收原生编辑器组件

#### 目标架构

```
SqlPreviewPanel
├── 顶部工具栏（自研：复制/格式化/刷新...）
├── CENTER: 垂直 JSplitPane
│   ├── 上半: 水平 SplitPane
│   │   ├── 左：参数输入区（自研）
│   │   └── 右：原生 Database 控制台编辑器（含原生工具栏）  ← 改为原生
│   │       ├── 原生工具栏（数据源选择器/Tx/执行按钮）
│   │       └── 原生 SQL 编辑器
│   └── 下半: 原生结果区（Output/结果 tabs）  ← 原生
└── 底部按钮区
```

## 四、开发任务分解

### Phase 1：Issue 2 - 连接检测与后台执行（优先级：高）

#### 任务 2-A：连接前置测试

**目标**：在 `executeQueries` 之前测试连接可用性

**修改文件**：`src/main/kotlin/.../execute/DataSourceSelector.kt`

**实现要点**：
- 新增 `tryGetConnection(session)` 方法：反射从 `DatabaseSession` 获取 JDBC `Connection`
- 新增 `testConnection(connection)` 方法：调用 `isValid(3)` 测试连接
- 在 `executeInConsole` 中，`executeQueries` 之前插入连接测试
- 连接失败时弹错误提示（含"打开 Database 工具窗口修复"引导）

**反射目标**：
- `com.intellij.database.console.session.DatabaseSession` → `getConnection()` 或类似方法
- `java.sql.Connection` → `isValid(int timeout)`

#### 任务 2-B：执行线程 EDT → 后台线程

**目标**：将 `executeQueries` 调用移到后台线程

**修改文件**：`src/main/kotlin/.../execute/DataSourceSelector.kt`

**实现要点**：
- 将 `executeInConsole` 中 `executeQueries` 调用包到 `Task.Backgroundable` 中
- 执行完成后 `invokeLater` 更新 UI（内嵌组件、Timer 重试）
- `resultPanel.showLoading()` 保持在 EDT（`executeSql()` 入口调用）

#### 任务 2-C：超时检测 + 友好提示

**目标**：Timer 重试超时后主动提示用户

**修改文件**：`src/main/kotlin/.../execute/DataSourceSelector.kt`

**实现要点**：
- Timer 重试 10×400ms=4s 后，如果结果 Tab 仍未出现
- 检测是否有隐藏弹窗（密码/驱动下载）
- 弹友好提示："如果 IDEA 弹出了密码输入框或驱动下载框，请关闭本面板后处理"

#### 任务 2-D：i18n 国际化

**目标**：新增连接检测相关提示文案

**修改文件**：
- `src/main/resources/messages/MpSqlVisualizerBundle.properties`
- `src/main/resources/messages/MpSqlVisualizerBundle_zh.properties`

**新增 key**：
```properties
# 连接检测
execute.connection.failed=Connection unavailable: {0}\n\nPlease open Database tool window → right-click data source → Properties to fix.
execute.credential.hint=If IDEA shows a password or driver download dialog, please close this panel and handle it.
execute.connection.testing=Testing connection...
```

### Phase 2：Issue 1 - 原生编辑器内嵌（优先级：中）

#### 任务 1-A：原生编辑器组件分离回调

**目标**：`DataSourceSelector` 增加 `onEditorComponent` 回调

**修改文件**：`src/main/kotlin/.../execute/DataSourceSelector.kt`

**实现要点**：
- 新增 `onEditorComponent` 回调参数：`(JComponent) -> Unit`
- 在 `attachConsole` + 编辑器就绪后，调用 `onEditorComponent(editor.component)`
- 回调时机：先于 `executeQueries`（编辑器就绪即可内嵌，不等执行完成）

#### 任务 1-B：SqlPreviewPanel 右侧改用原生编辑器

**目标**：移除自研编辑器，改为接收原生编辑器组件

**修改文件**：`src/main/kotlin/.../ui/SqlPreviewPanel.kt`

**实现要点**：
- 移除 `createEditor()` 方法（或保留但不作为主路径）
- `executeSql()` 中增加 `onEditorComponent` 回调：将原生编辑器内嵌到 `editorHolder`
- 右侧 `editorHolder` 改为接收原生编辑器组件
- 补全上下文注入：继续复用 `onEditor` 回调

#### 任务 1-C：参数回填逻辑适配

**目标**：原生编辑器不支持 `#param → 值` 回填，需要适配

**修改文件**：`src/main/kotlin/.../ui/SqlPreviewPanel.kt`

**实现要点**：
- 原生编辑器的 Document 操作与自研编辑器不同
- 参数回填改为通过原生编辑器的 `Document.setText()` 实现
- 或者：保留自研编辑器用于编辑，执行时同步 SQL 到原生编辑器

## 六、风险评估与缓解

| 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|----------|
| `DatabaseSession.getConnection()` 反射 API 不存在或签名差异 | 中 | 无法获取连接 | 多方式尝试：getConnection / connection / getJdbcConnection 等 |
| 后台线程执行 `executeQueries` 时序问题 | 中 | 结果 Tab 创建时序变化 | Timer 重试机制已覆盖异步场景 |
| 原生编辑器生命周期管理 | 中 | 内存泄漏/组件残留 | JdbcConsole 由 IDE 管理，内嵌后不主动 dispose |
| 参数回填功能丢失 | 高 | 用户体验下降 | 适配原生编辑器 Document 操作或保留自研编辑器 |
| EDT 阻塞 | 低 | UI 卡顿 | Task.Backgroundable 后台执行 |

### 关键发现

1. **`DatabaseSession` 无 `getConnection()` 方法**：反射 API 只有 `isConnected()` 可用于连接状态检查，但连接在 `executeQueries` 时才建立，前置检查仅作参考
2. **后台线程执行 `executeQueries`**：使用 `ExecutorService` + 5s 超时，超时后不取消 future（让用户在关闭面板后继续处理密码弹窗）
3. **原生编辑器双模式**：通过 `usingNativeEditor` 标志区分自研/原生编辑器，`showSql()`/`formatSql()`/`copySql()` 等方法均做了双模式适配
