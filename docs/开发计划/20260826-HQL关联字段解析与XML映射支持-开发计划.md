## 0. 背景与需求

### 0.1 问题

用户反馈 HQL 识别不准确。典型场景：

```java
String hql = "select rti.gradeType from RuleTableItem rti WHERE rti.ruleTable.id = :ruleTableId AND rti.type = :type ORDER BY rti.lineNO";
```

插件生成的 SQL（错误）：
```sql
SELECT rti.grade_type FROM rule_table_item rti
WHERE rti.rule_table.id = ? AND rti.type = ? ORDER BY rti.line_n_o
```

实际数据库表结构（SQL Server）：
```
THORN_RULE_TABLE_ITEM:
  ID, RULE_TABLE_ID, REFERENCE, TYPE, REFERENCE_TYPE, ENUM_VALUES, LINE_NO
```

Hibernate XML 映射：
```xml
<class name="RuleTableItem" table="THORN_RULE_TABLE_ITEM">
  <id name="id" column="ID">
  <many-to-one name="ruleTable" class="ThornRuleTable">
    <column name="RULE_TABLE_ID">
```

### 0.2 问题汇总

| # | 问题 | 期望值 | 当前值 | 根因 |
|---|------|--------|--------|------|
| P1 | 表名 | `THORN_RULE_TABLE_ITEM` | `rule_table_item` | 未读取 `.hbm.xml` 映射，仅靠命名策略猜测 |
| P2 | 关联字段 `rti.ruleTable.id` | `RULE_TABLE_ID` | `rule_table.id` | `mapPropertyToColumn` 不处理 associations；关联路径解析缺失 |
| P3 | `lineNO` 列名 | `LINE_NO` | `line_n_o` | `NamingStrategy.toSnakeCase` 对连续大写处理不符合实际列名 |
| P4 | `gradeType` 列名 | `GRADE_TYPE`（无注解时按约定） | `grade_type` | 同 P3，命名策略偏差 |

### 0.3 核心需求

| # | 需求 | 优先级 |
|---|------|:------:|
| R1 | 支持读取 `.hbm.xml` 映射文件，解析表名和列名 | P0 |
| R2 | HQL 关联字段路径解析：`alias.field.id` → 外键列名 | P0 |
| R3 | 命名策略优化：支持用户自定义或更灵活的 camelCase→实际列名转换 | P1 |
| R4 | 无映射文件时的降级策略：优先使用已解析的注解信息，其次命名策略 | P1 |

## 1. 技术方案

### 1.1 问题根因分析

当前架构中，实体元数据解析完全依赖 `JpaEntityResolver`，它只识别 JPA 注解：

```
HQL 字符串
  → CustomDaoHqlLocator / HqlQueryLocator 检测
  → 从 HQL 提取实体类名
  → JpaEntityResolver 解析 PsiClass（仅 JPA 注解）
  → TableInfo（tableName, columns, associations）
  → HqlConverter.convert() 做字符串级替换
```

**断裂点**：
1. 项目使用 `.hbm.xml` 而非 JPA 注解 → `JpaEntityResolver` 无法解析 → 返回空 TableInfo → 表名/列名全靠猜测
2. `HqlConverter.mapPropertyToColumn` 只遍历 `TableInfo.columns`，不处理 `TableInfo.associations` → 关联字段路径 `rti.ruleTable.id` 无法解析为外键列
3. `NamingStrategy.toSnakeCase` 对 `lineNO` 这类连续大写字段生成 `line_n_o`，不符合实际列名 `LINE_NO`

### 1.2 整体架构

```
改造后：
  HQL 字符串
    → CustomDaoHqlLocator / HqlQueryLocator 检测
    → 从 HQL 提取实体类名
    → JpaEntityResolver 解析 PsiClass（JPA 注解）
    → 【新增】HbmXmlEntityResolver 解析 .hbm.xml 映射文件
    → TableInfo（tableName, columns, associations）
    → HqlConverter.convert()
      → 【增强】mapAssociationPath：alias.field.id → 外键列名
      → mapPropertyToColumn：属性名 → 列名
```

### 1.4 关键设计

#### 1.4.1 HbmXmlEntityResolver

解析 `.hbm.xml` 文件，提取实体映射信息：

```kotlin
/**
 * 解析 Hibernate XML 映射文件（.hbm.xml），提取实体元数据。
 *
 * 支持的映射元素：
 * - <class name="..." table="...">  → 实体类名、表名
 * - <id name="..." column="...">    → 主键映射
 * - <property name="..." column="..."> → 普通属性映射
 * - <many-to-one name="..." class="...">
 *     <column name="...">           → 关联字段 + 外键列
 * - <one-to-one name="..." class="...">
 *     <column name="...">           → 一对一关联
 *
 * 查找策略：
 * 1. 在当前文件所在模块中搜索 *.hbm.xml 文件
 * 2. 在 resource 目录中搜索
 * 3. 在 hibernate.cfg.xml 的 <mapping resource="..."> 中查找
 */
object HbmXmlEntityResolver {

    data class HbmClassMapping(
        val entityClassName: String,     // 简单类名，如 "RuleTableItem"
        val fullClassName: String,       // 全限定名，如 "com.xxx.RuleTableItem"
        val tableName: String,           // 数据库表名，如 "THORN_RULE_TABLE_ITEM"
        val properties: List<HbmPropertyMapping>,
        val associations: List<HbmAssociationMapping>,
    )

    data class HbmPropertyMapping(
        val fieldName: String,           // Java 字段名，如 "lineNO"
        val columnName: String,          // 数据库列名，如 "LINE_NO"
        val isId: Boolean = false,       // 是否主键
    )

    data class HbmAssociationMapping(
        val fieldName: String,           // Java 字段名，如 "ruleTable"
        val targetClassName: String,     // 目标实体类名，如 "ThornRuleTable"
        val joinColumn: String,          // 外键列名，如 "RULE_TABLE_ID"
        val targetTable: String = "",    // 目标表名（延迟解析）
    )

    /**
     * 根据实体类名查找映射信息。
     * 优先精确匹配类名，其次模糊匹配。
     */
    fun resolve(entityClassName: String, project: Project): HbmClassMapping?

    /**
     * 从 PsiFile 中查找同模块的 .hbm.xml 文件。
     */
    fun findHbmFiles(psiFile: PsiFile): List<PsiFile>
}
```

#### 1.4.2 关联字段路径解析

增强 `HqlConverter`，处理 `alias.field.id` 模式：

```kotlin
/**
 * 处理关联字段路径：alias.fieldName.id → 外键列名。
 *
 * 示例：
 *   rti.ruleTable.id → rti.RULE_TABLE_ID（当 ruleTable 是 ManyToOne 关联，joinColumn = RULE_TABLE_ID）
 *   o.customer.name → o.CUSTOMER_NAME（当 customer 是 ManyToOne 关联，customer 有 name 列）
 *
 * 解析策略：
 * 1. 检测 alias.fieldName.id 模式
 * 2. 查找 alias 对应的 TableInfo
 * 3. 查找 fieldName 对应的 AssociationInfo
 * 4. 将 alias.fieldName.id 替换为 alias.joinColumn
 * 5. 对于更深层路径（alias.field.name），暂不支持，添加注释提示
 */
private fun mapAssociationPath(hql: String, table: TableInfo): String {
    // 匹配 alias.field.id 模式（两段式关联路径）
    val twoLevelPattern = Regex(
        "([a-zA-Z_][a-zA-Z0-9_]*)\\.([a-zA-Z_][a-zA-Z0-9_]*)\\.([a-zA-Z_][a-zA-Z0-9_]*)"
    )
    // 匹配 alias.field.name 模式（两段式，非 id）
    // 这种情况下需要关联 JOIN，暂用注释提示
    ...
}
```

#### 1.4.3 实体解析降级链

在 `SqlPreviewService.resolveHqlTable()` 中增加降级路径：

```
1. JpaEntityResolver（JPA 注解）  ← 现有
2. HbmXmlEntityResolver（.hbm.xml）  ← 新增
3. 命名策略猜测  ← 现有（fallback）
```

### 1.5 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| XML 解析方式 | `javax.xml.parsers.DocumentBuilder`（DOM） | .hbm.xml 通常不大，DOM 解析简单可靠 |
| 映射文件查找范围 | 当前模块 + resource 目录 | 避免全项目扫描，控制性能开销 |
| 关联路径深度 | 支持两段式（alias.field.id），三段式暂不支持 | 覆盖 90% 实际场景，避免过度设计 |
| 命名策略 | 保留现有 toSnakeCase，新增配置选项 | 向后兼容，允许用户覆盖 |
| 缓存策略 | 与 JpaEntityResolver 相同的三维缓存 key | 避免重复解析 |

## 3. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| .hbm.xml 文件格式多样（嵌套、继承、discriminator） | 解析不完整 | 优先支持常见模式（class/id/property/many-to-one），复杂场景添加注释提示 |
| 命名策略改动影响 MyBatis-Plus 现有用户 | 回归 | 命名策略改动仅影响 HQL 路径，MP 路径保持不变 |
| 关联路径解析引入误替换 | SQL 错误 | 严格匹配模式，不确定时保留原文并添加注释 |
| 全项目扫描 .hbm.xml 性能问题 | IDE 卡顿 | 限定扫描范围（当前模块 + resource 目录），结果缓存 |
