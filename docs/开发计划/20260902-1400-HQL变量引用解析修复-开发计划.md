# HQL 变量引用解析修复 开发计划

> 分支：`master`
> 范围：`HqlQueryLocator.extractHqlString()` 的 `PsiReferenceExpression` 分支

## 目标

修复 HQL 提取为变量后预览显示变量名（如 "hql"）而非实际 SQL 字符串的问题。支持直接字面量变量、字符串拼接变量、`final` 常量字段三种场景的静态解析，方法参数等不可静态解析场景优雅降级。

## 问题

用户将 HQL 赋值给变量后传入 `createQuery()`：

```java
String hql = "select" + " count(booking.id), ...";
entityManager.createQuery(hql);  // 预览显示 "hql" 而非实际 SQL
```

预览 SQL 直接显示 `hql`（变量名），而非展开后的实际查询语句。

## 根因

`HqlQueryLocator.extractHqlString()` 的 `PsiReferenceExpression` 分支（line 291-303）只处理了 `initializer is PsiLiteralExpression` 一种情况。当变量通过字符串拼接初始化时（`String hql = "select" + " ..."`），initializer 是 `PsiBinaryExpression`，不满足 `PsiLiteralExpression` 判断，直接回落到返回变量名 `firstArg.referenceName`（即 `"hql"`）+ `isLiteralHql=false`。

## 任务

### T-HqlVarResolve-01 核心修复 — 拼接初始化器处理

- `extractHqlString()` 的 `PsiReferenceExpression` 分支新增 `PsiBinaryExpression` / `PsiPolyadicExpression` 判断，命中时复用 `collectStringLiterals()` 递归收集所有字面量片段拼接。
- 编译时常量求值方案评估：`ConstantEvaluationHelper.computeConstantValue()` 在 2026.2.1 平台不存在（jar 反编译确认），不引入；`static final` 常量字段的 initializer 本身就是 `PsiLiteralExpression`，已有分支覆盖。
- 其他非空表达式 / `null` initializer（方法参数）保持优雅降级：返回变量名 + `isLiteralHql=false`。

### T-HqlVarResolve-02 测试覆盖

新增 4 个测试用例（`HqlQueryLocatorTest`）：

| 测试 | 场景 | 预期 |
|------|------|------|
| `testEntityManager_createQuery_variableLiteral` | `String hql = "..."; em.createQuery(hql)` | 展开实际 HQL，`isLiteralHql=true` |
| `testEntityManager_createQuery_variableConcat` | `String hql = "select" + " ..."; em.createQuery(hql)` | 展开拼接结果，`isLiteralHql=true` |
| `testEntityManager_createQuery_finalConstantField` | `static final String HQL = "..."; em.createQuery(HQL)` | 展开常量值，`isLiteralHql=true` |
| `testEntityManager_createQuery_methodParameter_gracefulDegradation` | `void foo(String hql) { em.createQuery(hql); }` | 返回变量名，`isLiteralHql=false` |

### T-HqlVarResolve-03 同步检查 CustomDaoHqlLocator

- `CustomDaoHqlLocator.extractHqlString()` 已有递归处理（line 300 `extractHqlString(initializer)`），能正确处理拼接初始化器，无需改动。
