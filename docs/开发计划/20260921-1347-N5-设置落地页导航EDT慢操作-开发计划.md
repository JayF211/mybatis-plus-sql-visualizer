# N5 设置落地页双击导航在 EDT 触发慢操作 — 开发计划

> 来源：2026-09-21 用户粘贴两份真机栈（`java.lang.Throwable: Slow operations are prohibited on EDT`，栈顶应用帧为 `PluginSettingsFolderConfigurable.onDoubleClick`）；同日定位根因并立项实施。
> 相邻事项：导航实现与 T-SettingsTruth P3 / T-ProjectSettingsScope 同源，本次只改「用哪个键去查」，不改导航语义；同类站点（平台 MCP 页跳转）评估后不收编，见 §七。

## 一、现象与影响

- **现象**：在设置页（Tools → SQL Visualizer 落地页）双击搜索/列表条目时，日志出现
  `java.lang.Throwable: Slow operations are prohibited on EDT`，栈顶应用帧是
  `PluginSettingsFolderConfigurable$createComponent$1.onDoubleClick`。两份栈是**同一个索引查询的两个检查点**——一份报在外层 `FileBasedIndexScanUtil.ensureUpToDate`，一份报在扫描内部的 `WorkspaceFileIndexDataImpl.ensureIsUpToDate`，不是两个独立问题。
- **平台版本已钉死**：栈内三处行号在 243.28141.41（IntelliJ IDEA 2024.3.7.1）源码里逐帧对上——
  `ConfigurableWrapper.java:97` = `configurable = wrapper.getConfigurable()`、`:118` = `myConfigurable = createConfigurable(myEp, false)`、`Settings.java:30` = `unwrap(ConfigurableVisitor.findByType(...))`，`KotlinScriptingSettingsConfigurable.java:46` 也正是那行 `getAllDefinitions`。
  （本机 `%LOCALAPPDATA%\JetBrains\IntelliJIdea2024.3\log` 的 idea.log/idea.1.log/idea.2.log 里都没有这条记录，故这份栈不是这台机器当前日志里出来的；不影响结论。）
- **影响**：EDT 上做了一次文件名索引扫描（`FilenameIndex.getVirtualFilesByName`），索引未就绪时界面卡顿；日志多一条 ERROR。
- **不是崩溃**：2024.3 的 `SlowOperations.assertSlowOperationsAreAllowed`（`SlowOperations.java:106-114`）在非测试环境走 `Holder.LOG.error(...)`，抛异常（`SlowOperationCanceledException`）只在 `FORCE_THROW` 区段即测试/内部模式；导航本身照常完成。
- **量化**：`ConfigurableWrapper` 缓存实例，代价是**每次设置对话框会话的第一次双击**付一次；`SlowOperations.isAlreadyReported()` 按栈去重（`ThrowableInterner`），同一进程只记一条日志。
- **性质**：既有缺陷（导航功能自 T-SettingsTruth P3 起就这么写），非本轮引入。只在装了 Kotlin 插件、且首次导航时索引未热时暴露，故长期未被发现。

## 二、根因（平台源码级，243 sources jar）

链路：`onDoubleClick(:66)` → `navigateTo(:138)` → `navigateToPage` 里那句 `settings.find(configurableClass)`（改前 `:155`）。

- `Settings.find(Class)`（`Settings.java:29-31`）= `ConfigurableVisitor.findByType(type, myGroups)`，对树里每个 `ConfigurableWrapper` 调 `ConfigurableWrapper.cast(type, wrapper)`（`ConfigurableVisitor.java:36-38`）。
- `cast`（`ConfigurableWrapper.java:86-99`）本有一条短路：EP 声明的类型与目标类型不相容就 `return null`，不创建。但它取的是 `wrapper.getExtensionPoint().getConfigurableType()`，而 `ConfigurableEP.ClassProducer`（`ConfigurableEP.java:415-450`）**没有覆写** `ObjectProducer.getType()`（`:392`，返回 null）→ `getConfigurableType()` 恒为 null → **这条短路在 2024.3 是死代码** → 必然执行 `wrapper.getConfigurable()`（`:97`）→ `createConfigurable`（`:118`）→ **把整棵树实例化一遍**，直到命中目标类。
- 被顺带实例化的是 Kotlin 插件 `KotlinScriptingSettingsConfigurable`（其 EP 排在我们页面之前）。该构造器第 46 行即 `KotlinScriptDefinitionsModel.createModel(getAllDefinitions(project), settings)` → `ScriptDefinitionsManager` → `ScriptTemplatesFromDependenciesProvider.loadSync` → `FilenameIndex.getVirtualFilesByName` → 索引扫描 → EDT 慢操作断言。
- 平台自身的 `ShowSettingsUtil.showSettingsDialog(project, Class)`（`ShowSettingsUtilImpl.kt:105-115`）走的是同一套 `ConfigurableWrapper.cast`，所以「换成平台 API」躲不掉——问题不在用错了哪个 API，而在**按类型查这个动作本身**。

## 三、修法

对话框内定位改为**按 EP id 查**：`settings.find(configurableId)`。

- `ConfigurableWrapper.getId()`（`:219-231`）：EP 声明了 `id` 就直接返回 `myEp.id`，**不实例化**；只有目标页会被创建。
- 语义等价：`find(Class)` 与 `find(id)` 都经 `Settings.unwrap` 返回底层实例并登记 `myMap` 映射，后续 `settings.select(...)` 拿到的仍是同一个 wrapper（选中/切换行为不变）。
- 落地要点：
  1. `SubPageDesc` / `SearchableField` / `SearchItem` 增 `configurableId`（8 个登记目标的 id 取自 `plugin.xml`，与既有 `configurableClass` 并存）；
  2. 查找收敛到唯一入口 `resolveTarget(settings, configurableId)`——签名里没有 Class，退回按类查编译不过（反回归哨兵）；
  3. **保留** `configurableClass` 只服务兜底分支（`currentSettings()` 取不到、需新开设置对话框时）：平台没有按 id 的公开重载——`showSettingsDialog(project, String)` 是按**显示名**定位（`ShowSettingsUtilImpl.kt:130-134`），按 id 的那个 `showSettingsDialog(project, idToSelect, filter)` 是 `ShowSettingsUtilImpl.Companion` 的 impl 级静态方法（`ShowSettingsUtilImpl.kt:77-89`），不引入内部 API 依赖。
- **取舍**：只动「用哪个键查」，不动导航语义、聚焦闪烁、兜底分支行为；不改 `focusTarget`（目标页的 `createComponent` 本来就要在 EDT 上跑）。

## 五、测试（实测读数）

落地在 `PluginSettingsFolderConfigurableTest`（新增 4 例，该类共 9 例）：

1. **判别性用例** `test导航按id查_不实例化无关设置页`：按 id 命中目标页（目标页 `getRawConfigurable() != null`，即真的跳到了）+ 兄弟页（界面与操作页）`rawConfigurable == null` + **真机触发点 Kotlin scripting 页**（夹具树里在场）`rawConfigurable == null`。探针 `ConfigurableWrapper.getRawConfigurable()` 只回读缓存实例、不触发创建，故「null = 没被实例化」是可信读数。
2. **正对照** `test按类查会实例化全树_正对照`：按类查之后该页 `rawConfigurable != null`，证明探针看得见实例化（防空绿）。
3. **一致性守卫** `test登记目标id与类指向同一设置页`：8 个登记目标逐个比对 EP 元数据（不实例化），id 与 `plugin.xml` 漂移会在此转红。
4. **P1 探针** `test探针_设置树内无id的EP清单`：打印读数（见 §四）。
5. **变异实验**：把 `resolveTarget` 的查找换回修复前形态（`settings.find(SqlLogConfigurable::class.java)`）→ 判别性用例转红，读数
   `junit.framework.AssertionFailedError: 按 id 查不得实例化无关设置页——按类查（ConfigurableVisitor.findByType）会实例化全树`（该轮 9 例 1 失败）；随后按副本逐字还原，`diff` 与主树一致。
6. **定向回归**：`config` 包全量 **20 类 / 148 用例 / 0 跳过 / 0 失败 / 0 错误**（`BUILD SUCCESSFUL`）。

真实 IDE 2024.3.7.1（与栈同版本）→ 打开设置 → Tools → SQL Visualizer → 在搜索框输入关键词 → 双击任一命中条目：

- `%LOCALAPPDATA%\JetBrains\IntelliJIdea2024.3\log\idea.log` 内 `Slow operations are prohibited` **0 条**。
  ⚠️ 该断言要求**新开一次 IDE 会话**：`SlowOperations.isAlreadyReported()` 按栈去重，同一进程内重复触发不再记录，旧会话的残留条目不能当读数。

## 七、未收编项与边界

- **平台 MCP 页跳转两处**（`McpConfigurable.kt:140-158`、`PluginSettingsPanel.kt:1175-1193`）走 `showSettingsDialog(project, Class)`，同一套 `cast` 全树实例化。不收编理由：目标是平台插件的页、只有 `Class.forName` 得到的运行时类名，没有可核实的 id 可用；且动作语义是「新开设置对话框」，与本次修复的对话框内导航不是同一条路径。属已知残留，未验证。
- **兜底分支**（`currentSettings()` 取不到时新开对话框）保持按类查，理由见 §三。
- **无 id 的 EP 仍会被实例化**（§四 P1）：按 id 查时 `getId()` 对这类 wrapper 会退化成 `cast(SearchableConfigurable.class, this)`。真机全树里有多少个无 id 的 EP 未实测；把这条彻底归零需要「不触碰任何其它 wrapper」的定位方式，而平台未提供（`Settings` 不暴露 groups，自建组列表拿到的 wrapper 未必是对话框里那一个实例）。
- 本项不改变「哪些条目可跳转」的集合，也不动搜索索引内容。
