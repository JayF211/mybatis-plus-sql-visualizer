## 一、现状与目标

### 1.1 现状

- **预览面板**：`SqlPreviewPanel.kt`（2278 行）`toolbar()` 用 `smallButton(text){action}` 追加按钮（现有 8 个）；**无按钮置灰先例**（Community 现为静默回退+提示）；执行入口 `executeSql()` → `SqlPreviewDialog.createActions()`。
- **原生执行链**（`execute/`）：`SqlExecutor` 门面三入口（execute/prepareConsole/executePrepared），Community 由 `ExecuteSqlSupport.isAvailable()`（Class.forName 反射）短路；`DataSourceSelector` 承担 Runner 获取/控制台 attach/`executeQueries`/结果 Tab 换入（`REUSE_ACCEPT_TICKS=4`、`swapGeneration`、`refreshResultsComponent`）；结果显示在内嵌控制台 SplitPane 底部，状态条 `SqlResultPanel`。
- **Dialect SPI**（`sql/Dialect.kt` 单文件 9 object）：接口方法 `renderLimit/quoteIdentifier/reservedWords/quoteIfKeyword/renderUpsert/renderUpsertStatement`；`renderUpsert` 返回 null 即降级，双形态约定可参照。
- **EXPLAIN 现状**：全库无执行/解析逻辑；仅 `SqlTypeClassifier` 已把 EXPLAIN 归入免确认查询类（与新功能天然吻合）。
- **静态规则引擎**：`sql/perf/` 20 条规则 → `PerfWarning` → `PreviewResult.perfWarnings` → `SqlPreviewPanel.updateMeta()` 的 `buildPerfLine`（顶部 metaLabel HTML 第二行）。

### 1.2 目标

预览面板新增「EXPLAIN」按钮：按方言包 EXPLAIN 语句 → 走原生控制台执行 → 结果 Tab 展示真实执行计划；顶部静态规则标注（已有）与真实计划同屏对照。

### 1.3 非目标

- 不解析执行计划为结构化建议、不自动改写 SQL（P-立项-06 已定不做）。
- 不新建计划渲染组件——首版直接复用原生结果 Tab 展示。

## 二、实现设计

### 2.1 Dialect SPI 扩展

接口新增 `fun renderExplainStatement(sql: String): String?`（null = 不支持，按钮降级），首版支持矩阵：

| 方言 | 渲染 | 依据 |
|------|------|------|
| MySQL / MariaDB | `EXPLAIN FORMAT=JSON <sql>` | 主战场 |
| PostgreSQL | `EXPLAIN (FORMAT JSON, VERBOSE) <sql>` | 主战场 |
| KingBase | `EXPLAIN <sql>`（PG 兼容系） | 需真机验证后放开 |
| H2 | `EXPLAIN PLAN FOR <sql>` | 引擎级可测 |
| SQLite | `EXPLAIN QUERY PLAN <sql>` | 引擎级可测 |
| Oracle / SQL Server / DM | null（首版降级） | Oracle 需两步链查 PLAN_TABLE；SQL Server 需会话 SET；DM 语法未验证 |

实现放 `Dialect.kt` 各 object，参照 `renderPgStyleLimit` 共享辅助函数模式。

### 2.2 按钮与灰化

- `toolbar()` 追加 `smallButton("panel.action.explain")`。
- 新增置灰模式（全项目首个先例）：`isEnabled=false` + tooltip 说明原因，条件三条——`ExecuteSqlSupport.isAvailable()`、数据源已选（`DataSourceSettings` 有默认值）、`dialect.renderExplainStatement(sql) != null`。任一不满足置灰并注明「需 Ultimate/需选择数据源/当前方言不支持」。

### 2.3 执行链

- `SqlExecutor` 新增 `explain(sql)`：内部走 `prepareConsole` + 用 `renderExplainStatement` 产物提交 `executeQueries`，完整复用 `DataSourceSelector` 的 attachConsole/结果 Tab 换入/代际机制（swapGeneration/REUSE_ACCEPT_TICKS 原样沿用，不新造执行路径）。
- `SqlTypeClassifier` 已将 EXPLAIN 归免确认类，无需改动。
- 执行中复用 `SqlResultPanel.showLoading`；错误走 `showError` + 既有 errorCopyButton。

### 2.4 静态对照

真实计划在结果 Tab（原生网格），静态规则在顶部 metaLabel（已有 `buildPerfLine`）——执行 EXPLAIN 后无需新组件即同屏；在 metaLabel 追加一行「EXPLAIN 已执行于 {数据源名}（{时间}）」提示对照关系。

## 四、验证

- 单测：逐方言 `renderExplainStatement` 断言（含 null 降级三方言）。
- DBX 真机：MySQL/PG 直接执行渲染产物验证语法；KingBase 验证通过后才移入支持矩阵。
- 沙盒 runIde：全链点击→结果 Tab 换入→与 M36.5 系列防串机制无回归（BUILD_STAMP 防呆）。
- Community 测试沙盒（database jar 已排除）：按钮置灰不报错。

## 五、风险

1. **原生控制台对 EXPLAIN 类语句的结果呈现**：JSON 大文本在网格单元格的可读性一般——首版接受，后续再议格式化视图。
2. **KingBase 语法未实测**：先 null 降级，真机通过才放开，不硬编码猜测。
3. **执行链防串**：EXPLAIN 与普通执行共用控制台，必须走同一代际机制，禁止绕过 `executeQueries` 直连。
