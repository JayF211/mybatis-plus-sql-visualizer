# SQL→Java 反向解析：子查询 JOIN 与 FROM 子查询修复

> 创建日期：2026-08-21
> 状态：**计划中**
> 优先级：**P0**（阻断级——用户 demo 项目核心用例无法转换）

## 1. 问题描述

### 1.1 现象

复杂 SQL（含子查询作为 JOIN 表源或 FROM 主表）通过「SQL→Java」反向转换时报错：

```
无法解析该SQL: 表名格式不正确(第9行)
```

### 1.2 触发示例（demo 项目 `DeviceInfoServiceImpl.joinExtAndSubTable`）

```sql
SELECT t.id, t.station_id, t.share_scheme_id, t.device_name
FROM car_device_info t
LEFT JOIN station_info stationInfoEntity ON stationInfoEntity.id = t.station_id
    AND stationInfoEntity.station_name = '中心站'
LEFT JOIN (
    SELECT tt.id, tt.station_id, tt.station_name, tt.merchant_id
    FROM station_info tt
    WHERE tt.merchant_id >= 0
) tt ON tt.station_id = t.station_id
WHERE t.id = 1
```

第 9 行 `LEFT JOIN (` 的 `(` 触发"表名格式不正确"。

### 1.3 根因

`SqlReverseParser` 有两处假设"表名一定是 WORD token"：

| 位置 | 代码 | 问题 |
|------|------|------|
| `parseJoin()` L369 | `val tableName = parseTableName(cursor)` | JOIN 表为 `(SELECT ...) alias` 时当前 token 是 `(`（SYMBOL），`parseTableName` 要求 WORD → 抛"表名格式不正确" |
| `parseSelectBody()` L77 | `val tableName = parseTableName(cursor)` | FROM 主表为 `(SELECT ...) alias` 时同样报错 |

`parseTableName` 内部校验：
```kotlin
if (t.type != TokenType.WORD) {
    throw SqlReverseException(t.offset, KEY_PARSE, "表名格式不正确")
}
```

### 2.2 设计决策：子查询 JOIN 的生成形态

子查询 JOIN 无法映射为 MPJ 三参 lambda `leftJoin(Class, Sub::getX, Main::getY)`，因为：
- 子查询不是实体表，无 `Class` 参数
- 子查询内含 WHERE 条件、聚合等复杂逻辑

**决策：回落字符串 raw join** — `leftJoin("(SELECT ...) alias ON 条件")`，与 `MPJQueryWrapper` 字符串写法对齐。生成器已有 `canLambdaJoin` → false → `joinString` 路径，无需修改生成器。

### 3.2 详细改动

#### 3.2.1 `SqlReverseParser.kt` — 新增 `parseSubqueryTable()`

```kotlin
/**
 * 解析子查询表表达式：`(SELECT ...) [别名]`。
 * 前置条件：当前 token 为 `(`。
 * 返回完整文本（含括号和别名），作为表表达式供 raw join / FROM 透传。
 *
 * @throws SqlReverseException 括号不匹配
 */
private fun parseSubqueryTable(cursor: Cursor): String {
    val startToken = cursor.current
        ?: throw SqlReverseException(cursor.offsetAtEnd(), KEY_PARSE, "缺少子查询")
    val startOffset = startToken.offset
    var depth = 0
    while (cursor.current != null) {
        val tk = cursor.current!!
        if (tk.type == TokenType.SYMBOL && tk.text == "(") depth++
        if (tk.type == TokenType.SYMBOL && tk.text == ")") {
            depth--
            if (depth == 0) {
                val endOffset = tk.offset + 1  // 包含 )
                cursor.advance()              // 消费 )
                val subqueryText = cursor.source.substring(startOffset, endOffset)
                // 消费可选别名（ON/WHERE/JOIN 等为边界）
                val alias = consumeSubqueryAlias(cursor)
                return if (alias != null) "$subqueryText $alias" else subqueryText
            }
        }
        cursor.advance()
    }
    throw SqlReverseException(startOffset, KEY_PARSE, "子查询括号不匹配")
}
```

#### 3.2.2 `SqlReverseParser.kt` — 新增 `consumeSubqueryAlias()`

```kotlin
/**
 * 消费子查询后的可选别名（ON/WHERE/GROUP/ORDER/LIMIT/JOIN 等为边界）。
 * 无别名返回 null。复用 consumeJoinAlias 逻辑（边界集一致）。
 */
private fun consumeSubqueryAlias(cursor: Cursor): String? = consumeJoinAlias(cursor)
```

> 注：`consumeJoinAlias` 已包含 ON/WHERE/GROUP/ORDER/LIMIT/LEFT/RIGHT/INNER/FULL/CROSS/JOIN 边界，完全适用子查询别名场景。

#### 3.2.3 `SqlReverseParser.kt` — 修改 `parseJoin()`（L368-370）

```kotlin
// 修改前：
val tableName = parseTableName(cursor)
val alias = consumeJoinAlias(cursor)

// 修改后：
val (tableName, alias) = parseJoinTableExpression(cursor)
```

新增 `parseJoinTableExpression()`：

```kotlin
/**
 * 解析 JOIN 表表达式：普通表名 或 子查询 `(SELECT ...) [别名]`。
 * 返回 (tableName, alias)：
 *   - 普通表：("table", "alias")
 *   - 子查询：("(SELECT ...) alias", null) — 别名嵌入文本，alias 置 null
 */
private fun parseJoinTableExpression(cursor: Cursor): Pair<String, String?> {
    val t = cursor.current
        ?: throw SqlReverseException(cursor.offsetAtEnd(), KEY_PARSE, "缺少 JOIN 表名")
    if (t.type == TokenType.SYMBOL && t.text == "(") {
        return parseSubqueryTable(cursor) to null
    }
    return parseTableName(cursor) to consumeJoinAlias(cursor)
}
```

#### 3.2.4 `SqlReverseParser.kt` — 修改 `parseSelectBody()`（L77-78）

```kotlin
// 修改前：
val tableName = parseTableName(cursor)
consumeOptionalAlias(cursor)

// 修改后：
val tableName = if (cursor.current?.type == TokenType.SYMBOL && cursor.current?.text == "(") {
    parseSubqueryTable(cursor)  // FROM (SELECT ...) alias — 别名已嵌入
} else {
    val name = parseTableName(cursor)
    consumeOptionalAlias(cursor)
    name
}
```

> FROM 子查询的别名不存入 `SqlReverseResult`（无 `fromAlias` 字段），嵌入 tableName 即可。

#### 3.2.5 `JavaCodeGenerator.kt` — 无需修改

验证路径：
1. `canLambdaJoin` → `join.alias` 为 null → `entity?.subEntities?.get(null)` → null → 返回 false ✅
2. `renderJoins` → false 分支 → `"${joinMethod(join.type)}(\"${javaEscape(joinString(join))}\")"` ✅
3. `joinString` → `tablePart = "(SELECT ...) tt"` + `null` alias → `"(SELECT ...) tt ON ..."` ✅

### 3.3 数据流

```
SQL: LEFT JOIN (SELECT ... ) tt ON tt.station_id = t.station_id
                    ↓
parseJoinTableExpression → 检测到 ( → parseSubqueryTable
                    ↓
tableName = "(SELECT ... ) tt", alias = null
                    ↓
ReverseJoin(type=LEFT, tableName="(SELECT ... ) tt", alias=null, onConditions=[...], rawOn="...")
                    ↓
renderJoins → canLambdaJoin(alias=null) → false
                    ↓
leftJoin("(SELECT ... ) tt ON tt.station_id = t.station_id")
```

## 6. Case 1 增强：ext 条件 lambda 化（已完成部分基础上的增量）

### 6.1 问题

当前 `canLambdaJoin` 要求 ON 只有单等值列对（`singleOrNull`），导致"join key + 副表 ext 过滤条件"的常见场景回落字符串 raw join，无法生成 4 参 `leftJoin(Class, left, right, ext -> ext.eq(...))`。

示例：`LEFT JOIN station_info ext ON ext.id = t.station_id AND ext.station_name = '中心站'` → 当前生成 `leftJoin("station_info ext ON ...")` 字符串，应生成：
```java
leftJoin(StationInfoEntity.class,
    StationInfoEntity::getId, DeviceInfoEntity::getStationId,
    ext -> ext.eq(StationInfoEntity::getStationName, "中心站"))
```

### 6.2 改动方案

#### 6.2.1 `JavaCodeGenerator.kt` — 放宽 `canLambdaJoin`

当前 `joinKeyComparison` 要求 `singleOrNull` → 改为：恰好 1 个 ColumnComparison（key）+ 其余均为副表 Simple 条件（ext）。

```kotlin
// 新增数据类
data class JoinKeyInfo(
    val key: Condition.ColumnComparison,
    val extConditions: List<Condition.Simple>,
)

// 替代原 joinKeyComparison
private fun extractJoinKey(join: ReverseJoin, sub: EntityTarget): JoinKeyInfo? {
    val keyConditions = join.onConditions.filterNot { isSubLogicalDelete(it, sub, join.alias) }
    val key = keyConditions.singleOrNull { it is Condition.ColumnComparison } as? Condition.ColumnComparison ?: return null
    val ext = keyConditions.filterIsInstance<Condition.Simple>()
        .filter { it.column.tableAlias == join.alias }  // ext 条件必须引用副表列
    return JoinKeyInfo(key, ext)
}

// 放宽 canLambdaJoin
private fun canLambdaJoin(join: ReverseJoin, entity: EntityTarget?): Boolean {
    val sub = join.alias?.let { entity?.subEntities?.get(it) } ?: return false
    val info = extractJoinKey(join, sub) ?: return false
    val leftField = sub.columnToField[info.key.left.columnName]
    val rightField = entity?.columnToField?.get(info.key.right.columnName)
    return leftField != null && rightField != null
}
```

#### 6.2.2 `JavaCodeGenerator.kt` — `renderJoins` 拆分 key/ext

```kotlin
private fun renderJoins(result: SqlReverseResult, entity: EntityTarget?): List<String> =
    result.joins.map { join ->
        if (canLambdaJoin(join, entity)) {
            val sub = entity!!.subEntities[join.alias]!!
            val info = extractJoinKey(join, sub)!!
            val leftField = sub.columnToField[info.key.left.columnName]!!.replaceFirstChar { it.uppercase() }
            val rightField = entity.columnToField[info.key.right.columnName]!!.replaceFirstChar { it.uppercase() }
            val base = "${joinMethod(join.type)}(${sub.className}.class, " +
                "${sub.className}::get$leftField, " +
                "${entity.className}::get$rightField"
            if (info.extConditions.isEmpty()) {
                "$base)"
            } else {
                val extChain = info.extConditions.joinToString("\n            ") { ext ->
                    val colName = sub.columnToField[ext.column.columnName]?.replaceFirstChar { it.uppercase() }
                        ?: ext.column.columnName
                    "ext.eq(${sub.className}::get$colName, ${javaValue(ext.value)})"
                }
                "$base,\n            ext -> $extChain)"
            }
        } else {
            "${joinMethod(join.type)}(\"${javaEscape(joinString(join))}\")"
        }
    }
```

#### 6.2.3 影响分析

| 场景 | 当前行为 | 改动后行为 |
|------|----------|------------|
| 单等值列对（无 ext） | 3 参 lambda | 不变，3 参 lambda |
| 等值列对 + ext 条件 | 回落字符串 | 4 参 lambda（ext ->） |
| 多键对（复合主键） | 回落字符串 | 不变，仍回落字符串 |
| 子查询 JOIN | 回落字符串 | 不变，仍回落字符串 |

#### 6.2.4 `joinKeyComparison` 引用更新

`joinKeyComparison` 仅被 `canLambdaJoin` 调用，改为 `extractJoinKey` 后无需保留原函数。`isSubLogicalDelete` 调用不变。

## 7. 风险与注意事项

1. **`consumeJoinAlias` 边界覆盖**：已包含 ON/WHERE/GROUP/ORDER/LIMIT/LEFT/RIGHT/INNER/FULL/CROSS/JOIN，子查询别名后紧跟这些关键字时不会误消费。
2. **嵌套子查询**：`parseSubqueryTable` 使用 depth 计数器，正确处理 `(SELECT * FROM (SELECT ...) x)` 嵌套。
3. **rawOn 捕获**：`parseJoin` 中 `onStart` 从 ON 后首个 token 到条件解析结束，子查询不影响 ON token 区间。
4. **FROM 子查询别名**：`SqlReverseResult` 无 `fromAlias` 字段，别名嵌入 tableName 后生成器按 `entityClassName(tableName)` 推断实体名会不准确 — 但子查询场景下生成器走 raw join 路径（`isJoin=true`），不依赖 tableName 推断实体名，无影响。
5. **bundle 文案**：复用 `KEY_PARSE`（`reverse.error.parse` = "无法解析该SQL: {0}"），无需新增 key。
