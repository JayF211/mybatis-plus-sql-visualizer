# SQL→Java 多表 JOIN 支持开发计划（T-M37）

- 日期：2026-08-15
- 状态：**立项（需求已收集，排期待实施）**
- 前置：T-M36.1~T-M36.5 已交付（组/OR/降级/lambda/面板全链路，984 全绿）
- 背景来源：用户需求——「支持复杂的 SQL，例如多表连查等」；MPJ（MyBatis-Plus-Join）是多表 Wrapper 的官方形态（插件正向链路已全量支持 MPJ 转换与渲染）

## 1. 需求分析

现状：`SqlReverseParser` 对 JOIN 明确报错（"暂不支持的 SQL 结构：JOIN"）。目标：多表连查 SQL 反向生成 **MPJ 代码**（与插件正向 MPJ 支持对称），单表 SQL 行为不变（回落 QueryWrapper/LambdaQueryWrapper 家族）。

支持范围（P0）：
- `FROM 主表 [别名] LEFT|RIGHT|INNER|FULL [OUTER] JOIN 副表 [别名] ON 条件`，多 JOIN 链；
- ON 条件：单等值 `t1.a = t2.b`（→ MPJ 三参 leftJoin）、多条件/非等值（→ 字符串 raw join 透传）；
- WHERE 条件列带表别名（`t1.status = 1`）→ 按别名归属实体渲染 `Entity::getStatus`；无前缀列归属主表；
- SELECT 列带别名同样归属。

明确不支持（后续期）：子查询 JOIN、USING、NATURAL JOIN、UNION 多表、ON 内子查询。

## 2. 生成目标形态（对齐正向 MPJ 语义，实证）

```java
// 主表/副表实体都可用 → MPJLambdaWrapper
new MPJLambdaWrapper<DeviceInfoEntity>()
    .selectAll(DeviceInfoEntity.class)
    .leftJoin(AddressEntity.class, AddressEntity::getDeviceId, DeviceInfoEntity::getId)   // ON t1.device_id = t.id 单等值
    .eq(DeviceInfoEntity::getStatus, 1)
    .eq(AddressEntity::getCity, "北京");

// ON 多条件/非等值 → 字符串 raw join 透传（MPJ leftJoin(String, args) 形态）
.leftJoin("address t1 ON t1.device_id = t.id AND t1.type = 1")

// 主表实体缺失 → MPJQueryWrapper 字符串形态（主表类名推断 + 注释提醒）
new MPJQueryWrapper<>(DeviceInfoEntity.class)
    .selectAll(DeviceInfoEntity.class)
    .leftJoin("address t1 ON t1.device_id = t.id")
    .eq("t.status", 1)
```

形态强制规则：**多表 JOIN SQL 恒生成 MPJ 形态**（无视设置 reverseWrapperFormat——其他形态无法表达 JOIN；面板下拉对多表 SQL 显示提示，T-M36.6 §4）。

## 3. 技术方案

### 3.1 解析层（SqlReverseParser 扩展）

1. **列归属保留**：`parseColumnRef` 当前剥离表别名（`t1.status` → `status`）——改为保留 `ColumnRef.tableAlias`（单表场景生成器忽略前缀，行为不变；round-trip 反而更精确）；
2. **JOIN 子句解析**（主循环新增分支，`isClauseStart` 之外的 JOIN 关键字组）：
   - `[LEFT|RIGHT|INNER|FULL] [OUTER] JOIN 表[.库] [别名]` → 副表名（剥前缀/反引号，复用 parseTableName/consumeOptionalAlias）；
   - `ON` 条件列表：专用解析器——等值列对 `t1.a = t2.b` → `Condition.ColumnComparison`（现有模型！）；其余条件复用普通条件解析（值/IN/BETWEEN/LIKE）；结束边界：下一个 JOIN/WHERE/GROUP/ORDER/LIMIT；
3. **多 JOIN 链**：循环解析至 WHERE 或语句结束；
4. **模型**：`SqlReverseResult` 增加 `joins: List<ReverseJoin>`（type/tableName/alias/onConditions）；`ReverseJoin.type` 复用 `JoinType` 枚举（模型层已有）；
5. 单表 SQL 完全不变（joins 空 → 现有路径）。

### 3.2 实体层（EntityClassFinder 多表）

- 主表 + 每个副表按表名 `find()`（现有单表查找复用，循环调用）；别名 → 表 → 实体映射表；
- 多表候选交互：每表独立候选集——P0 简化：**只对主表做候选选择**（多候选弹 SqlSelectionDialog，T-M36.2 交互复用）；副表取第一个匹配（或缺失 → 字符串列回落）；完整多表候选选择列 P1。

### 3.3 生成层（JavaCodeGenerator MPJ 形态）

- `GeneratedWrapper.MPJ_LAMBDA` 扩展：joins 渲染（selectAll + leftJoin 链）+ 列渲染按归属实体（ColumnRef.tableAlias → 实体映射 → `Entity::getX`，映射缺失回落字符串列名 `"t1.city"`）；
- `GeneratedWrapper` 新增 `MPJ_QUERY`（主表实体缺失时的字符串形态：`MPJQueryWrapper<推断类名>` + selectAll + raw join + 字符串列）；
- 多表 + 设置非 MPJ 形态 → 按 3.2 判定后强制 MPJ 分发（converter 层，`SqlToJavaConverter.generateCode` 增加 joins 判断）。

### 3.4 round-trip 闭环

- 正向 `SqlGenerator` 已支持 `SelectStatement.joins`（JoinClause 渲染）——反向 parse JOIN → `ReverseJoin` → 重建 `SelectStatement(joins=...)` → 再渲染逐字符等价（复用 T-M36 round-trip 测试模式）；
- ON 单等值/多条件/多 JOIN 链各加闭环用例。

## 5. 边界与风险

- **ON 非等值条件**（`t1.a > t2.b`、函数）→ 字符串 raw join 透传（不解析为 ColumnComparison 以外形态）；
- **无前缀列归属**：多表 JOIN 中无前缀列按主表处理（SQL 语义歧义列本应报错，取保守归属）；
- **副表实体缺失**：该表列回落字符串列名（`"t1.city"` 保留别名前缀），生成代码可编译（MPJ 字符串列合法）；
- **主表实体缺失**：MPJQueryWrapper 字符串形态（类名推断）——仍可转换，注释提醒调整类名；
- 性能：JOIN 数通常 ≤5，多表实体查找为 5 次索引查询（后台 ReadAction，可接受）。
