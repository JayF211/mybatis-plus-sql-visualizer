# T-ReportL10n 报告需求池文案与 IDE 显示语言不一致 — 开发计划

- 日期：2026-09-14 14:06
- 来源：用户真机反馈（截图：IDE Internal Errors 界面全英文，「报告到 SQL Visualizer 需求池」菜单项为中文）
- 前置：T-FeedbackDlg / T-FeedbackDlg2（同一报告链路的语言问题，本轮是文案语言落点）

## 一、问题

IDE 界面语言已切英文（Internal Errors 对话框标题、按钮、隐私提示全英文），但本插件经
`errorHandler` EP 注入的菜单项「报告到 SQL Visualizer 需求池」仍显示中文，与周围平台
UI 语言割裂。用户语言设置为「跟随系统」（AUTO）时预期跟随 IDE 显示语言。

## 二、根因

`MpSqlVisualizerBundle`（M14 起自管理 ResourceBundle，语言独立于 IDE）的 AUTO 分支
落在 `Locale.getDefault()`——JVM 进程 locale。系统为中文时 JVM locale 恒为 zh，
而 IDE 显示语言由平台语言包决定（本机 243 实证 `DynamicBundle.getLocale()` →
`LocalizationUtil.getLocale()`），两者脱节：系统中文 + IDE 切英文 → 插件文案仍是中文。
`errorHandler` 提交器的 `getReportActionText()/getPrivacyNoticeText()` 经同一入口解析，
故菜单项中文、周围平台英文。

## 三、修复设计

`MpSqlVisualizerBundle`：

- AUTO 分支由 `Locale.getDefault()` 改为新增 `internal fun ideDisplayLocale(): Locale`
  = `runCatching { com.intellij.DynamicBundle.getLocale() }.getOrElse { Locale.getDefault() }`
  ——平台入口返回 IDE 实际显示语言；测试/headless 平台不可用时回退 JVM locale（与旧行为一致）。
- `zh`/`en` 显式选择行为不变；`getFallbackLocale=null` 防回退链语义不变。
- 插件自己的对话框（ErrorReportDialog 等）继续走插件语言设置（原语义），仅 AUTO 的
  语言落点变精确——所有经 AUTO 解析的文案一并受益，不只是提交器两处。

API 核实（铁律：本地 jar 反编译唯一权威）：

| 入口 | 243 | 262 |
|------|-----|-----|
| `DynamicBundle.getLocale()` | util-8.jar `public static Locale getLocale()`（javap） | intellij.platform.core.jar 同签名（javap） |

243 字节码进一步证实内部委托 `LocalizationUtil.INSTANCE.getLocale()`（IDE 显示语言，
非 JVM locale）。

## 四、验收

- 新增 `MpSqlVisualizerBundleLocaleTest` 2 例：`ideDisplayLocale` 永不抛异常且返回有效
  Locale（平台/回退两路径）；测试环境无设置服务时文案兜底中文可解析。
- 全量裸命令 test 绿即门禁（verifyFull/buildPlugin 按用户口径跳过）。

## 五、真机走查清单（留人工）

1. 语言设置=跟随系统 + IDE 英文：Internal Errors 菜单项、隐私提示显示英文。
2. 同环境把 IDE 切回中文：菜单项恢复中文（DynamicBundle locale 随语言包动态变化）。
3. 语言设置=中文/英文显式选择：行为与改前一致（不受 IDE 语言影响）。
4. 「报告到需求池」对话框自身文案仍随插件语言设置（本轮未动）。
