# 设置导入/导出反馈弹框被设置弹窗遮挡 修复 开发计划

> 现象：设置弹框（Settings 对话框）内点「导入/导出」，结果反馈用 `Messages.showInfoMessage(rootPanel, ...)` 模态弹窗，父组件是设置页内部面板——弹窗居中于**设置弹窗内部**（Z 序在其下/被其遮住），必须先关掉设置才能看到结果，无法确认是否成功。
> 用户要求：先制定开发计划文件，再实施修复。
> 工作目录：dev worktree；并行登记沿用 `master-to-dev-merge / mpsv-master2dev`。

## 一、根因定位

`PluginSettingsPanel.kt` 两处（T-Perf-14 移后台改造时保留的旧反馈形态）：

| 位置 | 现状 | 问题 |
|------|------|------|
| `importSettings()`（L1227~1255） | 成功 `Messages.showInfoMessage(rootPanel, ...)`；失败 `Messages.showErrorDialog(rootPanel, ...)`，parent=rootPanel | 模态弹窗 parent 为设置页内嵌面板，IDEA Settings 是带层级对话框——弹窗叠在 Settings 窗口之下，关掉 Settings 才可见 |
| `exportSettings()`（L1260~1293） | 同上成功/失败两处 | 同上 |

关联背景：M54 T-Perf-20 已确立「报错露出降级」红线——用户操作类提示优先面板内行内警示，不打模态。本面板同文件已有现成先例：`cacheInfoLabel`（清缓存后行内反馈「已清空」）、`settings.buildNumber.copied`（复制按钮临时换文案 1.2s）。本修复对齐该模式。

## 二、方案决策

**方案 A（选定）：设置页内行内反馈 label（复用 cacheInfoLabel 模式）**
- 导入/导出按钮行右侧（或行下方）加 `statusLabel`：成功=绿/默认色，失败=红（`ErrorForeground`），随语言重建刷新。
- 优点：零模态、不遮挡、结果常驻可见（直到下次操作覆盖），对齐 T-Perf-20 红线与既有 UI 模式；实现小、无平台 API 风险。
- 失败信息含异常详情（截断 ~120 字符防溢出），tooltip 放完整信息。

**方案 B（弃）：Notification bubble**——弹 IDE 右下角通知，但 Settings 模态打开时通知滑出常被忽略，且通知中心噪音违反「弹窗克制」方向。
**方案 C（弃）：DialogWrapper parent=Settings 对话框**——需拿到 Settings 顶级窗口引用（层层向上遍历），仍属模态遮挡链，未治本。

时序说明：导入/导出的文件 IO 已在后台线程（T-Perf-14），仅反馈回 EDT 改写 label，无新增 EDT 重活。

注意事项：
- `rebuild()`（语言切换）会 `removeAll()+buildSections`，`statusLabel` 引用须重新赋值（对齐 `cacheInfoLabel` 现状——它就是重建时重新 add 的成员，label 实例随 rebuild 更新，成员引用同步刷新）。
- 单元测试模式：`importSettings` 的 FileChooser 在 headless 会弹本地对话框——测试绕过文件选择，直接拆出 `applyImportedText(text)` / `writeExportedFile(file)` 可测内部函数（文件选择与 IO 分离，顺带提升可测性）。
- `reset()` 在成功导入后调用会刷表单；`showStatus` 在 reset 之后调用防被覆盖。
