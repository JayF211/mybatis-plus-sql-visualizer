# 自研 DAO 字符串 SQL 预览与方法定义锚点贯通 开发计划

> 源自 2026-09-06 用户反馈（微信截图 7 张）：自研框架（`beanCruder` / `beanQuery`）的 Java 字符串拼接 SQL 调用行无 SQL 预览图标；`selectListPagination` 等 DAO 分层方法的**方法定义**处光标快捷键无法预览。

## 背景与现状

用户两段真实代码形态（截图对应）：

形态一（截图 1，业务方法内拼接 SQL 后交自研框架执行）：

```java
public List<ScheduleVO> getScheduleList(Long userId) {
    String sql = "SELECT " +
        " ROW_NUMBER() OVER (ORDER BY wp.PROC_NAME) as task_id, " +
        // …… 数十行字面量 + 拼接，含 UNION ALL、CASE WHEN、:CUR_USER 命名参数
        "GROUP BY " +
        " WP.PROC_DEF_KEY ";
    List<ScheduleVO> scheduleVOList =
        beanCruder.selectList(ScheduleVO.class, sql, "CUR_USER", userId);
    // ……
}
```

形态二（截图 2~7，DAO 分层委托链，光标停在方法定义名上）：


相关链路（已逐行核实）：

| 环节 | 代码位置 | 现状 |
|------|---------|------|
| JDBC 模板 gutter | `JdbcTemplateSqlGutterLineMarkerProvider.getLineMarkerInfo` | 方法名须 ∈ `JDBC_TEMPLATE_METHODS`（query 族/update/execute/delete/insert）；`selectList`/`selectListPagination` 不在 → 无图标 |
| 家族守卫 | `PreviewReceiverResolver.classify` | `beanCruder`/`beanQuery` 变量名无 Dao 后缀、类型不在 `JDBC_RECEIVER_TYPES` → `UNKNOWN` → 即使方法名命中也被 `!= JDBC_TEMPLATE` 守卫拒 |
| SQL 实参定位 | `JdbcTemplateSqlLocator.locateFromCall` | 只看**第 1 实参**；形态一第 1 参是 `ScheduleVO.class`（Class 字面量），`concat` 非 String 字面量返回 null → 定位失败 |
| 批量锚点冲突 | `WrapperAnchorDetector` 场景 D | `selectList` ∈ `batchOperationMethodNames`（SELECT 模板按 ids 集合消费），字符串 SQL 形态被批量转换器接住后**点击无法转换**（`BatchOperationConverter` 只认 Wrapper/集合实参） |
| 方法定义锚点 | 全部 11 个 gutter provider | 锚点形态全部是「调用表达式方法名 identifier」/注解/XML 标签；`PsiMethod.nameIdentifier` 无任何 provider 认领 → 无图标 |
| 快捷键 | `ConvertToSqlAction` fallback 链 | `JdbcTemplateSqlLocator.resolveCallExpression` 对方法定义元素向上找不到 `PsiMethodCallExpression` → 全链失败 → 文件级注解候选为空 → 弹「未找到」 |

## 根因

两层缺口，四个失败点：

1. **方法名白名单覆盖不足**：`JdbcTemplateMethodDetector.JDBC_TEMPLATE_METHODS` 只收 Spring JDBC 模板方法名，自研 DAO 层通用方法名（`selectList`、`selectListPagination` 等 select 族）不在集合，gutter 与快捷键共用该判定，同源双失效。
2. **SQL 实参位置假设过强**：定位器假设「首参即 SQL」。自研框架常见 `(Class beanClass, String sql, Object... params)` 形态，SQL 在第 2 参；Class 字面量首参在 `SqlStringConcatenator.concatLiteral` 处失败。
3. **家族守卫误伤**：自研框架接收者解析不出家族（`UNKNOWN`）即被拒。而 `isLikelySql`（`JdbcTemplateSqlPreviewService`）已有点击时防误伤校验，快速路径的家族守卫可以放宽到 UNKNOWN 兜底而不引入误预览。
4. **方法定义锚点完全缺失**：没有任何 provider/定位器认领 `PsiMethod.nameIdentifier` 形态；一个方法体内的字符串 SQL 调用（哪怕可静态聚合）也不会在方法名上提供入口。

## 目标

1. 形态一：`beanCruder.selectList(ScheduleVO.class, sql拼接变量, "CUR_USER", userId)` 调用行出现 SQL 预览图标，点击/快捷键弹出拼接展开后的完整 SQL（`:CUR_USER` 命名参数进参数面板）。
2. 形态二：`selectListPagination` 等方法的**方法定义**行出现预览图标（方法体内存在字符串 SQL 调用即标）；点击/快捷键预览方法体内 SQL 候选（0/1/多分发）。
3. 与批量操作锚点（场景 D）互斥去重：同一调用行只出一个图标，字符串 SQL 形态让字符串 SQL 路径接管。

## 已知边界（MVP 不做）

- **运行时构造 SQL 无法静态还原**（截图 2 执行层 `query.getQuery()` 形态）：SQL 文本在运行期才存在，静态聚合不可达。该形态点击返回「未找到」级提示。委托链中静态可见的部分（包装方法体内的调用行）由方法定义锚点提供图标入口。
- **跨方法参数流追踪不做**（包装方法形参 `sql` → 调用方实参 → 业务层字面量）：超出 PSI 单方法体分析边界，列为后续里程碑候选。
- Kotlin 文件不在本次范围（新 provider 仅注册 `language="JAVA"`）。

## 任务

### T-DaoSql-01 方法名白名单扩展（`JdbcTemplateMethodDetector`）

- 新增 `DAO_STRING_SQL_METHODS`：`selectList` / `selectOne` / `selectCount` / `selectPage` / `selectMaps` / `selectObjs` / `selectListPagination`（对齐 MP BaseMapper/IService select 族命名 + 用户场景 `selectListPagination`）。
- 新增判定入口 `isStringSqlMethodCandidate(name)` = `JDBC_TEMPLATE_METHODS ∪ DAO_STRING_SQL_METHODS`，供 gutter / 定位器 / action 统一换用（原 `isJdbcTemplateMethodReference` 保留委托，调用点全部切换）。
- 误标防线说明：select 族同时是 MP BaseMapper 方法名，但 MP 形态实参是 Wrapper/实体/集合（无字符串形态实参），被「存在字符串形态实参」守卫排除；`list.insert("x")` 类通用方法名调用由点击时 `isLikelySql` 拦截。

### T-DaoSql-02 SQL 实参定位泛化（`JdbcTemplateSqlLocator` + `PreviewReceiverResolver`）

- `PreviewReceiverResolver` 新增 `hasStringLikeArg(call)`：实参列表中**任一**实参为字符串形态（String 字面量 / `+` 拼接 / `toString()` 调用链 / resolve 为 String 的变量引用）；原 `isStringLikeFirstArg` 保留委托（语义 = 首参形态，兼容既有调用点）。
- `JdbcTemplateSqlLocator.locateFromCall`：`resolveSqlExpression(firstArg)` 改为扫描实参列表取**第一个字符串形态实参**（复用 `isStringLikeExpression` 逻辑提为内部共享函数）。JdbcTemplate 原生形态 SQL 就是首参，行为不变；`(Class, sql, ...)` 形态命中第 2 参。
- 方法名判定换 `isStringSqlMethodCandidate`。

### T-DaoSql-03 家族守卫 UNKNOWN 兜底与批量锚点让位（去重）

- `JdbcTemplateSqlGutterLineMarkerProvider`：家族守卫从「必须 JDBC_TEMPLATE」改为**排除制**——`CUSTOM_DAO` / `HIBERNATE_TEMPLATE` / `JPA_SESSION` 家族拒绝（各有专属 provider，防双图标），`JDBC_TEMPLATE` 与 `UNKNOWN` 通过；首参守卫换 `hasStringLikeArg`。
- `WrapperAnchorDetector` 场景 D 增加让位守卫：批量白名单命中且 `hasStringLikeArg(call)` 为 true → 返回 null（字符串 SQL 形态交由字符串 SQL provider 接管，避免同行双图标/点击无法转换）。守卫位置在批量白名单命中**之后**，普通标识符负例仍零成本；`hasStringLikeArg` 中变量引用形态做一次 resolve，与既有 `selectAll` 撞名守卫同量级（红线语义：负例零 resolve 不变）。
- 点击时防线：`JdbcTemplateSqlPreviewService.isLikelySql` 已有（非 SQL 字符串返回 null），无需新增。

### T-DaoSql-04 方法定义锚点（新 provider `StringSqlMethodGutterLineMarkerProvider`）

- 新文件 `ui/gutter/StringSqlMethodGutterLineMarkerProvider.kt`，注册 `language="JAVA"`。
- 锚点：`element is PsiIdentifier && element.parent is PsiMethod && method.nameIdentifier === element`。
- daemon 快速路径判定（性能论证）：方法体非空且 `body.textLength <= 200_000`（极端大方法护栏）时，`PsiTreeUtil.collectElementsOfType(body, PsiMethodCallExpression)` 过滤「方法名 ∈ `isStringSqlMethodCandidate` 且 `hasStringLikeArg`」存在即标。成本 = 每方法仅 nameIdentifier 一个 leaf 触发一次、限方法体子树纯结构遍历（零 resolve 遍历主路径；`hasStringLikeArg` 仅对白名单命中调用生效）、无索引访问，与 M54「daemon resolve 风暴」（引用解析走索引）不同量级；真机验证项见 T-DaoSql-06。
- 点击 handler：`SqlPreviewService.previewAsync` 后台 ReadAction 内收集方法体候选（白名单调用 → `JdbcTemplateSqlLocator.locateFromCall` 成功者），0 → `showResult(null)`；1 → `JdbcTemplateSqlPreviewService.preview(call, anchor)`；多 → `SqlSelectionDialog` 0/1/多分发（候选摘要 = 调用方法名 + 行文本，对齐既有交互）。
- 候选收集逻辑放 `JdbcTemplateSqlPreviewService.collectMethodCandidates(method): List<Call>`（gutter 点击与 action fallback 共用单一来源）。

### T-DaoSql-05 快捷键贯通（`ConvertToSqlAction`）

- fallback 链在 `tryJpaFallback` 之后、文件级注解候选之前新增 `tryMethodBodyStringSqlFallback`：`PsiTreeUtil.getParentOfType(element, PsiMethod)` → `collectMethodCandidates` → 0/1/多分发（与 T-DaoSql-04 点击共用）。
- 覆盖两类光标：方法定义 nameIdentifier 上（形态二主诉求）；方法体内任意非调用处（局部优先于文件级注解候选，行为变化记录到交付说明）。
- 调用处光标（形态一）经现有 `tryJdbcTemplateFallback` 自动生效（T-DaoSql-01/02 后 `locate` 能命中）。

## 影响面

- 新增 1 个 gutter provider（plugin.xml +1 行）+ i18n 4 个 key（中英）。
- `JdbcTemplateMethodDetector` / `JdbcTemplateSqlLocator` / `PreviewReceiverResolver` / `WrapperAnchorDetector` / `ConvertToSqlAction` 行为扩展，既有调用点语义向后兼容（首参字符串形态不变）。
- 批量锚点让位仅影响「批量方法名 + 字符串形态实参」的调用（该形态批量转换器本就无法转换，点击必失败），无既有能力回退。
- 方法体内快捷键优先级变化：方法体候选优先于文件级注解候选（语义更局部精确）。
