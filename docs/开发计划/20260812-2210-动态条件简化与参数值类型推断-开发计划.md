# 动态条件简化 + LIKE 百分号 + 字段类型推断——开发计划（M13，M12 微调）

> 本文档是 **MyBatis-Plus SQL Visualizer** 的 M13 增量微调计划（M12 交付后的三处调整）：
> ① **动态条件简化**——删除判空语义（StringUtil/isNotBlank/isNotNull 识别与静态求值），有布尔参数的条件下沉为「复选框纯手动勾选」；
> ② **LIKE 占位符自动拼百分号**——`like/likeLeft/likeRight` 的值输入框回填时按位置自动拼 `%`（`'%值%'` / `'%值'` / `'值%'`）；
> ③ **字段类型推断引号**——String 类型列输入数字时不再被识别为数值（恒加引号 `'123'`），由实体字段类型推断。
>
> 配套文档：[M12 开发计划](../开发计划/20260812-2107-动态条件复选框与空值跳过-开发计划.md)（本计划为其增量微调，M12 已交付 commit d367fb5）、[主开发计划](../开发计划/20260812-1058-MP-SQL可视化-开发计划.md)。
> 当前基线：Kotlin 2.3.20 + IntelliJ Platform Gradle Plugin 2.18.1 + IDEA 2025.3.5，v1.6（M12）已提交，测试全绿。

## 1. 概述与目标

**用户反馈（三处微调）**：

1. **动态条件判断太复杂**：不需要判断 `StringUtil.isNotBlank(name)` / `name != null` 这类判空方式——**只要首参是布尔参数，就展示一个复选框允许勾选即可**（用户已确认：**复选框纯手动**，空值不再联动勾选态）；
2. **LIKE 模糊查询没有自动拼百分号**：`like("name", name)` 这类带运行时值（占位符）的条件，回填后是 `name LIKE '张三'`，期望 `name LIKE '%张三%'`（`likeLeft` → `'%张三'`、`likeRight` → `'张三%'`，对齐字面量值的现有渲染）；
3. **String 类型列输入数字被识别成数值**：String 列（如 `name`）的值输入框填 `123` 时被 `NUMBER_REGEX` 启发式判定为数值 → 渲染 `name = 123`，期望 `name = '123'`——**通过实体字段类型推断**（`String`/`CharSequence` → 恒加引号）。

**期望的交互（简化后）**：

```
左栏（示意，右栏为 SQL 编辑器）：
┌──────────────────────────────┐
│  动态条件                      │
│  ☑ name = '张三'              │  ← .eq(true, "name", "张三")，无值框
│  ☐ station_id = '2'           │  ← .eq(false, "station_id", "2")，默认排除
│  ☑ name LIKE ?     [张三]      │  ← .like(flag, name, nameVar)，填值 → '%张三%'
│  ☑ name = ?        [123]      │  ← String 列：填数字 → '123'（恒引号）
│  ────────── 参数 ────────────  │
│  #deviceId         [ 1001 ]    │  ← 普通未解析参数（无布尔标志）
└──────────────────────────────┘
```

**交互规则（M13 定稿）**：
- 有布尔首参的条件 → 复选框，**默认勾选态**：字面量 `true` → 勾选、字面量 `false` → 不勾选、运行时布尔 → 勾选；
- 勾选/取消勾选 → 该条件拼接/移除（其余条件不受影响）；
- 值输入框空 → **保留 `?`，不联动勾选态**（删除 M12 的 SKIP_ON_BLANK 自动取消勾选与 SKIP_ON_NULL 空值拼 `''`）；
- LIKE 条件填值 → 按位置自动拼 `%`（恒加引号 + 单引号转义）；
- 类型已知的列填值 → String 恒引号、其余恒原样；类型未知 → 保留现有 `NUMBER_REGEX` 启发式。

**范围控制**：
- 仅触碰 M12 相关代码（模型/转换/生成/服务/UI），不改入口与展示方式（恒弹窗）；
- **生成 SQL 文本与 M12 基线逐字节一致**：类型推断与 LIKE 百分号发生在「面板回填阶段」（用户输入值），生成层只新增**回填提示**（hint），不改变 `?` 渲染；
- 批量操作路径（`previewModel=null`）无参数输入，不受影响；旧文本路径通过 `PreviewResult.paramHints` 透传享受同样的类型/LIKE 回填。

## 3. 方案设计

### 3.1 总体数据流（回填提示模型）

```
源码 Wrapper 链
   ▼
QueryWrapperParser（M13 简化：布尔首参 → toggle，无判空语义）
   ▼
SqlStatement（Condition 树，toggle 无 emptyRule；ColumnInfo.fieldType 可查）
   ▼
SqlGenerator.generateWithParams → GeneratedSql{ sql, unresolvedParams, paramHints }
   │  生成 SQL 时对每个 ? 同步产出 ParamHint（列类型 + LIKE 位置）
   ▼
SqlPreviewPanel.backfillParamsBySource(sql, sources, hints)
   ├─ hint.likePosition 非 null → 按位置拼 %，恒引号（'%张三%'）
   ├─ hint.quote == true   → 恒引号（'123'，String 列）
   ├─ hint.quote == false  → 原样（123，数值列）
   ├─ hint 缺失/quote==null → 保留现有 NUMBER_REGEX 启发式
   └─ 值空 → 一律保留 ?（复选框纯手动，不联动）
```

**新增回填提示**（`sql/ParamHint.kt`，与 `GeneratedSql` 同包）：

```kotlin
/**
 * 单个 `?` 的回填提示（M13）：与 GeneratedSql.unresolvedParams 并行，
 * 在生成时根据列类型与 LIKE 位置计算，供面板回填值渲染（引号 / 百分号）。
 *
 * @param quote        该值是否必须加引号：true=String 列恒引号；false=数值等列恒原样；
 *                     null=列类型未知（面板走现有 NUMBER_REGEX 启发式）
 * @param likePosition 非 null 表示该 ? 属于 LIKE 模式（恒引号，并按位置拼 %）
 */
data class ParamHint(
    val quote: Boolean? = null,
    val likePosition: LikePosition? = null,
)
```

`GeneratedSql` 增加 `val paramHints: List<ParamHint> = emptyList()`（默认空 → 旧调用零影响）。

### 3.2 模型层简化

- **删除 `EmptyValueRule` 枚举**与 `ConditionToggle.emptyRule`、`ConditionView.emptyRule`（`ConditionToggle.kt`/`SqlPreviewModel.kt`）；
- `ColumnInfo` 增加 `fieldType: String? = null`（`TableInfo.kt`）；
- `EntityResolver.resolveColumn()`：`fieldType = field.type.canonicalText`（Java/Kotlin 字段均可，解析失败为 null 兜底）。

### 3.3 转换层简化（判空语义删除）

`QueryWrapperParser`：
- 删除 `detectEmptyRule`、`evaluateCheck`、`NULL_CHECK_REGEX`、`BLANK_CHECK_REGEX`、`REVERSE_CHECK_REGEX`、`SINGLE_VALUE_METHODS`，以及 `FlagAnalysis.emptyRule`；
- `analyzeFlag()` 的 `defaultEnabled` 简化为：

```kotlin
val defaultEnabled = when (literalFlag) {
    "true" -> true
    "false" -> false
    else -> true   // 运行时布尔（isActive / StringUtils.isNotBlank(name) 等）默认勾选
}
```

- `bindToggle()`/`parseApply()`：不再传 `emptyRule`（`parseApply` 的 `defaultEnabled = flagSource != "false"` 保留）；
- **默认生成输出与 M12 基线逐字节一致**（`false` 条件仍进入模型、生成层默认排除）。

### 3.4 生成层：回填提示产出

`SqlGenerator` 内部为渲染线程化「列类型」与「hint 收集器」：

- `generateInternal` → 各语句渲染方法把 `statement.table` 传入条件渲染链，`paramSink` 旁新增 `hintSink: MutableList<ParamHint>?`（同一处同步 add，保证与 `unresolvedParams` 并行）；
- 列类型查询：`table.columns.firstOrNull { it.columnName == condition.column.columnName }?.fieldType`（联表 `tableAlias` 不影响 `columnName` 匹配）；
- String 判定 `isStringType(type: String?): Boolean?`：null → null；含 `String`/`CharSequence` → true；其余（数值/时间/布尔/枚举）→ false；
- `renderValue`（Simple/In/Between/update set 等）：占位符 → `hintSink?.add(ParamHint(quote = 列类型))`；
- `renderLike`：占位符 → `hintSink?.add(ParamHint(quote = true, likePosition = position))`（LIKE 模式恒为字符串，与列类型无关）；字面量值路径不变（已有 `%` 拼接）；
- **`?` 输出与 SQL 文本完全不变**，仅并行产出 hint → 既有 SQL 断言全部原样通过。

### 3.5 服务/UI 层

- `SqlPreviewService.buildPreviewResult`：`PreviewResult.paramHints = generated.paramHints`（旧文本路径回填用）；`toConditionViews` 删 `emptyRule` 参数；
- `SqlPreviewPanel`：
  - `showResult`：`enabledIds` 初值 = 各 view 的 `defaultEnabled`（删除 `skippedByBlank` 空值联动）；
  - `onConditionValueChanged`：只更新 `paramValues[source]` + `renderSql()`（**不再**自动改勾选态）；
  - `backfillParamsBySource(sql, sources, hints)`：空值一律保留 `?`（删除 `blankAsEmpty` 集合）；非空值按 hint 渲染（见 3.1）；
  - `conditionTooltip`：删除 `panel.condition.skipNull` 提示，保留 `flagSource` 展示；
  - bundle 删除 `panel.condition.skipNull`（中英文各一）。
- `model` 路径与旧文本路径统一走同一 `backfillParamsBySource`：模型路径传 `generated.paramHints`，旧文本路径传 `result.paramHints`。

### 3.6 交互规则汇总（与用户反馈逐条对齐）

| 用户反馈 | M13 规则 |
|------|------|
| ① 布尔参数判断太复杂 | 首参为布尔 → 复选框（`defaultEnabled`：true→勾选、false→不勾选、运行时布尔→勾选）；**删除** StringUtil/isNotBlank/isNotNull 判空语义识别、静态求值、空值联动 |
| ① 复选框纯手动 | 值输入框空 → 保留 `?` 不自动取消勾选；勾选态仅由用户操作决定 |
| ② LIKE 没拼百分号 | `like/notLike` → `'%值%'`；`likeLeft` → `'%值'`；`likeRight` → `'值%'`（恒引号 + `'` 转义 `''`），字面量值路径不变 |
| ③ String 列被识别成数值 | 实体字段类型 `String`/`CharSequence` → 值恒加引号（`'123'`）；数值等类型 → 恒原样（`123`）；类型未知 → 现有数字启发式 |
