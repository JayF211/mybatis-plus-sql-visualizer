# 全量 API 预览支持开发计划（M20~M22：MyBatis-Plus / MyBatis-Plus-Join 官方 API 全集预览）

> 本文档是 **MyBatis-Plus SQL Visualizer** 的**全量 API 覆盖计划**：目标是让插件对 **MyBatis-Plus（MP）与 MyBatis-Plus-Join（MPJ）官方 API 的全部调用形态都能预览 SQL**——现有《[MPJ 用法收集与兼容性测试清单](../需求文档/MPJ用法收集与兼容性测试清单.md)》§5.6 矩阵中的 🟡（部分支持）与 ⬜（暂不支持）项全部清零，或显式文档化边界（远期/外部依赖）。
>
> 计划依据：2026-08-13 对两库**官网 + GitHub 源码 + Maven jar 三重交叉调研**（MP 核实到 3.5.15 jar javap 与 v3.5.9/v3.5.17 tag 源码、官方文档；MPJ 核实到 master 源码逐类核对与 43 页官方文档、releases/tags），调研结论见 §1；与插件现有实现逐文件核对（文件:行号见 §2）。
>
> 当前基线：M19.5（310 测试全绿，2026-08-13）。本计划**吸收并替代**《[低频复杂 API 后期实现计划](./20260813-0829-低频复杂API后期实现计划.md)》§4 的 M20 建议排期：原 P2-01~07 并入本计划 M21，P3-01（UpdateJoinWrapper/DeleteJoinWrapper）提前至 M21，P3 其余并入 M22。
>
> 版本基线：MP **3.5.15**（真实项目）/ 最新 **3.5.17**（2026-07-08 发布）；MPJ **1.5.6**（真实项目）/ 最新 **1.5.9**。插件为 PSI 静态分析（不依赖用户工程 classpath），**按最新稳定版 API 方法名超集收录**——旧版本项目是子集自动兼容；API 版本标注仅用于文档与降级策略说明。

### 1.3 版本策略结论

1. **方法名超集收录**：以 MP 3.5.17 + MPJ 1.5.9 面为准收录全部方法名（PSI 层无法可靠获取用户依赖版本，且旧版本方法是新版本子集，天然兼容）。
2. **新旧双名同模板**：3.5.9 起 `selectByIds/deleteByIds` 与旧名 `selectBatchIds/deleteBatchIds` 并存，映射同一 SQL 模板。
3. **新版本独有 API**（`eqOrIsNull` 3.5.17、`selectWithCursor` 3.5.17、MPJ 1.5.2+ 子查询族等）：直接实现，低版本项目不会出现这些调用，无兼容风险。
4. **Kotlin 侧**（KtQueryWrapper/KtUpdateWrapper/ktQuery()/ktUpdate()/MPJ Kotlin 扩展）依赖 Kotlin PSI 基础设施，列为远期（P3-05 原判不变）。

1. 每个里程碑：`./gradlew clean test --no-build-cache` 全绿 + `./gradlew buildPlugin` 通过；

4. 性能红线不变：gutter 快速路径 O(1) 纯语法、不 resolve、不预计算（`WrapperAnchorDetector` 复用注册表集合，扩展集合时锚点自动生效，无需另改）；

## 5. 风险与注意

| # | 风险 | 应对 |
|---|------|------|
| 1 | MPJ 文档与源码不一致（fullJoin 文档称无独立方法，源码 18 重载） | 按源码支持，以 jar javap / tag 源码为准 |
| 2 | MP 3.5.17 包名变更传闻（extension→spring）存疑 | 实现时若遇类名/包名漂移，以 jar javap 复核为准；插件按方法名映射驱动，不硬编码版本 |
| 3 | `around` 的 SQL 渲染位置文档无示例 | T-M21-09 先对照 MPJ 源码 `getSqlAround()` 确认位置（ORDER BY 前后）再实现 |
| 4 | 子表 MConsumer join / from / fill 三者的子查询渲染与现有 selectCollection 子查询实现耦合 | 提炼公共子查询渲染抽象，避免三处各自实现 |
| 5 | T-M20-06 消费核对若发现锚点缺失（如 `selectObjs` 无 gutter 图标），根因可能位于 `WrapperAnchorDetector` 快速路径集合 | 扩展注册表集合时同步核对 `WrapperAnchorDetectorTest`，补锚点回归 |
| 6 | 消费方法名与链终结点名冲突（`update` 同时是消费与终结点；`page` 同时是 IService 方法与链终结点） | 沿用既有 `isServiceChainStart`/`consumingCall` 守卫（L446-452/L178-188），新方法加入时逐一核对守卫 |
| 7 | 批量族 `insertOrUpdate` 的 BiPredicate 重载与 `saveOrUpdate` 语义差异（MP 3.5.7+ 与 IService 两套） | 模板归一到 UPSERT，谓词参数忽略（静态不可求值），文档标注近似 |
