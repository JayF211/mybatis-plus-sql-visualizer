# SQL 日志与 SQL 历史两项缺陷修复 开发计划

> **创建日期**：2026-08-31 17:30
> **触发**：用户实测发现 SQL 日志面板与 SQL 历史面板各一处功能缺陷。
> **优先级**：高（用户日常高频使用面板，缺陷影响读图、计数准确性、文件正确性）。

## 二、根因分析

### 根因 A：耗时字段链路从未接上

链路（按数据流向）：

```
控制台一行输出
   │ LogFilterProxyHandler { line -> ... }
   │   ├─ myBatisParser.feed(line)
   │   │       └─ 生成 LogSqlEntry(rawSql, restoredSql, params, source=MYBATIS)
   │   │            executionTimeMs ← 从未赋值！
   │   ├─ hibernateParser.feed(line)
   │   └─ jdbcParser.feed(line)
   │
   ▼
   taken.forEach { entry -> buffer.addEntry(entry.copy(sourceFile, sourceLine)) }
                                                         ↑ 仅补此两项
```

**结论**：`ExecutionTimeParser`（`src/main/kotlin/.../log/ExecutionTimeParser.kt`）已完整支持 p6spy/MP TimeCount/自定义前缀等格式，但**生产链路从未调用它**——`LogSqlEntry.executionTimeMs` 始终为 `null`，列表显示无耗时、历史文件记 `—`。

### 根因 B：M46 重构后 cellRenderer 完全退化为纯文本

`SqlLogPanel.kt:670-699` 当前 cellRenderer：
```kotlin
list.cellRenderer = object : javax.swing.DefaultListCellRenderer() {
    ...
    this.text = "$timestamp$duration${entry.summary}$dedupeBadge"
    ...
    foreground = durationColor(entry.executionTimeMs, isSelected)
}
```

**M46 注释**：移除 HTML 标签，消除 Swing HTML 引擎开销 + EDT 上的 SQL 词法分析。

**取舍**：性能换可读性。本次回滚只渲染层（不影响其他子系统），仍走 Swing `setText("<html>...")`，但 SQL 高亮渲染走 `SqlListHtmlRenderer`（已有 `render(sql, scheme)` 接口，按 IDE 主题取色）。

**复用**：`SqlListHtmlRenderer`（`src/main/kotlin/.../log/SqlListHtmlRenderer.kt`）正是为此场景设计，文件名虽带 `Html` 但 `render()` 输出 HTML 片段，可直接喂 Swing `JLabel.setText`。

### 根因 C：去重开启/关闭动作不对称

```kotlin
// 当前实现（SqlLogPanel.kt:144-153）
addActionListener {
    val wasEnabled = manager.entries.dedupeEnabled
    manager.entries.dedupeEnabled = isSelected
    if (!wasEnabled && isSelected) {
        manager.entries.resetDedupeCounts()   // 仅清计数
        refreshList()                          // 不去重既有条目！
    }
}
```

**修复方向**：
1. `SqlLogEntryBuffer.dedupeExisting()` —— 开启后对既有 `entries` 按 `dedupeWindowMs` 时间窗裁剪（同 SQL 留首条去后条，超窗保留全部）并把多余的丢弃数累加到 `dedupeCounts`——保证徽章累积数据连续
2. `SqlLogPanel` 调用后 `refreshList()` 触发渲染
3. 关闭去重时也清空 `dedupeCounts`（语义：关闭 = 「不累计本次丢弃」）

### 根因 D：去重丢弃未通知 UI

```kotlin
// SqlLogEntryBuffer.kt:51-67 addEntry
if (dedupeEnabled && isDuplicate(entry)) {
    dedupeCounts.merge(entry.restoredSql, 1, Int::plus)
    return false  // ← 此处未 notifyChanged()，徽章显示延后一拍
}
```

`SqlLogEntryBufferTest` 现有两条断言强制该行为（`去重窗口内相同 SQL 丢弃且不通知` / `去重丢弃不触发监听器`）。修复时**同步更新这两个用例**为「返回 + 通知」。

### 根因 E：SQL 注释三个 `-`

`SqlLogAutoSaver.kt:129`：
```kotlin
w.write("--- source: $source | time: $duration | $timestamp ---\n")
```

实际该行为 SQL 单行注释 `-- ... --`，多一划变 `-- -..-` 仍会被多数 SQL 引擎视为整行注释（多数 SQL 方言要求 `--` 后跟空格、且整行结束），但视觉上不一致，且更严格的 SQL 方言可能整行注释失败。
**修复**：起结改回 `--`。`SqlLogFileReader.NEW_HEADER_REGEX` 已写为 `^--- source:` 起结，要兼容历史 `-- source:` 文件，正则改为 `^--(-?) source:` / `(?^(-?)$`（接受 2 或 3 个 `-`），保证向后兼容。

## 三、目标与非目标

### 3.1 目标

1. SQL 日志列表：恢复 SQL 词法高亮（关键字/表名/字符串/数字/注释分色），显示 `ms` 耗时。
2. SQL 日志去重：勾选「移除重复的sql」后，缓冲现有重复条目立即合并；丢弃计数实时更新（不需等下一条 SQL）。
3. SQL 历史列表：恢复 SQL 词法高亮，显示 `ms` 耗时（读自历史文件头 `time: xxxms`）。
4. SQL 历史文件：从本计划起，新写入文件头部注释为 `--`（两个 `-`）格式；旧文件仍能读取。
5. 测试同步：现有去重「不通知」两条断言改为「返回 + 通知」；新增 SQL 注释三处回归（写入端 + 读取端兼容 + 历史列表耗时展示）。

### 3.2 非目标

- 不重构 buffer 的并发模型（现有 synchronized + ConcurrentHashMap 已稳定）。
- 不动 `LogDurationParser` 的 p6spy/druid 解析逻辑——已通过 `LogDurationParserTest`。
- 不实现 Swing HTML 的「仅 SQL 摘要着色、其余纯文本」混合（要么全 HTML 要么全文本；本次全 HTML，因为同一 cellRenderer 已经能跑）。

    if (paused) { notifyChangedOnce(); return false }  // ← 新增：暂停态也通知（让 UI 感知状态变化）
    if (isFiltered(entry.restoredSql)) return false

**b)** 新增 `dedupeExisting()`

```kotlin
/**
 * 手动触发去重裁剪（用户勾选「移除重复的sql」时）：
 * - 扫描现有 entries，时间窗内相同 SQL 保留最早一条、丢弃后续
 * - 丢弃数累加到 dedupeCounts（与运行时去重共享计数）
 * - 返回本次去重移除的条目数（面板日志展示 / 测试断言）
 */
fun dedupeExisting(): Int {
    if (!dedupeEnabled) return 0
    var removed = 0
    synchronized(entries) {
        val keep = mutableListOf<LogSqlEntry>()
        for (entry in entries) {
            val duplicate = keep.firstOrNull { it.restoredSql == entry.restoredSql
                && kotlin.math.abs(entry.timestamp - it.timestamp) < dedupeWindowMs }
            if (duplicate != null) {
                dedupeCounts.merge(entry.restoredSql, 1, Int::plus)
                removed++
            } else {
                keep += entry
            }
        }
        entries.clear()
        entries.addAll(keep)
    }
    if (removed > 0) notifyChanged()
    return removed
}

/**
 * 关闭去重时清空累计计数（语义：「关闭」=清零；再次开启从零起算）。
 */
fun disableDedupe() {
    if (dedupeEnabled) {
        dedupeEnabled = false
        val hadCounts = dedupeCounts.isNotEmpty()
        resetDedupeCounts()
        if (hadCounts) notifyChanged()
    }
}
```

**c)** `clear()` 内追加 `notifyChanged()` 已经在；保留不变。

## 七、风险与回退

| 风险 | 缓解 |
|------|------|
