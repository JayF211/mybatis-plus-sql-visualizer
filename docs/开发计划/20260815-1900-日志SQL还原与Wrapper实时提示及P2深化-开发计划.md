### 2.1 需求（交互设计，参考 MybatisCodeHelperPro「MyBatis Log 面板」）

用户实测参考：MybatisCodeHelperPro 的日志面板「经常使用、非常不错」。其交互要点：
- 独立**工具窗口面板**（可停靠），运行项目时**自动监听**控制台 MyBatis 日志输出；
- 解析 `Preparing:` / `Parameters:` 行并合并为**可执行 SQL 条目列表**；
- 点击条目还原完整 SQL（占位符替换为真实参数）；
- 支持**控制台选中日志 → 右键还原**（Restore SQL）入口；
- 还原出的 SQL 可直接执行。

本项目差异化（免费 + 复用现有弹窗能力）：

1. **工具窗口「MyBatis SQL Log」**（右侧/底部可停靠）：
   - 自动监听本项目控制台输出，解析日志 → 条目列表（每行展示还原 SQL 单行摘要 + 表名/耗时可选）；
   - 双击条目 → 打开**现有 SQL 预览弹窗**（SQL 高亮 / 格式化 / 复制 / 执行 / 补全全部复用，零新 UI）；
   - 面板工具栏：清空 / 暂停监听 / 保留条数上限；
   - 条目可复制、删除单条。
2. **控制台右键还原**（MybatisCodeHelperPro 同款）：控制台选中 `Preparing`/`Parameters` 文本 → 右键「Restore SQL」→ 打开预览弹窗。
3. **日志格式**：MP 前缀格式（`==>  Preparing:` / `==> Parameters:`）与 MyBatis 原生格式（`Preparing:` / `Parameters:`）自动识别；支持多条 Parameters 行配对（批量/foreach 场景多条 Preparing）。
4. **参数还原规则**（复用 `ParameterReplacer` 引号判定经验，日志场景类型信息更精确）：
   - `(String)`/`(Timestamp)`/`(Date)`/`(LocalDateTime)` 等 → 引号包裹 + 内部 `'` 转义为 `''`；
   - `(Long)`/`(Integer)`/`(Boolean)`/`(BigDecimal)` 等 → 原样；
   - `null` → `NULL`；
   - 无类型标注兜底：数字字面量启发式（复用现有引号推断）。
5. **设置项**（PluginSettings）：监听开关、格式自动识别/强制指定、过滤关键字（如排除 `from_dual`）、保留条数上限（默认 200）、双击行为（打开弹窗/直接复制）。

### 2.2 现状盘点（已核实）

- **弹窗复用零成本**：`SqlPreviewDialog(project, PreviewResult)` 直接可构造（`ui/SqlPreviewDialog.kt:21`），`PreviewResult(sql, compactSql, ...)` 为纯数据类——日志还原只需构造 PreviewResult 即可获得高亮/格式化/复制/执行/补全全套能力（`SqlPreviewService.showResult` 同链路）。
- **无 ToolWindow 经验**：项目此前全部为弹窗 + gutter + 设置页形态，本次首次引入 ToolWindowFactory EP（平台稳定 API，需 243 沙盒试编译核实）。
- **无 ConsoleView 监听经验**：ConsoleView `addMessageFilter` 拦截输出行是 MyBatis Log 系通用做法（输出经 console 渲染时逐行回调，可同时捕获 stdout 日志）。
- **执行 SQL 链路已有**：`execute/` 包 + `database/` 包（反射隔离，Ultimate + Database 插件），弹窗「执行 SQL」按钮已接线。

### 2.3 技术方案

1. **监听**：`ConsoleView.addMessageFilter`（project 级挂载：监听 Run 控制台输出行；随 console 关闭自动卸载）。消息过滤器中解析行文本，匹配 `Preparing` / `Parameters` 正则（MP 前缀 `==>` 可选）。备选方案（面板空闲时扫描 console 全文）作为兜底。
2. **解析与配对**：新 `log/` 包：
   - `MyBatisLogParser`：正则识别 `Preparing:`/`Parameters:`（含 `<==`、`Columns:`、`Total:` 噪声行过滤）；Preparing 行开启新条目，Parameters 行（可多条）追加到当前条目；
   - 还原：参数元组 `值(类型)` 解析 → 类型→引号规则表（见 2.1-4）→ 逐 `?` 替换；字符串转义 `'` → `''`；
   - 条目模型 `LogSqlEntry(sql 原文, 还原 SQL, 时间戳, 摘要)`。
3. **面板**：ToolWindowFactory EP（plugin.xml 注册 + `com.intellij.openapi.wm.ToolWindowFactory`）→ JBList 条目列表 + 工具栏（清空/暂停/条数）；双击构造 PreviewResult → `SqlPreviewDialog` 打开。
4. **右键还原**（二期，优先级低于面板自动监听）：控制台为特殊非文件 Editor（项目已有教训：非文件编辑器 DataContext 处理有坑，见 UiCompatibleDataProvider 适配）——经 ConsoleView 的右键菜单（`EditorPopupMenu` EP + 判定 console 编辑器）实现；首期可在面板工具栏提供「从控制台选中文本还原」按钮兜底。
5. **测试**：解析/还原纯逻辑单测为主（fixture：MP 格式 / 原生格式 / 批量多 Parameters / 类型引号规则 / 转义）；面板与监听做轻量 headless 验证（ToolWindow 不布局，仅条目模型与事件分发断言）。

## 3. T-M32 Wrapper 链实时提示（P1 二期）

### 3.1 需求

把「按需触发」变为「无处不在」——编辑器内实时反馈 wrapper 链问题，提升存在感与留存：

1. **Inspection（LocalInspectionTool，Java）**，逐项：
   - a. **字段引用错误**：`Entity::getXxx` / `eq("xxx")` 引用的字段在实体中不存在 → Error 标红 + quickfix「预览 SQL」（打开现有弹窗，复用 `SqlPreviewService.showResult`）；
   - b. **UPDATE/DELETE 无 WHERE** → Warning（复用 `SqlPreviewService` 现有警示判定逻辑）；
   - c. **值类型与字段类型明显不匹配**（如 String 列 `eq(100)` 数字字面量）→ Warning（复用引号推断的类型判定）；
   - d. **链未消费**（wrapper 构造后无消费调用：`.list()/.one()/.update()/...`）→ WeakWarning。
2. **Inlay hint**：wrapper 链消费行尾内联提示 SQL 摘要（表名 + 条件数，如 `⚡ device_info WHERE id=? · 3 条件`），hover 显示完整 SQL；性能红线：仅链尾行计算，文档变更节流（debounce），复用 WrapperCache。

### 3.2 现状盘点

- `WrapperLocator`（约 950 行）已有全链定位 + 消费语义识别；`EntityResolver` 已有字段→列、字段类型；引号推断已有类型判定逻辑——inspection 三项判定全部可复用现有能力，新增成本集中在「标红 + quickfix 接线」。
- **无 Inspection / Inlay 经验**：`LocalInspectionTool` 与 `InlayModel` 为平台稳定 API（243 存在性需试编译核实——同 T-M30 的逐类核对流程）。
- **性能红线**（项目既有约定）：gutter 快速路径 O(1) 纯语法不 resolve——inlay 计算必须走「锚点检测快速路径」（`WrapperAnchorDetector` 已有），不可对全文件做 WrapperLocator 全量定位。

### 3.3 技术方案

1. Inspection 先行（增量扫描无性能压力）：新增 `inspections/` 包，`LocalInspectionTool` 注册（plugin.xml `<localInspection>`）→ 对 PsiMethodCallExpression 走锚点快速判定 → 命中 wrapper 链才做完整判定（a/b/c/d）→ 注册 quickfix（打开预览弹窗）。
2. Inlay 二期：文档变更 debounce（500ms）→ 变更行附近找消费锚点 → 仅对锚点行做一次 `WrapperLocator.locate` + 轻量渲染（表名 + 条件数，不跑完整 SQL 生成）→ `InlayModel.addInlineElement`；hover 用 `InlayHoverRenderer` 显示完整 SQL（复用 preview 全量渲染，仅 hover 时触发）。
3. 测试：inspection fixture（错误字段标红断言、无 WHERE 警示、quickfix 打开弹窗）；inlay 变更节流行为测试（headless 下 inlay 模型断言）。

### 3.4 验收标准

- [ ] 错误字段标红 + quickfix 打开预览弹窗；无 WHERE / 类型不匹配 / 未消费三类告警分级正确
- [ ] inlay 摘要显示且 hover 出完整 SQL；大文件文档变更不卡顿（节流生效）
- [ ] 全量测试回归绿；性能：锚点快速路径不破坏 O(1) 红线（inlay 仅锚点行计算）

## 4. T-M33 拦截器模拟（P2，P-立项-02 提升）

### 4.1 需求与方案

按《剩余立项开发计划》P-立项-02 实施（`docs/开发计划/20260814-0804-剩余立项-开发计划.md`），优先级从 P2 待定提升为**立即实施**：

1. **TenantLineInnerInterceptor**：设置页「拦截器模拟」配置组（开关 + 租户列名默认 `tenant_id`）→ 中央注入（仿 `injectLogicDeleteCondition`/`injectOptimisticLockCondition`）：SELECT/UPDATE/DELETE 条件追加 `tenant_id = ?`；INSERT 列清单补 `tenant_id`；
2. **DataPermissionInterceptor**（3.5.9+）：handler 注入片段静态不可得 → 追加可读占位条件（`AND <数据权限片段: 运行时注入>`），文档化近似；
3. **DynamicTableNameInnerInterceptor / setTableName(Function)**：表名函数静态不可求值 → 预览表名标注占位提示（与 T-M21-09 no-op 策略一致）；
4. **@KeySequence**：Oracle/PG 序列取主键 → INSERT 主键列渲染 `序列.NEXTVAL` 占位（设置页可配序列名格式，默认 `SEQ_表名`）；
5. **@InterceptorIgnore**：mapper 方法级注解命中成员则跳过对应注入（与定位消费方法 PsiMethod 的既有能力联动）。

**依赖**：`PluginSettings` + `PluginSettingsPanel` 配置面扩展（模拟开关与参数，沿用既有持久化与中英文 bundle）。

**难点**：拦截器组合注入顺序与去重（tenant + logicDelete + version 三层）；@InterceptorIgnore 的 PSI 定位成本。

### 4.2 验收标准（沿用 P-立项-02）

- 6.2 涉及 Database 结果集 API（反射隔离 + 表格 UI），工作量大，排 6.1 之后单独评估。
