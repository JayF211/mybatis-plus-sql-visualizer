## 一、目标与范围

将 SQL Visualizer 从“代码/日志转 SQL”进一步扩展为“解释 SQL、理解数据关系、验证预览、诊断实际运行”的 IDE 工具。

三条交付主线：

1. 预览洞察：当前 SQL 的逻辑结构、读写对象、结果字段来源、渲染解释和参数场景比较。
2. 运行洞察：独立执行事件、工作负载画像、预览与真实执行对照、请求 SQL 时间轴和重复查询证据。
3. 验证闭环：SQL 数量/结构/性能预算、元数据差异、计划对比、影响分析与场景回归包。

首期不建设分布式后端、不默认上传 SQL、不做全方法剖析、不承诺任意 SQL 的完整血缘。不为图形化提高最低 IDE 版本，不要求使用者安装 Database/Diagram/JCEF 才能看到核心结果。

## 四、设计约束

### 4.1 静态分析事实模型

以下为概念设计，名称可在实施时调整，不是现有 API：

- `AnalysisSnapshot`：SQL 文本/哈希、语句顺序、方言、参数场景、源码与修改版本、数据库上下文、元数据版本。
- `SqlSemanticModel`：语句作用域、表/列引用、逻辑步骤、读写角色、表达式、输出字段、诊断。
- `SemanticEdge`：边种类、起终点、来源 SQL 范围、解析证据和完整性。
- `AnalysisQuality`：确定、条件式、部分支持、歧义、未知；同时给机器可读原因和用户说明。

边种类至少分开：读取、写入/赋值、删除、JOIN 匹配、过滤、分组/排序影响、直接值来源、表达式派生。过滤与匹配依赖默认折叠，按需查看，不能混成值来源线。

对象身份包含数据库上下文、catalog/schema、按方言处理的引号与大小写、作用域和别名。未绑定数据库时使用明确的未解析上下文，不能与某个真实库自动合并。`schema1.t` 与 `schema2.t`、自连接两别名、同名 CTE 与基表必须独立。

同一模型服务说明、树表与图形，避免三套语义各算一遍。解析/布局在后台执行，可取消；缓存键包括方言、元数据版本和场景，而不仅 SQL 指纹。

### 4.2 运行事件事实模型

新增独立分析通道，保留已有日志阅读行为：

```text
全局停采、隐私与排除策略
  └─ agent 的真实执行观测（保留执行身份）
      ├─ 分析事件通道：质量检查 → 有界存储/聚合 → 画像/时间轴
      └─ 现有日志通道：展示去重/融合 → 列表/历史
```

分析通道不是无限保存的原始敏感数据仓库。首期仅显式启用后记录，默认使用参数化文本/脱敏摘要；列表清空和分析会话清空的语义独立且可见。

执行事件最少包含：

| 字段组 | 语义要求 |
|---|---|
| 身份 | 进程启动 UUID/会话身份、执行 ID、单调事件序号；PID 复用不碰撞 |
| 时间 | 开始墙钟、单进程单调时间基准、持续纳秒；保留来源与精度 |
| 上下文 | 线程 ID/名称、已证实的请求/trace/span/父 span、可选连接/事务身份 |
| SQL | 参数化文本/结构指纹、参数采集与脱敏状态、调用来源、数据库逻辑身份 |
| 结果 | SUCCESS/ERROR/UNKNOWN、错误类别、可用的 SQLState、DML 计数及已知/部分/未知 |
| 质量 | 采样、主动排除、队列溢出、编码失败、传输缺口、截断、能力缺失 |

请求根/结束、能力协商和质量快照需要非 SQL 事件；没有 SQL 的请求也能正确闭合。协议采用版本/能力协商，字段可选，新旧端兼容策略先通过测试再实施；旧端进入“仅 SQL 观测”模式，不伪造 request/span。

**完整性终结契约**：事件序号和心跳只证明已收到的部分，不能发现“最后一条 SQL 丢失后进程退出”。请求结束/会话关闭须携带终态生成计数或最后水位，以及涵盖该范围的丢弃/采样/能力摘要；该控制状态不能仅依赖可能已满的 SQL 队列。接收端允许结束先到，按有界乱序窗口收敛；水位、计数、质量或覆盖任一缺失时为 INCONCLUSIVE。终态消息也可能丢失，不承诺可靠送达；超时、异常退出和突然卸载均关闭为不完整。只在声明支持的覆盖范围内判定完整，不把“零收到”直接当“零执行”。

执行 ID 在可计数的投递点之前产生，使队列丢失可发现。代理/织入对同一 execute 使用共享调用令牌或明确主通道；不能用文本+毫秒窗口代替身份。控制台事件先保留为降级观测，不与 agent 简单求和；只有确定同一执行才能合并，分析指标显示当前来源覆盖。

连接 URL 必须先剔除凭据，数据库显示名不是稳定身份。不同进程的单调时钟不能直接比较；跨进程只用可解释的墙钟/父子信息与偏差提示，不生成虚假的严格顺序。

### 4.3 统计口径

- SQL 次数按执行实例计；批处理区分一次 executeBatch、批项数和已知影响行数。
- `Σ JDBC duration` 是累计客户端调用耗时，不是请求总耗时，也不是数据库 CPU 时间。
- 同请求并行 SQL 的区间并集可表示“至少一个 JDBC 调用活跃的墙钟时间”；请求根未完整捕获时不提供 SQL 占请求比例。
- 分位数带样本数、范围、采样/截断说明；极小样本不营造稳定性。
- 查询结果行数、ResultSet 读取耗时、连接池等待与数据库服务端耗时分别建模，首期未采集即未知。
- SQL 执行成功与事务提交成功分开。DELETE 不生成“值写入血缘”；UPDATE 修改值来源与 WHERE 行选择分开。
- 同模板次数只能支持“重复/疑似 N+1”；证明 N+1 需要更充分的请求内模式与调用证据。

### 4.4 分析会话生命周期

分析会话使用独立 generation；进程身份、执行序号与会话 generation 不混用。每次订阅/关闭/清空建立明确接收边界，先于清空产生的旧消息不得补回新会话；不能仅按 IDE 收到消息的墙钟判定。

| 操作 | 原始分析事件/聚合 | 在途请求与旧消息 | 已有历史 |
|---|---|---|---|
| 停止分析采集 | 停止新增，已有结果保留供看；仍遵循保留期限 | 在边界截断，未闭合请求标不完整；停采确认前后按generation/水位过滤 | 不自动删除 |
| 清空分析会话 | 删除该会话内存事件与聚合，推进generation | 旧消息拒收；跨边界请求标截断，不冒充完整新请求 | 默认不删已显式保存的快照，删除须单独操作 |
| 清空普通SQL日志 | 沿用现有列表语义 | 不暗中重置分析会话；界面明确二者区别 | 沿用现有历史规则 |
| 重新开启分析 | 新会话/新generation，不续接旧统计 | 握手确认新边界，旧在途消息不得回填 | 旧快照仍独立可读 |
| 关闭项目/卸载 | 停止新增，释放内存与任务 | 尽力通知agent停发；无终态时标不完整，安全降级 | 仅保留显式保存/约定TTL内快照，不隐式持久化原始敏感流 |

停止采集不等于删除已有数据，关闭功能也不应悄悄抹掉用户保存的证据。导出与保存的保留策略必须在界面说明；清理分析数据不改写日志历史。

### 4.5 交互与平台

复用现有完整预览，在“更多”中提供可见的“分析”文字入口；分析内容按需挂载，不新增一排日志根页签。节点联动 SQL 范围、详情解释与源码导航；大图可打开编辑器，窄侧栏保留树表模式。

- W22 IDE 分流与统计：在展示去重前建立分析通道；停采、隐私、排除规则仍生效；不依赖自动存档无界队列。

- W24 预览—执行候选：先人工选择当前预览与运行样本，后加可解释排序。比较结构、参数类型/数量、命名/分页等差异，不把相同指纹视为同一次调用。

退出门 G3：100 次相同 SQL 在分析通道为 100 次，日志可仍折叠；一次执行双路捕获不翻倍；不同库/进程不混；丢失使诊断显式降级。关闭分析后没有新增持续采集和保留。

### M3：单 JVM 请求 SQL 诊断与预算

对应 SI-08/09/10、SI-14 的部分运行面。

- W30 标签分组：兼容现有 requestTag，明确标为“标签观测”，无起止不报请求时长。
- W31 请求边界：M0 通过后，选定 Servlet 同步请求族作为首个支持面，分别验证 `javax`/`jakarta` 依赖隔离；根事件覆盖无 SQL 请求、异常请求和嵌套分派。
- W32 SQL 时间轴/归因树：请求根—SQL 执行—调用栈解释；并行区间可见。没有方法耗时就不画方法耗时火焰图。
- W33 重复/N+1：请求内结构、调用点及可用参数模式证据；批量写、重试、同库/跨库分开；支持忽略规则与判定说明。
- W34 请求基线/预算：先数量、错误、结构，再耗时；保存环境和采集质量；结果 PASS/FAIL/INCONCLUSIVE 三态。
- W35 事务探针：物理连接与池租借、autoCommit、commit/rollback、失败/嵌套与保存点先实验；只有证据完整的局部事务才展示终态。XA、跨库全局事务首期不支持。

异步线程池、CompletableFuture、Servlet async、响应式/Reactor、虚拟线程按适配器另行验证，不得用 ThreadLocal 全覆盖声明。**同步 Servlet 也可能在线程池发 SQL 再 Future.get() 等待**，HTTP 同步返回不能证明 SQL 都在请求线程。首版无传播时只能称“请求线程内 SQL 观测”，不能给整个请求的预算 PASS；跨线程覆盖不明时为 INCONCLUSIVE，已观察到的数量/耗时下界超预算仍可判 FAIL。仅对已证明全部执行范围可关联的适配器启用整请求 PASS。可识别的上下文断开明确显示，不能假装能识别所有未关联异步 SQL 的所属请求。W35 可以独立延后，不阻塞已验证且口径受限的 W31～W34。

退出门 G4：相同入口并发/复用线程不串请求；有终态覆盖证据的无 SQL 请求正确闭合；异常/超时清理上下文；末尾丢失、结束乱序、线程池等待反例均通过；预算对不完整采集及跨线程覆盖不明不判绿；用户实际工程的端到端样本通过。

## 七、验证与验收矩阵

### 7.1 静态语义必验

| 用例 | 可判定期望 |
|---|---|
| SELECT 两表 JOIN | 两个读取对象与结果节点；无表到表写入边 |
| 自连接与同名别名 | 别名作用域分开，不能因同表名折叠角色 |
| 显式列 INSERT…SELECT | 源表读、目标表写；目标列按位置绑定 |
| UPDATE t SET a=b WHERE c=? | a 为赋值目标、b 为值来源、c 为筛选依赖 |
| DELETE | 删除目标可见；无虚构输出值来源 |
| CASE/聚合/窗口表达式 | 变换和影响关系分类型；未覆盖函数显式未知 |
| CTE 遮蔽/子查询/UNION | 局部别名不泄漏，UNION 按列位置对齐 |
| 星号缺元数据/裸列多候选 | 保留未解析节点，不猜字段归属 |
| 跨 schema/引号/大小写 | 按方言与完整对象身份处理，不全局 lowercase |
| 递归 CTE/MERGE/过程体 | 超首期语义范围时部分/不支持，不以 parse 成功冒充支持 |
| 未展开 XML、解析 null、非法 SQL | 不崩溃，显示未展开/失败，现有 SQL 原文可继续看 |
| 格式化/注释/多字节字符/编辑 SQL | 定位有效；陈旧异步结果不得覆盖新快照 |

至少针对“把 JOIN 当值流”“把表集合当读写”“歧义时选第一个”“旧缓存覆盖新 SQL”做摘除防护后的反向红。黄金语料包含真实项目匿名样本，不只有为算法量身定做的字符串。

### 7.2 运行与完整性必验

| 用例 | 可判定期望 |
|---|---|
| 同 SQL 100 次，日志开启去重 | 分析次数=100，统计耗时来自100个事件 |
| 一次 SQL 代理/织入/控制台多观测 | 确定身份的执行只计1；无法关联的来源不自动相加 |
| 两进程/两库/两请求同文本 | 身份和统计不串，PID复用也不碰撞 |
| 同线程先后请求、异常后复用 | 请求根与SQL严格隔离，无上下文遗留 |
| 并行SQL与嵌套调用 | 累计耗时与墙钟区间不混标、不重复扣减 |
| executeUpdate/execute/batch | 已知/未知/部分行数正确，不把-1/-2当真实行数 |
| 隐式抛异常、捕获失败、旧载荷 | 状态可UNKNOWN，缺错误文本不自动成功 |
| 断连/队列满/编码异常/截断 | 质量计数与缺口可见，预算为INCONCLUSIVE |
| 最后一条SQL丢失后进程退出、SQL全部丢失 | 无终态/计数不符，不能显示零执行或完整；预算INCONCLUSIVE |
| 请求结束先于SQL到达、终态消息丢失 | 有界乱序收敛；超时不判完整，无无限等待 |
| 同步Servlet在线程池查询后Future.get() | 无传播时仅请求线程观测；整请求不可PASS，不能把漏关联SQL当不存在 |
| 停采/清空/重开/卸载 | 遵循§4.4保留矩阵，无新增泄漏与后台任务遗留；清空后旧generation消息不得回填 |
| SQL成功后rollback/commit失败 | 不显示已提交；事务未知单独提示 |
| 不支持的异步/响应式路径 | 显示未关联，而不是按线程猜父请求 |
| 预览同调用点多候选 | 可解释候选供确认，不自动错误配对 |

数量对照必须来自业务端独立计数/已知工作负载，不用被测分析通道自己生成期望。损失路径主动注入，证明质量降级确实触发，而非默认永远 COMPLETE。

### 7.3 安全与资源门

- 默认不扩大 SQL 参数采集；日志中已有敏感信息不代表新分析导出可默认外发。
- 导出前显示字段清单和预览，允许移除 SQL、参数、路径、库标、错误文本；字面量、错误消息、JDBC URL 都要测脱敏。
- 页面名称/SQL/错误中含 HTML、脚本、URL 等不得执行；离线包不能拉外网资源。
- EXPLAIN ANALYZE、COUNT 试算、结果比较均为不同操作；任何可能访问数据库的动作复用既有目标确认、权限、超时与取消。未知副作用拒绝或要求明确执行确认。
- 首期性能目标是建议验收预算，M0 校准，不冒充已达成：普通单条分析暖态 P95 ≤200ms，取消反馈 ≤200ms；大语句达预算即降级，不持读锁持续扫工程。
- 初始容量建议：分析事件总额≤10,000条或64MiB先到者截断；单请求≤2,000条；单场景批次≤20；默认展开图≤200节点/400边。数值经M0测量调整并写入快照质量；不是当前产品已有参数。
- agent新增功能开启后，固定工作负载额外P95延迟≤5%、CPU增加≤5个百分点、额外常驻内存≤64MiB作为初始预算；区分相对“现有捕获开启”和“无agent”两条基线。超预算先收范围/采样，不能删质量说明。
- 新分析关闭时不得有请求hook持续上报、解析/存储后台任务或可观测显著开销；深栈、批量、断连均做长稳对照，不只测空载。

## 十、风险与降级

| 风险 | 处理 |
|---|---|
| 语法支持广、语义覆盖窄 | 公开精确子集与未知原因，不用parser成功装绿 |
| 新事件通道扩大隐私采集 | 全局策略先行，显式启用、默认脱敏、有界保留 |
| 去重前分流造成重复计数 | 执行身份与来源覆盖，不凭文本/时间猜唯一性 |
| 请求hook影响宿主或多agent共存 | 小范围适配、开关、故障隔离；宿主安全优先于完整性 |
| 异步/线程复用串请求 | 清理与恢复上下文测试，未支持路径显示断开 |
| 计划对比或COUNT误导执行安全 | 明确成本/行数语义，所有执行仍走既有确认链 |
| 全项目影响索引造成卡顿 | 显式范围、后台分片、取消和缓存失效；无热路径全扫描 |
| dev资产接口变动或不获合流授权 | 不提前依赖，不重复造轮子，调整阶段范围 |
| 页面越加越拥挤 | 预览内按需分析、树表后备、大图放大，不堆根页签 |
| 开发范围膨胀成APM平台 | G0～G4阶段门，M4分项立项，不默认全实施 |
