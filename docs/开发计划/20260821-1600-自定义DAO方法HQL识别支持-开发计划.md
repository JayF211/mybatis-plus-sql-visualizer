# 自定义 DAO 方法 HQL 识别支持

> 创建日期：2026-08-21
> 状态：**计划中**
> 优先级：**P1**（功能扩展——用户实际项目中的 HQL 调用形态）

## 1. 问题描述

### 1.1 现象

用户项目中大量使用**自定义 DAO 方法**传递 HQL 字符串，而非标准的 `session.createQuery()` 调用。当前插件无法识别这类 HQL：

```java
// 用户实际代码（截图）
List<Long> locIdList = boxList.stream()
    .filter(b -> WmsBoxType.BX.equals(b.getType()))
    .map(WmsBox::getId).collect(Collectors.toList());

if (CollectionUtils.isNotEmpty(locIdList)) {
    Long count = (Long) commonDao.findByQueryUniqueResult(
        "select count(1) from WmsZone z " +
        "left join WmsLocation loc on loc.zoneId = z.id " +
        "where loc.id in (:locIdList) and z.beAutoZone = true",
        "locIdList", locIdList);
}
```

### 1.2 现有识别能力分析

| 组件 | 当前能力 | 缺陷 |
|------|----------|------|
| `HqlQueryLocator` | 仅识别 `session.createQuery(...)` / `createNamedQuery(...)` | 不识别自定义 DAO 方法 |
| `HqlConverter` | HQL → SelectStatement 转换（已有） | 存在但未接入 UI |
| Gutter 图标 | 无 HQL 相关 gutter | `session.createQuery()` 也无图标 |
| `SqlPreviewService` | 无 `previewHql()` 方法 | 即使定位到 HQL 也无法预览 |

**核心差距**：
1. `HqlQueryLocator` 与 `HqlConverter` 已写好但**未接入 UI 链路**（无 gutter、无 preview 方法）
2. 自定义 DAO 方法 HQL 完全无识别能力

### 1.3 自定义 DAO HQL 的常见形态

| 形态 | 示例 | 参数传递 |
|------|------|----------|
| **name-value 交替** | `dao.findByQuery("HQL", "name1", v1, "name2", v2)` | 参数名-值交替 |
| **Map 传参** | `dao.findByQuery("HQL", paramsMap)` | Map 包裹 |
| **位置参数** | `dao.findByQuery("HQL", v1, v2)` | 仅值，按位置 |
| **单字符串** | `dao.findByQuery("HQL")` | 无参 HQL |

## 2. 影响范围分析

### 2.1 用户项目受影响场景

| 场景 | 调用方式 | 当前状态 |
|------|----------|----------|
| `commonDao.findByQueryUniqueResult(HQL, ...)` | 自定义 DAO + name-value | ❌ 不识别 |
| `commonDao.findByQueryList(HQL, ...)` | 自定义 DAO + name-value | ❌ 不识别 |
| `session.createQuery(HQL)` | 标准 Hibernate | ⚠️ 有 locator 但无 UI |
| `sessionFactory.getCurrentSession().createQuery(HQL)` | 标准 Hibernate | ⚠️ 有 locator 但无 UI |
| `@Query("JPQL")` | Spring Data | ✅ 已支持 |
| `findByXxx()` 派生查询 | Spring Data | ✅ 已支持 |
| CriteriaQuery | JPA 强类型 | ✅ 已支持 |

### 2.2 设计决策

**决策 A：HQL 内容检测策略**

自定义 DAO 方法名无法穷举，必须结合**上下文启发式**：
1. **qualifier 类型启发**：变量名匹配 `*Dao` / `*DaoImpl` / `*Mapper` / `*Repository` / `*CommonDao` 等模式
2. **方法名启发**：方法名含 `Query` / `Hql` / `Jpql` / `execute` 等关键字
3. **内容启发**：字符串参数匹配 HQL 语法模式（含 `SELECT`/`UPDATE`/`DELETE` + `FROM` + 驼峰实体类名 + `:paramName` 命名参数）

三重启发取**逻辑与**（同时满足 1 或 2 + 3），降低误判率。

**决策 B：参数提取策略**

优先从 HQL 字符串本身提取 `:paramName` 命名参数（静态可确定），方法参数作为补充：
- name-value 交替：`("name1", v1, "name2", v2)` → 提取 `{name1: v1, name2: v2}`
- Map 传参：标注"参数来自 Map，运行时确定"
- 位置参数：标注"位置参数，运行时确定"

**决策 C：实体解析策略**

自定义 DAO 方法无 `Entity.class` 二参，实体解析完全依赖 `JpaEntityResolver` 从 HQL 中的实体类名查找：
1. 从 HQL 的 `FROM EntityName` 提取实体类名
2. 通过 `JpaEntityResolver` 按类名查找 `@Entity` 注解类并解析表信息

### 3.2 详细改动

#### 3.2.1 `CustomDaoHqlLocator.kt` — 新增

```kotlin
/**
 * 自定义 DAO 方法 HQL 定位器。
 *
 * 识别用户自定义 DAO 方法中的 HQL 字符串（非标准 session.createQuery()）。
 *
 * 检测策略（三重启发）：
 *  1. qualifier 类型启发：变量名匹配 DAO 模式（*Dao/*Mapper/*Repository 等）
 *  2. 方法名启发：含 Query/Hql/Jpql/execute 等关键字
 *  3. 内容启发：字符串参数匹配 HQL 语法（SELECT/UPDATE/DELETE + FROM + 实体类名）
 *
 * 参数提取：
 *  - 从 HQL 字符串提取 :paramName 命名参数
 *  - 从方法参数提取 name-value 交替对
 */
object CustomDaoHqlLocator {

    // DAO 类型变量名后缀（qualifier 启发）
    private val DAO_QUALIFIER_SUFFIXES = setOf(
        "Dao", "DaoImpl", "Mapper", "Repository", "CommonDao", "DaoHelper", "BaseDao",
    )

    // 方法名关键字（方法名启发）
    private val QUERY_METHOD_KEYWORDS = setOf(
        "Query", "Hql", "Jpql", "execute", "findByQuery", "findBySql",
    )

    // HQL 内容模式（内容启发）
    private val HQL_CONTENT_PATTERNS = listOf(
        Regex("""\bSELECT\b.*\bFROM\b""", RegexOption.IGNORE_CASE),
        Regex("""\bUPDATE\b.*\bSET\b""", RegexOption.IGNORE_CASE),
        Regex("""\bDELETE\b.*\bFROM\b""", RegexOption.IGNORE_CASE),
        Regex("""\bFROM\b\s+[A-Z][a-zA-Z0-9_]*\b""", RegexOption.IGNORE_CASE), // FROM EntityName
    )

    // 命名参数模式
    private val NAMED_PARAM_PATTERN = Regex("""(?<!:):([a-zA-Z_][a-zA-Z0-9_]*)""")

    data class CustomDaoHqlInfo(
        val hql: String,
        val isLiteralHql: Boolean,
        val entityClassName: String?,  // 从 HQL 中提取的实体类名
        val parameters: List<HqlParameter>,
        val method: PsiMethod,
        val paramSource: ParamSource,  // 参数来源类型
    )

    enum class ParamSource { NAME_VALUE_PAIRS, MAP, POSITIONAL, NONE }

    fun locate(anchor: PsiElement): CustomDaoHqlInfo? {
        // 1. 从锚点向上查找 PsiMethod
        // 2. 扫描方法体内全部 PsiMethodCallExpression
        // 3. 对每个方法调用检查是否为自定义 DAO HQL 调用
        // 4. 提取 HQL 字符串和参数
    }

    /**
     * 判断方法调用是否为自定义 DAO HQL 调用。
     * 三重启发：(qualifier 启发 OR 方法名启发) AND 内容启发
     */
    private fun isCustomDaoHqlCall(call: PsiMethodCallExpression): Boolean {
        val contentMatch = hasHqlContent(call)
        if (!contentMatch) return false
        val qualifierMatch = matchesDaoQualifier(call)
        val methodNameMatch = matchesQueryMethodName(call)
        return qualifierMatch || methodNameMatch
    }

    /**
     * 从 HQL 字符串提取实体类名（FROM 子句后的第一个驼峰标识符）。
     */
    private fun extractEntityClassName(hql: String): String? {
        val fromPattern = Regex("""\bFROM\s+([A-Z][a-zA-Z0-9_]*)\b""", RegexOption.IGNORE_CASE)
        return fromPattern.find(hql)?.groupValues?.get(1)
    }

    /**
     * 从方法参数提取 name-value 交替对。
     * 模式：("name1", v1, "name2", v2) → [(name1, v1), (name2, v2)]
     */
    private fun extractNameValuePairs(args: List<PsiExpression>): List<HqlParameter> { ... }

    /**
     * 从 HQL 字符串提取 :paramName 命名参数。
     */
    private fun extractNamedParamsFromHql(hql: String): List<String> {
        return NAMED_PARAM_PATTERN.findAll(hql).map { it.groupValues[1] }.toList()
    }
}
```

#### 3.2.2 `HqlGutterLineMarkerProvider.kt` — 新增（标准 createQuery 的 gutter）

```kotlin
/**
 * Hibernate HQL gutter 预览图标：识别 session.createQuery() / createNamedQuery() 调用，
 * 在调用行显示预览图标，点击弹出 SQL 预览。
 *
 * 复用 HqlQueryLocator.locate() 判定。
 */
class HqlGutterLineMarkerProvider : LineMarkerProvider {
    override fun getLineMarkerInfo(element: PsiElement): LineMarkerInfo<*>? {
        if (element !is PsiIdentifier) return null
        val method = PsiTreeUtil.getParentOfType(element, PsiMethod::class.java) ?: return null
        if (method.nameIdentifier !== element) return null
        if (!gutterEnabled()) return null
        // 复用 HqlQueryLocator 判定
        if (HqlQueryLocator.locate(element) == null) return null
        return LineMarkerInfo(...)
    }
}
```

#### 3.2.3 `CustomDaoHqlGutterLineMarkerProvider.kt` — 新增

```kotlin
/**
 * 自定义 DAO HQL gutter 预览图标：识别自定义 DAO 方法中的 HQL 调用。
 *
 * 锚定在方法调用的方法名 PsiIdentifier 上。
 * 复用 CustomDaoHqlLocator.locate() 判定。
 */
class CustomDaoHqlGutterLineMarkerProvider : LineMarkerProvider {
    override fun getLineMarkerInfo(element: PsiElement): LineMarkerInfo<*>? {
        if (element !is PsiIdentifier) return null
        // 锚定在方法调用的方法名上（非 PsiMethod 名）
        val parent = element.parent ?: return null
        if (parent !is PsiReferenceExpression) return null
        val grandParent = parent.parent as? PsiMethodCallExpression ?: return null
        // 确认当前 identifier 是方法名（非 qualifier）
        if (grandParent.methodExpression.referenceName != element.text) return null
        if (!gutterEnabled()) return null
        if (CustomDaoHqlLocator.locate(element) == null) return null
        return LineMarkerInfo(...)
    }
}
```

                    ↓
CustomDaoHqlGutterLineMarkerProvider → CustomDaoHqlLocator.locate()

1. qualifier "commonDao" 匹配 *Dao 后缀 ✅
2. 方法名 "findByQueryUniqueResult" 含 Query ✅
3. 字符串内容匹配 SELECT...FROM EntityName ✅

## 6. 风险与注意事项

1. **误判风险**：三重启发（qualifier + 方法名 + 内容）取逻辑与，大幅降低误判。但 `dao.execute("print ...")` 等非 HQL 字符串仍可能命中——需确保 HQL 内容模式严格（必须含 `FROM EntityName` 或 `UPDATE EntityName SET` 等完整结构）。
2. **实体解析**：自定义 DAO 方法无 `Entity.class` 二参，实体解析依赖从 HQL 文本提取类名后查找。若项目中多个同名类（不同包），可能解析到错误实体——后续可优化为按 qualifier 类型的泛型参数推断。
3. **gutter 锚点**：自定义 DAO HQL 的 gutter 锚定在 `PsiMethodCallExpression` 的方法名 `PsiIdentifier` 上（非 `PsiMethod` 名），需精确判断 `element.parent is PsiReferenceExpression` 且 `grandParent.methodExpression.referenceName == element.text`。
4. **与现有 JPA gutter 的去重**：`commonDao.findByQuery(...)` 不满足 `DerivedMethodLocator.isDerivedQuery()`（非 Repository 接口方法），不会与 `JpaGutterLineMarkerProvider` 冲突。但需确认不与 `JpqlGutterLineMarkerProvider` 冲突（后者锚定在 `@` token，不会冲突）。
5. **性能**：`CustomDaoHqlLocator.locate()` 需扫描方法体内全部 `PsiMethodCallExpression`，但 gutter 快速路径只做 O(1) 锚点判定（identifier 类型 + 父链形态），完整扫描仅在点击时执行。
6. **bundle 文案**：新增 4 条 key（中英文各 2），需同步更新 `MpSqlVisualizerBundle.properties` 和 `MpSqlVisualizerBundle_zh.properties`。
