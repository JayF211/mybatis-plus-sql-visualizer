## 二、目标与红线

**目标**：
1. 在 616a5e2（6395 例）上重测权威带：冷跑＋两轮 warm 纪律起手，墙钟/execSum/失衡带/计数 parity 入账（当前 tip 第一份墙钟台账）。
2. 权重画像刷新到当前类集并验证失衡带不劣于 T12 带（+11~13%）。
3. 三项审计各出定案读数：固定 sleep 总账、bootstrap 13s 拆账、testDatabase 串行段评估。
4. 若 bootstrap 拆账给出 ≥3s 可处置项且同窗 A/B 墙钟 −5% 达标才落码，否则零构建脚本改动收口。

**达标判据**（沿用 T12）：墙钟中位较基线中位 −5% 以上（同窗交错口径；窗口漂移带 ±5~8%，T5 定例）。本轮预判大概率达不到 −5%——审计结论与权威带刷新本身即交付物，未达时如实入账，不硬凑。

**红线**：
1. 零删例、零断言改动、零 `src/main` 改动。改动面限：`dev-support/`（审计脚本）、`docs/`。若实施中确需动 `buildSrc`/根构建脚本（仅 D43 触发时），即构成大改动判据，收口加跑 verifyGate 三目标。
2. 计时纪律照抄：全机只跑一路 test、跑前 `python parallel_tasks.py check` 登记＋`timeout 10 docker info`＋Commit 余量 ≥12GB 预检、效应 <10% 必须**同窗交错 A/B**、失败轮先收证（拷失败 XML）再跑下一轮。
3. 失败集合判据：616a5e2 合并态门禁 6395/0/0/9 全绿 → 实验轮期望零失败恒等；若出现既有红（O-93 族间歇形态），判据退为「失败集合⊆既有集＋逐轮恒等」并先收证。
4. 新树纪律（T12 新增）：冷轮读数不作判据、均衡观察等两轮 warm、借画像前核同基线。
5. 画像刷新用 weight-refresh.ps1 自带的污染闸（execSum>900s 拒写），不手工改 tsv。

## 三、方案

### S0 建树基线（数据件）
零机制改动，跑三轮：R0 冷跑（编译税全额，读数不作判据，喂 warm 权重窗）→ R1/R2 warm。逐轮记录：BUILD 墙钟、各片 exec 与 expected 对照、临界片、SHARD TOTAL、parity 行、告警行、agent/testExternal 早收时点。R1/R2 中位＝本轮基线，与 T12 带（163s±漂移）对照定 V55。

### S1 画像刷新（主修通道执行件）
取 R1/R2 中干净一轮（execSum<900s 过污染闸）跑 `dev-support/weight-refresh.ps1` 刷 559→当前类集入库；随后 R3 验证轮读失衡带，与 S0 基带和 T12 带（+11~13%）三方对照定 V56。收益预期如实：稳态带收益 0~10s 级（失衡带本已自愈到 +11~13%），主要价值在冷树首轮均衡与防缺权告警，如实入账不夸大。

### S2 固定 sleep/尖刺审计（定案件，零改动预判）
写 `dev-support/sleep-audit.py`：扫 src/test 全部 sleep 调用点，按「deadline 轮询形态／固定等待形态／语义时间窗形态」三分类，逐处估最大等待时长，按类聚合对齐画像权重表，产出总账（固定等待合计 ÷ execSum）。判据：合计 <5% execSum 即销案（立项目测 ~0.4%）；若 ≥5% 才立项收割（收割方式=改等真实状态信号、断言零改动，T11 尖刺判别法）。预判销案。

### S3 bootstrap 13s 拆账（定案件）
读分片沙盒 idea.log（测试沙盒启动时间戳）或必要时加时间戳探针（跑完即删，不随提交），把 13s 拆为核心初始化/插件描述符装载/扩展点枚举三段，五片交叉核对。决策点 D43：仅当插件级成本 ≥3s 且剔除后全量仍绿且同窗 A/B 墙钟 −5% 达标才落 classpath 剔除（推荐=预判核心占大头，销案补数）。

### S4 testDatabase 串行段评估（评估件，不实施）
现状：DB 链门禁触达时 testDatabase 五类串行、forkEvery=1 每类一次 JVM 冷启动，+2~3 min（T 系列从未量过它）。评估内容：①五类对 demo MySQL 的读写形态（共享写冲突是并行化的硬前提）；②per-JVM 隔离已成立（forkEvery=1 的动因）→ 并行 JVM 间互不污染的机制可行性；③五路并行 platform JVM 的 Commit 峰值（对照 5 分片 65.0GB）。产出=可行性结论＋前提清单，落 D44 推荐，本轮不写码。若 demo MySQL 未运行，评估降级为文档推断并如实标注证据边界。

### S5 收口
默认态权威轮（S1 刷新后的 R3 兼任）；片数复测义务核算——对 5 片定案基线（T7/T8/T9）比对 execSum 结构性增长是否 ≥10%，预期豁免论证入账（6 片否决前提=Commit 69.67GB/余量 5.0GB 未变，维持否决）；文档三处同步（本计划 §七回填、约定记忆更新、变更记录台账行）；分 hunk 提交（`T-TestPerf13` 前缀，`git commit -F` 文件式信息）；分支 push 留底；**不自动并 dev/master，报告待用户处置**。

## 五、决策点（带推荐）

- **D43（bootstrap 拆账处置）**：仅当插件级成本 ≥3s 且剔除安全（全量绿）且同窗 A/B ≥5% 三件齐才落 classpath 剔除，否则销案补数。推荐=销案（T9 的「平台侧能力」定性＋Vue/Database 剔除先例是为正确性非性能，性能面未证）。
- **D44（testDatabase 并行化）**：本轮不实施，登记为在册候选（触发面窄＋demo MySQL 共享写冲突未证伪＋真库验证依赖）。推荐=维持串行现状，待 DB 链门禁高频化或真库窗口（D41 走查批）再启。
