### 4. T-FS-06 守卫两缺口

- `303370d`：`convention/BannedApiSourceScanTest.kt`。13 条既有守卫用例**原样保留**，重构性质：
  - **缺口一（规则覆盖）**：旧实现用两个互不覆盖的提取器——默认模态规则要求 `invokeLater` 后**紧跟**
    `{`，`any()` 规则只扫括号实参区。现由统一站点提取器 `invokeLaterSites` 一次取全「实参区 +
    尾随 lambda 体」（`InvokeLaterSite.body`），两条规则降级为薄判定。
  - **缺口二（配平过报）**：花括号配平此前跑在未剥注释的原文上（注释/字符串里不成对 `{` → 过报、
    不成对 `}` → 漏报）。新增 `maskNonCode`（剥行注释/嵌套 block 注释 + 涂白字符串与字符字面量，
    **逐行保行**，涂白而非删除以保住 body 内令牌匹配），配平与提取改跑其输出。
- **计划前提订正（实质发现）**：计划点名的「双规则盲区形态」`invokeLater(ModalityState.any()) { … }`
  **编译不过**——平台 `Application` 只有 `invokeLater(Runnable)`、`(Runnable, Condition)`、
  `(Runnable, ModalityState)`、`(Runnable, ModalityState, Condition)` 四个重载，**不存在
  `(ModalityState, Runnable)`**（`util-8.jar` javap 实证）。故那是一条**不可达**的「盲区」，旧 KDoc 的
  表述随之订正；真正可达且被旧规则漏掉的是 `invokeLater({ … }, ModalityState.defaultModalityState())`
  （显式默认模态 + **括号内** lambda），新规则已收编。
- **残留边界（登记不扩判据）**：`invokeLater({ … })`（括号内 lambda 且完全不写模态实参）两条规则都不覆盖
  （判据是「省略实参列表或实参区含 `defaultModalityState()`」）。收编需改成「实参区无 any()/nonModal()
  令牌即视为默认模态」，会连带改变对自定义模态（`stateForComponent` 等）的判定，故本轮只登记边界。

### 7. P20 定案：自研求值器的真缺口，但当前生产链不可达（影响面 0，不单独立项）

对照集 31 场景中 P20（`test` 表达式里用 DTO 属性，如 `u.name`）出现**真实分叉**：真引擎产出
`AND name = ?`，自研侧整条 `if` 判假不展开。**定案=第 ② 类（自研求值器真缺口），不是 mock 值语义差异、
不是探针构造问题**：

- **根因**：`xml/Ognl.kt:529-549` 的 `OgnlEvaluator.property()` 只覆盖 `MockObject` / `Map` /
  `Collection` / `Array` / `CharSequence`，其余载体落 `else -> null` → `u.name` 取不到 → 判假。
- **最小复现已固化**：对照集内「P20 归因」用例断言同一表达式在 `ProbeDto` 载体下 `EvalResult.Ok(false)`、
  在 `MockObject` 载体下 `EvalResult.Ok(true)`——载体一换即翻。
- **不可达证据**：面板 / MCP 三处出口全走 `XmlPreviewModel`（`ui/XmlPreviewService.kt:54`/`:124`、
  `mcp/MapperCheckTool.kt:93-94`、`xml/AnnotationSqlParser.kt:36`），`renderSql` 把**全部** `IfSqlNode`
  （含 `choose` 的 `when`、含 `foreach` 体内 `if`）整表作为 `conditionOverrides` 传入
  （`xml/XmlPreviewModel.kt:121-129`），而 `IfSqlNode.apply` 的第一真值源就是覆盖（`xml/IfSqlNode.kt:15`）
  → 表达式求值在生产路径根本不触发；且 `mockBindings` 只会产出 `MockObject`/`MockIterable`/`"1"` 等，
  从不喂真实 POJO（`XmlPreviewModel.kt:131-151`/`:157-163`）。
- **处置=不单独立项**：修法是给 `property()` 补 POJO getter/字段反射分支（0.5~1 人天），但需先定反射
  可见性与「求值失败是否记 errors」；**建议随首个真实触达场景（真实参数求值模式）一起做**。
