## 一、环境准备

1. **载体**：`./gradlew buildPlugin` 产物 zip 装入 IDE，或 `./gradlew runIde` 沙盒（建议沙盒，避免污染日常 IDE）。
2. **平台**：IntelliJ IDEA 2024.3 及之后（基线 since-build 243）。
3. **工程素材**（按验收项取用）：
   - Wrapper 链 / 注解 SQL / JPA 预览：任意 MyBatis-Plus 工程；
   - mapper XML 高亮与补全：含 `mapper/*.xml` 的工程；
   - 分页模拟：mapper 方法或 XML 带 `IPage` / `Page` 形参；
   - EXPLAIN 与执行计划：需 Ultimate + 已配数据源；SQL Server 段需真库；
   - ShardingSphere 双段日志：控制台出现 `Logic SQL:` / `Actual SQL:` 形态日志；
   - 增强捕获织入：可 attach 的运行中应用（Spring Boot 或原生 MyBatis 工程）。
4. **前提提醒**：agent / 增强捕获相关项要求被测应用能正常启动并产出 SQL，否则「零事件」无法归因到本次增量。

## 三、分功能验收步骤

### 3.1 参数预设（方案）（R22 T-01~T-04）

入口：预览面板参数区「预设:」行（折叠件，缺省折叠）+「管理预设…」按钮。

1. 打开任一可预览 SQL（Wrapper 链 / mapper XML / 注解 SQL），展开「预设:」行。
2. 在参数区填几个参数、勾选若干 OGNL 条件，点「管理预设…」→ 另存为，输入名字。
3. 下拉切到该预设，再切回另一预设，最后切回本条语句。
4. 预期：切到预设时参数值、OGNL 勾选态、foreach 权威值整组还原；参数输入的来源锚点不串位（值不会写进别家输入框）。
5. 预期（快照语义）：编辑参数后切走再切回已存预设，显示的是**保存时**的快照值；日常编辑改写的是工作区（默认预设），不会就地覆写命名预设。
6. 预期（按语句隔离）：切到另一条语句，下拉只列该语句自己的预设；不同语句下可同名各存各值；重命名/删除作用于同名预设的全部语句（对话框已注明）。
7. 「管理预设…」：另存为/重命名/删除可用，默认预设受保护（删除带知情确认）；方案数达上限时报「已达上限」。
8. 折叠状态跨语句、跨弹窗保留，重启 IDE 复位为折叠。
9. 预期（旧数据）：升级前已有的参数历史自动成为「默认预设」，无需迁移动作。

### 3.2 绑定数据源指示行（O-96 / T-PreviewEdtGuard S3）

入口：预览面板顶栏「更多」按钮下方右对齐灰字行。

1. 打开预览面板，未在控制台执行过查询时观察指示行。
2. 预期（未绑定）：「未绑定数据源（在控制台执行一次查询即可绑定）」。
3. 预期（上次使用）：「数据源（上次使用）：<源名>」。
4. 在面板内嵌控制台执行一次查询后再看。
5. 预期（已绑定）：「已绑定：<源名>」，且执行路径切换/关掉控制台重开时该行即时刷新，不停留在「上次使用」态。

### 3.3 列信息表 Ctrl+A 全选（O-85）

入口：`<pages>` 预览（maintainPage）时的「列信息」页签。

1. 打开含 `<pages>` 的 mapper 预览，切到「列信息」页签。
2. 鼠标点进表格，按 Ctrl+A。
3. 预期：整表行全选（此前 IDEA 全局 Ctrl+A 的「选中文本」语义抢占，表格默认绑定不生效）。
4. 预期：列宽/内容不受影响，单选、拖选行为不变。

### 3.4 导出可移植 SQL（O-91，缩范围首版）

入口：预览面板「更多」→「导出可移植 SQL」。

1. 对一条 INSERT 预览（带回滚语句）点该菜单，选 CSV / TSV / TXT，选路径保存。
2. 预期：输出为当前 CRUD 语句与回滚语句串联，每条前有注释标注方言/种类/UPSERT 形态。
3. 预期：无法生成回滚的形态被诚实跳过，不产出半成品语句。
4. 预期：写盘在后台线程，界面不卡；成功后给通知。
5. 对 UPDATE / DELETE 预览重做一遍，预期同样成立。

### 3.5 EXPLAIN 支持面（R23）

入口：预览面板执行计划按钮。

1. 用 Oracle 数据源执行 EXPLAIN：
   - 预期：走 `EXPLAIN PLAN FOR`，并给「执行计划已登记到 PLAN_TABLE」一类诚实提示说明查看方式（PLAN_TABLE 会话级，插件不解析 DBMS_XPLAN）。
2. 用 SQL Server 数据源执行 EXPLAIN：
   - 预期：走 `SET STATISTICS XML`，结果交原生控制台呈现。
   - 注意：SQL Server 段为官方文档级形态，**本机未真库验证**，如实留账（见 §六）。
3. 预期：不支持的方言不硬解析、不报内部错误。

### 3.6 EXPLAIN 结构化渲染（R33，实验特性，默认关）

入口：设置 → SQL 预览 →「预览面板内结构化渲染 EXPLAIN（实验特性，默认关闭：走原生控制台）」。

1. 默认状态下点 EXPLAIN：预期走原生控制台（现行为不变）。
2. 勾选该开关并 Apply，回到预览面板点 EXPLAIN：
   - 预期：MySQL 表格形态 / PostgreSQL JSON 计划渲染为表格或可折叠树，头部显示方言 / 数据源 / 耗时，附索引建议。
   - 预期：结果过长时有截断提示。
3. 制造回退条件（未填参数 / 无数据源 / 无对应数据库插件 / 计划格式不认识），预期：回退原生控制台并给出具体原因，不静默失败。
4. 结果区应有「原生控制台」入口可切回。

### 3.7 分页拦截器模拟（R12）

入口：设置 → SQL 预览 →「模拟分页拦截器（COUNT 查询预览）」（默认开）。

1. 打开带 `IPage` / `Page` 形参的 mapper 方法或 XML 路径预览。
2. 预期：主 SQL 尾部按方言追加 LIMIT（参数取 `(当前页-1)×页大小`），并额外产出第二段 `分页 COUNT 查询（PaginationInnerInterceptor）`（`SELECT COUNT(*) FROM (…) TOTAL`）。
3. 预期：主 SQL 与 COUNT 语句各自以 `;` 收尾（复制到控制台执行不粘连）。
4. 源码里手写 LIMIT 时，预期不重复追加。
5. 关掉该开关，预期回到不分页的原形态。

### 3.8 XML 条件求值探镜（R30）

入口：XML / 注解预览的条件区（`<if>` 行）。

1. 打开一个含多个 `<if>` 的 mapper XML 预览。
2. 预期：每条条件行旁标注本轮求值三态（真 / 假 / 未求值），悬停显示「本轮求值结果：…」。
3. 预期：切换参数、勾选 OGNL 条件后标注随本轮预览更新。
4. 预期：预览 SQL 文本与开启探镜前逐字节一致（纯只读探针）。

### 3.9 历史 / 日志导出（R4）

入口：历史面板右键「导出 SQL」；SQL 日志面板右键「导出」（当前可见行集）。

1. 在历史面板先做一次搜索/过滤，缩小可见行集，再右键导出，选 CSV / TSV / TXT 保存。
2. 预期：导出内容＝面板**当前可见**行集（过滤/搜索/排序生效后），后台写盘不卡界面。
3. 预期：完成后通知含条数与落盘路径；写盘失败给错误通知且不抛内部错误。
4. 在 SQL 日志面板重复，预期同构。

### 3.10 历史 / 版本 SQL 对比（R31）

入口：历史面板多选恰两条 → 右键「对比选中两条」。

1. 历史面板中先只选中 1 条，右键看菜单项状态：预期不可用（或按实现置灰）。
2. 选中 2 条后右键执行，预期：打开 IDE 原生 Diff 窗口，左右为「旧 / 新」，逐行差异高亮。
3. 选两条「结构相同、仅参数值不同」的 SQL，预期：给出「结构等价，仅参数不同」一类指纹提示。
4. 选 3 条时预期菜单项不可用。

### 3.11 历史正则检索（R16）

入口：历史面板二级搜索框。

1. 输入 `regex:` + 合法正则（如 `regex:SELECT .* FROM t_user`）回车。
2. 预期：对 SQL、摘要、来源文件三个目标做正则匹配，结果集正确。
3. 输入非法正则（如 `regex:[` ）。
4. 预期：回退子串匹配，不产生「零结果」假象，不报错。
5. 普通（无 `regex:` 前缀）搜索行为不变，原有子串 / 行号 / 时间 / 源文件多目标路径照常。

### 3.12 同结构计数徽章与「只看同结构」（O-90）

入口：SQL 日志 / 历史列表条目元信息行徽章；右键菜单「只看同结构」。

1. 制造 ≥3 条结构相同、仅字面量不同的 SQL（如 `IN ('a')` / `IN ('b')` / `IN ('c')`）。
2. 预期：这些条目的元信息行显示「同结构 N 条」徽章（琥珀色），不足 3 条不显示。
3. 右键其中一条，预期「只看同结构」可用（未达阈值的条目该菜单项置灰），悬停有判定口径说明。
4. 点击后预期：列表只剩该结构的全部条目，出现过滤 chip；点 chip 清除提示可恢复全量。
5. 预期：徽章计数按面板**全量**条目聚合，不随当前过滤/搜索波动。
6. 历史面板侧同构可用。

### 3.13 数据源上下文角标（R32）

入口：SQL 日志 / 历史条目的角标（需 agent 通道捕获到连接 URL）。

1. 通过增强捕获产生带连接 URL 的条目。
2. 预期：角标显示「方言 · 库名@host:port」（如 `MySQL · demo@127.0.0.1:3306`）。
3. 预期：URL 缺库名或 host 时只显可得部分；URL 畸形时只显方言或完全不显。
4. 预期：JDBC URL 里的 user / password 及 query 串不出现在角标任何位置。

### 3.14 日志转 SQL「从剪贴板读取」（O-92）

入口：工具窗「日志转 SQL」输入栏按钮。

1. 剪贴板为空时观察按钮：预期不可用或点击给「剪贴板中没有文本」轻提示。
2. 复制一段 MyBatis 日志入剪贴板，点该按钮。
3. 预期：文本贴入输入区并立即触发转换，结果区产出 SQL。

### 3.15 日志 DDL 预览三修（T-DdlLogPreview）

入口：SQL 日志里点开一条 `CREATE TABLE … COMMENT '…'` 的条目。

1. 预期（S1）：参数区**不再**出现 `#param1..#paramN` 伪参数（DDL 不做字面量参数恢复），参数区为空或提示无参数。
2. 预期：预览文本保留原文引号与注释，不走占位符化。
3. 点「格式化」，预期（S2）：定义列表 `(` 后换行缩进、列定义按顶层逗号逐行、外层 `)` 独立成行、`VARCHAR(64)` 尺寸括号贴紧、`PRIMARY KEY (`id`)` / `CHECK (…)` 仍留空格；`ALTER` 顶层动作逐行。
4. 回归：对一条普通 SELECT / INSERT 点「格式化」，预期输出与升级前**逐字节一致**。
5. 对 `DROP TABLE IF EXISTS x ;` 这类本就单行的语句点「格式化」，预期（S3）：给「已是最可读形态，格式化后无变化（单行语句或本就没有换行点的语句）」轻提示，不报错；单测环境静默。

### 3.16 捕获诊断行两项计数（T-DevAcceptFix2 ⑤⑩）

入口：SQL 日志面板诊断行（增强捕获状态行）。

1. 挂载增强捕获后观察诊断行。
2. 预期：恒显「已收事件 N 条」（含后续被去重/屏蔽丢弃的），N=0 可据此判 agent 侧未到、N>0 判消费侧。
3. 在「管理屏蔽规则」中建一条会命中当前 SQL 的规则，重放该 SQL。
4. 预期：诊断行出现「屏蔽规则命中 N 条（见「管理屏蔽规则」）」；规则删除后该计数归零。
5. 预期：另两项既有计数（重放丢弃 / EP 短路）行为不变。

### 3.17 ShardingSphere 双段日志捕获（R10）

入口：设置 → SQL 日志 → ORM 页签 →「启用 ShardingSphere 日志捕获」（默认开）。

1. 开启开关，在控制台产生 `Logic SQL:` / `Actual SQL:` 双段日志。
2. 预期：`Logic SQL` 成主条目，`Actual SQL` 逐行折叠为该条目的附注（可展开看到数据源路由）。
3. 预期：关掉开关后不再产生这两类条目。
4. 回归：Hibernate / JDBC / MyBatis 三族的既有解析不受影响（同组另两个开关行为不变）。
5. 注意：解析器为骨架级、基于公开文档样例形态；真实双段日志语料到位后细节按 TODO 清单补全（见 §六）。

### 3.18 gutter 按来源分组显隐（R2）

入口：设置 → UI and Actions → 六个复选框（mapper XML 语句 / 注解 SQL（@Select 族）/ JPA·HQL 族 / JdbcTemplate 字符串 SQL / 通用 XML 内嵌兜底 / Wrapper 链·方法名字符串 SQL）。

1. 打开一个同时含多来源 SQL 的工程文件，确认各来源 gutter 图标在场。
2. 取消勾选其中一组（如「注解 SQL」），Apply。
3. 预期：仅该来源的图标消失，其余来源图标照常；「任何条件都不挡路」的既有行为不变。
4. 重新勾选恢复，预期图标立即回来（无需重开文件）。
5. 预期：默认全开，即升级后现行为不变；该开关随界面语言切换同步刷新文案（不残留旧语言）。

### 3.19 mapper XML 语法高亮注入（T-XmlSynHi）

入口：打开任意 mapper XML；总开关在设置 → UI and Actions →「mapper XML 语法高亮（关键字 + 参数占位着色）」。

1. 打开含动态标签（if / foreach / choose）、`#{}` / `${}`、`test` 属性的 mapper XML。
2. 预期：语句文本内 SQL 关键字着色、`#{}` / `${}` 占位底色、`test` / `value` 属性表达式着色。
3. 在语句文本内键入 `#` 或 `$`，预期自动补出 `{}` 并把光标置于花括号内。
4. 在 `resultMap` 的 `column` 属性处触发补全，预期给出列名候选。
