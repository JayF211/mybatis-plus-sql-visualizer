### 2. `3e2295e` 那处冲突的语义与裁决（本节重点）

冲突落在 `ui/SqlPreviewPanel.kt` 的 `projectPreviewFile()` 文件名构造一处，**两侧都不能直接选**——这不是「格式冲突」，是两个都正确但目标相反的设计正面相撞。

**本批侧（T-ICI）**：`java.io.File(dir, PreviewInlayScope.PREVIEW_FILE_NAME)`。文件名与 inlay 作用域锚点**同源**，防的是「两处各自硬编码字面量、改名时静默打穿锚点」。

**master 侧（T-FixN2，`49da332`）**：`java.io.File(dir, nextPreviewTempFileName())`。**每次预热换唯一文件名**，让每次预热都落在**没有任何 document 的全新路径**上（首次创建即裸写安全），从根上消除平台「File Cache Conflict」模态弹窗；配套把方言映射改成挂**目录**（`previewDialectMappingTarget(vf) = vf.parent ?: vf`）以适配「文件名每轮都变」。

**取任一侧的后果（这是不能二选一的理由）**：

- 取 **master 侧** → 一级文件名变成 `前缀 + owner-序号 + 扩展名` 形态，而锚点保留名只有 `mpsql-preview.sql` / `mpsql-preview-memory.sql` 两个字面量 → `previewStatementKind()` 恒返回 null → **inlay 在主路径静默永不渲染**。注意其失效形态是「不报错、不抛异常，只是悄悄不出现」，无任何日志线索。
- 取 **本批侧** → **撤销 N2 根治**，File Cache Conflict 模态弹窗回来。

**裁决解法：让两侧共用同一个名字来源**（不是折中，是把「形态」与「运行期取值」拆开）：

1. 名字来源整体**上移进 `PreviewInlayScope`**（实测定义于 `ui/inlay/PreviewInsertColumnInlayProvider.kt:56`）。新增 `previewTempFileName(owner, seq)` 作为**形态的唯一生成入口**（实测 `:104-105`），形态常量 `PREVIEW_FILE_NAME_PREFIX = "mpsql-preview-"`（`:67`）与 `PREVIEW_FILE_NAME_EXT = ".sql"`（`:70`）。
2. 面板只供**运行期取值**：`PREVIEW_TEMP_FILE_OWNER`（本 IDE 进程 pid，实测 `SqlPreviewPanel.kt:4464`）与 `PREVIEW_TEMP_FILE_SEQ`（`AtomicInteger`，`:4468`），`nextPreviewTempFileName()` 委托 `PreviewInlayScope.previewTempFileName(...)`（`:4471-4473`）；`projectPreviewFile()` 在 `:770` 用它建文件（函数起于 `:758`）。
3. 面板侧原有的 `PREVIEW_TEMP_FILE_PREFIX` / `PREVIEW_TEMP_FILE_EXT` **两个字面量已删除**——撰写者实测 `git grep "PREVIEW_TEMP_FILE_PREFIX\|PREVIEW_TEMP_FILE_EXT" -- "src/*"` **命中 0**，形态不再有第二份事实源。
4. 锚点判据改为「**内存级名精确匹配 或 一级名匹配紧致形态**」（`isPreviewFileName`，实测 `:117`）：形态 = `^` + `Pattern.quote(前缀)` + `\d+-\d+` + `Pattern.quote(扩展名)` + `$` **全串匹配**（实测正则 `:93-95`）。**刻意不用裸 `startsWith`**——否则会把 `mpsql-exec.sql`（原生控制台临时文件）与用户自造的同前缀文件一起放进来，打穿「只认本面板预览编辑器」这条判据。owner 段**不与当前 pid 比对**，理由写在 KDoc：跨会话残留（同 pid 复用 / 已退出会话的残留文件）经 `projectPreviewFile` 兜底分支仍会被本面板使用，按 pid 比对会让那一支静默失去 inlay。
5. 旧 `PREVIEW_FILE_NAME` 固定名字面量改名 `PREVIEW_FILE_NAME_SAMPLE`（实测 `:82`）并由 `previewTempFileName("12480", 1)` **推导**，仅供文档与测试构造「形态合法」的一级名引用——不再是生产固定名。

**双向反向验证（两侧的判据都被钉住，且都不是空绿）**：

1. **唯一名改回固定 `mpsql-preview.sql`** → N2 侧 `SqlPreviewPanelPreviewTempFileTest` **3 例红**（命名形态、两次装配不同名 + 旧文件回收、目录不增长）。撰写者实测该类 `fun test` 共 4 例（前 3 例即上述三条，第 4 例为方言映射挂目录）。
2. **锚点只认旧固定名** → T-ICI 侧 **6 例红**，含主路径正向用例 `test主路径预览文件INSERT出目标列提示`（实测 `PreviewInsertColumnInlayProviderTest.kt:70`）；而「用户自己的 `.sql` 不出现 inlay」**三条仍绿**（`test用户自己的SQL文件不产提示` `:106`、`test用户文件即使被挂上语句类型载体也不产提示` `:114`、`test测试缝文件名preview_sql不产提示` `:122`）——即收窄锚点**不误伤**用户文件边界，只有本面板预览失效。
3. **判据放宽成裸 `startsWith("mpsql")`** → `test原生控制台临时文件名不产提示`（实测 `:239`）**变红**，证明 exec 边界判据**非空绿**：它确实在拦 `mpsql-exec.sql`，而不是「恰好没有这种输入」。
