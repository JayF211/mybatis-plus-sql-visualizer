## 一、环境准备

任选其一：

- **装发行包**：`./gradlew buildPlugin` 产出 `build/distributions/mybatis-plus-sql-visualizer-2026.9.14-beta.1.zip`，IDE（2024.3+）「设置 → 插件 → ⚙ → 从磁盘安装」加载。
- **沙盒跑**：`./gradlew runIde`（JDK17+）。

建议准备一个含 MyBatis-Plus 实体与 Wrapper 链的演示项目（仓库惯例 demo 路径见 runIde 验证工作流），并配好至少一个 MySQL 数据源（EXPLAIN 与控制台执行功能需要）。

## 三、分功能验收步骤

### 3.1 SQL 列表 CRUD 类型颜色标记（T-CrudColor）

**入口**：SQL 日志工具窗与「SQL 历史」页的二级 SQL 列表自动生效；配置在「设置 → SQL Visualizer → SQL 日志」分组。

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 捕获若干条 SELECT / INSERT / UPDATE / DELETE 日志（或从历史页打开旧文件） | 列表每行左缘出现 3px 色条：SELECT 蓝、INSERT 绿、UPDATE 橙、DELETE 红；OTHER 行无标记 |
| 2 | 键盘上下键浏览 | 色条样式下选中行走平台填充、色条仍在 |
| 3 | 设置页把标记样式切到「整行淡背景」 | 整行染类型淡色；选中行不铺平台选中填充，改为类型色调加深 + 一圈 2px 描边；耗时快/慢着色在选中行不再被白色抹掉 |
| 4 | 设置页修改某类型颜色（如 SELECT 改紫）保存 | 列表与类型过滤弹窗图例即时变色，无需重开面板 |
| 5 | 样式切到「关闭」 | 列表逐字节回到无标记状态 |
| 6 | 点开日志页「类型过滤」弹窗 | 每个复选框左侧有对应颜色色块图例；样式为「关闭」时图例不显示 |
| 7 | 设置页点「恢复默认」 | 四色与样式回到默认（色条 + 蓝/绿/橙/红） |

### 3.2 错误/反馈一键上报（T-ErrReport）

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | IDE 主菜单「帮助 → Submit Feedback (SQL Visualizer)」 | 弹出反馈对话框（类型/分类/描述，可选附带异常堆栈） |
| 2 | 填写后提交 | 提示已送达官网需求池（sql-visualizer.jvtools.cn/about/feedback）；勾选堆栈附件时报告含 IDE/插件版本 |
| 3 | 触发一次 IDE 内部异常（或等真异常） | IDE 错误对话框出现「Report to SQL Visualizer Feedback Pool」按钮，一键提交且异常堆栈预填 |
| 4 | 设置页「更新与诊断」分组 | 有手动反馈入口 |
| 5 | 24 小时内重复提交同一异常 | 去重，不重复上送 |

### 3.3 SQL 列表三种显示模式（T-ListMode）

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | SQL 日志工具窗工具栏找到显示模式下拉 | 三项：单行 / 关键字换行 / 格式化，默认「关键字换行」 |
| 2 | 切「单行」 | 每条日志固定一行（长 SQL 截断） |
| 3 | 切「关键字换行」 | SQL 按关键字折行，行数随内容伸缩 |
| 4 | 切「格式化」 | 完整格式化排版 |
| 5 | SQL 历史页重复 1~4 | 两列表共享同一设置；重启 IDE 后模式保留 |
| 6 | 任意模式下选中条目 Ctrl+C | 复制的是纯 SQL，非渲染文本 |

### 3.4 gutter 左右键与最近执行反查（M37.1/M38.2）

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 打开含 `new QueryWrapper<>()...` 链的类 | 行左侧有锚点图标 |
| 2 | **左键单击**图标 | 直接弹出该锚点 SQL 预览（一键最短路径） |
| 3 | **右键单击**图标 | 弹菜单两项：「预览 SQL」「最近执行记录」 |
| 4 | 开启日志捕获并跑一次该位置后，右键选「最近执行记录」 | 反查本会话捕获的该位置执行记录（同文件优先、行号 ±30 行内排前），选中即打开带参数完整 SQL |
| 5 | 未捕获过时选「最近执行记录」 | 菜单项为空（正常） |

其余预览图标（注解 SQL / XML / JPA / HQL 等）仍是单击直接预览。

### 3.5 真实 EXPLAIN 执行计划（M37.2）

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 预览面板出 SQL 后，选中已配置的数据源 | 「执行计划」按钮可用（中文界面文案为「执行计划」） |
| 2 | 点击 | 按当前方言包装 EXPLAIN 提交原生控制台，真实执行计划与面板静态性能标注同屏对照；无 DML 二次确认弹窗 |
| 3 | 换 Oracle 或 SQL Server 数据源点击 | 提示该方言不支持，不影响其他功能 |

方言渲染形态与真机验证矩阵见 [M37/M38 说明 §2.3](../架构设计/M37M38竞品融合新增功能-说明文档.md)。前置：Ultimate + 已配数据源。

### 3.6 ORM 识别域扩展（M39/M44）

无需 UI 操作，识别到即出现 gutter 预览图标：

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 打开 EasyQuery / Querydsl / Xbatis / MDS 风格查询链代码 | 对应锚点行出现预览图标，可预览 SQL |
| 2 | 打开 Spring Data JPA Repository | 派生方法 `findByXxx` 支持 Specification / QueryByExample 形态；`@Query` JPQL 可预览 |
| 3 | JPA 实体含 `@Embedded` / `@Convert` / 填充字段（`insertable`/`updatable` 元数据） | 预览 SQL 正确展开嵌入列、标记转换字段、跳过不可插入/更新列 |

### 3.7 自动监听被动模式（行为变更）

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 设置页开启「自动开始监听」后（不启动项目） | 不再立即进入预捕捉状态（此前会立刻 armed） |
| 2 | 启动项目 Run | 自动开始捕捉 |
| 3 | 手动点「停止捕捉」后再 Run | 不再自动重新捕捉（需手动开启或重启） |

### 3.8 渲染与性能改进（观察项）

- 打开 / 刷新含上百条日志的列表：不再出现秒级冻结（后台扫描 + 增量刷新 + 固定行高快路径）。
- SQL 历史页扫描大 .idea 历史目录：后台执行，EDT 不卡。
- 每条日志自动生成 `#N` 会话内行号，方便引用（项目重启清零属正常）。

## 四、已知边界

- Oracle / SQL Server 不支持 EXPLAIN（点击提示降级）。
- MyBatis-Flex 暂不支持（调研结论暂缓）。
- 「最近执行记录」依赖日志捕获已开启且捕获过该位置。
- EXPLAIN 与控制台执行依赖 Ultimate 的 Database 工具窗；Community 版仅实体侧 CRUD 入口可用。
- runIde 真机走查（渲染器融合后三显示模式 × 三标记样式的组合观感）为留人工项——即本文档 §3.1/§3.3 的真机验证。
