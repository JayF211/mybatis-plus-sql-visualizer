# T-SqlHistoryFull SQL 历史全量化 + 历史打开防卡顿 — 验收文档

> **验收对象**：master 提交 `7c8a680`（主功能）+ 压测补充与并发丢条修复（`SqlLogAutoSaver` drainAndWrite 加锁）。背景与设计见 [T-SqlHistoryFull 开发计划](../开发计划/20260917-2118-T-SqlHistoryFull-SQL历史全量化与防卡顿-开发计划.md)。
> **回归基线**：IDE 全量 testShards **4317/0/0/6 绿**（含压测新增）；编译 0 错；log+config 定向全绿。

---

## 一、背景与验收前置

原行为：SQL 历史只记录**从列表淘汰**的 SQL（`onEvicted`）——列表未满或手动删除/清空的会话，SQL 不进历史。本次改为**入队成功即写全量**，并针对性加固历史打开性能（用户反复强调性能敏感）。

**环境**：装发行包或 `runIde` 沙盒；设置 → SQL 日志分组开启「自动保存历史 SQL」。跑项目产生 SQL 后用历史面板观察。

## 二、改动总览

| # | 改动 | 入口 / 位置 |
|---|------|------------|
| 1 | 历史记录全量化：成功入队即写（`onEntryStored`），不再仅淘汰写 | 自动保存开启后所有进入列表的 SQL 落盘 |
| 2 | 历史打开防卡顿：二级列表分批填充（`ignoreRepaint` + 首屏 30 + 每 30 `invokeLater` + gen 守卫） | 历史面板双击文件打开大文件 |
| 3 | 历史文件读取流式逐行（整读 → `useLines`） | 大文件读入内存峰值降为单条 |
| 4 | 并发丢条修复：`drainAndWrite` 与 `close` 同一监视器串行 | 写盘风暴与面板 dispose 并发不丢历史 |

## 三、分项验收步骤（真机走查，留人工）

### 3.1 全量历史（核心）

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 开启自动保存历史 SQL，让列表从未达到 200 上限（默认 `logMaxCount`）时跑几条 SQL | 这些 SQL **也出现在历史文件**（此前只有超限淘汰才进） |
| 2 | 列表已满后继续跑 SQL | 老条目被淘汰，但**全部**都能在历史文件里找到（含被淘汰的） |
| 3 | 手动删除列表单条 / 清空列表 | 历史中仍保留这些 SQL（此前直接丢弃） |

### 3.2 历史打开大文件不卡（性能关键）

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 造一个几百上千条 SQL 的历史文件（长时间开启自动保存） | 双击进入二级列表：**首屏立即显示约 30 条，随后分块追加直至全部**，界面不长时间冻结 |
| 2 | 打开期间切换搜索 | 搜索的 `gen` 代际生效，不发幽灵/重复条目 |
| 3 | 观察 IDE「正常」无卡死 | 渲染虚拟化只耗可视行，高亮成本与总量无关（维持现状自研高亮） |

### 3.3 语义边界

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 勾选去重，同一 SQL 短时间重复 | 去重窗口内重复的不重复进历史；**窗口外首次出现的相同 SQL 各进一次**（全量 vs 列表去重的差别） |
| 2 | 暂停捕捉 / 配置过滤关键字命中 | 暂停、过滤命中条目不进历史（沿用「成功入队」定义，非字节级全量） |
| 3 | 关闭自动保存 | 历史不再记录（仍是不记录的总开关） |

## 四、自动化已验证项（无需人工）

| 项 | 结果 |
|----|------|
| `SqlLogEntryBufferTest` 新增 `onEntryStored` 4 例 | 成功入队触发 / 覆盖淘汰 / 暂停过滤不触发 / null 安全，全绿 |

## 五、已知边界 / 取舍

- 「全量」沿用「成功入队」定义：去重窗口内重复、暂停、过滤命中的 SQL 不进历史；要连这些也留档是独立需求（会显著放大写盘与文件量级）。
- 单文件默认 100MB 滚动保留；全量化后单文件条目更多，读侧已流式降内存、打开已分批降冰冻。若单文件实测仍偏大，可再评估日内滚动。
- 未采纳「改原生 SQL 高亮」：渲染虚拟化下高亮非瓶颈，换原生无收益且引入 Database 依赖。

## 六、真机复验判定卡

- [ ] 列表未满 / 手动删除 / 清空后，历史仍含全部曾进列表的 SQL（§3.1）
- [ ] 上千条历史文件双击打开，首屏快显后分块追加、不冻结（§3.2）
- [ ] 去重窗口外同 SQL 各进一次、重复不重复进；暂停/过滤不入历史（§3.3）
