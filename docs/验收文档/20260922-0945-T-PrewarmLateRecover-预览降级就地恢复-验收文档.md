## 一、本次交付的用户可见变更（1 项）

**预览降级后可以就地恢复，不必关掉重开。**

原先的形态：冷启首开（首次索引 / 机器有负载）时预热耗时可能远超 500ms 预算，预览落「内存 PSI」降级态并在顶部挂红字横幅；而预热其实成功了，只是产物此后无人消费（`createEditor` 只在没有编辑器时进入），横幅在整个对话框生命周期内常驻——用户只能按横幅说的「关闭并重新打开预览」。

现在两条恢复出口：

| 出口 | 触发条件 | 用户看到什么 |
|------|---------|------------|
| **自动换装**（F1） | 预热产物在超时之后才到达，且**用户没有编辑过**预览里的 SQL | 横幅在数秒内自己消失；编辑区内容逐字不变；编辑器背后的文档由「内存 PSI」升级为项目内临时文件（表/列上下文补全随之恢复）；光标与焦点尽量复位 |
| **横幅「重试」动作**（F2） | 预热**硬失败**（项目内临时文件建不出来 / VFS 认领失败 / PSI 解析失败）——没有产物可等 | 降级横幅右侧多一个可点的「重试」；点一下重新预热，就绪后同样原地换装并清横幅；再失败则横幅与动作保留，可再点 |

判定「用户没编辑过」用的是文本比对（插件最后一次写入的文本 vs 当前文档文本），**不用** `Document.isModified()`（该 API 在 262 已从接口移除）。用户在降级态下动过 SQL 时不换装，避免抢编辑现场。

等待预算仍为 500ms，**未抬高**（依据见[预热耗时采样与预算建议](./20260920-预热耗时采样与预算建议.md) §5.2：要覆盖重负载首开需 ≥1.5s，代价是等待期普遍变长）。

## 二、逐项验收步骤

### A. 自动化已验证（无需人工重复）

| # | 断言 | 用例 |
|---|------|------|
| A1 | 迟到产物到达 → 编辑器文档落在项目内预览目录下、横幅清除、降级文档身份清空、psiFile 带真实 VFS 文件 | `SqlPreviewPanelPrewarmLateRecoverTest.test迟到产物到达_自动换装并清横幅` |
| A2 | 用户已编辑 → 不换装、用户文本不被覆盖、横幅保留 | 同族 `test用户已编辑_迟到产物不换装且不丢内容` |
| A3 | 面板已销毁 → 不换装、不抛 | 同族 `test面板销毁后_迟到产物不换装不抛` |
| A4 | 降级横幅显示「重试」动作、文案取自 i18n 键、点击后重新预热并就绪换装 + 清横幅 | 同族 `test降级横幅重试动作_点击后重新预热并换装` |
| A5 | 超时放弃后产物到达走迟到通道（而非被丢弃）；预算内交付不走该通道 | `PrewarmAwaitTest.test超时后产物到达_走迟到通道` / `test预算内交付_不触发迟到通道` |
| A6 | 既有消费链不变（主路径仍落项目内文件、产物一次性语义不变） | `SqlPreviewPanelPrewarmConsumeTest`（3 例，未改动，仍绿） |
| A7 | 降级横幅文案仍给出可行出路（守卫要求含「重新打开 / reopen」，且不得出现「等索引」） | `DegradedBannerWordingGuardTest`（3 例） |
| A8 | 中英 bundle 键集合全等、占位符形态合法 | `BundleParityGuardTest` |

### B. 需真机走查（自动化测不到）

| # | 操作路径 | 预期结果 |
|---|---------|---------|
| B1 | 冷启动 IDE（最好是首次索引或机器有负载时）→ 打开 demo 工程 → 第一次触发预览（gutter 行标 / 日志条目 / 快捷键均可） | 若出现降级横幅：**不关闭对话框**，等数秒，横幅应自己消失；编辑区 SQL 与出现横幅时逐字相同 |
| B2 | 承接 B1，横幅消失后检查 `.idea/sql-visualizer/preview/` | 该目录下有本轮唯一名文件（`mpsql-preview-<pid>-<n>.sql`）；关闭预览后目录回到空 |
| B3 | 承接 B1/B2，在编辑区输入 `SELECT * FROM ` 触发补全 | **补全候选出现数据源的表/列**（这是换装的实际收益；降级态下没有）。此条即计划 §七 前提 2——本环境（数据源模型 `roots=0`）测不了，必须真机确认 |
| B4 | 降级横幅出现时点右侧「重试」 | 横幅在数秒内消失、编辑器不变形（文本不变）；若预热再次失败，横幅与「重试」仍在 |
| B5 | 降级态下**手动改一个字**，等预热产物到达 | 编辑区**不得**被换装覆盖（内容与光标保持用户编辑后的样子），横幅保留 |
| B6 | 正常路径回归：预热在预算内的常规打开（同会话复开） | 全程无横幅、无「重试」动作；参数勾选、格式化、刷新等既有交互零变化 |

## 三、不属于本次交付（勿重复验收）

- **不抬预热预算**：`PREWARM_WAIT_MS` 仍为 500ms，重负载首开仍可能先降级（只是现在会自己恢复）。
- **不优化预热耗时**：VFS refresh / PSI 解析 / 方言映射的内部耗时未动。
- **P9 窄路径仍在册不修**：控制台 attach 后又 detach（未走 `clear()`）时同面板二次装配必降级——见[待分析问题清单](./20260920-待分析问题清单.md) P9。本次改动不覆盖该路径。
- **无新弹窗、无新设置项**：横幅动作是面板内嵌提示上的一个文本动作，不属于弹窗形态。
