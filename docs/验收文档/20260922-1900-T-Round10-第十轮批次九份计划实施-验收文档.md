`BannedApiSourceScanTest.kt` 少了 `TFS06自证_显式模态实参写法必报且配平不越界` 用例（176 行被删，2343→2167 行），使本批次新增的元守卫在实跑中转红（`6 tests completed, 1 failed`，点名 `anyModalityWriteOffenders（VIOLATIONS）`）；同时 `SqlStatementSplitter.kt` 被**整体还原为改前基线**（`grep -c declareSection` = 0，`git diff --cached --stat` = +4/-113），而它的新用例仍在——即「删掉修复 + 保留新用例」的自相矛盾态，此时若提交或跑门禁等于「8 例必红且 P1 缺陷回归」。复核员已核实该删除**不是实施者遗留**（实施者提交的 md5 与 HEAD 一致，文件 mtime 晚于本波提交 8 小时），而是并行的另一复核进程所留。
**处置**：主调度 `git checkout HEAD -- <两文件>` 还原（本轮实测两文件与 HEAD 逐字节一致、`declareSection` 8 处、`TFS06自证` 2 处）。

**已修②（原 major，T-Round10-01）——新增的声明段「武装条件过宽」，在非 Oracle 方言上把后续语句整体吞并（本改动引入的回归，零测试覆盖）。**
武装只要求「语句首 `DECLARE` + 后方任意位置存在 `END` 词」，不要求随后在声明段边界出现 `BEGIN`；一旦武装，顶层 `;` 直到文本尾都不再切分。复核员用同一探针分别编译基线与本实现，实测四例：`DECLARE @x INT;` + `SELECT CASE … END AS y;` 基线 2 段 → 实现 1 段；`DECLARE @a INT; SELECT 1; SELECT CASE … END FROM t;` 3 → 1；带注释头形态 2 → 1；PG 合法顶层语法 `DECLARE c CURSOR FOR SELECT … CASE … END FROM t; FETCH ALL IN c;` 2 → 1。违反计划自身的保守原则「宁碎不吞错」。
**处置**：武装条件补「后方必须存在 `BEGIN` 词」（PL/SQL 声明段之后必有块主体，T-SQL/PG 的 DECLARE 语句没有）；前视扫描抽成 `hasWordAhead` 供 END/BEGIN 共用。**反向验证（本轮实测）**：临时摘掉该判据 → 93 例 4 失败，且恰为新增的 3 条判别用例转红、正对照保持绿；还原后复绿。见 `2158a4d`。

**已修③（原 major⑤，T-Round10-02）——EXPLAIN 幂等短路的多语句旁路。**
已包装文本此前**无条件**原样返回，`EXPLAIN SELECT 1; DROP TABLE t` 整段绕过 `ExplainGate` 交回执行链
（IDE 链只有 `confirmDollarRawSegments`/`confirmUnknownParams` 两闸，没有 `executeSql` 的 DML 确认闸），
第二条 DDL 会真实执行；而首条包装成功后控制台文档恰是 EXPLAIN 文本，用户追加一句即可命中。

`isExplainableSource` 判已包装文本——PG/KingBase/H2/SQLite 的已包装文本首词是包装选项

**已修⑦（原 major③，T-Round10-01）——`END IF` / `END LOOP` 等内层终结符不再递减块深度。**
复核指出 T-SSP-01 的同族缺陷原先**只修了 CASE 一类**：`END IF`/`END LOOP` 仍无条件递减 `blockDepth`，
含 IF/LOOP 的 PL/SQL 块（匿名块与具名过程）依旧被切碎，而碎句仍会被逐条提交执行——正是本任务要消除的危害。
复核实测（改前）：`BEGIN IF 1=1 THEN NULL; END IF; END;` 基线 2 段 → 仍 2 段；
`CREATE OR REPLACE PROCEDURE p IS BEGIN IF 1=1 THEN NULL; END IF; END;` 2 → 2；
`DECLARE v NUMBER; BEGIN IF v=1 THEN NULL; END IF; END;` 3 → 2。
**修法**：`END IF`/`END LOOP`/`END WHILE`/`END REPEAT` 是**内层**终结符，不减块深度；与 CASE 层的差别在于
CASE 有**裸 END** 收尾形态故须 `caseDepth` 计数，而这四个只有双词终结形态，跳过递减即可。
主状态机与 `beginEndBalance()` 两处同口径改动，避免漂移。
**三段读数（本轮实测）**：**反向验证**摘掉两处抑制 → `SqlStatementSplitterTest` **73 例 5 失败**，
且失败**恰为新增的 5 条 IF/LOOP 用例**、正对照保持绿；还原后 **73 例 0 失败**；
`testFast` 全量 **3104 例 0 失败 6 跳过**（原 3099 + 新增 5），无更广回归。见 `239c4a1`。
