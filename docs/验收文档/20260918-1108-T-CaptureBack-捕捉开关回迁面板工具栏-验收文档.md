## 一、背景与验收前置

SQL 日志面板的「捕捉」按钮用户反馈「不见了」。两轮截图实证**按钮并非丢失，而是被迁到了工具窗标题栏**——界面原生化 T-UN-11（提交 720ca21）为退役「uiTraverser + 反射强改图标」hack，把捕捉开关从面板内工具栏迁到 `ToolWindow.setTitleActions`；而新 UI 下标题栏动作需悬停/激活才渲染，入口在用户视角「消失」，且空态文案「点击『捕捉』」与实物位置割裂。

本批次修复=捕捉开关回迁面板工具栏首位（单一入口），T-UN-11 的反射 hack 退役收益完整保留（状态刷新沿用 `updateActionsImmediately` 展示链）。

**环境**：装发行包（`./gradlew buildPlugin`）或 `runIde` 沙盒均可；新 UI（用户日常 IDE 2024.3）与旧 UI 均需覆盖。

## 三、分项验收步骤（真机走查，留人工）

### 3.1 捕捉按钮常驻面板工具栏（核心回归，T-CB-01）

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 打开 SQL 日志工具窗口（新 UI，不需要悬停标题栏） | 工具栏首行**最左**立即可见捕捉钮（▶ Execute 图标 + 「捕捉」文案），**不随悬停显隐** |
| 2 | 不悬停标题栏，直接看工具窗标题栏右上角 | **无**捕捉按钮（单一入口，未残留） |
| 3 | 点击捕捉钮 | 图标切为 Suspend、文案变「停止」，进入捕捉态 |
| 4 | 捕捉态下点停止 | 图标回 Execute、文案回「捕捉」，停止捕捉 |
| 5 | （可选）捕捉开启且尚无控制台时悬停捕捉钮 | tooltip 显示「等待项目运行——控制台出现后自动开始捕捉」（bundle 文案，非硬编码中文颠簸） |
| 6 | 旧 UI（Eclipse/经典模式）同样走查步骤 1–4 | 行为一致，按钮常驻 |

### 3.2 状态与空态呼应（回归口径）

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 空态面板（无捕获条目） | 空态文案「暂无捕获的 MyBatis SQL。点击『捕捉』后开始监听控制台」与按钮位置重回一致（按钮就在上方工具栏），不再找不到 |
