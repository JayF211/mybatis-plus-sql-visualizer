## 三、发现的新问题

### N1（中）预览编辑器装配在写不安全语境下改文档，平台记 ERROR

- 现象：重开预览（走预热回调主路径）时，idea.log 出现平台 ERROR 级告警：
  `java.lang.Throwable: Write-unsafe context! Model changes are allowed from write-safe contexts only. Please ensure you're using invokeLater/invokeAndWait with a correct modality state (not "any"). … current modality=ModalityState.NON_MODAL`
- 复现：打开任意 mapper 语句预览 → 关闭 → 再打开（即让装配走 `PrewarmAwait` 的 onReady 回调），必现。
- 证据：idea.log 第 1829-1860 行，栈为
  `PrewarmAwait.scheduleOnce$lambda$0$0(PrewarmAwait.kt:57)` →
  `resolvePreviewEditorSource$lambda$0(SqlPreviewPanel.kt:754)` →
  `assemblePreviewEditor(SqlPreviewPanel.kt:2579)` →
  `WriteCommandAction.runWriteCommandAction` → `DocumentImpl.setText` → `assertWriteAccess`。
- 根因（代码实证）：`SqlPreviewPanel.kt:523-524` 构造 `PrewarmAwait` 时用
  `invokeLater(runnable, ModalityState.any())`，回调因此在 `ModalityState.NON_MODAL` 下执行；
  而 `assemblePreviewEditor` 在该回调里调用 `WriteCommandAction.runWriteCommandAction` + `document.setText`，
  平台判定为写不安全语境并记 ERROR。
- 影响：不致命（写入仍发生、界面表现正常），但属平台契约违反，会污染日志，
  且在平台测试断言下会被升格为失败。建议回调改用可写安全的 modality（如 `ModalityState.nonModal()` 配合
  `TransactionGuard`/`invokeLater` 的写安全入口），或把文档写入挪到写动作里。

### N2（中）预览临时文件触发平台「File Cache Conflict」模态弹窗

- 现象：预览时弹出模态对话框「File Cache Conflict — Changes have been made to
  'F:\code\...\mybatis-plus-sql-visualizer-demo\.idea\sql-visualizer\preview\mpsql-preview.sql' in memory and on disk.」，
  三个按钮：Load File System Changes / Keep Memory Changes / Show Difference。该弹窗会**抢焦点**，
  使随后的合成点击全部落空。
- 复现：连续打开两次以上预览（预热线程重写同名项目内临时文件，而编辑器仍持有内存文档）即触发；
  本会话在 DELETE 预览与 UPDATE 预览两次独立出现。
- 证据：`shots/_p8_delete_dialog.png`（首次）、`shots/_p11_mismatch.png`（再次，覆盖在回滚弹窗上）。
- 说明：临时文件名固定为 `mpsql-preview.sql`（`SqlPreviewPanel.kt` 的 `projectPreviewFile()`），
  每次预热都重写同一文件，与内存文档形成冲突。真实用户连续预览同样会遇到。
  建议：每次预热用唯一文件名，或写入前先让 VFS/文档同步（避免"内存与磁盘均变"判定）。

### 6.5 关键订正：§3.3 步骤 1 的真实拦截点在参数导入对话框，不在宽度预算

上一轮把「提交空内容后提示态不出现」记为「环境受限未验证」，并把 P10（宽度预算覆盖）当作待验根因。本轮真机实测表明**这个归因不成立**，真实链路是：

1. 「导入参数」入口只有一条：`SqlPreviewPanel.kt:810` → `importParamsFromClipboard()`（`:3413-3420`）——它**不读剪贴板**，只弹 `ParamImportDialog`（对话框内初始文本为空，见 `ParamImportDialog.kt:100`）。
2. `ParamImportDialog.doOKAction()`（`ParamImportDialog.kt:189-194`）末句是 `if (text.isNotBlank()) onConfirm(text)`——**空内容直接 return，回调根本不发生**。
3. 于是 `importParams(emptyMap())` 从未被调用，`showEmptyClipboardHint()`（`SqlPreviewPanel.kt:3592-3603`）从未执行。**提示态不是「被覆盖」，而是「压根没被写出来」**——P10 修的是写出来之后的覆盖，管不到这一段。
4. 一旦提交非空但解析为空的内容（`{}`），链路立刻走通，提示态按 P10 修复后的行为完整呈现（6.2 步骤 1b~附加全部通过）。

**两条待产品定夺的口径**（本轮不改代码，仅记录）：
- 若「空内容也要给行内提示」是预期 → 需改 `ParamImportDialog.doOKAction`（空内容也回调），或把入口改成读剪贴板；**当前 P10 的修复不足以让 §3.3 步骤 1 通过**。
- 若「空内容什么都不做」是预期 → 需改验收文档 §3.3 步骤 1 的操作与预期（改为「提交非空但无法解析的内容」）。
- 另：P10 的回归用例 `SqlPreviewPanelMetaHintTooltipTest.test提示态_宽度预算重算后不被meta覆盖` 直接调 `importParamsForTest(emptyMap())`，**绕过了对话框**，故单测绿不能代表步骤 1 的真机行为——这也解释了上一轮「提示态此前只在单测里成立」的现象为何比 P10 描述的更严重。

### 7.3 本轮新发现（均为既有代码，非本轮修复引入）

#### N3（低-中）参数导入对话框在 Disposer 树中泄漏，IDE 优雅退出时被平台记 SEVERE

- 现象：IDE 正常退出（20:28:04）时平台报 3 条内存泄漏（本会话共打开该对话框 3 次，3 个实例全中）：
  `SEVERE - #c.i.o.u.ObjectTree - Memory leak detected: 'cn.song.mybatisplus.visualizer.ui.ParamImportDialog@…' … was registered in Disposer as a child of 'ROOT_DISPOSABLE' … but wasn't disposed`（idea.log:2835 起，`Plugin to blame: SQL Visualizer version: 2026.9.18`）。
- 注册栈（平台给出）：`DocumentImpl.addDocumentListener(:1072)` ← `ParamImportDialog.createCenterPanel(ParamImportDialog.kt:81)` ← `DialogWrapper.init` ← `ParamImportDialog.<init>(:59)` ← `SqlPreviewPanel.importParamsFromClipboard(:3482)`。
- 机制：`createCenterPanel` 里 `editor?.document?.addDocumentListener(listener, this)` 把**对话框自身**当 `parentDisposable`；而该对话框实例本身并未登记进 Disposer 树，`ObjectTree.register` 于是给它在 **ROOT** 下建节点，该节点永远带着子节点且无人 dispose → 退出时判泄漏。平台建议的修法就是把监听器挂到「合适的 parentDisposable」——本类已有 `DialogWrapper` 自带的 `disposable` 可用，无需用 `this`。
- 归属：`ParamImportDialog.kt:81/85`（`addDocumentListener` 与 `}, this)`）与 `dispose()` 的 blame 均为 **2026-08-20/21**（`bb673db` / `70f8383`），**与本轮 P13 改动（只动 `doOKAction`）无关**。
- 为何前几轮没看到：前两轮走查的 IDE 都是**强杀**（`MPSV-AcceptWalk` / `MPSV-P10Reverify` 的日志末尾均无 `IDE SHUTDOWN` 行），平台的泄漏检查只在优雅退出时跑；本轮是首次优雅退出，故首次暴露。

#### N4（低）从「更多」popup 直接弹模态对话框，触发平台 focus 告警

- 现象：`SEVERE - #c.i.u.p.u.PopupImplUtil - Showing dialogs in PopupStep.onChosen can result in focus issues. Please put the dialog showing code into invokeLater…`，栈为 `SqlPreviewPanel$moreActionsStep$1.onChosen(SqlPreviewPanel.kt:891)` → `importParamsFromClipboard(:3482)`。本会话 3 次（每打开一次该对话框一次），idea.log:1676 / 1829 / 2395。
