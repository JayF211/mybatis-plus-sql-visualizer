## 三、发现的新问题

### N1（中）预览编辑器装配在写不安全语境下改文档，平台记 ERROR

- 现象：重开预览（走预热回调主路径）时，idea.log 出现平台 ERROR 级告警：
  `java.lang.Throwable: Write-unsafe context! Model changes are allowed from write-safe contexts only. Please ensure you're using invokeLater/invokeAndWait with a correct modality state (not "any"). … current modality=ModalityState.NON_MODAL`
- 复现：打开任意 mapper 语句预览 → 关闭 → 再打开（即让装配走 `PrewarmAwait` 的 onReady 回调），必现。
- 证据：idea.log 第 1829-1860 行，栈为
  `PrewarmAwait.scheduleOnce$lambda$0$0(PrewarmAwait.kt:57)` →
  `resolvePreviewEditorSource$lambda$0(SqlPreviewPanel.kt:754)` →
  `assemblePreviewEditor(SqlPreviewPanel.kt:2579)` →
  `WriteCommandAction.runWriteCommandAction` → `DocumentImpl.setText` → `assertWriteAccess`。
- 根因（代码实证）：`SqlPreviewPanel.kt:523-524` 构造 `PrewarmAwait` 时用
  `invokeLater(runnable, ModalityState.any())`，回调因此在 `ModalityState.NON_MODAL` 下执行；
  而 `assemblePreviewEditor` 在该回调里调用 `WriteCommandAction.runWriteCommandAction` + `document.setText`，
  平台判定为写不安全语境并记 ERROR。
- 影响：不致命（写入仍发生、界面表现正常），但属平台契约违反，会污染日志，
  且在平台测试断言下会被升格为失败。建议回调改用可写安全的 modality（如 `ModalityState.nonModal()` 配合
  `TransactionGuard`/`invokeLater` 的写安全入口），或把文档写入挪到写动作里。

### N2（中）预览临时文件触发平台「File Cache Conflict」模态弹窗

- 现象：预览时弹出模态对话框「File Cache Conflict — Changes have been made to
  'F:\code\...\mybatis-plus-sql-visualizer-demo\.idea\sql-visualizer\preview\mpsql-preview.sql' in memory and on disk.」，
  三个按钮：Load File System Changes / Keep Memory Changes / Show Difference。该弹窗会**抢焦点**，
  使随后的合成点击全部落空。
- 复现：连续打开两次以上预览（预热线程重写同名项目内临时文件，而编辑器仍持有内存文档）即触发；
  本会话在 DELETE 预览与 UPDATE 预览两次独立出现。
- 证据：`shots/_p8_delete_dialog.png`（首次）、`shots/_p11_mismatch.png`（再次，覆盖在回滚弹窗上）。
- 说明：临时文件名固定为 `mpsql-preview.sql`（`SqlPreviewPanel.kt` 的 `projectPreviewFile()`），
  每次预热都重写同一文件，与内存文档形成冲突。真实用户连续预览同样会遇到。
  建议：每次预热用唯一文件名，或写入前先让 VFS/文档同步（避免"内存与磁盘均变"判定）。
