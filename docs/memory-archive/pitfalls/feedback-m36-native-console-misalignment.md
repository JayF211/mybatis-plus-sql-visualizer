M36.2 八轮迭代（d69e444→9b60583）曾判定「Database 原生控制台无法内嵌到插件面板」（RunnerLayoutUi 在 ContentManager 外 0 尺寸），M36.2i 转 JDBC 直连 + JBTable。**M36.4/M36.5 系列（2026-08-28~29）推翻此结论**：原生控制台成功内嵌并跑通（头部工具栏/会话下拉/结果表格/数据渲染/绿勾，沙盒逐轮实证）。

**组件甄别铁律（反编译实证，两阶段通用）**：
1. `consoleView.getComponent()` = LanguageConsoleView 拼合体（编辑器+history viewer+"Console output"占位）——必多一块
2. `logView.getContent().getComponent()` 在 ContentManager 外曾 0 尺寸；`ui.getComponent()` 只是结果区（RunnerLayoutUi）；`editor.component` 才是纯编辑器
3. 结果 Tab 由 `executeQueries` 异步创建——EDT Timer 非阻塞重试；执行后 RunnerLayoutUi 重建组件，旧引用显示停留上一轮，须限时多次重取（600ms×8，实例变化去重）换入
4. `ensureContentInitialized()` 在 BaseLogView(logView) 上；模态 DialogWrapper 遮挡原生密码框——非模态

**M36.5 内嵌成功的关键条件（缺一不可）**：
1. **编辑器塌缩防护**：editor.component 强制可见 + 首选高度 <50 兜底 200 + embedConsole 分隔保险（首触强制 40%）
2. **▶ 执行按钮启用链**：EDITOR + `SessionClientHolder.CLIENT_KEY`（=console）+ PSI_FILE——2024.3 DataValidators 拒绝 legacy DataProvider 在 EDT 同步提供 PSI（PluginException "Use DataSink.lazy"），须实现 **UiDataProvider**：EDITOR/VIRTUAL_FILE/CLIENT_KEY 同步 `sink.set`，PSI_FILE 走 `sink.lazy`
3. **原生工具栏**：`JdbcConsole.buildHeaderComponent(Editor, JdbcConsole)`（public static）才是完整原生头部（▶/Tx/会话/数据源选择器）；`addLeftToolbarConsoleActions` 只装 console 通用动作
4. **跨预览共享控制台**：每预览新建 session+连接的模式挂死（关闭旧弹窗后第二个会话连接永不发起，无日志无报错）——共享缓存（last-used 数据源一致且 isValid）直接复用，不重建 session/临时文件/方言映射
5. **方言预映射**：建临时 .sql 后、findFile 前显式 `SqlDialectMappings.setMapping(vf, MySQL)`——dumb mode 下 SqlDialectPusher 的替换被推迟，按 GenericSQL PSI 解析会静默不执行（表象"超时/无结果"而非报错）
6. **执行提交等 smart**：executeQueries 提交包 `DumbService.runWhenSmart` + generation 代际计数防串（面板清空/新预览作废挂起提交——共享控制台文档是单文档）
7. **结果区按内容出现**：contentAdded 监听（排除 Output）换入完整 SplitPane，不预嵌空占位；提示符 "rbac>" = `LanguageConsoleView.setPrompt("")`（数据源/搜索路径变化可能重设，可接受）
8. **Swing 构造必须在 EDT（M36.5.11 教训）**：任何"后台线程执行→完成后构建 UI"的路径，`new JSplitPane(...)`（含 `buildConsoleSplitPane`）必须与 `invokeLater` 换入**一体**——只包 "invoke 换入"、把组件构造留在后台线程，构造触发子组件 hierarchy 事件（editor 响应需 EDT）即抛 `ThreadingAssertions` 异常。
9. **后台 lambda 异常静默级联**：`executeOnPooledThread` 中任意 Swing 违规异常会中断后续所有逻辑且只报一次（无 "result tab not appeared" 日志）——"提示关闭弹窗才出现""第二次执行不成功"实为异常阻断，易误判为超时时机/共享缓存问题。
10. **模态弹窗冻结默认 modality 的 invokeLater（M36.5.13 教训）**：File Cache Conflict/密码框等模态打开期间，EDT 活着（用户可点击）但默认 modality 的 invokeLater 任务全部排队不执行（沙盒日志铁证：executeSql 12:10:02 → retry#1 12:10:50，48s 期间连 retry#2 都没有——Timer 未启动是因为**启动它的 invokeLater 被冻结**）——执行链所有 UI 回调（换入/startResultTabRetry/提示/探针）一律 `invokeLater(runnable, ModalityState.any())`。
11. **VFS 已跟踪文件禁止直写磁盘**：`FileUtil.writeToFile` 覆盖已在 VFS 的文件（console 编辑器持有其 document）→ `MemoryDiskConflictResolver` File Cache Conflict 模态弹窗 → 连锁冻结执行链（教训 10）。改 `WriteAction.compute { vf.setBinaryContent(sql) }`（VFS/document/磁盘三方同步）；文件不存在才写盘+refresh；WriteAction 失败兜底直写。
12. **结果区刷新去重不能只靠实例变化**：RunnerLayoutUi 组件实例可恒定（内容更新但实例不变，M36.5.10 已实证 8 拍实例恒定）——"实例变化才换入"导致新结果永不显示（用户实测第二次执行后仍显示第一次结果）；结果 Tab 出现（startResultTabRetry 命中）即 `forceSwapIn` 强制换入一次，换入后置 swapped 防重复，实例变化路径仍保留。
13. **提示符需每拍压制**：DatabaseLogView 在执行/数据渲染后重设 prompt（prepare/reuse/入口清理后仍重现，用户三轮实测）——refresh Timer（600ms×8）**每拍** `setPrompt("")` + 执行换入后清一次；彻底移除需反编译注销 LogView 重设监听，成本高不做。
14. **执行内容"滞后一轮"终局方案（M36.5.14~21d）**：自建 ScriptModel 传给 `executeQueries` 的路线**全部不可靠**——缓存引用（isActual() 误报新鲜）/ getScriptModel() 重取（返回同一实例）/ createROFile 文本直构（statements() 反射即抛，RO file 缺 DBN 会话上下文）/ vf PSI model（三要素日志证明 model+语句+PSI 全对仍执行旧内容——executeQueries 内部状态依赖）。**终局 = 原生两步链**：`JdbcConsoleProvider.findScriptModel(psiFile, psiElement, editor, execOption)` → Info → `doRunQueryInConsole(console, info)`（两个 public static，完全复刻 Ctrl+Enter，与原生动作同源无分支差异）。
15. **doRunQueryInConsole 必须 EDT + write-safe 事务**：内部 chooseStatements→saveAllDocuments 属 model 修改，要求 write-safe context——pooled ReadAction 里调抛线程违规；`invokeLater(runnable, ModalityState.any())` 是 **NON_MODAL write-unsafe**（TransactionGuard 抛 "not any"）。正确写法：`TransactionGuard.getInstance().submitTransactionLater(console as Disposable) { findScriptModel + doRunQueryInConsole }`——与原生用户事件同机制，事务挂 console 为 Disposable（面板关闭取消挂起事务）。**不阻塞等待**：pooled 持读锁等 EDT 有死锁风险，且超时后兜底 executeQueries 会重复执行。
16. **三要素日志一击判定**：执行前打 `executing model: class=SqlScriptModel, stmts=count=N, vfPsiText tail=...`（model 类型/语句数/PSI 内容）——vf PSI 须先 `WriteAction` 同步 console 文档 + **显式 `PsiDocumentManager.commitDocument(fileDoc)`**（同 tick 内 findFile 的 PSI 才对齐，否则解析 commit 前旧内容=滞后一轮）。语句元素取值用 **`StatementIt.query()`**（元素非 PsiElement，cast 恒 null）。
17. **execOption 禁用 new 空实例**：`DatabaseSettings$ExecOption` new 出来 execSelection=0（非法值）→ ScriptModelUtil.getSelectedStatementsRange 按空选择解析 → getTextRange()=(N,N) 零长度 → ▶ 恒灰。用 **`DatabaseSettings.getDefaultExecOption()`**（public static 原生默认配置）。
18. **反射探针必须核对 invoke 语义（M36.6.2 教训，假阴性第 2 次）**：`EvaluationHelper.isStatement` 是接口**实例方法**（EP:LanguageExtension 分发），探针 `invoke(null, api)` 以 null 接收者调用必抛 NPE 被 runCatching 吞掉 → `isStatement=null` 自 M36.5.24 起一直是探针自身假阴性，误导 24d/26 两轮方言修复方向。正确链路：`EP.forLanguage(model.language)` 取实现实例 → 实例调用。探针读数异常时先怀疑探针本身。
19. **▶ 启用链字节码事实（M36.6.2 取证）**：启用链模型来自 `DatabaseScriptingSessionClient.getScriptModel()`；`ScriptingDatabaseSessionClientHolder extends SessionClientHolder<JdbcConsole,...>` 即 client=JdbcConsole 本体（我们替换的 myScriptModel 可达）。caret=0 时空 selection 分支只探测 `subModel(TextRange(0,1))`（前两个字符）——`probe01` 探针复刻此行为判定 subScript 语义。
20. **内嵌组件不拉伸填充容器的表面性"空洞"（M36.5.59，BorderLayout vs GridLayout）**：`editorComponent` 包装层用 `BorderLayout.CENTER` 尊重子组件（DBN 控制台编辑器）preferredSize（按行数推算、非拉伸）——编辑器只在 topBlock 顶部渲染 ~4 行高，下方留大片面板底色空洞。**判据**：分隔条落点正确（60/40）但子组件占不满分配区——分隔条在 60%，空洞在 topBlock **内部**（逐像素扫描：编辑器暗色框 ~80px，topBlock 区延伸到结果区，中间全为面板底色且无分隔条线）。**修正**：嵌入别家组件到固定大小容器，用会强制填充的布局 `GridLayout(1,1)`（与 editorHolder 同机制），并解除子组件 `maximumSize` 上限（Int.MAX_VALUE），避免 preferred 推算压回。
21. **预览切换残留上个 SQL 回显（M36.5.62，Output 历史未清）**：DBN 每次执行/预览把写入 SQL 回显到 `LanguageConsoleView` 的 `historyViewer.getDocument()`（Output tab 渲染此文本）。`clearResultContents` 只 `ui.removeContent` 移除 **result Content**（`isOutputContent` 过滤会**保留 Output Content**），移不掉历史回显——预览 SQL A 时下方仍显示之前 SQL B 的回显。**修正**：预览（execute=false）路径除 `clearResultContents` 外再 `clearConsoleHistory`（反射 `historyViewer.getDocument().setText("")`）；**执行路径不清**（需重新回显 + `consoleErrorBaseline` 依赖历史基线，清空会改变基线语义）。
22. **外层布局对、内层结果页塌缩（M36.5.63，"Restore Default Layout" 可修复）**：结果区只显示 Output 一行、结果网格不显示，但点 DBN "Restore Default Layout" 即恢复。`[BOUNDS]` 证实**外层** JSplitPane 落点/尺寸全对（bottom=MyNonOpaquePanel 有完整高度、结果 Tab 已选中），问题在**结果区内部**——DBN 结果页（RunnerLayoutUi 结果网格）自带 Output 消息区/结果网格的 **sub-split**，re-parent 后内部状态未重算，`setDividerLocation` 只调外层、内层塌缩（Output 一行）。**判据**：外层 bounds 正确但结果显示"只有 Output 一行" → 必有内层 JSplitPane 塌缩；逐像素"结果区小"易误读为外层塌缩。**对策**：需对齐并校准**内层** sub-split divider（递归找结果区内的 JSplitPane 设 divider），而非再调外层。
23. **结果区塌缩到 preferred（M36.5.64，Output 没撑满下方空白）**：DBN 结果区（RunnerLayoutUi grid）preferred=84px（只够 Output 一行），re-parent 后 JSplitPane 每次重排把 bottom **拉回 preferred**（`bottom=MyNonOpaquePanel bounds=[0,572,903x84]`，`topH=569 total=656`=86%）。`realignDividerOnce` 的 `force=false` 分支**只校正"顶部过小"**（`topH<total*0.35`），漏掉"顶部过大/结果区塌缩"方向——塌缩后永不触发。**修正**：①`realignDividerOnce` 双向校正（`topH > total*0.68` 也拉回 0.6）；②bottom（结果区）设 `minimumSize`（>=160px），JSplitPane 无法压回 preferred。
24. **GridLayout 不撑开 DBN 编辑器（M36.5.65，编辑器组件未填满 topBlock）**：DBN 编辑器（`editor.component`）自身带 header(35px)+编辑器视图（`PanelWithFloatingToolbar`）的内部布局，`PanelWithFloatingToolbar` 用 OverlayLayout 让滚动窗（MyScrollPane）保持 preferred 高度（368px）**溢出父容器（199px）**。`GridLayout(1,1)` 只把编辑器组件分配到部分高度（`top.child[0]=...x234` 在 403px topBlock 中），编辑器只按内容高 paint，剩余面板底色空洞。**修正**：编辑器包装层（GridLayout）加 `componentListener`，随父容器 resize 强制 `editorComponentRaw.setSize(父宽, 父高)` + revalidate——任何布局管理器下 DBN 编辑器都被强制填满 topBlock。
25. **外层布局修复后的剩余空白 = Output 控制台（M36.5.66 验证→68 纠正）**：M36.5.64（bottom min=160 + realign 双向校正）+ M36.5.65（编辑器 setSize 填满）后，`[BOUNDS]` 证实 `top=402px/bottom=270px/divider=60%/select=Result 5` **全部正确**——外层布局修完。**关键教训：有效 SQL 渲染 Result 4 网格正常，问题 SQL（Unknown column）时 Output 控制台**应撑满**下方、方便查看信息——曾被我误判为"文本控制台自然留白"（M36.5.66），用户纠正后（M36.5.68）证实是 Output 内容视图没被拉伸（`JBScrollPane`=0x0，文本只在顶部渲染）。**判据**：报错查询下结果 grid 无数据行，DBN 切回 Output 控制台是**对的**，但 Output 控制台本身的文本滚动视图须撑满；需加深 dump（[TEXT] 扫 JScrollPane/ConsoleView/JTextComponent 实际 bounds）定位谁没撑满。
26. **Output 控制台内容组件被压到 44px（M36.5.69，forceOutputConsoleFill——已回退，勿复用）**：`[TEXT]` 探针（递归 12 层）实证——问题 SQL 时结果区内容容器 ProviderWrapper=228px（填满），但内部 Output 编辑器 `EditorImpl$PanelWithFloatingToolbar`/`MyScrollPane` **只 44px**（工具条高），其 `EditorComponentImpl` 内容 2574px 被滚到 y=-2530（用户看到 Output 只一行 + 下方大片空白）。这是 DBN EditorImpl 组件**不随父容器拉伸**（与 M36.5.65 顶部编辑器块同机制）。**⚠️ 修正方案 `forceOutputConsoleFill`（无差别 setSize 递归结果区）副作用极大——把结果 grid 也弄空白（用户实测 Result 1/Result 5 标签 + 空白网格），已整体回退（5a4904e）。教训：DBN 结果区是 RunnerLayoutUi grid（消息区/结果区自适应），无差别 setSize 会破坏 grid 单元格布局，属过度工程，勿再用。**

29. **Output 撑满必须取"大祖先"高度，非直接父（M36.5.72/73）**：M36.5.72 `fillOutputConsole` 用 `c.parent.height` 作目标高度——Output 编辑器的**直接父**是中间一层小容器（44px），`parent.height>50` 判 false 被跳过，Output 编辑器仍 44px（用户实测大小不够）。`[BOUNDS]` 证实 GridCellTabs/ProviderWrapper=234px（结果区内容容器有高度），但 Output 编辑器链中间层只有 44px。**M36.5.73 修正**：`findBigAncestor` 向上遍历取最近 **>100px 大容器**（ProviderWrapper/GridCellTabs）高度作目标再 setSize；类名精确匹配 `EditorImpl$PanelWithFloatingToolbar`/`MyScrollPane` + 只在结果区（bottom），不误伤结果网格。**教训**：DBN 嵌套容器链中间层常把高度压成工具条（44px），直接父高度不可靠，须向上找大容器。

28. **Output 有内容但大小不够（M36.5.72，fillOutputConsole 精准撑满）**：M36.5.71 直写 history doc 成功（Output 有内容），但 Output 编辑器滚动视图只 44px（视作工具条高），内容 352px 被滚到 y=-308，用户看到 Output 只几行 + 下方空白（结果区 270px 没被利用）。**与 M36.5.69 的区别**：`fillOutputConsole` **只在结果区（bottom）内**找类名**精确匹配** `EditorImpl$PanelWithFloatingToolbar`/`EditorImpl$MyScrollPane` 的 Output 编辑器组件，setSize 到父容器可用高度 + viewport view 撑到可滚动区域——类名精确匹配，结果网格的 JBScrollPane/DataGrid 类名不同，绝不误伤。**⚠️ stale-class 陷阱**：`buildPlugin` 曾打包旧 class（`build/classes/java/main` 残留导致 jar 仍是旧 stamp），沙盒 jar 未更新——须 **`clean buildPlugin`** 重建并 grep jar 内 class 验证（memory: project-sandbox-jar-file-lock）。

27. **问题 SQL 时 Output 控制台空白（M36.5.70/71，直写 history document）**：回退 M36.5.69 后布局恢复（有效 SQL Result 2 网格正常），但问题 SQL（Unknown column）时 Output 空白、无信息。`[TEXT]` 探针确诊：`extractConsoleError` 能读到错误（historyViewer document 有文本），但 Output 内容视图 `JBScrollPane`=0x0（`[0,0,0x0]`，viewport=[-2,-2]）——DBN 报错（无结果行）时把 Output 内容滚动视图布局成 0x0，错误文本在 document 但不显示。**M36.5.70（走 `ConsoleView.print(String, ConsoleViewContentType)`）失败**——`com.intellij.execution.ui.ConsoleViewContentType` 枚举类在平台**不存在**（全 IDE jar 只搜到 CWM 同名 `ConsoleViewContentTypeModel`），反射 `Class.forName` 在 try 里 return，print 静默跳过仍空白。**M36.5.71 修正**：`writeConsoleOutput` 优先**直写 `consoleView.getHistoryViewer().getDocument()`**（`WriteCommandAction`+`insertString`，这是 Output 实际渲染的 document，`extractConsoleError` 正是读它）+ invokeLater 滚到底（caretMove+scrollToCaret）；`ConsoleView.print` 仅作兜底。不依赖枚举类、不破坏结果区布局。**教训**：反射 `Class.forName` 类不存在时须打印日志而非静默 return（M36.5.70 正是静默返回导致无效）；DBN Output 显示的 document = `getHistoryViewer().getDocument()`。

**Why:** M36.2 的"架构性不可解"实为组件时机/数据上下文缺失（编辑器未布局 0 首选高度、嵌入面板无数据上下文、dumb 期方言未定），非架构限制——补齐可见性兜底 + UiDataProvider + 共享复用/等 smart 后成功。
**How to apply:** 内嵌原生 Database 控制台按上述 9 条件逐项核对；探针读 PSI 必须包 ReadAction（EDT 无 read action 直查 lazy PSI 被校验器拦，动作线程 BGT 不受影响）；后台执行完成后的 UI 工作一律整块包 invokeLater。关联 [[project-m36-direct-execute]] [[project-sandbox-jar-file-lock]]。
