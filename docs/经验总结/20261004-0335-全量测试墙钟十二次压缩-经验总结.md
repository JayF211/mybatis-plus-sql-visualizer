# 全量测试墙钟十二次压缩（T-TestPerf14）经验总结

> 2026-10-04，分支 `t-testperf14` 自 `t-testperf13` tip `509759e`（dev 系，D48 可快进位）；台账与定案详版见计划文档 §七。
> 结论先行：本轮没有找到新物理杠杆（T13 已收割殆尽），交付的是**存量杠杆的兑现机制**——auto-handicap（T13 裁定规则的机制化，A/B 实测 −7.7%）+ testDatabase 五类并行化（串行段首次实测后并行化，warm 墙钟 −50%+）。机制收益实测为真，但因 auto 轮暴露顺序依赖竞态，**D45 定案缺省关**——收益在册、开关留用户。

## 六条认知

1. **「实测过但不常在」的杠杆比新杠杆值得先找**。T13 的 handicap A/B（−7%，4/4 方向一致）收口后躺在「触发条件入册、等人盯告警手工加参」状态——恒临界窗口的收益实际处于无人兑现状态。本轮把它机制化（历史落盘+配置期自动判定+因子现算+过补自愈），同窗 A/B 立刻兑现 −7.7%（off 中位 183s vs auto 169s）。轮次台账：R1(off, 183.4s 窗)→R2(auto, 炸)→R2b(auto, 169s)→R3/R4/R5(off, 183/196/182s)→R6(auto 自然重触发, 炸 1 例)。触发/断链/重触发的自动序列全程按设计工作（R2b→R3 断链、R3~R5 三连后 R6 重触发、因子 0.82→0.88 随近期超权现算）。

2. **自动改分区=把顺序依赖地雷从「固定埋点」变「随机踩面」**。auto 轮 3 轮中 2 轮踩响 SqlPreviewService 族竞态（R2 炸 20 例：OfficialApiTest 18/39 单行 ComparisonFailure=T13 O-97 同款+TenantTest 2 例租户注入残值；R6 炸 1 例 BatchTest=O-93 族当事类，定向 31s 复绿），off 侧 5 轮全零。补偿本身数学正确、R2b 证明零失败兑现 −7.7% 也为真——但「门禁红即需人工」的概率性失败违背「测试效果不能变」的实用语义，**D45 定案缺省关，等 O-97 根因修复再翻默认开**。这是继 T9 DisableExplicitGC 之后第二条「性能机制与测试语义边界冲突」实证，且这次冲突面不在断言层而在状态泄漏层。

3. **O-97 从「冷轮偶发」升级为「分区/时序敏感竞态」**。T13 只在 R0 冷轮见过（18/39），本轮 R2 证明 warm+分区变化也能踩响（同注入历史复跑 R2b 零失败=非确定性）。分区大搬家（补偿/片数/画像刷新/新增测试类）都是潜在触发面。修复线索增补：R2 shard4=117 类快照、SqlPreviewService 同族多类同片（JpaCrud/OfficialApi/Tenant/XmlInline）、失败 XML 归档 `build/fail-evidence/r2|/r6`。该族前有 O-93 方言残值（已修两处），渲染状态泄漏疑似同一治理面上的第三处。

4. **自动控制系统的反馈信号要选「补偿后仍超阈」，不是「形态偏离预期」**。初版过补判定含「临界换到非目标槽」——但补偿成功后目标槽变轻、临界换片恰恰是到位的预期形态，该条件会把成功误判为过补。同理，「可比集剔除 auto 轮后取尾 3」会保留补偿前的旧 3 连导致 cooldown 后立即重触发（振荡）；改成「按时间序尾 3 轮插队即断链」才真正防振荡。两条都在实施中自查修正、dry-run 构造样本 8 组锁定。

5. **buildSrc precompiled script plugin 的配置缓存追踪可靠**：`providers.gradleProperty`（-P 变化）与配置期文件读取（jsonl 内容变化）都正确驱动 CC 失效重算（干净实验双证实）。「CC 对 buildSrc 插件内读文件不追踪」的担忧不成立；反向教训是排查时先查自己的操作序列——一次「显式开启没触发」的假警报实际是前一轮收尾 `rm` 了历史文件（零历史不触发正是设计行为），加上 grep 管道 `$?` 取末命令退出码造成的误读。

6. **testDatabase 串行段的账首次算清**：五类 296s execSum（DbConsole 131.6s+DbSelector 140.6s 占 92%）+5 次 JVM 冷启，串行执行段 ~356s——T13「+2~3min 注释口径」实为 +6min 档。拆五任务并行（每类独占 JVM+独占沙盒，隔离只增不减）后 warm 墙钟 2m44s（max suite 172s），计数 10/0/0 与串行恒等零 skip。`forkEvery=1` 的「类间换 JVM」隔离语义由「每类一任务」无损承载；实施中抓出一处致命遗漏——`withType<Test>` 的 database-jar classpath 豁免按任务名 `testDatabase` 特判，新任务名不命中会误剔 database jar 全炸，改前缀特判（**新增按名分流的配置时，改名/拆任务必须全仓 grep 任务名引用**）。

## 地板声明更新（供下一轮立项对照）

5 片时长均衡栈的墙钟地板维持 ≈2m30s~3m00s @ 6395 例（本窗 warm 带 165~196s，窗口漂移 ±5~8%）：T13 物理面已关账，本轮机制面（auto-handicap）实测 −7.7% 但因竞态面默认关。**剩余可做**：①O-97/O-93 族渲染状态泄漏根因修复（修成后 auto-handicap 翻默认开，恒临界窗口自动 −7%）；②auto-handicap 机制已在役，任何树显式 `-PtestShardAutoHandicap=true` 即可用（恒临界历史攒满 3 连自动启用）。物理面新入口仍为零：片数/均衡/拆分/外部分离桶/JVM 参数面/bootstrap/固定 sleep 全部销案维持。
