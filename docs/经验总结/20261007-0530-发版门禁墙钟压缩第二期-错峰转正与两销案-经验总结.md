## 一、一句话结论

releaseGate 的长杆 verifyMarketplace（在线解析，solo warm ≈589s）**前段 ~285s 是双核满负荷解析、后段 ~7 分钟是低占用等待窗**——把 verifyGate 与 5 个测试分片的启动延迟 285s 嵌入等待窗，market 争用系数从 +86~165s 压到 ≈+77s，总墙钟 −10.8%，五环节口径零变化。

## 二、三条窄缝的定案读数

### N1 时间性错峰（转正，D80）

- **探针**（proc-sampler.ps1，5s 间隔按命令行分角色采样）：market 进程 warm 曲线=START 后 ~285s 高占用（CPU 141~199%）→ ~7 分钟低占用（多分钟 <40%，最低 5.1%）；gate 进程恒高占用 200~275%。
- **实验**（整链交错 B1→A2→B3）：B 组 {666, 679}s vs 浮动 {766(R1), 742(A2)}s = **−10.8%**；market 自身 744.3 → 666.1s；分片窗 208s → 153.6~176s（回 solo 带）。
- **实现**（`f5cda71`+`e2b7790`+`32e4af8`）：`-PgateStaggerMs`/`-PtestStaggerMs`，doFirst 内 sleep；缺省值接 `invokedTaskNames`——`releaseGate` 编排内自动 285000ms，verifyGate 冒烟/日常 testShards 缺省 0，显式传 0 可关。
- **安全方向**：market 高占用段变长 → 分片尾段与其重叠（小伤）；变短 → 低占用段空转（无伤，market 恒为长杆）。

### N2 verifier JVM 堆（免跑销案，前提 B 命中）

market/gate 进程 Commit 峰值 2.8GB/2.3GB，双双 <3GB 判据线——缺省堆（8GB 上限）绰绰有余，GC 非瓶颈。verifier-cli 无对外堆旋钮的必要，A/B 免跑。

### N3 testHeapSize 512m（销案关账，T-TestPerf2 P9 悬案落地）

干净四轮交错（2g→def→2g→def，全绿 6522/0/0/9 恒等）：片均值 2g {137.6, 136.4} vs def {134.4, 135.8}——**2g 慢 +1.4%**；整链 2g +4.7%（临界、方向为负）。维持缺省 512m，与 T5/T9「JVM 旋钮无赢家」闭环。

## 三、方法论沉淀（照抄价值最高）

1. **进程级曲线是争用类问题的唯一裁决**：T6 只采全机 Commit，「浮动结构最优」只能推理；本轮分角色 CPU 曲线直接看见「前段满负荷+后段空转」的嵌入窗，推理变实测。采样器 `dev-support/proc-sampler.ps1` 已入库（按命令行分 gate/market/test 角色）。
2. **「重排序=串行化」的推理有漏洞**：max() 结构下，只要短任务总时长 < 长杆时长，把短任务整体搬进长杆的空闲段就是纯收益——错峰不是重排序，是**填充**。
3. **计时实验窗口内禁 buildSrc 变更（连并行提交都不行）**：工作树文件即跑即读，S2 首轮四轮作废重跑。R11「禁夹带」的加强版。
4. **配置缓存坑第二次现身（T-ReleasePerf-05 同款）**：脚本顶层 val 被 doFirst lambda 引用=持有脚本对象引用不可序列化（BUILD FAILED 而任务本体全绿的分裂形态）。修法恒定=声明挪进 register 块内为局部值。
5. **flake 名单新增两成员**（均负载敏感、定向双复绿）：`HistorySqlLogPanelPreviewTest.testV2带参条目预览构建参数行与日志页一致`（S2 首轮 round4）、`ExecDocSyncTest.testBoundedDispatchDefersWriteWhenContextUnsafe`（「2s 预算」时序断言，S5 首轮 2112ms vs 2000ms）。加上 A2 轮的 `SenderLoopBackoffTest`（T6 已在册），本轮三例 flake 全部与改动无关——判定依据=定向复绿+失败形态与在册家族同构。
6. **e2e 的 demo 工程是共享活体**（`612fdb5`）：demo `target/classes` 被 -Dprofiles.active=dm 重编后 e2e 静默吃达梦驱动→织入改写 VerifyError→应用起不来 23 例失败。修法=e2e 启动命令行钉死 `--spring.profiles.active=mysql`（须放主类名之后，放 `-cp` 前被 JVM 当自有选项 fatal）。

## 五、遗留与建议

- stagger=285s 是本机当前校准值（market 高占用段时长）。verifier/marketplace/网络形态变化时按 proc-sampler 曲线重校；错峰过头的代价方向安全（见 N1 安全方向）。
- releaseGate 的新地板：**暖窗 ≈10.2~11.2min（S5 权威轮 613.1s 实测 / S4 B 组均值 672.5s），常规争用 ≈11.5min**——对 T6 地板（11m23s/13min）改善 −8%~−22%，对 v2026.10.6 发行日 13m11s 为 −22.5%。
- N2/N3 销案后，JVM 参数面全清单无悬案；testShards 本体维持 T15 地板（本轮 4 轮全绿 6522/0/0/9 再证）。
- S5 权威轮三次启动：首跑 testShard5 一例时序 flake（`ExecDocSyncTest`「2s 预算」断言 2112ms，定向复绿）；二跑 marketplace 代理 SSL 掐断（环境性，探活恢复后复跑）；三跑全绿 613.1s。在线门禁的失败重试属发行日常，两例均非改动引入。
- 错峰形态 Commit 峰值 73.61GB（S5 实测，余量 1.1GB 偏紧）——归因系统底噪浮动带而非错峰（并发任务集与浮动相同），R15 单车道+Commit 预检纪律不变。
