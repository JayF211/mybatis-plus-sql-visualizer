## 二、本轮最有价值的认知

### 1. 门禁可以「看起来全绿」地少跑——聚合报告读的是文件不是任务

分片任务因 MPV-Build 时间戳（Jar 恒重跑）+prepareSandbox 链**每轮必真跑**，而 testExternal 与 `:sql-visualizer-agent:test` 的 classpath 不含插件 jar，无源码变更的连跑会被 Gradle 判 UP-TO-DATE 静默跳过——**聚合报告照读上一轮的旧 XML，护栏「本轮已验」是假的**。识别特征＝桶读数两轮完全相同（59.4s==59.4s）。修法＝两者 `outputs.upToDateWhen { false }`（墙钟代价≈0：与分片并行且早收）。定例：**给聚合门禁新增旁路任务时，必须同步决定它的 up-to-date 语义与主链一致**；看门禁结果时对「完全相同的耗时读数」保持怀疑。

### 2. buildSrc 变更的真实代价链比「+2 分钟重编」更长

R4/A1/收口三个 ~5m10s 异常轮的共同真身＝buildSrc 触碰 → 配置缓存失效全量重配置 + **compileKotlin/compileTestKotlin 全量重跑**（惯例插件 classpath 进编译输入，~2-2.5min）——不是玄学空转，收口轮日志直接实证（"Configuration cache entry reused" 同时两次 Kotlin 编译带全量 warning 重跑）。定例：**计时实验轮之间禁夹带 buildSrc 改动**（T-BuildConcurrency 老坑的实验设计版）；buildSrc 改动集中一个提交、改完先跑一轮废轮付税，再开始计时。

### 3. cold 画像会伪造「原子巨类群」——先鉴别数据温度再定拆分名单

cold 轮逐类权重冒出一批 36~40s 的 1~4 例巨型类，形似「不可拆的原子山群」；warm 数据揭开真相：**真原子只有 SqlPreviewPanelTest 41.9s 一座山**（次档 14~18s），那些 38s 单例类是平台子系统首启摊销落在谁头上谁显大。与 T5「拿历史 XML 画像前先鉴别是否 clean」同族的姊妹教训：**拿 cold 数据做拆分/均衡决策前先鉴别数据温度**——本轮若按 cold 名单去「拆」1 例类，一行都拆不出来还白付维护面。

### 4. 方法级跨片拆分是「类原子性」的结构解法，但天花板由次档原子决定

S3 把 73 例巨类按实测逐例权重贪心对半（fragA 21.9s/37m 留主体片 + fragB 21.8s/36m 挂最轻他片），配置期同一份数据生成 include/exclude 互补清单（防双跑/漏跑），union 断言入日志；新增用例自然落主体片、删例残留 pattern 无害＝零维护。红线安全：零删例（并集断言）、零断言改动、隔离只增不减（两 JVM 各自完整 bootstrap）。收益 −1~3s 的原因也诚实入账：**拆掉最大原子后，临界片由 14~18s 次档原子+贪心装箱效率接管**——这类杠杆的价值随头部类增长复利（该类一天内 72→73 例），当期数字小不代表结构价值小。

### 5. flake 在册四年口径的三次升级空间——读码定位机制，处置仍守红线

FatalPassthroughTest 回调计数竞态（expected:<1> was:<2>）今日 3 次，首次**读码定位到机制**：AgentSession 的 sendConfig catch 与 init 读循环 catch 双双触发 onStateChange，假 socket 读侧快速失败时计数=2，纯竞速。读码能定位≠能修：收敛它必须改断言语义（判 1~2 或过滤回调类型）＝撞「零断言改动」红线。处置维持 T5 定例（定向复跑+登记不修码），**机制定位写进台账**留给后续单独立项（用户定案红线口径后再动）。

### 6. 其余销账与登记

- S2 片数保质期第四次触发：6 片两轮同向赢 5 片（−1.9%/−6.1%）但合并中位 −2.0% 未过 5% 判据，且 Commit 峰值 66.1GB 余量 8.6GB 贴线——**维持 5 片**。负结果入账防复立项；execSum 并发膨胀率从 T7 时代 +39% 收窄到 +17~29%（卡巴斯基排除确实削了 IO 争用），负载再变时按同法重测。
- S4 尖刺复扫：6 站 ≥13s 尖刺全部无 sleep/await 轮询形态＝动作 update()/设置树实例化固有成本（T7 已定性），零改动销账；testExternal 无新候选（头部权重类全需平台沙盒）。
- V1 诚实订正：卡巴斯基 −28% 单轮读数（1m48s）系成熟沙盒+黄金窗口产物，新树不可迁移——**绝对值比较永远同窗交错，跨树读数只看相对量级**。
- 均衡器对「片数切换」有数据面畸变：权重采样只扫 1..N 目录，切换片数后首轮的预期均衡失真（6 片轮预期 91.1 vs 实际 111~140），交错第二轮起收敛——片数实验至少两轮/配置的又一理由。
