## 二、本轮最有价值的认知

### 1. 「重复劳动消除」与「固有成本」要分开算账——墙钟的天花板由重类固有成本决定

测试实现层的慢分两类：**重复劳动**（同一信息被反复获取：全盘遍历、全仓重读、skip 前的昂贵发现、串行外部进程）和**固有成本**（UI 平台测试的 EDT/fixture、PSI 解析、沙盒 JVM 启动）。前者可以零语义风险地消除（本轮收割 ~104s execSum）；后者是墙钟的真正决定者——**关键路径片里 SqlPreviewPanelTest 43s 巨类（单类原子、单例 0.2~1.3s 均匀分布、无重复劳动）+ 失衡涨落支配墙钟**，execSum 降 14% 传导到墙钟被失衡方差和窗口漂移完全淹没（3m08s vs 3m10s）。**推论：改测试实现层能买到的墙钟已经买完了；再往下只有合并用例（删减）或共享可变 fixture（改隔离语义），两者都撞红线。T-TestPerf5 的「地板水位」结论在实现层压缩之后依然成立。**

### 2. ZCode 沙盒新建的源文件对 gradle 编译不可见（本轮最大坑，机制未明，解法可复制）

工作树里经 ZCode 工具（Write/printf 跨调用/cp）新建的 .kt 文件持续不被 compileTestKotlin 编译：源清单里有它（`--info` 日志 "Kotlin source files:" 可见）、文件系统上真实存在（非沙盒进程可读）、但编译器解析不到（引用方报 Unresolved reference）。实验矩阵里唯一的可靠通道是 **bash 同调用内写文件+编译**（printf/cat heredoc 落盘后紧接 gradlew 即可见）；Edit 修改既有文件不受影响。已观测细节：小体量 printf 新建文件偶发可见（3 行探针两次成功）、138~142 行含 KDoc 的文件 100% 不可见——机制未查明（VFS/配置缓存/增量状态/属性/沙盒视图逐一排除）。**定例：会话内新建源码文件一律 bash heredoc 落盘并在同一调用内触发编译；文档（不参与编译）不受限。**

### 3. quoted heredoc 吃一层反斜杠——带正则字面量的 Kotlin 源码不能走 heredoc

`cat << 'EOF'`（quoted）按 POSIX 不应展开转义，但本机 Git Bash 实测把源码里的 `\d` 写成 `\d`（Kotlin 字符串随即报 Unsupported escape sequence）。解法：正则字面量改 Kotlin raw string（`Regex("""\.\d+\.""")`）绕开，或经 python（bash 单引号包裹命令）写入。顺带：用 python 字符串拼接生成 Kotlin 代码块极易转义套娃出错（本轮 companion 块三处损坏：正则被吃、`\n` 变真实换行、chr(92) 未求值）——**生成代码用 Edit 工具修改既有文件，新建文件用 heredoc 时逐字节校验关键行**。

### 4. doLast 引用脚本顶层 val 炸配置缓存（mpv-testing 首见实例）

聚合报告给分片打标签时写了 `if (idx < testShardCount)`——testShardCount 是脚本顶层 val，doLast 执行期引用即 "cannot serialize Gradle script object references"。解法：标签改用 `dir.name`（testShardN 目录名即标签）。此前 mpv-testing 注释里「doLast 只做文件 IO + 读 inputs」的纪律多了一条具体形态：**执行期连脚本顶层标量都不能摸**。

### 5. 新工作树的权重表冷启动滞后一轮

B1 用旧权重分区（关键路径片 174s 失衡 29%），B2 起新权重回正（预期 132.4×4）但撞上劣化窗。与 T-TestPerf5 §二.4（新树权重表被冷跑污染）互补：**新树前两轮分片的墙钟读数不作数**。
