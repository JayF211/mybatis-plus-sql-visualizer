# 全量测试墙钟七次压缩（T-TestPerf9）经验总结

> 2026-09-29，分支 `t-testperf9` 自 master `bee2019`；17 轮台账与定案详版见计划文档 §七~§九。
> 结论先行：四旋钮＋片数复测全部无赢家，墙钟与 T8 持平带同档——本轮价值＝段级拆账地基＋负结果二代证据链＋一条语义红线新知。**构建侧可压缩空间已到地板**。

## 六条认知

1. **运行时 flag 不是天然语义中立**。`-XX:+DisableExplicitGC` 让 ConflictProbeProjectRetentionTest（弱键集回收断言「强引用消失+GC 后应被回收」）确定性变红——它依赖 `System.gc()` 真回收。「JVM 参数只是调性能」的直觉在 GC 依赖型断言面前不成立；任何运行时 flag 进测试 JVM 前都该 grep 审计 `System.gc()`/弱引用确定性依赖。这是本项目继「守卫可能看不见目标站点」之后又一条「防护面自以为中立实则越线」的实证。

2. **段级拆账三源法（--profile + 任务起止时间戳 + JUnit XML exec）一次立起全链账**：墙钟 161s ＝ 启动+配置 ~2s ＋ jar/composedJar 1.1s ＋ prepareSandbox×5 并行 ~0.1s ＋ 临界片任务 156s（exec≈143＋bootstrap≈13，bootstrap 并行不叠加）＋ agent:test 42.5s 早收。**开销带合计 ~4s，墙钟 97% 在分片窗口**——T2~T8 反复猜测的「固定开销」从此有实数；后续任何提速轮先对照这张账再立项。

3. **线程面假说二代证据链闭合**：T5 一代 ActiveProcessorCount（压应用线程池）无收益曾被解读为「可能帽错了对象」；本轮二代（GC 工作线程帽 −2.5%、JIT 编译线程帽 +11% 反向、禁显式 GC 语义破线、TieredStop −2.4%）全数无赢家——两代合流结论＝**5 并发平台 JVM 的自带线程争用被 6C12T 自然吸收，不是墙钟主分量**，此路线彻底销案。

4. **跨树借权重预热合法且高收益**：同 repo 同基线的 `build/test-results/testShardN` XML 拷入新树（本地构建数据不入 git），首轮分区即 5×135.1s 完美均衡＋S3 拆分激活，跳过冷启动两轮失准期（T8 为此付过 749.9s execSum 和两轮不作数）。附带发现：`register` 过期续期＝`done --name` 后重新 `register`（同名直接重注册会拒）。

5. **临时采集工具有、正式脚本没有的坑：陈旧分片目录污染 exec 聚合**。片数切换后的下一轮，`testShard*` 通配会把上一片数的残留 XML 计入 execSum（r13 多算 118s、r16 多算 251s）；正式 mpv-testing 的权重表与聚合报告都按 1..N 有界扫描无此坑。教训＝临时工具的读数与正式脚本口径不同源，跨轮对比前先对齐目录边界（本轮台账已逐轮订正）。

6. **flake 方法学微调（相对 T8「失败轮墙钟作废」的修正）**：分片测试的 flake 无轮内重试，1 例失败不改变其它分片的执行轨迹与墙钟——失败轮的计时/exec 照收入账（逐轮对齐计数口径），flake 本体定向复跑证伪后登记。本轮 17 轮 5 例 flake（agent SenderLoopBackoff ×2、FatalPassthrough ×2、HistorySqlLogPanelPreview ×1）全部定向复绿、零阻断；若按旧口径本轮将烧掉近半轮次的等待。收口仍以零失败轮的 SHARD TOTAL+parity 行为准（6093/0/0/9、533 类全覆盖）。

## 地板声明（供下一轮立项对照）

5 片时长均衡栈的墙钟地板 ≈ **2m30s @ 6093 例**（本机 6C12T/32GB、卡巴斯基排除已落地）：调度层（片数/均衡/拆分/外部分离桶）与 JVM 参数面（GC/堆/线程/启动）均已双轮实测无空间；**测试执行语义内部也已关账（§十 预审计，2026-09-29 用户批准试点后实施前否决）**——头部类的 15~27s 不是 fixture 成本而是 **per-JVM 一次性平台初始化的归因伪象**（同例跨轮 20.1s→3.6s、19.8s→2.7s 实证；每 JVM 恰付一次、均衡器已自动摊成每片一个），类内 fixture 共享在平台缓存面前收割 ≈0，第一档等待谓词无存量、第三档缩验证面越线；测试代码自身每例实际执行 ≈0.1s 级。剩余选项只剩：更少平台 JVM（实测更差）/更便宜的平台初始化（平台侧能力，JVM flags 无收益）/缩验证面（红线越线）——均不可行。
