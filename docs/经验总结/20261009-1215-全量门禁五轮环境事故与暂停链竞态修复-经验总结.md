# 全量门禁五轮环境事故与暂停链竞态修复——经验总结

> **来源**：T-PremainReattach 实施日（2026-10-09）的收口全过程复盘。修复本体（D1+P4）约 45 分钟，
> 总耗时约 3.5~4 小时——**约八成时间耗在验证链路**：8 轮全量门禁中 5 轮失败（4 轮环境事故、
> 1 轮既有守卫清点、2 轮抖出真实竞态），每轮失败都要「取证→定责→处置→再验」。
> 本文沉淀定责分流表、门禁值守纪律与暂停/恢复通道的竞态修法模式。
> 关联：计划 `docs/开发计划/20261009-0819-T-PremainReattach-*` §九；验收文档 §8.4 两条追记。

## 一、时间去向对账（为什么慢）

| 阶段 | 耗时 | 说明 |
|------|------|------|
| 前提核对 + D1 实施 + 守卫编写 | ~30min | 一次成型 |
| 首轮定向红修（竞态 D127） | ~15min | 5/12 红=真竞态，修生产码而非改测试 |
| 反向验证两刀 + 恢复探针 | ~10min | 每刀仅 20~30s，纪律成本可忽略 |
| **门禁第 1 轮：卡死 20min + 诊断 + 处置** | **~40min** | 内存挤兑：shard1/4 出生 OOM、shard2 卡死 20.6min；**盲等 20min 才开始诊断**（教训一） |
| 门禁第 2 轮 + 既有守卫清点红修 | ~10min | 合法调用点清点 3→4，预期内 |
| 第一批提交 + 文档 | ~10min | — |
| P4 实施 + 守卫 + 反向第三刀 | ~25min | 一次成型 |
| **P4 门禁三轮失败 + 逐轮取证修复** | **~90min** | 竞态①backlog 哑元滞留 → 竞态②drain/resume 并发吞噬 → TaskStop 残留锁 jar ×2 → IU-253 金丝雀；每轮 15~25min 取证修复 |
| 终态对账 + 提交 push + 文档记忆 | ~15min | — |

结构性原因三条：

1. **这台机器的全量门禁正处内存边缘（R16 基线）**：5 个分片执行器同时出生就是高危窗，当日
   机器还叠着用户 runIde 沙盒与我前序定向测试的 JVM，环境事故概率天然偏高——8 轮里 4 轮纯环境。
2. **改的是并发生命周期状态机**（通道 accept/pause/resume/drain + 会话提交），竞态只有全量门禁
   的负载与时序才抖得出来——门禁抖出 2 道 D1 设计自身的真实缺陷，每道都是「读沙盒日志→时序
   推演→修复→3 连跑+重跑门禁」的完整循环。这个成本**不可压缩**：压缩掉就是把缺陷留给用户真机。
3. 我自己的两个处置教训（可改进，已入纪律）：门禁启动后**盲等 20 分钟**才诊断（应做出生探查，
   见 §三）；TaskStop 后**没有立即清残留执行器**（导致后续两轮 prepareSandbox 锁文件失败）。

## 二、环境事故定责分流表（当日四类，按签名速查）

| 签名 | 定责 | 处置 |
|------|------|------|
| `ProcessExecutionException` + hs_err `malloc Chunk::new` + 分片启动即死 | 执行器出生 OOM（R16/R18 内存挤兑） | 杀残留 + `--stop` 清 daemon + 原样重跑 |
| `AssertionError: Indexing timeout` ×2 + **单类挂 20min 零产出** | 内存挤兑环境伤（索引等超时后基础设施僵住） | 该类单类复跑 42s 绿=定责完成，不查代码 |
| `prepareSandbox_testShardN` 报 `ERROR_USER_MAPPED_FILE`（复制沙盒 lib jar 失败） | TaskStop 残留执行器 **mmap 住沙盒 jar**（T-SqlToJavaPromote 五连坑① 二次命中） | 核命令行含自家 `test-sandbox/shardN` → 杀 Executor → 试删被锁文件验证锁释放 → 复跑 |
| `McpDbSignatureCrossVersionTest` / `PlatformSignatureCrossVersionTest` 的 IU-253 红 | **内存墙金丝雀**（外部平台子 JVM 最先死，R16 二遇判据） | 先查 commit 水位再怀疑代码；清 daemon 原样重跑即绿 |

共同纪律：**每轮失败先取证定责再处置，不盲跑也不盲修**——四类环境事故都不动一行代码，
真正要动代码的（竞态）反而要看沙盒日志逐帧推演。

## 三、长门禁值守纪律（新增）

1. **出生健康探查**：门禁启动后 ~2.5 分钟做一次进程探查——5 个分片执行器是否齐、CPU 是否在烧
   （10s 采样增量）。执行器没齐/CPU 全零=早停早处置，别等 20 分钟。
2. **判活性看两样**：分片 XML **产出增量**（`find build/test-results/testShardN -newermt <时刻> | wc -l`）
   与 JVM **CPU 增量**。沙盒里的遥测/心跳文件每分钟都在写（定时器活着），**遥测在写≠在推进**。
3. **XML 真伪看内嵌 timestamp**：结果目录混有分片均衡重排的陈旧件，文件 mtime 与总数都不可靠，
   `<testsuite timestamp="…">` 才是权威；跨轮拼读时分片和数不作口径。
4. **单类挂死别硬等**：某分片几十分钟无类产出，找 daemon 日志定位卡在哪个类，杀该执行器
   （kill 前核命令行含自家 shardN 沙盒）让构建快速失败退出，单类复跑定责。
5. **TaskStop 之后立即清场**：停门禁必带「查残留 Executor（命令行过滤 `Gradle Test Executor`
   + `test-sandbox/shardN`）→ 杀掉」，否则残留进程 mmap 住沙盒 jar，后续几轮构建全给锁死。

## 四、暂停/恢复 socket 通道的竞态三坑（D1 设计层教训）

本轮 D1「暂停待重连」设计上线即被门禁抖出两道缺陷、实施中自堵一道，三坑同源——
**把 TCP 监听 socket 当「可暂停的服务状态」管理时**：

1. **绝不能 accept-then-close**：对端 SenderLoop 有「连上即被关」计数（本仓 `MAX_FAST_DROPS=10`
   计满即 PORT_ABANDONED 永久放弃端口）。暂停期拒绝连接必须让它**停在内核 backlog**
   （不被 accept 就不计入），1s→5s 退避下 accept-close 约 40s 就能把对端逼疯。
2. **唤醒用的哑元连接会滞留 backlog**：向自己的监听端口自连以唤醒阻塞的 accept 线程，若线程恰在
   「循环条件检查」处退出（未消费哑元），哑元连接占住槽位（backlog=1 时占满），此后一切回连被拒
   （Windows backlog 满即拒绝，Linux 是丢 SYN 重试，形态不同 equally 致命）。修法=暂停退出时由
   accept 线程**清空 backlog**（时间有界的 accept+close 循环），保证交接时槽位干净、resume 后
   第一个 accept 必是对端真连接。
3. **清尾与重启不能并发**：清尾循环（drain）与 resume 新起的 accept 循环共用同一个 ServerSocket，
   并发时互抢连接 + **共享 soTimeout 字段互踩**（新循环改写 30s 后，旧 drain 的超时退出条件失效，
   变成 30s 的「连接吞噬僵尸」）。修法双保险：清尾**时间有界**（500ms 封顶——绝不能在暂停期常驻
   服务，否则退回坑 1 的放弃计数灾难）+ 重启前对旧线程**无界 join**（其全部退出路径有界：
   清尾 100ms 拍 / 读帧 5s / accept tick 30s，join 最长数秒，换零并发窗口）。

另有一条实施期教训：**跨线程状态登记要趁早**。`channel.pid` 原在会话构建完成后才写，而构建链
（CONFIG 下发/巡检懒启/广播）有毫秒级尾巴——「关开关」恰好落在窗口内时判据读到旧值走错分支。
读到即登记（HELLO 拆出 pid 的第一行就写），配合「会话提交段与清表段互斥 + 锁内提交门禁」
（sessionCommitLock）才能把复活态/误关态一起堵死。

## 五、并发状态机改动的测试设计

- **await 的前置要对齐判据的确切前置**，不是邻近可见信号：首版守卫等「会话已建立」就关开关，
  而 `pid 登记→会话提交`之间还有毫秒级链路，5/12 恰落窗口。改为等「pid 已登记」（分流判据本体）。
- **测试红有两种**：测试写错了 vs 生产真竞态。本轮首轮 5/12 红是后者（sessionCommitLock 因此
  而生）——先读沙盒日志逐帧推演再决定改哪边，别顺手放宽测试。
- **守护测试抖出设计缺陷正是门禁的价值**：竞态①②单跑 3 遍全绿、只在全量门禁时序下现形。
  结论不是「单测没用」，而是这类改动必须过门禁，且门禁红时优先怀疑「负载时序下的新交错」
  而非环境（环境事故见 §二分流表，两者签名不同）。
- 反向验证分层钉：直连入口用例钉机制本体、收口入口用例钉接线——摘钩子只有收口用例红，
  摘机制两者都红，判别面各自精确。
