> 基线：2026-09-25 T-TestPerf5（分支 t-testperf5，工作树 mpsv-testperf5）。

## 二、本轮最有价值的四个认知

### 1. 多会话并发构建会污染「历史读数」，拿旧 XML 做画像前先鉴别该轮干不干净

主树 2026-09-24 14:36 一轮分片结果 execSum 高达 1528s（T-TestPerf4 收口同口径 687s），测试规模只 +2.6%。逐类对比坐实是双开 testShards 量级的并发争用伪象，且膨胀幅度按测试形态分化：PSI/UI 重类 ~1.3×（SqlPreviewPanelTest 42.6→56.7s），走 ProcessBuilder 外部进程的签名护栏族最狠 6.7×（McpDbSignatureCrossVersionTest 21.5→70.2s，clean 实测仅 10.4s）——CPU 饥饿下「自己被分时」与「等被抢的子进程」叠加，进程生成型测试受害最深。

推论两面：①拿 `build/test-results` 历史 XML 做「负载数据画像/权重」前，先看 execSum 量级鉴别该轮是否单路 clean（本仓 clean ≈600s，翻倍即污染）；②分片权重表被污染轮喂过会失准——K=2 中位数削不掉同侧膨胀，好在权重只影响分区不影响正确性，两轮 clean 跑后自动回正（本轮 run2→run3 实证）。实操定例：**全量门禁只在单路窗口跑**（AGENTS.md 已有定例，本轮给出违例的量化代价：墙钟 2.2 倍起）。

### 2. 机器窗口漂移 ±5~8% 与典型调参效应同量级——单窗成对对照会制造假阳性

SerialGC 在筛查窗读出 −6.4%（177s/173s vs 基线 194s/180s，达 5% 门槛且「复跑确认」），落了默认；随后晚窗收口跑 193s/188s 不复现，同刻加跑 G1 对照 187s/190s——与 serial 无差。真相：execSum（配置无关的总活）早窗 ~590-600s、晚窗 ~620-640s，机器状态整体漂了 +5%，早窗的 G1 基线是「慢窗里的 G1」、serial 是「快窗里的 serial」。连「serial 让各片失衡更收敛」也不跨窗成立（晚窗 G1 ±5.0% vs serial ±11%）。

方法论定例：**效应量预期 <10% 的构建/测试调参实验，必须同窗交错 A/B/A/B（或至少 A-B-A-B），禁「先 A 后 B 各两跑」**——「复跑确认」防的是单跑毛刺，防不了窗口漂移；发现不复现时的正确动作是同刻补对照组，而不是纠结配置差异。回退定参后此教训与两个开关一起留档。

### 3. 无收益 + 一次竞态嫌疑 = 路线整体销账；竞态嫌疑的处置是「定向复跑判别 + 如实登记」

`-PtestProcCap`（`-XX:ActiveProcessorCount`）的假说（线程面超额认领是片间争用主因）被 cap3 直接证伪：189s vs 基线均值 187s——片间膨胀的主分量不在 JVM 线程层（内存带宽/调度更可能，与 T-BuildConcurrency「瓶颈看内存提交量」同向）。cap4 那跑出过一例 `FatalPassthroughTest` 回调计数断言失败（sendConfig 的 catch 链在调用线程同步走完 `alive=false → onStateChange()`，断言 95 行已过而 96 行 stateChanges≠1），定向复跑 cap4×2 + 裸跑×2 四连全绿不复现——判为负载形态敏感的时序竞态嫌疑：不洗白（不能证明 cap4 无辜）、不采信（不能证明有罪）、不修码（描述性问题不动手），登记入脆弱清单备查。

### 4. 权重表首轮会被本工作树冷跑读数污染——新工作树做基线实验按「冷跑 + 两轮 warm」起手

新工作树 build/ 全空，run1 冷跑逐类耗时（编译竞争 + 沙盒冷态）成为 run2 权重表唯一样本（K=2 不足退化为最新一份），聚合报告 expected 全等且偏高（187.1s×4 vs 实测总量 593.5s）。第二轮中位数把冷跑读数稀释一半，第三轮回正。推论：冷跑读数永远不当基线；要权重收敛，实验前先无观察热身两跑。

## 三、销账台账更新（接 T-TestPerf4 §四）

| 维度 | 结论 | 出处 |
| --- | --- | --- |
| 线程面治理（-PtestProcCap，开关保留） | 无收益；cap4 一次时序竞态嫌疑（定向不复现） | T-TestPerf5 |
| GC：SerialGC 换型（开关保留） | 同窗假阳性 −6.4%，同刻对照净效应 ≈0，不落默认 | T-TestPerf5 |
| 5 片 × SerialGC | 仍回劣（execSum +20% 并发膨胀不随 GC 换型消失） | T-TestPerf5 |
| GC：ParallelGC / 堆加大 / 多 fork / 纯逻辑桶 / build cache | 维持销账 | T-TestPerf2/3/4 |

## 四、地板判断（本轮的主交付：证实而非再压缩）

warm 墙钟 = 关键路径片墙钟 ≈ execSum(≈600s)/4 + 固定开销 17s + 前置 10s ≈ 177s 理想 vs 实测 180~194s——残余差距是逐跑随机的失衡涨落（均衡器追不动，T-TestPerf4 已裁决）与窗口漂移。调度层（片数、GC、堆、线程面、fork、分桶、缓存）的全部常规杠杆至此实测完毕，**3m00s~3m14s 就是零测试源码改动前提下的地板水位**。再往下只剩测试实现层：最重类 SqlPreviewPanelTest 42.2s/73 例、签名护栏 ProcessBuilder 族 clean 合计 45.3s——单类原子，改测试代码撞红线，登记不立项。若测试规模再涨 ~40%，按保质期判据重探片数（6 片需先证伪「固定开销×6 + 更高膨胀」）。
